# Method and provenance

The sources are [Evo-Harness, arXiv 2608.15071v2](https://arxiv.org/abs/2608.15071v2) and the CL path in [A-EVO-Lab/a-evolve at 3c7c7b8](https://github.com/A-EVO-Lab/a-evolve/tree/3c7c7b8c62a3f07da1d4407aa03f0ca079954bcf), particularly `evo_harness/cl_bench.py`.

The proposal path retains the Solver's messages and model and appends negative feedback to that same context. Penguin therefore continues the original Solver Session for reflection. One independent Evolver then curates all negative candidates against the complete training batch and pre-batch library with ADD/MERGE/REVISE/SKIP. Successful contexts are counterevidence, not sources of positive candidates. There is no candidate retest or score-acceptance gate.

The reference `_build_system_prompt` loads all current-topic bodies and general descriptions. This toolkit retains that distinction using native Skill directories and fixed initial context. General bodies remain in the private library. The five-general/five-per-topic ceilings and 16,000-byte complete package are the existing Penguin adaptation; the byte budget is not an exact token budget.

Each training unit runs once in its documented continuing environment. Each task is answered and scored once before one batch compilation. The frozen baseline and learned States transfer to fresh tests, with three complete repetitions by default. There is no iterative training-score curve or across-training-run standard deviation in this experiment design.

The toolkit describes the learning method; Penguin and the selected Benchmark supply task discovery, Session continuation, environments, State handoff and scoring. Record runtime replacements and deviations without claiming the paper's published benchmark results.
