# Skill：本地部署与微调加入 AI 应用开发分组，另有演示文稿创作

- **Date:** 2026-07-22
- **Type:** feature
- **Scope:** `skills`
- **PR:** [#19](https://github.com/Prism-Shadow/penguin-harness/pull/19), [#44](https://github.com/Prism-Shadow/penguin-harness/pull/44)

[English](2026-07-22-skills.md)

三个新的内置 Skill 扩展了 AI App Development 分组，使 Agent 能够把它所依赖的模型部署起来并调优：

- **vllm**——用 vLLM 的 OpenAI 兼容服务端安装并部署模型，包含 Agent Harness 所需的工具调用参数（`--enable-auto-tool-choice --tool-call-parser …`）、量化与显存选项，以及排障指引。
- **ollama**——用 Ollama 拉取并部署本地模型，介绍其 OpenAI 兼容端点，以及通过 `OLLAMA_CONTEXT_LENGTH` 或 Modelfile 调整上下文长度。
- **llamafactory**——用 LlamaFactory 做微调（数据集注册，以上游示例 YAML 驱动的 `llamafactory-cli train/export/chat/api`），随后用 vLLM 部署产物，或经 Modelfile 导入到 Ollama 部署。

两个部署类 Skill 共用一套引导式流程：先询问用户要部署哪个模型（在用户没有偏好时推荐小巧的 Qwen3.5-0.8B 作为默认），以及倾向哪个引擎——Ollama 作为易上手的默认项，追求吞吐时选 vLLM——然后部署、验证，并用 penguin CLI 注册该端点（模型只有在 `model add` 之后才会出现在 `penguin config model list` 中）。每个 Skill 的图标都沿用对应项目的官方标识。

那条关于根目录隔离的硬性守则，放在教授配置的地方——`penguin-cli` Skill（现为 v5）与 `penguin-sdk` Skill：为 Penguin 自身配置模型使用默认根目录，但为正在开发的 AI 应用配置模型必须使用该应用自己的项目目录（`--root ./penguin_data`），除非用户另有选择——绝不使用全局的 `~/.penguin/data`。部署类 Skill 指向这条规则，而不是重复陈述它。

**bento-slides** 加入 Office Productivity 分组，使 Agent 在被要求做演示文稿时能产出一份真正的幻灯片，而不是一堵要点墙。一份 Bento 幻灯片是一个自包含的 `.bento.html` 文件，其文档就是 `#bento-doc` script 块中的普通 JSON；该 Skill 教 Agent 就地编辑这个块、在从零开始时先从 bento.page 获取应用本身，以及——真正要紧的部分——把素材映射到合适的能力上（数字用图表、网格用表格、跨页变化的主体用形变过渡、下钻用状态页、动效用 ken-burns 与数字滚动），而不是一律退回文字页。它还带上了那些不写就要多跑一轮的坑：图表序列数据必须是纯数字、形变需要稳定的共享元素 id、素材以 data URI 内嵌、已有幻灯片的 `docId` 绝不重新生成。改编自 Bento 项目自己的 Skill（MIT，© 2026 The Bento/Suite authors），在 Skill 正文中注明出处；权威 schema 仍以 https://bento.page/agents.md 为准。

`agenthub-models` Skill 跟进 AgentHub 0.4.1 升级：记录了新的受支持模型注册表、客户端现在可能直接拒绝的配置参数，以及 Gemini 3.6 / Kimi K3 / GLM-5.2 系列及其推理强度旋钮，并附上一张依该版本实际客户端匹配顺序重写的路由表。
