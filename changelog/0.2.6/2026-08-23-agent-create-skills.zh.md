# 新建 Agent 时选择预装技能

- **Date:** 2026-08-23
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#431](https://github.com/Prism-Shadow/penguin-harness/pull/431)

[English](2026-08-23-agent-create-skills.md)

新建 Agent 对话框新增「技能」字段：一个可一次勾选多个技能库条目的下拉选择，创建 Agent 时把选中的技能装入该 Agent。

## 细节

- 该字段复用定时任务对话框中模型、工作区选择器已在用的表单式触发器，面板则复用对话输入框技能下拉的同一个多选面板——顶部搜索框、每个技能库条目一行可勾选行，勾选时面板保持展开。
- 该面板新增一行批量控件，由使用方按需开启：左侧是已选数量，右侧是**全选**与**全不选**。两者都只作用于搜索框当前筛出的行，因此先筛选再全选只会加入匹配项。
- `POST /api/projects/:p/agents` 接受 `skills` 数组，元素为技能库中的技能名。这些名字在 Agent 目录创建之前就完成解析——未知的名字返回 404 `unknown_skill`，不创建任何内容——随后经由技能标签页安装所用的同一个写入函数装入，并处于 Agent 初始化其余步骤相同的清理窗口内。
- 未勾选任何技能时创建的 Agent 与此前一致，不安装任何技能。

## 导入项目目录自带的技能

同一个对话框还可以安装项目目录里已有的技能——编码 Agent 会把它们留在 `.agents/skills/` 或
`.claude/skills/`。选定目录后，其中的技能出现在一个独立的选择器里，同样带「全选／全不选」；未被
勾选的不会被安装。

- 目录技能独立成一个字段，而不是并入技能库选择器：目录技能可能与库中技能同名且仍是被安装的那一个，
  单一的「已选名称」列表无法表达究竟指的是哪一个。
- `.claude` 常常是指向 `.agents` 的符号链接，否则每个技能都会被列出两次：两个根经 `realpath`
  解析，指向同一目标时只读取一次。两者都作为真实目录存在且同名时，以 `.agents` 为准。
- 目录技能会覆盖同时选中的同名库技能：为这个 Agent 选定某个目录，是更明确的意图。
- 目录中没有可安装技能时，字段里如实说明，而不作为错误处理；被跳过的内容静默跳过：没有 `SKILL.md`
  的目录、`SKILL.md` 没有 frontmatter 的目录、安装器不接受的名称、符号链接形式的技能目录，以及
  文件读不出来或超出上限的技能——一个有问题的技能不会连累目录里的其余技能。
- 读取所选目录复用归档导入的上限与遍历规则——200 个文件、单文件 5MB、合计 20MB——因此这些数字对两
  个入口只有一处定义，而不是各自一套。每个文件都先由 stat 确认是目录自身的常规文件且未超上限才读取，
  `SKILL.md` 与 `icon.svg` 同样如此：符号链接无法把技能目录外的文件带回来，FIFO 不会把读取卡死，
  超大文件在进入内存之前就被拒绝。
- 列出目录只读取描述一个技能所需的内容；构成可安装内容的附属文件只为被勾选的名称读取。
- 两个入口以同一种方式接纳前端传来的路径——绝对路径、存在、是目录、经 `realpath` 解析——由一个
  helper 统一处理，目录浏览接口现在也共用它。
- 前端只发送名称，从不发送技能内容：创建时由服务端从磁盘重新读取，且两个来源都会先全部解析完成才写入
  任何文件，因此一个已经消失的名称会在 Agent 尚不存在时就失败。
