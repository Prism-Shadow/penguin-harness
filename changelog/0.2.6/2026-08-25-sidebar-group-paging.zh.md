# 每个分组各自计算被折叠的对话数，分组本身改为分页

- **Date:** 2026-08-25
- **Type:** feature
- **Scope:** `server`, `web`
- **PR:** [#461](https://github.com/Prism-Shadow/penguin-harness/pull/461)

[English](2026-08-25-sidebar-group-paging.md)

对话侧边栏的分组列表新增了只为本组说话的展开行、把已展开分组收回的方式，以及对分组自身的真正分页。

## 细节

- **每个工作区分组各自翻自己的服务端数据流。**列表按 Agent 取数，而侧边栏按工作区分组，因此此前所有分组共用一个游标：首页把各分组填得参差不齐——谁占着最新的行谁就吃掉大半页——而某个分组点「更多」会消耗掉兄弟分组本该读到的那一页。结果是别的分组的行凭空出现、计数自行变动，而真正点击的那个分组增长不足一页、甚至一行都不增加。列表接口新增 `workspaceGroup` 过滤（与 `category` 一样在翻页前生效），每个分组持有自己的游标，且每个渲染出来的分组都从自己的第一页开始。
- 分组的展开行由原先的「更多」改为 **展开其余 N 个对话**，其中 N 是该分组自己被折叠的对话数：它在服务端的确切份额减去已显示的行数。计数不受任何其他分组影响。
- 一旦可能持有该分组行的每个 Agent 都已取完，已加载的行**就是**该分组的份额。存储的计数只在重新加载时刷新，此前计数高于实际时会留下一个点了也没有内容的展开行；现在它随最后一条被折叠的对话一同消失。
- 一次点击展开一页，且仅当展开超出已加载的行时，才拉取该分组数据流的下一页。
- 未显式指定工作区的会话各自获得一个一次性的临时目录，侧边栏一向把它们合并为一个分组；服务端将该分组命名为 `temp`，使其与其他分组一样可翻页。
- 分组的首次带作用域拉取从它已持有的行数开始，而非从 0 开始：这些行来自 Agent 整体数据流的前缀，而整体数据流的前缀按工作区切分后仍是该分组数据流的前缀——因此这一次点击读到的是新行，而不是重读屏幕上已有的行。
- 新增 **收起** 行，把已展开的分组折回第一页。已拉取的行保留在内存中，再次展开不产生请求。
- 分组内折叠的文件夹——子智能体、定时任务、已归档——其展开行采用同样的写法，按各自的份额计数。
- 分组本身改为分页：每页最多十个，列表下方以 `‹ 1/3 ›` 翻页控件切换，取代原先「再展开十个分组」的那一行。该窗口仍只是显示层面的事——任何分组的数据加载都不取决于它落在第几页。
- 搜索完全绕过分页，与此前绕过显示上限一致：落在第 3 页的匹配项等同于没有匹配。
- 手动分组顺序仍然按完整的分组序列提交，而非当前页面上的分组，因此在第 2 页拖动不会丢掉未渲染的分组。
- 新建工作区会翻到该工作区所在的页。空的已登记分组追加在末尾且尚未被置顶或排序，超过十个分组后新建的工作区本会落在用户看不到的页上，那次点击就会像没有生效。
- 按时间分组最多只有三个分桶——最近一天／最近一月／更早——因此不分页。
- 切换 Project 或切换分组方式会清除各分组的展开状态：以 Agent id 为键的上限对工作区分组没有意义，而另一个 Project 的分组已经不复存在。
- 本次改动只作用于对话侧边栏的分组列表，其他分组列表不受影响。
