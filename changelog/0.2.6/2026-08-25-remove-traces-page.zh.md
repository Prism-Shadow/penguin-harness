# 独立的 Trace 页已移除，轨迹在产生它的对话里阅读

- **Date:** 2026-08-25
- **Type:** feature
- **Scope:** `web`, `docs`
- **PR:** [#462](https://github.com/Prism-Shadow/penguin-harness/pull/462)

[English](2026-08-25-remove-traces-page.md)

[会话轨迹只保留一个入口](2026-08-23-trace-one-entry-point.zh.md) 移除了应用内指向 `/traces` 的三处链接，但保留了页面本身，仍可通过 URL 进入。本次将其彻底移除：阅读轨迹只发生在对话的 Trace 面板中，这也是唯一的入口。

## 细节

- 删除 `/traces` 路由与页面，以及只有它渲染的 Trace 文件目录树（按 Agent 的惰性加载、工作区／Agent 分组开关，及其自有的分组翻页）。既有的 `/traces?sessionId=…` 链接不再可解析。
- **导入 Trace 移至「系统设置 → 通用」**，位于语言与币种偏好下方——这是唯一别处没有的能力。选择目的地的 Project 与 Agent，再挑选 `.jsonl` 文件，挑选即确认；提示信息会点名它落到了哪里。
- 目的地的两个部分都需选择，而旧对话框只问 Agent。接口按 Agent 划分，因为轨迹文件自带的 `session_meta` 无法指认本机的 Agent，其中的 `agent_state` 路径属于导出它的那台机器；而 Project 之所以要问，是因为设置对话框并不显示当前打开的是哪一个——它的其余每一行都属于账号或服务器——若默默沿用，导入就会落到侧边栏碰巧选中的那个 Project 里。因此也可以导入到当前打开之外的 Project；只有目的地正是当前 Project 时才刷新会话列表，因为那是屏幕上唯一的那份列表。
- **导入的 Trace 现在会成为列表中的一个对话。**此前导入只登记轨迹文件、别无其他，导入的 Session 仅存在于磁盘上：会话列表由 sessions 表提供，因此该行只有在开启「显示 CLI 会话」后才出现——而那个开关是为本服务器从未创建过的 Session 准备的，用户显式导入的文件并不属于此列。现在导入会同时把 Session 写入索引（`client: web`），并从文件自带的 `session_meta` 中带出模型引用、工作区与标题，列表刷新后即出现在侧边栏中。
- **重复的 session id 在整个部署范围内被拒绝**，而不只是接收它的那个 Agent。session id 在各处都是身份标识——sessions 表以它为主键、前端按它去重、`/chat/:sessionId` 按它路由——因此把同一个 Trace 导入到第二个 Agent 此前会「成功」为一个无人能拥有的 Session：既无法在既有行旁再插入一行，列表又会把两者折叠成一个对话，于是该分组的计数比它所能显示的行数多出一个。现在返回 409 `trace_session_exists`，与单个 Agent 内一直以来的行为一致。
- 导出保持不变，并继续与它下载的文件待在一起：Trace 面板中针对所选文件的导出链接。
- 面板本身未作改动——同样的文件视图、性能时间线与事件列表，作用域为当前打开的对话。
- 服务端的 Trace 接口全部保持不变，按 Agent 的列表接口也在内：它是有文档的对外面，消失的只是 Web App 对它的使用。
- `Select` 现在会把 `aria-label` 透传到触发按钮，与原生 select 的行为一致——设置行中的 Agent 拾取器由此获得自己的名称，因为该行的标签命名的是动作而非控件。

## 存量数据

本次改动**之前**导入的 Trace 没有 Session 行，因此本次改动并未把它们放进会话列表。它也不提供迁移，因为仅凭自身无法迁移——没有 Session 行的 Trace 与 CLI 创建的 Session 无法区分，若把所有这类 Session 一并收编，真正由 CLI 创建的会话也会被一起提升；当时把旧的导入拉回列表的办法是删除其轨迹文件后重新导入。此后本版本中加入的启动收编对账（见[向后兼容](2026-08-25-backward-compatibility.zh.md)）会把每一个没有 Session 行的 Trace——旧的导入与真正的 CLI 会话一并——收编为 `client: "cli"` 行。
