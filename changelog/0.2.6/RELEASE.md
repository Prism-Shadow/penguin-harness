PenguinHarness 0.2.6 — two Flash models and a gateway that mints its own key, agents that drive the harness, and a Session you can answer from a chat app: `glm-5.3-flash` and `qwen3.8-flash` joined the built-in catalog beside a new TokenDance provider group whose **Authorize key** action creates a key on your account without a trip to a console, a subagent turned from something you watch into something you talk to — steered mid-run by the model and from the panel's own composer, with a child's approvals escalating to you instead of being auto-denied — `penguin run` and `penguin chat` became HTTP/SSE clients of the running server, so an Agent can list, start and steer sessions on the install hosting it and the new `penguin-orchestration` Skill teaches it how, a Session can be bound to a self-built Feishu app or a Telegram bot and answered from that chat with no public URL on either side, and the context ring became a button that breaks the current context into six named parts with the compaction point marked on the bar.

## Install

**Desktop app**: grab your platform's installer from [penguin.ooo/download](https://penguin.ooo/download) — the page measures both sources on every visit and keeps GitHub unless the OSS mirror is measurably faster, with a manual selector beside the result. The macOS builds are Developer ID signed and notarized and the Windows installers are Authenticode-signed, so neither platform needs a first-launch unblock.

CLI / server (Linux, macOS; bundled Node runtime):

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows (PowerShell):

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

Or via npm (needs Node >= 24):

```sh
npm install -g @prismshadow/penguin-cli
```

## Highlights

**Two Flash models, one of them three times over.** `glm-5.3-flash` and `qwen3.8-flash` joined the built-in catalog, both with a million-token context window, both reading images, and both priced roughly an order of magnitude under their non-Flash siblings. GLM-5.3 Flash is listed three times because three routes sell it — Z.AI directly, OpenRouter, and the new TokenDance group — and each row records what that route charges: a direct-vendor row stores the vendor's list price, so the Z.AI row reads $0.03 / $0.15 / $0.50 per MTok while the OpenRouter row stores what the gateway actually bills and therefore halves that until Z.AI's promotion lapses on 2026-09-09. The vision badge on the direct row is narrower than it looks: AgentHub 0.4.8 taught the GLM client to forward `image_url` parts, in a prompt and in a tool result alike, for `glm-5.3-flash` and no other GLM id — every other one answers an image with `"GLM <id> does not support image inputs."` rather than dropping it quietly, which is why the rest of that group stays vision-off. Qwen 3.8 Flash sits in the Qwen Pay-As-You-Go group with a million-token input window against a 131K output cap.

**A TokenDance gateway, and a key you do not have to copy.** TokenDance became a provider group of its own, reaching `https://tokendance.space/gateway/v1` over Chat Completions with seven presets. Its **Authorize key** action sends you to TokenDance's own authorization page, mints a key on your account there and writes it into every model in the group, so a first run no longer starts with a console and a copy-paste: the PKCE verifier is generated on the server and never sent to a browser, the minted key goes straight into the group's models without passing through one either, and it appears in no response, log line, URL or error message. Where a redirect cannot reach you — the desktop shell, an unusual deployment — a manual mode shows a one-time code to paste instead. The group's prices are official list prices, the convention the two Qwen groups already follow, and two rows are on live promotions tagged in TokenDance's credential-free catalog API. Alongside the group, model requests now name PenguinHarness to the gateways that read an app-attribution header — `HTTP-Referer` and `X-OpenRouter-Title` for OpenRouter, `X-App-URL` for TokenDance — chosen by the endpoint's host rather than by the provider group, so a model filed under **custom** that points at one of those gateways is attributed the same way.

**Subagents you can talk to.** A subagent used to be fire-and-observe: `input_subagent` refused a prompt while the child was still running, the panel offered no way to correct or stop one, and stopping the main agent left its children running. All of it is replaced by one mechanism — the steering channel you already have into the main session, pointed at the child session, reachable by the model and by you. For the model, a prompt sent to a running child is injected mid-run as a steering message at the child's next step; a new `abort` argument stops the child's current run only, leaving the session alive for follow-ups, and combining `abort` with a prompt interrupts and redirects in one call. `input_subagent`'s output became the child's most recent complete reply — an idempotent snapshot on every access rather than a delta drain — and a released `subagent_id` revives automatically when the model messages it again. For you, the selected child is driven by the **same composer as the main conversation**: text, skills and slash commands, a per-turn thinking level, the context ring showing the child's own usage, and the approval-mode selector. "This subagent has ended" is no longer a dead end. And a background child that hits a tool approval with nowhere to ask now escalates to you as an ordinary approval card, while a parent task ending converges only the main session's approvals.

**An agent that can drive the harness.** `penguin run` and `penguin chat` executed a Task in-process against core — no server involved, and nothing the Web App could see. They are HTTP/SSE clients now: the CLI parses arguments and renders the stream, the server runs the Task, so a conversation started from a terminal shows up in the sidebar and one started in the browser can be picked up from a terminal. Beside `run` and `chat` there is a family for reading and moving an install — `ls`, `input`, `logs`, `agent`, `project`, `cost` and `schedule` — and every command an Agent runs is handed the coordinates to use them: `PENGUIN_API_URL`, `PENGUIN_API_TOKEN`, `PENGUIN_PROJECT_ID`, `PENGUIN_AGENT_ID` and `PENGUIN_SESSION_ID` go into every tool subprocess, so from inside a session a bare `penguin agent ls` reaches the very server running that session with that Project and that Agent already the defaults, and there is no login step on that path. `penguin input` is the same verb one level out — absorbed as a course correction at a running session's next step, a new turn on an idle one, and an idempotent last-reply snapshot with no `-m` — while `--timeout` bounds any wait and expires as a soft yield: exit 0, a line naming the follow-up command, and the Task still running server-side. A session an Agent starts inherits the caller's Workspace, model pair, approval mode and thinking level field by field, the same inheritance `run_subagent` applies to children. The server mints an API token at every boot into `<data-root>/api-token` (mode 0600) and a CLI on the same machine reads it, on the grounds that filesystem access to the data root already is admin authority; a remote `--server` gets no such shortcut and is refused without an explicit `PENGUIN_API_TOKEN`. The recipes ship as **`penguin-orchestration`**, a new Skill in the library's AI App Development group with no preinstall marker, carrying both the conventions and the real edges — one active Task per session, a spawned session inheriting your approval mode, an Agent that can message Agents building a loop that never terminates, and everything it starts billing the same Project.

**A Session you can reach from Feishu or Telegram.** A conversation no longer has to be read in a browser tab. A Session can be bound to a self-built Feishu app or a Telegram bot: messages sent to the bot land in that Session as ordinary user input, and the assistant's replies come back into the chat. Both channels sit behind one connector seam and a Session keeps a saved config for each — Feishu takes an App ID, App Secret and API domain, Telegram a single Bot Token — but at most one is enabled, and the enabled one holds the live connection, gated in the UI and refused by the server. Neither channel needs a public URL: Feishu's inbound events arrive over the SDK's WebSocket long connection and Telegram's over an offset-based `getUpdates` long poll, and on connect the poller discards whatever accumulated while nothing was listening rather than replaying a dark period as a flood of Tasks. Replies arrive as they finish rather than in one block at the end — each completed assistant message is relayed the moment it completes, serialised per Session and chunked under the channels' text limits, and in a group chat only a run's first outbound chunk is threaded onto the message that triggered it. Credentials follow the models page's interaction: the field starts empty, a stored secret shows only as its mask, and a "clear stored …" checkbox drops it on save — refused while that channel's connection is enabled. The binding is edited from the session row's menu or from a **Messaging** panel in the conversation's dock, and a Session holding a live connection carries a small paper plane on its sidebar row. What the model sees is nothing special: inbound text starts a Task as plain composer input, with no marker and no special sender.

**Seeing where the context went, and where the update is.** The context ring in the composer became a button. Clicking it splits the current model context into six parts — system prompt, tool definitions, user messages, model messages, tool requests, tool results — as one bar running the full context window, with a dashed mark where compaction will fire and a ranking of the five tools eating the most of it; the parts are apportioned by largest remainder so the columns total exactly the occupancy the ring reports, and every derived figure is marked `~`. Separately, a phone-style red dot now marks the chrome whenever something is updatable, and every dot leads down an unbroken path to the control that performs that update rather than stopping at a notice: a software release (or a downloaded desktop build) trails from the menu button and the sidebar avatar to the user menu's update row, and an Agent kernel update trails from the same menu button through the Agents entry to the outdated Agent's card, its settings Overview tab, and the enabled **Update kernel** button. The session list is deliberately left unbadged — a dot there would lead to no action.

**Lists that keep the order you put them in.** Both the chat sidebar's conversation groups and the models page's provider groups can be dragged into a manual order, stored per Project; the chat model picker follows the models page, and the sidebar keeps a separate order per grouping mode. The sidebar's groups also stopped sharing one cursor: each Workspace group pages its own server stream, so a group's reveal row reads **Show N more chats** with that group's own hidden count, a **Show less** folds it back, and the group list itself paginates ten at a time with a `‹ 1/3 ›` pager. Searching bypasses the pagination entirely, a manual drag still commits against the full group sequence rather than the page on screen, and time grouping — last day / last month / earlier — has too few buckets to paginate and is excluded from manual ordering by construction.

**One place to read a Trace.** The standalone `/traces` page is gone, along with the Trace-file tree only it rendered. A Trace is read in its conversation's Trace panel, which is now the only way in, and importing one moved to System settings → General with an explicit Project and Agent destination. An imported Trace becomes a listed conversation: the import used to register the Trace file and nothing else, so the Session existed only on disk, and it now indexes the Session too — carrying the model reference, Workspace and title from the file's own `session_meta` — while a duplicate session id is rejected across the whole install rather than only within the receiving Agent.

**Agents that are easier to start, and a state file that cannot be half-written.** The Agent create dialog gained a Skills field that takes several library skills at once, plus the Skills a chosen project directory already carries (`.agents/skills/` or `.claude/skills/`, resolved through `realpath` so a symlinked pair is read once), and it can initialize an Agent straight from an exported snapshot package instead of creating an empty Agent and importing into it. Underneath, every file the Harness keeps on disk — `system_config.yaml`, `.project_config.toml`, `.vault.toml`, `AGENTS.md`, `MEMORY.md`, schedule files, `GOAL.yaml` — is now replaced atomically through one writer, so a crash mid-write can no longer leave a truncated `system_config.yaml` that still parses as YAML while the tool list, MCP servers, vault and skills settings silently vanish. Skill installs stage into a dot-prefixed directory and swap in as the last step, and `edit_file` / `write_file` follow a symlink to the file at its end instead of replacing the link.

## Notable in this release

- **Breaking (Windows installers carry a new signing identity).** The Authenticode certificate changed subject, from `RushRush Network Technology Ltd` to `NaisNet Technology Co., Ltd.`, and the publisher name recorded in the update metadata changed with it. electron-updater checks a downloaded update against the publisher recorded in **the installed app**, so a Windows desktop client installed from 0.2.4 or earlier refuses this update and stays where it is: **reinstall once** from [penguin.ooo/download](https://penguin.ooo/download), after which auto-update works again and accepts either identity. macOS, Linux and the CLI are unaffected. It is also why this release is 0.2.6 and not 0.2.5: v0.2.5 was tagged for the same set of changes and published the npm packages, then failed on that identity check before any release asset was produced, so 0.2.5 exists on npm and has no GitHub Release.
- **`penguin version`.** A new command prints the running build's identity as one line — `v0.2.6` for a release, `git describe --tags --dirty` output for a build made from a checkout — with `--json` for the full record and `GET /api/version` serving the same record, so the two cannot disagree about one install. The record's `harness` half names what a hot update pushed to the machine, read from that data root's HMR store.
- **The hot update path answers its failure modes.** A bundle whose runtime is too old to publish the business capabilities now refuses to boot and rolls back rather than landing as half a version; every resource an App creates sits on a written delivered / suspended / detached inventory that the swap executes, so a dead generation can no longer act on the live one's objects; a bundle that fails to boot is recovered by re-booting the version that was actually running, held as the loaded object rather than re-derived; and a pushed bundle now goes straight to its content-addressed path in the store instead of also accumulating forever in `hmr/uploads/`.
- **A stopped background command reads as stopped.** A `run_in_background` command ended on a SIGTERM used to reach the conversation as a failure, and a model's reasonable response to a failed dev server is to start it again — undoing the stop that was just asked for. There is now a `stopped` status for a deliberate end, with `failed` keeping the outcomes nobody asked for, so an OOM kill still reads as the failure it is.
- **Truncated tool output keeps its tail.** The output budget splits in half: the head window streams live as before, and over-budget output ends as head, a counting marker naming how much was kept out of how much there was, and the last tail window. For command output the informative part is usually the end — the verdict, the error, the last lines before exit.
- **Background completion reports are stamped.** A report delivered while the agent loop is running carries `delivery: steering` on the wire, so every turn-segmentation implementation can tell "inside the same turn" from "an independent turn" instead of guessing from position; legacy Traces keep a positional fallback.
- **Phone-width surfaces stay inside their box.** The skill library's card actions, the cost center's error table, the Agent card's stats line and the memory group header each stopped pushing something out of reach at phone width.
- **A bare URL ends where the URL ends.** A link typed into Chinese prose swallowed the punctuation and clause after it; Markdown surfaces in the Web App now end a bare URL at its last ASCII character, and one shared plugin list backs all five renderers.
- **AgentHub 0.4.7 and 0.4.8.** 0.4.7 splits a Gemini message that mixes tool results with other content into consecutive same-role contents, fixing the Vertex AI 400 `Requests ending with a model turn are not supported.` that could make a session fail identically on every retry until its context was discarded. 0.4.8 is what carries GLM images.
- **Breaking (`kill_subagent` and `kill_command` are gone).** A subagent session is always resumable and never destroyed, so the kill notion went with it: stopping a subagent run is `input_subagent`'s `abort`, and terminating a command is `input_command` with `kill: true`. Nothing translates the old names — an Agent whose stored tool configuration names them simply stops assembling those entries, and a model that calls one gets the standard unknown-tool failure. Update anything that pins either name by hand.
- **Breaking (a kernel update keeps or advances a whole settings tab).** The unit of the kernel update moved from a config leaf to an Agent settings tab. A tab you have customized is never overwritten; the cost is that an Agent with one customized built-in tool stops receiving new built-in tools entirely. **Restore the default configuration** on that tab puts it back under kernel updates, and the update's result names every tab it kept.
- **Breaking (Agent commands no longer inherit the harness's `PENGUIN_*` environment).** No `PENGUIN_*` variable — nor `PORT` or `HOST` — reaches a command an Agent runs, so a harness an Agent starts takes its own default data root rather than the serving install's. Outbound proxy variables are the deliberate exception. To restore one, set it in that Agent's vault, which is applied after the host environment is stripped.
- **Breaking (the CLI no longer runs a Task without a server).** `penguin run` and `penguin chat` go through the server API; where none is running they start one locally, and fully offline core-direct execution is no longer a CLI mode — the SDK keeps that capability for embedders. In the same rework the per-user "show CLI sessions" filter was retired and every session is always listed, with a once-per-boot sweep adopting legacy CLI-direct Traces into the index, so Sessions an older CLI left behind appear in the sidebar on their own. Nothing on disk has to be migrated, and old binaries keep working against their own cores until they are updated.
- **Breaking (stop reasons converge to four values).** `completed` / `aborted` / `retryable` / `fatal` is now the only stop-reason vocabulary; `ToolStopReason`, `CompactionStatus`, `McpConnectStatus` and `LLMOutcome.permanent` are gone, the concrete failure rides on `error_message`, and the abort event means exactly one thing — the user interrupted the run — with an LLM or compaction failure recorded by the `request_end` / `compaction_end` already on the stream. Existing Traces stay readable and render the retired spellings; the break is source-level, for an SDK embedder or an HTTP consumer that reads a stop reason.
- **Breaking (core's `/interfaces` subpath split).** `SubagentHandle.run` and `sendToBackgroundSubagent` take an OmniMessage list instead of a string (`[userText(prompt, "parent_agent")]` reproduces the old behaviour), and `BuildInfo`, `BuildRuntimeInfo`, `HarnessInfo`, `HarnessSource` and `VersionReport` now ship from the package root rather than from `@prismshadow/penguin-core/interfaces`. Both are compile-time errors with a one-line fix; no shim is kept.
- **New catalog rows are not automatic.** Presets are copied into `.project_config.toml` at Project creation and nothing rewrites them. Use **sync presets** on the models page to pick up GLM-5.3 Flash, Qwen 3.8 Flash and the TokenDance group — it appends and updates catalog-owned fields, deletes nothing, and touches neither your stored default model nor any credential. A Project older than that group has to sync once before the group, and its **Authorize key** action, appear at all.

## Requirements

Linux or macOS (x64 / arm64), or Windows 10+ (x64). The desktop app and the CLI installers bundle their own runtime; installing from npm needs Node >= 24. All data stays under `~/.penguin/data`.
