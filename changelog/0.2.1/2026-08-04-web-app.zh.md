# Web App：随机预置的管理员密码与登录节流

- **Date:** 2026-08-04
- **Type:** feature
- **Scope:** `server`, `web`
- **PR:** [#172](https://github.com/Prism-Shadow/penguin-harness/pull/172)

[English](2026-08-04-web-app.md)

内置管理员那个固定且被公开记录的初始密码（`penguin-2026`）没有了。

## 随机预置密码

首次启动时，服务端现在为 `admin` 预置一个随机的 `penguin-<4 位数字>` 密码，并只在启动控制台上打印一次（`Seeded built-in admin "admin" — initial password: penguin-1234 …`）；登录页与修改密码对话框改为指向启动输出，而不再点名某个常量，README、文档、安装脚本的后续步骤与博客文章随之更新。`PENGUIN_SEED_ADMIN_PASSWORD` 可为自动化测试与 e2e 固定该预置值，并且与其他所有初始/重置密码一样受 ≥ 8 字符策略约束——一个配置上的手误不可能造出一个弱得离谱的特权账户。

## 登录节流

登录端点新增按用户名的节流，使这个一万种取值的密码形态只是便利、而不是攻击面：连续 5 次失败之后，下一次尝试只有在距上次失败经过一段指数增长的延迟后才被受理（从 1 秒翻倍至 60 秒封顶；窗口内的尝试得到 `429 too_many_attempts`——界面上已本地化——且不会延长该窗口），而一次成功登录会清零计数。约 40 次失败之后，攻击者每分钟只能猜一次，而打错字的用户等待时间永远不超过上限。未知用户名同样被节流，因此这个节流不构成账户是否存在的判别器。计数器存放在进程内存中，重启即清空。
