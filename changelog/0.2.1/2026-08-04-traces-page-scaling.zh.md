# Web App：Traces 页像会话侧边栏一样可扩展

- **Date:** 2026-08-04
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#183](https://github.com/Prism-Shadow/penguin-harness/pull/183)

[English](2026-08-04-traces-page-scaling.md)

Trace 列表此前是一次性把一切都拉下来：每个 Agent 在加载时自动展开，每次展开都在服务端走遍该 Agent 的整棵 trace 树并对每个文件做一次 stat，每一行会话与每一枚文件标签都渲染出来，而任何分页的侧边栏 store 尚未加载的会话，都以等宽字体回退显示它的原始 id——长期使用的 Project 会把页面卡死。

`GET /api/projects/:p/agents/:a/traces` 现在接受可选的 `offset`/`limit`。不带它们时响应形状与此前逐字节一致；带上之后，服务端返回最新在前的会话分组加上一个总数，并且只对返回的这一页做 stat（尺寸回写进索引）。

发现流程本身不再逐请求触碰目录树。一个由 SQLite 派生的 **trace 索引**（`trace_files`，加上在注册时读取一次的逐会话事实：来源、工作区、以首条提示词作兜底的标题、模型引用）为每一个消费方提供服务。热路径是两次 stat——对 traces 根目录与最新日期目录各做一次 mtime 闸门检查；闸门一旦变动，就只对发生变化的日期目录做增量 readdir，每个新会话经一次有界的头部读取分类一次；服务端侧的写入（导入、会话/Agent/Project 删除）同步更新索引；而任何消费方在未命中时，都必须先强制完整对账一次才允许返回 404，因此一个陈旧的索引代价是多扫一次，而绝不会给出错误答案。该索引是一份可重建的缓存——磁盘上的 Trace 文件始终是唯一事实来源，升级或重启之后的第一个请求只是把它重建一遍。同一个索引现在还供给 Agent 列表的 30 天活跃度迷你图（此前每次 Agent 列表请求都要走遍全部历史）、`/messages` 的子 Agent 解析器（此前是全 Project 扫描）、trace 的定位/下载/删除、CLI 会话发现——收编流程已不再读取任何文件——以及会话恢复。列表操作不做任何头部读取；标题来自已存的事实：先取数据库中的会话标题，否则取注册时记下的首条提示词兜底。

该页面现在完全照搬侧边栏的结构，而不只是照搬它的纯函数助手。侧边栏的分组头部、文件夹小节、「更多」行与分组模式开关，被从其内部闭包中逐字抽取到共享的 `components/ui/group-list.tsx` 中——而侧边栏本身也重构到它们之上，因此两处界面渲染的是同一份实现。traces 树获得两种分组模式（按 Workspace 或按 Agent，共用与侧边栏相同的持久化偏好——在任一界面切换模式，两边一起切换），以及每个分组下的三个惰性文件夹（子 Agent、定时任务、已归档），各自独立分页。服务端的支持是增量式的：分页的会话分组携带 `category` 与 `workspace`，响应携带逐分类与逐工作区的计数，而 `category=` 过滤器可在单个文件夹内分页——全部由 trace 索引作答，且由于事实是在注册时存下的，第一个请求的分类就是精确的。

其他方面，此前的修复依然成立：加载更多的分页粒度拆分（traces 专用的步长——20 个会话、15 个分组，比侧边栏的 10 更大，因为整页高度能放下更多）、分组上限配一行「更多分组」、对被深链的 Agent 采用置顶优先的排序、默认只展开被聚焦的（或第一个）Agent、文件标签数量设上限，以及带记忆化的标题查找。CLI 来源的会话在这里同样遵循用户的「显示 CLI 会话」偏好，默认隐藏；而一条指向 CLI 会话的「查看 trace」深链，无论该偏好如何都仍能解析并打开详情面板。会话 id 不再出现在该页面的任何位置——未命名的会话显示标准的「新会话」标签，详情副标题只保留日期 · 大小。聊天页也做了反向链接：其会话信息下拉新增一个「查看 trace」操作，深链到 traces 页并聚焦该 Agent、选中该会话；当会话位于第一页之外或在某个文件夹内时，回退为对单个 Agent 的完整拉取。
