PenguinHarness 0.2.10 — the release where the conversation grows a workbench. A Files panel browses and edits the Workspace in place, the context ring measures against the point compaction actually fires and its threshold becomes a cutter you drag, scheduled tasks live in the dock beside the chat, and a shortcuts ball on the conversation's right edge fans the whole workbench open. Hooks became a capability of the loop itself, with goal mode and continual learning shipping as installable plugins; a shared Create with AI kit puts an agent behind the app's creation forms; an official Docker image makes a server one `docker run`; and DeepSeek V4.1 Flash is the model a new Project starts on.

## Install

**Desktop app**: grab your platform's installer from [penguin.ooo/download](https://penguin.ooo/download) — the page measures both sources on every visit and keeps GitHub unless the OSS mirror is measurably faster, with a manual selector beside the result. The macOS builds are Developer ID signed and notarized and the Windows installers are Authenticode-signed, so neither platform needs a first-launch unblock.

CLI / server (Linux, macOS; bundled Node runtime):

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows (PowerShell):

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

Or via npm (needs Node >= 24):

```sh
npm install -g @prismshadow/penguin-cli
```

Or the official Docker image (`linux/amd64` and `linux/arm64`):

```sh
docker run -d --name penguin -p 127.0.0.1:7364:7364 -v penguin-data:/data hiyouga/penguinharness:latest
```

`latest` follows `main` and is rebuilt on every push, `0.2.10` is this release built from its own tag, and the example publishes the port on the host's loopback, so a fresh deployment answers only on the machine running Docker.

## Highlights

**The Workspace is a two-pane file browser you can type into.** The Files panel gained a directory tree beside the preview — lazy-loaded, arrow-key navigable, filterable, with a draggable divider that remembers its width and a toolbar toggle that hides it — and text files open into a monospace editor with a Wrap toggle and Ctrl+S. A save is version-checked: the content GET now returns an `ETag`, the write sends it back, and a file the Agent changed during the turn answers `409` having written nothing, which the panel turns into a question that names the file and keeps your draft either way. OS files dropped anywhere on the panel upload into the directory under the pointer. Drafts survive a Session switch, a collapsed dock and a hidden tab; only closing the panel outright asks.

![The Files panel: a directory tree on the left beside an open file in the plain-text editor on the right](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/files-panel.png)

**The context ring measures against compaction, and its threshold is a control.** The composer's ring now fills against the point the conversation will actually be summarized rather than against the model's whole window, so 64k against a 128k threshold on a million-token model reads 50% instead of 6%. The panel's bar keeps the window as its scale and marks the trigger with a dashed cutter — which is now the control that moves it: drag it, confirm the number in a still-editable field, and that Agent's compaction threshold changes for the conversation in front of you, immediately. Immediately is a core change: compaction settings left the strict request-prefix tier and are re-read at every compaction checkpoint. The panel also ranks the five files whose `read_file` / `edit_file` / `write_file` traffic occupies the most context, beside the tool ranking it already had. Underneath all of it, every model context is now assembled whole from the Agent State as it stands when the context opens — an edit made mid-conversation takes effect at the next compaction rather than the next Session — under three explicit tiers: strict (the byte-fixed request prefix), soft (the thinking level) and unrestricted (the approval mode).

![The context panel: a bar scaled to the model window with a draggable compaction cutter, and the Top 5 files view](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/context-panel.png)

**A shortcuts ball on the edge of the conversation.** While no dock surface is up, a translucent round button floats just inside the right edge of the chat body under a "Shortcuts" caption; a click fans its entries onto a tight semicircular ring — one per dock panel plus a terminal, glyphs alone, each name read out by that same caption — and picking one opens that panel, at which point the ball goes away. The workbench had been reachable only through the toolbar's toggle, which a narrow window made easy to miss entirely. The ball drags along the edge and remembers where you left it, the pending-approval dot rides it, and the arc's last entry puts it away for good, with an Appearance setting to bring it back.

![The shortcuts ball on the conversation's right edge, fanned open into a semicircular ring of panel entries](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/shortcuts-launcher.png)

**Scheduled tasks moved into the conversation.** A new dock panel lists the tasks bound to the Session you are in, with search, state filters, a plain-language schedule line ("Every day at 08:00 · Next: tomorrow 08:00"), enable switches, an edit/delete menu for owners and a suggestions list. Its header carries the create pair: **Create with AI** composes the request and writes it into *this* conversation's composer — nothing is posted, so pressing Send stays your move — while **Create manually** opens the form pinned to this Session. A Session holding an enabled task that still has a next fire time wears an alarm clock on its sidebar row, and saving a task no longer claims it "takes effect in a new conversation": a task fires on the scheduler's clock, with no conversation involved.

![The scheduled-tasks panel in the dock with its Create with AI and Create manually buttons, and a sidebar session row wearing an alarm clock](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/schedule-panel.png)

**Hooks are a capability of the loop, and goal mode is a plugin.** Core codes the hook *points* — **stop** (the moment a Task ends), **pre_tool_use** and **user_prompt** — and the hooks themselves arrive as hook packages: plain Node scripts installed into `agent_state/hooks/` beside the skills. Goal mode left core entirely and became the `goal` plugin's stop hook, ralph-loop style, over a state file the hook rewrites after every Task; a second package, `continual-learning`, hands a long Task's findings to a background subagent. The skill library became a **plugin library** — one npm package per plugin, skills and hook packages inside, dated versions, a detail Modal with a file browser over everything a plugin ships. On top of that the Agent settings gained a **Hooks** tab with one Agent-level enable switch (the shape Skills already had), zip export and re-import, and the Skills tab's chat-import dialog, which takes a URL, a repository, a local path, a description or another tool's hooks config and previews the prompt it will hand the agent.

![The Agent settings Hooks tab: the enable-switch card, a package row with hook-point chips, and the import dialog entry](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/hooks-tab.png)

**Create with AI, as a kit.** Every object the Web App creates from a form is getting a second path — describe it to an agent — and this release ships the shared machinery behind it: the accented **Create with AI** button beside a plain **Create manually**, the prompt panel with clickable examples and a folded full-prompt preview, and the dialog that hands the composed prompt to the Project's default agent as a prefilled draft. The dialog has exactly one way out, **Edit in a new conversation**, and nothing is ever sent automatically. The Skills tab's import-via-chat, the Memory tab's add and edit jumps, and the new Schedule surfaces all go through it. This is the kit; the remaining creation surfaces wire it up in their own changes.

![A page header's Create with AI and Create manually button pair, with the Create with AI dialog open over it](https://raw.githubusercontent.com/Prism-Shadow/penguin-harness-community/main/releases/0.2.10/create-with-ai.png)

**A server on another machine, two ways.** There is now an official container image — Docker Hub `hiyouga/penguinharness`, built from this repository's source for `linux/amd64` and `linux/arm64`, running `penguin server` on `0.0.0.0:7364` with its data root on a `/data` volume, as an unprivileged user under `tini`, so a deployment is one container and one volume. It publishes exactly two kinds of tag and nothing that moves under a second name: `latest`, rebuilt on every push to `main`, and `X.Y.Z`, built from that release's own tag. A Docker quickstart documents the first sign-in through the log, upgrading by pulling a new tag, reverse proxies and the forgotten-password rescue. Alongside it, the **Machines** family grew up: what this server installed on which host moved from a JSON file into `web.db` and now belongs to a Project, every machine mints a 16-character id of its own and answers `penguin server status` / `penguin server stop` over ssh, and everything this server says to a machine rides **one** held `ssh -T -D` session per machine — commands, the installer, the tarball and a SOCKS channel through the same connection. A connected machine's API answers same-origin at `/server/<machineId>/api/…` as that machine's admin; connecting a machine hands it the Model credentials of the Projects that use it; and a machine already on this release but carrying different pushed state is a hot update over its own update channel rather than a reinstall, with Restart as a control of its own.

**The model catalog moved a long way.** DeepSeek released V4.1 Flash under the bare id `deepseek-flash`, and it is now the model a new Project starts on — a 1,000,000-token window, image input, CNY 0.04 / 2 / 8 per million tokens at peak and half that outside Beijing weekday 09:00–12:00 and 14:00–18:00 — with the resold rows on TokenDance and OpenRouter arriving in the same read. Gemini 3.8 Flash joined directly and on OpenRouter, and every Gemini 3.x Flash row now stores its list price and declares Google's launch discount rather than baking it in, which corrected two rows that were billing the wrong figure. GPT-6 Astra joined direct and on OpenRouter, ByteDance's three Doubao Seed models joined the TokenDance group, and a new **vLLM** group carries the eight self-hosted models AgentHub's vLLM adapter has a thinking switch for — priced at a real zero, with no base URL, and with the protocol pinned by the group so a `Qwen/*` or `deepseek-ai/*` id cannot be routed to the wrong vendor's client.

**A rejected tool call explains how to fix itself.** A model that named the shell text `command` instead of `cmd` had every `exec_command` call rejected with a one-line "missing argument", and typically re-issued the same call unchanged; `exec_command` now accepts either spelling, and every built-in tool that rejects a call for its arguments answers with a full correction guide — the fault, the argument names it received, the ones it does not declare, its parameters restated from the schema the model was handed, and the shape of a correct call. Separately, `read_image` and `describe_image` folded into `read_file`: an image file or an http(s) URL comes back as image content when the Session's model reads images, and as the Project's vision model answering a new optional `prompt` when it does not — everything the two tools did, behind one name and one schema.

## Notable in this release

- **What upgrading asks of you: one restart for one kind of user, and two clicks.** This release carries the first restart-only schema migration (`drop-goal-state`), so whoever *hot-pushes* this platform onto a running runtime must restart the server first — the push is refused before it touches the database, with the migration named. An ordinary install, package update or app restart applies it at open and needs nothing. Two things are worth a click: goal mode on an Agent that existed before this release answers `409 goal_plugin_not_installed` until the `goal` plugin is installed on it once from the plugin library, and the kernel version advanced to `2026-09-10` — an existing Agent reads images through `read_file` as soon as it tries, but is only *told* so after a kernel update, and until then a model still calling `read_image` / `describe_image` gets the unknown-tool reply and image reads run under the stored 30 s timeout. Scripts that create Agents with `skills` / `--skills` change to `plugins` / `--plugins`. API clients: `GET …/usage` no longer returns `errors.clearable` (read `errors.total`), `DELETE …/usage/errors` requires both date bounds, `POST /api/version/update` answers at once with a job status instead of blocking, and the machines routes moved under a Project — a server that installed on machines under 0.2.9 comes up with an empty list and re-installs from the Project that should own them. Downgrading to 0.2.9 still works. See [`2026-09-02-backward-compatibility`](2026-09-02-backward-compatibility.md) and [`2026-09-02-backward-compatibility-read-file-images`](2026-09-02-backward-compatibility-read-file-images.md).
- **Updating runs through one dialog** — check, the release with its notes, **Download and update**, a real progress bar with **Continue in background**, then **Restart and update**. The server self-update became a background job the CLI supervises, so `penguin server` and `penguin web` relaunch the service onto the newly installed release instead of ending in "restart the service by hand"; the desktop shell no longer downloads on its own.
- **A slow turn says what it was waiting on.** The chat header's details card and the Trace view print each duration with its two components — `Elapsed 10.3s (API 5s, tools 5.3s)` — API time being time inside LLM requests with the approval wait deducted, tool time being the union of the tool intervals so parallel tools count once.
- **The sidebar says which conversations still have something running.** A row whose Session started a dev server or a background subagent carries an activity trace beside its status glyph, the chat header counts the same tasks in a pill, and both follow a new live `session_background` event rather than a list refresh. The same mark sits on the tool row of any call made with `run_in_background`.
- **A compaction shows its work.** The compaction row became a running work group: its title doubles as the status (Compacting, then Compacted) and carries the wall time, and while it runs the request's thinking streams into one disclosure row and the summary into another beneath it, each with its own timing.
- **An LLM request times out on silence, not on length.** `model.timeoutMs` is an idle budget between upstream events, now documented as such and defaulted to 300000 — a model that keeps its reasoning off the wire used to put its whole thinking phase into the single gap before the first event. Every request now asks for thought summaries, and the retry ladder resets on an attempt that received any content at all, under a separate ceiling of 20 attempts per turn.
- **A queued steering message survives an interrupt.** Text steered into a running Task and never delivered is handed back and returns to the composer with its images and attachments, rather than being dropped with the run; a reload restores it too.
- **The sidebar lists every Workspace**, not only the ones its first pages of conversations happened to touch — the group list is built from the server's per-Workspace counts, so a Workspace whose newest conversation is older than an Agent's ten newest still appears, and asks for its own first page when it scrolls into view.
- **The Trace panel prices each request at the tier it ran in**, with the cost center's own rule, so a Session's Trace files finally add up to what the toolbar and the cost center report for the same requests.
- **An Agent's `penguin` is the harness running it.** The server writes a launcher into `<root>/bin/penguin` and puts that directory at the front of PATH for every command a Session spawns — in the child environment and again as a statement in front of the command, because a login shell's profile rewrites PATH after the fact.
- **Clearing error records names its range** the way the picker does, and takes exactly the rows the panel listed — the trailing presets narrow to their instant window, and an admin's clear now includes the unattributed rows an admin's panel shows.
- **Terminals behave like terminals.** A URL and a program-written hyperlink both open where they point (and a click inside a full-screen program works at all, since links are now decided by position rather than by object identity across a redraw), a program's own copy reaches the system clipboard through OSC 52, and Ctrl+W closes the focused terminal after a confirmation.
- **Copy Session ID** is an action on the Session row itself — the ellipsis button or a right-click — labelled the same as the details card's copy button and placed between archive and delete.
- **Every dialog holds keyboard focus and hands it back.** The `Modal` primitive traps Tab and Shift+Tab, restores focus on every close path, and carries `role="dialog"` with a name taken from its own heading; only the headerless variants had any of that.
- **The frontend is compressed on the way out** — brotli or gzip negotiated per request, cached against the ETag, `Vary` sent on every response that could have varied. On the current bundle, 1229 KB → 329 KB.
- **Schema changes are ordered migrations**, stamped into `PRAGMA user_version`, each with frozen DDL and a declared `down` (or an explicit `null`); a hot-pushed platform applies only the `swapSafe` ones and refuses the rest whole, before touching the database.
- **Memory files keep one order whatever locale the server runs under** — the topic-file comparator no longer follows the process locale, so the same scope exported on two hosts produces the same document.
- **The discount badge says what it means**: `50% off` / `省 50%`, in place of a bare `-50%`. The sidebar's marks were corrected in the same spirit — a history glyph for the last conversation, a robot with a face for Agents, a brain for the model library, two people for Project members — and the Agents page's update notice keeps its distance from the list.
- **The landing page** alternates "auto-dev" and "auto-tuning" in its headline (自动开发 / 自动调优 in Chinese), and draws the app's own Agent glyph rather than a second version of it, pinned by a test that fails when only one of the two moves.
- **The docs gained a Security Model page**, organized as the scenarios a user meets in order — first login, changing a password by each of its four paths, local automation, remote machines, taking access away — and ending on the leak-response case the design is built around: a leaked data-root backup is a credential-rotation incident for the model keys in it, not a forged-session incident.
- **Under the hood**: the CI runtime artifact now carries the Web App and packing without it fails outright; the server prints and checks its web dist instead of answering a bare 404; skill-archive caps are enforced from the zip's central directory before an entry inflates; the terminal stream suite kills each test's shells before the next; the default system prompt tells an agent to search from `CWD` down rather than widening to the whole disk; and AgentHub moved to 0.4.11, which is what makes a large screenshot readable on GPT-5.6, the vLLM adapter available, and `gpt-6-astra` routable.

## Requirements

Linux or macOS (x64 / arm64), or Windows 10+ (x64). The desktop app and the CLI installers bundle their own runtime; installing from npm needs Node >= 24, or the official Docker image, which carries its own. All data stays under `~/.penguin/data` — the `/data` volume in the container.
