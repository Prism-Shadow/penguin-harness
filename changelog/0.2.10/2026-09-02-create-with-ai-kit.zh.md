# Web App 共用的「用 AI 创建」组件包

- **Date:** 2026-09-02
- **Type:** feature
- **Scope:** `web`, `docs`
- **PR:** [#583](https://github.com/Prism-Shadow/penguin-harness/pull/583)

[English](2026-09-02-create-with-ai-kit.md)

Web App 里凡是通过表单创建的对象，都将多出第二条路径：向 Agent 描述它。本次改动加入了这条路径背后可复用的组件包——分别通向两条路径的一对按钮、带可点击示例与折叠完整提示词预览的提示词面板，以及把拼好的提示词交给 Project 默认 Agent、在新对话里预填为草稿的弹窗。各创建页面在各自的改动中接入。

## 细节

- `features/ai-create` 导出桥接 hook（`useAiBridge`）、纯函数的草稿构造、默认 Agent 的选取（`default_agent`，否则取第一个）、提示词拼接、`AiCreatePanel`、`AiCreateModal` 与 `CreateButtons`；`MAGIC_WAND_ICON` 与 `HAND_ICON` 字形加入 `components/ui/icons.tsx`。
- `CreateButtons` 渲染两个分开的按钮，而不是分体式控件或模式切换：先是带魔法棒、取强调色的**用 AI 创建**，再是浅色带手形的**手动创建**。两条路径同时可见；不提供手动路径的页面省去第二个按钮即可。
- 弹窗只有一个出口——**在新对话中编辑**，且不会自动发送任何内容：拼好的提示词落进新对话的输入框，按下发送始终是用户自己的动作。
- 技能标签页的「经对话导入」与记忆标签页的「经对话新增 / 编辑」跳转改走同一座桥；记忆标签页的跳转现在也会先把已输入未发送的草稿文本停放起来，而不是覆盖它。
- 提示词输入框改用较小的控件字号，长草稿在弹窗里也看得清；**完整提示词**预览展开后与上方示例左对齐（`HelpFold` 新增 `flush`，供正文是一个块而非一段散文时使用）。
- 拼好的提示词不再比它所引出的草稿活得更久。它写入草稿缓存时带上「由 AI 拼成、非用户键入」的标记：既不编辑也不发送就离开草稿页时清空该槽位（只保留模型延续，与发送后一致），后续再次跳转时直接丢弃、而不是把它停放为一条草稿对话。用户一旦编辑，它就成为用户自己的文本，与其他草稿一样缓存与停放。
- Web App 文档以双语描述了该模式。
