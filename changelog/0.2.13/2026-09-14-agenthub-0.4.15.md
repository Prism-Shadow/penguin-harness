# AgentHub 0.4.15: a turn that runs two tools in parallel survives a gateway that interleaves the calls

- **Date:** 2026-09-14
- **Type:** fix
- **Scope:** `core`, `cli`
- **PR:** [#720](https://github.com/Prism-Shadow/penguin-harness/pull/720)

[中文版](2026-09-14-agenthub-0.4.15.zh.md)

`@prismshadow/agenthub` moved from 0.4.14 to 0.4.15 (agenthub [#218](https://github.com/Prism-Shadow/agenthub/pull/218)). A turn that calls two tools in parallel through a Responses gateway that opens every call before closing any of them — Console Go streams that order — no longer loses the whole turn one request later with `400 … No function call found for function_call_output with call_id 'call_…'`.

## Details

- The four Responses clients (`openai_responses`, `gpt6`, `deepseek_v4`, `minimax_m3`) accumulated a response's function calls in a single slot, so the second call's opening overwrote the first. The assistant message then replayed only the surviving call while both tool results were replayed, and the provider rejected the orphan; the engine classified that as a provider 4xx and the Task stopped. AgentHub now carries an `item_id` on each `partial_tool_call` fragment and keys its open calls by it, falling back to the previous single-call behaviour for a server that sends none.
- `pnpm-workspace.yaml`'s `minimumReleaseAgeExclude` entry names 0.4.15 in place of 0.4.14.
