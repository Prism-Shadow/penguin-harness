# AgentHub 0.4.15：并行调用两个工具的轮次不再被交错返回的网关弄丢

- **Date:** 2026-09-14
- **Type:** fix
- **Scope:** `core`, `cli`
- **PR:** [#720](https://github.com/Prism-Shadow/penguin-harness/pull/720)

[English](2026-09-14-agenthub-0.4.15.md)

`@prismshadow/agenthub` 从 0.4.14 升到 0.4.15（agenthub [#218](https://github.com/Prism-Shadow/agenthub/pull/218)）。经由先打开全部调用、再逐个关闭的 Responses 网关（Console Go 正是这种顺序）并行调用两个工具的轮次，不再在下一次请求时整轮丢失于 `400 … No function call found for function_call_output with call_id 'call_…'`。

## 详情

- 四个 Responses 客户端（`openai_responses`、`gpt6`、`deepseek_v4`、`minimax_m3`）用单个槽位累积一次响应里的函数调用，第二个调用的打开覆盖了第一个：随后的 assistant 消息只回放幸存的那个调用，两个工具结果却都被回放，提供方拒绝了孤立的那条，引擎把它归为提供方 4xx，Task 就此停住。AgentHub 现在给每个 `partial_tool_call` 片段带上 `item_id` 并据此区分打开中的调用，服务端不发 id 时退回原先的单调用行为。
- `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 条目改为 0.4.15，取代 0.4.14。
