# 同步预置后模型名不再丢失

- **Date:** 2026-09-11
- **Type:** fix
- **Scope:** `web`, `server`
- **PR:** [#679](https://github.com/Prism-Shadow/penguin-harness/pull/679)

[English](2026-09-11-catalog-sync-display-name.md)

通过 Models 页的「同步预置」按钮加入 Project 的模型，保存时不带显示名，列表里只显示原始 model id，
再同步一次也找不回名字。现在同步构造的行会带上内置目录中的名称，并为任何没有名称的预置行补上它，
从而修复此前同步已经写坏的 Project。

## 细节

- 模型接口区分「字段缺失」与「空字符串」。缺失表示「沿用内置目录给这个模型的名称」；空字符串表示
  用户清空了名称，磁盘上也只有它记录这次删除。此前路由层在服务层看到之前就丢弃了空字符串，服务层
  只能把「字段缺失」当作有意清空——于是一个只是拿不出名称的客户端，会清空它所提交的每个目录模型的
  名称。
- `GET /projects/:id/models` 把已清空的名称报为空字符串，而不是报成没有名称，使整张表在下一次 PUT
  回传时仍然表示「已清空」，而不是转而索取目录里的名称。
- 「同步预置」只填补空缺的名称，已有名称一律保留：与价格、上下文窗口不同，存下来的名称可能是用户
  自己的重命名。代价是用户特意清空的名称会在下一次同步时被重新填上。Models 导航徽标按同一规则计入
  这项修复，因此徽标与按钮对「是否还有内容需要同步」仍然口径一致。
- 用户主动同步之前，既有配置文件不受影响：`display_name = ""` 的含义仍是「已清空」，在 Models 页上
  的普通保存也会保留它。
