# 工具链：开发用数据根目录与已安装的分离

- **Date:** 2026-07-24
- **Type:** fix
- **Scope:** `tooling`
- **PR:** [#67](https://github.com/Prism-Shadow/penguin-harness/pull/67)

[English](2026-07-24-tooling.md)

从源码运行 server 或 CLI 时，此前操作的是与用户真实安装的 penguin 完全相同的数据：core 的 `resolveRoot()` 返回 `PENGUIN_HOME ?? ~/.penguin/data`，而开发入口不设置任何值，于是 `pnpm dev` 与生产安装共用 Agent、会话与 `web.db`。现在开发入口——`pnpm dev`、`pnpm dev:server`、`pnpm penguin`，以及 packages/cli 自己的 `penguin` 脚本——通过脚本内部的 POSIX `${PENGUIN_HOME:-…}` 替换，把 `PENGUIN_HOME` 默认指向一个独立的开发数据根目录 `~/.penguin/dev-data`。显式导出的 `PENGUIN_HOME` 仍然优先，产品侧的默认值——`resolveRoot()`、服务端配置、CLI 的 `--root`——均未改变：隔离只存在于开发脚本中，因此已安装的 penguin 依旧使用 `~/.penguin/data`。CONTRIBUTING.md 的开发命令小节与安装文档（中英）记录了这个开发根目录。
