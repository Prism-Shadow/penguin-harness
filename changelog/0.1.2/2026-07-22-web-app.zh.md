## Workspace HTML 预览改为在独立源上打开

Workspace 中 html 文件的「在新标签页打开」此前是从应用自身的源、在一个没有 `allow-same-origin` 的 CSP 沙箱下提供页面。这确实让 Agent 生成的标记远离了会话 Cookie 与 API，但也把该文档置于不透明源中，于是 `localStorage` 与 `document.cookie` 会抛出 `SecurityError`，页面上任何第三方嵌入——分析、聊天挂件、地图——都彻底失效。基于查询参数的 URL 还有第二个问题：页面的相对子资源会解析到 `/api/sessions/<id>/files/<name>`，而这个路由并不存在，因此多文件的生成式应用永远加载不了自己的 CSS 或 JS。

预览现在在**独立源**上以基于路径的 URL 打开。链接指向 `GET /files/preview-redirect?path=`，它先对调用方鉴权，再签发一个绑定了 Session、预览主机与过期时间的短时效 HMAC token，然后 302 到 `/preview/<token>/<path>`。本地开发时，应用被规范化到一个环回名（`localhost`），预览则由另一个（`127.0.0.1`）提供——Cookie 以主机为键且忽略端口，因此这确实是两个独立的 Cookie 罐，而换个端口做不到这一点。真实部署设置 `PENGUIN_PREVIEW_ORIGIN`；两者都没有时，重定向回退到旧的同源沙箱，`GET /api/me` 上的 `previewIsolated` 报告 `false`，因此文件面板会标注该链接，而不是让页面无声地坏掉。

由于现在的隔离边界是源，预览响应不再剥离 `allow-same-origin`：页面获得正常的源，存储与 Cookie 可用，嵌入也能运行。有若干细节保证了这样做的安全性。应用与预览源是同一个进程上的两个主机名，因此预览主机被锁定为只服务 `/preview/*`：它的 `/api` 回 `401`，所有应用路由都 `302` 到规范主机，因此会话 Cookie 绝不会在那里被设置或被接受——否则预览源上的 Agent HTML 就能同源调用 `/api`，以用户身份行事。token 绑定了预览主机，而 `/preview/...` 拒绝在应用源上提供服务；缺了这一条，这就会变成一个具备完整 API 权限的同源 XSS。响应携带 `Referrer-Policy: no-referrer`，否则带 token 的 URL 会经由 `Referer` 泄漏给正是本次改动所启用的那些第三方。而路径在服务端仍会针对 Workspace 重新解析，因此 `..` 与符号链接逃逸依旧被拒；错误的 token、过期的 token、错误的主机与越界路径，一律回以一个光秃秃的 404。

预览 URL 的端口取自服务端自身的绑定，而不是浏览器当前的源。二者在开发环境下并不相同——SPA 跑在 Vite 的端口上，只有 `/api` 被代理——因此从请求推导会指向一个根本不提供 `/preview` 的端口，标签页会连不上。生产环境下两者重合。只有绑定到环回名（`127.0.0.1` / `localhost`）时才提供环回预览；通配绑定（`0.0.0.0` / `::`）或某个具体的非环回地址没有可达的对应物——`localhost` 可能解析到 `::1`，而 `0.0.0.0` 绑定从不服务它——因此这些情况会回退并必须设置 `PENGUIN_PREVIEW_ORIGIN`，而不是在 `/api/me` 声称已隔离的同时指向一个死地址。

该链接是一个带 `rel="noopener noreferrer"` 的普通锚点，而不是先 fetch 再 `window.open`：在 await 之后开标签页会触发弹窗拦截，而脚本打开的窗口会保留一个指回应用的 `opener` 句柄——这恰恰是独立源要杜绝的那个引用。服务端还同时绑定 IPv6 环回，因为 `localhost` 常常优先解析到 `::1`，否则每个预览 URL 都会拒绝连接。

应用内的渲染视图现在也走同一道门。它此前把文件文本经 `srcdoc` 喂进 iframe——那是一个没有真实 base URL 的文档，因此页面的相对子资源（`foo.png`、`app.js`、`style.css`）永远解析不了——而「在新标签页打开」早已在预览源上提供真实 URL。在隔离可用时，文件面板的 iframe 现在加载同一个 `preview-redirect` URL，于是相对资源可解析、页面存储在面板内也能工作，并处于一个沙箱之下（`allow-scripts allow-same-origin allow-forms allow-popups allow-modals allow-downloads`——现已在文档中逐项列明），该沙箱严格严于不带沙箱的新标签页；隔离不可用时，旧的 `srcdoc` 回退与其警告保持不变。源文本在首次切换到「源码」时才惰性拉取，因此大文件不再被下载两次，而一次瞬时的拉取失败也只影响源码视图。

针对隔离信号的后续加固：`previewIsolated` 在界面登录之后重新拉取，而不是沿用挂载时的取值，因此没有独立源的部署不会在用户经界面登录后把面板送上隔离路径；服务端还会拒绝主机名与应用自身相同的预览源配置——Cookie 忽略端口，因此端口不同并不隔离任何东西——此时在 `/api/me` 上报告 `false` 并启用安全回退，而不是给一个同源文档授予 `allow-same-origin`。

## 统一的表单控件、单一的通知规则，以及去重的文案

表单控件层已经长出五份近乎相同的脚手架副本。现在一个共享的 `Field` 包装器拥有标签 / 提示 / 错误的标记结构，一个共享的 `controlBase` 类名串拥有边框、悬停、聚焦环与深色模式处理，因此 `Input`、`Textarea`、`Select`、`OptionMenu` 与 `PasswordInput` 全都从同一处读取，而不再各自携带一份。`Select` 去掉了手写的开合与定位副作用，改为复用 `OptionMenu` 早已在用的同一个 `usePortalPanel` hook，于是两种菜单都经同一条代码路径实现上下翻转、按视口收敛，以及在滚动/Esc 时关闭。在 `Modal` / `Drawer` / `Sheet` 中重复三遍的关闭按钮合并为单个 `CloseButton`，而在十来处调用点内联的 chevron、对勾与加号图形也变成了共享图标组件。Agent 运行时标签页中的思考等级与压缩模式下拉框去掉了各自的「重置为默认」链接（一个 `ResettableOptionMenu` 包装器），改用朴素的 `OptionMenu`——那个链接只是回退了本次会话内的选择，而关闭对话框本就能做到这一点。

通知现在遵循单一规则。普通结果——一次保存、一次「已是最新」、一次连接失败——以从顶部滑入并自行消失的 toast 呈现；toaster 在成功与错误之外新增了用于中性消息的 `info` 色调。针对某个具体字段的取值错误不再落在表单底部一条通用的红色文字里：出错的输入框变红，其消息直接位于其下方，因此提交失败时视线会径直落到需要修改的字段上。所有创建/设置类表单都迁移到了这个划分上——必填、格式与不匹配类错误改为行内呈现，临时拼凑的绿色「已保存」横幅与瞬时操作失败改为 toast——而那些与「重试」按钮配对的页面加载失败状态仍保留为行内，因为在那里用会消失的 toast 是错的。

针对该规则的审查加固：行内错误文字现在会向辅助技术播报——`FieldError` 带 `role="alert"`，每个共享控件通过 `aria-describedby` 关联其消息，这一接线在控件层做一次、所有表单继承。`Select` 与 `OptionMenu` 获得了与文本输入相同的 `error` 属性（红色边框 + 下方消息），因此失败的下拉框也参与其中。而服务端的拒绝现在会落在其**错误码**所指的字段之下——修改密码与创建用户对话框此前把每一种拒绝都钉在同一个硬编码字段上，于是「新密码过短」会渲染在「当前密码」/「用户名」之下。

i18n 词条经过精简与去重：移除 41 个死键，并把约两打在两种语言下完全相同的取值（Name、Username、Role、Actions、Created、Cost、Time……）折叠进共享的 `common` 键，使一个标签只定义一次。英文文案中位于句中的 "Agent" 改为小写 "agent"——它是普通名词，只在标签或句子开头才大写——而领域术语（Workspace、Token、Task、Session、Project、Trace）与专有名称（Agent State、AgentHub）保留大写。

## Skill 更新覆盖安装前先确认

更新一个 Skill 安装——卡片上的旋转按钮，或管理安装对话框中逐 Agent 的「更新」——会把库中的副本重装覆盖到该 Agent 的文件上。这个覆盖会静默丢弃对已安装 Skill 的任何本地修改，既没有确认，也（不同于 Agent State 导入）没有快照。它现在会先弹出确认对话框：列出每个受影响的 Agent 及其 `v_old → v_new`，警告覆盖会丢失本地修改，并建议必要时先导出备份。背后是一个共享的 `ConfirmModal`（取消 / 确认页脚，危险或主要色调），可供日后的确认场景复用。已有的破坏性操作本就有确认（删除用户 / Agent / Project / 会话 / vault 条目 / 定时任务），而 Agent State 导入仍会自动快照并在版本冲突时额外确认——这些均未改变。

## 本地化的错误提示、完整的错误细节，以及必填标记

服务端的 `{error:{code,message}}` 消息只有英文，因此中文界面的用户会看到前端未映射内容的未翻译文本——而当时只映射了两个错误码。`apiErrorText` 现在经由新的 `S.errors.byCode` 表本地化约两打常见错误码（认证、权限、未找到、id 已被占用、文件/路径、任务进行中、版本冲突……），仅对未映射的错误码回退到服务端原始消息，而此前直接展示 `e.message` 的每一个错误呈现处现在都经它转换。（那条声称服务端消息是中文的过时注释已修正——它们是英文。）

成本中心的近期错误表此前把每条消息截断为一行，完整文本只能通过悬停标题看到，因此一次请求失败只显示了开头——例如 `llm request error: 402 openai_error`——把 Provider 真正的原因切掉了。每条消息**默认仍只显示一行**（错误风暴不该塞满表格），但**点击即可就地展开完整文本**（再次点击收起）；完整文本同样保留在悬停标题里。服务端至多保留 500 字符；完整栈仍在日志中。

必填表单字段现在在标签后带一个红色 `*`，使必填与选填一眼可辨。该标记由共享字段控件（`Input`/`Textarea`/`Select`/`OptionMenu`/`PasswordInput`）上的 `required` 属性驱动，它同时设置 `aria-required`，但刻意不透传原生的 `required` 属性（应用在提交时校验；浏览器的气泡提示会与行内字段错误冲突）。

## 侧边栏：会话列表只加载活跃会话；文件夹点击时才加载并各自分页

由子 Agent 与定时任务创建的 Session 本就位于各自带标签、默认折叠的文件夹中（Subagents / Scheduled），因此在每个标题旁重复的小来源徽章只是噪音——已移除。

列表的拉取逻辑与它的「更多」入口也被解耦了。服务端分页此前对来源无感知：一页 20 条可能全是子 Agent / 定时 / 已归档的行，而它们都消失进折叠的文件夹里，于是可见的活跃列表依旧很短，而「更多」还一直显示（或者更糟——被这类页面挡在后面的活跃会话变得不可达，因为首页中没有活跃行的分组根本就不提供「更多」）。会话列表端点现在接受一个 `category` 过滤器（`active` / `subagent` / `schedule` / `archived`，与侧边栏渲染时所用的「归档优先」优先级一致），外加可选的 `counts=1` 以获取分类总数，侧边栏的一切都以此为准：

- 默认加载只拉取**活跃**（用户创建、未归档）行——每页 10 条，「更多」每次加载 10 条——外加各分类总数；已归档、定时与子 Agent 会话不再预先加载。
- 分组的「更多」只统计**外层的活跃行**（折叠的文件夹从不喂给它），而由于它拉取的页面已按分类过滤，因此每次点击都能让可见列表整整增长一页。
- 折叠的文件夹依服务端总数标注数量，并在**首次展开时**拉取第一页。展开之后它以自己的「更多」行独立分页——每个分组与每个文件夹各自推进，不会替其他部分拖入页面。
- 带计数的响应还会**按 Workspace 路径**拆分总数，因此每个分组——包括 Workspace 分组——只为**属于自己的那一份**显示文件夹：标签计数精确，且只在这一份尚未加载完时才显示「更多」。（最初 Workspace 分组是依逐 Agent 总数推断其文件夹的，于是某个 Agent 位于**其他** Workspace 中的子 Agent / 定时会话，会让不相关的分组长出一个空文件夹，而点击其「更多」会让整个文件夹消失。）
- 审查后续改进：分页游标改为每一对的**已拉取行数**，因此被 `add()` 塞进列表的深链行不会再让下一页跳过一条服务端记录；被点击的「更多」在其拉取期间会禁用并显示「加载中……」（在 Workspace 模式下，一页可能整页落进其他分组——这次点击仍要让人看到有反应）；而服务端在**发现流程已有的同一次目录遍历**中定位每个 Session 最早的 Trace 分片，因此 `counts=1` 的分类不再为每个 Session 重新遍历一遍 Traces 树。

不预加载文件夹内容带来一个后果：在 Workspace 分组模式下，如果某个 Workspace 已加载的会话全是已归档或自动化创建的，它就不再自行构成一个分组（没有可见内容可以挂靠）；其会话仍可通过 Agent 分组模式的文件夹到达。

自动打开的「上一次会话」现在也遵循单一规则。此前进入 `/chat` 而未指定 Session 时，取的是扁平列表中字面意义上的第一行（第一个 Agent 已加载的最新行——而非该 Project 的最新，且在深链之后还可能是一条已归档或子 Agent 的行），而收起态导航栏的入口只是跳过了已归档行。现在两者——以及删除后跳向相邻会话的行为——都选取已加载的最新**活跃或定时**会话：已归档行是用户主动隐藏的，而子 Agent 会话隶属于其父对话，因此二者都绝不会被自动打开。当被自动打开的会话由定时任务创建时，只有其所在分组的 Scheduled 文件夹会展开并加载；外层活跃列表的「更多」不受影响。

## 每个写文件的操作都先确认；空保存会明说

在服务端写文件的操作此前是混杂的：删除会确认，Skill **更新**会确认，但设置保存（AGENTS.md / 系统提示词、运行时参数、工具覆盖）、Skill **卸载**（它会删除已安装副本，包括本地修改）以及落在同名文件上的工作区上传，都是一键即执行。它们现在统一经共享的 `ConfirmModal` 先行确认，而该组件也做了改版：一张紧凑的卡片，**没有标题栏**——只有一个带色调的图标徽记来一眼定调（删除用红色警告三角，保存/覆盖用中性铅笔），消息位于其旁（每条消息自带其对象与后果），再加一对小的「取消/确认」按钮。原先的标题仍为辅助技术保留以命名对话框。所有既有确认（删除会话/Agent/Project/定时任务/vault 条目、模型对话框写入、导入版本冲突）都迁到了同一个组件上，因此各处确认外观完全一致。在已配置的名称下新增 vault 变量现在也会确认（它会覆盖一个不可恢复的值）；聊天内的快捷设置控件（审批模式、思考等级）刻意保持一键。

什么都没改就点保存，此前会静默无事发生（多数表单跳过请求；模型对话框甚至会报「已保存」）。现在每条保存路径都会检测这种空操作——Agent 设置各标签页、定时任务编辑对话框与模型编辑对话框——并显示一个信息 toast：「没有需要保存的更改」。

## 任务运行期间，聊天输入框可转向或排队

运行期间发送此前无处可去——输入框仍可用，但在任务结束前提交是空操作。任务运行时，输入区现在会做两件实事：**转向**（默认）把草稿以 `[user_steering]` 消息在运行途中投递，搭上模型的下一次请求；**排队**则经完整的正常组装路径把整份草稿——包括图片、Skill 与 @ 交接——带 `queueIfBusy` 发出，服务端予以保留，并在运行结束时作为普通的后续任务自动发送。模式在输入工具栏上新增的「更多设置」浮层中选择——这是一个可扩展的设置行面板，草稿状态下也可用，取代了此前在窄屏上会溢出的行内分段开关——该选择像侧边栏分组模式一样按用户记忆，因此运行状态下的一次发送直接依此执行。停止与发送也合并为一个按钮：输入框为空时它停止运行，一旦有内容就变为发送，并按记忆的模式转向或排队。工具栏本身现在是一个左右分列的行，其拾取器经共享的 portal 层渲染，因此面板在窄屏上绝不会被滚动的工具栏裁切。输给运行完成竞态的转向消息会回退到同一条完整发送路径。排队的后续消息能在中止与压缩中存活，并有一个由服务端驱动、可在刷新后保持的「已排队 N 条」提示位于输入框附近；一次成功的转向会显示一个轻量的排队提示，直到其消息出现在流中。转向消息在对话中渲染为随流的、用户样式的芯片——它们绝不会把 Task 切开——而运行中的占位文字会说明其投递方式。

## /model 把对话切换到另一个模型

在处于空闲状态的活跃会话中输入 `/model` 斜杠命令，会打开模型拾取器（与草稿拾取器相同的列表与分组，当前模型有标记）。选择另一个模型会以交接方式继续该对话：为同一个 Agent 在所选模型上开一个**新**会话，复用源会话的 Workspace 与审批模式，其第一条消息以成对的 `[model_switch_from]` 源信息块开头，写明源会话、其最新 trace 文件、工作区与此前的模型——模型需要更早的上下文时会自行从源 trace 读取。命令之后剩余的任何文本会像一次普通发送那样搭进第一个任务，新会话则显示一个「已切换模型」的横幅并链接回源会话。该命令会立即消耗掉自己的 token——Escape 与点击外部只是关闭，与 `/compact` 一致——运行状态在选择时会重新检查，而选择当前模型则是空操作。

## 活跃会话中的思考等级成为逐轮覆盖

活跃会话中只读的思考等级标签变成一个可编辑的拾取器，只列出各个等级。它以 Agent 配置中的等级初始化（经既有的 Agent 配置端点获取），在未被触碰时随任务不发送任何值——配置回退继续生效，因此会话中途修改配置仍然起作用。一旦用户选定某个等级，它就为该会话固定下来并随每个任务发送，且绝不写回 Agent 设置；草稿拾取器「切换即成默认」的行为未变。

## 工具卡片上的调用描述，以及会展示载荷的审批

工具调用卡片把模型撰写的调用描述作为折叠态标题的副标题展示，Agent 设置的 Tools 标签页则为每个参数中声明了该属性的工具条目新增一个逐行的调用描述开关。待审批区块会在一个可滚动的窗格中渲染解码后的文件工具载荷——`old_string` / `new_string` / `content` 与路径并列——而对 shell 工具，审批预览保留真实命令：用户批准的是实际改动，而不是模型对它的概括。文件工具预览把路径缩短为一层父目录加文件名；完整路径保留在展开的参数中。

## 免费模型带 Free 徽章

免费行——`:free` 变体与免费模型路由器——现在显示一个浅黄色的 "Free" 徽章，这是一个新的共享徽章色调，刻意与警告用的琥珀色区分开；它出现在模型页卡片上、默认与视觉徽章旁边，以及聊天模型拾取器中。由一个共享的 `isFreeModel` 助手判定：该条目必须带有显式定价且三个档位全为零，因此未定价或只有部分定价的行——它们的成本只是未知——绝不会被标为免费。
