## 落地页、README 与博客讲同一个故事，安装走 penguin.ooo/install.sh

各个对外表面现在讲同一套 1x/100x 叙事，用同一个编号式「Why」小节完成说服，并从站点自己的域名安装。

- **penguin.ooo/install.sh**——落地页站点提供一个瘦的 `public/install.sh`，转发到最新 GitHub Release 的安装脚本（GitHub Pages 无法提供真正的重定向），因此 `curl -fsSL https://penguin.ooo/install.sh | sh` 在任何环境下都能用；首屏命令、README（中英）、文档的安装/快速开始（中英）与博客文章全部切换到它。
- **落地页**——首屏用两行叙事取代了轮播词标题（"With LangChain, you build agents by hand — at 1x; with PenguinHarness, agents build agents — at 100x"，其中 100x 片段用品牌色），并配上 "zero-code Harness CLI and Web UI, 1000+ models" 的副标题。一个编号式的 Why 小节（1 基准测试套件 + DeepSeek 调优，2 一句话构建演示配真实 RAG 截图，3 自进化循环配「演示视频即将上线」标签）吸收了原先的 Pillars / Showcase / Benchmark / SelfImprove 四节；UI 截图撤出首页；导航锚点改为 why / quickstart / contract / features（理由 1 保留 #benchmark 锚点）。博客本就与落地页共用 Nav、主题与语言设置。
- **README（中英）**——副标题改为 "Harness CLI and Web UI"；website/docs/blog/community 链接渲染为 shields.io 徽章；顶部截图与 Changelog-Blog-Docs 小节移除；三条理由以编号加 emoji 排在「Why PenguinHarness」之下；模型表只保留一行「任意 OpenAI 协议端点均可」的说明；Requirements 改为表格；安装小节加上 emoji；路线图新增桌面应用与 Windows 支持；致谢链接 LlamaFactory、PrismShadow AI Team 与 Fable 5。

## 落地页 Trace 截图：中英文展示同一个已打开的时间线

英文版 Trace 截图显示的是「请选择一个 Session」的空状态，而中文版显示的是完整 trace；现在四张图都拍摄同一个已打开的 trace，带统计数据与包含工具调用的执行时间线。

- 截图脚本原先导航到 `/traces?sessionId=...`——但 traces 页面只有在 `agentId=` 同时存在时才会响应 session 深链（产品自身的链接始终两者都带），于是选中操作依赖于一次脆弱的标题点击，而该点击在英文下会被 `.catch()` 静默吞掉。脚本现在使用规范的 `?agentId=default_agent&sessionId=...` 深链，并在拍摄前等待时间线的 `exec_command` 泳道出现，因此空截图会显式失败而不是被发布出去。
- 脚本中的英文 Session 标题长 31 字符，而 core 在 `TITLE_MAX_CHARS = 30` 处截断标题，导致截图里出现 "…Agent ap"；mock 标题现改为 "Build a data-analysis Agent"（27 字符）。
- 重新生成了 `traces-{en,zh}-{light,dark}.webp`；聊天与基准测试截图未变。

## 落地页打磨：滑动公告、建造动画、趋势数值标签、功能拆分

对落地页的动效与分组做了一轮打磨，并把博客中的使用指引改为 Web 优先。

- **公告栏**——浅品牌色背景；两条公告现在都链接到博客文章（新模型那条指向发布文章，额度那条指向 AMD 文章）；改为横向滑动切换（自动轮播、悬停暂停），用圆点指示器取代箭头；尾部的箭头图标移除。
- **LangChain 对比**——共用同一循环周期的「建造」动画：LangChain 卡片一次砌一块灰色砖，在周期重置前永远封不了顶；而 PenguinHarness 卡片在两秒内拔起一整片品牌蓝的天际线并保持住。降低动效偏好下两侧天际线均直接呈现完成态。
- **自进化趋势**——三张结果图表现在由同一个 rAF 时钟驱动，每条曲线的移动端点上都骑着一个数值标签（分数上升，成本与时间下降），随线条绘制而变化；降低动效偏好下直接显示完成的线条与最终数值。
- **功能按截图拆分**——只有三个带真实截图的功能（多会话聊天、Trace 视图、Agent 评估）构成标签栏；其余六个以经典卡片网格排在下方，并以一张「and more…」卡片收尾。
- **博客使用指引改为纯 Web**——发布文章的入门部分与 AMD 文章的配置部分现在只引导用户走 `penguin web` 与模型页；CLI 的配置/运行替代方案被移除，以便把用户导向 Web UI。

## 公告轮播：单向滑动，保留箭头，去掉圆点

公告栏保留那个把每条公告标示为可点击链接的小箭头，去掉右侧的圆点切换按钮，并且只朝**一个**方向自动滑动轮播：第一条的克隆件跟在最后一条之后，当克隆件完全进入视野后，轨道无动画地瞬间归位——公告栏永远不会出现可见的倒退滑动。悬停仍然暂停轮播。

## 功能标签页去掉描述卡片

三个带截图的功能标签页不再在截图上方渲染一张图标卡片；该功能的一行描述现在作为居中文本直接置于图片上方（标签本身已经承载了标题与图标）。没有截图的功能保留下方的卡片网格。

## 趋势数值标签带上单位与动画小数

自进化循环的三个结果标签在骑着曲线端点移动时，现在读起来是真实的测量值：分数为带一位小数的百分比（79.0%）、成本为带两位小数的美元（$0.25）、时间为带一位小数的秒（83.0s）——小数部分随线条连续变化。

## 修复导航悬停高亮从边缘扫入的问题

落地页与文档站导航的滑动悬停药丸原先从其位于导航左缘的隐藏状态开始动画，因此第一次悬停会让一颗灰色药丸横穿整行链接飞过去（移开时又滑回去）。

该药丸现在**就地**出现在它落到的第一个链接之下——位置直接跳变，只有淡入有动画——在链接之间移动时才滑动，指针离开时则在原地淡出。落地页导航与和它对齐的文档站导航采用完全相同的处理。

## 合并 main 以恢复常驻的导航激活高亮

该分支的基线早于 main 的 [#6](https://github.com/Prism-Shadow/penguin-harness/pull/6)（「修正导航状态与锚点滚动」），因此缺少导航的常驻激活高亮——即标记当前小节或路由的黑色片——合并时本会把那个修复回退掉。合并 origin/main 使其恢复，并与该分支的导航改动做了调和。

- 落地页导航：小节链接重新经由 `/#id` 路由并配合 `getActiveNavItem` 跟踪（新增 `lib/nav-state.ts` 及其测试），激活链接保留带 `aria-current` 的黑色片，分支的就地悬停药丸行为则叠加保留。
- 同样从 [#6](https://github.com/Prism-Shadow/penguin-harness/pull/6) 恢复：锚点目标滚动到粘性头部之下（通过 `.section-anchor`，id 移到小节的内层 div 上）、页脚/首屏/CTA 锚点改为路由链接，以及文档站品牌 logo 回到落地页。
- 文档站导航（与落地页对齐的那套）另外会用同样的黑色片把自己的「Docs」链接标记为当前页。

## 导航高亮跟随实时滚动位置

导航的黑色当前项标记此前只根据 URL hash 更新（也就是点击时），滚动过程中它会一直保持陈旧。现在一个滚动侦测 hook 在每个滚动帧测量五个小节锚点（rAF 节流，文档级捕获以便任意滚动容器都生效），并点亮**最后一个**顶部已越过粘性头部下方激活线的小节——位于第一个小节之上时为 null，处于小节之间时保持上一个锚点点亮。首页上的高亮完全实时，其他路由仍使用基于路由的状态（Blog）。

## Cases 标签页展示成品 RAG 应用并使用本地化提示词

RAG 案例现在展示来自字符串词条的精简版 claude-code-docs 配置专家提示词（中英本地化），以及与访客语言和主题相匹配的成品应用截图，取代原先共用的英文提示词与 PenguinHarness 聊天截图。
