# 语言与主题在落地页和文档站之间保持一致

- **Date:** 2026-07-21
- **Type:** fix
- **Scope:** `landing`, `docs`
- **PR:** [#13](https://github.com/Prism-Shadow/penguin-harness/pull/13)

[English](2026-07-21-site-preferences-sync.md)

这两个站点是部署在同一源下的两个独立 SPA——penguin.ooo 与 penguin.ooo/docs/——但各自把偏好存放在自己的 `localStorage` 键下（`penguin-landing.*` 与 `penguin-docs.*`）。于是在其中一边选了深色模式或中文，再点进另一边，访客又被退回系统默认值，读起来就像设置被忽略了。

- 两个站点现在通过一个小的 `state/site-prefs.ts` 模块读写同一对共享键 `penguin-site.theme` 与 `penguin-site.lang`，该模块在两个包中各存一份（它们不共享任何包，这与 `theme.tsx`、`locale.tsx` 的现状完全一致）。两边的键必须保持完全一致；一旦漂移，同步会静默失效。
- 已废弃的各站点独立键仍会作为回退被读取，因此回访者会保留他们在这次改动之前做出的选择，而不会被重置一次。
- 一个 `storage` 监听器覆盖了两个站点同时打开的情况：现在在一个标签页里切换主题或语言，另一个标签页无需重新加载即可更新。站点之间的跳转本身是一次完整的页面加载，由挂载时的读取来处理。
- 文档站的绘制前主题脚本同样读取共享键，而原本没有该脚本的落地页也补上了一份。没有它的话，从深色的文档页跳到落地页会先闪过一次白色背景，然后 React 才启动。
- 对 `localStorage` 的读取全程做了包裹：在禁用 Cookie 和分区隔离的上下文中它会直接抛出异常，而一项偏好设置不值得让整个页面挂掉。

已针对组装后的站点验证（落地页位于 `/`，文档站位于 `/docs/`，同一源）：在落地页选择深色 + 中文后，跳转到文档站再跳回来该选择依然保持；在文档站一侧做出的修改也会反向传播；而一份只带有已废弃 `penguin-docs.*` 键的配置，仍然渲染为深色与中文。
