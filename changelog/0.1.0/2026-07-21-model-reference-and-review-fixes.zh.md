# 显式的模型引用二元组，以及一批审查修复

- **Date:** 2026-07-21
- **Type:** fix
- **Scope:** `core`, `cli`, `server`, `web`, `landing`
- **PR:** [#7](https://github.com/Prism-Shadow/penguin-harness/pull/7)

[English](2026-07-21-model-reference-and-review-fixes.md)

Provider 分组在任何地方都不再被自动解析——模型要么以完整的 `(provider, model_id)` 二元组引用，要么就不引用——同时对发布分支的一次代码审查又查出了一批正确性、可访问性与文档缺陷，这里一并修复。

- **Provider 绝不被推断、猜测或默认（core、CLI、server、web）。** 此前有两套机制会替用户挑选分组，现已全部移除。目录推断（`inferProviderForUpstream`）取的是第一个裸 id 匹配，而网关会以上游 id 转售厂商模型——`glm-5.2`、`qwen3.7-max`、`qwen3.7-plus` 与 `deepseek-v4-pro` 如今各自都属于两个分组——因此 `penguin config model add --model-id glm-5.2 --api-key <key>` 会把一个 Z.AI 凭证写到 Qwen Token Plan 的条目上，并发往阿里云的端点（而在上一个版本，同样的命令会解析到 `zhipu`）。配置解析（`resolveModelRef`）则是另一套：只要裸 `model_id` 在 Project 已配置的模型中恰好唯一，它就会匹配上。两者连同 `inferProviderForUpstream` 与 `providersForUpstream` 一并删除。现在到处都是**要么两半都给，要么都不给**：`config model add` 上 `--provider` 为必填；在 `run` / `chat` 上，这个二元组作为整体仍是可选的（两半都省略即使用 Project 默认），但只给一半是错误；`addModel` 与 `Agent.createSession` 在类型层面要求完整二元组；`POST /sessions` 与 schedule 路由对半个引用返回 400，而只持久化了 `modelId` 的 schedule 文件会被报为无效，而不是静默绑定到一个猜出来的分组。`run_subagent` 在 `model_id` 旁新增 `provider` 参数并拒绝半个引用，这样发起委派的模型也无法把子 Agent 落到错误的厂商上。Trace 查看器不再为打标签之前的 trace 按首个匹配猜测归集成本，而是不显示成本。CLI 帮助、CLI/模型/服务端 API/快速开始/配置/接口文档（中英）、README 以及每个会脚本化调用 CLI 的 Skill 均已更新为传入完整二元组。
- **Escape 不再清空输入框（Web App）。** 斜杠菜单的 Escape 处理会清掉整个输入内容——在菜单只对以 `/` 开头的草稿弹出时这是正确的，但本次发布中菜单改为按位置弹出，于是从草稿中间的某个 `/token` 处按 Escape 会摧毁此前输入的一切，且不可恢复（textarea 是受控组件，撤销也救不回来）。现在 Escape 只关闭菜单，通过一个 `slashDismissed` 偏移量与 `@` 提及的行为保持一致。另外，`removeSlashToken` 原本会折叠剩余草稿中**每一处**两个及以上空格的连续段，而不只是拼接处，会静默重排粘贴进来的代码、YAML、对齐的表格与缩进；现在它只处理拼接处。
- **penguin.ooo 安装脚本会转发参数。** `https://penguin.ooo/install.sh` 此前把真正的安装脚本直接管道给 `sh`，于是 `--universal` 与 `--version` 被静默丢弃——这让架构不受支持的用户拿到一条通过文档 URL 根本无法生效的建议（「请加 `--universal` 重试」），也把版本固定变成了「装最新版」。现在这个转发脚本会先下载到临时文件，用 `"$@"` 运行它，并透传退出码；这同时消除了「把截断的下载内容管道给一个会先删旧安装再移入新安装的脚本」所带来的半执行风险。
- **测速要么报出吞吐量，要么什么都不报。** 测速模式把输出上限提高到 64 个 Token，却复用了连通性探测的提示词——而后者只要求回一个词——于是速率是在一个 1 到 3 个 Token 的样本上算出来的，还被收尾 usage 分块的往返时延所主导，同一个模型会因为 30ms 的抖动而被评为绿色或黄色。测速模式现在有了自己的提示词，会持续生成直到触及上限；新增的纯函数 `probeTps` 会在样本低于有意义的下限（16 个 Token、100ms）时丢弃速率，只保留 TTFT，而不是给出一个编造的数字。
- **公告栏（落地页）。** 轮播现在在键盘获得焦点时也会暂停，因此获得焦点的链接不会再被留在一张 `aria-hidden`、且已被平移出视野的幻灯片里（这既违反 ARIA，也不满足 WCAG 2.2.2）；在 `prefers-reduced-motion` 下，轮播也不会再把自己搁浅在克隆幻灯片上。
- **流式保真规则由测试固定下来。** 随 AgentHub 0.4.0 载荷一起加入的两条规则——`fidelity.signature` 会收尾当前打开的文本片段，以及 fidelity 的键在增量之间是合并而非替换——此前没有任何覆盖；把这两条都改坏，整个测试套件依然全绿。现在任一条被破坏测试都会失败，从而防止回放时把一个签名交给 Provider 去覆盖它其实从未签署过的文本，也防止 GPT-5 的 phase 分段在恢复时丢失。
- **新的基准测试结果，以及一个改了形态的对比。** 两套测试均已刷新，对比的设计也随之改变：不再让三个 Harness 都跑同一个 DeepSeek V4 Pro，而是各自搭配它通常配套的模型——PenguinHarness 用 DeepSeek V4 Pro，Claude Code 用 Claude Opus 4.8，OpenAI Codex 用 GPT-5.5——因此模型这一列本身成为结果的一部分，而 Token 与成本是整套测试的总量而非单次运行的均值。数据分析（15 个任务，单次运行）：PenguinHarness 66.67%，两个对手均为 53.33%，成本分别是 $0.55 对 $38.48 与 $19.41。编码（40 个任务 × 2 次运行，准确率取全部 80 个结果）：71.25%，与 Codex 持平、落后于 Claude Code 的 86.25%，成本为 $3.81 对 $220.08 与 $146.97。文案随数据一同调整——该小节不再声称「同一模型」或「三者中准确率最高」，这两点都与新结果相悖，转而以单位质量成本立论；文案中 35×/70×/58×/39× 这几个倍数现在由单元测试对着数据断言，因此下次刷新时它们不会漂移。README 与博客的图表由 `render-benchmark-svg.mjs` 从同一数据源生成。柱状图保持线性且从零起，但设有最小长度：按真实比例，成本面板会把 PenguinHarness 压到约 2px，读起来像一个空槽位而不是胜出的序列，因此这个下限让它保持可见，同时仍然明显是最短的那根——每根柱子旁都印有精确数值。README 的图表说明现在是一行结论，而不是一段运行参数，与 RAG 的成本钩子保持一致。
- **演示视频登上落地页。** 自进化小节的「演示视频即将上线」标签被录像本身取代，RAG 案例标签页也改为播放成品应用而不再只是配图——两者都与 README 保持一致，也都做了语言匹配（`evo_zh`/`evo_en`、`rag_zh`/`rag_en`）。文件不放在本仓库：每个约 9 MB，而整个仓库历史约 17 MB，提交四个就会让每位贡献者克隆的体量翻三倍，而这些素材只有营销站点会用到；因此它们由兄弟仓库 `penguin-harness-community` 经 `raw.githubusercontent` 提供，该服务返回 `accept-ranges: bytes`（拖动进度可用）与 `access-control-allow-origin: *`。它的 `application/octet-stream` 类型不会阻碍播放——`nosniff` 只对脚本与样式强制执行，不针对媒体——这一点是在 Chromium 中端到端验证过的，而非想当然。每处嵌入都配一张海报图并设置 `preload="none"`，因此一次页面访问只下载一张约 37 KB 的静帧，在有人按下播放之前不下载任何视频字节（通过观察加载时的网络请求断言：零个 mp4 请求）。独立嵌入刻意去掉了截图所用的 BrowserFrame 外框，因为自进化那段录像是一份带旁白的演示而非产品自身界面；RAG 案例则保留外框，因为那里确实就是应用本身。
- **草稿页真正居中了，向上弹出的菜单也不再被裁切。** 品牌区块原先位于上方的 flex 弹性空间之内，因此它上方的间距比示例卡片下方的间距正好短了品牌区块自身的高度——整个页面偏高，而从输入框向上弹出的斜杠菜单会撞到滚动区域的顶部。品牌区块现在与输入框、药丸和示例任务处在同一个居中区块内，使上下两处间距完全相同（实测：视口高 1000px 时为 134/134，900px 时 84/84，800px 时 34/34）。斜杠菜单与 `@` 菜单另外会把自身高度限制在输入框与最近的裁切祖先之间实测出的可用空间内，而不是固定的 `40vh`——后者不可能知道这个距离：此前菜单在 900px 高时被裁掉约 50px，800px 时仍被裁掉 5px，现在一直到 620px 高都能放下，靠自身收缩与内部滚动来适应而不是被裁切。
- **Web 打磨。** 切换活动 Project 时测速徽章会重置（结果以 `(provider, model_id)` 为键，此前会跨 Project 泄漏）；工作分组头部的计时与最终落定使用同一个时间跨度，因此其时长不会往回跳；Markdown 渲染器的组件映射具有稳定标识，因此流式输出不再重新挂载已闭合的代码块、也不再丢失文本选区或 Copy 状态。
- **源码重新可 diff。** 有四个文件把复合键分隔符写成了字面的 NUL 字节而不是 `\0` 转义，导致 git 把它们当作二进制——`catalog-sync.ts`、model-catalog 与 models 的测试，以及 scheduler，都因此产生不了可审查的 diff、没有 `git grep` 输出、也无法做文本合并。运行时取值未变。
- **文档与元信息。** 工作区 `files/content` 预览模式及其响应头写入了服务端 API 参考（中英）；skills README 现在列出实际存在的分组；Skill 库页面的文档字符串描述的是它真正渲染的逐 Skill 配色与两列网格；`penguin-cli` 的 `updated` 日期与其版本号对齐；penguin-sdk 的 RAG 配方不再把整个 Skill 库装进它生成的应用里；README 的模型表不再把 Kimi K3 列在 Moonshot 名下（后者并不提供它）；目录定价区块里的一处中文注释已翻译。
- **一个没有在测试的测试。** 那个断言「子会话输出不计入 1000 字符触发阈值」的早期标题用例，在把来源守卫移除后依然全绿；现在缺了它就会失败。
