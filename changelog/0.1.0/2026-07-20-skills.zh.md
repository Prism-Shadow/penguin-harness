## Skill：把 CLI 的 --root 固定到应用目录，并在无可用 key 时快速停止

三个 Skill 为 AI 应用开发新增了两条硬性规则：始终把 penguin CLI 指向应用自己的数据根目录；一旦没有可用的 API key，立即停止求助循环。

- penguin-sdk（v7）、agenthub-models（v4）、penguin-cli（v2）：构建 AI 应用时，`penguin config ...` 必须始终传入 `--root <data_dir>`，指向当前工作目录内该应用自己的数据目录（也就是传给 `createAgent({ root })` 的同一路径，例如 `./penguin_data`）；不带 `--root` 运行会写入全局的 `~/.penguin/data`，那属于运行 Penguin 的人，而不属于这个应用。
- penguin-sdk（v7）与 agenthub-models（v4）：当没有可用的 API key 时立即停止，转而向用户求助，而不是在工具调用上空转——反复执行 `env`、反复检查 vault、反复重试构建，只会浪费轮次和金钱；做一次明确的检查，然后把控制权交回用户（通过齿轮图标打开 Agent 设置，往 key vault 中添加一个 key）。

## 系统提示词暴露 Provider 与 Model ID；Skill 明确「key 优先」的前提

Agent 系统提示词的 Environment 小节现在带上了本次 Session 的模型引用，AI 应用类 Skill 也把 key 与 root 这两个前提写在了开头。

- `# Environment` 小节在 `Session ID` 之前新增 `Provider: {{PROVIDER}}` 与 `Model ID: {{MODEL_ID}}` 两个占位符（取自解析后的模型条目，即本次 Session 模型的 Provider 分组与上游 id），字段顺序重排为 `Project Dir → Agent ID → CWD → Provider → Model ID → Session ID`。`assembleSystemPrompt` / `SessionEnvironmentValues` / `sessionEnvironment` 将这两个新值贯穿传递；配置文档的占位符表格（中英）随之更新。
- penguin-sdk（v8）与 agenthub-models（v5）开篇即声明前提：进行 AI 应用开发时，请用户在**本 Agent 的 key vault** 中添加模型 API key，*然后*再开始构建；并把应用的 Penguin 数据根目录保持在 **CWD 工作区之内**（`--root ./penguin_data`），绝不使用 `~/.penguin`；模型 id 可以从 penguin CLI 的目录中获取。
