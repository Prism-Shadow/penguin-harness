# MMSP 0.5.6: Kimi K3.1 Pro on Moonshot and OpenRouter

- **Date:** 2026-10-24
- **Type:** feature
- **Scope:** `model-catalog`, `core`, `skills`, `docs`
- **PR:** [#1315](https://github.com/Prism-Shadow/penguin-harness/pull/1315)

[中文版](2026-10-24-catalog-mmsp-0-5-6.zh.md)

PenguinHarness moved to MMSP 0.5.6, and the built-in catalog took the Kimi K3.1 Pro rows that MMSP 0.5.6's registry added for the groups PenguinHarness ships. New Projects get them as presets; existing Projects pick them up through "Add new models".

## What changed

- **MMSP:** `@prismshadow/mmsp` moved from `^0.5.5` to `^0.5.6` in core, the server and the CLI.
- **Moonshot:** `kimi-k3.1-pro` at CNY 13 input / 68 output / 1.3 cache hit, and `kimi-k3.1-pro-highspeed` (Kimi K3.1 Pro Highspeed) at CNY 26 / 136 / 1.3. Both have 1,048,576 tokens and image input, and route by their ids to Moonshot's own client (`moonshot-official`).
- **OpenRouter:** `moonshotai/kimi-k3.1-pro` at $2 / $10 / $0.20, 1,048,576 tokens, image input.
- **Thinking level `none`:** with MMSP 0.5.6, Moonshot's own client sends it as `reasoning_effort: "none"` on Kimi K3, K3.1 Pro and K3.1 Pro Highspeed, which turns reasoning off; MMSP 0.5.5 sent `"low"`. Anthropic's own client turns thinking off for it on Claude Sonnet 4.6, Opus 4.8, Sonnet 5 and Opus 5, and runs Claude Fable 5 at its lowest effort. Session titles, `read_file`'s proxy vision reads and the server's one-shot completions, such as id suggestions, ask for `none`, so on these models they run without reasoning.
- **`unified-llm-api` Skill** (`agent-development`, version 2026.10.24.1): the model table lists the K3.1 Pro ids, and the config notes say that `NONE` turns reasoning off on the Kimi K3 series and that `moonshot-official` takes `prompt_caching` `ENHANCE` there.
- **Docs:** the `models` page's preset list names the K3.1 Pro rows.
