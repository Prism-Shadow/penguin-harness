Prepared version 0.2.17. The root, every package under `packages/` and every plugin moved to 0.2.17 with core's `VERSION`; `packages/skills`, private and created during this cycle at 0.2.13, joined the lockstep, and the `plugins/sandbox-*` backends stayed on their own 0.2.3 line. The batch was frozen as `changelog/0.2.17/` with its `RELEASE.md`, the release line in `CHANGELOG.md`, the in-app release notes and the README's Docker tag. The release blog post ships in its own pull request.

## Changelog sweep

- Two `Type: feat` values became `feature`, the RFC move gained its `PR`, and a bare PR number became a link.
- Entries amended by later pull requests cite them: [#1320](https://github.com/Prism-Shadow/penguin-harness/pull/1320), [#1308](https://github.com/Prism-Shadow/penguin-harness/pull/1308) and [#1304](https://github.com/Prism-Shadow/penguin-harness/pull/1304).
- The vLLM and placeholder entries no longer describe the base URL placeholder that [#1316](https://github.com/Prism-Shadow/penguin-harness/pull/1316) replaced before any release.
- The 2026-10-15 compatibility file gained its `## Compatibility` heading, and the AMSP stream entry's `Breaking` value its `yes —`.
- The origin guard entry ([#1268](https://github.com/Prism-Shadow/penguin-harness/pull/1268)) was marked `Breaking` for deployments behind a TLS-terminating proxy, with the setup they need.
- The API socket route entry gained its `PR` ([#1272](https://github.com/Prism-Shadow/penguin-harness/pull/1272)) and lost its `Breaking` mark, since no release opened the socket at the old path; its Compatibility section says so, and the single-socket entry cites it too.
