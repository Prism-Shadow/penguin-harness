# 新增仓库 Skill：文字由网关模型撰写

- **Date:** 2026-10-19
- **Type:** process
- **Scope:** `skills`
- **PR:** [#1216](https://github.com/Prism-Shadow/penguin-harness/pull/1216)

[English](2026-10-19-writing-skill.md)

在 `.agents/skills/` 下新增开发用 Skill `penguin-harness-writing`，记录 penguin.ooo 上的文字怎样产出，博客文章、文档页和 landing 文案都适用。读者能看到的每一个字都由 TokenDance 网关上的模型撰写，每一步单独调用一次 API。Agent 负责调研、整理事实、编写提示词、拼装模型写好的各节、按模型给出的文字画图、检查和发布。密钥从 `TOKENDANCE_API_KEY` 或 `TOKENDANCE_KEY_FILE` 读取，不进入仓库。

## 细节

- 文章按人写文章的方式产出，由 `scripts/prose.mjs` 完成：
  - `outline` 先列提纲，其中的 `# Plan` 表给每一节定下篇幅、可用的事实和配图。
  - `plan` 对照 Profile 的篇幅预算、图表清单和事实文件检查这张表，通过后冻结。
  - `write` 按冻结的提纲一次写完整篇文章，每一节都接着上一节往下写。它保留指定的标题、作者的备注和已经画好的图块，并报告每一节相对上限和计划的篇幅。
  - `check --plan-rows advisory` 把计划篇幅当作目标，把 Profile 的上限当作限制。
  - `review` 通读全文，给各节之间的每一处衔接打分。`fix`、`trim`、`translate` 也作用于全文，改动了不该改的部分的输出会被拒绝。审阅时正文放在围栏里，和指令分开。TL;DR 行、标出的关键句，以及议论文要求的「先摆出反方再回应」，都不会被当作问题提出；正文不用列表的文章，审阅也不会要求改成列表。
  - `transition` 单独做一轮过渡修改，每种语言在最后一轮 `fix` 之后各做一次。每个小标题只允许改它后面的第一句，衔接需要时连带改标题前的最后一句。其他任何改动或丢失事实标记的输出都会被拒绝。改完后由 `review` 重新给衔接打分。
  - `unstrip` 把已发布的文章还原为草稿：恢复 figure 块和事实标记，把已画好的图保存为文件，并从参考资料列表生成事实文件的初稿，这样修改文章时不必重画图。它会校验 `strip` 能还原出同样的图和正文。
  - 长文和文档页仍可用分节模式：`section` 一次写一节，`assemble` 把各节逐字节拼成全文，`route` 按审阅意见引用的原文把意见分到对应的节。
- 篇幅预算是硬性约束。提纲受 Profile 上限约束。单节篇幅超过计划篇幅的 1.1 倍或 Profile 的上限时，`check` 报错。受篇幅约束的提示词都写明上限和 `check` 的计数规则。单节的提示词按计划篇幅提要求，全文剩余篇幅更少时按剩余篇幅，从不按 1.1 倍的余量。每完成一节，`check` 都会报告全文合计与上限的对比。单节仅存在篇幅过长问题时，交由 `trim` 删减，不重写。对整篇草稿，`trim` 只把超过上限的节删到略低于上限，不再压到大纲的计划篇幅；全文超出上限时，按各节篇幅分摊删减。它要求在完整的句子里改写，保留每个数字及其单位、「约」之类的约数、出处和「许多」这样的限定词；某节被删到比目标低 10% 以上，或丢掉了原文的数字时，输出会被拒绝。`trim`、`transition` 和 `emphasize` 会把输出改动过的图块换回原样；模型照抄提示词里的单独一行围栏时，每一步都会在检查前把它去掉。
- `fix` 和 `trim` 的输出先经检查再保存。这类输出若出现以下任一情况：引入审阅意见未提及的事实、改动审阅意见未指向的图块、改动事实标记，或删减后仍超出上限，整份输出将被搁置。`fix`、`polish`、`translate` 和 `trim` 的输出若改动了版本说明，同样会被搁置。被搁置的输出不写入下一个版本。
- 文章采用论文式引用，多数句子不带引用。事实文件中的每条事实都标注来源。`strip` 把写作时的事实标记转换为带编号的 GFM 脚注，文末附带链接的参考资料列表，编号按首次引用的顺序排列。每个来源全文只引用一次，每段最多一处引用，由段中第一句带来尚未引用来源的句子承担。可选的 `## NOCITE` 一节里列出的事实不产生引用，文章只是提到的仓库文件和文档页也不引用，正文用代码格式写出文件名。TL;DR 是正文的概括，不带脚注。脚注放在结束该分句的标点之前（`text[^1].`、`文字[^1]。`）。Profile 的 `sources` 设置限定参考资料的条数，观点文章为 6 到 13 条。超过上限、一段或一句里有两处引用时，`check` 报错；少于下限时给出警告。另一种语言引用来源的顺序相同时，沿用同一套编号。`pair` 检查两种语言引用的来源是否一致。`**Sources**` 页脚不再使用。正文中的 URL 写成 `<https://…>` 格式的自动链接，因为网站会把紧跟在裸 URL 后面的脚注当成链接的一部分。
- `reference/profile-<name>.md` 存放随文字类型而变的部分：结构、读者、篇幅，以及 `check` 据以检查的规则。目前提供观点文章、文档页和 landing 文案三种，各自配有输出约定。观点文章按议论文来写，段落完整、前后相连：每一节论证一个分论点，给出推理和证据，并在反对意见出现的地方作答。Profile 的 `body-lists: none` 让 TL;DR 之外的列表报错，`body-tables: none` 对表格同样处理。
- 文风规则要求模型把读者设想为有阅读障碍或注意力缺陷（ADHD）、读起来吃力的人。写作需做到要点先说，句子短，用常见的词，不插题外话，不预先辩解。规则还点名禁止「是的，但是……」式的让步转折，`review` 会检查这两点。`SKILL.md` 原文引用了这条规则所来自的作者技巧。英文句子超过 35 个词、中文句子超过 60 个字时，`check` 给出警告。中文里 Harness 和 Agent Harness 保持英文。`check` 把「夹具」当作错误，把小写的 harness 当作警告。
- 面向相同读者，文章开头提供列出关键结论的 TL;DR。新增的 `emphasize` 步骤将每节的一个关键句标为粗体，不改动其他任何字符。文章中的粗体仅可用于这一关键句，界面标签写在引号内，其他粗体 `check` 一律报错。`emphasize` 的输出如果改动了正文、某节没有标出或标出两处、只标出半句、或是将收尾的 `**` 放在句末标点之后，都会被拒绝，中文里这样收尾的粗体无法显示。作者的备注（`--notes`）可以指明该标哪一句。`check` 会标出 CommonMark 无法识别为粗体的 `**`。
- 图里的每一个字都来自模型写的 figure 块。绘制的图以内联 SVG 嵌入正文，`check` 会把其中的文字逐条与 figure 块比对。
- 脚本的本地步骤不联网检查文字，覆盖结构、篇幅、配图、事实标记及其来源、脚注和各语言的禁用词表。`selftest` 用内置样例跑一遍这些步骤。
- 开发 Skill 的阅读表和 `reference/authoring.md` 都加了指向新 Skill 的入口。
