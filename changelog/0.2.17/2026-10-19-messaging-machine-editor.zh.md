# 机器上的对话，其消息渠道编辑器会说明机器人在哪里运行，机器离线时仍可查看

- **Date:** 2026-10-19
- **Type:** feature
- **Scope:** `web`, `ui-gallery`
- **PR:** [#1219](https://github.com/Prism-Shadow/penguin-harness/pull/1219)

[English](2026-10-19-messaging-machine-editor.md)

位于机器上的对话，其「远程控制」面板与弹窗现在会说明机器人从哪台机器连接；那台机器连不上时，以只读方式继续显示绑定；启用机器人之前，会通过[服务端条目](2026-10-19-messaging-account-holders.zh.md)中的 account-holders 路由在所有服务端上检查一遍。

## 细节

- 机器上的对话，编辑器顶部显示「连接自」与机器的 ssh 别名。「绑定后会发生什么」折叠项补充了它的含义：连接由那台机器主动向平台发起，因此它需要能访问该平台，不需要公网地址；扫码登录的是那台机器，而不是这台电脑；只要那台机器的服务在运行，即使本应用关闭或与它断开，机器人也会继续回复。
- 机器连不上时（正在重连、已停止重连、登录被拒、服务已停止、尚未连接），编辑器不向它发送任何请求，而是以只读方式显示本浏览器上次读到的绑定，上方的提示写明机器的状态、机器人是否仍在回复以及那次读取的时间；连接状态以「最后已知状态」显示为灰色，不用实时状态的颜色。此前从未读到过时，只显示提示。机器恢复连接后，编辑器重新读取，控件恢复可用。机器在查看途中断开时，已读到的表单保留在屏幕上，只停止状态轮询。
- 机器上对话的绑定，最近一次读到的内容（读取路由返回的脱敏视图）保存在 localStorage 的 `penguin.machineMessaging.<project>:<machine>:<session>` 下，每次读取、保存和切换都会替换它，读到没有任何已保存配置时将其删除。本服务端上的对话不保存。
- 启用机器人之前，先询问本服务端哪些服务端已启用了它。有其他服务端启用时，开关拒绝并提示是哪一台，不向该对话所在的服务端发送任何请求。有机器未能询问时，照常启用，并在控件下方的一行里列出这些机器及原因（未连接、需要更新、没有答复）。停用机器人不询问任何服务端。
- 组件画廊的模拟 API 响应 account-holders 路由。
