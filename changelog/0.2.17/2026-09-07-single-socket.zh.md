# 每个 Web App 标签页一条 API 套接字，共享机器事件流并限制重试

- **Date:** 2026-09-07
- **Type:** feature
- **Scope:** `server`, `web`, `docs`
- **PR:** [#912](https://github.com/Prism-Shadow/penguin-harness/pull/912), [#1272](https://github.com/Prism-Shadow/penguin-harness/pull/1272)

[English](2026-09-07-single-socket.md)

Web App 标签页通过一条 WebSocket 承载 API 调用和长期订阅，不再让各自独立的 HTTP 流耗尽浏览器连接槽位。服务端在 socket hub 内为每台机器共享一条套接字和一次事件订阅，发现静默的调用与流，并在重试时避免重复堆积无应答请求。HTTP 用户事件 relay 退役：Web App 改读机器聚合流，一台机器唯一的一次订阅现在覆盖每个读取方；运行着不带 socket hub 的旧版本的机器在 Web App 上失去实时事件（行数据仍经 HTTP 拉取）。设计见 PRFC-0011。

## API 传输与兼容

- 套接字是既有 API 的第二种传输，而不是另一批端点。调用进入与 HTTP 相同的路由，保留授权、校验与错误正文。帧携带方法、路径、JSON 正文和允许的请求头（`last-event-id`、`accept`、`content-type`）；应答保留 `date`、`content-type`、`retry-after` 与 `etag`。
- 握手使用 `GET /api/socket`，即套接字自己的 upgrade 路由：会话 Cookie 认证与同源检查照常生效，平台通过 `Http.fetchAs` 以该 Cookie 的用户身份进入路由。传输实现位于平台层，使用既有 shell 接缝。（它最初以一个保留的终端 id 打开；[它自己的路由](2026-10-20-api-socket-own-route.zh.md)取代了那个 id。）
- 事件流响应转换为一帧 `stream`、事件帧及一帧 `end`，每个事件以它本来的对象直接交递——这条传输上不再写出 SSE 文本再解析回来。取消会中止端点请求并释放订阅。套接字心跳发现静默两拍的对端；读取方超过发送水位时以 `lagging` 结束，而不是积累无界队列。
- `apiFetch` 在套接字可用时使用它，否则使用 HTTP。仅限 HTTP 或被平台拒绝承载的端点回 `421 not_on_socket`；不支持的响应正文回 `415 unsupported_transport`，客户端改经 HTTP 获取这些响应。认证与热更新请求保留在 HTTP 上。
- 既有 SSE 端点与 `/server/<id>/api/…` 代理继续可用，CLI 继续经 HTTP 消费 SSE。浏览器套接字握手持续失败时，调用继续走 fetch，流则静默等待一个不会到来的套接字——没有 EventSource 孪生。新增聚合端点不要求迁移数据或配置；旧页面可以继续使用每台机器各自的流。
- 调用始终进入当前 App，包括插件重装配之后。平台推送时，后继者在启动完成两秒后以关闭码 `1012` 和原因 `the harness was updated; reconnect` 关闭继承的套接字；浏览器重连并恢复各条流。在第一次携带这套交接能力的推送期间已经打开的窗口，仍需重新加载一次。

## 共享机器事件

- 机器代理与事件 hub 在每一代内共享一个套接字缓存，经各台机器的 SSH 会话以其 admin 身份拨号。套接字仅在该会话内复用；会话被替换时丢弃旧套接字，下一次请求重新拨号。
- 转发的机器流从不回退到 HTTP。握手拒绝记住一分钟；拨号期限为 10 秒，8 秒内未打开的流会拆掉其套接字。失败以 `502`/`504` 和 `machine_socket_refused`、`machine_socket_unavailable` 或 `machine_stream_not_opened` 作答，而不是再占住一条 HTTP 转发。
- socket hub 内的聚合与代理读取方共享每台机器的一次上游 `/api/events` 订阅和有界重放缓冲。代理读取方收到机器自己的事件与事件 id；Web App 像其他读取方一样读取聚合流，HTTP 用户事件 relay 退役而不是被静默保留。
- `GET /api/projects/:projectId/machines/events` 对 admin 与项目成员开放，立即开流，每个标签页通过一条流承载它关注的全部机器。`machine_event` 帧标明来源机器；`server_event` 帧携带 `hello` 或 `resync_required`，无 id 的心跳说明聚合流自身的活性。重连从比响应寿命更长的缓冲重放，最多保留 10,000 条事件或 8 MB，并按关注的机器过滤。
- 聚合流每次打 20 秒心跳时重新读取 Project 的机器，不重开标签页的流就接入新连接的机器。已接入的机器不会每拍重新查找；后续重拨由 hub 负责。聚合适配器位于 `machines/aggregate-stream.ts`。
- 聚合 holder 在拨号失败或流未打开之后继续持有机器订阅。重试从 1 秒起倍增，最多 30 秒，每次尝试前重新读取连接，从而跟随被替换的 SSH 会话。拨号成功后从机器的最后一个事件 id 续上。相同套接字失败在一轮连续失败期间只记一次日志和错误记录，而不是每次拨号都记。
- `/server/<machineId>/api/events` 的读取方立刻收到失败并自行重试；聚合流保持打开，由 hub 重试其中的机器。没有读取方再持有机器时停止重拨。
- Machines 页面展示 `MachineInfo.socket`：`dialling`、`connected`、`refused` 或 `failed`，附进入状态的时间与失败详情。对于本机及尚无流请求套接字时，该字段为 null。它说明本地套接字的状态，并不证明远端端点正在应答。

## 静默、取消与重试限制

- 连接、调用与流的活性分别跟踪。用户事件流每 20 秒发出心跳事件；hub 取消静默两拍的上游，并从最后一个事件 id 恢复，浏览器则独立重发它自己的静默流。重放未命中时要求重新同步；停止消费的读取方在 4 MB 高水位被结束，而不是被无界缓冲。
- 浏览器握手 10 秒后仍未打开时关闭并重试。对可达服务器连续三次握手失败后放弃套接字：调用继续走 fetch，流保持静默，直至页面重载。
- 单次调用 20 秒无应答时发送 `cancel` 帧，让服务端中止请求、机器代理丢弃转发。取消不记为机器不可达。警告标明调用与套接字状态；写请求作为网络错误失败，不再重试，因为它可能已经落地。
- 对机器的读若无应答、套接字却仍有帧往来，则以 `machine_no_answer` 失败，不经 HTTP 重复同一条转发。对本服务器的读，以及套接字自身静默后的读，保留 HTTP 回退。
- 一台机器若没有回答会话列表重载中的任何问题，休息期间显示缓存行。2 秒后用一个问题探询；探询失败使休息时间翻倍，最多 30 秒，第一次应答恢复整轮查询。本地重载完全无应答时也从 2 秒到 30 秒退避重试，并给出诊断警告。
- 20 秒内未打开的流会被取消并重新发出。中断的流带最后一个事件 id 恢复，各自从 1 秒到 30 秒退避；`401`/`403`/`404` 停止重试。对话历史加载超过 15 秒时报告目标与套接字状态。
- 错误帧共用一个局部写入器，取消帧与重试清理各有单一客户端入口，hub 读取方清理集中处理，但不合并不同传输状态机。订阅在返回 detach 回调之前同步结束时，relay 也只 detach 一次。取消用例容许已发出的 SSE ping，并在断言失败时仍关闭套接字。
