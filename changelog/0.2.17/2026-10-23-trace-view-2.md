# The Trace panel gets a sticky round navigator and readings on demand; a command's exit status is no longer a tool failure

- **Date:** 2026-10-23
- **Type:** feature
- **Scope:** `web`, `ui`, `core`, `server`, `docs`
- **PR:** [#1305](https://github.com/Prism-Shadow/penguin-harness/pull/1305)

[中文版](2026-10-23-trace-view-2.zh.md)

The Trace panel was rebuilt around one sticky toolbar: the round navigator opens from a button that names the round in view, rounds are ruled rows whose context ring opens the exact token figures, each event row wears one pill toned by its record family, and the thinking level reads as text. A command that ran and exited non-zero, or was killed by a signal, now ends as an ordinary completed tool call everywhere it is shown.

## Trace panel

- One sticky toolbar replaced the file pills and the date row: the file is a picker when the Session has several files and a label (number, date, size) when it has one, then the rounds button, then a flat export icon. It stays at the top of the panel at any scroll position.
- The file picker and the rounds button open the same dropdown: a ghost button naming the current choice, and a panel no wider than the room in the Trace panel with a title row (the list's name and count) over one row per choice, the current one filled and checked. Opening focuses the current row; ArrowUp and ArrowDown walk the rows, Home and End jump to the ends, Escape closes and returns focus to the button. A file's row gives its number and date, with its size at the end.
- The rounds button names the round in view and follows the panel's scroll; it shows from two rounds up. Its list has the number box in the title row, then every round (number, compaction badge, first prompt line, four readings); it names no thinking level. Picking a round closes the list, draws and opens the round and lands its head under the toolbar. The per-round "back to the navigator" control was removed.
- The global summary stays at the top of the view. It and the rounds are ruled sections instead of cards, and a round is a ruled row: number, compaction badge, tool calls, hit rate, cost, duration, then the context ring. The Session's fields stay in the `session_meta` row, which now lists the `provider` too.
- The ring is a button. Hovering it gives the usage percentage; clicking it opens the round's readings, each figure once: input, cache hits with the hit rate, cache misses, output, output TPS, then the context used against the window. A compaction round has no snapshot and shows a tokens glyph that opens the same list without the context usage. The input, cache-hit, output and TPS figures no longer appear on a round's row or its first line.
- The timeline's explanation moved behind a "?" beside its title.
- Each event row wears one pill naming the record's kind, with the role for `text` and `inline_data` (`text (user)`, `text (assistant)`), in its family's tone as before: neutral for a `model_msg`, attention for an `event_msg`. The role left the text's summary. An opened row shows its stop badge only when the reason is not `completed`.
- The thinking level is text, not a pill: a `request_begin` row reads `thinking_level=medium → high` where the level switched and `thinking_level=medium` where the file first states it.
- A failed tool's bar on the timeline is ringed with the danger tone token instead of a fixed red.
- `TokenDonut` gained `hint={false}`, for a ring inside a control that names it: no tooltip and no accessible name of its own.
- `MenuItem` takes a `tabIndex`, for a list of rows that is a single tab stop.

## A command's exit status

- `exec_command` and `input_command` end a command that ran as `completed` whatever its exit status. A non-zero exit and a signal still close the output with `[exit code: N]` or `[terminated by signal X]`. `fatal` remains for the tool's own failures (unknown tool, bad arguments, a throw, a spawn error, a timeout) and `aborted` for a denial or an interruption.
- The chat's tool card, the Trace row and timeline, and the CLI show such a call as an ordinary completed one, with no red mark and no `fatal` badge. Records written before this change keep `fatal` and render as recorded.
- The cost center's error table no longer records a command killed by a signal; a spawn error and a timeout are still recorded. The rule that kept an ordinary non-zero exit out of the table was removed.
- A background command's completion report keeps calling a non-zero exit `failed`.
- The AMSP records docs page states that a command's exit status is a completed result.
