# 观点文章：控制上下文斜率

- **Date:** 2026-10-19
- **Type:** process
- **Scope:** `landing`
- **PR:** [#1239](https://github.com/Prism-Shadow/penguin-harness/pull/1239)

博客新增一篇观点文章，中英文各一份：《先压低上下文斜率，再谈压缩》（`context-slope`）。文章把上下文斜率，也就是 Agent 的上下文每次请求增长多少，定为 Harness 在压缩之前就应控制的指标。每次请求的上下文分成每次请求都携带的截距和每一步新增的斜率；同一条原则「索引先行，按需拉取」贯穿 Skill 渐进加载、落盘的输出上限、CLI 输出和 MCP 工具定义，文章最后落在 MCP 工具集的规则上。

## 细节

- 文章是一篇完整的议论文，开头有三点 TL;DR，导语和每节各加粗一句关键句；过渡轮只改写小标题前后的句子。
- `context-slope` 配有四张以内联 SVG 绘制的插图，使用共享的插图样式：一次合成测试在有无 16,000 字符输出上限时各次请求的估算上下文体积、随版发布的 Skill 库各内容层级的估算体积、超上限工具输出进入上下文与恢复文件的路径，以及三种 MCP 设计的对照。
- 两张图表的数据来自仓库提示词缓存测试辅助工具在合成测试上的测量；体积为基于字符的估算值，不是服务商的 Token 计数。
- 引用以编号脚注呈现：每段最多一个脚注，每个来源只引一次，中英文引用相同的 7 个来源。
- 落地页博客测试把这篇文章列为观点类的第一篇。
