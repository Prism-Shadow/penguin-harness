# 会话区不再对着马上就要出现的列表说"还没有会话"

- **日期：** 2026-08-24
- **类型：** fix
- **范围：** `web`

[English](2026-08-24-chat-empty-state.md)

有两处窗口期，会话区会声称没有内容可显示，而列表其实几秒后就到。两处都已修复。

## 智能体集合还在拉取，说明列表仍在加载

没有智能体集合就没法拉会话列表，因此没有时会提前返回——并且刻意不动 loading 标志，因为什么都没加载。
在此之前没有别的东西覆盖这段窗口，于是首次加载成功之后它就一直读作"已加载"。而每次切换项目都会清空并
重新拉取智能体，这就出现了一段"已加载，而且这里什么都没有"——盖在一个刚被清空的列表上。有三处消费这个
标志的地方在这段时间里全是错的，其中一处还会为一个只是尚未拉取的会话发起多余的查找。

## 路由里的会话不等于不存在的会话

列表是分页的，所以路由里的 id 不在已加载的行里是很正常的——深链接、刚创建的会话、第一页之外的行——
这要靠一次直接查找来判定，而不是假定会话已经没了。自动选中的 effect 本来就拒绝在查找未完成时下结论；
渲染却照样下了结论，并在整个查找期间画出空状态。现在渲染等待的条件和 effect 完全一致。
