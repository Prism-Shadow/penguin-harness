# QQ 机器人可以扫码绑定

- **Date:** 2026-08-27
- **Type:** feature
- **Scope:** `server`, `web`, `docs`
- **PR:** [#504](https://github.com/Prism-Shadow/penguin-harness/pull/504)

[English](2026-08-27-messaging-qq-scan.md)

绑定 QQ 机器人此前必须从开发者后台里逐字抄下 App ID 与 App Secret。QQ 绑定编辑器在这些字段
上方加了一个二维码：用 QQ 扫码、选择机器人，凭据就到了服务端。手动填写的字段保留在下方，用于
扫码覆盖不到的情形。

## 细节

- 绑定协议实现为对 `q.qq.com` 的三次调用：用新生成的 AES 密钥注册一个任务、把返回的 URL 编码
  进二维码（由 QQ 客户端打开，本服务端从不请求它），以及轮询取回用该密钥加密的 App Secret。
- **密钥完全没有交给浏览器。** 它在服务端生成、持有、使用并丢弃；客户端拿到的只有任务句柄、
  URL 与状态，由此得到的凭据被直接写入存储而不回传——与「已存密钥不回传表单」是同一条规则。
- 绑定任务只保存在内存，归属发起它的 Session，限量按 Session 而非按进程计，因此一个调用方的
  扫码任务挤不掉另一个调用方的；任务由「解决它的那一次轮询」认领，重放与对同一任务的并发轮询
  得到的都是 404，而不是第二次绑定。取消（包括离开编辑器，以及连续轮询失败后放弃）会立刻释放
  密钥，无人回头的任务也会在十分钟 TTL 到期时被清扫，而不是等到下一次有人发起扫码。
- 扫码成功改为只**保存**绑定，到此为止。启用仍是每个渠道上那个独立且互斥的动作，因此扫码不会
  把机器人从正在持有它的另一个对话手里夺走。该 Session 自身的 QQ 连接处于启用状态时，发起扫码
  被拒绝并返回 409 `messaging_disable_before_scan`；在连接被启用期间完成的扫码，则加上了与
  PUT 相同的账号占用检查。
- 新增三个路由——`POST /messaging/qq/scan`、`…/scan/poll` 与 `…/scan/cancel`，全部仅限
  Project 所有者：无论调用方实际输入多少，这个流程的终点都是一份存下来的凭据。
- 二维码改为在浏览器本地生成并以 `<svg>` 内联，因此不会有第三方从图片请求里得知任务句柄。它在
  明暗两种主题下都画成白底黑码，并保留 QR 规范要求的四模块静区——为深色背景反色的二维码扫描
  成功率并不可靠。
- 轮询面板改为能扛住临时故障：连续若干次轮询失败之前，二维码不会从屏幕上消失；平台报告已过期
  的二维码会自动更换，但更换次数有上限，超过后面板退回到「重新发起扫码」。
- 二维码编码库选用 `uqr`（MIT，无依赖）。
