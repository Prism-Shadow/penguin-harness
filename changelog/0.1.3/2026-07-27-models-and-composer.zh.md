## Fireworks 上的 Kimi K3

预置目录新增 Fireworks 上的 **Kimi K3**（`accounts/fireworks/models/kimi-k3`）：1M Token 上下文窗口，支持视觉，使用 OpenAI 兼容客户端对接共享的 Fireworks base URL，价格为每百万 Token $0.30 / $3 / $15（缓存读取 / 缓存写入 / 输出），在该 Provider 的行中排在 Kimi K2.7 Code 之前。

## 图片上传移入输入区的「+」菜单

图片选择器从独立的工具栏按钮中移出，成为「+」扩展菜单的第一项，而该菜单现在领衔整行工具栏——由两个 8×8 槽位变成一个，这个差别决定了手机上那一行会不会滚动。真正的文件输入框仍挂载在菜单之外（菜单在选中时会卸载其条目），由该条目去点击它，且仍处在这次点击的用户激活窗口内，因此对话框能正常打开。在不支持视觉的模型上，该条目仍可使用，其提示会说明图片将改为以草稿区文件路径的形式发送；目标模式下则禁用它，因为目标轮次只支持纯文本。

## 输入框高度跟随已渲染的取值

输入框的自动增高此前是在每次状态更新旁经 `requestAnimationFrame` 调用的，这会与 React 对受控 textarea 的提交产生竞态：当回调抢先时，它量到的是旧的多行内容并把高度重新钉在很高的位置——而此后再没有任何东西会触发重新测量，于是每次发送之后输入框都保持撑开。尺寸计算现在放在一个以文本取值为键的布局副作用中，它在提交之后、绘制之前运行，因此输入框在挂载时（还原的多行草稿）、输入过程中，以及发送后清空时，都能正确定尺寸且不会闪烁。

## 更安静的版本行

新会话草稿页的版本行去掉了产品名前缀——只留 `vX.Y.Z · 最近更新 …`——因为品牌字标就在它正上方，而侧边栏的版本页脚也是不带前缀的。
