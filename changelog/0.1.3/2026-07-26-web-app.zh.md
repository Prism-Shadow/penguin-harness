[English](2026-07-26-web-app.md)

六项围绕聊天与可观测性的改动一同落地：子 Agent 对话从消息流中移出、进入一个带调用图的可停靠面板；进行中的回复现在能在页面刷新后存活；头部统计实时跳动；运行状态行在手机上不再撑高；Trace 文件可以跨部署搬运；应用能说出自己的版本并自我更新。

## 子 Agent 对话移入带调用图的侧边面板

一次 `run_subagent` 调用此前会把子会话的整段对话内联进父级的消息流，卡片套卡片。子对话现在住在一个专门的 **Agent 面板**中，它像 Workspace 文件面板那样停靠在右侧（工具栏开关、可拖拽调宽并记忆宽度、窄视口下变为底部抽屉，且两个停靠面板互斥，绝不会一起挤压聊天列）。在消息流中，每个子会话只留下一行与其他折叠流行同款的整宽条——Agent 头像、解析出的 Agent 名称（取自子会话自己的 `session_meta`，依次回退到派生参数、会话列表，最后是短 id）、运行时的加载指示，以及只要其子树中任何位置有待审批就亮起的琥珀色圆点；该圆点是可访问名称的一部分，工具栏按钮也带同样的角标，因此嵌套的审批在面板关闭时仍可被发现。面板顶部展示一张**调用图**：每个参与的 Agent 一个节点（头像 + 名称 + 运行状态点 + 已用时间——运行中是跳动的墙钟，结束后由消息时间戳冻结，因此刷新后的页面显示的时长与实时页面一致；主会话为根节点），边表示谁派生了谁，重复轮询到的子节点会去重。点击节点会切换下方展示的对话——由与主流相同的机制渲染，因此嵌套的工具卡片会实时流式输出，审批按钮也能在面板内直接工作。该图默认展示最近一次 Task，并在每次切换 Session 时重置回它；点击更早一轮中的某一行，则会钉住那一轮的 Task 并展示其历史派生树。打开任一停靠面板（任何入口，包括工具栏）都会关闭另一个，因此两者绝不会一起挤占聊天列。面板的可见性是**按 Task 作用域**的：每个新 Task 开始时它都是关闭的（上一个无关 Task 遗留的打开状态绝不会滞留），当该 Task 首次派生子 Agent 时它会在本 Task 内自动打开一次（仅限停靠布局），而手动的打开或关闭在该 Task 剩余时间内始终优先；进入会话时同样从关闭开始——这条逐 Task 规则是该面板刻意偏离文件面板持久化行为的唯一之处，而目标模式的一次迭代算作一个 Task 边界。子对话现在也终于能实时展示它自己的用户侧：子 Agent 运行器会把派生提示词（以及后续输入）经带来源标记的流转发出来，因此面板无论实时还是刷新之后，都以同样方式渲染子会话的用户消息。

## 进行中的回复能在刷新与重连后存活

在 Task 中途刷新此前会丢掉正在流式输出的一切——写了一半的回复、思考内容，或一次长工具调用的部分输出——直到该消息完成为止，因为历史是从 Trace 读取的（只含完整消息），而新建的 SSE 连接不会重放任何内容。服务端现在为每个运行中的会话保留一条**实时尾巴**：所有未闭合片段的聚合，以来源链与片段标识为键，在消息发布的同一个 tick 内更新，并设有上限，使失控的输出只保留其尾部。消息端点以 `live: { cursor, fragments }` 返回它，且在开始读取 trace 之前原子地捕获。客户端把这些片段作为合成的 `partial_* start` 事件播种在游标位置，丢弃位于游标处及之前的已缓冲部分内容（它们的内容已经包含在片段里），并让完整消息继续经既有的重叠去重流动——刻意从不按游标丢弃完整消息，因为一次发布可能先于它的 trace 追加真正落盘。效果是：在刷新、关闭再打开或一次重新同步之后，已经流出的前缀立刻回来并继续增长，主会话与子 Agent 皆然。端到端测试会在命令中途与文本中途重新加载，并断言最终的对话记录与从未重新加载过的一次运行逐字节一致。

## 头部统计实时更新

聊天头部的三个芯片（含子 Agent 的会话 Token、成本、已用时间）此前实际上只在 Task 结束时才刷新。已用时间现在在 Task 运行期间每秒跳动一次（已结算的跨 Task 总量，加上当前运行 Task 的墙钟，由测试所固定的同一个纯函数助手折叠在一起，因此运行中的增量绝不会在 Task 边界处被重复计入）。成本显示服务端最近记录的取值，加上一份由当前运行 Task 的用量档位按当前模型定价换算出的实时估算——跑在其他模型上的子 Agent 会让 Task 中途的估算略有偏差，空闲时的重新拉取会对齐到已记录的取值；在没有定价时则跳过实时增量，`*` 这个未计价标记仍保持其含义。Token 本就按每个完成的请求推进，未做改动。在全新会话上，成本芯片会一直隐藏到第一笔用量落地，而不是在 Task 刚开始的瞬间闪一个格式化的零。

## 运行状态行在移动端保持单行

在 640px 以下，运行状态相关的界面不再折行或撑高：回复的统计页脚——它固定的高度使折行后的芯片会盖住下方内容，这是其中唯一一个货真价实的缺陷——保持单行；而两处消息页脚（回复与用户气泡）现在在**手机上始终可见**：它们的悬停显示在触摸下从未触发过，这个缺口早于本次 PR 就存在。为了在 390px 下不出现滚动，TPS 芯片在 `sm` 以下隐藏，数值类芯片在那里改用紧凑变体（金额保留两位有效数字，因此非零成本绝不会显示为 `$0.00`；10 秒以上取整秒）；所有内容仍置于一个隐藏滚动条的滚动行中作为兜底，复制按钮固定在末端。头部以一个脉动圆点取代「运行中」文字，并使用纯图标的 Workspace 按钮；工作分组隐藏步骤计数，并把「等待审批」药丸收缩为一个带标签的琥珀色圆点。在工具卡片上，文字形式的决策指示**在所有断点下都已移除**——状态图标独自以其可访问名称承载「已批准 · 自动/手动」或「已拒绝 · …」（恰好一个事实来源，而且被拒绝的卡片不会再同时显示「已中止」）。操作按钮遵循相反的规则：允许/拒绝在**任何断点下都保持文字**——指示器可以是图标，按钮必须是文字——而当某次调用在手机上等待审批时，它的完整命令会折行完整显示（这是单行规则唯一被认可的例外：你要读得到你所批准的东西），决策之后再收起。桌面端渲染逐像素未变。

## Trace 文件可以导出与导入

Traces 页面现在能把一条运行轨迹跨部署搬运：任何成员都可以逐字下载 Trace 文件（`application/x-ndjson` 附件），而 Project 所有者可以通过 Agent 行上的上传按钮，把一个文件导入到任意 Agent 之下（14MB 上限，与 Agent 快照导入一致）。导入的文件必须是合法的 Trace JSONL，且首条记录是一个带文件名安全 `session_id` 的 `session_meta`——在服务层构建路径的那一处重新校验。若目标 Agent 下已存在同名 session id，则直接拒绝（409）：一个会话的第 _N_ 号文件意味着「上下文分段 _N_」，因此把一个无关文件塞进那里，会把它拼接进既有的对话记录、悄然成为恢复点，并与实时会话的写入者竞争。因此一次被接受的导入总是某个新会话的 001 号文件，以 `wx` 写入，使并发导入也无法互相覆盖，并按其首条记录的本地日期归档（与 Trace 写入者的约定一致）；超大的选择会在任何上传发生之前于客户端被拒绝。目录树会立即刷新并选中导入的文件；被导入的会话与其他任何经目录发现的（「非托管」）会话一样可浏览。

## 应用知道自己的版本，并能自我更新

侧边栏用户菜单在「修改密码」正下方新增一行**检查更新**，其右侧行内显示运行中的版本（`v0.1.3`，不带产品名前缀），当检查发现新版本时带一个上标的「有新版本」角标；该行的 tooltip 携带一句可读的 `最近更新 7 月 26 日`（`Last updated Jul 26`），它**完全离线**地取自随发布打戳的 `BUILD_DATE`——今后每个发布都会在 tarball 与 npm 两个任务中于发布时存下它的日期，为此绝不发起任何网络查询。点击该行会强制一次新的检查（`?force=1` 会穿透服务端的 TTL 缓存——这是用户发起且低频的——其结果会被重新缓存），而「已是最新」与失败情形均经共享的 toast 呈现。新会话草稿页在其副标题下方带有同样一行安静的文字，角标即为发布说明链接。打开该菜单同样会触发一次更新检查，这是服务端唯一一次、也是第一次对外网络调用：以与 `penguin update` 相同的请求形态拉取最新的 GitHub Release，在服务端缓存（成功缓存一小时，失败缓存十分钟），严格软失败——查询失败只报告「未知更新」，绝不报错——而 `PENGUIN_UPDATE_CHECK=off` 可将其完全禁用。当存在更新的发布时，头像会亮起一个圆点，菜单中出现发布说明链接；管理员另外获得**立即更新**，它会重新运行 CLI 自己的更新器（`penguin server|web` 把其入口导出为 `PENGUIN_CLI_ENTRY`；该端点以固定的参数列表 spawn `node <entry> update --yes`——请求中的任何内容都不会进入该命令）。CLI 的安装方式检测与各种拒绝逻辑逐字沿用，而一次成功的运行只会说出那件仍然需要人来做的事：重启服务以加载新代码。
