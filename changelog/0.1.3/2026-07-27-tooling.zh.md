# 工具链：让 Windows CI 保持诚实

- **Date:** 2026-07-27
- **Type:** process
- **Scope:** `tooling`, `ci`
- **PR:** [#88](https://github.com/Prism-Shadow/penguin-harness/pull/88), [#90](https://github.com/Prism-Shadow/penguin-harness/pull/90), [#94](https://github.com/Prism-Shadow/penguin-harness/pull/94)

[English](2026-07-27-tooling.md)

三项后续工作加固了新的 `ci-windows` 任务，使其能应对 runner 的各种病症，且每一项都以证据而非盲目重试为依据：server 测试套件的清理现在会对 `ENOTEMPTY`/`EBUSY` 的删除做重试，并在按平台区分的超时下运行（此前一次清理失败会连锁引发后续多个文件的「database is not open」）；core 的 win32 测试超时提高到 120s，依据是带埋点的运行显示在一台降级的 runner 上，一次冷启动的 Git-Bash spawn 耗时 35.7s——并有一次放大实验证明延迟是 1:1 地穿过引擎，不存在竞态——另配一个平台中立的回归测试，固定住「一个慢工具只按其自身延迟拖慢运行」这一性质；还有两处由 main 的 CI 捕获的跨 PR 组合性破坏（一个测试替身缺少了新近必需的成员，以及对路径分隔符想当然的断言），在出现当小时即修复。这一批以一次依赖安全清扫收尾：23 个开放的 Dependabot 告警全部以真实修复解决——vitest 3、react-router 8 与 hono-node-server 2 三个大版本升级均经全套测试验证，范围内的传递依赖刷新，另有两个临时 override（`@anthropic-ai/sdk`、esbuild）各自带有明确的退役条件——使 `pnpm audit` 在 dev 与 prod 两个范围下均归零。
