# MMSP 0.5.2：Google 的官方客户端改名 `google-official`，协议菜单新增 Google GenAI 与 MMSP

- **Date:** 2026-10-10
- **Type:** feature
- **Scope:** `core`, `web`, `cli`, `docs`, `skills`
- **PR:** [#1016](https://github.com/Prism-Shadow/penguin-harness/pull/1016)

[English](2026-10-10-mmsp-0-5-2-clients.md)

PenguinHarness 升级到 `@prismshadow/mmsp` 0.5.2。这一版把 Google 的官方 Gemini 客户端命名为 `google-official`，并新增连接 MMSP 服务器的 `mmsp` 客户端。base URL 输入框里的协议菜单在原有三种协议之后，新增了 Google GenAI（generateContent）与 MMSP。

## 路由

- core 对 MMSP 路由的镜像跟随 0.5.2：未设客户端类型、以 `gemini-` 开头的模型 id 路由到 `google-official`；它在 `MMSP_CLIENTS` 中的一行沿用 `gemini-official` 那一行的环境变量（`GEMINI_*`）、请求路径（`/v1beta/interactions`）与快速模式协议。Web 端 Google 分组的协议路径也改用 `google-official`。
- `gemini-official` 保留为别名行，存有这个名称的 Project 照常可用，且从不被改写：见[向后兼容](2026-10-10-backward-compatibility.zh.md)。
- 官方 Anthropic 客户端上的 `claude-haiku-5-5` 不再提供快速模式开关：MMSP 0.5.2 对它拒绝快速模式，与 Sonnet 5.5、Fable 5.1 相同。

## 选择协议

- base URL 输入框右端的协议菜单在 OpenAI Responses、Anthropic Messages 与 OpenAI Chat Completions 之后，列出 **Google GenAI (generateContent)**（`/v1beta/models`）与 **MMSP**（`/stream`）。custom 与自建分组的模型弹窗、各分组的分组设置，以及新增分组的弹窗，用的都是这同一个菜单。
- 存有 `google-genai` 或 `mmsp` 的模型或分组，在菜单中显示为已选中，不再显示只读的「沿用原配置」提示。存有 `gemini-generate-content`（`google-genai` 在 0.5.0 中的名称）的，显示为 Google GenAI，不会被改写。
- 协议检测不变：只探测 OpenAI Responses、Anthropic Messages 与 OpenAI Chat Completions，Google GenAI 与 MMSP 需手动选择。
- `penguin config model add --client-type` 的帮助文案列出了这五种协议。

## `mmsp` 客户端

- 走 `mmsp` 的模型只在解析不出 base URL 时回退到 `MMSP_API_KEY` 与 `MMSP_BASE_URL`（缺省为 `http://127.0.0.1:25752/v1`），由客户端自己读取。有 base URL 而没有 key 时，以不带 key 的方式构建客户端，而不是拒绝，开放的 MMSP 服务器正是这样调用的；新增分组的弹窗同样可以不带 key 列出这类服务器的模型。这是该客户端自己的规则。
- `mmsp` 不提供快速模式开关：客户端把它转发给服务器，由服务器上该模型那一行的客户端决定。

## Skill 与文档

- `agent-development` 插件的 `unified-llm-api` Skill 更新到 MMSP 0.5.2：`google-official` 及其别名 `gemini-official`、`mmsp` 客户端及其凭证、`UpstreamError`，以及 Claude Haiku 5.5。插件版本升至 `2026.10.10.1`。
- 模型与配置文档页列出这五种协议，改用 `google-official`，并说明 `mmsp` 客户端的环境变量与快速模式。
