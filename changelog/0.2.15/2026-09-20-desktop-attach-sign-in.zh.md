# 数据目录被别的服务端占用时，桌面应用自己完成窗口登录

- **Date:** 2026-09-20
- **Type:** fix
- **Scope:** `desktop`, `server`, `web`, `docs`
- **PR:** [#811](https://github.com/Prism-Shadow/penguin-harness/pull/811)

[English](2026-09-20-desktop-attach-sign-in.md)

桌面应用发现数据目录已被另一个服务端占用时——`penguin web` 或 `penguin server` 实例，或仍在运行的旧版应用——会附着到那个实例，并把窗口留在 App 的登录页上。而那个页面要的密码根本不存在：桌面端为 admin 生成的是一个随机值，哈希后即丢弃，从不显示，于是唯一的出路是去终端跑 `penguin server reset-admin-password`。现在壳自己完成登录：在它所拥有的数据目录里签发一个会话，并为窗口设置对应的 Cookie；此后窗口每次再落到登录页，也照此处理。

## 细节

- `attach-session.ts` 负责规划这次登录：它对数据目录调用 server 包的 `mintApiToken`，返回要设置的 Cookie，或一份可供展示的失败说明。签发函数是参数传入的，模块因此保持纯粹，每种结果都由测试覆盖。
- 签发的会话有效期为三十天，与普通浏览器登录相同。更短的会话够不到服务端的续期窗口，无论窗口怎么使用都会按时过期。
- 附着模式在开窗之前设置 Cookie，然后加载应用根地址。同一套尝试也挂在主窗口的导航事件上，因此会话过期与 claim 失败都会重新变成已登录状态，而不是停在登录页。每次抵达登录页只尝试一次，只有窗口到达 App 只对已登录窗口提供的页面时才重新武装。
- 退出登录的效果予以保留。壳会观察 App 结束会话的那个请求，并放任随之而来的登录页不管，直到再次有人登录、或应用重新启动为止——其余各种抵达登录页的情形照常处理。
- `mintApiToken` 新增 `via` 选项标记会话的种类，默认仍为 `cli`，`penguin auth token` 的行为不变；桌面端签发 `desktop`，App 据此在修改密码表单里省去当前密码一栏。
- 修改密码表单是否索取当前密码，改用与服务端判定相同的组合条件——会话为 `desktop`，且服务端以桌面模式启动——于是在服务端仍要求旧密码的场合，这一栏不会再消失。
- 签发失败时——`web.db` 属于另一个操作系统账号、由另一个版本写入，或数据目录里根本没有 `web.db`——弹窗会给出数据目录、占用它的服务端的端口与 pid、签发失败的原因，以及 `penguin server reset-admin-password` 这条补救命令，然后继续前往登录页。
- 会话失效把子窗口送去登录页时，子窗口直接关闭而不再显示登录页：分离出去的终端标签因此回到主窗口的停靠面板，而不是被困在一张用不了的表单后面。
- 会话 Cookie 的名字是服务端 `SESSION_COOKIE` 的一份副本，由一条测试把两者钉在一起。
- 桌面端快速开始文档新增一段，说明数据目录被别的服务端占用时会发生什么，以及窗口仍然出现登录页时该怎么做。
- 初始密码提示条在壳签进来的窗口里不再出现：它提醒的是握有那个密码的人，而壳自签的会话既没有那个密码、也改不了它；该提醒的人在起那台 server 的终端里已经看到了开机提示。
