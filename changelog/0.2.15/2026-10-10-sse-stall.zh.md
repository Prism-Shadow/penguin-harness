# 实时流无声断开时，Web App 自行追上进度

- **Date:** 2026-10-10
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#1026](https://github.com/Prism-Shadow/penguin-harness/pull/1026)

[English](2026-10-10-sse-stall.md)

Session 流或用户事件流的连接如果在没有任何错误的情况下断掉（半开的连接、卡住的代理或 NAT、休眠或切换了网络的笔记本），页面会一直停在原处，直到刷新，而 Agent 仍在服务器上继续运行。现在页面会察觉这段静默，从收到的最后一个事件处续接流；服务器也会切断对端已不再读取的流。

## 细节

- 服务器的心跳改为名为 `ping` 的事件（`data: {}`，没有 `id:` 行），在流的初始事件之后立即发送，之后每 20 秒一次，取代页面看不到的注释行。它既不改变客户端的 `Last-Event-ID`，也不改变重放位置。
- 流发送过 ping 之后，Web App 把 50 秒内没有任何事件判定为连接已死：关闭这条流，从见到的最后一个事件 id 新开一条。服务器据此重放；该 id 已移出缓冲区时则回以 `resync_required`。标签页重新显示时立即检查一次。
- 来自从不发送 ping 的服务器的流（例如仍在旧版本上的机器）以及浏览器已放弃的流，行为与以前相同。
- 没有 `Last-Event-ID` 请求头时，`GET /api/sessions/:id/stream` 与 `GET /api/events` 接受以查询参数 `lastEventId` 传递的最后事件 id，因为页面自己新建的 EventSource 无法设置请求头。两者同时出现时以请求头为准。
- socket 连续 40 秒没有发出任何数据（有写入挂起时最长 80 秒）的事件流会被关闭连接，仍然在线的客户端随之重连并续传。
- 服务器 API 参考文档（`/docs/server-api`，「流式传输（SSE）」一节）补充了 ping 事件、`lastEventId` 参数、空闲超时和客户端的存活检查。
