# 输入框附件：把文件拖拽到聊天区

- **Date:** 2026-08-18
- **Type:** feature
- **Scope:** `web`, `docs`
- **PR:** [#319](https://github.com/Prism-Shadow/penguin-harness/pull/319)
- **Issue:** [#311](https://github.com/Prism-Shadow/penguin-harness/issues/311)

[English](2026-08-18-web-drag-drop-upload.md)

把操作系统的文件拖拽到**聊天区**（即对话与输入框所在的区域），成为输入框既有附件通道的第三个入口，与「+」菜单的选择器和粘贴图片并列。在此之前，文件被放到页面上只会触发浏览器的默认行为：标签页跳转去打开该文件，正在运行的应用连同尚未发送的草稿一起被顶掉。

## 拖到聊天区

- 文件拖动经过聊天区时，会显示一层限定在该区域内的「松开以添加附件」浮层，松手即把整批文件交给输入框。会话页与草稿页都可用，Task 运行期间同样可用。
- 图片走粘贴图片的同一管线（`image_url` 部件；不支持视觉的模型仍回退为 scratchpad 路径），其余文件成为文件附件（写入 scratchpad，并追加一行 `[attached file: <path>]`）。校验与报错与「+」菜单一致——超限的文件在读取前即被拒绝，弹出原有的提示。
- 目标模式接受拖入的图片，拖入文件则以提示拒绝，与该模式下「+」菜单把文件项置灰是同一条规则。
- 非文件的拖动在任何位置都被忽略——选中的文本、拖动的链接与页面图片、侧边栏的会话拖动排序——所以把选中的文本拖进输入框，依旧是浏览器原生的插入行为。

## 聊天区之外

- 侧边栏、顶栏、对话工具条、右侧停靠的 Files 与 Subagents 面板，以及任何没有输入框的页面，都在拖放目标之外：不会亮起浮层，也不会添加任何附件。
- 应用外壳上的一道守卫（`guardWindowDragOver` / `guardWindowDrop`）会取消浏览器「跳转去打开文件」的默认行为——只针对聊天区没有接管的文件拖动——并在这类拖动悬停时显示禁止放置的光标。这道守卫刻意保持沉默：不显示浮层、不添加附件、不弹提示，只为让文件放在那里彻底无事发生，而不是把应用丢掉。

## 细节

- 浮层的显隐在每个事件上依据拖动的当前位置重新推导，而不是靠 enter/leave 计数累加，因此拖动若在浏览器之外结束（既不触发 `drop` 也不触发 `dragend`），也不会把浮层永久留在屏幕上。
- 判定逻辑——文件拖动识别、区域命中判断、批次拆分与外壳守卫——落在 `packages/web/src/lib/file-drop.ts`，保持不依赖 DOM 并配有单元测试；`packages/web/src/features/chat/drop-zone.tsx` 中的 `ChatDropRegion` 与 `FileDropZone` 负责把它接到聊天区与输入框上。
- Web 应用文档页以中英两种语言补充了这一流程的说明。
