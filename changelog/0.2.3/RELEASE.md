PenguinHarness 0.2.3 — conversations you can branch, take back and watch: fork a Session from a completed reply, recall a queued steering or follow-up message into the composer to edit and resend, live per-row Session status in the sidebar, a compaction that streams its summary into a row you can open instead of passing as a silent gap, thinking levels selectable wherever the work happens with a mid-chat switch that states its cost first, and custom model entries that detect their own protocol and vision support.

## Install

**Desktop app**: grab your platform's installer from [penguin.ooo/download](https://penguin.ooo/download) — served from the OSS mirror when it is reachable, GitHub otherwise. The macOS builds are Developer ID signed and notarized, and as of this release the Windows installers are Authenticode-signed too, so neither platform needs a first-launch unblock.

CLI / server (Linux, macOS; bundled Node runtime):

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows (PowerShell):

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

Or via npm (needs Node >= 24):

```sh
npm install -g @prismshadow/penguin-cli
```

## Highlights

**Fork a Session from a completed reply.** Completed root assistant replies gained a **Fork** action beside Copy: confirm, and the conversation is duplicated into a new Session up to that reply, keeping the Project, Agent, model, Workspace, approval mode and title while truncating the transcript at the selected completed Task. Forks own independent Trace shards and a recursive scratchpad snapshot, and local image and file marker paths are rewritten to the new Session id, so attachments keep rendering after either Session is deleted. The server rejects forged or unsafe Trace positions and refuses to fork while the source is running or compacting. Discarding a fork got quieter too: deleting the conversation you are looking at used to leave a `session_not_found` record behind on every delete, visible in the Cost Center's error panel, and the Session list now tombstones the ids it deletes so that lookup never fires.

**Recall a queued message back into the composer.** A mid-run message still waiting — an undelivered steering message, or a follow-up queued behind the current run — can be pulled back into the input box, edited and resent. Every queued hint line above the composer gained an icon-only recall control; clicking it withdraws the message server-side and restores its original content in front of whatever is currently typed, with images and file attachments coming back as composer chips and a follow-up restoring the per-turn thinking level it was queued with. New `DELETE` routes for steering and follow-ups back it, `task_state` gained the pending follow-up list that rebuilds the hints after a reload, and every recall re-broadcasts, so the hint disappears in the other tabs too — including the one that sent the message.

**The sidebar says what every Session is doing.** A row now carries an hourglass that turns while its Session is busy — amber for a compaction, gray for a run — and a green dot afterwards for as long as the last reply has not been read; a Session whose reply has been read shows nothing at all, so the only marks left in the list are the ones worth acting on. Status is live for every row rather than only for the conversation on screen: the server publishes each flip on the user-level event stream, so a scheduled task, a subagent or another tab lights up the row it belongs to, and a run that finishes while you are looking elsewhere leaves the unread dot instead of settling silently. Nothing polls, read state is tracked per Project in the browser, and both live states and the dot name themselves in their tooltip and accessible name in both locales.

**A compaction you can watch, and one that runs when it should.** Compaction stopped being a silent gap in the transcript: the summary rides the output stream as it is written, inside a row collapsed by default exactly like a thinking block, which you expand to watch it being generated or to read it afterwards — and a reader joining mid-compaction picks up the prefix generated so far. The row also names what it did, so a step that drops the old context reads "Clear" rather than being announced as a compaction, and a discarded round is flagged as a compaction turn at all now instead of rendering as a bare card. Two defects went with it. A compaction triggered on a turn that ended in tool calls now runs those tools to completion and compacts with their results in their original call order, inventing nothing synthetic. A compaction the user quit out of is closed as a failed compaction the next time the Session loads, its half-written summary discarded rather than reconstructed — so messages sent after a compaction survive a reload and stale "(unknown tool)" cards are gone. And compaction works on a Session resumed after a client restart, where it was refused with "nothing to compact" however long the conversation actually was; availability is now answered from the state the Trace replay recovered, and each of the three refusals got its own error code so the reason arrives in the reader's language.

**Thinking level, chosen where the work is — and a switch that says what it costs.** The composer's picker stopped applying a mid-chat change silently: a pick that would move the level opens a confirmation stating in one sentence that switching lowers the provider's prompt-cache hit rate and raises the cost of the next request, and offers three ways out — "Compact, then switch", which runs a compaction and applies the level once it ends; "Switch anyway"; and Cancel. The picked level is now stored on the Session, so it survives a reload and outlives a later Agent-config edit. AgentHub 0.4.4 added a `max` tier above `xhigh`, selectable in the Web pickers, valid for `run_subagent` and accepted everywhere a level is stored or sent, and every tier is now labelled with the value it actually sends. `run_subagent` gained a `thinking_level` argument so the model can run a cheap mechanical subtask lower and hard analysis higher, and the CLI gained `--thinking` on `run` and `chat` plus a `/thinking` command that reports the level the next turn will run at and overrides subsequent ones. Widening that enum changed the default tool entry, so every existing Agent takes a kernel update — automatic wherever the stored entry was not hand-edited.

**Model entries that find out for themselves.** Pointing the harness at your own endpoint stopped being guesswork. Custom and user-defined groups are no longer pinned to one protocol: a **Detect** action in the model dialog probes which of AgentHub's generic protocol clients a base URL serves — `openai-responses`, then `ant-messages`, then `openai-chat`, first hit wins — with minimal invalid requests that bill nothing and need no model id, so even a keyless endpoint can be classified; confirming the dialog while the protocol is still unset detects first, and falls back to `openai-chat` rather than saving an entry that cannot start. A second probe beside the vision switch sends one 1x1 PNG and a one-word prompt and turns the switch on when the model answers — a real billed completion, so it runs only on an explicit press. Model entries also gained a **fast mode**, opting a model's session requests into the provider's faster serving tier at premium pricing (`service_tier: "priority"` on OpenAI-protocol clients, `speed: "fast"` on Anthropic-protocol ones). It is offered only where the resolved client can actually serve it, switching it on asks for confirmation and names what the premium is not reflected in — the entry's recorded prices, and so every cost surface — and a model that rejects the parameter anyway fails the run immediately with a message naming the fix instead of retrying.

## Notable in this release

- **Session rows.** The hover pair — archive and delete, one click each — returned to the row's trailing slot, and the full set (pin, rename, archive, delete) moved onto right-click, press-and-hold and Shift+F10, anchored to the row rather than to a viewport corner. The list-options menu took leading glyphs on all four rows, and a title clipped by the sidebar's width scrolls its hidden tail into view on hover or keyboard focus, holding still for 0.3s first so a pointer crossing the sidebar leaves every row as it found it.
- **Web App polish.** Files dragged onto the chat area now attach to the composer, and a file dropped anywhere else no longer navigates the tab away from the running app; exited background processes became removable from the session details card; copy buttons confirm with the check icon alone, announced to screen readers through a live region; the Trace file row shows a single-line file name with the full path on a copy button beside it; and the models page keeps every group action reachable as an icon-only control on narrow rows.
- **CLI.** `penguin config model remove` closes the model CRUD gap, deleting an entry with the credential inlined on it and reporting the resulting default; `penguin server reset-admin-password` recovers a forgotten admin password from the machine that owns the data root, re-arming the whole initial-password machinery; and the chat REPL collapses long tool output to its first and last four lines with a marker naming how many it hid, which `/verbose` and `penguin chat --verbose` switch off. Collapsing is display-only — the model, the Trace and the Web App receive the complete text either way, and `penguin run` never collapses.
- **Models.** The catalog was refreshed against AgentHub's line-up: Gemini 3.7, GLM-5.3 and the GPT-5.6 generation joined the direct groups along with their OpenRouter counterparts, plus Grok 4.6 and DeepSeek V4 Pro 0813; a new MiniMax group ships a direct `MiniMax-M3` preset; the direct and gateway DeepSeek rows were re-priced from the current official lists; the delisted `inclusionai/ling-3.0-flash:free` row was dropped; OpenRouter's `openai/*` rows moved onto the Responses protocol; and the generic Chat Completions client was renamed `openai-chat`, with bare `openai` still a working alias that is normalized on read. Gateway heartbeats injected into a streaming response no longer fail the stream, ending the endless "reconnecting" through one-api-style proxies and OpenRouter.
- **Hot update.** A running PenguinHarness, the desktop app included, can be updated in place: `POST /api/hmr/upgrade` replaces the backend platform, the CLI's command implementations and the Web App as one atomic version, with no restart and no reinstall, and live state such as a running terminal process survives the swap. The new platform must boot and the web dist must validate before anything is committed, a restart resumes the last committed version as a unit, and one rollback candidate is kept. The hot APIs require an admin session and are loopback-only unless served over HTTPS.
- **A lighter code highlighter.** The first code block a conversation renders pulls ~69 KB gzip instead of ~308 KB: Shiki's JavaScript regex engine replaces the Oniguruma WASM engine, and an explicit language list replaces the 332-grammar registry. `dist/` drops from 11 MB across 304 chunks to 3.3 MB across 29. A fenced language outside that list renders as unhighlighted monospace.
- **Proxy options accept SOCKS.** The admin proxy address takes any proxy URL undici's dispatcher does — `http://`, `https://` and the (experimental) `socks5://` / `socks://` schemes, credentials allowed — gated by constructing a probe agent rather than by a scheme list, so a value undici cannot speak is refused at write time instead of crashing every later startup. The bare `host[:port]` shorthand and the loopback exemption are unchanged.
- **Traces.** The trace index's mtime gate now stats every known date directory rather than only the newest, so a shard that compaction rotated into an older directory is indexed instead of leaving the conversation stuck on the compaction banner until something else happened to trip the gate.
- **Desktop.** A dedicated macOS icon master centres the brand artwork in the platform's safe area, matching the optical size of neighbouring Dock and Launchpad apps.
- **Docs and skills.** Installation was folded into Quickstart, which became an overview branching into one page per route (desktop app / CLI and Web App / SDK), the usage guides moved ahead of the core-design chapters, and the renderer gained tabbed code blocks, collapsible callouts and Shiki highlighting behind dynamic imports. The `remote-claude-code` skill moved to v2: user messages are relayed word-for-word, permission prompts and plan approvals are carried back to the user, multi-line messages travel through a tmux buffer, and menu navigation runs one key per call with a capture in between.
- **Contributor tooling.** An unpackaged desktop run takes a `PenguinHarness-Dev` identity and its own data root, so hacking on the shell no longer collides with an installed release build; and `pnpm penguin` at the repo root runs the CLI again after the entry split left it importing a module that ran nothing.
- **Breaking (thinking levels on DeepSeek).** AgentHub 0.4.4 aligned the DeepSeek client with the effort vocabulary DeepSeek actually accepts: `low` now sends `low` where it sent `high`, and `xhigh` now sends `high` where it sent `max`. A DeepSeek Session left on `xhigh` reasons less deeply than it did — pick `max` to keep that depth; one on `low` reasons and costs less, and `high` is the closest match to its old behavior.
- **Breaking (`/compact` error codes).** Two of the three `POST /compact` refusals moved off the shared `nothing_to_compact` code onto `compaction_not_configured` and `already_compacted`. `nothing_to_compact` keeps its meaning — no completed conversation turn yet — along with its HTTP status and the shape of the error body, so a client that only rendered `error.message` needs no change.

## Requirements

Linux or macOS (x64 / arm64), or Windows 10+ (x64). The desktop app and the CLI installers bundle their own runtime; installing from npm needs Node >= 24. All data stays under `~/.penguin/data`.
