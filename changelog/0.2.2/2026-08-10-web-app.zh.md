- **Scope:** `web`, `server`, `core`
- **PR:** [#241](https://github.com/Prism-Shadow/penguin-harness/pull/241), [#245](https://github.com/Prism-Shadow/penguin-harness/pull/245)

## 头部统计变成详情卡，会话的进程就在其中

聊天工具栏的 Token / 成本 / 已用时间统计移到最右侧，并且它们本身就是详情入口：宽视口下点击这些数字即打开详情卡（不再有单独的信息图标），而窄视口把整个触发点收缩为那一个信息图标。当该对话有存活的后台进程时，一个绿色的运行中服务计数挂在已用时间右侧。

详情卡以小节形式展示模型、**Session id**（可选中的等宽文本，旁边配复制按钮）、工作区、创建时间与统计，其中统计以每行一个数字的项目符号列表呈现——Token 那一条读作 `总 Token <total>（缓存命中率 <pct>）`，命中率为缓存读取占全部已记录输入的比例。其下是一个可交互的**会话进程**列表：该对话启动的后台进程（一个活过了其让出窗口的 `exec_command`，比如跑在 localhost:3000 的开发服务器）各自显示命令、启动时间与 pid，运行中的行带一个停止按钮，它会杀掉整个进程组并移除该行。原先的「查看 trace」按钮变成同一套「标签加取值」结构下的 **trace 文件**小节，其中实际的 `.jsonl` 路径是一个带下划线的链接，深链进 trace 观测。

底层方面，命令会话现在暴露枚举能力（environment 与 core Session 上的 `listBackgroundCommands`；进程 id、pid、命令、cwd、启动时间、运行状态）与按 id 终止，由两个新端点提供服务（`GET /api/sessions/:id/processes`、`POST /api/sessions/:id/processes/:processId/kill`——只由活动运行时作答，绝不复活一个）。随之堵上两个真实的生命周期缺口：删除 Session、Agent 或 Project 现在会在其进行中的驱动结束后释放运行时，因此后台进程随对话一同消亡，而不是永远跑下去；而活动表的空闲清退会跳过仍有运行中后台进程的条目——清退它会让操作系统进程失去任何停止手段而被搁浅。

## 已打出但未发送的文本变成草稿对话

在新会话输入区仍有文本时点击任一「新建对话」入口——侧边栏按钮、分组头部的「+」、收起态导航栏、Agent 页，或 Skill 库的快捷调用（此前会静默覆盖已打出的文本）——现在会把那份草稿停放为一个**草稿对话**：会话列表顶部「草稿」分组中的一行（按用户 × Project 存于 localStorage，最新在前，上限 50）。打开某一行（`/chat/draft-<id>`）会恢复完整草稿——文本、Agent、工作区、模型、审批模式与已选中的 Skill——可随时编辑与发送；发送会创建真实 Session 并移除该行，而这些行也可以在确认之后删除。活动的草稿槽只保留模型的延续（「切换即成默认」，与发送之后一致），因此新会话总是从空白输入区开始，已打出的内容绝不会不可见地滞留。

## 管理员初始密码在被修改之前一直可见

预置的 admin 密码此前只在首次启动时打印一次；若那一行还没被读到就滚走了，凭证就没了。它现在会在仍是初始密码期间保存在数据根目录中（`initial-admin-password`，仅所有者权限），而每次服务端启动都会用 ASCII 边框重新打印并附上修改提醒——`penguin web` 挂接到一个已在运行的实例时也打印同样的提示。admin 的任何密码更新（自行修改、桌面端设置，或管理员重置——其所选的取值绝不持久化）都会删除该文件；在本次改动之前预置的数据根目录没有该文件，保持静默。文档相应更新。

## 面板交换先收回再展开

在 Agent 面板与工作区面板之间切换此前会同时运行两段宽度过渡：总宽度保持不变，因此正在关闭的面板其内容从不移动——它只是被进入的面板抹了过去，读起来就是「没有收回动画」。停靠面板的交换现在有了时序：已打开的面板完全收回（聊天列把空间收回去），然后另一个滑入。移动端的 Sheet 保持即时切换——它们是覆盖而非共享宽度。

## 对话打开时吸附在底部、位于提示横幅之下

消息流会在其滚动容器或内容于流提交之外发生尺寸变化时重新吸附到底部——此前初始密码横幅在 `/api/me` 解析之后才挂载，或者一张延迟加载的图片，都会让刚打开的对话停在离底部一个横幅高度的位置，而且没有任何滚动事件来纠正它。

## 定时任务：拾取器与默认值对话框对齐

定时任务的创建/编辑表单现在使用与 Project 新会话默认值对话框相同的表单式拾取器：在「每次运行新建 Session」模式下，模型与工作区控件就是那对共享的下拉框 / 目录浏览器（而不是一个光秃秃的 `<select>` 加一个裸路径输入框），而选中 Project 默认值——或者保持不动——意味着「跟随默认」，因此此后对 Project 默认模型的修改会继续贯通。「绑定 Session」模式把它那个自由文本的 Session id 字段换成一个覆盖该 Agent 完整会话列表的**可搜索下拉框**，按标题或 id 匹配。三个表单拾取器（模型、工作区、会话）现在共用同一个触发组件。

## 复制反馈保持一致，且始终落在按钮上

每一个复制控件都经由同一个共享按钮：反馈落在按钮自身——图标变成对勾，tooltip 读作「已复制」，空间允许时还会显示「已复制」文字——而且它绝不替换附近的标签。（详情卡的 Session id 行曾是唯一的例外，会翻转它的「Session id」标签；它现在与其余部分行为一致。）

## 更小的改进

保存 Project 新会话默认值现在会以一个「已保存」toast 确认（对话框保持打开，因此此前一次成功保存是无声的）。Agent 的 Prompt 标签页的「可用占位符」列表补回了缺失的 `{{SHELL}}` 项——默认系统提示词用了十三个占位符而该列表只显示十二个——并配一个测试把该列表固定到真实的默认提示词上，使它不会再次漂移。基准测试的 case 详情对话框打开时两个材料分组（任务材料与 rubric）都展开，readme 的自动预览留在任务材料一侧，因此两者不会争抢预览窗格。而会话输入区那个只读模型芯片现在可点击：它会说明 `/model` 用于切换模型，并在新会话中继续该对话。
