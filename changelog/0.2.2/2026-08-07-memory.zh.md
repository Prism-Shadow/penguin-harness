# Memory：Agent 在 Session 之间保留下来的东西

- **Date:** 2026-08-07
- **Type:** feature
- **Scope:** `core`, `server`, `web`
- **PR:** [#144](https://github.com/Prism-Shadow/penguin-harness/pull/144)

[English](2026-08-07-memory.md)

Agent 现在拥有一个由它自己维护的长期存储：位于 `agent_state/memory/` 下的 Markdown 笔记，分为两个作用域——一个面向用户，一个逐 Workspace——各自带有一份进入上下文的 `MEMORY.md` 索引，而主题正文按需读取。它承载的是后续 Session 无法从 Workspace 重新推导出来的东西：用户是谁及其长期偏好、项目决策及其理由、约定、进入外部系统的入口。

Memory 不是上下文压缩。压缩保留的是单个 Session 的短期工作状态；Memory 是 Session 结束之后仍然幸存的东西。

## 作用域与布局

有两个作用域，都属于同一个 Agent，且绝不与另一个 Agent 共享：

- **用户作用域**（`memory/user/`）——无论 Agent 在哪里工作都成立的东西：用户是谁、他们的长期偏好、不绑定于某个代码库的参考材料。每个会话都会读取它。
- **Workspace 作用域**（`memory/<workspace_memory_key>/`）——关于某一个 Workspace 的事实：项目决策、收到的反馈、指向其外部系统的入口。同一个 Agent 在同一个 Workspace 中的各个会话共享它；不同 Workspace 的主题文件彼此分开。

每个作用域携带自己的 `MEMORY.md` 索引——每条记忆一行，`- [标题](file.md) — 钩子`，链接相对于该作用域目录——而不同 Agent 即便在同一个 Workspace 中也绝不共享 Memory。

```text
agent_state/memory/
├── user/                         # 用户作用域（随 Agent 一同创建）
│   ├── MEMORY.md                 # 该作用域的索引
│   └── prefers-pnpm.md
└── my-app-a81f32c4/              # 在该 Workspace 中的首个 Session 时创建
    ├── .workspace                # 该键所代表的 Workspace 路径
    ├── MEMORY.md
    └── testing-conventions.md
```

保留 `user` 这个名字是安全的，因为每一个生成出来的 workspace memory key 都是 `<base>-<8 位十六进制>`，因此总是带连字符——一个不含连字符的名字永远不可能被生成出来。

workspace memory key 是 `<安全的 basename>-<真实路径 sha256 的 8 位十六进制>`。身份由目录本身决定，不依赖 Git：指向同一目录的两个符号链接解析为同一个键，而移动或重命名一个目录会使它成为一个新的 Workspace——旧的 Memory 留在磁盘上、挂在旧键之下，而不是跟着一条不再存在的路径走。

**临时** Workspace 不获得 Workspace 作用域。它每个会话分配一个，因此绝不会有后续会话在那里运行并把它读回来——以它为键的记忆将是只写存储。这类会话仍然获得用户作用域，而它学到的任何东西本就该归在那里。判定依据是该目录的位置——是否位于某个 Agent 的 `workspaces/` 之下——而不是调用方是否显式传入了 Workspace，因为子 Agent 会把父级的 Workspace 作为显式参数继承下来，临时的也不例外。

一个主题文件是一个语义上的主题，而不是每个 Task、Session 或日期一个，并在 frontmatter 中声明 `name`（kebab-case，与文件名一致）/ `description`（一行，用于在召回时判断相关性）/ `updated_at`——一条记忆属于哪个作用域由它所在的目录表达，因此没有类型字段。正文中用 `[[name]]` 链接相关记忆，而更正 / 决策类记忆带 **Why:** 与 **How to apply:** 两行。绝不保存的内容：凭证、任务进度、未经确认的猜测，以及代码与 Git 历史本就说明了的事实。

## 什么会抵达模型

只有索引，经由模板的 `{{MEMORY}}` 占位符：它展开为 `memory.prompt`——Memory 是做什么用的、以模板示例形式给出的保存机制，然后是一节 `## User memory` 及其索引（`{{USER_MEMORY_INDEX}}`）——再加上 `memory.workspace_prompt`（一节 `## Workspace memory`，含 `{{WORKSPACE_MEMORY_INDEX}}`），后者仅当该 Session 运行在持久 Workspace 中时才出现，因此临时 Workspace 绝不会被告知一个它并不拥有的作用域。两份提示词都是逐 Agent 的配置，可在 Memory 标签页编辑，并像模板的其他小节一样以 Markdown 标题组织。`User Memory Dir` 那一行是字面模式 `<app_data_dir>/agents/<agent_id>/agent_state/memory/user`，可从 Environment 小节解析出来；而 `Workspace Memory Dir` 那一行经 `{{WORKSPACE_MEMORY_DIR}}` 渲染为已解析的结果，因为它的最后一段——workspace memory key——是一个模型自己永远拼不出来的路径哈希。

空索引会注入一句明确的「尚未保存任何内容」，而注入按每个作用域 200 行设上限，再以合计 25,000 字符作为长行索引的兜底——超过上限时，一条截断说明会告诉模型自行打开完整的 `MEMORY.md`。默认的 Memory 提示词声明了行数上限，并要求索引行控制在约 150 字符以内；字符兜底只存在于代码中。

不含 `{{MEMORY}}` 的模板不会注入任何内容——例如一个在 Memory 之前创建的 Agent。Memory 标签页会报告这一点，并提供把该占位符插入进去（插在 `# Environment` 之前，也就是默认模板给它的位置）作为一个显式的一键操作；绝不会自动拼接进去。组装后的提示词记录在 `session_meta` 中。

读取、写入与去重都是模型自己的工作，经由普通的文件工具完成——Harness 只决定 Memory 存在哪里、并把写入限制在其中，仅此而已。

## 在 Web App 中管理它

Agent 设置在 Prompt 与 Runtime 之间新增一个 **Memory** 标签页：顶部是开关（立即写入，不并入该标签页的保存，因此关闭 Memory 绝不会捎带上一处无关的半成品编辑），随后是按作用域分组的全部记忆——用户记忆在前，然后每个 Workspace 一组，以其目录 basename 为标题、完整的 `.workspace` 路径列在旁边，最近活跃者在前。分组点击头部即折叠，与 Skill 库同一套约定，而折叠状态按用户 × Project × Agent 记在浏览器中。每行显示该记忆的名称、描述与日期。

该标签页也在分组下方就地编辑那两份 memory 提示词。行是刻意只读的，配以像 Skill 标签页那样的纯图标操作。**查看**（眼睛）在桌面端的右侧抽屉、窄屏的底部抽屉中打开渲染后的正文（剥去 frontmatter——那些字段头部已经显示了），交互与聊天页面板一致（半高 / 全高吸附点）；**删除**（垃圾桶）会确认、删除文件，并从该作用域的 `MEMORY.md` 中机械地移除其 `](<file>)` 行，因此索引绝不会列出一个已经不在的文件；**编辑**（铅笔）先打开一个桥接模态——一个需求字段加上所生成提示词的实时预览，形态与 Skill 导入模态相同——然后经同一套草稿缓存路由跳转到与该 Agent 的新会话，提示词已预填、需求已填入（或留在末尾以便在输入区补完）。一条 Workspace 记忆的编辑会话还会钉住那个 Workspace，因此这个进行编辑的 Session 被注入的正是它即将改动的那份索引。

每个分组头部还带一个**新增**入口，是位于折叠箭头左侧的一个幽灵文本操作——沿用模型页的逐分组约定——其模态与编辑模态同形，含一个必填的内容或来源字段（粘贴的文本、一个文件路径或一个 URL；来源由 Agent 自己去读），桥接到一个新会话，由 Agent 把内容整理进该作用域。两种桥接草稿都刻意保持精简，只点明目标与诉求——保存机制本就住在该 Agent 的 Memory 提示词里。而 Agent 列表卡片的统计行会在其他计数旁以一个大脑图标显示记忆数量，并深链到 Memory 标签页。

关闭 Memory 会保留每一个文件，标签页也完全可用；它只是让 Memory 不再进入上下文、也不再为新 Session 准备目录。

API 位于 `/api/projects/:p/agents/:a/memory` 之下——概览、逐作用域的文件列表、文件读取、文件删除，以及幂等的占位符插入；刻意不提供内容写入或重命名，因为内容的改动经由聊天进行。它从不接受路径：一个文件由 Agent、作用域键与该作用域内的一个名称来寻址，每一项都经过校验，并在解析之后再次做包含性复核。
