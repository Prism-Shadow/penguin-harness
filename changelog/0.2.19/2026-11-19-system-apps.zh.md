# 系统应用移入应用中心

- **Date:** 2026-11-19
- **Type:** feature
- **Scope:** `web`, `ui`, `server`
- **PR:** [#1658](https://github.com/Prism-Shadow/penguin-harness/pull/1658)

[English](2026-11-19-system-apps.md)

模型库、插件市场、机器管理、成本中心与评估中心改为系统 Agent 的**系统应用**：每个都从导航入口改为应用中心的图块，打开的仍是原来的页面与地址，导航中的「应用中心」在这些页面上保持选中（设计：[PRFC-0033](https://github.com/Prism-Shadow/penguin-harness-design/pull/496)）。

## 细节

- **以页面贡献声明。** 带 `app: { order }` 的页面贡献即系统应用：Web App 的 `PageData` 与服务端的 `WebPageData` 都新增这一字段。图块的名称与图标取页面的 `title`、`titleZh` 与 `icon`，点开即进入页面 `path`，谁能看到由页面的 `admin` 决定，因此机器管理仍只对管理员显示。五个应用仍由各自的功能模块贡献，导航改为 `nav: "none"`，因而在安全模式下仍在。服务端模块插件可以用同样的方式贡献系统应用；带 `app` 而没有 `title` 的贡献页面不算应用，仍可按地址访问。
- **应用中心的图块。**
  - 没有个人排列时，系统应用按顺序排在最前；本次改动之前保存的排列，会在末尾追加它们，与新应用的规则相同。
  - 图块以页面的线条字形绘制在应用图标的形状上（UI 包的 `GlyphAppIcon`），悬停提示为「<名称>，系统应用」；点击即进入页面，不开窗口。
  - 系统应用的图块可以移动、编入分组，排列中记为 `system_agent/<页面 key>`。图块菜单只有打开、移动到…、向前 / 向后移动与移出分组，没有全屏打开、Agent 设置与移除。
  - 还没有任何 Agent 的应用时，Workbench 的说明与「用 AI 创建」按钮显示在系统应用之下。
  - 服务端的应用中心列表读取失败时，系统应用照常显示；机器的图块中从不出现系统应用。
- **导航。** 侧栏导航与收起的图标栏去掉这五个入口。在每个系统应用的页面，以及按路径位于其下的页面（如某个 Benchmark 的页面）上，「应用中心」保持选中。
- **系统 Agent。** 它的设置页「工作台」子页面列出查看者可打开的系统应用，每行带「打开」按钮；Agents 页上它的卡片显示这些应用的数量。
