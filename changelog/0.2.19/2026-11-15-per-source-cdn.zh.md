# 插件安装链可以经部署自己的镜像到达 GitHub

- **Date:** 2026-11-15
- **Type:** feature
- **Scope:** `server`
- **PR:** [#1563](https://github.com/Prism-Shadow/penguin-harness/pull/1563)

[English](2026-11-15-per-source-cdn.md)

插件安装链的两次取数——索引文档（`index.json`）与索引条目 channel 安装用的 release 资产——
今天各只有一个地址，都落在 GitHub 上；不可达它的部署发现不了插件、也装不上插件。两次取数
现在都带备选：部署可以配置改写规则（`PENGUIN_PLUGIN_PROXY`，一个 JSON 数组），把一个 URL 改
写成镜像提供同一份字节的地址；每次取数按配置的顺序逐个尝试地址——源自己的地址在前、改写出
来的在后——连接失败、超时、非 200 或答到一半停住的答案都会换下一个，全部失败时报错列出试过
的地址。不做测速选优，所以同一个部署每次取数走同一条路径，过的地址。不做测速选优，所以同一个部署每次取数走同一条路径，直到某个地址真的失败为止。

顺序的起点跟着成功走：每次取数从上次应答的那个地址开始（索引文档解析过的、字节校验过的），
canonical 死了的部署不必每次取数都付它的窗口。这是记忆，不是测速——不探测、不测速；起点死了
同一次取数内就把走序交回配置顺序，文档或字节被拒绝的地址不会被记住。

规则的形状照 Cloudflare 的 rewrite：`kind`（`"rewrite"`）、`match`（对整个 URL 的 JS 正则）与
`rewrite`（结果地址，`$1`–`$9` 引捕获组）。规则在配置解析时编译并做形状检查——最坏匹配时间
不是线性的模式（`safe-regex`，拒绝灾难性回溯：规则跑的输入一半是远端可控的）、超长度的模式
与 URL、不认识的规则类型，都在启动时拒绝而不是等到取数。镜像只换字节从哪里来：索引文档照旧
经同一个解析器，release 资产照旧按条目的 sha512 integrity 校验，镜像给了被改过的字节一样拒绝。

npm 从哪里拉包本身，现在是设置页（插件源）里的一个选项：官方 registry 在前且是默认，旁边列
着命名的镜像。安装器把选项作为 `--registry` 带进它跑的每一条 npm 命令；不设置时 npm 自己的
配置照旧生效，和从前完全一样。
