# 在其他机器上新建的对话改按该机器的沙箱默认设置启动

- **Date:** 2026-11-25
- **Type:** fix
- **Scope:** `web`
- **PR:** [#1862](https://github.com/Prism-Shadow/penguin-harness/pull/1862)

[English](2026-11-25-remote-machine-tool-approval.md)

修复了在其他机器上新建的对话里，即使该机器的沙箱默认预设要求先询问，工具调用也从不弹出审批请求的问题。新对话页原先会把从本服务端沙箱设置读到的审批模式随每次创建请求一起发出，现改为从会话实际运行的机器读取权限菜单和默认值；只有用户亲自选过，或 Project 的新对话默认设置指定了审批模式时，创建请求才会带上这一项，其余情况都交给那台机器按自己的默认预设决定。

## 细节

- 在那台机器的设置返回之前，新对话页的权限按钮显示「…」且无法展开，不再显示取自其他服务端的模式。
- 新对话草稿不再保存用户没有选过的审批模式。
- 权限菜单里的「更多…」会打开对话所在机器的 Agent 运行沙箱设置页，新对话页、对话中和子 Agent 面板都是如此。
