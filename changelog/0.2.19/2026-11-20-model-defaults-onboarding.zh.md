# 新建 Project 不再预设默认模型，首次打开时引导用户选定

- **Date:** 2026-11-20
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `cli`, `docs`
- **PR:** [#1674](https://github.com/Prism-Shadow/penguin-harness/pull/1674)
- **Breaking:** yes — 新建 Project 没有默认模型，在其中不指定模型就创建 Session、定时任务或组织会被拒绝，直到设置了默认模型

[English](2026-11-20-model-defaults-onboarding.md)

新建 Project 与「恢复默认」不再把 DeepSeek V4.1 Flash 设为默认模型：默认模型由所有者选定，Web App 在首次打开该 Project 时询问。默认模型集中到一个「默认模型设置」弹窗；模型配置里一键即可：对话模型「设为默认模型」，其他模型「使用模型」。已有 Project 保留原来的默认模型。

## 「默认模型设置」弹窗

- 模型库页头的「默认模型设置」（取代原先通往「项目设置 › 多模态模型」的入口）打开同名弹窗，分三组：**对话**（默认对话模型）；**多模态**（文本生成、图像生成、图片理解——即 Project 的视觉模型——、视频生成、语音识别、语音合成）；以及字色较淡的**工具**（网页搜索、读取网页，以及其他插件声明的绑定）。
- 这些模型用于哪里、每项选好即保存，收进标题旁的「?」（成员看到的那句写明只有所有者可以更改）；首次引导打开弹窗时说明原因的那句仍留在各行之上。
- 每行一个选择器，只列出能承担该项的已配置模型，选中即保存。没有候选的一行写「连接一个提供这类模型的供应商」并附「前往模型库」。成员看到同样的各行，只读。
- 文本生成未绑定时，该行写「跟随默认对话模型（<模型>）」；选定模型即绑定，选择器底部的「跟随默认对话模型」解除绑定。
- 弹窗即 `@prismshadow/penguin-ui` 的 `DefaultModelsDialog`，组件画廊新增「模型」板，与引导（`ModelSetupGuide`）同列。
- 「项目设置 › 多模态模型」与弹窗的多模态、工具两组列出同样的各行（次序、名称、候选、空态与「跟随默认对话模型」一致），二者共用同一组件 `DefaultModelSections` 与同一处填行代码；语音输入的润色设置仍在各行之下。

## 默认与使用中

- 「默认」只标出本 Project 的默认对话模型。「使用中」标出被选用于某项多模态或工具的模型（文本生成、图像或视频生成、语音识别或合成、网页搜索、读取网页，或任一插件的绑定），悬停列出用于哪些（如「用于：文本生成、网页搜索」）。对话模型可以同时带两枚标签。视觉代理模型仍用它自己的「视觉代理」标签，图片理解不计入「使用中」。两枚标签在卡片与模型配置里都显示。
- 模型配置不再逐项列出多模态能力、各带一个「设为默认」。紧挨「测试连通性」只有一个按钮：对话模型是「设为默认模型」，与此前相同；不能对话的模型是「使用模型」，先确认（正文列出各项），再用于它能做、当前又没有用它的全部各项，浮层列出用于哪些；全部用上之后按钮变为「取消使用模型」：不确认，直接从各项撤下，浮层列出撤下了哪些。一项也做不了的模型不显示按钮；弹窗有未保存的修改时停用。逐项指定（包括对话模型）在「默认模型设置」里进行。
- `PUT /models` 新接受 `visionModel: null`，即清除视觉模型（不带仍为保留）。

## 分组测速

- 不能对话的模型改为显示这次请求用了多久。语音识别改发一句简短的话（NASA 阿波罗 11 号的公有领域录音，随多模态工具插件发布），不再发无字的提示音（转写为空，卡片上什么也不显示）；语音合成朗读一个词，搜索搜一次，网页读取读一个网页，图像生成画一张小图。
- 视频模型不参与测速，卡片写「不测速」，悬停说明原因；本项目没有用到的、不能对话的模型同样如此。

## 首次引导

- 所有者打开没有默认对话模型的 Project 时：已有对话模型带 key（模型自己的、分组的，或服务端环境变量里的——与模型选择器同一判定）则直接打开「默认模型设置」弹窗；否则先出现引导，请其连接 TokenDance 或 Penguin Go（各自打开模型库并走该分组的连接流程），或者填写 key；key 一到（本窗口的改动，或回到窗口时），引导即换成弹窗。
- 引导与弹窗只在对话页上自动出现，每个 Project 在一个浏览器里只自动出现一次，关闭后记在该浏览器。成员不会看到。
- 之后，没有模型的新对话在输入框顶部显示一条注意色调的横条「还没有默认模型」，与输入框连成一体，所有者另有主按钮「设置默认模型」（成员看到「还没有默认模型，请找所有者设置」）；为本次对话选定模型或设置默认模型后消失。首页其余部分不变。发送要等选定模型。Project 没有默认模型时，新对话不再自动用列表里的第一个对话模型。
- 在没有默认模型的 Project 里连接 TokenDance 或 Penguin Go，改为打开「默认模型设置」弹窗，不再询问是否更换默认模型。「未配置 API key」引导只在默认模型存在而没有 key 时出现。

## 没有默认模型时

- 在没有默认模型的 Project 里不指定模型就创建 Session，得到 400 `no_default_model`，消息写明两条出路（指定模型，或在「默认模型设置」里、经 `penguin config model default` 设置默认模型）。
- 在这样的 Project 里，新建或更新不指定模型的定时任务、新建不指定模型的组织，同样被拒绝。定时任务表单此时要求选择模型，选定前「创建」停用。
- `penguin run` 与 `penguin chat` 遇到这一拒绝时输出「这个 Project 没有默认模型：请用 --provider 与 --model-id 指定模型，或用 `penguin config model default …` 设置默认模型。」，`penguin chat` 开场的模型一栏写明没有默认模型，并提示 `/switch-model <分组> <模型 id>`。
- `/agent` 交接的浮层等 Web App 各处的提示改为「该 Project 还没有默认模型，请先在模型库的「默认模型设置」中设置」。
- 文档「模型」页写入了弹窗、引导与新建 Project 没有默认模型的情况。

## 兼容性

已有的 `.project_config.toml` 保留其 `default_model`；变化的只是新建 Project 与「恢复默认」写入的内容。先创建 Project、再不指定模型就创建 Session、定时任务或组织的脚本，需要指定模型，或先经 `PUT /api/projects/:projectId/models/default` 或 `penguin config model default --provider <分组> --model-id <模型 id>` 设置默认模型。
