PenguinHarness 0.2.4 — a DeepSeek model that reads images, a workspace built to work in, and a cost center that reads as a time series: `deepseek-v4-flash-vision-exp` and a direct `claude-opus-5` joined the built-in catalog while an endpoint's whole model listing can now be imported in one save, the chat page's side panels and its terminals became tabs in two uniform docks over server-side shells that survive a reload, `exec_command` and `run_subagent` gained a background mode that reports back on its own with kill tools to end it, a Project-level command policy refuses destructive shell commands under every approval mode, and the usage charts were rebuilt around one shared time axis with range and precision controls.

## Install

**Desktop app**: grab your platform's installer from [penguin.ooo/download](https://penguin.ooo/download) — served from the OSS mirror when it is reachable, GitHub otherwise. The macOS builds are Developer ID signed and notarized and the Windows installers are Authenticode-signed, so neither platform needs a first-launch unblock.

CLI / server (Linux, macOS; bundled Node runtime):

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows (PowerShell):

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

Or via npm (needs Node >= 24):

```sh
npm install -g @prismshadow/penguin-cli
```

## Highlights

**A DeepSeek model that reads images.** AgentHub 0.4.6 added `deepseek-v4-flash-vision-exp`, and the catalog picked it up in two places: the direct DeepSeek group, where it is the only vision-capable model — a Session running it reads images itself instead of routing them through the `vision_model` proxy behind `describe_image` — with image input on top of V4 Flash's text capabilities, a 1M context window and V4 Flash's own price; and the OpenRouter group, at that gateway's published rates. Both rows record the official **off-peak** tier like every other DeepSeek row, so peak hours (Beijing 9:00–12:00 and 14:00–18:00) bill exactly double what the cost center counts. A fresh Project still defaults to `deepseek-v4-flash`. The same bump moved the first-party DeepSeek client from Chat Completions to the OpenAI Responses API: the base URL hint reads `/responses` for that group now, `https://api.deepseek.com` is unaffected because DeepSeek serves both, and a `deepseek-v4*` entry aimed at a Chat-Completions-only endpoint needs `client_type = "openai-chat"` set by hand.

**The rest of the model catalog work.** `claude-opus-5` was missing from the direct Anthropic group while its OpenRouter counterpart was already listed; the direct preset was added — 1M context window, vision, $0.50 / $6.25 / $25 per MTok — and the five sibling Anthropic rows were re-read against Anthropic's published pricing in the same pass, with a regression test and a comment pinning the one price inversion that looks like a transcription slip and is not. The models page's **add group** dialog gained an import mode: type a key and a base URL, detect the protocol (or pick it), and **Import all models** fetches every id the endpoint serves and appends them as entries of the new group in one save, each carrying the base URL, protocol and key inline — duplicates and unusable ids are skipped and counted in the toast rather than sinking the import, and only the id is taken from the endpoint, so pricing, context window and vision stay unclaimed until they are filled in. User-defined group headers gained a **Delete group** action. The connectivity test and the vision probe now send the lowest thinking level instead of turning thinking off, which several reasoning endpoints reject outright. And a model whose key comes from an exported environment variable finally counts as configured everywhere: the chat picker had judged that by the stored key alone, hiding an `ANTHROPIC_API_KEY`-backed model behind "show models without key" on the same screen where the library card printed that variable's masked value.

**Everything on the chat page is a tab, in one of two docks.** The drawer-style side panels and the old terminal pane system were replaced by two uniform dock surfaces, one on the right and one at the bottom. The subagents panel, the Workspace files panel, the Memory panel, a new Trace panel and any number of terminals are all closable tabs in either dock: both docks open at once, tabs switch by click, reorder by drag, move to the other edge by drag or by the dock's move button, and the old mutual exclusion between panels — and between panels and terminals — went away with the drawers. The arrangement is per conversation, like a browser window managing its own tabs, and survives a reload; one made while drafting is handed to the Session the first send creates, and a dock no longer follows the user onto pages that have no conversation of their own. The toolbar's per-element icons and their pin system collapsed into two pull-open buttons, an empty dock offers a centered picker, and each dock's "+" adds a tab, a fresh shell, or any live shell no conversation is holding. The Trace panel shows the current conversation's Trace files with the timeline and event list from the traces page, and the Traces entry left the left navigation — the browsing page stays reachable through its deep links. `` Ctrl+` `` walks the conversation's terminal states. Below 1024px the two docks render as one merged bottom surface and split apart again when the window widens. Saved arrangements from before the update are not carried over: the docks start closed once, and running shells are pulled back in from a "+" menu.

**Shells that live in the server, not in the tab showing them.** Terminals run in the daemon: every pty byte feeds a headless xterm there, so views are disposable and a reload, a moved tab or a second device repaints the exact screen — scrollback, colours, cursor and input modes — while the shell keeps running. `/api/terminals` is a JSON control plane (list / create / get / kill, plus plain-text `capture` and `keys` so a non-rendering client can drive a shell too) over a binary WebSocket data plane that coalesces output, resizes the pty to the attaching client and repaints with one Restore frame; a viewer lagging past 1 MiB is resynced rather than disconnected, sessions outlive connections, and there are 12 live shells per user. The shell is the user's own, started so their profile is in effect — `$SHELL -l` on POSIX, PowerShell rather than `%ComSpec%` on Windows, `PENGUIN_SHELL` overriding both — which is deliberately not the agent's command shell, and it is a shell as the server's OS account: the upgrade checks the session cookie and a strict `Origin`, and a terminal is for accounts you would give SSH. The terminal carries its own light/dark setting, defaulting to follow the app; clipboard follows terminal conventions on both platforms; and one terminal detaches into its own `/terminal?id=…` window and returns to its dock when that window closes. In the desktop app they work again: node-pty is the one dependency the bundler cannot absorb, and `pnpm build` now stages a trimmed node-pty package directory that both a source run and a packaged app resolve.

**Work that runs in the background and reports back.** `exec_command` and `run_subagent` gained a `run_in_background` argument: the call returns its `process_id` / `subagent_id` immediately, and when the task settles the result arrives **as a user message injected by the harness** — no polling loop. The report opens with a `[background_task_done]` marker block and carries the tail of the output not yet delivered; the Web App collapses it into a one-line notice with the body underneath. `kill_command` and `kill_subagent` end a background session — the first SIGTERMs the whole process group and returns the undelivered output, the second aborts the run, denies its pending approvals and frees the concurrency slot — and `input_command`'s default empty-poll wait went from 5000ms to 120000ms so one poll waits out most builds. A background subagent announces itself at launch instead of at the first poll, and the two ways it used to hang — a freshly created Session that never surfaced its reports, and a child parking forever on its first read-write tool because no polling window was open to resolve approvals — are fixed and covered end to end by Playwright against a real server. The kernel version advanced with the new tools and arguments, so an Agent already on disk adopts them through the settings page's kernel update, its own customizations kept. Alongside it, the background-process list learned to show a clickable link to the service a process serves: core scans the command's own output for local URLs and, when it printed none, probes the process group's listening ports.

**A Project-level command policy.** A deny-rule list now runs at the approval boundary for both tools that reach a shell — the command `exec_command` launches, and what `input_command` types into an already-running one — so a hit is rejected under every approval mode, allow-all included, and the model reads `Tool call denied by policy.` rather than a person's cancellation. The factory set is deliberately small and every entry is destructive with no undo: `rm` carrying both a recursive and a force flag, `mkfs`, `dd` onto a block device, the classic fork bomb, shell redirection onto a block device, and four Windows equivalents. Ordinary evasions of the spelling are normalized away first — a leading path, a `sudo`/`env`/`xargs` wrapper, quoting, a backslash escape, a literal `sh -c '…'` — while a command assembled at run time is deliberately out of scope: this is an accident guardrail, not a security boundary, and the boundary is process confinement, which is separate work in progress. The rules are plain editable data in the `[command_policy]` block of `.project_config.toml`, Project-owned so an Agent editing its own configuration cannot reach them, and every rule can be edited, switched off, deleted or added from Project settings — which became a tabbed dialog (General / Members / Defaults / Security policy) along the way.

**The cost center reads as a time series.** The usage charts were rebuilt around one shared time axis with a date-range preset — trailing last hour and last 24 hours, calendar last 7 / 30 / 90 days, or a custom pair of dates — where the range alone decides the precision the series is drawn at, so there is no second control to keep in step with the first. The share pie and the per-model progress bars were replaced by two requests-and-success-rate charts side by side, one by Agent and one by Model: stacked request bars against the left count axis, each entity's success rate as its own dashed line against a right-hand 0–100% axis in the same hue, the top four entities named with a CVD-checked hue each and the rest folded into a neutral series that says how many it folded. The Token chart kept its stacked bars and gained the cache hit rate as a dashed line; Cost stayed a polyline. Charts never scroll, no line is smoothed or heavier than another, and empty intervals get two different answers on purpose — a bucket where an entity made no request carries its line across and prints a dash in the hover table, while a bucket that recorded nothing at all is not drawn, with a break mark on the axis wherever it skipped. `GET /usage` gained `granularity`, `fromTs`/`toTs`, `series`, `byAgentSeries` and `byModelSeries`, and dropped `trend`, `byAgent` and `success` with the three queries behind them.

**Memory, on three fronts.** A Task that changed the Agent's Memory now says so in the conversation: a memory-changes card sits directly below the file-summary card, one row per topic file with the scope and the change kind as icon-and-tooltip markers, and clicking a row opens the new Memory panel straight on that memory's content. The panel is a peer of the subagents, terminal and Workspace tabs and holds two levels — both scopes' topics, then one memory rendered like the file viewer. Each scope group on the Memory tab also moves in one piece now: **Export** downloads the group as a single JSON document holding every memory and its `MEMORY.md`, **Import** reads such a document back into any group of any agent under one of three collision modes, and an import that would overwrite or delete anything is refused unless it is confirmed — the gate being what the import would actually cost rather than the mode's name. Export is open to any Project member; import is owner-only. And the built-in `memory.prompt` stopped leaving the judgement of *when* to save entirely to the model: it now names the moments that produce a durable fact — a request repeated, a correction that holds beyond the task, a habit stated more than once, a reusable working detail that would otherwise have to be asked for again — while dropping blanket prohibitions on things users do sometimes want kept. Despite the addition the prompt got slightly shorter, so no session pays for it.

**One settings dialog, and explanations that wait to be asked.** The rows and dialogs scattered through the sidebar user menu merged into a single **System settings** dialog with a left rail of Personal and Server pages: General, Appearance, Account, Proxy options, Upload limits and Users, each a list of title-and-description rows, with page visibility driven by one registry so a non-admin is never told a page exists. The old `/settings/:section` and `/admin/users` routes were removed. Checking for updates stayed outside it, on one row in the user menu directly under **System settings**, where the server row and the desktop client row share a slot and are mutually exclusive — an update is one click from the menu rather than two clicks and a page. Across those surfaces the explanations moved onto one rule: what a row or page *means* is disclosed by a circled "?" beside its title, and only what shapes a value — an MB range, "one `KEY=value` per line", a character rule — stays on screen where it is read while typing. Required fields converged on one rule too: a red `*` on the mandatory ones, no mark on the optional ones, and no label or placeholder saying "optional" — which corrected several fields that were refused when empty while carrying no mark at all. The four sections that can come up empty share one dashed block instead of a bare line of placeholder text, and the Skills tab's import action moved down to the head of the installed list.

**The draft screen.** Clicking an example used to create the Session and submit the canned prompt on the spot; it now fills the composer and stops — the prompt lands in the text body as editable plain text, the example's skills are preselected when the Agent has them installed, and the user presses Send. Five new examples arrived with a new folder: a Muse Dash-style rhythm runner, a conversational investment analyst built on the Penguin SDK, and three **Create scheduled tasks** entries that each set up a real schedule. And the block gained a last folder holding the user's own saved prompts: **New shortcut** opens an editor already carrying whatever is in the composer, with its first line suggested as the name; saving files it under the folder (three at most), clicking a row fills the composer like any built-in example, and the list is stored per user on the server, so it follows the account to another browser or machine.

**Per-server permission for MCP Servers.** An MCP Server entry gained an optional `permission` key with three states — `auto`, `r` and `rw` — that fixes the approval level of every tool that server exposes. `readOnlyHint` is optional in the MCP spec and many servers never set it, so their whole toolset landed on `rw` and the read-only approval mode stopped for it on every call; an explicit level overrides the annotation for all of them at once. Exactly one approval mode reads the level, and the key is not a sandbox: it never reaches the server and does not restrict what the server's tools do once they run.

**Desktop, packed and launched properly.** The desktop app stopped shipping a `node_modules` tree — `pnpm build` emits the shell, the server and the CLI as three self-contained bundles and `electron-builder.yml` lists exactly what goes into an installer, replacing the script that assembled, pruned and rewrote an app directory by hand. The app directory that ships shrank from 128 MB to 29 MB. GUI launches on macOS and Linux now read the user's login-shell environment before anything reads `process.env`, so keys exported in `.zshrc` or `.profile` reach the model env fallback and the agent shell gets the user's real `PATH` — merged fill-missing-only, with a 5s timeout, skipped from a terminal and on Windows, and opt-out through `PENGUIN_NO_LOGIN_SHELL_ENV`. Updating the client got its own row in the account menu of the shell's own window, driving electron-updater end to end — check, background download with progress, confirmed restart-to-install — over a desktop-mode API that a browser signed into the same server cannot reach.

## Notable in this release

- **Compaction threshold.** Newly created Agents are seeded with `compaction.max_context_length: 256000` instead of `128000`. The effective threshold is still the smaller of that and the model's window minus headroom, taken at every use, so a small-window model compacts exactly where it did before while a big-window model carries twice the context. Existing Agents are not migrated — edit the value on the Runtime tab, run **Update kernel**, or restore the default configuration.
- **Session titles.** Title generation stopped waiting for model output: the first words of the user's text are persisted as a fallback and pushed to the UI the moment a Task starts, while the LLM request runs in the background on the user input alone and replaces the fallback when it lands. The fallback truncation became word-aware, a manual rename is final, and a subagent's title now generates at registration from the prompt that spawned it.
- **The conversation list.** A third grouping mode joined Workspace and Agent: by time, cutting conversations into past day / past month / earlier on each one's last activity, with empty buckets dropped and the folders and paging row moved below the buckets as one Project-wide set. The chat header's details card gained an Agent row above the Model row.
- **Trace timeline.** Tool-call executions sharing a tool name and not overlapping in time now share one row, so a burst of serial calls to the same tool collapses from N rows to one. Only a different name, or same-name calls that really ran in parallel, still open extra rows.
- **A written-down design system.** Three conventions the Web App had been carrying implicitly are now enforced by tests: status colour is picked by meaning from one module of five tones (amber had been spelled three ways for one meaning), an explanation is disclosed on demand unless it is needed while typing, and a line icon comes from one renderer at one stroke weight in a role-named size. The session list's running hourglass moved to the shared amber, and compaction took a new mark so the two live states differ by shape and motion rather than by colour alone.
- **Streams survive what the client does not recognize.** AgentHub 0.4.5 marks an unrecognized stream event `unused` instead of throwing, so a gateway heartbeat crossing into the wrong protocol can no longer end a generation as `llm request failed after 5 retries`. `AGENTHUB_DEBUG` restores the guards.
- **Skills.** The `penguin-sdk` skill states its trigger up front — building an agent application, not configuring an Agent State inside PenguinHarness — and recommends wiring the user's own tools in as CLI commands, reserving MCP servers for what a CLI wrapper cannot express.
- **Build and CI.** Every package compiles for one Node target (`node24`), with `engines: { node: ">=24" }` finally declared on the two published libraries and a drift guard that fails when a tsup target and a package's declared engines disagree; `pnpm -r test` went from a 64.7s median to 38.7s (the server package from 51.5s to 13.4s) through a token scrypt cost in tests and a module registry shared across each worker's files; `ci-windows` split into two shards, roughly halving its wall clock; and `packages/desktop/.gitignore` now names every path a packaging run writes, so 340 MB of unpacked application is no longer one `git add -A` away from a commit.
- **Breaking (destructive commands are denied by default).** Every Project — existing ones included — begins rejecting the factory destructive commands under every approval mode, allow-all included, whether the command is launched with `exec_command` or typed into a running shell with `input_command`. A routine flow that relied on `rm -rf` (deleting `node_modules`, say) now gets the fixed `Tool call denied by policy.` To restore it, disable or edit that one rule — or switch the whole policy off — in Project settings → Security policy. No data migration is involved.
- **Breaking (`GET /usage` dropped three fields).** `trend`, `byAgent` and `success` are gone. `trend`'s points are in `series`, which defaults to exactly the same trailing 30-day window when no range is given; per-Agent request counts are the sum of `byAgentSeries[].requests`, and per-Agent Token totals come from `?groupBy=agent`; a Model's successful requests and non-aborted denominator are the sums of `byModelSeries[].completed` and `byModelSeries[].denominator`. The per-status counts `success` carried (`aborted`, `failed`, `timeout`, `malformed`) have no replacement — nothing displayed them, and the errors panel records source and code per failure. The Web App read none of the three, so only a third-party consumer of the HTTP API has to move.
- **Breaking (DeepSeek on the Responses protocol).** A model whose id contains `deepseek-v4` and which carries no `client_type` routes to the DeepSeek client by its id alone, and that client now posts to `{base_url}/responses`. Entries pointed at `https://api.deepseek.com` are unaffected. An entry pointed at an endpoint that serves Chat Completions only — a self-hosted server, a relay, a third-party DeepSeek-compatible gateway — starts failing after the upgrade: set `client_type = "openai-chat"` on it, in `.project_config.toml` or through the models page's protocol selector.
- **Breaking (`agent-creation` is now `agent-initialization`).** The Agent Tuning group's Skill was renamed for what it does — initializing an Agent's settings rather than creating an Agent. Behaviour is unchanged. An Agent that already installed `agent-creation` keeps its copy, which still works but corresponds to no library Skill and will never be updated again; install `agent-initialization` from the library and delete `agent-creation` from the Agent's Skills tab. There is no automatic migration, by decision, and anything that pins the Skill by name — a prompt, a saved shortcut, an `AGENTS.md` — needs the new name.
- **Breaking (saved dock arrangements).** The chat page's dock layout is stored under a new localStorage key; the three old terminal-dock keys are no longer read and are left in place, with no migration. The one-time effect is that the docks start closed after the update. Shells keep running server-side, and every live shell no conversation holds is pulled back in from a dock's "+" menu or the picker's terminal row. The shared side-panel width carries over unchanged.

## Requirements

Linux or macOS (x64 / arm64), or Windows 10+ (x64). The desktop app and the CLI installers bundle their own runtime; installing from npm needs Node >= 24. All data stays under `~/.penguin/data`.
