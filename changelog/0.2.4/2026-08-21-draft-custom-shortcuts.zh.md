# 草稿页新增用户自定义快捷指令折叠夹

- **Date:** 2026-08-21
- **Type:** feature
- **Scope:** `web`, `server`, `docs`
- **PR:** [#401](https://github.com/Prism-Shadow/penguin-harness/pull/401)

[English](2026-08-21-draft-custom-shortcuts.md)

在草稿页示例区末尾新增一个折叠夹，存放用户自己保存的快捷指令。点**新建快捷指令**会打开编辑框，其中已带上输入框中现有的内容，并以首行作为建议名称；保存后归入该折叠夹，点击某一行即把该提示词填入输入框、不发送，与内置示例完全一致。每行提供编辑与删除，列表按用户存放在服务端（`ui_prefs.draftShortcuts`），换浏览器、换机器都还在。

## 细节

- 一条快捷指令由名称与提示词组成，不绑定 Skill：用户保存的提示词并非针对产品内置的 Skill 目录撰写，且运行它的 Agent 是在点击之后才选定的。因此填入时输入框中已勾选的 Skill 原样保留。
- `PUT /api/me/prefs` 在写入前校验并规范化该字段——最多 3 条、名称最多 40 个字符、提示词最多 4000 个字符、id 不得重复、多余字段不入库——不合法时返回 `invalid_draft_shortcuts`（400）且不写入任何内容。Web App 侧保有同一组数值，用于计数与禁用态。
- 切换折叠夹时示例区高度仍然不变：内置折叠夹彼此长度相差不超过一行；「最多 3 条」这个上限让用户折叠夹（快捷指令行加上**新建快捷指令**行）同样落在这个范围内。它没有自己的滚动容器，也不再固定高度——只有几行的折叠夹里出现滚动条本身就像是坏了。注册表文档注释与该区块的注释都写明了这条规则，并有测试分别锁住这两半。
- 折叠夹标题右侧显示「已用/上限」（`0/3`、`1/3`、`3/3`）；到达上限后**新建快捷指令**行直接消失，而不是留一行禁用状态——标题已经说明了原因。折叠夹为空时就只剩这一行。
- 折叠夹标题行抽出为共用的 `ExampleFolderRow` 组件，内置折叠夹与本折叠夹共同使用。
