# AgentHub 0.4.3: gateway heartbeats no longer kill a stream

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `core`, `cli`
- **PR:** [#334](https://github.com/Prism-Shadow/penguin-harness/pull/334)
- **Issue:** [#286](https://github.com/Prism-Shadow/penguin-harness/issues/286)

[中文版](2026-08-19-agenthub-0.4.3.zh.md)

`@prismshadow/agenthub` moved from 0.4.2 to 0.4.3, which skips the heartbeat events gateways inject into a streaming response instead of failing the stream (agenthub [#174](https://github.com/Prism-Shadow/agenthub/pull/174)).

A gateway in front of a model API — one-api-style proxies, OpenRouter — sends a heartbeat during a long generation. On 0.4.2 that event reached the unknown-event guard and threw, the harness classified the throw as a retryable request failure, and the retry hit the next heartbeat: a long generation through such a gateway reconnected until it gave up, showing as an endless "reconnecting" in the Web App.

## Details

- Responses-protocol clients (`gpt-5.6`, `openai-responses`, `minimax-m3`) treat `keepalive` as a known no-op; Chat Completions clients (`openai-chat`, `deepseek-v4`, `glm-5.3`, `kimi-k3`) read `choices` only when the field is populated; the Anthropic-protocol clients (`claude-5`, `ant-messages`) accept `ping`; and Gemini clients skip a chunk carrying neither candidates nor usage. Genuinely unknown events still fail loudly.
- 0.4.3 also moved the MiniMax routing branch into the client-type chain, after the Kimi branch. Every client type routes to the same client as before, so the model catalog and the protocol-path hints are unaffected — the two published clients were diffed to confirm no base URL or endpoint construction changed between 0.4.2 and 0.4.3.
- `pnpm-workspace.yaml`'s `minimumReleaseAgeExclude` entry now names 0.4.3; the 0.4.2 entry was dropped as that file's own note instructed.
