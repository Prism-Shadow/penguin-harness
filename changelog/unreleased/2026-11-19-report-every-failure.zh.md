# 每一处失败都提供「[报告问题]」，拒绝不提供

- **Date:** 2026-11-19
- **Type:** feature
- **Scope:** `ui`, `web`, `ui-gallery`
- **PR:** [#1631](https://github.com/Prism-Shadow/penguin-harness/pull/1631)

[English](2026-11-19-report-every-failure.md)

「[报告问题]」原先只在缺陷时出现（服务端收敛后的 500、未命名的 5xx、意料之外的异常）。现在应用显示的每一处失败之后都有它：提示条、紧跟文字的行内报错、对话里的失败行，以及恢复面板。拒绝与原来一样，不带入口：服务端带命名错误码的 4xx 应答（输入校验不通过、密码错误或登录已过期、无权限、对象不存在、名称已存在或状态冲突、超出大小或次数上限），以及页面在发出请求之前自己做的检查。这扩大了 [2026-11-02-report-issue-entry](2026-11-02-report-issue-entry.zh.md) 定下的规则。

## 细节

- 2026-11-02 排除的三种情况现在算作失败、提供入口：服务端命名的 5xx（机器连不上、上游服务失败、超时）、不是服务端给出的应答（被代理或开发服务器的页面顶替），以及完全没有应答（网络断开、机器无应答）。错误码以 `_failed` 或 `_error` 结尾的 4xx 是服务端借 4xx 报告的失败（`plugin_install_failed`、`import_failed`），同样提供。带入口的提示条停留 10 秒。
- 由结果或记录说明、而不是应用捕获到的失败，现在也提供报告：模型测试、协议与视觉能力检测、消息渠道测试、MCP Server 测试、装好却没能加载或没能全部移除的插件、回答不成功的插件操作、更新的各个步骤、机器任务、重连中机器的上一次失败、配置同步、源码检出的镜像构建、失败的压缩。
- 报告的信息尽量全，隐私信息打码。每份报告的文字都经过同一道打码：密钥、Token 与一切像密钥的字符串、电子邮件地址、环回以外的 IP 地址，以及家目录路径里的账户名。涉及用户自己机器的原话——ssh 的输出、机器的任务日志与配置同步详情、MCP Server 自己的报错——随报告带上，同时打码主机名、IPv6 地址与 `user@host`，并去掉该机器的别名、主机名、账户与密钥文件。文件面板、文件夹选择器、目录浏览器与终端把所操作的目录替换为 `<workspace>`。
- 原先用自己的措辞说出捕获到的错误、却不带入口的提示条，现在都带上：对话里的操作、内置浏览器、消息渠道的扫码与测试、更新、Vault 与 MCP 列表、批量更新、已归档对话、Chrome 配对、终端与文件面板。
- 文字之后带上入口的行内报错：机器页及其对话框（失败任务的步骤行、上一次重连失败、配置同步一行、镜像构建、添加机器与 SSH 主机对话框）、文件面板的列表、搜索、页面源码与版本读取、文件夹选择器、目录浏览器（也包括插件的文件树与 Benchmark 用例）、应用中心与应用页面、工作台的重新加载、恢复、移除与历史、Trace 面板与 Trace 文件，以及成本中心与其错误表格。
- 对话里：失败的压缩在原因之后、连接失败的 MCP Server 行在报错之后、没能取回的折叠内容在「[重试]」之后，都提供入口。
- 页面主体或应用根部崩溃时由恢复面板接管，面板现在在错误之后提供「[报告问题]」，报告含错误与调用栈，并在面板自己的对话框里显示。自 2026-11-02 起恢复面板在这里取代了崩溃提示，却一直没有这个入口。
- 报告对话框的说明不再断言是缺陷：「这可能是 PenguinHarness 的缺陷，也可能来自网络、模型服务或所连的机器。」
- UI 包的报告工具：判定规则改为 `isReportable`（原 `isSeriousError`）；`Failure`、`reportFor` 与 `toldReport` 生成失败的报告；`FailureText` 把文字与其后的入口放进已经显示错误的那一行；`maskPrivate` 是那一道打码，报告的 `mask` 再加上主机名打码与已知的隐私值。`ActivityGroup` 在不可展开的标题行上接受 `actions`。`LoadFailed` 与 `EmptyState` 的说明、文件面板与添加机器对话框的错误，以及 `Input` 的错误都可以是节点。
- 组件库的「报告问题」看板并排展示失败与拒绝的提示条，以及行内报错：危险色的一行、提示框、字段错误与输入有误的提示并列，以及 ssh 原话已打码的告知型失败。
