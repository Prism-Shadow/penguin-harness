# The Trace panel gets a sticky round navigator, a Session section and readings on demand; a command's exit status is no longer a tool failure

- **Date:** 2026-10-23
- **Type:** feature
- **Scope:** `web`, `ui`, `core`, `server`, `docs`
- **PR:** [#1305](https://github.com/Prism-Shadow/penguin-harness/pull/1305)

[中文版](2026-10-23-trace-view-2.zh.md)

The Trace panel was rebuilt around one sticky toolbar: the round navigator opens from a button that names the round in view, the file's Session record is listed field by field at the top, rounds are ruled rows whose context ring opens the exact token figures, each event row wears one neutral pill, and the thinking level reads as text. A command that ran and exited non-zero, or was killed by a signal, now ends as an ordinary completed tool call everywhere it is shown.

## Trace panel

- One sticky toolbar replaced the file pills and the date row: the file is a picker when the Session has several files and a label (number, date, size) when it has one, then the rounds button, then a flat export icon. It stays at the top of the panel at any scroll position.
- The rounds button names the round in view and follows the panel's scroll; it shows from two rounds up. It opens the round navigator as a dropdown no wider than the panel: the title, the round count and the number box, then every round (number, compaction badge, first prompt line, the thinking-level change as muted text, four readings). The round in view is current and takes focus; picking a round closes the list, draws and opens the round and lands its head under the toolbar; ArrowUp and ArrowDown walk the rows, Home and End jump to the ends, Escape closes and returns focus to the button. The per-round "back to the navigator" control was removed.
- A **Session** section lists every field of the file's `session_meta`: `provider / model_id` with the context window, source, the Session id with a copy button, the Workspace and Agent State paths on one line each, the thinking level where an old record carries one, and the system prompt behind a toggle that names its length. It is read from the file's first record.
- The global summary and the rounds are ruled sections instead of cards, and a round is a ruled row: number, compaction badge, tool calls, hit rate, cost, duration, then the context ring.
- The ring is a button. Hovering it gives the usage percentage; clicking it opens the round's readings: this round's input, cache hits with the hit rate, output and output TPS, then the context used against the window and its three segments. A compaction round has no snapshot and shows a tokens glyph that opens the first four. The input, cache-hit, output and TPS figures no longer appear on a round's row or its first line.
- The timeline's explanation moved behind a "?" beside its title.
- Each event row wears one neutral pill naming the record's kind, with the role for `text` and `inline_data` (`text (user)`, `text (assistant)`); the role left the text's summary. An opened row shows its stop badge only when the reason is not `completed`.
- The thinking level is text, not a pill: a `request_begin` row reads `thinking_level=medium → high` where the level switched and `thinking_level=medium` where the file first states it.
- A failed tool's bar on the timeline is ringed with the danger tone token instead of a fixed red.
- `TokenDonut` gained `hint={false}`, for a ring inside a control that names it: no tooltip and no accessible name of its own.

## A command's exit status

- `exec_command` and `input_command` end a command that ran as `completed` whatever its exit status. A non-zero exit and a signal still close the output with `[exit code: N]` or `[terminated by signal X]`. `fatal` remains for the tool's own failures (unknown tool, bad arguments, a throw, a spawn error, a timeout) and `aborted` for a denial or an interruption.
- The chat's tool card, the Trace row and timeline, and the CLI show such a call as an ordinary completed one, with no red mark and no `fatal` badge. Records written before this change keep `fatal` and render as recorded.
- The cost center's error table no longer records a command killed by a signal; a spawn error and a timeout are still recorded. The rule that kept an ordinary non-zero exit out of the table was removed.
- A background command's completion report keeps calling a non-zero exit `failed`.
- The OmniMessage docs page states that a command's exit status is a completed result.
