# 模型、Project、消息绑定、公司模式与其余弹窗接入设置项提交方式

- **Date:** 2026-10-10
- **Type:** feature
- **Scope:** `web`
- **PR:** [#1031](https://github.com/Prism-Shadow/penguin-harness/pull/1031)

[English](2026-10-10-settings-interaction-rest.md)

[系统设置弹窗](2026-10-10-settings-interaction.zh.md)的设置项提交方式推广到 Web App 的其余部分：模型配置页及其弹窗、Project 弹窗、消息绑定、公司模式、ssh 主机表单、手动新建 Benchmark 表单、对话的快捷指令与内置浏览器的主页。每张表单的「保存」（或「创建」「添加」「招募」）只在有改动且没有错误时可点，格式不对的值在输入时即在字段下方指出；带未保存修改离开表单——Esc、×、点击弹窗外、「取消」、切换标签页或文档、站内路由——都先问「放弃未保存的修改？」。记录类弹窗自己的写入未返回前，任何方式都关不掉它。

## 模型

- **模型配置弹窗：** 底部按钮由「确认」改为「保存」（已有模型）/「添加」（新模型）。表格写入返回前弹窗保持打开，写入成功才关闭；写入被拒时弹窗连同草稿留在原处，列表保持原样——此前列表会把被拒的修改显示得像已保存。
- **详细配置里的错误：** 有字段出错时「保存」禁用，出错字段若在折叠的「详细配置」里，该折叠区自动展开，让禁用的原因可见。
- **促销：** 对有促销的模型保存价格或标识的修改会结束促销，因此先问。每次保存前那张「保存模型配置」确认已去掉。设为默认模型、设为视觉代理模型会一并写入草稿，因此也等草稿合法。
- **分组设置与新增分组：** 无改动、base URL 或分组名不可用时按钮禁用，并在字段下说明原因。分组设置不再弹「当前没有需要保存的修改」。

## Project

- 设置弹窗切换标签页或关闭时，若标签页有未保存修改先问：显示名、新对话默认值、规则列表，以及规则编辑器里输入到一半的规则。
- 命令策略的总开关一拨即写入，提交的是已存规则加上改动后的开关；旁边对规则的修改留在列表里，等列表的「保存」。
- 新建弹窗等到 id 合规才可「创建」，不合规时在输入时即指出。

## 消息绑定

- 对话的消息绑定面板在停靠栏标签 × 将丢弃未保存的凭证时先问，站内路由同样先问。会话行上的绑定对话框改用全站统一的确认卡，不再用自己的卡片。两处各用各的范围，一处的修改不会让另一处发问。
- 「保存」等到有可提交的修改；token 或域名格式不对时在输入时即指出。

## 公司模式

- **组织设置、招募、预算、汇报线、换工位、新建频道、重命名与目的、新建文档、新建工单、日程、工单各分区与标记阻塞**都接入离开确认，按钮在可提交前禁用。暂停或恢复组织仍即时写入，旁边正在输入的字段保留修改。
- **去掉了普通保存前的确认：** 招募、改预算、汇报线或思考等级、保存日程、保存工单分区都直接写入。移动工单、删除与换工位保留确认。汇报线的说明补上「其下属随之一起移动」。
- **财务页的预算就地编辑**不再在离开输入框时保存：回车或对勾保存，Esc 或叉号取消，输入框有改动时离开页面先问。
- **手册编辑器**的「保存」等到有修改才可点；「取消」、改选文档与「新建文档」改用全站统一的确认卡，站内路由、切换组织与刷新同样先问。

## 其余

- **ssh 主机、手动新建 Benchmark 与内置浏览器主页**在可写入前按钮禁用，关闭时若有输入先问。添加用例后又删掉的 Benchmark 视为未改动。
- **对话的快捷指令编辑**等写入返回：保存被拒时弹窗连同输入留在原处，此前会关闭并丢弃输入。
- **多字段表单里回车不再提交：** ssh 主机弹窗、新建频道的 id、新建工单的标题与快捷指令的标题都等按钮。单字段表单保留回车提交：频道名称、新建文档、Project 显示名。
