# The Web App boots a module tree, and every route is a page a module contributes

- **Date:** 2026-10-03
- **Type:** refactor
- **Scope:** `web`, `ui-gallery`

[中文版](2026-10-03-web-module-tree-pages.zh.md)

The Web App now boots a kernel module tree before its first render, with the same `@Module` / `@Provide` / `@Bind` and slots as the server. `src/web-root.ts` is the composition root: `WebRoot` lists the modules, and `bootWeb()` boots them and returns WebApp's root component, which `main.tsx` mounts once the install-scope reconcile has also finished. The UI gallery's framed app goes through the same `bootWeb()`.

The router's pages come from one slot. `web-app/module.ts` declares the `WebApp` interface and its `WebAppSlots`; `WebAppModule` provides it, and its `pages` slot carries each page's key, path, frame (`shell` or `bare`), nav placement, admin and released flags, and order, with the page component as the code half. Each feature that owns a route has a `module.ts` contributing to `WebAppModule.pages` and binding its components: chat (the surface-aware chat route), agents, models, plugins, machines, one machine's ports, usage, benchmark and the dashboard inside the WebApp; terminal and the two workflow app paths outside it; company as one `/org/*` page whose nested routes live in its own `OrgRoutes`. `src/module.json` and the router's `BUILTIN_PAGES` registry are gone, and `web-app/router.tsx` imports no feature.

The kernel brings arktype into the browser bundle: the production entry chunk grows by about 184 kB (about 55.5 kB gzipped, about 47 kB of it arktype), a cost accepted for running one kernel on both sides. Booting takes 2–3 ms and makes no request.

## Details

- `src/router.tsx` moved to `web-app/router.tsx`, and `lib/pages.ts` to `web-app/page-table.ts`.
- The two readers of `GET /api/contributions` (`state/contributions.tsx` and company mode's `use-org-pages.ts`) take the app's own page keys from the booted table: `contributedPages` (was `mergePages`) returns the server pages that mount beside it. The WebApp draws an iframe page itself (`web-app/contributed-page.tsx`); company mode's `OrgRoutes` mounts the company-mode pages plugins contribute under the organization layout, drawing the proposals page with its own component. A builtin-named contributed page outside company mode is no longer mounted.
- The runtime-languages hook moved to `lib/use-runtime-languages.ts`, and the router reads the home path from the company state (`useCompany().homePath`).
- `lib/module-deps.tsx` adds `createDeps()`: a module binds its dependencies into its root component, and the components under it read them with `useDeps()`. The WebApp binds the page table this way; the router, the sidebar and the collapsed rail read it through `useWebAppPages()`.
- The sidebar's nav decisions (`lib/nav-group-collapse.ts`) take the main-nav pages as an argument instead of reading the manifest at load. Nav order and the admin and released rules are unchanged.
- `ifaces.json` is generated by `pnpm gen:ifaces` (the web package's `dev`, `build`, `typecheck` and `test` run it first, and so does the root `gen:ifaces`) and is not committed.
- The web and gallery Vite configs set `esbuild.target` to `es2022`, so the dev server lowers the decorators.
- The boundary test allows `web-root.ts` to import `module.ts` files and nothing else to; the baseline lines for the router's feature imports are gone (company mode's routes now import the proposals page).
- Nothing users see changed.

CI regression coverage follows the current shared highlighter paths and keeps the terminal helper tests inside the terminal module, discovered by the flat Vitest configuration. The dictionaries retain their existing bilingual shape; fragment extraction is not a prerequisite for booting a kernel module. The layout reaches both browser operations through the existing browser entry, reducing its two browser edges to one without adding a baseline exception. The gallery answers the contributions endpoint with empty slots when no server plugins exist.
