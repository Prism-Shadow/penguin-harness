# 命令约束，后端以扩展形式提供

- **Date:** 2026-08-22
- **Type:** feature
- **Scope:** `core`, `server`, `docs`
- **PR:** [#354](https://github.com/Prism-Shadow/penguin-harness/pull/354)

[English](2026-08-22-sandbox.md)

Agent 执行的 shell 命令现在可以被约束。harness 有了自己的沙盒接口——形制取自 DeepSeek Harness 的设计（改写 argv、如实报告约束完整度、fail-closed），但归属在这里，因此它可以命名三个维度：`fs-write`、`network` 与 `mask-paths`。没有任何后端属于 harness 本体：每个后端都是部署自行安装、并在 `extensions.json` 中点名的扩展包，这也是它建立在[扩展机制](2026-08-22-extension-mechanism.zh.md)之上的原因。

## 细节

- `core` 增加了 spawn 缝：`confineSpawn` 沿既有的 `proxyEnv` 线路穿过，在 `ManagedSession` 真正 spawn 前一刻生效。它收到确切的 argv、`cwd` 与 `workspaceDir`，返回应当改为执行的 argv。纯机制——它从不解释 argv。
- 后端声明自己实现哪些维度，不声明即表示仅文件系统。服务按需求把每条策略路由到覆盖它的后端，因此未实现的维度不可能被悄悄丢弃。若无任何后端覆盖某项需求，则 fail-closed，并说明每个已挂载的后端各自覆盖什么。
- `confine` 必须返回具约束力的 argv，否则抛错。抛错会中止 spawn 并表现为该命令的 spawn 错误，因此不会因为后端失败而让命令在无约束状态下运行。
- 随之发布四个后端包：`extension-sandbox-dsh`（可移植的 DSH 适配器，三平台上覆盖文件效果）、`extension-sandbox-bwrap`（Linux）、`extension-sandbox-seatbelt`（macOS）与 `extension-sandbox-mxc`（Windows，经由 Microsoft MXC 的 `processcontainer`）。三个原生后端实现全部三个维度。
- 约束设置随寄存的平台上下文一同存活，因此一次热推送无法悄悄解除某个部署的约束；设置在保持默认时不写入，因此默认部署的文档对不认识沙盒的 bundle 仍然可接受。
- 由于平台 bundle 内不再含任何后端，它也不再内联任何贴近原生的模块，`deploy.mjs` 中运行时解析原生模块的 shim 已被删除。
- 默认部署没有点名任何扩展，因此不约束任何命令。
