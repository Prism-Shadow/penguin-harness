# 命令沙箱，后端以插件形式提供

- **Date:** 2026-08-22
- **Type:** feature
- **Scope:** `core`, `server`, `plugins`, `docs`
- **PR:** [#354](https://github.com/Prism-Shadow/penguin-harness/pull/354)
- **Breaking:** yes — `extensions.json` 不再被读取，两个 SDK 子路径改为 `/plugin`；插件契约改为封闭，`context.terminals` 现在需要类型转换

[English](2026-08-22-sandbox.md)

Agent 运行的 Shell 命令现在可以被约束。harness 拥有了自己的沙箱接口——改写 argv、如实报告强制程度、失败即关闭——并命名三个维度：`fs-write`、`network` 与 `mask-paths`。没有任何后端属于 harness：每个后端都是部署自行安装、并写入 `plugins.json` 的插件包，这也是它建立在插件机制之上的原因——该机制以[扩展机制](../0.2.8/2026-08-22-extension-mechanism.zh.md)之名随 0.2.8 发布，并在本次更名。默认部署不列出任何插件，因此不约束任何命令。

## 细节

- **接缝在 core。** `confineSpawn` 沿既有的 `proxyEnv` 线穿过，在 `ManagedSession` 中于 spawn 前一刻应用：它收到确切的 argv、`cwd` 与 `workspaceDir`，返回应当改为 spawn 的 argv。只是机制——它从不解释 argv。
- **路由不会悄悄丢掉某个维度。** 后端声明自己实现哪些维度（不声明即表示仅文件系统），服务把每条策略路由到覆盖其所需的那个后端。若某项要求无人覆盖，则失败即关闭，并列出每个已挂载后端各自覆盖什么。`confine` 必须返回具强制力的 argv 或抛出；抛出会中止 spawn 并呈现为该命令的 spawn 错误，因此绝不会因为后端失败而让命令在无约束状态下运行。
- **四个后端以独立包形式发布：** `plugin-sandbox-dsh`（可移植的 DSH 适配器，在三个平台上覆盖文件效果），以及 `plugin-sandbox-bwrap`（Linux）、`-seatbelt`（macOS）与 `-mxc`（Windows，经由 Microsoft MXC 的 `processcontainer`）——三个原生后端实现全部三个维度。每个包都声明 `Apache-2.0`，并随包发布自己的 `README.md`，写明它实际强制了什么，细到 bwrap 的挂载顺序与 Seatbelt 的规则优先级：部署正是据此挑选后端。由于 platform bundle 内不含任何后端，它不再内联任何贴近原生的模块，`deploy.mjs` 中运行时解析原生模块的兜底代码也已删除。沙箱设置随 park 的 platform context 一同保存，因此一次热推送不会悄悄解除某个部署的约束。
- **插件契约改为封闭，并纳入沙箱词汇。** `PenguinContext` 与 `PenguinInterface` 写明每一个成员，不再被 `declare module` 重新打开：此前，一个对着契约做检查的插件，实际编译时面对的是只有某一个宿主才提供的成员。`SandboxPolicy`、`SandboxProvider`、`ConfinedArgv` 以及模式与维度联合类型现在位于 `@prismshadow/penguin-core/plugin`，因为后端正是针对这些名字编写、除此之外别无所需——而读取它们的辅助函数仍留在 server 包，这让两个插件子路径继续只输出类型。因此后端只需引用 core：四个后端都已从依赖中移除 `@prismshadow/penguin-server`，现在也无法再解析到它；server 的插件子路径则收窄为它真正拥有的那一个成员 `HarnessContext`。
- **这套机制统一称为「插件」。** 0.2.8 中以「扩展机制」发布的那一套，从此叫插件机制，读者在概念出现的任何地方遇到的都是同一个称呼。配置文件是 `<root>/plugins.json`，键为 `plugins`；SDK 子路径是 `@prismshadow/penguin-core/plugin` 与 `@prismshadow/penguin-server/plugin`；契约中的名字是 `Plugin` / `PluginContext` / `PluginEvents`，宿主侧是 `PluginHost`；四个后端为 `plugins/` 下的 `@prismshadow/penguin-plugin-sandbox-*`。`PenguinContext`、`PenguinInterface`、`HarnessContext` 以及整套沙箱词汇均未改名。这个词在别处仍另有其义，那些地方一概未动：文件扩展名、remark/micromark 语法扩展、输入框的「+」扩展菜单，以及 SDK 自己的「扩展点」。它也不是 cordis 的 `plugin`——DSH 适配器正是通过 cordis 的 `Context.plugin` 挂载 DSH 的链路，两套词汇除了这个词之外毫无关系。

## 兼容性

磁盘上已有的 `extensions.json` **不会被读取**，也不会被迁移。用旧名字配置了插件的部署仍能运行，但其中的插件一个也不会加载，对应能力静默失效——对这几个沙箱后端而言，这意味着命令将在无约束状态下 spawn。请把该文件改名为 `plugins.json`，并把其中的 `"extensions"` 键改为 `"plugins"`；里面的 specifier 只在点名本仓库的沙箱后端时需要改动，那几个包现在叫 `@prismshadow/penguin-plugin-sandbox-*`。针对 `@prismshadow/penguin-core/extension` 或 `@prismshadow/penguin-server/extension` 编译的包将无法解析：把 import 指向 `/plugin`，并改用新的三个类型名即可。

`terminals` 是 harness 的类，不可能进入契约。它被命名在继承契约的 `HarnessContext` 上，因此发出的值仍满足契约、接缝没有变化——但读取 `context.terminals` 的插件现在需写 `ctx as HarnessContext`，在使用处表明它依赖这个宿主。

线上格式、数据库以及其他任何磁盘文档均无变化。
