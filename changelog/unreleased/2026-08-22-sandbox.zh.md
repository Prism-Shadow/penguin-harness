# 命令沙箱，后端以扩展形式提供

- **Date:** 2026-08-22
- **Type:** feature
- **Scope:** `core`, `server`, `docs`
- **PR:** [#354](https://github.com/Prism-Shadow/penguin-harness/pull/354)
- **Breaking:** yes — 扩展契约改为封闭，`context.terminals` 现在需要类型转换

[English](2026-08-22-sandbox.md)

Agent 运行的 Shell 命令现在可以被约束。harness 拥有了自己的沙箱接口——改写 argv、如实报告强制程度、失败即关闭——并命名三个维度：`fs-write`、`network` 与 `mask-paths`。没有任何后端属于 harness：每个后端都是部署自行安装、并写入 `extensions.json` 的扩展包，这也是它建立在[扩展机制](2026-08-22-extension-mechanism.md)之上的原因。默认部署不列出任何扩展，因此不约束任何命令。

## 详情

- **接缝在 core。** `confineSpawn` 沿既有的 `proxyEnv` 线穿过，在 `ManagedSession` 中于 spawn 前一刻应用：它收到确切的 argv、`cwd` 与 `workspaceDir`，返回应当改为 spawn 的 argv。只是机制——它从不解释 argv。
- **路由不会悄悄丢掉某个维度。** 后端声明自己实现哪些维度（不声明即表示仅文件系统），服务把每条策略路由到覆盖其所需的那个后端。若某项要求无人覆盖，则失败即关闭，并列出每个已挂载后端各自覆盖什么。`confine` 必须返回具强制力的 argv 或抛出；抛出会中止 spawn 并呈现为该命令的 spawn 错误，因此绝不会因为后端失败而让命令在无约束状态下运行。
- **四个后端以独立包形式发布：** `extension-sandbox-dsh`（可移植的 DSH 适配器，在三个平台上覆盖文件效果），以及 `extension-sandbox-bwrap`（Linux）、`-seatbelt`（macOS）与 `-mxc`（Windows，经由 Microsoft MXC 的 `processcontainer`）——三个原生后端实现全部三个维度。由于 platform bundle 内不含任何后端，它不再内联任何贴近原生的模块，`deploy.mjs` 中运行时解析原生模块的兜底代码也已删除。沙箱设置随 park 的 platform context 一同保存，因此一次热推送不会悄悄解除某个部署的约束。
- **扩展契约改为封闭，并纳入沙箱词汇。** `PenguinContext` 与 `PenguinInterface` 写明每一个成员，不再被 `declare module` 重新打开：此前，一个对着契约做检查的扩展，实际编译 against 的是只有某一个宿主才提供的成员。`SandboxPolicy`、`SandboxProvider`、`ConfinedArgv` 以及模式与维度联合类型现在位于 `@prismshadow/penguin-core/extension`，因为后端正是针对这些名字编写、除此之外别无所需——而读取它们的辅助函数仍留在 server 包，这让两个扩展子路径继续只输出类型。

## 兼容性

`terminals` 是 harness 的类，不可能进入契约。它被命名在继承契约的 `HarnessContext` 上，因此发出的值仍满足契约、接缝没有变化——但读取 `context.terminals` 的扩展现在需写 `ctx as HarnessContext`，在使用处表明它依赖这个宿主。线上格式与磁盘格式均无变化。
