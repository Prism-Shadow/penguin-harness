# Web App: session details card with live process control, draft conversations, sequenced panel swaps, a persistent initial-password notice, and chat polish

## Header statistics become the details card, with the session's processes inside

The chat toolbar's Token / cost / elapsed statistics move to the far right and are now themselves the details entry: on wide viewports clicking the numbers opens the details card (no separate info icon), and narrow viewports collapse the whole trigger to the single info icon. While the conversation has live background processes, a green running-services count rides to the right of the elapsed time.

The details card shows Model, Workspace, creation time and statistics as sections, the statistics as a bulleted list with one figure per line — the tokens bullet reads `总 Token <total>（缓存命中率 <pct>）`, the hit rate being cached reads over all recorded input. Below them sits an interactive **session processes** list: background processes the conversation started (an `exec_command` outliving its yield window — a dev server on localhost:3000, say) each show their command, start time and pid, and running rows carry a Stop button that kills the whole process group and drops the row. The former "View trace" button becomes a **trace file** section in the same label-plus-value anatomy, the actual `.jsonl` path being an underlined link that deep-links into trace observability.

Under the hood, command sessions now expose enumeration (`listBackgroundCommands` on the environment and core Session; process id, pid, command, cwd, start time, running state) and kill-by-id, served over two new endpoints (`GET /api/sessions/:id/processes`, `POST /api/sessions/:id/processes/:processId/kill` — answered from the active runtime only, never resurrecting one). Two real lifecycle gaps close with it: deleting a Session, Agent or Project now disposes the runtime once its in-flight drive settles, so background processes die with the conversation instead of running forever; and the active table's idle eviction skips entries that still have running background processes — evicting one would strand the OS process with no remaining stop control.

## Typed-but-unsent text becomes a draft conversation

Clicking any "New chat" entry point — the sidebar button, group-header "+", the collapsed rail, the agents page, or the skill library's quick invoke (which previously overwrote typed text silently) — while the new-chat composer holds text now parks that draft as a **draft conversation**: a row in a Drafts group at the top of the session list (per user × Project in localStorage, newest first, capped at 50). Opening a row (`/chat/draft-<id>`) resumes the full draft — text, Agent, Workspace, model, approval mode and selected skills — for editing and sending at any time; sending creates the real Session and removes the row, and rows can be deleted behind a confirmation. The active draft slot keeps only the model carry-over ("switch becomes default", as after a send), so a new chat always starts on an empty composer and typed content never lingers invisibly.

## The initial admin password stays visible until it is changed

The seeded admin password used to be printed exactly once, at first start; if that line scrolled away unread, the credential was gone. It is now kept in the data root (`initial-admin-password`, owner-only permissions) for as long as it remains the initial one, and every server start re-prints it framed in ASCII with a change-it reminder — `penguin web` attaching to an already-running instance prints the same notice. Any password update for admin (self change, desktop set, or an admin reset, whose chosen value is never persisted) deletes the file; roots seeded before this change have no file and stay silent. Docs updated accordingly.

## Panel swaps retract before they expand

Switching between the Agents panel and the Workspace panel used to run both width transitions simultaneously: the total width stayed constant, so the closing panel's content never moved — it was simply wiped over by the incoming panel, which read as "no retract animation". Docked swaps are now sequenced: the open panel retracts fully (the chat column takes the space back), then the other slides in. Mobile Sheets keep the instant switch — they overlay rather than share width.

## Conversations open pinned to the bottom under the notice banner

The message stream re-pins itself to the bottom whenever its scroll container or content resizes outside a stream commit — the initial-password banner mounting after `/api/me` resolves, or a late-loading image, previously left a freshly opened conversation sitting a banner's height above the bottom with no scroll event to correct it.

## Smaller refinements

The benchmark case-detail dialog opens with both material groups (task materials and rubric) expanded, the readme auto-preview staying with the task materials so the two never race for the preview pane. And the session composer's read-only model chip is now clickable: it explains that `/model` switches models, continuing the conversation in a new session.
