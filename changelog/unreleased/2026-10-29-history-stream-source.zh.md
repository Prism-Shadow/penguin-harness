# 套接字上的流可控速，机器以 Trace 行提供历史

- **Date:** 2026-10-29
- **Type:** feature
- **Scope:** `server`, `core`, `web`, `docs`
- **PR:** [#1391](https://github.com/Prism-Shadow/penguin-harness/pull/1391)

[English](2026-10-29-history-stream-source.md)

API 套接字上的流式调用可以用 `x-flow: credit` 请求确认流控：服务端在流的起始帧回显该头，客户端看到回显后才回报已处理的事件数据量，因此早于确认流控的服务端不会收到这类帧。服务端在途的未确认数据不超过实测送达速率的 2 秒量（介于 32 KiB 与 1 MiB 之间），一次大传输不再在套接字的其他调用之前堆积几分钟的数据。流在等待期间可以发出具名 `ping` 作为节拍，且不占窗口；一次性调用在应答读取期间被释放后，不再收到多余的 `200` 应答帧。

服务端之间的套接字，以及通往另一台电脑上浏览器的套接字，以 permessage-deflate 压缩各帧，且每帧单独压缩（不保留上下文），任何一帧的大小都不取决于其他帧的内容；同一台电脑上的浏览器（含桌面端）不压缩。

每个服务端都为自己的 Session 提供 `GET /api/sessions/:sessionId/history-lines`。流在读取任何内容之前就开始并发出节拍；先给出历史窗口的信封与其记录所在 Trace 字节的布局，然后只发送调用方尚未持有的 Trace 行——只发整行、最新的在前，包括窗口在内的每个事件都不超过 32 KiB 文本。调用方只持有一部分的行，只有窗口需要它时才在窗口就绪之前补齐余下部分，其余的都在就绪之后，重新打开的窗口因此不必等一张被切断的大截图传完。调用方持有的每一段都按文件身份、大小、行边界以及首尾字节的散列校验，校验不过的文件从头重发；文件身份以 inode 为准，容器重启后变化的设备号、平台没有保留的创建时间都不再导致重发。运行中 Task 暂存的输入只在窗口尚未包含时才提供，其中的图片因此不会显示两次。inode 以十进制字符串传递，超过 2^53 的 NTFS 文件 id 也保持精确。

每个分窗的历史页都给出所含的 Task 数（`page.units`），在切窗处按同一规则计出；逐页加载到 N 个 Task 的客户端由此与 `tailLimit`、`limit` 的计数一致。

`GET /api/sessions/:sessionId/trace-body?ref=` 取回一个被折叠的值的全文，且只应答指向该 Session 自身或其派生的子 Agent 会话中某一行的 ref；其他 ref（包括指向其他 Project 文件的）一律返回 404。

core 的 `interfaces` 子路径新增历史窗口使用的折叠规则：超过 16 KiB 的工具输出、子 Agent 会话的内联图片、工具调用参数中的长字符串与思考文本只保留开头与结尾的一小段，并附一条 `elided` 记录指明该值，展开时据此取回全文。
