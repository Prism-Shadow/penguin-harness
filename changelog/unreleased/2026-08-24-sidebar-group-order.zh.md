# 拖动侧边栏分组，排成自己的顺序

- **Date:** 2026-08-24
- **Type:** feature
- **Scope:** `web`
- **PR:** [#440](https://github.com/Prism-Shadow/penguin-harness/pull/440)

[English](2026-08-24-sidebar-group-order.md)

对话侧边栏的分组——工作区文件夹与 Agent——可以像组内的对话行那样拖动排序。该顺序按 Project 和分组方式分别保存，刷新后仍然保持。

## 细节

- 拖动分组本身就是意图：分组没有额外的排序开关。未存储过顺序的 Project 与分组方式，渲染结果与此前的自动排序完全一致——工作区分组按其最新对话排列、合并后的临时工作区分组排在最后，Agent 按既有顺序排列。
- 合并后的临时工作区分组与其他分组一样可拖动。排在末尾只是默认位置；一旦被拖动过，就以用户选择的位置为准。
- 没有存储位置的分组排在列表**最前**，并在同样未定位的分组之间保持其自动顺序，因此首次使用的工作区或刚创建的 Agent 不会出现在长列表的末尾。
- 按时间分组被排除在外：它的分桶是最近一天／最近一月／更早，是一条固定的时间阶梯。`group-order.ts` 拒绝为该模式读写顺序，因此这一排除不依赖调用处的检查。
- 分组顺序与对话行顺序是两个数组，存储键命名空间也各自独立（`penguin.groupOrder.<projectId>.<mode>`），因此拖动分组不会扰动组内的行，拖动行也不会移动分组。
- 分组顺序与既有的分组置顶的组合方式，同行顺序与行置顶的组合方式一致：置顶的一簇仍在最前，落点始终留在自身所属的置顶分区内，因此拖动只会重排，不会置顶或取消置顶。
- 分组标题栏即拖动手柄，落点指示线画在整个分组上，因此「下方」指的是该分组及其对话之后。两者都不占用布局宽度，标题栏在手机宽度下仍保留其操作按钮。
- 一次落点提交的是该模式的完整分组列表，而不是显示上限展示的那十个分组；同时清理分组已不存在的存储键——但仅当该 Project 的所有 Agent 都已上报各自的按工作区计数时才清理，因此只是尚未加载的分组会保留其位置。
- 匹配不到分组的存储键会被忽略，存储值损坏时退回自动排序。
- 手动顺序只作用于对话侧边栏；Trace 页面的工作区目录树不受影响。
