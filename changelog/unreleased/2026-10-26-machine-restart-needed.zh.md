# 服务进程早于 API 套接字的机器，提示需要重启

- **Date:** 2026-10-26
- **Type:** fix
- **Scope:** `server`, `web`, `ui`, `docs`

[English](2026-10-26-machine-restart-needed.md)

远程机器的服务进程若是 0.2.17 之前启动的，它上面的对话能加载历史，却不会实时更新，回复要刷新页面才出现。这样的服务端应答 HTTP，却不应答 API 套接字的握手，而流从不经 HTTP 转发。现在这类机器在机器管理页和对话的输入框上方都会显示需要重启，直到一次握手完成。

## 细节

- 拨机器的 API 套接字握手超时后，本服务端会经同一端口再问一次 HTTP。机器的服务端有应答时，它的套接字状态记为 `unanswered` 而不是 `failed`，因此被拒的每条流都以 `502 machine_socket_unavailable` 作答，错误信息写明办法：在机器管理页重启那台机器。本服务端不会自动重启它。
- 这一状态只存内存，再次拨号期间保持不变，一次握手完成后（比如重启之后）清除。进入和离开这一状态都会推送 `machines_changed`，打开着的页面无需刷新就能看到。
- 机器管理页把这台机器显示为「需要重启」，悬停胶囊可看原因，即使记录的版本与本服务端相同。详情弹窗里「重启服务」成为主按钮（有「更新」时仍以「更新」为主），API 套接字一行显示「无应答」。
- 这类机器上的对话会在输入框上方显示一条提示，说明那台机器上的实时更新到不了这里以及原因，附「打开机器管理」按钮。流在后台照常重试，机器重启后自行打开。

## 运行中被更新的机器

本服务端在机器的服务端运行时交给它的更新，只替换平台，不动服务进程。本服务端启动时会把自己的构建交给每台构建不同的机器，所以本服务端升到 0.2.17 后，这样的机器显示为已是当前版本，不提供「更新」，却仍然没有 API 套接字。0.2.17 发布说明中「在机器管理页更新每台机器」的建议覆盖不到这种情况。这类机器现在会显示「需要重启」：在机器管理页重启它的服务，就会载入磁盘上已有的构建，无需重新安装。
