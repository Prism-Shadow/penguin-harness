# 打开历史会话更快

- **Date:** 2026-10-03
- **Type:** performance
- **Scope:** `server`, `web`

打开一段历史对话曾经要排在侧栏的会话列表扇出后面。

## 正文不再等侧栏

- 聊天页对路由里那个会话的直接查证，不再等待会话列表加载完。那份列表会对每个 Agent、每台连着的机器各拉一次首页，这堆活原来挡在读者要看的对话前面。
- 列表仍在加载时的查证失败，不再被当成"这个会话没了"：路由保持待定，列表落地后再查一次，第二次才失败才跳转。
- 同一个会话同时只有一个查证在飞。这个 effect 原来会随列表变动重跑（取消后重新发出），一次深链因此打过十来个一模一样的请求。

## 侧栏的列表扇出变成每个来源一次请求

- 新增 `POST /api/projects/:p/sessions/batch`，一次往返回答侧栏要的每一个 (Agent, 分页) 组合，而不是一个组合一次请求。工作区分组模式还会再掀起一波按分组按 Agent 的请求；现在两条路径都走它。
- 答案仍然按 Agent 分开：404 表示"这台服务器没有这个 Agent"（`reason: "absent"`），其它情况表示没答上来（`reason: "error"`），所以失败不会被读成"没有会话"。
