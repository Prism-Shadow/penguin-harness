# Web App：侧边栏被截断的标题会滚动显出完整文字

- **Date:** 2026-08-18
- **Type:** fix
- **Scope:** `web`
- **PR:** [#328](https://github.com/Prism-Shadow/penguin-harness/pull/328)
- **Issue:** [#309](https://github.com/Prism-Shadow/penguin-harness/issues/309)

[English](2026-08-18-sidebar-title-scroll-reveal.md)

聊天侧边栏里的对话标题会被裁成一行，而越过这层裁剪的唯一办法是一个很容易被忽略的原生 tooltip——前缀相同的一批对话因此彼此难以分辨。现在把指针悬停到某一行、或用键盘把焦点移到它上面，被裁掉的标题尾部就会滚动进视野，session 行与停放的草稿行一视同仁。

## 滚动揭示

- 标题会先静止 0.3s，什么都不动，随后以恒定的阅读速度（60 px/s，因此长短标题掠过的节奏一致）向左滑动实测的溢出宽度，时长夹在 0.35s 到 4s 之间。滑到尾端后只要悬停或焦点还在就一直停住，二者一旦结束，一帧之内弹回原位。
- 这 0.3s 静止期内没有任何变化，省略号也在其内，所以指针只是路过侧边栏时，每一行都保持原样。这是因为所有会改变渲染的声明都写在 `title-scroll-reveal` 关键帧里、且填充模式只有 `forwards`——其中就包括那条让文本可被 transform 的 `inline-block`，而它同时也是让省略号消失的原因，于是「…」会一直留到滑动开始的那一帧。
- `:focus-visible` 把键盘触发限定为真正的键盘焦点，而不是落进该行的任意焦点；它又写在宽容匹配的 `:is()` 内部，因此不支持 `:has()` 的引擎仍然保有悬停触发。
- 动画是纯 CSS 的，由 `Truncated` 实测并写出的两个自定义属性（`--title-scroll-shift`、`--title-scroll-ms`）驱动：没有定时器，也不需要为每一行订阅媒体查询。transform 被裁在该行原有的盒子内，因此不产生布局位移，该行的点击、拖拽排序与悬停操作按钮也都未受影响。
- 放得下的标题会被测出「放得下」，从而纹丝不动——不加类、不写变量、不挂 tooltip。这项测量会在尺寸变化时、以及标题或其样式变化时重新执行；1px 的亚像素容差则避免了舍入误差既生出多余的 tooltip、又带来 1px 的滚动。

## 减弱动效与辅助技术

- 在 `prefers-reduced-motion` 下，仓库全局的 `animation: none !important` 区块直接把这段揭示动效整个关掉，无需为它单写覆盖规则。此时标题的渲染与静止状态完全一致：朴素的省略号，外加被截断标题本就为指针悬停带上的 `title` tooltip。
- 无论视觉上是否被裁，完整标题始终留在 DOM 中，因此屏幕阅读器会把它整句读出。
- 触摸既没有悬停也没有键盘焦点，而移动端浏览器并不会在长按时给出 `title`；在那里，完整文字要通过打开该 Session 来看到。
