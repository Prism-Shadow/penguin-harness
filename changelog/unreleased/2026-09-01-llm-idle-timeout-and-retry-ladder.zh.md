# LLM 请求超时计的是沉默,不是长度

- **Date:** 2026-09-01
- **Type:** fix
- **Scope:** `core`, `web`, `docs`
- **PR:** [#PRNUM](https://github.com/Prism-Shadow/penguin-harness/pull/PRNUM)

[English](2026-09-01-llm-idle-timeout-and-retry-ladder.md)

`model.timeoutMs` 一直计的是等待上游**下一个**事件的时长:计时只在等待网关时进行,收到任一事件即归零,消费侧的时间一概不计。而文档把它写成"单次 Request 超时",这会被读成"一次回复最多能生成多久"。在边写边吐字的模型上,两种读法没有差别;在思考不外露的模型上,两者相去甚远——GPT-5 与 Gemini 在思考期间什么都不发,整段推理因此落进首个事件之前的那一个间隔里,120000 于是悄悄变成了"思考不得超过两分钟"。在那里被切断的请求不产生任何 usage,而重试会在同一个地方再沉默一次。

## 细节

- 措辞改为它本来的样子:上游事件之间的空闲预算,约束的是连接建立与首个事件的等待、以及流式过程中的事件间隔,不是整次请求的总时长。配置表、接口清单与 Agent 设置里的字段说明同步。
- 缺省值由 120000 提到 **300000**。这是一次内核变更(generation `2026-09-01`,runtime 标签页):运行时标签页仍是内置缺省的 Agent 会在内核更新时取到新值,用户改过的则保留自己的取值。
- 每次请求现在都索取思考摘要(`thinking_summary`)。没有 Provider 会因这个字段报错——网关在有对应能力的家族上映射它,在没有的家族上丢弃它——于是凡是能外露推理的模型都会把推理发到线上:读者看得见模型在想什么,空闲计时也在这段时间里不断归零。有两个家族对它的理解更具体:Claude 系会把思考流切为摘要,而部分 Gemini 型号接受 `include_thoughts` 却仍然不返回摘要。仍会沉默的那些,正是提高缺省值所覆盖的。

## 重试计的是连续失败,而不是失败

重连阶梯此前在同一轮里重试 5 次就放弃,中间发生过什么都不算数。而 `terminated: other side closed (UND_ERR_SOCKET)` 这类断开通常发生在响应中途,此时模型已经写出了一部分答案——那是一次已经连上、并且产出过内容的尝试,旧的计数却把它读成"端点不通"的又一个证据。

- **收到过内容**的尝试——任何内容都算,哪怕只是一段被切断的思考、或半个工具调用的参数——现在会把阶梯归零:下一次断开重新从 2s 那一级开始。`[turn_retried]` 会把此前已产出的内容一路带进每次重试,因此这样重试的一轮是在往前推进,而不是原地重复。
- 为归零兜底的是另一条绝对上限:**单轮总尝试 20 次**,只有"每次吐几个字就断"的端点才够得着它。
- `request_end` 上的 `attempt` 仍然计所有尝试、从不回退,Web 与 CLI 打印的"第 N 次"因此保持单调;宣告的 `retry_in_ms` 也仍与随后真正的等待一致,含归零之后的那一次。
- 压缩循环共用这份重试预算,但不适用归零规则:它的预算同时覆盖"已提交但不可用的响应"(空摘要,或调用了工具的响应),在那里"产出过内容"根本不是进展的证据。
