# Trace 页加载轨迹文件的全部分页

- **Date:** 2026-09-12
- **Type:** fix
- **Scope:** `web`

[English](2026-09-12-trace-view-all-events.md)

较长的轨迹文件里，靠后的轮次——包括位于文件末尾的压缩轮——时间线下的消息数为 0：分析覆盖整个文件，并按
索引区间把消息归入各轮，而事件只取了前 1000 条，于是区间起点落在该分页之后的轮次无消息可列。现在 Trace
页会翻完整个文件，已加载完成的文件中不会再有消息列表为空的轮次。

## 细节

- `features/traces/trace-events-loader.ts` 负责翻页：从 offset 0 起逐页请求，下一个 offset 取自上一页
  实际返回的条数，直到走到最新一页的 `total` 为止。`total` 每页重读，因此翻页期间被追加写入的文件会跟到
  新的末尾；返回空页即结束翻页，单次翻页的请求数有上限，翻页结束后返回最后一页的 `total`。
- 文件视图渐进渲染：每一页按自己的 offset 就位插入列表，长文件的开头在其余部分到达之前即可阅读。因此刷新
  （面板在每轮结束时都会重读文件）是就地更新列表，不会把列表退回只剩一页；翻页结束后按刚读到的长度裁掉
  多余的行。
- 切换文件、面板卸载或触发刷新都会取消进行中的翻页；某一页失败时，错误显示在已加载内容旁边，不清空已有
  内容。
- 消息列表底部的脚注由「仅展示前 N 条」改为加载提示（`已载入 5 / 12 条消息…`），全部消息到位后消失。
- `test/trace-events-loader.test.ts` 用假接口覆盖翻页行为：2500 条事件分三次请求、被服务端 limit 截短的
  分页、翻页途中变长的文件、分页在 `total` 之前就耗尽的截断文件、两页之间的取消、请求数上限，以及翻页
  结束时返回的长度。
