# AgentHub 0.4.12: an image read by a tool reaches the model behind a strict OpenAI-compatible gateway

- **Date:** 2026-09-11
- **Type:** fix
- **Scope:** `core`, `cli`, `docs`
- **PR:** [#692](https://github.com/Prism-Shadow/penguin-harness/pull/692)

[中文版](2026-09-11-agenthub-0.4.12.zh.md)

`@prismshadow/agenthub` moved from 0.4.11 to 0.4.12 (agenthub [#209](https://github.com/Prism-Shadow/agenthub/pull/209)). Reading an image with `read_file`, or calling an MCP tool that returns one, on a model reached over the `openai-chat` protocol, on a Kimi K3 row or on a `glm-5.3-flash` row no longer fails with `400 Failed to deserialize the JSON body into the target type: data did not match any variant of untagged enum ChatCompletionRequestToolMessageContent`: the client sends the tool's images in the user message that follows the turn's tool messages, the one placement the Chat Completions schema documents, instead of inside the `tool` message. A gateway that validates the schema rejected the whole request, which ended the turn with that error.

## Details

- The fix lives in AgentHub's `openai_chat`, `kimi_k3` and `glm5_3` clients, so every row pinned to `openai-chat` (the TokenDance, OpenRouter, Fireworks, SiliconFlow and Qwen groups, and custom OpenAI-protocol entries), the vLLM rows, whose `openai-chat-vllm-adapter` subclasses that client, the Moonshot direct rows and the `glm-5.3-flash` rows are covered alike. Every tool result now goes out as a plain string on those clients. The Responses-protocol clients were not affected.
- `pnpm-workspace.yaml`'s `minimumReleaseAgeExclude` entry names 0.4.12 in place of 0.4.11.
- The last `gpt5_6` spellings, in the fast-mode table on the models page and in a core test title, read `gpt6`, the name AgentHub 0.4.11 gave the client.
