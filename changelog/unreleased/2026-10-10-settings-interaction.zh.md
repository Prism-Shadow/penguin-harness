# 设置项统一提交方式：开关即拨即存，表单点保存，离开先问

- **Date:** 2026-10-10
- **Type:** feature
- **Scope:** `web`, `ui`, `skills`

[English](2026-10-10-settings-interaction.md)

Web App 的设置有了统一的交互模型，系统设置弹窗率先接入：开关一拨即生效；文字与表格只在点「保存」后生效；带未保存修改经任何途径离开，都先弹「放弃未保存的修改？」，按钮为「放弃修改」与「继续编辑」。其余设置页面见各自的条目。

## 共享的离开确认

- 共享 UI 包新增未保存登记表与 `useFormDraft`、`useUnsavedChanges`、`useGuardedClose`、`guardLeave`，以及 `UnsavedChangesHost`——所有离开都经它弹出同一张确认卡。只要有表单处于有修改状态，它还会挂上 `beforeunload`，刷新或关闭浏览器标签时由浏览器用自己的文字提问。
- Web App 的路由改为数据路由，导航因此可以被拦下：侧栏链接、应用内各处链接与重定向、`?tab=` 切换，以及浏览器的前进后退，在有修改时都会先问。
- 只有「保存将发出的值」与存储值不同时才算有修改：改回原值即恢复为无修改，开关永远不计入有修改。

## 系统设置弹窗

- **离开：** 在左侧导航切换子页，或以 Esc、×、点击弹窗外关闭弹窗，子页有未保存修改时先问。切换界面语言会重建所有页面，同样先问。
- **代理选项：** 两个开关一拨即写入，每次只写该开关，写入失败时回到原值并以浮层说明原因。代理地址用自己的「保存」单独保存，保存后显示服务端存储的形式。地址有未保存修改时，两个开关禁用并提示「先保存代理地址」。
- **上传限制：** 只有限制值有改动且两项都是整数时「保存」才可点；不是整数的输入框在输入时即标出。
- **插件：** 卡片的总开关与各开关字段一拨即写入，各自写入所属条目；卡片上的其余输入等该卡片的「保存」。卡片从服务器重新读取时保留正在输入的内容；有卡片未保存时切换机器先问。
- **保存、重置与取消：** 无修改或有值不合法时「保存」禁用，这些页面不再弹「当前没有需要保存的修改」。页内表单新增「重置」，恢复为已存值，不再追问。
- **修改密码，以及管理员的新增用户、重置密码弹窗：** 字段合法后「保存」/「创建」才可点（两次密码不一致、用户名不合规时在输入时即指出），已有输入时关闭弹窗先问。
- **外观：** 托盘图标开关写入失败时说明原因，不再悄悄复原。
- **公司模式：** 关闭公司模式纳入受保护的重大操作。

## 工具

- 前端 skill 写入这条规则，并附新设置页面的检查清单。
- `test/form-commit-guard.test.ts` 解析 Web App 的 JSX：输入类控件不在 `onBlur` 或带写入的 `onChange` 里提交，提供「保存」的表单必须登记到离开确认，所列表单模块的每个弹窗都经它关闭。
- Web App 的测试新增按需启用的真实 DOM（jsdom），用于交互场景。
