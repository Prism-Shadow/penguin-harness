# 每个有待更新的页面共用一个提示块，并支持一键全部升级

- **Date:** 2026-08-28
- **Type:** feature
- **Scope:** `web`
- **Issue:** [#527](https://github.com/Prism-Shadow/penguin-harness/issues/527)

[English](2026-08-28-bulk-update-notice.md)

用于说明侧栏小红点指向何处的页面提示，现在在四个页面上是同一个共享块；在 Agents、技能库与模型库
上，它可以一次性处理自己所统计的全部对象，用户不必再逐个更新。

## Details

- Agents 页面新增了此前没有的提示块。其内核提示与另外三条一样变为可忽略：用户若有意让某个 Agent
  停留在它当初调校所依据的默认值代次上，红点不再长亮。该 gate 从 `update-badges.ts` 移入
  `todo-badges.ts` 并带上了签名；有新的 Agent 落后时，红点仍会重新亮起。
- 每个块只陈述本页面能够诚实统计的数字。模型库报告两个数字——表中缺失的目录条目，以及目录字段已
  变化的条目——直接取自同步动作本身计算的 delta。Agents 与技能库只报告一个：Agent 的内核不存在
  「新增」，而无人安装的 Skill 也不构成待办。成本中心保留单一的「标记为已读」，因为已经发生的错误
  无从更新。
- 批量按钮在写入前必须确认，措辞沿用各页面已有的原文：Agent 内核更新是智能合并，推进未改动的设置
  页、完整保留已自定义的设置页；Skill 更新是覆盖式重装，本地改动会丢失；预置同步以目录字段为准刷新
  差异，本地新增模型与 API key 保持不变。每个对话框都会列出批量操作将写入的具体对象。
- 部分失败时会点名未成功的对象，而不再只报告第一个错误。
- 逐个操作的路径保持不变：「同步预置」、各卡片上的 Skill 更新按钮，以及设置页内的单个 Agent 内核
  更新，行为一如既往。

## Compatibility

按用户存储在 `ui_prefs.todoDismissed` 下的忽略标记新增了第四个键 `agents`。此前写入的数据没有该
键，会被读作「未忽略任何内容」——Agents 的提示块会出现一次，可以再次忽略。无需迁移，也不会丢失
任何已存储的标记。
