# Web App：会话行区分运行中、已完成与完成未读

- **Date:** 2026-08-16
- **Type:** feature
- **Scope:** `web`, `server`, `docs`
- **PR:** [#302](https://github.com/Prism-Shadow/penguin-harness/pull/302)
- **Issue:** [#291](https://github.com/Prism-Shadow/penguin-harness/issues/291)

[English](2026-08-16-chat-completion-status.md)

运行中的会话此前只有一个小小的呼吸圆点，运行结束后圆点直接消失，于是"还在跑"和"已经跑完"在圆点消失后看起来毫无差别；而在用户看别处时跑完的任务，更是什么痕迹都不会留下。现在侧边栏的会话行和聊天页头部都会显示一个表示会话状态的图标：会话忙碌时是一个来回翻转的沙漏，会话安定下来后是一个圆圈对勾，并用颜色说明最后一条回复是否已读。

## 图标

- **忙碌** —— 沙漏，每三秒翻转 180 度两次，两次翻转之间有较长的停顿。压缩上下文同样属于忙碌，因此复用同一个沙漏，并沿用应用中压缩一贯的琥珀色；运行中则是灰色。也就是说这两个实时状态仅靠颜色区分，而每个图标都会在悬停提示和无障碍名称中说明自己是哪一种。
- **安定** —— 圆圈对勾。若会话在用户上次打开之后又运行过，显示为翠绿色；已读之后转为柔和的灰色。以图标实际所处的背景衡量，未读色在浅色主题下达到 5.48:1、深色主题下达到 10.47:1；已读色刻意收敛，为 2.54:1 与 2.66:1。两者之间的对比在浅色下为 2.16:1、深色下为 3.93:1，在模拟绿色盲下仍有 2.35:1 与 3.55:1，因为这一组颜色不只是色相不同，明度也不同。
- **不显示图标** —— 从未运行过的会话不显示任何图标，依据是服务端已有的 `hasTrace` 标记。该位置仍保留原有宽度，因此会话首次运行时整行不会重排。
- 每个图标都在两种语言下把自己的确切状态写进悬停提示和无障碍名称，已读与未读的区分也在其中，所以没有任何状态只能靠看颜色获知。实时状态以 `status` 播报，安定状态则是一张带标签的普通图像。

## 每一行都实时

- 运行状态此前只对标签页当前打开的那个会话是实时的。Session 通道的 `task_state` 事件以会话为界，且不带 id，因此其余每一行都停留在上次拉取列表时的状态：用户离开后仍在运行的会话会一直挂着沙漏，而在后台开始运行的会话 —— 定时任务、子 Agent、另一个标签页，或者用户刚刚离开的那个会话 —— 则根本不会出现沙漏。
- 服务端会把同一次状态翻转再发一次，走用户级事件流（`GET /api/events`），事件名为 `session_state`，除 `sessionId` 外还携带绘制图标所需的两个行字段：刚刚写入的 `lastActiveAt`，以及 `hasTrace`。Session 级的 `task_state` 保持原样：排队的后续任务计数和未投递的 steering 镜像属于正在观看的那个会话，列表事件两者都不带。
- 之所以要带上 `hasTrace`，是因为图标由三个字段决定而不是一个。它区分的是"已完成"与"从未运行"，而首次运行的会话，其列表行上仍是拉取时的 `false` —— 于是沙漏会正常转动，可一旦停下，那一行不会显示完成标识，而是直接变成空白。状态为 running 或 compacting 时该字段一律报 true，因为正在运行的会话必然已经启动过 Task；前端出于同样的理由把它当作只增不减的标志。
- 该事件只发往该 Project 拥有者与成员的用户通道，不发给其他任何人，并且只发往客户端确实已经打开的通道。
- 携带服务端自己的行时间戳，正是后台完成得以被看见的关键：用户在别处时跑完的任务读作未读，而不是直接落进柔和的已读图标。
- 若事件指向的会话不在任何已加载的分页中，则直接丢弃，而不是凭空造出一行 —— 其他 Project 的会话也是被同一条规则挡在列表之外的。
- 全程没有轮询。重连若落在通道重放缓冲区之外，本就会收到 `resync_required`；列表在该事件上重新拉取一次，因此投递缺口不会让某一行永远卡在运行中。
- 当前打开的会话永远不会画成未读 —— 用户正在看它 —— 所以在聊天页与用户通道先后报告同一次完成时，它的图标不会闪烁。

## 已读与未读

- 已读状态记录在浏览器本地，按 Project 划分，键名为 `penguin.sessionSeen.<projectId>`。API 中并没有已读回执这一概念 —— 既没有通知表，Session 上也没有已读字段 —— 因此这里沿用置顶会话出于同样原因而采取的做法，持久化在前端。
- 标记记录用户最后一次打开该会话的时间；当会话的 `lastActiveAt` 更新于该时间时即视为未读。打开会话会写入标记，用户正在观看时任务跑完也会写入。标记取墙上时钟与会话自身 `lastActiveAt` 中较晚的一个，因此即使浏览器时钟慢于服务端，打开会话也一定会被标记为已读。
- 每个 Project 首次写入标记时还会记录一个基准时间：在此之前最后运行过的会话一律算作已读，这样启用该功能不会让所有历史会话同时亮起未读。
- 每个 Project 最多保留 500 个标记，超出时淘汰最久未看的；会话被删除时其标记也会一并清除。
- 由于记录在浏览器本地，已读状态不会跟随账号流转：同一账号在另一台设备或另一个浏览器上从各自的标记开始，另一个标签页在重新加载之前也保持自己的视图。

## 减弱动态效果

在 `prefers-reduced-motion` 下，仓库全局的 `animation: none !important` 规则会直接关闭翻转，这里无需任何额外覆盖：`hourglass-turn` 关键帧只设置 `transform`，因此图标停留在静止时本来的样子 —— 一个竖直摆放、完整可见的沙漏 —— 而不会消失。
