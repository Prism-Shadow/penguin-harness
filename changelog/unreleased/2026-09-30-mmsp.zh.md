# MMSP 0.5.0：模型访问从 AgentHub 迁到 `@prismshadow/mmsp` 及其第二版流式协议

- **Date:** 2026-09-30
- **Type:** feature
- **Scope:** `core`, `model-catalog`, `skills`, `docs`
- **PR:** [#917](https://github.com/Prism-Shadow/penguin-harness/pull/917)
- **Breaking:** yes — 以 0.4.x 厂商 `client_type`（`deepseek-v4`、`minimax-m3`、`gemini-3.8`、`claude-5`、`gpt-6` 等）保存的模型条目无法再启动，因为 MMSP 0.5.0 不接受这些名称

[English](2026-09-30-mmsp.md)

PenguinHarness 把模型库从 `@prismshadow/agenthub` 0.4.15 换成了 `@prismshadow/mmsp` 0.5.0：同一个库，改名为 MMSP（Model Message Stream Protocol），带来第二版流式协议，客户端类型也改为按厂商的官方 API 或按传输协议命名。

## 流式输出

- `packages/core/src/llm/generative-model.ts` 里的流转换器精简为对 MMSP 语法的一一映射：`.delta` 项转成 `partial_*` 的 delta，`.done` 项转成 `partial_*` 的 `stop` 和完整消息，唯一的 `stop` 事件带来这次请求的用量与结束原因。不再从片段重组任何内容；工具调用直接由 `tool_call.done` 项补全，参数已经解析好。
- 结束原因为 `length` 或 `unknown` 的响应，其最后一项以 `fatal` 结束；没有收到 `stop` 事件就中断的流按 `malformed` 重试。

## 路由与预置

- core 对 MMSP 路由的镜像按 MMSP 的前缀规则重写。新增的 `routedClientType` 返回钉住的客户端类型；没有钉住时，返回小写模型 id 开头的厂商系列（`gpt-`、`text-embedding-`、`claude-`、`gemini-`、`glm-`、`kimi-`、`deepseek-`、`minimax-`）的官方客户端；都不匹配则什么也不返回。`resolveModelEnv` 与 `fastModeProtocol` 都读取它。
- 预置 `deepseek/deepseek-flash` 与 `minimax/MiniMax-M3` 去掉了钉住的客户端类型和 base URL：在 MMSP 0.5.0 下，这两个 id 自己就能路由。
- Penguin Go 的预置改为钉住 `gemini-generate-content`（Gemini 条目）与 `deepseek-official`（DeepSeek 条目）。
- 路由到 Google 官方客户端（Interactions API）的 Gemini 模型开放了快速模式，该客户端发送 `service_tier: "priority"`。
- base URL 是厂商自己端点、但没有 key 的模型条目，改为把厂商环境变量里的 key 显式交给客户端，因为 MMSP 0.5.0 不会把 `OPENAI_API_KEY` 或 `ANTHROPIC_API_KEY` 发往传给它的 base URL。
- 库自己的环境变量随之改名：`AGENTHUB_DEBUG` → `MMSP_DEBUG`，`AGENTHUB_CACHE_DIR` → `MMSP_CACHE_DIR`。`CLIENT_TYPE` 仍然有效。

## Skill 与文档

- `agent-development` 插件的 `unified-llm-api` Skill 针对 MMSP 0.5.0 重写：客户端类型及其 0.4.x 旧名、按前缀路由及其报错、流式语法（`.delta` / `.done` 项与唯一的 `stop` 事件）、只由 `.done` 项组成的消息、错误类型、模型注册表、各客户端的快速模式，以及 embedding 与内联数据。
- `penguin-sdk` 与 `agent-initialization` 两个 Skill 引用的 `agenthub-models` 并不是任何 Skill 的名字，已改为 `unified-llm-api`。`agent-development` 与 `agent-tuning` 插件升到 `2026.09.30.2`。
- 文档统一改用 MMSP 这个名字；模型、配置、CLI 与接口页面按厂商系列路由、承载快速模式的客户端以及新的客户端类型名做了更新。

## 兼容性

MMSP 0.5.0 不再接受 AgentHub 0.4 的客户端类型，而本版本之前写下的 `.project_config.toml` 可能存着它们。文件在第一次被读取时迁移一次，用户无需做任何事：见[向后兼容](2026-09-30-backward-compatibility.zh.md)。
