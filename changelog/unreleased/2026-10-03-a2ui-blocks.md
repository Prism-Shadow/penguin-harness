# Replies can carry A2UI blocks: choices, forms, steps, callouts and diagrams

- **Date:** 2026-10-03
- **Type:** feature
- **Scope:** `core`, `ui`, `web`, `server`, `cli`
- **PR:** [#968](https://github.com/Prism-Shadow/penguin-harness/pull/968)

[中文版](2026-10-03-a2ui-blocks.zh.md)

A reply can now carry components from a small trusted catalog as fenced blocks in its Markdown —
```` ```a2ui ```` with one JSON object, or ```` ```mermaid ```` — and the Web App draws them with its
own components and theme. A new preinstalled plugin, `a2ui`, teaches the model when and how to use
them, with STE-style writing rules and a checker script that tells it whether a draft is right
and how readable it is.

## Changes

- **Catalog:** `choice` (one question, 2–7 options, optional multi-select, "Other…" and a
  recommended mark), `form` (1–6 fields: single, multiple, text, number), `steps` (a procedure,
  with warnings and cautions above the step and notes below it), `callout` (note, tip, caution,
  warning), and Mermaid diagrams (lazy-loaded, strict security, coloured from the theme's tokens,
  with a "Show source" toggle).
- **Interaction:** picking an option or filling a form puts plain text into the composer — the
  option's value, or one `label: answer` line per field — and nothing is sent until the user
  presses Send. Only the latest reply of the main conversation is interactive; older replies,
  subagent conversations and the Trace view show the blocks read-only. While a reply streams, a
  block shows a quiet placeholder and draws once the reply settles; a block that does not parse
  shows its source with the first error above it.
- **Everywhere else, plain text:** the CLI and the messaging channels (Feishu, Telegram, QQ,
  WeChat) turn each block into readable Markdown — a choice becomes a numbered list ending in
  "Reply with a number or your own answer." The stored message and the Trace keep the blocks.
- **One grammar:** `@prismshadow/penguin-core/a2ui` is a dependency-free module holding the
  catalog's schemas, fence parsing, validation, a structural Mermaid check, an STE-lite prose lint
  for Chinese and English, the score and the text fallback. The renderer, the fallback and the
  checker all use it.
- **The checker** (`skills/a2ui/scripts/check.mjs`, bundled from that module by
  `pnpm build:a2ui-check`, Node builtins only) reports errors that would break rendering (L1:
  JSON, unknown type, missing fields, value limits, duplicate labels, forbidden Mermaid
  directives), warnings that cost the reader (L2: too many blocks or options, a question that is
  not last, a block nothing introduces) and prose warnings (long sentences, passive voice, vague
  words), scores the draft (any error makes the total 0), and with `--rubric` prints the
  self-review questions. The skill tells the model to run it on any draft with a block, fix it
  within three rounds, and send prose instead of a block that still fails.
- **Extensible:** the UI package's `registerA2uiRenderer` adds or replaces a block type, the same
  seam the dock's panel registry offers.
- **Docs:** the chat page's "Rich output blocks" section; the plugin is listed in the plugins
  README and the docs' skills page.
