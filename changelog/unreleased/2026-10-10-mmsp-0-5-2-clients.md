# MMSP 0.5.2: Google's official client is `google-official`, and the protocol menu offers Google GenAI and MMSP

- **Date:** 2026-10-10
- **Type:** feature
- **Scope:** `core`, `web`, `cli`, `docs`, `skills`

[中文版](2026-10-10-mmsp-0-5-2-clients.zh.md)

PenguinHarness moved to `@prismshadow/mmsp` 0.5.2, which names Google's official Gemini client `google-official` and adds the `mmsp` client for an MMSP server. The protocol menu in the base URL field now offers Google GenAI (generateContent) and MMSP after the three protocols it already listed.

## Routing

- Core's mirror of MMSP's routing follows 0.5.2: a `gemini-` model id with no client type routes to `google-official`, whose `MMSP_CLIENTS` row carries the variables (`GEMINI_*`), request path (`/v1beta/interactions`) and fast-mode protocol the `gemini-official` row carried. The Web's protocol path for the Google group names `google-official` too.
- `gemini-official` stays as an alias row, so a Project that stores it keeps working and is never rewritten: see [backward compatibility](2026-10-10-backward-compatibility.md).
- Fast mode is no longer offered for `claude-haiku-5-5` on Anthropic's official client, which MMSP 0.5.2 refuses it for, as for Sonnet 5.5 and Fable 5.1.

## Picking a protocol

- The protocol menu at the right edge of the base URL field lists **Google GenAI (generateContent)** (`/v1beta/models`) and **MMSP** (`/stream`) after OpenAI Responses, Anthropic Messages and OpenAI Chat Completions. The menu is the same in the model dialog of the custom and user-defined groups, in every group's settings and in the dialog that adds a group.
- A model or group that stores `google-genai` or `mmsp` shows it checked in the menu instead of the read-only "kept as configured" note. A stored `gemini-generate-content`, the 0.5.0 name of `google-genai`, shows as Google GenAI and is not rewritten.
- Detection is unchanged: it probes OpenAI Responses, Anthropic Messages and OpenAI Chat Completions only, so Google GenAI and MMSP are picked by hand.
- The help of `penguin config model add --client-type` names the five protocols.

## The `mmsp` client

- A model on `mmsp` falls back to `MMSP_API_KEY` and `MMSP_BASE_URL` (by default `http://127.0.0.1:25752/v1`) only when no base URL resolves for it, which the client reads itself. With a base URL and no key, it is built with no key rather than refused, which is how an open MMSP server is called; the add-group dialog lists such a server's models without a key too. This is the client's own rule.
- Fast mode is not offered on `mmsp`: the client forwards it to the server, where the client of the model's row decides.

## Skills and docs

- The `unified-llm-api` skill of the `agent-development` plugin was updated for MMSP 0.5.2: `google-official` and its `gemini-official` alias, the `mmsp` client and its credentials, `UpstreamError`, and Claude Haiku 5.5. The plugin moved to `2026.10.10.1`.
- The Models and Configuration pages list the five protocols, name `google-official`, and describe the `mmsp` client's variables and fast mode.
