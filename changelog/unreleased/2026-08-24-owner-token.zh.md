# 磁盘上不再有任何鉴权秘密

- **日期：** 2026-08-24
- **类型：** change
- **范围：** `server`、`cli`

[English](2026-08-24-owner-token.md)

鉴权方案原本在磁盘上放着两类长期秘密：`auth-token-secret`——一把永久签名密钥，数据根的备份一旦泄露
就等于能对线上服务永久伪造会话——以及 `initial-admin-password`，一个明文密码。两者都已消失。**磁盘上
不再有任何鉴权秘密。**

## owner token

`<root>/owner-token`——每次进程启动写入的新随机值，0600。通过 loopback 向 `POST /api/auth/owner`
出示它，就证明了"所有权"在这里一贯的含义（能读数据根），换回一个普通的签名会话。它不签名任何东西、
不由任何东西派生、随进程死亡：从备份里泄露出去的副本，几乎必然是服务早已不认的旧值。

用 magic-cookie 文件加 loopback HTTP 而不是 Unix socket，是刻意的：它在 Node 能跑的每个平台上行为
完全一致。代价如实说明：所有权检查发生在读取时刻——启动期间被偷走的值在下次重启前仍然可用，这是一个
有界的窗口，而签名密钥的窗口是无界的。

## 签名密钥搬进内存

进程启动时生成，从不落盘。备份无可泄露，轮换无需操作——重启即轮换。代价几乎落不到任何人头上：热推
只换 App 不换进程（密钥存活）；CLI 和 machines 的令牌只活一小时、按需重签；只有真重启后的浏览器会话
需要付出一次重输密码。

## 签发随之改变

`penguin auth token` 现在向运行中的服务兑换 owner token——这是常态，因为控制端在某台机器上签发之前
刚探测过它的服务。服务停着时哪里都没有密钥，于是退回唯一不需要密钥的会话形态：一行遗留会话记录，
验证路径一直认它。行路径上的外键保证了账号诚实——从未种过用户的数据根，伪造不出不存在用户的会话。

## 首次登录变成链接，不再是密码

新服务器的种子密码现在是生成、哈希、丢弃——没有人见过它。操作者拿到的是一条一次性登录链接，携带本次
启动的 first-login 令牌，在同样的框里打印，直到密码真正被设置为止，每次启动都会重印。

这条链接敢打印进控制台，是因为它有明确的边界：只在服务未被认领时有效、令牌只在内存且每次重启换新、
错误令牌和已认领的服务返回完全一致。它换到的会话标记为 `via: "setup"`——可以免旧密码设置密码（本来
就没有旧密码），但不开启任何桌面专属路由。

`penguin server reset-admin-password` 采用同样的形状：把管理员账号退回未认领状态并吊销其会话，不产生
任何需要抄写的明文。救援流程变成"启动服务，打开它打印的链接"。

## 兼容性

从旧版本沿用的数据根，其 `initial-admin-password` 文件会在**下次服务启动时被删除**。不会丢失任何东西：
账号密码本身没变，而仍在使用初始密码的服务会改为打印 first-login 链接。这段清扫无条件执行，等到所有
受支持的升级路径都不可能再带着那个文件时移除——跟踪点写在 `initial-password.ts` 里，与文件本身一同删除。
