# 平台数据库可以跑在 PostgreSQL 上

- **Date:** 2026-10-18
- **Type:** feature
- **Scope:** `server`
- **PR:** [#1192](https://github.com/Prism-Shadow/penguin-harness/pull/1192)

[English](2026-10-18-postgres-backend.md)

`PENGUIN_DB=pg` 让服务器自己的数据库——会话、用量记录、设置、Trace 索引——从数据根目录的
`web.db` 迁到 PostgreSQL 上运行。SQLite 仍是默认：不设这个变量，下次启动就回到文件，因为库里
没有任何字段记录它由哪个引擎写入。

## 数据层是怎么接上 PostgreSQL 的

- 平台数据层保留它同步的 `node:sqlite` 接口。shim 用 PostgreSQL 应答这套接口：异步的 `pg`
  驱动跑在自己的工作线程里，调用线程用 `Atomics.wait` 阻塞等待，因此各 repo 的预编译语句、
  `SCHEMA_SQL` 与有序迁移都原样运行。一个句柄就是一个连接，所以跨多次 `exec` 调用的事务仍是
  同一个事务，与 `node:sqlite` 的行为一致。
- 语句在出行时被翻译——只翻译平台真正写出的那些 SQLite 专有写法，其余原样放行；普通 CRUD、
  CTE、`ON CONFLICT`、`RETURNING` 本来就是 PostgreSQL 接受的。
- schema 在首次连接时建在一个 PostgreSQL schema 里（`PENGUIN_PG_SCHEMA`，默认 `penguin`），
  走的是新建 `web.db` 的同一条 `CREATE TABLE IF NOT EXISTS` + `ensureColumn` + 迁移路径。
  `PRAGMA user_version` 变成 `_pg_meta` 表里的一行，迁移阶梯因此保住它的版本戳。

## 翻译层改写了什么

| SQLite | PostgreSQL |
| --- | --- |
| `?` / `:name` 占位符 | `$n`，同名参数共用一个占位符 |
| `INSERT OR REPLACE` / `OR IGNORE` | `ON CONFLICT (<主键>) DO UPDATE` / `DO NOTHING` |
| `PRAGMA journal_mode` / `foreign_keys` / `busy_timeout` / `synchronous` | 丢弃 |
| `PRAGMA user_version`（读/写） | `_pg_meta` 表的一行 |
| `PRAGMA table_info(t)` | `information_schema.columns` |
| `BEGIN IMMEDIATE` / `EXCLUSIVE` / `DEFERRED` | `BEGIN` |
| `ALTER TABLE … ADD COLUMN` | `ADD COLUMN IF NOT EXISTS` |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| 标量 `max(a, b)` / `min(a, b)` | `GREATEST` / `LEAST`（单参数聚合函数不动） |
| 取值形态的 `a IS b` / `a IS NOT b` | `IS NOT DISTINCT FROM` / `IS DISTINCT FROM`（`IS NULL` 不动） |
| `LIKE` | `ILIKE` |
| `strftime` / `date(…)` 分桶 | `to_char` / `date_trunc` |
| `GROUP BY` 下被直接选出的列 | 追加进 `GROUP BY` 列表 |
| FTS5 虚拟表与 `MATCH` | 带生成列 `tsvector` 的表，`@@ to_tsquery` |

## 重复的读

每一次读都要为这座同步桥付费：调用线程阻塞着，一个工作线程、一个连接串行处理，于是每个请求
里几个小查询就能累出可观的等待。300 毫秒内重复的读由工作线程内一个按表记账的 LRU 直接应答，
写语句则会丢弃所有涉及它所写表的缓存项——进程内读己之写始终正确，进程外的写入最多陈旧 300 毫秒。

## 配置

| 变量 | 含义 | 默认值 |
| --- | --- | --- |
| `PENGUIN_DB` | 设为 `pg` 选用 PostgreSQL 后端 | 未设置：使用 `PENGUIN_WEB_DB` 指向的 SQLite |
| `PENGUIN_PG_DSN` | 完整连接 URL，可带 `?schema=`；设置后覆盖下面的分项 | 未设置 |
| `PENGUIN_PG_HOST` / `PENGUIN_PG_PORT` | 主机与端口 | `127.0.0.1` / `5432` |
| `PENGUIN_PG_DB` / `PENGUIN_PG_USER` / `PENGUIN_PG_PASSWORD` | 库、用户、口令 | `penguin` / `penguin` / 空 |
| `PENGUIN_PG_SCHEMA` | 存放平台表的 PostgreSQL schema | `penguin` |
| `PENGUIN_PG_TZ` | SQLite `localtime` 出现处所用的时区 | 服务器自身时区 |

## 适用范围

- 一个数据库对应一个服务器，与 `web.db` 相同：shim 只持有一个连接，而阻止两个服务器共用一个
  数据根目录的仍是实例锁。
- `web.db` 与 PostgreSQL schema 是两个独立的存储。迁移已有安装是把行复制过去，不是一个开关；
  本次改动不包含两者之间的搬迁工具。
