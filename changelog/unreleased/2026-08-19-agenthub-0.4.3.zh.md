# AgentHub 0.4.3：网关心跳不再中断流式响应

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `core`, `cli`
- **PR:** [#334](https://github.com/Prism-Shadow/penguin-harness/pull/334)
- **Issue:** [#286](https://github.com/Prism-Shadow/penguin-harness/issues/286)

[English](2026-08-19-agenthub-0.4.3.md)

`@prismshadow/agenthub` 从 0.4.2 升到 0.4.3。新版本会跳过网关注入到流式响应中的心跳事件，而不是让整条流失败（agenthub [#174](https://github.com/Prism-Shadow/agenthub/pull/174)）。

架在模型 API 前面的网关——one-api 一类的代理、OpenRouter——会在长时间生成期间发送心跳。在 0.4.2 上，这类事件会落到未知事件的兜底分支并抛错，harness 把这次抛错判定为可重试的请求失败，而重试又会撞上下一个心跳：经由这类网关的长生成会一直重连到放弃，在 Web App 里表现为无休止的「正在重连」。

## 细节

- Responses 协议的 client（`gpt-5.6`、`openai-responses`、`minimax-m3`）把 `keepalive` 视为已知的空操作；Chat Completions 系的 client（`openai-chat`、`deepseek-v4`、`glm-5.3`、`kimi-k3`）只在 `choices` 字段确实有值时才读取它；Anthropic 协议的 client（`claude-5`、`ant-messages`）接受 `ping`；Gemini 的 client 会跳过既无 candidates 也无 usage 的分块。真正未知的事件仍然照旧报错。
- 0.4.3 还把 MiniMax 的路由分支挪进了 client type 判断链，位于 Kimi 分支之后。所有 client type 的路由结果与此前完全一致，因此模型目录与协议路径提示不受影响——已逐个比对两个已发布版本的 client，确认 0.4.2 到 0.4.3 之间没有任何 base URL 或端点构造上的改动。
- `pnpm-workspace.yaml` 中 `minimumReleaseAgeExclude` 的条目改为 0.4.3；按该文件自身注释的要求，移除了 0.4.2 的条目。
