# 页面放弃的调用在服务端一并取消，到机器的转发随之断开

- **Date:** 2026-09-29
- **Type:** fix
- **Scope:** `web`, `server`

[English](2026-09-29-socket-timeout-cancels.md)

API 套接字上的调用 20 s 无应答时，页面就放弃了它，服务端却不知道，仍在继续处理。对机器的调用而言，这意味着一条转发一直开在那条不应答的路由上。几轮重载叠在一起，这些转发就在 hub 上越积越多，而页面早已不再等它们。现在页面放弃一个调用，服务端也随之释放它。

## 细节

- 应答超时的那一刻，页面为该调用发一个 `cancel` 帧；服务端中止该调用的请求，与它对流的处理相同。
- 机器代理在它转发的请求被中止时断开转发。被取消的转发不记为机器不可达。
