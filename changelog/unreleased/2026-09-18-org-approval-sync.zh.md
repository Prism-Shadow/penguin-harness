# 组织的审批模式改动也作用于已有的会话

- **Date:** 2026-09-18
- **Type:** fix
- **Scope:** `server`, `web`, `skills`
- **PR:** [#791](https://github.com/Prism-Shadow/penguin-harness/pull/791)

[English](2026-09-18-org-approval-sync.md)

在组织设置里改审批模式，现在连组织已有的工位会话与工单会话一并改掉，而不只作用于此后新开的会话。对话输入框在组织的会话上不再提供 `always-ask`——在那里它只会把须审批的调用一律拒掉。审批模式从此只归董事会：包括 CEO 在内，任何员工都不在 `org_config.toml` 里改它。

## 细节

- 组织设置的每次 API 写入都经过 `OrganizationService.patch`：`approval_mode` 变了，它就把新模式写到组织文件所列的每个会话上——台账里的现任与历史工位，以及各工单列出的会话——已归档的除外。运行中的会话自下一次审批决策起按新模式判定。模式没变的写入不动任何会话，因此某个会话在自己的输入区改过的模式会保留到组织下一次改模式为止。
- 对 `client: "org"` 的会话，输入区的审批选择器只列 `read-only`、`allow-all` 与 `deny-all`，与组织设置一致；智能体面板里子会话的输入框改的是父会话的模式，同样如此。已存为 `always-ask` 的会话仍列出并勾选它，直到改选其他模式。
- `company-employee` 与 `company-ceo`（插件 `agent-company` `2026.09.18.1`）写明审批模式属于董事会、由董事会在组织设置里修改：员工即使得到同意也绝不在 `org_config.toml` 里编辑 `approval_mode`——手工改动只作用于此后新开的会话——认为需要改时在全员频道向董事会请示。新建组织时生成的手册索引在目录表里写明同一点，中英两个模板都改了；已有组织的手册没有重写。
- 磁盘上模式已与组织不一致的会话保持原样，待组织下一次改模式时才随之更新；没有做任何迁移。
