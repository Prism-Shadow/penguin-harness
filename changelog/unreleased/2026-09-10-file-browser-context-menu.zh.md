# 文件浏览面板新增右键菜单、自动换行，编辑器与阅读视图外观一致

- **Date:** 2026-09-10
- **Type:** feature
- **Scope:** `web`
- **PR:** [#682](https://github.com/Prism-Shadow/penguin-harness/pull/682)

[English](2026-09-10-file-browser-context-menu.md)

原先浏览 Workspace 的停靠面板改名为「文件浏览」，右键可用此前无处安放的单条目操作；源码视图与就地编辑器
也统一为同一种呈现：同样的行号、同样的高亮、同样的换行方式，两者都不再有外框。

## 细节

- 右键、Shift+F10 与触摸长按都能唤出菜单，文件树行与预览区一致。整棵树共用一个处理器，由手势落点所在
  的行自行解析目标；落在行与行之间时保留浏览器自身的菜单，就地编辑器内同样保留——粘贴文本靠的正是它。
  HTML 与 PDF 预览是 iframe，其中的右键只会到达 iframe，不会传到面板。
- 菜单可复制条目在 Workspace 内的相对路径、把该条目的引用添加到对话，文件夹另有上传、文件另有下载。
- 「添加到对话」把 `@path` 插入到输入框的光标处，草稿其余部分原样保留；文件夹的引用保留末尾斜杠。不会
  发送任何内容，也没有任何解析——`@` 是写给人读的。
- 添加预览中的选中内容则写入一个以 `@path (L3-L7)` 开头的代码块，选中文本逐字保留。行号范围仅在源码
  视图能够确定时给出；围栏长度按需加长，使本身含有围栏的选中内容仍能正确嵌套。选中范围随后仍然保留：
  把引用交给输入框会让输入框获得焦点，而文本框获得焦点会清空文档中的选区，因此该范围会被重新选上。
- 源码视图显示行号，并去掉了外框、语言标签与顶栏——与编辑器一样直接展示文本。其上方的切换现在写作
  **预览 / 源码**：说的是你正在看什么，而不是它是怎么生成的。
- 复制与编辑浮在文件内容区的右上角。两者作用的都是它们下方的正文，而文件标题那一行只负责标出文件本身
  以及把文件带走的操作——视图切换、自动换行、新页面打开与下载。它们始终可见，而非悬停才出现：在触摸屏
  上，只在悬停时出现的控件等于没有，而编辑在这里没有第二个入口。
- 编辑器同样有行号与语法高亮：它现在是一个文字透明的 textarea，叠在源码视图所用的同一层代码之上，两层
  共用一个滚动容器，因此不可能错位。超过 32KB 的文件在编辑时不高亮——编辑器在每次输入停顿后都要重新
  着色，超过该体量后这段等待就不再像「颜色正在跟上」。行号在任何体量下都保留。
- 面板的全部操作——自动换行、编辑、复制、新页面打开、下载、刷新、上传——都改为图标按钮，不再显示文字。
  每个按钮的名称保留在无障碍名称中，并以 tooltip 显示在按钮下方：横排的一行图标若把提示放在侧边，就会
  盖住紧挨着的其它按钮。上传进行中时图标变为转圈指示，件数移入 tooltip——此时已没有别处可以显示它；
  预览无法使用独立源时，该提示并入链接自身的名称，而不再在旁边挂一个 ⚠。
- 源码视图也有了自动换行开关，并与编辑器共用同一个记忆值：两者是同一个文件的两种看法，按下编辑不应让
  文件重新折行、把你正要改的那一行带走。对话流中的代码块仍然横向滚动而不换行——那是记录的答案，不是
  文件阅读器的答案。

## 兼容性

自动换行的默认值改为开启，编辑器与新增的源码视图开关都是如此。存储的偏好项（`penguin.files.editorWrap`）
未改动且仍然读取：凡是用过编辑器换行开关的用户都保留自己的选择，只有从未存过值的浏览器才会采用新默认值。
该键保持原名，因为改名会悄无声息地丢掉这些选择。
