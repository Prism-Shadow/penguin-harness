# Claude Code 表面改读程序自己给出的状态与标题

- **Date:** 2026-09-07
- **Type:** improvement
- **Scope:** `core`, `server`, `plugins`

[English](2026-09-07-claude-code-state-and-title.md)

## 运行状态：以程序自己的说法为准

此前的规则是「有输出即运行、静默超过一个窗口即空闲」。那是另一个问题，只是答案常常相同：重绘不等于在干活（改窗口大小、粘贴回显），而一次长工具调用也不会因为转轮停一下就结束。

现在直接读屏幕上 Claude Code 自己的转轮行：

```
✻ Working… (3s · ↑ 1.2k tokens · esc to interrupt)   ← 运行中
✻ Worked for 2s · done 1:31 AM                        ← 空闲
```

字形会动、词是从一长串里挑的，所以匹配的是**形状**——一个符号、一个词、一个省略号——而不是某个具体的词。只读最后几行有内容的行，因为上面的会话记录里什么都可能出现。

## 会话标题取 Claude Code 自己起的那个

Claude Code 会给自己的对话命名，并把这个名字写进转写文件（`{"type":"ai-title","aiTitle":"…"}`），随着工作推进还会更新。表面跟随这个文件并上报每一个新标题，于是会话不再永远叫第一条 prompt 碰巧说的那句话。

转写文件在**每次轮询时重新选择**——取该工作区最新的那一个——而不是在启动时钉死：TUI 里的 `/resume` 会把程序切到另一个会话，钉死的文件只会指着最初那一个。

表面现在可以上报 `{ status, title }`，而不只是状态；旧的裸状态形式仍然有效。标题只在「还没有更合适的人命名过」时采纳：楼层记得自己上次写了什么，因此程序可以改进第一条 prompt 留下的那一行，而人一旦改名，这件事就到此为止。

## ……以及：一次推送现在送的是它自己的插件，而不是上一次的

在机器上验证标题时发现：修好的插件到了，跑的却还是上一版。热更新会在新平台启动**之前**落地并发布新的 assets，却在启动成功**之后**才提交 `harness.json`——因此启动时读「已提交指针」的平台，读到的是它正在替换的那一版。于是每次推送送的插件都比自己旧一版，修复看起来总是「下一次推送才生效」。

现在平台加载的是它正在启动的这一版所带的插件。
