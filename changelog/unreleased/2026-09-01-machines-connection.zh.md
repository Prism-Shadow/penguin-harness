# 通往一台机器的一条连接，以及「别名就是目标」

- **Date:** 2026-09-01
- **Type:** refactor
- **Scope:** `server`
- **PR:** [#578](https://github.com/Prism-Shadow/penguin-harness/pull/597)

[English](2026-09-01-machines-connection.md)

在上一处改动立在 `machines/` 前面的那道门之后，现在**每台机器只有一条连接**，本服务端对一台机器说的一切都走它。

## 这条连接

`ssh -T -D <端口> <alias> sh`，常驻——VS Code Remote-SSH 持有主机用的就是这个形状。命令从它的 stdin 进去、stdout 回来，由每个会话各自随机的标记定帧，因此命令无论打印什么都伪造不出自己的终止符。脚本或 tar 包以 base64 heredoc 的形式走**同一个 stdin**，其终止符不可能出现在正文里。而 `-D` 让这个会话同时是我们某个 loopback 端口上的 SOCKS 服务器，于是通往机器的任何 TCP 连接都成了同一个 ssh 会话内部的一个 channel。

于是一次安装就是：问一句这是什么机器、安装器走 stdin、store 走 stdin、再问一句它最后成了什么——一条连接上的四次往返；而在此之前，每一步都是各自的一次 ssh、各自的一次握手，外加一次 `scp`。

这是**结构，不是配额**：不管多少调用者要、要多少次，都开不出对同一台机器的第二条连接，因为根本没有能开出它的东西；第二个请求排在第一个后面。Win32 OpenSSH 没有 ControlMaster，所以「一条连接」不能靠多个 ssh 进程共享套接字得到——靠的是从不启动第二个进程。

**例外是 Windows 远端。** 它的 sshd 把命令交给 cmd.exe，没有 `sh` 可以用来持有会话，因此它的 PowerShell 安装器自带一条连接（`oneShot`/`copyTo`，按机器串行）。这一点写在代码所在处，而不是留给人去发现。

## 别名就是目标

过去安装前会跑一次 `ssh -G` 来解析别名。它唯一被用到的输出是 user，而这个值又被原样以 `-o User=…` 交回给 ssh——ssh 读的是同一份配置，于是这一趟等于问了 ssh 一个问题，再用它的答案回答 ssh。主机、端口、身份文件、跳板机被解析出来，从来没有人读。它也分辨不出别名是否存在（对任何名字都会打印一份默认配置），所以由它喂出的那个拒绝码，实际上只在配置写坏或 ssh 不在 PATH 上时才会触发。

它和它背后的设置解析器一起删掉了。别名原样交给 ssh，它的含义由 ssh 每次按自己的配置重新决定——这里不会有任何东西对着一个人随时在改的文件过期。列出配置里的别名保留；那是本应用从这份文件里拿走的唯一东西。

## 兼容性

`POST …/machines/:id/install` 不再返回 `502 unresolvable_host`。ssh 用不了的配置，会在连接打开时以 ssh 自己的话报出来。
