# The App Center is a home screen of workbench apps

- **Date:** 2026-11-04
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `ui-gallery`, `plugins`, `docs`, `rfcs`
- **PR:** [#1488](https://github.com/Prism-Shadow/penguin-harness/pull/1488)

[中文版](2026-11-04-app-center-workbenches.zh.md)

The sidebar gained an **App Center** entry (`/apps`), pinned right after Agents. It is the Project's home screen: one tile per workbench of the Project's agents on this server whose own `package.json` declares `penguin.appCenter.show: true`, each tile the app's icon and name. A click opens the app in a window over the grid, and the tile's menu opens it full screen. The viewer drags tiles to reorder them and into folders, or makes a folder from **New folder** in the page header, and the arrangement is kept with their account. A tile whose app is still building shows a turning ring and opens once the build is done.

## Details

- A workbench's manifest gained `penguin.appCenter { show, title?, titleZh?, icon?, tab? }`. Titles default to the first tab's, then to the package name; `icon` names an SVG, PNG, JPEG, WebP, GIF or AVIF file under `ui/` of at most 256 KB, whose bytes must agree with its extension; `tab` picks the tab the shortcut opens. A declaration that does not hold up does not fail the load: the workbench has no shortcut, and its load hints and `.build/status.json` name the fix. `WorkbenchInfo.appCenter` carries the parsed declaration.
- `GET /api/projects/:projectId/app-center` answers `{ shortcuts, layout }`. Each `AppCenterShortcut` carries its titles, its `icon` as `{ url, tint }`, the full-page path, its `tab`, and `build`: `building` while a load of its files is under way or queued, `failed` with the recorded `error` when the last load failed, else `ready`. The list reads the manifests and load status only and compiles nothing; it starts each listed Agent's file watcher, and lists this server's Agents only.
- A load that starts sends `workbench_building { projectId, agentId, workbenchId }` on the user event stream; `workbench_updated` still follows when it ends. A building tile cannot be opened and turns live by itself.
- The icon follows the plugin icons' rules ([#1514](https://github.com/Prism-Shadow/penguin-harness/pull/1514)): core's `iconImage` checks it, and `GET /api/projects/:projectId/agents/:agentId/workbenches/:id/app-center/icon` answers with the server's shared icon response — the content type its bytes say, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` and `Cross-Origin-Resource-Policy: same-origin` — at a URL whose `rev` follows the bytes. The Web App draws it with `ImageIcon`, a monochrome SVG in the text colour, never as markup.
- The viewer's order and folders are kept per account and Project in `ui_prefs.appCenterLayouts` as `AppCenterLayout { v: 1, items }`, written through `PUT /api/projects/:projectId/app-center/layout { layout | null }` (`null` restores the default order). Its shape is checked and a write that does not hold up is refused whole; `PUT /api/me/prefs` refuses the key. A new app is appended, one that went away drops out, and a folder goes only once it is empty: a folder of one app stays.
- Dragging a tile between two others moves it, onto another makes a folder called **New folder** (renamable), onto a folder adds it; an open folder is a panel over the grid, and dragging a tile out of it takes it out. Nothing moves until the drop: a line in the gap or a ring around the target marks what the drop would do, and the tile's `data-drop` names it.
- **New folder** in the page header, also the first row of the grid's empty-space menu (**New folder…**) and of a tile's **Move to…**, opens a dialog: a name, starting as **New folder** and selected, and a checklist of every app with its icon, where an app already in a folder names it and leaves it when checked. **Create** waits for a checked app; the folder takes the place of the first checked app and is stored through the same layout write. From a tile's menu the dialog opens with that app checked.
- Every tile, folder and the grid's empty space has a context menu: open, open full screen, Move to…, move forward / backward, remove from folder, show error, view in agent settings, remove from the App Center; rename and ungroup for a folder; **New folder…** and **Restore default order**, which asks first. The menus are how the keyboard and touch arrange the grid.
- `PATCH /api/projects/:projectId/agents/:agentId/workbenches/:id/app-center` `{ show }` rewrites only `penguin.appCenter.show` in the workbench's `package.json` (2-space JSON, other keys kept), reloads it and records the edit as a version. A `package.json` that is not a JSON object is answered 409 `workbench_manifest_invalid`. In Agent settings, each workbench row of a local Agent (the Plugins tab since [#1497](https://github.com/Prism-Shadow/penguin-harness/pull/1497)) gained the App Center switch, committed on click and labelled **App Center** (a click on the words flips it too; the longer hint is its tooltip).
- A workbench row now says what its controls do: **Open** is a text button; its two switches carry their words, **Enable** and **App Center**; and Reload, **Version history**, Export and Remove (still asked first) moved from bare icon buttons into a **More** (⋯) menu. The row leads with the workbench's App Center icon when it declares one, else its plugin's icon or the anvil tile; `WorkbenchInfo.icon` carries it as the same `IconRef` the shortcut gets, re-rooted onto a machine for a machine's Agent. A machine's Agent has no App Center switch.
- A workbench turned off by its own or the Agent-wide switch ([#1496](https://github.com/Prism-Shadow/penguin-harness/pull/1496)) has no tile. Its row still names its App Center declaration and icon, and the App Center switch rewrites its manifest without loading it.
- The full page of a workbench opened from the App Center returns to it, to the window it was opened from when there was one.
- `packages/ui` gained `ContextMenu`: the menu of one target, opened by a right-click at the pointer, by Shift+F10 or the ContextMenu key from the focused target, or by a press and hold on touch; Esc closes it and hands focus back; the innermost of nested targets owns a gesture, and the browser's own menu is kept everywhere else. `isContextMenuKey` now also takes the ContextMenu key, for every row menu. `InstallRing` is the building ring. The gallery's pickers board shows the context menu, and a new App Center surface shows the tile states and a folder.
- With no shortcut, the page explains what a workbench is and offers **Create with AI**, which opens a conversation with the `web-design` and `penguin-plugin` Skills asking the agent for a workbench in the App Center.
- The `penguin-support` plugin's Support workbench declared `appCenter: { show: true, icon: "ui/icon.svg" }` with a new icon, and its `penguin.version` moved to `2026.11.04.1`. An installed copy on `penguin_support` reports one plugin update; it appears in the App Center once updated.
- The `penguin-plugin` Skill (`2026.11.09.1`) gained an "App Center" section on the manifest key.
- The registry of external apps, health probes, `[app_center]` origin block, `penguin app` CLI and `app-center` Skill of [#595](https://github.com/Prism-Shadow/penguin-harness/pull/595) were not adopted.
- `rfcs/PRFC-0020-agent-workbench.md` moved to v1.3.0 with an "App Center" section.
