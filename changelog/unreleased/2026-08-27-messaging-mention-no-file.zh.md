# 回复里提到但并不存在的文件名，不再发进聊天

- **Date:** 2026-08-27
- **Type:** fix
- **Scope:** `server`
- **PR:** [#511](https://github.com/Prism-Shadow/penguin-harness/pull/511)

[English](2026-08-27-messaging-mention-no-file.md)

回复文件功能会扫描回复正文里像路径的词，把能在 Workspace 中解析到的发出去。解析不到的名字原先会被播报进聊天——*「回复中提及但未发送——该会话 Workspace 内没有这些文件：hello-world.md」*——理由是：承诺过的文件没到、又没有任何说明，会让人觉得功能坏了。本次改动去掉了这条通知，改为把这些名字写进服务端日志。

## 细节

- 那条理由只在「确实承诺过」时成立。该规则读的是自然语言，而自然语言提到文件名的原因常常与投递无关：模型描述了一个它最终并没有写的 `hello-world.md`，或者引用了它读过的文档里的某个路径。把这些播报出来，等于在完全正确的回复下面加一行像报错的字，而读到的人无事可做。
- `messagingFilesMissingNotice` 改名为 `messagingFilesMissingLog`，改名本身就是重点：聊天通知与日志面对的是不同的读者，而只有其中一方需要为回复顺口提到的一个名字买单。
- **确实存在**但上传失败的文件仍然会在聊天里点名。那种情况下回复承诺了某样东西却没送到，正是沉默会被读成「坏了」的唯一情形。
