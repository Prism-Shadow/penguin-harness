# 一个众所周知的服务端口

- **日期：** 2026-08-15
- **类型：** feature
- **范围：** `core`、`cli`、`desktop`、`docs`

[English](2026-08-15-server-port.md)

服务端、CLI 和桌面客户端现在把 **7364** 端口当作一个地址，而不只是一个默认值：客户端通过探测这一个
已知端口来找到"这个用户的服务"，探不到时可以提出为你装一个。端口号本身没变——变的是它现在固定了。

## 改了什么

- 桌面客户端内嵌的服务绑定 `DEFAULT_SERVER_PORT`，不再向系统要一个临时端口。`--port` / `PORT`
  在各处仍然可以覆盖。
- 客户端"记住上次端口"的机制被删掉了。它原本是为了让应用来源（以及渲染进程里按来源隔离的
  `localStorage` 和 cookie）在多次启动之间保持稳定；端口固定之后，这一点自然成立。
- 端口被占用时不再绕开。客户端在启动新服务之前，仍然会先连上同一数据根上已经在跑的 penguin 服务，
  所以这只在别的程序占了 7364 时才会发生——那种情况值得报错，而不是悄悄换一个来源。

## 代价

默认每台机器每个用户只跑一个服务：第二个实例必须显式指定端口。这是固定地址换来的代价，而且 SSH
隧道本来就有同样的约束——本地端口必须等于远端端口，因为预览 URL 是按服务自己绑定的端口拼出来的。
