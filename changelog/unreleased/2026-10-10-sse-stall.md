# The Web App catches up on its own when a live stream dies silently

- **Date:** 2026-10-10
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#1026](https://github.com/Prism-Shadow/penguin-harness/pull/1026)

[中文版](2026-10-10-sse-stall.zh.md)

A Session stream or the user event stream whose connection died without an error (a half-open connection, a stuck proxy or NAT, a laptop that slept or changed networks) left the page frozen until it was reloaded, while the Agent kept running on the server. The page now notices the silence and resumes the stream from the last event it received, and the server cuts off a stream whose peer stopped reading.

## Details

- The server's heartbeat is now a named `ping` event (`data: {}`, no `id:` line), sent right after a stream's initial events and every 20 seconds after, instead of a comment line the page could not see. It moves neither the client's `Last-Event-ID` nor the replay position.
- Once a stream has sent a ping, the Web App treats 50 seconds without any event as a dead connection: it closes the stream and opens a new one from the last event id it saw, which the server replays from, or answers with `resync_required` when that id has left its buffer. Showing the tab and coming back online check at once. Reopens that keep failing back off from 1 second, doubling up to 30 seconds; a stream the browser gave up on (for example a 502 while the server restarts) is reopened the same way.
- A stream from a server that never pings, such as a machine still on an older version, is left to the browser's own reconnection, as before.
- `GET /api/sessions/:id/stream` and `GET /api/events` accept the last event id as the `lastEventId` query parameter when no `Last-Event-ID` header is sent, since a page cannot set headers on an EventSource it opens itself. The header wins when both are present. The machine proxy forwards both.
- A stream whose writes have been stuck on a full socket for 30 seconds has its connection closed, so a client that is still there reconnects and resumes.
- The server API reference (`/docs/server-api`, § Streaming (SSE)) documents the ping event, the `lastEventId` parameter, the write timeout and the client's liveness check.
