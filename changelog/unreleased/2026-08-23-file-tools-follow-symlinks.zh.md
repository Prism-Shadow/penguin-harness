# edit_file 与 write_file 沿软链接写入，而不是替换掉链接

- **Date:** 2026-08-23
- **Type:** fix
- **Scope:** `core`, `docs`

[English](2026-08-23-file-tools-follow-symlinks.md)

编辑或写入一个软链接路径时，链接会被替换成普通文件，而它指向的文件原封不动——工具却报告成功，
还附上了一份从未落到真实文件上的 diff。`stat` 和 `readFile` 本身就会解引用，因此两个工具读到的
内容和权限位都是目标文件的；唯独原子写最后那一步 `rename` 作用在链接自身上。现在两者都会先解析
整条链接链、写入链尾的文件，链接得以保留，内容也落在它指向的地方。

## 细节

- `resolveWriteTarget` 用 `readlink` 逐跳解析（上限 40 跳，与内核自身的 `ELOOP` 预算一致），
  返回第一个不是可读链接的路径。成环时报 "Too many levels of symbolic links" 而不是卡住。
- 解析只针对末段，而非走 `realpath`：目标尚不存在的链接同样能解析出来，`write_file` 会像 Shell
  重定向穿过悬空链接那样创建该文件及其父目录。路径中间的目录软链接不做处理——临时文件只需要与
  最终文件名同处一个目录，rename 就仍是原子的。
- 临时文件现在创建在解析后的目标旁边，链接跨越挂载点时 rename 也不会跨文件系统。
- 保留被覆盖文件权限位的行为至此才真正成立：这些位取自解引用后的 `stat`，现在被还原到同一个
  inode 上。
- 指向 Workspace 之外的链接与其他路径一视同仁地跟随——这两个工具本就接受任意绝对路径，与
  Shell 工具同等对待。
