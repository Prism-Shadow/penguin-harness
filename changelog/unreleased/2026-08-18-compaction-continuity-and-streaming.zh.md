# 压缩：Task 中途的续接、悬空区间的修复与流式摘要

- **Date:** 2026-08-18
- **Type:** fix
- **Scope:** `core`, `server`, `web`
- **PR:** [#329](https://github.com/Prism-Shadow/penguin-harness/pull/329)
- **Issue:** [#288](https://github.com/Prism-Shadow/penguin-harness/issues/288), [#290](https://github.com/Prism-Shadow/penguin-harness/issues/290)

[English](2026-08-18-compaction-continuity-and-streaming.md)

修复了三个压缩缺陷，并让压缩横幅显示实时的摘要文本。Task 中途的压缩现在会先关闭本轮挂起的工具交换再压缩，Agent 循环因而能在压缩之后继续跑下去；被进程意外终止留下的悬空压缩区间会在会话恢复时得到修复，压缩之后发出的消息不再因刷新而消失，过期的 `(unknown tool)` 卡片也随之消失；摘要则通过新增的 `compaction_delta` 事件，在写出的同时抵达 Web App。

## 压缩前先关闭挂起的工具交换

Task 中途的压缩过去会把本轮刚到达的工具结果折叠进压缩请求本身。由于压缩请求骑在一个尚未闭合的工具交换上，模型往往继续推进任务而不是给出摘要，而每一个这样的响应都会烧掉一次重试，并把被折叠的输出吸收进旧上下文（[#85](https://github.com/Prism-Shadow/penguin-harness/issues/85) 的携带规则）。压缩一旦被放弃，整个运行要么空手而归地结束，要么只带着几条光秃秃的 `[tool error]` 修复输出继续。

- 新增可选的 `LLMInterface.appendExchange`——由 `GenerativeModel` 基于 AgentHub 的历史实现——把本轮的工具输出作为独立的、已完成的交换提交，并以一条简短的合成助手回复收尾（不能为空，因为各家提供方都会拒绝空的助手内容）。压缩 Prompt 于是作为全新的用户轮次到达，配对关系保持完整，被拒绝的尝试也再无法吸收这些输出。追加从不重写历史，提供方的提示词缓存前缀因此得以保留；压缩成功后旧对象会被丢弃，那条收尾回复也就不产生任何代价。
- 手动 `/compact` 保留折叠：它的输入是中断携带过来的内容，可能把 flatten 文本与结构化输出混在一起，并不是一个可以闭合的单一交换。未实现 `appendExchange` 的 LLM 实现同样保留折叠。
- 当被吸收的输出已让本轮没有任何可发送的任务内容时，一次失败的 Task 中途压缩会合成一条续接输入——一条 `[compaction_failed]` 注记，仅对模型可见，从不产出也从不持久化——跟在所有修复输出之后，于是这次运行会在原有上下文上继续，而不是就此结束。

## 悬空的压缩区间在恢复时自愈

压缩进行到一半时进程死亡，会在分片里留下一个没有对应结束事件的 `compaction_begin`。核心的重放能够容忍这个悬空事件，并把后续对话继续追加到同一个文件，但每一个无状态读取方都会把这一对事件之间的消息当作压缩内部内容，于是压缩之后发出的一切都会在重新加载时消失；等到后来某个 `compaction_end` 在 Task 中途把状态解开，工具输出便会因为其调用被吞掉而渲染成 `(unknown tool)` 卡片。

- `resumeTrace` 会报告这个未配对的 begin，`resumeSession` 则在任何新记录落盘之前追加一条合成的、标记为 aborted 的 `compaction_end`，使文件对此后每一个读取方都是良构的。修复是幂等的，健康的 Trace 会被跳过。
- 各读取方另外还会在几个无歧义的信号上自行关闭过期区间——另一个 `compaction_begin`（区间从不嵌套）、一个 `abort` 事件（引擎总是先关闭这一对），以及轮转产生的 `session_meta`——Web 侧的 reducer、服务端的窗口扫描器与 Trace 分析流程都是如此，让在修复之前就已受损的 Trace 仍然可读。
- 服务端扫描器的缓存版本随之提升（`CACHE_VERSION` 2），已缓存的 `page_stats` 记录会按新的边界规则重新计算。

## 压缩摘要实时流式呈现

压缩请求的原始消息仍然只存在于 Trace 中，但它生成的文本会作为新增的、仅存在于流中的 `compaction_delta` 事件，在成对的压缩事件之间被转发出去。

- Web App 的压缩横幅会在标题下方展示正在写出的摘要，尾部截断，并用核心所用的同一个宽松抽取器剥掉标签；压缩尘埃落定之后，完整文本会折叠进一个可展开的正文区域。
- 增量从不写入 Trace——Writer 在结构上就拒绝它们——而历史重建会依据压缩区间中已记录的助手输出重新构造出同样的文本，因此重新加载后看到的与实时观看者看到的一致。
