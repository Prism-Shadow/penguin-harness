# CI 更快：锁文件改动只检查它波及的包，最长的作业拆分

- **Date:** 2026-11-10
- **Type:** process
- **Scope:** `ci`, `server`
- **PR:** [#PR_NUMBER](https://github.com/Prism-Shadow/penguin-harness/pull/PR_NUMBER)

[English](2026-11-10-ci-time.md)

CI 规划不再把普通 PR 变成三平台全量运行；决定全量运行时长的作业被拆分，或少构建了不需要的内容。每个测试套件仍在原来的平台上运行。

## 规划

- `pnpm-lock.yaml` 的改动只选出自身锁文件条目有变、或解析到的依赖闭包触及变动条目的包，连同其使用方（`scripts/ci-lockfile.mjs`）。其中有插件时，与改动插件文件一样，同时选上读取插件目录的包；锁文件改动仍会运行 npm packaging 作业，desktop 自身的依赖有变时还会打包 desktop 应用。根工具链、锁文件的设置或覆盖项改动，或规划读不懂的锁文件，仍全量验证。此前任何锁文件改动都会全量验证。
- `rfcs/` 属于文档，不选任何包作业。规划与聚合门禁自己的测试由每次都运行的 style 作业执行，改动它们不再多选作业；`scripts/release-npm.sh` 只选执行它的 npm packaging 作业。
- 测试 desktop 的分片不再构建 Web App 的打包产物——只有打包后的应用才读取它；负责打包的 runtime 作业照旧构建。

## 作业

- server 套件在 Linux 上分为两个作业（`test (server-1)`、`test (server-2)`），按与 Windows 分片相同的实测权重分配文件，各自上传本半的覆盖率。
- 全量运行中，macOS 把站点包分为两半（`test-macos (sites-1)`、`test-macos (sites-2)`），core 与 server 合为一个作业（`test-macos (core-server)`，先跑 core 的套件），使一次全量运行不超过账户可同时运行的五个 macOS 作业。非全量运行的 macOS core 与 server 仍分开。
- 运行 gallery 布局检查的作业在构建的同时安装 Chromium，经共享 setup action 新增的 `alongside` 输入。
- `packages/server/test/shard-weights.json` 按最近八次运行重新测定：自该表建立以来，套件已从 873 增长到 1349 个 Windows 测试秒，旧表让一个 Windows 分片比其余分片重约六分之一。
