# Group connections: one key, base URL and protocol per model group

- **Date:** 2026-10-02
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `cli`, `docs`, `plugins`
- **PR:** [#948](https://github.com/Prism-Shadow/penguin-harness/pull/948)
- **Breaking:** yes — `penguin config provider` was removed in favour of `penguin config model` without `--model-id`; `GET /models` reports a model's own `clientType` and `credential` only, what it is used with in `effective` (sources `model`, `provider`, `none`), and the group's values in `providers`

[中文版](2026-10-02-provider-connection.zh.md)

A model group holds its connection (API key, base URL, protocol) once, in `[providers.<id>]`, and its models follow it field by field unless they set their own. The Project config file became the only source of these values: the built-in catalog is written into it when a Project is created, by **Add new models** and by **Restore defaults**, and is never read as a fallback. Every group header gained a settings gear, where the group key is entered; **Connect** writes it as well; OpenRouter, TokenDance and SiliconFlow take hand-added models; "Sync presets" became **Add new models**, which only adds, beside **Restore defaults**; and `penguin config provider` merged into `penguin config model`. Existing files are migrated once; see [backward compatibility](2026-10-02-backward-compatibility.md).

## Storage and resolution

- `.project_config.toml` gained `[providers.<id>]` (`api_key`, `base_url`, `client_type`, `created_at`), written between the top-level keys and `[[models]]`. A `[[models]]` entry stores `api_key`, `base_url` and `client_type` only as its own overrides.
- Each field resolves on its own from the file alone (`effectiveConnection`, `resolveEntryCredential` in core): the model's value, then the group's, then none, which leaves it to the client: its default endpoint, MMSP routing by model id, and the environment key where PRN-021 allows it. Sessions, the vision describer, the connection and speed tests, vision and protocol detection and the utility completion build their clients on the resolved connection, and PRN-021's environment fallback judges the resolved endpoint: a DeepSeek group pointed at a proxy takes no `DEEPSEEK_API_KEY`.
- A key follows its endpoint (`groupKeyReaches`): the group key reaches a model with no base URL of its own, or one with the same origin (scheme, host, port) as the group's base URL. A model pointed at another host needs a key of its own; Atria Dawn Preview in **Custom** carries its own endpoint, so a Custom key never reaches its host.
- A new Project's file stores each built-in group's catalog endpoint and protocol in `[providers.<id>]` (`catalogGroupConnection`, `presetProviderTable`): the OpenAI-compatible gateways and ModelScope get a base URL and a protocol, Penguin Go and OpenCode Go a base URL, vLLM a protocol; the first-party vendors and **Custom** get none. Preset rows store their catalog facts (context window, pricing, `vision = false`) and a protocol or endpoint only where theirs differs from the group's: the per-model protocols of Penguin Go and OpenCode Go, OpenCode Go's Messages endpoint, and Atria's endpoint and protocol. `ensurePresetModels`, which backfills a Project with no models, writes the same tables for built-in groups whose table the file lacks, and stores the backfilled rows against a table the file already holds, as **Add new models** does.
- A row's own protocol always wins over its group's, so every group takes a protocol, Penguin Go and OpenCode Go included.
- A row without `vision` reads as supporting images; the catalog is not consulted. Preset display names still come from the catalog, as labels.

## Group keys

- **Connect** (TokenDance, Penguin Go, ModelScope), **Group settings** and ModelScope's token refresh write the group key and leave a key set on one model in place; the dialogs say how many models use the group key and how many keep their own.
- The header has no **Enter key**: the group key is entered in **Group settings**. A connected group's status reads **Connected** (已连接) and opens a menu with **Sync models** (Penguin Go), **Reconnect** and **Disconnect**, which deletes the group key after a danger confirmation; a member sees the status as text. **Connected** means the group key is stored.
- The group key is written even when no model uses it yet (every model has its own key, or the group has none), and the result says 0. Penguin Go's and ModelScope's **Connect** no longer report that case as a failed write (`apply_failed`).
- Account balances are read with the group key only; without one, with the environment key the group's resolved endpoint allows (DeepSeek's `DEEPSEEK_API_KEY`). The amount opens a menu with **Pin beside your name** / **Unpin** and **Refresh**, and a line with the provider's figures and the read time; the separate pin and refresh icons were removed.
- Penguin Go's authorization and **Sync models** only add: a model the platform offers and the Project lacks arrives with its price, promotion and protocol, and no key of its own. Its endpoint follows the per-field rule of **Add new models**: where the group's table in the file holds a base URL, the row stores one only where it differs from the platform's relay URL, so a group pointed at a proxy takes the new model along with its key; where the table holds none, the row stores the platform's in full. Models already stored, with their prices, protocols and promotions, are no longer rewritten, and none is removed.

## Group settings

- Every group header, **Custom** included, ends with the speed test and **Settings** (a gear), so the two stand at the same right edge. The **{group} group settings** dialog edits the group's API key (masked, clearable), base URL and protocol as the file stores them. An empty base URL says the client's default endpoint is used, and **Detect** probes the field's URL, else the stored one, with the group key as the fallback key. The protocol's first option, **Not set**, leaves it to each model or to routing by model id. Where the catalog gives the group an endpoint or protocol that differs from the field, a grey line shows it for reference. The dialog says how many models carry their own values, saves only the changed fields, and detects the protocol on save only for **Custom** or a user-defined group where nothing else decides it.
- `PUT /api/projects/:projectId/models/providers/:provider` (owner) writes one group. `PUT /models` accepts `providers`, merged per group, and drops a user-defined group's table once the group has no models. `POST /models/detect` accepts `provider` without `modelId`, meaning the group key. `GET /models` returns `providers` (keys masked) and each model's `effective` connection with the source of every field.

## Adding models

- OpenRouter, TokenDance and SiliconFlow take hand-added models (`ModelProviderInfo.addable`); TokenDance and SiliconFlow carry `openai-chat` as their catalog group protocol. **Add model** became an icon, and its dialog is titled **Add model** (新增模型) in every group, without the "(OpenAI protocol)" the gateway groups had.
- The add-model and **Model settings** dialogs gained a **Details** section, collapsed by default. Adding shows only the model ID, display name and group; the API key, base URL and protocol (with **Detect**), the connection test, the context window, output cap, prices, vision and fast mode sit in **Details**. **Model settings** keeps the key, base URL and protocol in view and folds the other five. Saving opens the section and focuses a required field there that is missing or invalid.
- An API key or base URL a model would inherit from its group shows only "Leave blank to use the group's setting" as its placeholder, without the group's value; a key field whose model the group key does not reach says so.
- Protocol detection on save runs only when neither the model nor its group decides the protocol.
- **Import models** writes the base URL, key and protocol to the new group's settings once and imports the models bare.

## Presets

- "Sync presets" split into **Add new models** and **Restore defaults**, both on the server: `POST /api/projects/:projectId/models/sync-presets` with `mode` `add` or `restore` (owner). The page's own merge was removed.
- **Add new models** adds the missing non-retired presets with their promotions. Per field, an added row stores its difference from the group's catalog value where the file's group table holds that field, so a group pointed at a proxy takes it along, and the full catalog value where the table lacks it. A group table is written only for a built-in group with neither rows nor a table in the file. Existing rows, tables, keys and promotions are untouched. The badge and the notice count new models only: "{n} new preset models to add".
- **Restore defaults**, behind a danger confirmation, resets built-in rows' context window, prices and vision flag, removes their display name, output cap and fast mode, and returns their base URLs and protocols to the catalog's, stored only where they differ from the group's. The tables of built-in groups other than **Custom** get the catalog's base URL and protocol back, a missing one is created and an emptied one dropped; **vLLM**, whose catalog has no endpoint and whose models run on the user's own server, keeps its base URL and gets only the catalog's protocol back, while a vendor group's proxy base URL is removed. Deleted presets come back, and promotions are reset to the catalog's (Penguin Go's and those of the user's own models are kept). Every key is kept: in a built-in group with no group key whose keyed rows share one key that would reach them all, that key moves to the group. The confirmation lists what is kept, vLLM's base URL included. Custom's group settings, the models and groups the user added, and the default and vision references that still apply are kept.

## CLI

- `penguin config provider` was removed. `penguin config model add --provider <group>` without `--model-id` sets or clears the group's connection (`--api-key` / `--clear-api-key`, `--base-url` / `--clear-base-url`, `--client-type` / `--clear-client-type`); it refuses the flags that describe one model, an empty value, a field both set and cleared, and a call that changes nothing. `penguin config model remove --provider <group>` without `--model-id` removes the group's table and keeps its models, and refuses a group with no table. The `--clear-*` flags also clear a model's own value.
- `model add` writes no catalog value: a new entry stores `client_type` and `base_url` only when given, and gets `openai-chat` only as a custom or user-defined entry whose group sets no protocol. `model list` prints the groups' stored connections, then each model's resolved values, marking a group's `(provider)` and an environment key `(env)`. `model remove` drops a user-defined group's connection with its last model.

## Docs and skill

- The models, configuration and CLI pages, in both languages, describe the file as the only source and the resolution model → group → none, the tables a new Project writes, the key-reach rule, the group header and its **Connected** and balance menus, the dialogs' **Details** section and inherit placeholder, **Group settings**, **Add new models** / **Restore defaults**, and the merged CLI.
- The `penguin-config` skill (plugin `agent-development` `2026.10.02.2`) gained a Group connection section for `penguin config model add --provider <group>` without `--model-id`, and its list of groups that take hand-added models names openrouter, tokendance and siliconflow.

## Compatibility

- `penguin config provider set` and `penguin config provider list` are gone: run `penguin config model add --provider <group>` without `--model-id`, with the same flags, and `penguin config model list`, which prints the groups first. Scripts that parse `model list` see a `Groups:` block, then a `Models:` block of resolved values with `(provider)` and `(env)` suffixes and no catalog values.
- API clients that read a model's protocol, endpoint or key status from `ModelInfo.clientType` or `credential` read `effective` instead, whose sources are `model`, `provider` or `none` (`env` for the key), and `providers` for a group's own values.
- The model sync to a machine sends the group connections in `providers` beside every row as stored. A machine on an earlier release ignores `providers` and reads each row as complete: the group keys, base URLs and protocols set here never reach it, so a row that follows its group arrives there without them; and a model added by hand to OpenRouter, TokenDance or SiliconFlow is new to it and refused (`model_not_addable`), which refuses that Project's whole table. Update the machine before syncing.
