# 插件库的安装状态不再在机器连接或答复较慢时来回变化

- **Date:** 2026-10-22
- **Type:** fix
- **Scope:** `web`
- **PR:** [#1289](https://github.com/Prism-Shadow/penguin-harness/pull/1289)

[English](2026-10-22-plugin-market-install-status.md)

添加远程机器后，插件卡片的状态和「N 个 Agent 在用」会来回跳动：每当某台机器的 Agent 进入或离开可达集合，所有 Agent 的已装快照都会被清空并重新读取，本机的也不例外；机器超时的 Agent 被计为「未安装」；查看某台机器时，每次重读 Project 的插件表后，该机器的模块行都会先显示「不在本机」。现在插件库的每次读取都保留上次答复，状态和计数只在新答复确实不同时才变化。

## 细节

- **每个 Agent 的已装插件。** 每个 Agent 的已装列表在其所在服务器上读取，按 Project、机器与 Agent 保存在内存和浏览器存储中：插件库重新打开时先显示上次的结果（刷新页面后，在本机列出其 Agent 时即显示），内容相同的新答复不改变任何显示。Agent 列表变化时只读取新增的 Agent；机器连上、掉线或答复时，不会重新读取本机的 Agent。
- **未知不等于「未安装」。** 尚未答复或读取失败的 Agent 不计入任何一方。不可达机器上的 Agent 按该机器上次的答复计入，状态的悬停提示写明其中有几个按上次看到计入。
- **首次访问。** 在本机答复其 Agent 的已装插件之前，卡片的状态与「在用」位置显示固定宽度的占位条；机器的答复不会拖住它们。
- **管理安装。** 每个 Agent 都保留自己的一行。不可达机器的行置灰并写明原因；已装插件尚未知道的 Agent，其「安装」按钮在答复到达前保持禁用，并写明在等哪台机器。
- **查看的机器。** 机器的模块列表在重新读取期间保留上次答复。为该机器安装模块后，该行保持原状态直到机器答复，再显示机器报告的结果。
- **机器选择器。** 机器不可达时，标题栏的机器选择器保持原位：该机器仍留在列表中并标注「不可达」，正在查看的机器保持原名，标题栏的控件不会左右移动。它在首次绘制时即占好位置，不等本机的 id 读回。
- **插件库、插件索引与 Project 插件表。** 跨访问保留，每次访问重新读取；导入后重新读取，中间不出现占位；重读失败时列表保持不变。
