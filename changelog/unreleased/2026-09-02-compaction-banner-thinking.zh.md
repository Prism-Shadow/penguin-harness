# 压缩行在压缩结果旁流式呈现压缩请求的思考

- **Date:** 2026-09-02
- **Type:** feature
- **Scope:** `core`, `web`, `cli`, `docs`
- **PR:** [#582](https://github.com/Prism-Shadow/penguin-harness/pull/582)

[English](2026-09-02-compaction-banner-thinking.md)

Web App 的压缩行改为按运行完毕的工作分组的形态呈现：组头写明模式并带 wall time，折叠的正文分两节——压缩请求的思考与它产出的摘要——请求运行期间两者都流式写出。

## 细节

- Core 在成对压缩事件之间把压缩请求的思考推上输出流，方式与此前推送摘要文本相同：`partial_thinking` 片段原样转发，没有片段承载内容时改推完整的 `thinking`，二者绝不同时出现。压缩请求沿用模型上下文既有的思考等级，不会为它单独开启思考。Trace 不变。
- Web 端的 reducer 把这段思考累积到进行中的压缩条目上（`thinkingText`，并以 `thinkingStreaming` 记录片段是否仍打开），与摘要并列；历史重建从压缩区间已记录的思考读回同一内容；未完成的压缩把两份草稿一并丢弃。
- 压缩行的正文改为两条上下堆叠的折叠行，各自像思考块一样默认折叠：**思考**（有思考抵达后才出现）与**压缩结果**，都用思考块的正文样式与流式渲染器。组头从 summarize 压缩开始就带折叠箭头，请求运行期间在详情位显示「生成中」提示，实时计时的 wall time 在结束后定格为与运行结束统计行相同的格式。失败的压缩保留一行原因，`discard` 行仍不带折叠箭头。
- CLI 不打印流式思考，一如它此前不打印流式摘要。
- agent-loop 与 Web App 文档描述了压缩行的新形态。
