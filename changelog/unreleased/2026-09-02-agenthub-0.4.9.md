# AgentHub 0.4.9: GPT-5.6 reads a large screenshot instead of rejecting it

- **Date:** 2026-09-02
- **Type:** fix
- **Scope:** `core`, `cli`
- **PR:** [#580](https://github.com/Prism-Shadow/penguin-harness/pull/580)
- **Issue:** [#573](https://github.com/Prism-Shadow/penguin-harness/issues/573)

[中文版](2026-09-02-agenthub-0.4.9.zh.md)

`@prismshadow/agenthub` moved from 0.4.8 to 0.4.9 (agenthub [#194](https://github.com/Prism-Shadow/agenthub/pull/194)). Attaching a large screenshot to a `gpt-5.6-*` session no longer fails with `400 The image you provided requires N patches after processing, exceeding the limit of 30000`: the client reads the image's dimensions from the data URL's header and sends it at `detail: "high"` when it would exceed the limit at the model's default detail, so the API fits it into 2,500 patches and reads it. An image within the limit goes out as before, and no other model is affected.

## Details

- The fix lives in AgentHub's GPT-5.6, OpenAI Responses and OpenAI Chat clients, so the official `gpt-5.6-*` rows and the OpenRouter `openai/gpt-5.6-*` rows are covered alike, for an image in a prompt and in a tool result.
- `pnpm-workspace.yaml`'s `minimumReleaseAgeExclude` entry names 0.4.9 in place of 0.4.8. A bump always lands inside pnpm's release-age gate, so the entry moves with each bump rather than being removed as its earlier note said.
