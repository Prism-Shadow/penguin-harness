# 严重错误提供「[报告问题]」，页面崩溃时显示提示而不是一片空白

- **Date:** 2026-11-02
- **Type:** feature
- **Scope:** `ui`, `web`, `ui-gallery`

[English](2026-11-02-report-issue-entry.md)

属于缺陷、而不是用户自己能解决的错误，现在会提供「[报告问题]」。它打开一份问题报告，可以复制，也可以发到项目的 GitHub bug 表单；表单已预先填好，打开即可提交。页面某部分在显示时崩溃，原处会显示「[出错了]：这部分页面没能显示 [重新加载] [报告问题]」，不再是一片空白。

## 细节

- 严重错误指：
  - 服务端收敛成的 500（错误码 `internal`）或未命名的 5xx；
  - 意料之外的异常；
  - 渲染崩溃。

  服务端已命名的错误不算：校验、登录、权限、不存在、冲突、机器连不上、被代理拦下、网络断开。用户自己停止也不算。这些仍和原来一样。
- 报告为英文，包含发生了什么、页面（路由模式，不含任何 id）、错误与发生时间、PenguinHarness 版本、安装方式与操作系统，最后是错误的调用栈与组件栈。密钥、Token 与家目录路径里的账户名（`/Users/<name>`、`/home/<name>`、`C:\Users\<name>`）会被去掉；在用户复制报告或打开表单之前，任何内容都不会离开应用。
- 出现的位置：
  - 操作因严重错误失败时的错误提示条，这类提示条会停留 10 秒；
  - 对话历史因严重错误读取失败时的加载失败提示，以及对话顶部「更早的对话」那一行。服务端以收敛错误结束的历史读取算严重，反复违反自身帧格式的历史流也算；服务端已命名的错误码不算；
  - 包在页面主体外的崩溃提示（侧栏照常可用，切换到其他页面会重新显示）、每个停靠面板外的崩溃提示（坏掉的面板不影响旁边的对话），以及整个路由外的崩溃提示。
- 对话里请求失败的详情与原来一样，现在由同一套组件构建。
- UI 包提供这套组件：报告与去敏、bug 表单链接、严重错误的判定（`isSeriousError`）、「[报告问题]」（`ReportIssueAction`）、唯一的报告对话框（`ReportHost`），以及崩溃提示（`CrashBoundary`、`CrashNotice`）。错误提示条与 `LoadFailed` 可以带上一份报告。应用在根部一次性设置版本、安装方式与操作系统。
- 组件库新增「报告问题」板块：崩溃提示、带与不带入口的错误提示条、带入口的加载失败提示，以及报告对话框。
