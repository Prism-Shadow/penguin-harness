# 会话被吊销的窗口会自己回到登录页

- **Date:** 2026-09-21
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#819](https://github.com/Prism-Shadow/penguin-harness/pull/819)

[English](2026-09-21-revoked-session-lands-on-login.md)

管理员重置密码时，该用户的登录会话记录确实会被全部删除，与管理页的说明一致；但已经打开着应用的窗口仍停留在原处。SSE 流只在连接建立时鉴权一次，此后再无人复查；Web App 在整个登录期内只保持一条用户事件流，流断了也不向应用报告。于是窗口会一直推送下去，直到读者恰好发起某个请求。现在服务端会结束被吊销用户已打开的流，而失去流的窗口——或者只是重新回到前台的窗口——会主动确认自己是否还处于登录状态。

## 细节

- 服务端按连接建立时鉴权到的用户记录每一条打开中的 SSE 流（`LiveStreamRegistry`，由流自身登记与释放）。`AdminService` 在删除该用户会话记录的同一步里结束其全部流，重置密码与删除账号两条路径都是如此。
- 每条流在 20 秒心跳上复查自己的会话，记录已删除或已过期即结束连接——这是对那些未经注册表就删除会话记录的调用方的兜底。该复查按 token hash 读取记录，且绝不续期，因此一个连着不动的窗口无法靠什么都不做把自己续在登录状态里。
- 以本次启动的本地 API token 鉴权的流（CLI、Agent 自己的工具）没有对应的会话记录，不受影响。
- Web App 的应用级用户事件流在浏览器判定连接彻底断开时探测 `GET /api/me`，与聊天页的 Session 流此前的做法一致；两处现在调用同一个辅助函数，401 会走 api client 的全局处理器，清空当前用户并跳转到登录页。
- 窗口重新获得焦点或变为可见时也会做同一次探测，因此整夜开着的标签页不会滞留在失效页面上；终端列表的轮询也把 401 交给它，而不再默默沿用上一次的列表。并发的探测共用一次请求。
- 服务端 API 参考的 SSE 投递保证一节记下了心跳的会话复查，以及什么会结束一条流。
