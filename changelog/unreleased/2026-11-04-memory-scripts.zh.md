# 记忆可以附带 Agent 反复使用的脚本

- **Date:** 2026-11-04
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `docs`
- **PR:** [#1487](https://github.com/Prism-Shadow/penguin-harness/pull/1487)
- **Breaking:** yes — 记忆导出改为 zip，此次改动之前的服务端会拒绝它

[English](2026-11-04-memory-scripts.md)

一条记忆可以在与其文件同名（去掉 `.md`）的文件夹里附带 Agent 反复使用的程序：`csv-tools.md` 附带 `csv-tools/`。文件夹里的文件数量、语言和层级都不限。记忆正文写明每个文件的用途和运行方式，`MEMORY.md` 里仍只有这条记忆的一行。Agent 用文件工具写下这些文件，经 `exec_command` 运行，受该 Session 的沙盒、审批模式与命令策略约束。没有新增工具；没有文件夹的记忆行为不变。

## 提示词与内核

- 默认记忆提示词提到事实可附带的脚本，并新增 **Scripts:** 段落：模型原本要重写的程序由它所服务的事实保存在该事实的文件夹里，只依赖解释器。由事实自己的正文列出每个文件，写明用途、运行方式并附相对链接；`MEMORY.md` 从不列出这些文件，每个事实仍只占一行。脚本经解释器按绝对路径运行（文件没有执行位），文件夹随事实一起删除。密钥放在 vault 里，运行本 Session 没写过的脚本之前先读它。
- `KERNEL_VERSION` 改为 `2026-11-10`，记忆标签页原来的默认值记为已被取代。已有 Agent 通过 **更新内核** 采用这段文字；改动过的记忆标签页保留原文。
- 采用新提示词后，该 Agent 每个进行中的对话会在下一次上下文轮换时重新读取一次缓存的提示词前缀。

## 服务端

- `GET …/memory/scopes/:key/files` 为每个主题给出 `files`：其文件夹中的全部文件，各带在作用域中的路径、大小和日期。`orphanFiles` 列出旁边没有同名主题的文件夹中的文件，磁盘上的内容不会被隐藏。
- 文件路由改为接受路径：`GET` 与 `DELETE …/files/<folder>/<path>` 经与主题相同的路由读取、删除一个附带的文件。读取至多返回 512 KB 的 UTF-8 文本：超过时返回 413 `memory_file_too_large`，不是文本时返回 415 `memory_file_not_text`。删除时一并删去因此变空的文件夹。删除主题会连同其文件夹一起删除。
- 文件夹或其中的文件若是符号链接，绝不跟随：经由它的内容不列出、不读取、不删除；删除主题时也不碰链接指向的目标。
- `GET …/export` 返回作用域文件夹的 zip：`MEMORY.md`、全部主题和各文件夹中的文件都在根下，原样保存。它沿用 Skill 归档的检查与上限（1,000 个文件、单个 5 MB、总计 20 MB；超出时返回 413 `memory_too_large`）。
- `POST …/import` 以 `dataBase64` 接收这样的 zip。只要有一个条目不是记忆文件、越出作用域、以点开头、是链接，或在忽略大小写时与另一个同名，整个 zip 都被拒绝。一条记忆是主题及其文件夹，作为整体迁移：`overwrite` 一并替换两者，`replace` 还会删除 zip 中没有的记忆，没有主题的文件夹自成一条记忆。要求确认的 409 在 `details` 中列出受影响的记忆。`MEMORY.md` 只会增删主题行。
- 记忆文件夹的位置或通往其某个文件的路径上有非目录时，导入在写入任何内容之前以 409 `memory_folder_not_a_directory` 拒绝。
- 早先版本导出的 JSON 文档照常可以导入（`payload`），见[向后兼容](2026-11-04-backward-compatibility.zh.md)。

## Web App

- 记忆标签页中，附带文件的记忆在行上显示回形针和文件数。查看时先显示 Markdown，再列出文件及其路径、大小和日期。**查看** 以只读、带行号的方式打开文件，**返回** 回到记忆；**删除** 经确认后删除文件。删除记忆时，确认框写明会带走几个文件。文件没有 **编辑**。
- 分组在 **不属于任何记忆的文件** 下列出旁边没有同名记忆的文件夹中的文件。
- **导出** 下载 zip；**导入** 接受 zip 或早先版本导出的 JSON 文件，会覆盖或删除内容时先询问，列出服务端给出的受影响记忆。
- 对话的记忆面板与记忆变更卡片把对话写下的文件按路径显示在附带它的记忆之下，不再当作已删除而丢掉。

## 兼容性

- 记忆导出改为 zip，此次改动之前的服务端无法导入。请先升级那台服务端。
- `GET …/export` 返回 zip 而不是 JSON 文档，读取该文档的客户端改为读取 zip 中的文件。`POST …/import` 仍以 `payload` 接受 JSON 文档。
