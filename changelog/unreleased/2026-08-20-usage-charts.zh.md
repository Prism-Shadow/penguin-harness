# 用量图表重构为带范围与精度控件的时间序列

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `web`, `server`, `docs`
- **PR:** [#371](https://github.com/Prism-Shadow/penguin-harness/pull/371)
- **Breaking:** yes — `GET /usage` 不再返回 `trend`、`byAgent` 与 `success`，`success` 携带的分状态失败明细一并移除。

[English](2026-08-20-usage-charts.md)

围绕同一条时间轴重构了成本中心的图表。页面新增日期范围档位——「最近一小时」「最近一天」滑动窗口、日历式近 7 / 30 / 90 天（默认近 7 天）、或自定义起止日期。序列以何种精度绘制完全由范围决定——最近一小时按分钟，最近一天按小时，日历档位按天，跨度很长的自定义范围按周或按月——因此不再有第二个需要与之保持一致的控件。所有图表都按所选范围绘制：

- 占比饼图与各模型进度条被并排的**两张请求与成功率图**取代：一张按 Agent 拆分，一张按模型拆分。每张图中，单个时间桶的请求数是一根按对象分段堆叠的柱、走左侧计数轴，每个对象的成功率各自成一条虚线、走右侧 0–100% 轴并沿用该对象的色相——虚线与 Token 图的命中率曲线同理，用来标明这条线属于右轴——图例置于图下方。两个维度同屏可见——不再有维度切换，两张图也都不以合计视图开场。请求数最高的四个对象各占一个经色觉无障碍校验的色相，其余折叠为一条中性色序列，标签写明折叠了多少个。单独突出某个对象有三种方式，都会淡出其余：悬停它的某段柱、悬停它的成功率折线、或悬停它的图例项。折线绘制在柱子上方，响应指针的层级也在柱子上方，因此不会被高柱盖住。
- Token 图保留三段堆叠柱，并新增缓存命中率虚线，绘制在柱子前方、走独立的右侧 0–100% 轴。悬停列内任意位置即给出整桶信息（三段 Token 数与命中率），悬停单段则突出该段，悬停折线则突出折线。柱宽自适应卡片宽度，不再横向滚动。
- 成本保持折线带点（每个数据点一个圆点，外加面积填充），按所选范围绘制。

页面上所有折线都在数据点之间直连、不做任何平滑，且线宽统一——不会因为哪条线后写就画得更粗。图表不出现滚动条；图表区上方只有 Agent、模型与范围三个全局控件。异常面板去掉了滚动容器——高度只由分页限制，服务端返回的首页从 20 行缩减为 10 行。

## 空桶怎么处理

「空」在这里有两种含义，各自的答案也不同。

**没有比率的桶，是画出来的，不是读出来的。** 某个对象在某个桶里一次请求都没发，就没有成功率可言；某个桶没有缓存流量，也就没有命中率。折线沿坐标轴顶部横穿过去，只为让线保持连续。这只是关于线形的绘制选择，仅此而已——悬停表格在同一个桶显示「—」，绝不显示百分比。真正的 0% 仍然显示 0%：发了请求且全部失败，那是数据本身，不是数据的空缺。

**什么都没记录的桶，不画。** 无论选了多大范围，每张图都只画有值的区间、从左往右依次排开——这正是范围控件出现之前的形态，也是一段长期空闲不会被画成一条贴地直线的原因。跳过之处横轴上画有断轴标记，被压缩的横轴因此不会被读成连续的。

空与不空按桶判断、绝不按单个对象判断：只要有任何对象在这个区间跑过，桶就保留，当时空闲的对象在该列停在 0、比率显示「—」。正因为只有这一条规则，四张图才能共用同一次压缩、共用同一条横轴——各对象的计数与序列按同一份下标清单重排到保留下来的桶上，某个对象的历史不会错位到别的区间去。

## 细节

- `GET /usage` 新增可选查询参数 `granularity`（`minute` / `hour` / `day` / `week` / `month`，默认 `day`）与 `fromTs`/`toTs`（ISO 时间戳界定的滑动窗口，须成对给出；`minute` 精度必需，并把所有按范围统计的聚合细化到时刻级）。响应新增 `granularity`、`series`（零值补齐的时间桶，携带 Token 分项、成本、请求数与每桶成功数）、`byAgentSeries` 与 `byModelSeries`（与 `series` 按下标对齐的各对象请求与成功计数；各自忽略本维度的过滤条件，因此图表始终呈现该维度的完整拆分）。`trend`、`byAgent` 与 `success` 连同其背后的三条查询一并移除，该路由不再聚合固定 30 天窗口、各 Agent 调用次数与各模型分状态明细——这些都已无处展示。其余字段保持不变。范围 × 精度过大、会产生超长序列的组合返回 400。
- 分钟与小时桶按服务器本地时钟划分（与既有按日聚合键使用同一时区）；周桶以 ISO 周的周一为键，月桶以 `yyyy-mm` 为键。

## 兼容性

`GET /usage` 移除了三个响应字段。对应的数据现在在这里取：

- `trend`——最近 30 天、每天一个点的 Token 分项与成本。`series` 给出同样的点，未指定 `from`/`to` 时默认就是这个窗口，并额外带上每点的 `requests`、`completed` 与 `denominator`。
- `byAgent`——各 Agent 的请求数即 `byAgentSeries[].requests` 之和；各 Agent 的 Token 总量改用 `?groupBy=agent`，其 `groups` 行带有 `total`、`requests` 与 `cost`。
- `success`——某模型的成功请求数与其排除 aborted 的分母，分别是 `byModelSeries[].completed` 与 `byModelSeries[].denominator` 之和。分状态计数（`aborted`、`failed`、`timeout`、`malformed`）没有替代品：此前无处展示，失败诊断由 `errors` 面板承担，它按 source 与 code 记录每一次失败。

Web App 不读取这三个字段，因此本次不含客户端改动。直接消费该 HTTP 接口的第三方需要改用上述字段。
