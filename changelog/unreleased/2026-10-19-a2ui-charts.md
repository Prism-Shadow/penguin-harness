# A2UI charts: basic charts in a reply, and the widgets rebuilt on them

- **Date:** 2026-10-19
- **Type:** feature
- **Scope:** `core`, `ui`, `web`, `ui-gallery`, `skills`, `docs`
- **PR:** [#1225](https://github.com/Prism-Shadow/penguin-harness/pull/1225), [#1227](https://github.com/Prism-Shadow/penguin-harness/pull/1227)

[中文版](2026-10-19-a2ui-charts.zh.md)

A reply can carry a basic chart drawn from data (line, area, bar, pie, scatter, histogram or gauge) and a system-resource board. The data widgets are now built on the same charts. A metrics tile is a gauge, the weather card's next hours are a line chart and its days are range bars, and the resource board is gauge tiles, disk bars and a network line. The model uses a basic chart for data of any shape, or a composite for data of a known shape.

## Catalog

- `chart` with `kind` `line`, `area` (optionally stacked), `bar` (grouped, stacked or horizontal), `pie` (optionally a donut), `scatter`, `histogram` and `gauge`. All kinds share one data model: categories × 1–6 series, units on the axes (`xUnit`, `yUnit`), axis names, an optional value range and decimals. A histogram has bin edges in place of categories, and a scatter has `[x, y]` points in place of values. A gauge's `item` is one metrics item, read and printed exactly as in a `metrics` block.
- `resources`: one machine's CPU with its history and cores, memory with its history, swap, 1–6 disks, the network's receive and send rates, the load averages and the uptime, with at least one section. The app colours it by fixed thresholds: CPU, memory and swap at 80 % and 95 %, a disk at 85 % and 95 %, the load at one and two per core.
- New checker codes: `length_mismatch` (error); `chart_many_series`, `chart_many_categories`, `pie_many_slices` and `scatter_many_points` (warnings). A field the kind does not read is an `ignored_field` warning and is dropped. `no_as_of` also covers `resources`; a chart need not be a snapshot.
- As text (CLI, messaging channels), a chart prints a bullet per category or bin up to 20, and one summary line per series past that. A pie prints each slice's share, a scatter each series' extents and a gauge its metrics line. A resources board prints one bullet per reading.
- `metrics`, `weather`, `clock` and `countdown` keep every field.

## Rendering

- Basic chart components in the UI package: `BarChart` (grouped, stacked, histogram), `HBarChart` (stacked rows, range rows), `LineChart` (line or area, stacked, gaps), `ScatterChart` (both axes fit the data unless the spec sets a range), `PieChart` and `Gauge`, drawn through the existing chart primitives and theme colours.
- The chart block draws every kind in a reply, with units on the axes, a legend for two or more series, and a hover bubble on bar, line, area and histogram charts.
- The metrics tile is a `Gauge` with its sparkline and progress bar, and a `chart` of kind `gauge` draws the same tile. The weather card's hourly line is a `LineChart`, its daily rows are `HBarChart` range rows, and the resources block puts gauge tiles, disk bars and a network line together.
- The gallery's charts board has a Basic charts part with each chart, and the A2UI reply board shows a chart and a resources block.

## Skill and docs

- The `a2ui` skill (version `2026.10.19.2`) teaches `chart` and `resources`. It adds their catalog rows, the rule for choosing a composite when the data has its shape and a chart when it does not, a chart data model section and one worked chart example. The `metrics` docs drop the system-snapshot example.
- `scripts/sysinfo.mjs` prints a `resources` block: CPU and memory with their history, swap and network on Linux, every disk named by a repeated `--disk`, the load and the uptime. It no longer prints `metrics`, and `--lang` is gone because the block holds numbers only.
- Chat › Rich output blocks describes Chart and System resources, and the Skills & Plugins row names the charts.
