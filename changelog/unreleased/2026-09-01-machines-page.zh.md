# Machines 页面，以及把工作区开在另一台机器上

- **Date:** 2026-09-01
- **Type:** feature
- **Scope:** `web`
- **PR:** [#448](https://github.com/Prism-Shadow/penguin-harness/pull/448)

[English](2026-09-01-machines-page.md)

驱动这一切的页面：安装、连接、重启、断开，日志里是对面自己的原话。机器也可以在工作区选择器里被选中，因此可以在另一台机器的某个目录下开一个 Session。

**暂时还进不去。** 侧边栏入口、路由与选择器里的机器一行被刻意留住，等功能稳定之后由一个单独的改动一次性放开。这里落地的是页面本身。

## 窗口不会整个搬走

点名了某台机器的调用会被改写成 `/server/<machineId>/api/…`，由本地服务端转发过去。这里刻意**没有整窗口的「当前服务器」模式**。它一度存在过，后来被移除了：把整个窗口指向另一台机器，会让每一个页面都落到隧道后面，`/api/me` 也不例外——于是隧道一断，应用连「有没有人登录」都答不上来，而用来退出这个状态的控件，恰恰渲染在那个永远没能挂载的布局里面。藏在故障物后面的逃生门不是逃生门。

改为在真正与那台机器有关的调用上点名它，就不会这样失败：隧道死了，坏掉的正好是需要它的那个请求，而且它会说出来。一条字符串规则同时管住 `fetch` 与 SSE 订阅。

## 逐步拉长的探测节奏

每次探测对每台已安装的机器都是一次 ssh 往返，因此当答案不再变化时，间隔会逐步拉长：15 秒、30 秒、45 秒、一分钟、两分钟、三分钟……直到十分钟。**任何变化都会把它拉回第一档**——服务端刚刚挂掉、或者安装刚刚完成，正是接下来几个答案最要紧的时刻。

时间戳刻意不计入「是否变化」：每次探测都会改动它，把它算进去会让间隔永远停在 15 秒，而这正是这个指纹函数存在的理由。

节奏活在页面里，不在服务端。放在那边的定时器会在最后一个标签页关掉之后仍然不停地拉起 ssh；而在没有任何机器安装过时，根本不会有定时器运行。

## 在机器上选工作区

工作区是某台机器**上**的一个目录，所以只有此刻文件系统可达的机器才能被浏览：本机永远可以，其余需要一条活着的转发。每一台已安装的机器都**照样列出**，不可达的置灰并在行上写明原因——一个悄悄略去答案的列表，和一个坏掉的功能无法区分。

机器以自身的 id 标识、以 ssh 别名显示，因此改了名的主机仍然保得住它的工作区。

## 行上说了什么

安装与纳入是同一个按钮：站在人的角度，两者回答的都是「让这台机器在这里可用」，只不过其中一个要花一次传输。机器那一行把服务端报出的三个事实分开呈现，而不是揉在一起——本侧持有的转发、对它服务端的最近一次探测、以及它的 API 究竟有没有应答——因为「对着已死服务端的活转发被读成已连接」，正是整个功能围绕着重建的那个死循环。
