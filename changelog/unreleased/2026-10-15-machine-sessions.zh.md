# 机器上的会话改读那台机器，那里原有的会话按 CLI 任务归档

- **Date:** 2026-10-15
- **Type:** feature
- **Scope:** `server`, `web`, `ui`
- **PR:** [#1155](https://github.com/Prism-Shadow/penguin-harness/pull/1155)

[English](2026-10-15-machine-sessions.md)

在机器上运行的对话现在读取那台机器的记忆与模型；已归档对话页为管理员列出所用机器上的已归档对话，
每行都带来源胶囊；本服务端采用一台机器时那里已有的会话，按 CLI 任务归档。

## 细节

- 机器上的会话，记忆面板列出并打开那台机器上该 Agent 的记忆，「管理」链接进入它在那台机器上的设置页（`?machine=`）。
- 新建对话的工作区在某台机器上时，模型列表、缺省模型以及 Agent 的思考强度与技能都取那台机器，选回本机工作区即换回；
  机器上的对话切换模型与计价同样按那台机器的模型列表，思考强度与上下文压缩阈值读写那台机器上该 Agent 的设置，
  「打开 Agent 设置」进入它在那台机器上的设置页。
- 侧栏中机器上的工作区分组在栏宽不够时先截断名称，`[SSH: <别名>]` 始终可见（`GroupHeader` 新增 `qualifier`）。
- 向刚装好的机器首次下发配置时，等它建好 `default_project` 再下发，不再以 `project_exists` 失败，
  本服务端的模型在第一次连接时即到达那台机器。
- 已归档对话页的每一行都以胶囊写明来源，用户的对话也带。管理员另可见其 Project 所用、已连接的机器上的已归档对话，
  机器上的组标出 `[SSH: <别名>]`，取消归档与删除在那台机器上执行，读取不到的机器在列表上方写明；侧栏中机器上的会话重新提供「归档」。
- 本服务端记下采用一台机器的时刻（`machines.adopted_at`，迁移版本 19，首次记下那台机器时写入，别名换成另一台机器时重写），并在代理与自身的每次调用中
  以 `X-Penguin-Adopted-At` 带上。那台机器把在此之前创建的、来源为用户或尚未解析的会话，在这次读取中按来源 `cli` 处理，
  因而显示为已归档、带 CLI 胶囊，取消归档后留在侧栏。两边存储的数据都不改写，那台机器自己的界面与 CLI 看到的不变。
  此前已记录的机器不补记这个时刻，上面的会话一律保持原样，之后的连接与同步也不会补记。
