# Web App 显示 Agent 上插件的服务端模块，并可启用或请求启用

- **Date:** 2026-11-19
- **Type:** feature
- **Scope:** `web`, `ui-gallery`
- **PR:** [#1638](https://github.com/Prism-Shadow/penguin-harness/pull/1638)

[English](2026-11-19-plugin-module-on-agent-install-web.md)

Web App 跟上服务端对同时带服务端模块的插件的新规则（[PRFC-0031](https://github.com/Prism-Shadow/penguin-harness-design/pull/479)，服务端见 [#1636](https://github.com/Prism-Shadow/penguin-harness/pull/1636)）：安装的浮层说明模块如何处理；Agent 的插件行标出未在该 Agent 所在服务端运行的模块，并给出查看者能做的操作；管理员在系统设置的插件页处理成员的请求。

## 细节

- Agent 设置的「插件」子页面：Agent 带有的插件若其模块未运行，状态之后另有一个标记——未启用、等待管理员启用、管理员已停用、加载失败或待重启，悬停说明原因。模块未启用时行尾另有「启用服务端模块」（内置插件，或查看者是管理员）或「请求管理员启用」；等待中或已停用的模块，管理员也可在此启用。详情「在这个 Agent 上」一节另有「服务端模块」一行，状态（含运行中）与操作同列表行。此前已带有这类插件的 Agent 显示该标记与按钮，不会自动启用任何模块。
- 插件页与 Agent 设置里安装后的浮层另说明模块如何处理：已启用、已向管理员发出请求、管理员已停用，或未能启动。
- 机器上的 Agent 以 `skipModules` 安装，因为那台机器的插件列表由本服务端（hub）记录。机器报告模块未启用、且它自己的构建自带该包时，本服务端用现有的安装接口为那台机器列入该模块，并立即与三秒后各重新读取一次该 Agent；否则浮层提示在插件页为那台机器安装。目标模式的安装与导入对话框安装移植 Skill 也走同一路径。
- 系统设置的插件页在分隔线之下、服务器全局的插件选项之首新增「服务端模块请求」一节，随机器下拉切换。每条一行：插件、状态、Project、请求者与时间。待处理的为「启用」「拒绝」，所属 Project 已删除时只有「拒绝」；已启用的标出启用方式（内置自动、管理员、已批准）并可「停用」（先确认）；已拒绝的可「启用」。停用后若仍有 Project 的共享表列出该模块而使它继续运行，浮层写明这些 Project。
- 插件页在不兼容插件提示旁向管理员显示「N 个服务端模块等待启用」并附「查看」；侧栏插件入口的提示点同样计入这些请求。带服务端模块的插件卡片在请求未决或已被拒绝、且模块未运行时显示「待启用」或「已停用」。
- 收到 `plugin_modules_changed` 时，Agent 的插件页、插件页与请求列表重新读取，不弹浮层。
- 服务端模块安装与移除确认、以及导入对话框里的小字改为：重新装载服务器插件，正在运行的 Agent 不受影响。
- ui-gallery 的模拟接口覆盖三个新接口，并在 Agent 的插件与已装插件的答复中带上 `modules`。
