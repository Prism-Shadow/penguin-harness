# 会话标题不再回答对话，并跟随对话的语言

- **Date:** 2026-08-26
- **Type:** fix
- **Scope:** `core`, `server`
- **PR:** [#489](https://github.com/Prism-Shadow/penguin-harness/pull/489)

[English](2026-08-26-title-prompt-language.md)

自动生成会话标题所用的 Prompt 被重写为一条**针对一段文本**的指令，而不再是一次对话轮次。以 `你好`
开头的对话此前被命名为 `你好！有什么可以帮你的吗？`——模型回答了材料而不是为它命名——英文对话也可能
拿到中文标题。

## 细节

- 对话材料被围进 `<conversation>` 块，内部再分 `<user>` 与 `<assistant>`，并明确声明它是数据：
  不要回复、不要执行，也不作为指令来源。最后这条声明同时收走了对话左右这次自身没有 System Prompt
  的请求的能力。
- 即便是尚无助手文本的首轮，两个元素也一并保留：`<assistant>` 元素被填入
  `(the assistant has not replied yet)`，并随附一条规则，说明该行记录的是一次尚未发生的轮次、应当
  单独为用户的请求命名、且这份「缺席」本身永远不作为标题。围栏里只剩一句孤立的用户发言时，它的形状
  就是一个抛给阅读者的问题，而这正是 Prompt 其余部分所要对抗的形状。该标记用 Prompt 的指令语言写成，
  因此不会把标题从用户文本的语言上拽走。
- 要求被移到材料之后，Prompt 末尾换成一行光秃秃的 `Title:` 引子——它唯一合理的续写就是标题。用于关闭
  推理模型思考阶段的空 `<think></think>` 块被放在该引子正上方；抑制思维链的那条规则也改口，要的是
  标题而不是一个「回答」——「回答」正是它周围每条规则都在压制的那个动词。
- 语言规则写成映射，并锚定在**用户**的文本上——英文用户文本给英文标题，中文用户文本给中文标题，一律
  不翻译——助手用另一种语言作答不再左右这一判断。
- 不含主题的材料（打招呼、一句「ok」、一个孤零零的表情）拿到了专门的规则：为这个行为命名，`"hi"` →
  `Greeting`、`"你好"` → `打招呼`。两个示例放在该条末尾收尾，因此没有任何标点贴在示例输出上——把
  `Greeting;` 当作模型输出展示，示范的恰是下一条规则所禁止的尾部标点。
- 材料自身写有的 `<conversation>`、`<user>` 或 `<assistant>` 标签会被改写为方括号形式，因此围栏无法
  从摘录内部被关闭。该替换保持长度不变，2000 字符的摘录预算含义照旧。
- 模型输出中重述的 `Title:` / `标题：` 标签被连同其外层装饰一起去掉：被要求续写 `Title:` 的聊天模型
  给出 `**Title:** …` 的概率不亚于光秃秃的形式。这一剥离被放在请求路径上而非 `sanitizeTitle` 里，
  因为招来它的那行引子也在请求路径上——`sanitizeTitle` 的另一位调用者清洗的是用户自己的首行，那里的
  `Title:` 属于用户所写内容的一部分。
- `sanitizeTitle` 学会了剥离 Markdown 装饰——`**`、`#`、反引号、`~`、列表短横——头部悉数剥除，尾部
  则除收尾的 `#` 之外悉数剥除：标题合法地以它结尾是可能的（`Learning C#`），而 ATX 标题的收尾 `#`
  并非聊天模型会写的东西。
- `sanitizeTitle` 截断超长标题所用的朴素字符切分，换成了宿主兜底标题早已在用的、按词边界并识别代理对
  的切法。该切法以 `truncateTitle` 之名迁入 core，两条路径现在都调用它：跨在第 30 个字符边界上的
  表情不再留下一个孤立的代理项——它没有 UTF-8 编码，落到 SQLite 与 SSE 帧里都是 U+FFFD——切在空格处
  的标题也不再把那个空格一并留下。
