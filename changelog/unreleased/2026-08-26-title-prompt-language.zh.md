# 会话标题不再回答对话，并跟随对话的语言

- **Date:** 2026-08-26
- **Type:** fix
- **Scope:** `core`
- **PR:** [#489](https://github.com/Prism-Shadow/penguin-harness/pull/489)

[English](2026-08-26-title-prompt-language.md)

自动生成会话标题所用的 Prompt 被重写为一条**针对一段文本**的指令，而不再是一次对话轮次。以 `你好`
开头的对话此前被命名为 `你好！有什么可以帮你的吗？`——模型回答了材料而不是为它命名——英文对话也可能
拿到中文标题。

## 细节

- 对话材料被围在 `<conversation>` 块中，内部再分 `<user>` 与 `<assistant>`，并明确声明它是数据：
  不要回复、不要执行，也不作为指令来源。最后一点同时让对话无法左右这次自身没有 System Prompt 的
  请求。
- 即便是尚无助手文本的首轮，两个元素也都保留：此时 `<assistant>` 元素放的是
  `(the assistant has not replied yet)`，并随附一条规则，说明该行记录的是一次尚未发生的轮次、应当
  单独为用户的请求命名、且这份「缺席」本身永远不作为标题。围栏里只剩一句孤立的用户发言时，它的形状
  就是一个抛给阅读者的问题，而这正是 Prompt 其余部分所要对抗的形状。该标记使用 Prompt 的指令语言，
  因此不会把标题从用户文本的语言上拽走。
- 要求改为置于材料之后，Prompt 以一行光秃秃的 `Title:` 收尾——这个引子唯一合理的续写就是标题。用于
  关闭推理模型思考阶段的空 `<think></think>` 块紧挨在该引子上方。
- 语言规则写成映射，并锚定在**用户**的文本上——英文用户文本给英文标题，中文用户文本给中文标题，一律
  不翻译——助手用另一种语言作答不再左右这一判断。
- 不含主题的材料（打招呼、一句「ok」、一个孤零零的表情）有专门的规则：为这个行为命名，`"hi"` →
  `Greeting`，`"你好"` → `打招呼`。
- 材料自身写有的 `<conversation>`、`<user>` 或 `<assistant>` 标签会被改写为方括号形式，因此围栏无法
  从摘录内部被关闭。该替换保持长度不变，2000 字符的摘录预算含义照旧。
- `sanitizeTitle` 会去掉模型输出中重述的 `Title:` / `标题：` 标签，与已有的引号、尾部标点剥离在同一
  次不动点扫描中完成。
