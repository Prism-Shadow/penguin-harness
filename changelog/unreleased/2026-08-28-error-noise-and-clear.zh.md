# QQ 网关断开不再计为缺陷，错误表新增清空操作

- **Date:** 2026-08-28
- **Type:** feature
- **Scope:** `server`, `web`

[English](2026-08-28-error-noise-and-clear.md)

对成本中心错误面板的两项改动。QQ 网关被平台关闭、而连接器随即恢复的连接，不再计入「需要人处理」的错误；
Project owner 可以清空面板当前展示的错误表。

## 网关关闭按连接器的后续行为分类

QQ 网关会话现在以 `MessagingConnectionClosedError` 上报关闭，其中携带平台的 close code，以及下一次
握手能否在无人改动任何东西的情况下恢复连接。`error-kind.ts` 读取这个判定，而不读消息文本——计数因此不
依赖平台如何措辞自己的关闭。

- `expected`：close code 4009（平台让长连接过期，该关闭仍可 resume，会话据 seq 重放）与 4900–4913
  内部错误段，其文档给出的处理正是会话已在执行的重新 identify。
- `unexpected`，保持不变：4006 与 4007，只能靠全新 identify 恢复，其间到达的消息会丢失；4004、4014
  以及其他在凭据或控制台设置改动前会一模一样重复的拒绝；4914 与 4915，会话就此彻底停止；以及本就不属于
  平台关闭的失败——未完成的握手、停止回应心跳的网关。

已存储的记录保留写入时的 `kind`；该分类只作用于此后记录的错误。

## 清空错误表

`DELETE /api/projects/:projectId/usage/errors` 清空面板当前筛选下的错误表，面板底栏在确认弹窗之后提供
该操作。

- **范围**：当前选中的时间范围与 Agent，即面板读取所用的同一筛选。范围外的记录保留；确认弹窗会说明时间
  范围、选中的 Agent（若有）以及将删除多少条。
- **权限**：仅 Project owner，与删除 Agent 对错误记录已适用的规则一致。成员可以查看面板，删除会得到
  403；面板也不会向成员展示该操作。
- 未归属到 Project 的错误——登录失败、进程崩溃——不在任何一次清空的范围内，无论发起者是谁。它们不属于
  任何 Project，且会出现在每个 Project 的管理员视图中，因此删除的触及范围严格小于任何调用者的读取范围。
- `ErrorsRepo.deleteFiltered` 的 `WHERE` 由读取所用的同一子句构建，因此一次清空无法选中匹配读取本不会
  返回的行。

被删除的记录不可恢复：错误记录别处没有副本，也没有任何机制能还原它。
