# 从侧边栏打开 Agent 的应用，取代对话页的标签条

- **Date:** 2026-11-20
- **Type:** feature
- **Scope:** `web`, `ui`, `ui-gallery`, `server`

[English](2026-11-20-sidebar-apps.md)

侧边栏在三项导航之下、会话列表之上新增「应用」一组。它列出页面所在 Agent 的应用：当前对话自己的 Agent（对话在机器上时为那台机器上的它），否则为当前 Agent；其他仍在窗口中运行的应用排在其后，标「运行中」。点击行即在主区以应用中心的窗口打开该应用，关闭或最小化窗口回到点击时所在的页面。对话页上方的工作台标签条删除：对话页只有对话本身，此前打开标签页的地方都改为打开这个窗口。

## 细节

- **应用组。** 行为应用图标与名称，带应用中心图块的同一组标记：运行中、构建中（构建完成前不能打开，已在运行的除外）与加载失败；窗口在前时该行选中。行菜单为「打开」「从侧边栏移除」（即工作台行的「展示到侧边栏」，只对该设置列出的行提供）与「在 Agent 设置中查看」。组头可折叠，按浏览器记忆；组头的「管理应用」进入该 Agent 设置的「工作台」子页面。Agent 没有显示在侧栏的应用、也没有运行中的应用时整组不显示。切换 Agent 与服务端推送工作台消息时重新读取 `GET …/workbenches?view=sidebar`，已离开的 Agent 晚到的答复不再采用；不支持该清单的较旧服务端改读完整列表。
- **应用窗口。** 除应用中心外，侧边栏、工作台行的「打开」与整页的退出也都打开它。有两个及以上页面的 Workbench 在窗口标题栏切换页面；页面自己请求占满应用时打开整页。关闭回到打开窗口前的页面，浏览器不支持 Navigation API 时同样如此。工作台被移除时应用结束；仅仅不再出现在某个列表里的应用继续运行，因此从侧边栏打开、未显示在应用中心的应用在进入应用中心后仍在运行。
- **整页的退出**：从图块打开的回到应用中心的网格或分组，其余回到该应用的窗口并停在整页所示的页面，应用重新启动。命令面板中这一项为「退出全屏（回到应用窗口）」。
- **应用中心图块的菜单**新增可勾选的「在侧边栏显示」，与工作台行的同名开关是同一个设置。每个快捷入口以 `AppCenterShortcut.showInSidebar` 携带该值，不报告该项的服务端不显示这一行。
- **删除**：对话模块的 `sessionTabs` 槽及其贡献、标签条及其 hook、框架上的版本栏（重新加载、历史版本与移除仍在工作台行上），以及 dock 快捷键从标签页切回对话的处理。没有页面的 Workbench 的加载提示改在它的工作台行上显示，不再显示在对话上方。Workbench 清单仍以 `WebModule.sessionTabs` 声明自己的页面。
- **共享 UI 包**：新增应用列表的行 `AppRow` 及其画廊面板；窗口面板新增带页面切换的标题栏。
