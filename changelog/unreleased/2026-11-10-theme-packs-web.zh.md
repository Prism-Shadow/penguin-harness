# 外观页列出、导入、导出与移除主题包，应用加载导入的主题包时不出现半套样式的一帧

- **Date:** 2026-11-10
- **Type:** feat
- **Scope:** `web`
- **PR:** [#1530](https://github.com/Prism-Shadow/penguin-harness/pull/1530)

[English](2026-11-10-theme-packs-web.md)

Web App 接上了管理员在本服务器导入的主题包：主题选择在内置主题包之后列出它们，外观页列出全部主题包并可导出、导入与移除，切到导入的包时先等它的样式表加载完成。

## 加载主题包

- 登录时应用与账户偏好一同读取服务器的主题包（`GET /api/themes`），存入 `penguin.themePacks`，首帧脚本从这份缓存链接已存的主题包。打开外观页、服务器告知列表有变（`themes_changed`）以及事件流丢失事件之后都会再读一次。同一时刻只有一个读取在途，答复未变时界面不动，读取失败时保留上一份列表。
- 存储的导入包在缓存里有它、且主题 API 为本构建所支持时读作它本身，它的强调色预设一并保留；其余情况仍读作白领，存储值一概不改写。
- 切到导入的包时先挂它的样式表链接，链接加载完成后才写 `data-theme` 与 `data-theme-base`；切走时先写属性，下一次绘制之后再移除链接。在另一次切换开始之后才加载完的链接直接丢弃。首帧脚本写入的链接已持有样式表时直接沿用，否则重新请求一次。
- 样式表加载失败时界面保持原先显示的主题（打开页面时即为该包的则为白领），存储的选择不变；「主题」一行写明当前显示的是哪个主题，并给出「重试」。
- 正在显示的主题包被服务器移除时，应用回到白领并移除链接；再次列出时自动换回。被替换的包先加载新的样式表，再移除旧的。
- Workbench 应用框得到导入包的样式表链接，以及与应用根元素一致的 id 与强调色；应用框在应用根元素实际变化之后重新套用主题，而不是在选择器变化时。

## 外观页

- 「主题」一行先列内置主题包，再按导入次序列出导入的包。只有内置主题时仍是分段控件；服务器提供了导入的包时改为下拉框，因为包名由作者自定，随包增多的分段在手机宽度下会溢出这一行。
- 页末新增「主题包」分组，每个主题包一行：当前明暗下的三枚色样、名称（悬停显示 id）、版本与它基于什么。为更新主题 API 写的包置灰，并标出需要更新的版本。任何账号都可以导出任何主题包，内置的也一样；管理员可在确认后移除导入的包，也可导入不超过 16 MB 的 `.zip`，导入的 id 已安装时先确认是否替换。成员看到一行说明：只有管理员可以导入或移除。导入被拒时写明校验停在哪个文件的哪一行哪一列、原因是什么。
- 压缩包下载从 `features/agents` 移到 `lib/archive-download.ts`，设置页也能使用。
