# AgentHub 0.4.5：client 认不出的输出不再中断整条流

- **Date:** 2026-08-20
- **Type:** fix
- **Scope:** `core`, `cli`, `web`
- **PR:** [#360](https://github.com/Prism-Shadow/penguin-harness/pull/360)

[English](2026-08-20-agenthub-0.4.5.md)

`@prismshadow/agenthub` 从 0.4.4 升到 0.4.5。新版本会跳过 client 认不出的流式输出，而不是让整个请求失败（agenthub [#181](https://github.com/Prism-Shadow/agenthub/pull/181)）。

架在模型 API 前面的网关会在长时间生成期间注入自己的帧。0.4.3 只让每个协议家族认识了它当时见过的那种心跳拼法——OpenAI Responses 的 `keepalive`、Anthropic Messages 的 `ping`——因此任一拼法串到另一种协议上，仍会落到未知事件守卫并抛错。中转站把 `{"type": "ping", "cost": "@"}` 发进 Responses 流时，这一轮会以 `llm request failed after 5 retries: Unknown output: {"type":"ping","cost":"@"}` 结束：引擎把该抛错判定为可重试的请求失败，而每次重试又撞上下一个心跳。

## 细节

- 现在所有流式 client 都把认不出的事件标记为 `unused`，Gemini client 跳过认不出的 content part，因此没有任何网关帧能终结一次生成。把 `AGENTHUB_DEBUG` 设为 `0`、`false`、`no`、`off` 以外的任意值即可恢复守卫用于调试，报错文本与此前一致。
- `AutoLLMClient` 新增了 `list_models()`、`default_headers` 与 `UnsupportedOperationError` 错误类。harness 目前都还没有调用；模型目录与协议路径提示不受影响，`protocol-path.ts` 的校验注释已改为它重新核对过的版本号。
- 0.4.5 还把 `openai-responses` 与 `minimax-m3` 的消息转换与 GPT client 对齐：缓冲的 assistant 文本改为在每条消息结束时才 flush，而不是在每个顶层项之前。因此重放 `[text, tool_call]` 这样一轮时，这两类服务端收到的顺序变为 `[function_call, message]`，也就是 GPT client 一直以来发送的顺序。
- `pnpm-workspace.yaml` 中 `minimumReleaseAgeExclude` 的条目改为 0.4.5；按该文件自身注释的要求，移除了 0.4.4 的条目。
