# 个人资料页可设置用户的头像与昵称

- **Date:** 2026-09-12
- **Type:** feature
- **Scope:** `server`, `web`, `docs`
- **PR:** [#714](https://github.com/Prism-Shadow/penguin-harness/pull/714)

[English](2026-09-12-user-profile.md)

账号在界面上出现的每一处都只是它的用户名：侧边栏底部的用户行、收起态侧栏的触发点、用户管理列表。新增的**个人资料**页位于系统设置「个人」组之首，为每个账号提供头像与昵称，原本绘制用户名与首字母头像的位置改为显示它们。

## 细节

- 该页有两行设置与一个「保存」按钮。**更换头像**打开图片选择器；选中的图片按中心裁成正方形，并以 128×128 重新编码为 PNG——若 PNG 超过 100 KB，则改用质量 0.85 的 JPEG。仍超过 128 KiB 的图片在页面内直接报错，不再发出服务端同样会拒绝的请求；**移除头像**只在已设置头像时出现。**昵称**为 1–32 个字符，按字符计，因此中文昵称可以有 32 个；清空输入框即清除昵称。
- 该页在任何会话中都可见，包括桌面 shell 自己的 token 窗口——与旁边需要密码的「账户」页不同。`PUT /api/me/profile` 遵循同一规则，接受任何已认证会话。
- 该路由为补丁语义：字段缺省表示保持原值，`null` 表示清除，两个字段都未出现则返回 400。它校验昵称长度并拒绝其中的控制字符，并要求头像是 `data:image/(png|jpeg|webp);base64,…` 形式的 data URL、长度不超过 131072 个字符且载荷可解码——与浏览器衡量重新编码结果所用的数值和单位完全一致。
- `GET /api/me` 开始下发 `displayName` 与 `avatar`，未设置时字段整个省略。用户管理列表只下发昵称——该列表不分页，而每个账号都带一份头像会让一张只显示昵称的表格返回数 MB 数据。头像与昵称统一经由共享的 `UserAvatar` 组件渲染，因此导航行、收起态侧栏、新增的账户菜单头部与本页 64px 的预览不会各自走偏；用户管理列表以浅灰小字把昵称显示在用户名下方。
- 数据库迁移 5，`user-profile`：新增两个可空列 `users.display_name` 与 `users.avatar`。它是纯增量且 swap-safe 的——回滚到不认识这两列的旧平台既不会读也不会写它们——并且可回退，只是其 `down` 会删除这两列，已保存的昵称与头像随之丢失。既有部署无需任何操作：所有账号只是尚未设置个人资料，在设置之前继续显示用户名。
