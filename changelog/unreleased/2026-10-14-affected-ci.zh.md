# CI 按受影响包运行，发布前执行全量检查

- **Date:** 2026-10-14
- **Type:** process
- **Scope:** `ci`, `tooling`, `web`
- **PR:** [#1120](https://github.com/Prism-Shadow/penguin-harness/pull/1120)

[English](2026-10-14-affected-ci.md)

CI 改为通过 pnpm 选择变更的工作区包及其下游，构建所需依赖，并跳过无关任务。
公共或无法归类的输入变更，以及缺少比较历史的情况，会触发全量检查。

## 检查与发布门禁

- 浏览器和站点测试在 Linux 运行，受影响的原生包保留 macOS 与 Windows 测试。
- core、server 和 web 在已有的 Linux 测试运行中统计分支与行覆盖率。
- 三个使用本地 mock LLM 的浏览器 smoke 场景覆盖登录保持、批准前禁止执行命令、刷新恢复和后续消息。
- 打包检查保留版本注入、插件索引、安装器和内置 CLI 的回归兜底。
  npm 检查改用针对版本注入的测试，Electron 运行包改为仅在手动 CI 中上传。
- 新版本发布前必须通过实际发布 ref 上的完整三平台检查；已存在的不可变版本保留发布器和镜像同步重试。
- 手动发布改为记录实际检出 tag 的提交，而非触发工作流的分支提交。
- 必需的 `ci` 门禁只接受计划内跳过，并拒绝缺失或失败的任务。
- 图标注册表检查跳过了无关文件的解析，保留原有图形检查。
- SSH 超时与 workflow Session 测试显式建立了所需连接和模型条件。
- Docker `latest` 改为在 `main` 的运行时代码或构建输入变更时重建，无关站点和文档修改不再重建两个架构的镜像。
- PR 的新推送会取消已过时的站点预览构建，生产部署继续完成。
