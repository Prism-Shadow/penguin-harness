# 聊天机器人：从聊天里启动智能体的机器人，以及承载它的 Discord 插件

- **Date:** 2026-09-07
- **Type:** feature
- **Scope:** `server`, `plugins`, `docs`
- **PR:** [#641](https://github.com/Prism-Shadow/penguin-harness/pull/641)

[English](2026-09-07-chat-bots.md)

消息绑定把一个机器人绑到某个已经在网页端打开的 Session 上。**聊天机器人**把这层关系反过来：机器人只配置一次——一条凭据加一个目标 Agent——此后每一个给它发消息的聊天（私聊、@ 它的频道、子区）都得到一个自己的 Session，在第一条消息时创建、之后复用。没有人需要先打开网页端；这些 Session 照样出现在网页端的目标 Agent 之下。第一个聊天机器人是 Discord 的，以插件 `@prismshadow/penguin-plugin-discord-bot` 发布。

## 细节

- 宿主落在 `runtime/messaging/chat-bots.ts`，与渠道无关：它向消息桥取该渠道的连接器，用机器人的凭据打开一条入站连接，按聊天 id 把每条消息路由到该聊天的 Session——没有就经定时任务同一条路径创建一个——再经同一个连接器的客户端把每条完成的助手消息送回聊天：渲染 Markdown、按渠道上限分段、群聊里引用来信。聊天里附上的图片与文件按输入框的两种附件形态送达智能体。
- **聊天里的命令。** `/new` 为该聊天开一个新的 Session。`/approve` 允许智能体正在等待的工具调用，`/deny` 拒绝它——机器人会在有调用等待时说明，因为提问的人面前没有网页端。`/status` 报出该聊天的 Session。
- **给插件的槽。** `ChatBotsModule.bots` 接受一条清单项（机器人的 id、渠道与名字）和一个可以预填配置的代码半。Discord 插件的预填读取服务端环境变量 `PENGUIN_DISCORD_BOT_TOKEN`、`PENGUIN_DISCORD_PROJECT` 与 `PENGUIN_DISCORD_AGENT`；三者齐全时机器人以启用状态启动。设置存储里已有的值优先于预填，运营者关掉的机器人不会被预填重新打开。
- **管理员 API。** `GET /api/chat-bots` 列出每个插件贡献的机器人，带掩码后的凭据与实时状态；`PUT /api/chat-bots/:id` 保存凭据文档（按连接器自己的形状，连接器读不懂即拒绝）与目标 Project、Agent；`POST …/state` 是连接开关；`POST …/test` 探测凭据。全部存在服务端设置的 `chatbot:<id>` 下，聊天 → Session 表在它旁边，重启与热更新都不丢。
- `Messaging` 机制新增 `connectorFor`；插件表面导出聊天机器人的词汇（`ChatBots`、`ChatBotsSlots`、`ChatBotContribution`、`ChatBotBinding`、`ChatBotDefaults`）。
- 插件随每个构建一起发布、列入内置索引、默认不安装；README 写明开发者后台的步骤与两种配置方式。
