# 用时拆出模型 API 时间与工具 wall time

- **Date:** 2026-09-03
- **Type:** feature
- **Scope:** `web`, `server`

[English](2026-09-03-duration-breakdown.md)

对话页详情卡与轨迹观测的每处用时，现在都在括号里带上两个分项——`用时 10.3s（API 5s，工具 5.3s）`——一轮慢在哪里，是等模型还是跑工具，一眼可读。

## 细节

- **API 时间**是 LLM 请求内的时间，已扣除人工审批等待。审批等待落在请求区间之内（core 在流式循环里等待审批），那不是模型在工作的时间。
- **工具 wall time** 是各工具执行区间的并集，并行工具只计一次而不是相加。它不含审批等待，也不含模型吐工具参数的那一段——那段属于 API 时间。
- 二者是对同一段用时的两项实测，不是对它的切分：后台工具会在模型解码时继续运行，而审批等待与 harness 开销不属于任何一项。故其和可能大于也可能小于所跟随的用时，任一项都不由用时减去另一项得出。
- 轨迹分析响应新增 `apiMs` 与 `toolMs`，全局与逐轮各一份，全局值同 `elapsedMs` 一样是各轮之和。轨迹观测在文件摘要处内联展示分项，逐轮则放在用时的悬停提示里。
- 对话页在两个分项皆为零时不显示括号，未跑过的对话只显示裸的用时。分项随每个 Request 与工具收尾而推进、不逐秒跳动，因此一轮进行中会略落后于总用时。
- 分窗加载历史时，分项与它所属的总用时一同回填：消息窗口的 prior 统计同样新增了这两个值，其按分片缓存的扫描记录也随之升版，旧记录会重算。
