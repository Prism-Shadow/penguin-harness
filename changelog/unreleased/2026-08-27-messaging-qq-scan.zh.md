# QQ 机器人可以扫码绑定

- **Date:** 2026-08-27
- **Type:** feature
- **Scope:** `server`, `web`, `docs`

[English](2026-08-27-messaging-qq-scan.md)

绑定 QQ 机器人不再需要从开发者后台里抄 App ID 与 App Secret。QQ 绑定编辑器现在以二维码开头：
用 QQ 扫码、选择机器人，凭据就已经在服务端了。手动填写的字段留在下方，用于扫码覆盖不到的情形。

## 细节

- 整个流程是对 `q.qq.com` 的三次调用：用新生成的 AES 密钥注册一个绑定任务、把返回的 URL 编码
  进二维码（由 QQ 客户端打开，本服务端从不请求它），以及轮询取回用该密钥加密的 App Secret。
- **密钥不会离开服务端。** 它在 `qq-scan.ts` 中生成、持有、使用并丢弃；浏览器拿到的只有任务
  句柄、URL 与状态，凭据直接进入存储而不回传——与「已存密钥不回传表单」是同一条规则。
- 绑定任务只存在于内存，归属发起它的 Session，受条数与十分钟 TTL 双重约束，并被「解决它的
  那一次轮询」消费掉：重放得到的是 404，而不是第二次绑定。取消（包括离开编辑器）会立刻忘记
  该密钥。
- 扫码成功只**保存**绑定，到此为止。启用连接仍是每个渠道上那个独立且互斥的动作，因此扫码不会
  把机器人从正在持有它的另一个对话手里夺走。
- 路由为 `POST /messaging/qq/scan`、`…/scan/poll` 与 `…/scan/cancel`，全部仅限 Project
  所有者——无论调用方实际输入多少，这个流程的终点都是一份存下来的凭据。
- 二维码在浏览器本地生成并以 `<svg>` 内联，因此不会有第三方从图片请求里得知任务句柄。它在
  明暗两种主题下都画成黑底白码，并保留 QR 规范要求的四模块静区——为深色背景反色的二维码扫描
  成功率并不可靠。
- 二维码编码库选用 `uqr`（MIT，无依赖）；实现了同一协议的 `@tencent-connect/qqbot-connector`
  刻意不用——它是 `UNLICENSED`，dist 经过混淆，并且依赖一个终端二维码渲染库。
