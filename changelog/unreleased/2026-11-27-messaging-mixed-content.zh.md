# 消息渠道支持图文混合消息

- **Date:** 2026-11-27
- **Type:** feature
- **Scope:** `messaging`, `docs`
- **PR:** [#PRNUM](https://github.com/Prism-Shadow/penguin-harness/pull/PRNUM)

[English](2026-11-27-messaging-mixed-content.md)

图片配文字、文件配留言，或一起发出的几个附件，作为一条用户输入进入绑定的 Session，和 Web App 输入框带附件发送一样。飞书的富文本消息此前会收到「暂不支持」提示，现在可以读取。

## 细节

- 飞书：`post` 消息转成其中的文字（标题在前，链接写成 Markdown，提及按 `text` 消息的方式还原，代码块加围栏），后面依次跟着其中的图片；富文本里附带的文件作为文件送达。富文本里的视频与附带的文件夹会被点名为未发送。
- Telegram：同一相册的各条更新带着相同的 `media_group_id`，在会话安静片刻后合成一条输入。说明文字不论写在哪一项上，都算作整个相册的文字，写在视频上也一样。
- 所有渠道：单独发出的图片或文件，若同一个人紧接着发来文字，二者合成一条输入。文字从不被扣下等待，所以先于附件发出的文字仍单独成为一条输入。群聊里只有发送者本人的文字会并入。
- 一条消息中有部分内容送不到时，不再整条停掉：其余内容送达 Agent，聊天里收到一行双语说明，逐项列出未发送的部分及原因。所有附件都没送到的消息仍整条停掉，并回复该原因对应的提示。输入框的单条消息文件数上限同样作用于入站文件。
- 「暂不支持」提示改为 "Only text, images and files are supported for now. 目前仅支持文本、图片和文件。"，不再按消息类型来说。
- 连接器接缝上的入站消息新增 `omitted`、`groupId` 与 `senderId`。
- 远程控制文档补充了混合消息的说明，QQ 一节也不再写着 QQ 只支持文本。
