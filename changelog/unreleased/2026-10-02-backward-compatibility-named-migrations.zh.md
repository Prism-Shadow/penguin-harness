# 向后兼容：编号迁移戳记

- **Date:** 2026-10-02
- **Type:** process
- **Scope:** `server`
- **PR:** [#187](https://github.com/Myriad-Dreamin/penguin-harness/pull/187)

[数据库迁移改为具名，并记入台账](2026-10-02-named-migrations.zh.md)取代了 `web.db` 上的编号戳记。所有存量数据根仍带着这个戳记。

## 旧形态：只有 `user_version` 戳记，没有台账

此前数据库用 `PRAGMA user_version` 中的一个数字记录迁移进度。不同 PR 线给迁移编的号不同，同一个数字在两个数据根上可能指不同的迁移。

选择：**首次打开时收编。** 没有 `schema_migrations` 表的数据库把全部迁移执行一遍——效果已在库中的迁移即为空操作——并记下所有名字。`user_version` 不再读取，因为它的含义取决于写下它的那条线；也不再写入，保留最后一个编号时代构建留下的值。适用于所有数据根：发行版、桌面端、CLI 与开发用数据根，以及服务端交付构建所到的机器上的数据根。runtime 启动和热推送都会触发收编。

**用户无需做任何事。**

一处限制：由带台账的构建新建的数据库，`user_version` 为 0。向这样的数据根推送台账之前的构建会以「需要重启」被拒绝，因为旧构建把 0 理解为「什么都没应用」。改推带台账的构建即可。

## 何时可以移除

收编路径在所有受支持的数据根都已有台账之后即可移除，由设定这一基线的版本负责移除；在此之前它的代价是每次打开多查一次表。只为修复按另一条线编号盖戳的数据根而存在的修补迁移，随收编路径变得多余，一并移除。
