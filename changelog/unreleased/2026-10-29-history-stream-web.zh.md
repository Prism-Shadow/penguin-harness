# 远程对话的历史从最新处加载，并显示进度

- **Date:** 2026-10-29
- **Type:** fix
- **Scope:** `web`, `ui`, `ui-gallery`

[English](2026-10-29-history-stream-web.md)

远程机器上的长对话在慢速链路上不再显示「历史消息加载失败：网络错误」。对话页改为通过 `history` 流读取历史，不再依赖一次带 20 秒期限的调用。第一次读取只请求能放进 64 KiB 记录的最新几个 Task，因此即使链路只有 10 KB/s，最新消息也会在几秒内出现。随后更早的窗口依次补齐，直到对话最近的 20 轮问答都已显示；每个窗口都加在对话上方，阅读位置保持不动。链路中断后，socket 从最后一个事件处续传，记录不会重复出现。离开对话时，它打开的所有读取都会关闭。

机器上的对话加载超过一秒后，骨架屏换成传输进度行：写明来自哪台机器，并显示已收到的量和总量，单位与宽度在整个传输过程中保持不变。与机器的连接中断时，进度行下方显示服务端的重试与「立即重试」；机器本身离线时，显示机器自己的重试行。最新消息显示之后，对话顶部有一行浅色提示，表示其余历史正在同步到本服务端，同步完成后这一行消失。仍在获取的更早窗口在同一位置显示它自己的进度。

历史中被折叠的工具输出、过长的工具参数或思考内容，显示首尾两段，中间以省略号相隔。展开这一行时会获取完整内容，并替换预览显示。获取失败时显示共用的重试行。

Trace 面板读取机器上的 Trace 文件时，先以同样的进度行把文件取到本服务端，再读取其分析，不再转发一次长达数分钟的读取。

UI 包新增 `TransferProgress`：一句纯文本说明、传输量与一条细进度条。工具调用卡片和思考块新增 `bodyNote` 插槽，只在该行展开时挂载。组件库展示了传输进度行出现的每个位置，其模拟 API 也能应答 history 与 trace-body 流。
