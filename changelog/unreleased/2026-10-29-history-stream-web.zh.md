# 远程对话的历史从最新处加载，并显示进度

- **Date:** 2026-10-29
- **Type:** fix
- **Scope:** `web`, `ui`, `ui-gallery`
- **PR:** [#1393](https://github.com/Prism-Shadow/penguin-harness/pull/1393)

[English](2026-10-29-history-stream-web.md)

远程机器上的长对话在慢速链路上不再显示「历史消息加载失败：网络错误」。对话页改为通过 `history` 流读取历史，不再依赖一次带 20 秒期限的调用。第一次读取只请求能放进 64 KiB 记录的最新几个 Task，因此即使链路只有 10 KB/s，最新消息也会在几秒内出现。随后更早的窗口依次补齐，直到对话最近的 20 轮问答都已显示；每个窗口都加在对话上方，阅读位置保持不动。带图片的提问只算一轮：每个窗口的分页信息会说明其中包含多少个 Task。较早 Task 中的后台子 Agent，如果在该 Task 的窗口加载之前发言或重新发送审批，仍会保留其历史，最新的 Task 中也不会出现多余的子 Agent 卡片。链路中断后，socket 从最后一个事件处续传，记录不会重复出现。重连后需要重新读取历史时，更早的窗口仍留在屏幕上：若期间有新的 Task 到达，两者之间的窗口会在对话后台读取，并恰好在旧窗口起始的那条记录处衔接。离开对话时，它打开的所有读取都会关闭。

本服务端上的对话也随之改变：它们的历史同样经由该流读取，先显示最新的几个 Task 再补齐到 20 轮，被折叠的内容也相同。一个窗口就能装下的对话与以前一样，不显示「已到对话开头」；只有读者向上滚动、越过对话最初显示的那些问答之后，才会出现这一标记。

机器上的对话加载超过一秒后，骨架屏换成传输进度行：写明来自哪台机器，并显示已收到的量和总量，单位与宽度在整个传输过程中保持不变。进度行会等机器列表返回后才出现，机器名称不会在已显示的行里突然冒出来。服务端重试连接机器时，进度行下方显示重试与「立即重试」，并区分两种情况：连接已断开（正在重连），或已连接但机器没有回应（正在重新请求）；机器本身离线时，显示机器自己的重试行。最新消息显示之后，对话顶部有一行浅色提示，表示其余历史正在同步到本服务端，同步完成后这一行消失。仍在获取的更早窗口在同一位置显示它自己的进度；自动补齐到 20 轮的过程从第一个窗口到最后一个窗口始终是同一行，并且与骨架屏一样，在第一秒内不显示任何内容。服务端等待机器时，仍是这一行说明情况：一个沙漏图标，等待的说明保持同样的浅色，传输量与进度条保持原样。机器已连接但一分钟内没有传来新数据时，如实说明这一点，不显示尝试次数、倒计时或「立即重试」，因为此时没有任何重试；本版本不认识的等待原因，用中性的说法表述。

链接指向的对话不在列表中时，只要还有可能持有它的机器没有答复，页面就不再显示「会话不存在或已被删除」。本服务端回答“没有这个 Session”，只有在所有机器都答复之后才算定论；在此之前页面继续等待，说明本机没有这个对话，并列出它可能所在、但当前没有答复的机器（最多三台），在机器答复后重新查询。Hub 返回的 `machine_no_answer` 会指出它无法询问的机器；本页已在本服务端见过的 Session，只凭本服务端的答复即可下结论。

历史中被折叠的工具输出、过长的工具参数或思考内容，显示首尾两段，中间以省略号相隔；工具参数中的省略号就位于被折叠的字符串内部。展开这一行时会获取完整内容，并替换预览显示。获取失败时在同一行写明原因，并提供重试。待审批的调用总是显示所请求的完整内容：服务端重新发送的审批请求会替换历史中的折叠副本。已获取的完整内容在重连后仍保持完整，不会再次获取；重建对话时仍在进行的展开会在重建后的行上完成；流从头重发时，已获取的数量也不会倒退。

Trace 面板读取机器上的 Trace 文件时，先以同样的进度行把文件取到本服务端，再读取其分析，不再转发一次长达数分钟的读取。它只请求这一个文件；本服务端上的文件会立即应答。在分析结果到达之前，面板始终保持同一个加载状态，不会在传输进度行与文件之间退回骨架屏。

UI 包新增 `TransferProgress`：一句纯文本说明、传输量与一条细进度条。工具调用卡片和思考块新增 `bodyNote` 插槽，只在该行展开时挂载。组件库展示了传输进度行出现的每个位置，其模拟 API 也能应答 history 与 trace-body 流。
