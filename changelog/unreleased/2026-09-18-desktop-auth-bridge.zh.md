# 桌面端不再开出用户看不见的窗口，Penguin Go 授权在桌面端直接打开授权页

- **Date:** 2026-09-18
- **Type:** fix
- **Scope:** `desktop`, `web`
- **PR:** [#788](https://github.com/Prism-Shadow/penguin-harness/pull/788)

[English](2026-09-18-desktop-auth-bridge.md)

文件面板中预览的 HTML 文件曾能拿到桌面应用的一个隐藏窗口，并在不可见处操控它，只要脚本愿意就一直留着——
其 iframe 允许弹窗，壳分不清请求来自哪一帧，而从页面开出的窗口与该页面同源。通向它的路有两条：Penguin Go
授权开始时 Web App 自己开的那个隐藏 `about:blank` 窗口，壳为此放行；以及在预览地址上带 `show=no` 特性串的
`window.open`，Electron 会把它应用到壳为预览放行的窗口上。现在壳拒绝一切空白窗口、钉住页面能藏起窗口的
每一项，Web App 在壳内则直接打开授权页。

## 桌面端

- 对 `about:blank` 的请求——不带地址的 `window.open()`——与其他非 web 协议一样被拒绝，主窗口与它打开的
  每个窗口一律如此。主窗口不再有自己的新窗口例外。
- 壳确实开出的窗口（Workspace 预览的交接路由、预览主机上的页面、拆出的终端）一律显示、进任务栏、不透明、
  可聚焦、至少 320×240，无论打开它的页面在 `window.open` 特性串里要求什么。窗口出现时居中，页面自己的
  `moveTo` / `resizeTo` 被拒绝，因此无法被挪到屏幕外。
- 其余规则保持不变：指向其他地方的 `http(s)` 与 `mailto` 链接交给系统浏览器；本实例的其余地址一律拒绝并
  记日志。

## Web App

- 在桌面应用的窗口里，Penguin Go 的「授权」点击不再先开空白标签页。server 返回授权地址后，页面直接打开它，
  由壳转交系统浏览器——Electron 没有弹窗拦截器，浏览器里必须在点击内开出的那个标签页在这里并不需要。
  页面凭渲染器（user agent 中的 `Electron/`）区分桌面窗口与浏览器，因此接入模式下同样成立——那时窗口
  像浏览器一样经登录页登录。
- 在浏览器里——包括登录到桌面模式 server 的浏览器——流程不变：点击内先开一个空白标签页，地址返回后再
  导航到授权页。
