# 工作区是某台机器上的目录

- **Date:** 2026-09-08
- **Type:** fix
- **Scope:** `web`

[English](2026-09-08-a-workspace-is-a-directory-on-a-machine.md)

本机的 `/srv/app` 与机器上的 `/srv/app` 是两个不同的目录。侧边栏的工作区分组只按路径建键，因此当会话列表开始合并多台机器之后，两者会并成同一个文件夹——而这个文件夹做的每件事都落到了错误的地方：它的「+」在本机新建对话，用的是本机在该路径下碰巧有的东西（可能没有，更糟的是有别的）；它的计数是两台机器相加的结果，与其下方的行自相矛盾；它的「加载更多」会向每台机器索取，于是可能给出属于另一台机器那个文件夹的行——而这些行永远不会出现在这里。

现在分组按「机器 + 路径」建键，一台机器一个文件夹，并以所在机器命名：`app [SSH: prod-1]`，同样的写法用于它的悬浮提示，以及会话详情面板里的工作区一行。本机自己的分组写法完全照旧——不加后缀，键也不变——因此折叠状态、置顶与分组顺序原样保留。每个文件夹的「+」在它自己的机器上创建，计数只采信那台机器的回答，翻页也只问它所在的那台机器。

侧边栏手工添加的工作区本就记录了机器，但对它们的每次查找都只匹配路径：加载项目时，同路径的两条只保留先出现的那条，另一条就此丢失；重命名一条会改到另一台机器那条上——并且重写后丢掉了机器，等于把它挪回本机；删除一条会把两条一起删掉。这些查找现在都按「机器 + 路径」这一对来匹配。

机器没有可用名称时（机器列表仅管理员可读，主机也可能从 `~/.ssh/config` 里消失），回退为它自己的 id，而不是编一个名字出来。
