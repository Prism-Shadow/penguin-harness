# 路径里混进了另一个参数的内容时，直接点破

- **Date:** 2026-10-20
- **Type:** fix
- **Scope:** `core`

[English](2026-10-20-contaminated-path-diagnosis.md)

网关或模型有时会把两个参数序列化成一个字符串：`file_path` 的值里塞进了换行和本该是下一个键开头的 `">`。当成路径读，它当然不存在，于是 `File not found: <整坨>` 把模型送去寻找一个从未存在过的文件——它会原样重发这个畸形调用，而连发同一个调用的 run 会被 `tool_loop` 熔断砍掉。

## 改动

`read_file` 与 `edit_file` 现在认得这个形状并直说：路径里带着换行／多余的引号和冒号／远超路径能有的文字，是两个参数被序列化成了一个字符串，修法是路径只放在 `file_path`、要匹配的文本放在它自己的 `old_string` 里。

像样的路径不受影响：这条诊断只会替换一次**已经发生**的失败的措辞，不会把本来能读的文件变成读不了。
