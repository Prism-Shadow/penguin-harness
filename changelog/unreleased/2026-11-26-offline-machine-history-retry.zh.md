# 连不上的机器上的对话不再无限重试，改为显示缓存副本

- **Date:** 2026-11-26
- **Type:** fix
- **Scope:** `server`, `web`
- **PR:** [#1904](https://github.com/Prism-Shadow/penguin-harness/pull/1904)

[English](2026-11-26-offline-machine-history-retry.md)

打开一台连不上的远程机器上的对话时，不再无限重试：页面显示本服务端缓存的副本与一行状态，机器回来后自动重新加载实时历史。

## 细节

- 本服务端的历史读取如实报告等待原因：`not_connected` 为本服务端没有到机器的连接；新增的 `unreachable` 为连接还在，但 API socket 与转发都到不了机器上的服务；`retrying` 为机器应答过或流已打开，却没有进展就断了。此前 ssh 连接还在、机器上的服务已停的机器被说成「机器没有回应」。
- 每次等待都带上第几次与上限 `maxAttempts`（5），重试行写作「连不上 bm2 上的服务，2 秒后重试（第 2/5 次）」。连续 5 次重试（1、2、4、8、16 秒后）都没有进展即停止，读取以 503 `machine_unreachable` 结束，`details` 带 `machineId` 与最后一次的 `reason`；在这台机器的任何一条流再有进展之前，对它的后续读取只尝试一次、不再重试，反复打开对话不会重新开始一轮。
- 机器列表把机器读作离线（正在重连、已停止自动重连、保存的密码被拒、服务已停止、尚未连接）时，对话不打开历史流与实时流，立即显示缓存副本与离线提示行，等机器列表推送机器重新连上后才打开。
- 机器列表仍读作已连接、读取却放弃时，页面同样换成这一离线视图：首行写明原因（「bm2 上的服务没有响应。」或「bm2 没有回应。」），句末带「[重试]」，按下只再试一次；机器的 API socket 重新连上后自动再读一次。API socket 连上与断开时本服务端推送 `machines_changed`，页面不轮询。
