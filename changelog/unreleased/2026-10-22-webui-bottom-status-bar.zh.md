# Web App 最下方新增一条状态栏

- **Date:** 2026-10-22
- **Type:** feat
- **Scope:** `web`, `server`, `ui`
- **PR:** [#1286](https://github.com/Prism-Shadow/penguin-harness/pull/1286)

[English](2026-10-22-webui-bottom-status-bar.md)

Web App 的窗口如今收在一条横贯整个底部、全宽的状态栏里——导航列与 dock 列的下方都在它的
覆盖之内，而不只是主列。左侧读你正在工作的那台 machine——整机 CPU 利用率与已用/总内存，再无
其他（不含磁盘）；每 10 秒一次请求刷新，标签页隐藏时暂停。右侧只剩计数
`session: ${active} / ${viewed}`。

## 细节

- 两个数的读法是「所有 machine 加起来当前 active 有多少个」与「我查看了多少个」。`active`
  由本服务端与每台已连接 machine 求和而来：一次轮询（`POST /api/harness-status`，仅管理员——
  非管理员收到 403，状态栏永不渲染）会问每台 machine 自己的同名路由，它答自己的会话与自己
  所在机器的负载，并且不再向下扩散。未连接、或运行的还是这条路由出现之前版本的 machine，
  在它连上并更新之前不计入——与其他机器界面面对失联服务端的口径一致。
- `viewed` 是本浏览器自己的「我查看了多少个」——打开过的会话数，与列表同一份记账，存于
  localStorage、上限 200 个 id。点行上的 x 即不再关注该会话：它离开列表，计数随之减一。会话
  本身不受影响。
- 列表是你打开过、harness 仍然持有的那些会话——无论它们在 harness 的哪一侧，每行都带着
  它所在 machine 的标记、以及持有它的 company（若有）——再加上全部 active 会话，不论打开与否：
  你从未打开过的行只在轮询仍报告它 active 时随行，不带 x、不带标记，点一下便以现行语义打开它。
  你打开过的会话，若某次轮询首次读到它由运行转为空闲，会带上一次性的「已空闲」标记，直到你
  再次打开它。
- 点击一行既把外壳切到该会话，也让左列跟上：若该行所属的 company 不在当前侧栏上，侧栏先切到
  那个 company（外壳处于开发模式时先进入 company 模式）；不属于任何 company 的行则把外壳带回
  开发模式的列表（正处 company 模式时先切回开发模式）。随后侧栏展开该行所在的分组——company
  会话展开它所属工位的那一组，或像从工单打开一样把它列进临时组——并把该行滚动到可见。当前
  shell 的组织列表显示不了的 company，则一切照旧。
- 左侧跟随你最近查看的会话所在的 machine：要紧的负载是你最后在工作的那台的负载——公司在自己
  的 machine 上时，那台就是公司所在 machine。某台 machine 本轮未应答时显示不出数字，
  而不是拿另一台的充数。
- CPU 利用率在被读的那台 machine 上按需取两次 `os.cpus()` 读数求比值；进程首次读取返回
  null，状态栏显示占位文案；两次读取间隔不足 2 秒时直接回缓存答案——无后台定时器，无密集
  轮询。
- 本轮状态栏是 Web App 布局的固定部分；接缝只有一个组件，以后可以换成插件提供。
