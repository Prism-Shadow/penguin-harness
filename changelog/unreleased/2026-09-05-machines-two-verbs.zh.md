# 机器页：使用，或停用

- **Date:** 2026-09-05
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#622](https://github.com/Prism-Shadow/penguin-harness/pull/622)

[English](2026-09-05-machines-two-verbs.md)

机器页现在只有两个动作，每台机器一句话。**使用**一次做完让机器能跑 agent 所需的全部事情——安装或更新程序、启动对端服务、连接、下发 Model 配置——作为一个任务；**停用**则放开它。每一行用人话说明这台机器在哪一步（「已连接，随时可用」「对端服务未运行——点『使用』即可启动」），凡是提到问题的句子，都由同一个按钮解决。安装、更新、重启、连接、断开不再是需要人手动排顺序的各自独立的控件。

## 细节

- 每台机器一张卡片，本服务端排第一。静止时一张卡片只有两行：名字，以及状态和它旁边唯一要紧的那个信息——上次检查时间、落后于本服务端时它所装的版本、失败时对端的原话。卡片边缘的圆点：蓝色表示连接在线，琥珀色和红色表示需要人处理，灰色表示已安定。「启用」只出现在需要它的卡片上。
- 选择即卡片：点一下即选中。全选、清空、「启用」（插头）和「停用」（拔下的插头）是图标按钮，放在标题和卡片之间一条高度固定的操作条里，因此选择出现或消失时卡片不会移动。批量操作在服务端逐台排队执行。
- 排队或处理中的行在名字下方长出一条分段进度条，每段对应流程的一步（检查、安装、交接、重启、连接、下发配置），由服务端报告的当前步骤驱动。
- 卡片右侧的箭头展开详情：版本、安装时间、对端服务状态和端口、上次检查、机器 ID、任务的完整输出，以及任务给出时的强制安装。
- 尚未使用的机器放在「添加机器…」后面，在服务端的 ssh 配置里搜索；多选后确认即一起使用。
- 机器连上之后，保持连接是服务端的事：断开且未自行恢复的机器会以逐步拉长的间隔重试——从一分钟到十五分钟——直到重新连上或有人停用它。重启服务端后，不再需要有人打开页面机器才会重新连接。
- 「强制安装并重启」和以前一样只出现在任务失败的行上，并且仍会提示这会打断正在使用那台机器的人。
- 标题栏显示本服务端的版本；当有在用的机器落后于它时，出现「全部更新」，一次把它们全部更新并重新连接。
- 服务端新增 `POST /api/projects/:projectId/machines/use`，请求体 `{ machines: [...] }`（排队执行，返回 `202`；无需 ssh 即可判定的拒绝按 id 返回），以及 `POST .../machines/stop-using`。列表现在带有 `jobs`：每台机器排队中、运行中和最近一次完成的任务，以及各自所处的流程步骤（`phase`）。原有的按机器安装、连接、重启、释放、断开路由保留。
