# 机器「未同步的模型」提示可以关掉，并能说明是机器版本落后

- **Date:** 2026-10-24
- **Type:** fix
- **Scope:** `web`, `ui`, `server`, `docs`, `ui-gallery`
- **PR:** [#1317](https://github.com/Prism-Shadow/penguin-harness/pull/1317)

[English](2026-10-24-machine-sync-skipped-notice.md)

机器详情弹窗里列出配置同步没能带到这台机器的模型的提示，现在和旁边的环境变量密钥提示一样带关闭叉。关闭会按账号、这台机器和当前 Project 记住，并以当时列出的模型及各自被拒的原因为准：之后的同步仍以同样原因拒绝同样的模型时保持关闭，又有别的模型被拒、或列出的模型换了被拒原因时重新出现。

本服务器的内置模型被那台机器以「该分组不能添加其他模型」拒绝时，不再被说成手动添加、应改到自定义分组的模型。那是因为机器的构建里还没有这个模型，提示现在照实说明：先更新这台机器，再同步配置。

## 细节

- 「未同步的模型」列表改由共享的 `Notice` 渲染，带标题与关闭叉，与环境变量密钥提示共用同一份记录（`ui_prefs.noticesDismissed`，键为 `machine-skipped:<机器 id>:<Project id>`）。
- 机器 `configSync.skipped` 的条目在被拒的是本服务器该分组的内置模型时带 `builtInHere: true`；连接日志随之改为说明需要更新那台机器，不再转述对端「改用自定义分组」的建议。
- 只有关闭叉一个操作的 `Notice`，关闭叉留在正文那一行的末尾，正文在它旁边换行；此前正文一行放不下时，关闭叉会被挤到正文下方单独一行。带按钮的提示，按钮仍可单独占一行。
- Server API 文档补充了 `builtInHere`；UI 画廊的演示机器在被跳过的模型里加了一个内置模型。
