# 连上一台机器：连接它、代理它、浏览它

- **Date:** 2026-09-01
- **Type:** feature
- **Scope:** `server`, `docs`
- **PR:** [#574](https://github.com/Prism-Shadow/penguin-harness/pull/574)

[English](2026-09-01-machines-reach.md)

已安装的机器现在可以**连接**：本服务端通过 ssh 把它的 `penguin server` 拉起来，并让通往它的那条连接保持打开，它的 API 经此在本源上以 `/server/<machineId>/api/…` 应答。没有任何新的东西在任何地方监听，也没有任何新的连接被打开——机器本就持有的那唯一一条连接承载了它。

## 连接，以及它的代价

连接是一个任务：问那边究竟在跑什么，没在跑就把它的服务端启动，然后让连接保持打开。连接本身就是本服务端对每台机器本来就持有的那一条——一个 `ssh -T -D` 会话——所以「连接」不会新开任何东西；它做的是确保对面有一个能应答的服务端，并记住它所在的端口。

## 每个事实都写明它量的是哪一层

机器上新增了两个事实，并且刻意不与 [#568](https://github.com/Prism-Shadow/penguin-harness/pull/568) 加的那个合并：

- `connection` —— 本服务端对它持有会话。这是关于**本侧**某个进程的事实，它比对面的服务端活得更久。
- `api` —— 本服务端的代理最近一次把请求送过去时，那台机器的 API 答了、或没答。它由本来就要流动的流量盖章，而不是由一次专门的探测：没有定时器，没有轮询，没人问起的机器就干脆不被测量。

把其中一个当成另一个来读，就是 [#561](https://github.com/Prism-Shadow/penguin-harness/pull/561) 的那个连接死循环：对着已死服务端的活连接被读成「已连接」，于是每一个发现机器不作声的调用者都再请求一次连接，又被告知「已经连上了」，永远如此。**现在即便连接已经持有，连接操作仍然会去问那边究竟在跑什么**，没有在跑就把它启动——这也让「换一把新钥匙」或「重试一次」这类重连只花一次探测，而不是被一句拒绝挡回来。

## 同源代理

`/server/<machineId>/api/…` 经会话拨到那台机器的服务端。只转发 `/api` 路径——前端始终是本地那一份，所以这里不可能出现「整个窗口连自己是否登录都答不上来」的情况。

按机器**自身的 id**（[#568](https://github.com/Prism-Shadow/penguin-harness/pull/568) 引入的那个）寻址，而不是按 ssh 别名：别名只是某一台机器配置文件里的一行，用它做 URL 的键，会在有人给主机改名的那一刻全部失效；而 id 是 base64url 的，放进路径里不需要百分号转义。

**只有一个身份。** 调用者是本服务端的管理员，而本服务端的管理员就是那台机器的管理员——授权二者的是同一样东西：当初把程序装过去的那份 ssh 访问权。呈给对面的会话通过这份访问权铸出（在持有的连接上执行机器自己的 `penguin auth token`），并复用到接近其 TTL 为止。浏览器的 cookie 从不过去，机器的也从不回来。代理挂在本服务端自己的鉴权中间件里面，仅限管理员。

## 路由新增了什么

`POST …/connect` 是与安装同一形状的任务，靠 `job.kind` 区分。`POST …/disconnect` 撤掉连接，远端服务端保持运行——那是那台机器自己的服务端，别人可能正在上面。`GET …/dirs?path=` 经这条连接列出机器上的子目录，因此在它上面选一个目录只花一条命令，不必往它的 API 跑一趟。

持有的连接会一直持有：不会因空闲而关闭；断了——网络抖动、keepalive 判定链路已死——由传输层自己带退避重建，直到 disconnect 放手。连接属于打开它的那一代：热推时这一代在退出前关掉自己持有的每一条，下一代按记录把原本持有的逐台重新持有，并发 5，途中把没在跑的远端服务端拉起来。从不按事先记下的 pid 去关任何东西。

Windows 机器目前无法连接——它的 sshd 把命令交给 cmd.exe，没有可以持有会话的 shell——`POST …/connect` 会直接说明（`409` `connect_unsupported`），而不是让一条 POSIX 命令在任务日志里失败。浏览机器目录需要已持有的连接：机器未连接时 `GET …/dirs` 返回 `404`，且不会打开任何东西。
