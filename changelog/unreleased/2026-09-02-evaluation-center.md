# The Evaluation Center creates and optimizes Benchmarks

- **Date:** 2026-09-02
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `skills`, `docs`
- **PR:** [#596](https://github.com/Prism-Shadow/penguin-harness/pull/596)

[中文版](2026-09-02-evaluation-center.zh.md)

A Benchmark became a peer of an agent rather than something an agent owns: it moved to the Project level, one Benchmark can evaluate several agents, and the agent under test is recorded on each evaluation. The Evaluation Center was rebuilt around that and around the loop a first-timer needs — create a Benchmark, read its scores, hand it to an optimizer — each step one click away, with the prompts written for the person.

## Details

- Benchmarks moved from `agents/<agent>/benchmarks/<id>/` to the Project's `benchmarks/<id>/`, a sibling of `agents/`. `benchmark_config.toml` (title, description, runs) records no agent; every `scoreboard.yaml` evaluation carries the agent it tested as `agent_id`, written right after `time`. Files stayed the single source of truth.
- `agent_id`, the Agent State `version`, the `(provider, model_id)` pair and `thinking_level` form an evaluation's **label**. The Benchmark chart plots time against score and draws one series per label, so only comparable scores share a line; a record with no label falls into a grey series. The evaluation table names the agent under test in its own column, and a card's score change is measured against the previous evaluation under the same label.
- The page: one flat list, no per-agent grouping. A title with the search box (over titles, descriptions and the agents a Benchmark has evaluated) and the two create buttons beside it, the folded three-step guide naming the Skill behind each step under them, and one card per Benchmark carrying its title and directory name, the case and run counts, the last evaluation time, the agents it has evaluated, the newest score with its change, and a score sparkline — the list column, the header and the cards in the Agents page's shape.
- Opening a Benchmark **enters** it. A card, or its **View** button, navigates to that Benchmark's own page at `/benchmark/:benchmarkId` — the existing detail (chart, evaluation table, case browser) and a back button to the list — instead of expanding a second pane beside the list. An id that resolves to nothing, a deleted Benchmark or a stale link, says so and keeps the way back. Empty states carry the guide and the same pair of buttons, and `?agentId=` narrows the list to the Benchmarks that have evaluated that agent.
- **Create with AI** and **Create manually** are the kit's two buttons, side by side and the same pair the scheduled-tasks tab uses, each opening its own path. The AI one adds a Test Agent picker above the prompt, four scenario examples, and a fixed tail that hands the `benchmark-design` Skill the agent id, a desired baseline score, a pilot-iteration limit and the layout to write; the composed prompt is prefilled into a new conversation and sending stays the user's move. The manual one is a form — title, id proposed from the title, description, runs per case, and per case a directory suffix, title, statement and rubric, with format hints on screen and a folded note on what makes a rubric discriminating — and it no longer asks which agent the Benchmark belongs to.
- **Optimize with AI** and **Optimize manually** in the Benchmark page's header are the same pair over one prompt tail for the `agent-optimization` Skill: the manual one is a form (the optimizer agent, with a warning when it lacks the Skill; the agent under test, defaulting to the one the newest evaluation tested; the model of the optimizer's own conversation; runs per case; round limit; a target score defaulting to ten above that agent's baseline; an optional focus), the AI one a free prompt with examples. A card has no space for a pair, so its **Optimize** button opens the form. Either path ends the same way: the full prompt is prefilled into a new conversation for the user to read and send. A Benchmark with no baseline for the chosen agent says so first.
- The card's overflow menu copies the Benchmark's directory path or, for the owner, deletes it after confirmation.
- Server: the Benchmark routes moved to `/api/projects/:projectId/benchmarks` and dropped their `agentId` segment, membership and ownership now being checked at the Project level. `POST` (owner only) writes `benchmark_config.toml`, a `scoreboard.yaml` holding `evaluations: []`, and each case's `statement/README.md` (the title as its heading) and `rubric/README.md`, answering 409 `benchmark_exists` for a taken id; `DELETE …/benchmarks/:id` removes the directory whole. A listed Benchmark reports `agentIds`, the distinct agents its evaluations name in first-seen order, and each evaluation reports `agentId` (`null` when the record carries none).
- The list only returns directories holding a `benchmark_config.toml`. Deleting a Benchmark while an evaluation is still running leaves a directory behind — the run keeps writing to the paths it was deleted from — and that debris no longer appears as a Benchmark with a placeholder title. A Benchmark that has never been evaluated has its config and still lists.
- The `benchmark-design`, `agent-evaluation` and `agent-optimization` Skills read and write the Project-level path, state that a Benchmark may evaluate several agents with `test_agent_id` naming the one a request evaluates, return `agent_id` in the evaluation protocol, and write it into every scoreboard entry they append. The `agent-tuning` plugin version became `2026.09.12.1`.
- Initializing a Project's `default_agent` seeded the example Benchmark at the Project level, its three sample evaluations labelled `agent_id: default_agent`.
- The "Create with AI" bridge accepts a `modelRef`, which the Optimize dialog uses to pin the model of the optimizer's conversation.
- A `benchmarks/` directory left under an agent by an earlier version is not read by this version; nothing migrates or deletes it.
- The Web App, server API and self-improvement docs describe the page, the routes and the storage layout in both languages.
