# 文件汇总下方列出记忆更改,侧边面板展示差异

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `web`
- **PR:** [#375](https://github.com/Prism-Shadow/penguin-harness/pull/375)

[English](2026-08-20-memory-change-list.md)

Task 更改过 Agent 记忆时,对话现在会在两处展示出来。Task 末尾的文件汇总卡正下方新增一张记忆更改卡——每个主题文件一行,以 icon+tooltip 标注作用域(用户记忆或工作区记忆)与更改类型(写入 / 编辑)。聊天新增记忆面板——与智能体、终端、工作区面板同级,在面板切换器中有自己的入口,共用同一套停靠/Sheet 外壳与互斥编排——面板内分两级:列表(两个作用域的主题列表,与 Agent 设置记忆标签页同一份数据,本次对话更改过的主题带标记)与单条记忆的详情——正文本身以 GitHub 式整文件行差异呈现本会话的更改:新增行绿底、删除行红底插在原位、未变行为上下文,frontmatter 不参与比较;返回按钮退回列表。点击卡片行直达该条记忆的详情、差异即刻可见;经面板切换器进入则始终落在列表。未触及记忆的 Task 不显示此卡。

## 详情

- 行来自结构化工具记录:成功完成、路径落在会话记忆根(`<agent_state>/memory/`)下的 `write_file` / `edit_file` 调用,按文件合并为一行——整文件写入的权重高于其后的原地编辑——且每次调用保留可回放材料(编辑的新旧字符串、写入的完整内容)。
- 整文件差异靠把本会话的调用在当前内容上**逆向回放**重建会话前文本:编辑按新→旧逐个撤销(要求锚点唯一;`replace_all` 回退全部出现),整文件写入是截止点——转录中不存在更早版本,正文按全新内容渲染。某次调用无法撤销时(文件另有会话外改动),正文正常渲染、附说明,逐次调用差异折叠可查作兜底;仅动了 frontmatter 的更改直接说明,不渲染空差异。
- 各作用域的 `MEMORY.md` 索引与 `.workspace` 标记文件被过滤:索引几乎随每次主题变更连带改写,单列会使每行都翻倍。
- 经不透明 `exec_command` shell 所做的更改(包括删除——不存在内置删除工具)没有结构化信号,不会列出,与文件汇总卡既有的局限一致。
- 仅统计根会话的 Task;subagent 的记忆写入属于其自身 Agent。
- 已加载列表不再收录的已更改文件即已被删除:其条目——更改卡与面板列表中——保留可见并带删除标记,但不可打开,而不是点进去才遇到加载失败。
- 流式回复不再引起记忆界面闪烁:重派生但内容未变的行保持引用不变,列表与已打开的详情只在真正改动记忆的 Task 落定时刷新;定位闪烁只在显式点击时播放一次。
- 记忆管理(添加 / 编辑 / 删除)仍在 Agent 设置的记忆标签页;面板列表头部可跳转过去。窄视口下面板与其兄弟面板共用底部 Sheet;切换会话时重置为列表。
