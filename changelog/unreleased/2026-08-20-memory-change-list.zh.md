# 文件汇总下方列出记忆更改,并新增同级记忆侧栏

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `web`
- **PR:** [#375](https://github.com/Prism-Shadow/penguin-harness/pull/375)

[English](2026-08-20-memory-change-list.md)

Task 更改过 Agent 记忆时,对话现在会在两处展示出来。Task 末尾的文件汇总卡正下方新增一张记忆更改卡——每个主题文件一行,以 icon+tooltip 标注作用域(用户记忆或工作区记忆)与更改类型(写入 / 编辑)。聊天新增记忆面板——与智能体、终端、工作区面板同级,在面板切换器中有自己的入口,共用同一套停靠/Sheet 外壳与互斥编排——面板内分两级:列表(两个作用域的主题列表,与 Agent 设置记忆标签页同一份数据,本次对话更改过的主题带标记)与单条记忆的详情,内容以与文件查看一致的方式渲染。点击卡片行直达该条记忆的内容;经面板切换器进入则始终落在列表。未触及记忆的 Task 不显示此卡。

## 详情

- 行来自结构化工具记录:成功完成、路径落在会话记忆根(`<agent_state>/memory/`)下的 `write_file` / `edit_file` 调用,按文件合并为一行——整文件写入的权重高于原地编辑。被拒绝或失败的调用不会出现。
- 已加载列表不再收录的已更改文件即已被删除:它会从更改卡与面板列表中消失。列表尚未加载时,不把任何条目当作已删除。
- 各作用域的 `MEMORY.md` 索引与 `.workspace` 标记文件被过滤:索引几乎随每次主题变更连带改写,单列会使每行都翻倍。
- 经不透明 `exec_command` shell 所做的更改没有结构化信号,不会列出,与文件汇总卡既有的局限一致。仅统计根会话的 Task;subagent 的记忆写入属于其自身 Agent。
- 流式回复不会引起记忆界面闪烁:重派生但内容未变的行保持引用不变,列表与已打开的详情只在真正改动记忆的 Task 落定时刷新。
- 记忆管理(添加 / 编辑 / 删除)仍在 Agent 设置的记忆标签页;面板列表头部可跳转过去。窄视口下面板与其兄弟面板共用底部 Sheet;切换会话时重置为列表。
