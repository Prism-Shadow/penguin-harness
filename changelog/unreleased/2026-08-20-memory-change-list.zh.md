# 文件汇总下方列出记忆更改,侧边面板展示差异

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `web`
- **PR:** [#375](https://github.com/Prism-Shadow/penguin-harness/pull/375)

[English](2026-08-20-memory-change-list.md)

Task 更改过 Agent 记忆时,对话现在会在两处展示出来。Task 末尾的文件汇总卡正下方新增一张记忆更改卡——每个主题文件一行,以 icon+tooltip 标注作用域(用户记忆或工作区记忆)与更改类型(写入 / 编辑)。侧边面板新增记忆视图,与工作区文件树平级,由面板标题行的扁平双图标切换:先是本次对话的更改、每个文件逐次调用的差异,随后是 Agent 记忆本身——两个作用域的主题列表与只读内容,与 Agent 设置记忆标签页同一份数据。点击卡片行会打开该视图并定位到该行:展开其差异、滚动到位并短暂高亮。未触及记忆的 Task 不显示此卡。

## 详情

- 行来自结构化工具记录:成功完成、路径落在会话记忆根(`<agent_state>/memory/`)下的 `write_file` / `edit_file` 调用,按文件合并为一行——整文件写入的权重高于其后的原地编辑——且每次调用保留可回放材料(编辑的新旧字符串、写入的完整内容)。
- 差异按调用逐次回放、保持时间顺序、不做跨调用合并:编辑将其新旧片段渲染为删除/新增行;写入将写入内容渲染为新增行——转录中不存在整文件写入的「之前」,因此重复写入标注为重写,而非拼接的差异。
- 各作用域的 `MEMORY.md` 索引与 `.workspace` 标记文件被过滤:索引几乎随每次主题变更连带改写,单列会使每行都翻倍。
- 经不透明 `exec_command` shell 所做的更改(包括删除——不存在内置删除工具)没有结构化信号,不会列出,与文件汇总卡既有的局限一致。
- 仅统计根会话的 Task;subagent 的记忆写入属于其自身 Agent。
- 记忆管理(添加 / 编辑 / 删除)仍在 Agent 设置的记忆标签页;视图头部可跳转过去。窄视口下视图沿用面板既有的底部 Sheet。
