# 记忆提示词明确了何时保存

- **Date:** 2026-08-21
- **Type:** feature
- **Scope:** `core`, `docs`
- **PR:** [#397](https://github.com/Prism-Shadow/penguin-harness/pull/397)

[English](2026-08-21-memory-save-signals.md)

内置 `memory.prompt` 原本只说了什么值得保存，没有说什么时候该注意到它，判断完全交给模型。现在它点明了产生长期事实的时机：

- 用户再次提出同一诉求，或以超出当前任务的方式纠正某项结果——保存他们真正想要的做法，连同原因；
- 反复讲到的习惯、约定或开发实践；
- 交代过一次、否则还要再问一遍的可复用工作信息——服务地址、工单或仓库标识、惯用工具链。提示词在该
  信号处重申了凭据与个人信息的禁令，因为这类例子最容易把它们带进来。

「重复」被写成强信号而非硬性条件，因此长期偏好只讲一次同样成立；拿不准是否值得记住时，提示词要求 agent 在对话里直接询问用户。

## 细节

- 补充这段指引的同时也把整段收紧了：保存什么、何时保存、绝不保存什么、索引规范，改为四行带标签的条目，不再是几段密集的长文。虽然多了这段信号说明，整段提示词仍略短于改动之前（1739 → 1719 字符），不会让每个 Session 为此多付开销。

- 该提示词是受 kernel 管理的配置叶子。`2026-08-21` 这一代的 `memory.prompt` 哈希就地修订——该代未随任何版本发布；此前五代已冻结的哈希保持不变，因此存量 Agent 若仍是旧版默认值会被识别出来并由 kernel 更新推进。手工改过提示词的 Agent 保留自己的版本，不会拿到这段新内容；唯一的采用方式是 Agent 设置 → Kernel → 恢复默认配置，它会整体覆盖配置，并非只针对该提示词。
- 配置说明的记忆章节同步补了一句同样口径的说明，中英各一处。
