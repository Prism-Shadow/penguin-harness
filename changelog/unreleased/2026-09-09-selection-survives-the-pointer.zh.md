# 在接管了鼠标的程序上选中的文字不再消失

- **Date:** 2026-09-09
- **Type:** fix
- **Scope:** `web`

[English](2026-09-09-selection-survives-the-pointer.md)

Claude Code 的终端里复制不出任何东西：看上去选中了，手一离开鼠标高亮就没了，于是 Ctrl+C——有选区时复制、否则表示中断——永远只剩中断这一层含义。

这是两条规则撞在一起。xterm 在任何用户输入时清掉选区，这对敲键盘是对的：一开始打字，高亮就过期了。但鼠标上报同样算作用户输入，而开启了 any-event 追踪的程序（`?1003h`，Claude Code 就开）每一次空手移动、每跨一个字符格都会收到一条上报。选区是被飘过它的指针抹掉的。

现在，只要选区还在，空手移动就不再上报。程序失去的仅仅是高亮存在期间的 hover——点击、拖动、滚轮照常上报，敲键盘也依旧会按 xterm 的本意清掉选区。这是终端层面的修复：右侧 dock、独立终端页、Session 的 surface 一并受益。

macOS 此前在这类程序里根本选不中：xterm 在 Mac 上要求 Option+拖动，并且还要一个默认关闭的选项。该选项现已打开，Mac 拿回了其他平台一直有的那条退路。

没有改变的是拖动归谁：接管了鼠标的程序仍然拿走拖动，所以起选区依然要按住 Shift（Mac 上是 Option）。这个默认值值得单独再议。
