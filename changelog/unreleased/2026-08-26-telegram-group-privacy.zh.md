# 听不到群消息的 Telegram 机器人现在会说出来

- **Date:** 2026-08-26
- **Type:** feature
- **Scope:** `server`, `web`

[English](2026-08-26-telegram-group-privacy.md)

在群里向已绑定的 Telegram 机器人发消息，可能得不到任何回应，也没有任何线索：没有报错、状态不变、
也不留记录。原因是 Telegram 的 **Group Privacy**——凡是不以管理员身份加入群的机器人，该设置默认开
启。在它生效时，Bot API 只投递：明确指向该机器人的命令（`/command@this_bot`）、该机器人是群里最后
一个发言的机器人时的通用命令、经由该机器人发出的 inline 消息，以及对它自己消息的回复。一句普通的
话——以及一个普通的 `@` 提及——根本不会被投递，因此 `getUpdates` 什么也取不到，连接看上去完全正常。

PenguinHarness 无法更改该设置：它属于机器人拥有者，在 @BotFather 中。能做的是让这次失败不再无声无
息。

## 凭证测试会报出它

`getMe` 会返回 `can_read_all_group_messages`（「True，表示该机器人的隐私模式已关闭」，仅在 `getMe`
中返回）。Telegram 凭证测试的响应以 `groupPrivacy` 携带它；当测试成功而机器人仍开着隐私模式时，会
另起一条提示说明——凭证确实没问题，机器人在私聊里也确实会回应。

只有在 API 真的回答了这个问题时才会报出该字段。响应里没有这一项时就什么也不报，而不是去猜：凭一个
缺失的字段把用户支去 @BotFather，是在浪费他们一趟。

## 常见问题折叠面板写清三条出路

绑定面板的 Telegram 常见问题折叠里，在「一个 Token 只能被一个程序使用」旁边新增一条。它写全了修复
的每一部分，因为只做其中两条，机器人照样是哑的：

- 在 @BotFather 用 `/setprivacy` 关闭 Group Privacy；
- **把机器人重新拉入它已经在的群**——已有的群不会自动生效；
- 或者把它设为群管理员，管理员始终收到全部消息。

## 不在连接状态里显示

状态行报告的是连接是否健康，而开着隐私模式的机器人是连着的、也是能工作的：私聊照常回应。把它标在
那里，会让一个并无故障的绑定读起来像出了故障。
