# 重试会告诉模型失败的原因

- **Date:** 2026-10-11
- **Type:** feature
- **Scope:** `core`
- **PR:** [#1018](https://github.com/Prism-Shadow/penguin-harness/pull/1018)

[English](2026-10-11-retry-carries-error.md)

以前自动重连重发本轮输入时，`[turn_retried]` 块只带上一次的部分输出，对失败本身一字不提，模型只能当作什么都没发生继续下去。

- `[turn_retried]` 块末现在有一行 `[request_error code="…"]…[/request_error]`：最近一次失败的错误码，以及 Provider 或传输层的报错原文（空闲超时只有错误码、没有报文）。这个块在每次尝试时重新生成，重试多次也只带这一行，不会每次累加。
- 请求失败（`fatal`，或重试耗尽）后构造的 `[turn_aborted]` 块也带同样的一行，下一条消息或「重试」会告诉模型这一轮为什么被重发。并入旧块时先去掉旧的一行；用户中断不留这一行。
- 默认系统提示词的 `# System markers` 一节解释了这一行：先读报错再继续，若它指出可以修正的问题，就改变做法而不是重复同样的请求。配置内核前进到 `2026-10-11`，提示词 Tab 仍为默认值的 Agent 经内核更新取得新措辞。
- 图片被拒的说明恢复为固定文字，Provider 的报文原文改由这一行携带，而不是写进每一条说明。
