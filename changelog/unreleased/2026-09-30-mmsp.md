# MMSP 0.5.0: model access moves from AgentHub to `@prismshadow/mmsp` and its streaming protocol v2

- **Date:** 2026-09-30
- **Type:** feature
- **Scope:** `core`, `model-catalog`, `skills`, `docs`
- **PR:** TBD
- **Breaking:** yes — a model entry stored with a 0.4.x vendor `client_type` (`deepseek-v4`, `minimax-m3`, `gemini-3.8`, `claude-5`, `gpt-6`, …) no longer starts, because MMSP 0.5.0 does not accept those names

[中文版](2026-09-30-mmsp.zh.md)

PenguinHarness moved its model library from `@prismshadow/agenthub` 0.4.15 to `@prismshadow/mmsp` 0.5.0: the same library, renamed MMSP (the Model Message Stream Protocol), with its second streaming protocol and with client types named after a vendor's official API or after a wire protocol.

## Streaming

- The stream translator in `packages/core/src/llm/generative-model.ts` was reduced to a one-to-one mapping of MMSP's grammar: a `.delta` item becomes a `partial_*` delta, a `.done` item becomes the partial `stop` and the complete message, and the single `stop` event carries the request's usage and finish reason. Nothing is re-assembled from fragments any more, and a tool call is completed from its `tool_call.done` item, with the arguments already parsed.
- A response that finishes on `length` or `unknown` ends its last item `fatal`; a stream that ends without a `stop` event is retried as `malformed`.

## Routing and presets

- Core's mirror of MMSP's routing was rewritten on MMSP's prefix rule. The new `routedClientType` returns the pinned client type, else the official client of the vendor family the lowercased model id begins with (`gpt-`, `text-embedding-`, `claude-`, `gemini-`, `glm-`, `kimi-`, `deepseek-`, `minimax-`), else nothing; `resolveModelEnv` and `fastModeProtocol` read it.
- The presets `deepseek/deepseek-flash` and `minimax/MiniMax-M3` dropped their pinned client type and base URL: both ids route on their own under MMSP 0.5.0.
- The Penguin Go presets were re-pinned to `gemini-generate-content` (the Gemini rows) and `deepseek-official` (the DeepSeek rows).
- Fast mode was opened to Gemini models routed to Google's official client (Interactions API), which sends `service_tier: "priority"`.
- A keyless model entry whose base URL is the vendor's own endpoint was given the vendor's environment key explicitly, because MMSP 0.5.0 does not send `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` to a base URL it is handed.
- The library's own environment variables were renamed with it: `AGENTHUB_DEBUG` → `MMSP_DEBUG`, `AGENTHUB_CACHE_DIR` → `MMSP_CACHE_DIR`. `CLIENT_TYPE` is still read.

## Skills and docs

- The `agent-development` plugin's `unified-llm-api` skill was rewritten for MMSP 0.5.0: the client types and their 0.4.x names, routing by prefix and its error, the streaming grammar (`.delta` / `.done` items and one `stop` event), messages of `.done` items, the errors, the model registry, fast mode per client, and embeddings and inline data.
- The skill name `agenthub-models`, which no skill carries, was replaced by `unified-llm-api` in the `penguin-sdk` and `agent-initialization` skills. The `agent-development` and `agent-tuning` plugins moved to `2026.09.30.2`.
- The docs were moved to the MMSP name, and the models, configuration, CLI and interfaces pages were updated for routing by vendor family, the clients that carry fast mode, and the new client type names.

## Compatibility

MMSP 0.5.0 renamed its client types, and it refuses a name it does not know when the client is built (`Unknown client type "deepseek-v4". Pass one of the …`). A `.project_config.toml` entry that stores one of the 0.4.x vendor names — `gpt-6`, `gpt-5.6`, `gpt-5.5`, `gpt-5.4`, `claude-5`, `claude-4-8`, `claude-4-7`, `claude-4-6`, `gemini-3.8`, `gemini-3.7`, `gemini-3.6`, `gemini-3`, `gemini-embedding`, `gemini-interactions`, `glm-5.3`, `glm-5.2`, `glm-5.1`, `kimi-k3`, `kimi-k2.6`, `kimi-k2.5`, `deepseek-v4`, `minimax-m3` — no longer starts a Session. Earlier catalogs wrote some of these names themselves: `deepseek-v4` on the `deepseek/deepseek-flash` preset (the default model of new Projects) and on Penguin Go's DeepSeek rows, `minimax-m3` on `minimax/MiniMax-M3`, and `gemini-3.8` on Penguin Go's Gemini rows.

An entry without a `client_type` whose id AgentHub matched by substring but which begins with no known vendor family — an owner-prefixed id such as `anthropic/claude-fable-5`, or a Bedrock id such as `global.anthropic.claude-opus-4-8` — no longer routes either. The generic client types (`openai-chat` and its `openai` alias, `openai-responses`, `ant-messages`, `openai-chat-vllm-adapter`, `openai-embedding`) are unchanged.
