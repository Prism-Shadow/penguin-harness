# Agent 的插件标签页拆为四个子页面：插件、技能、钩子与工作台

- **Date:** 2026-11-12
- **Type:** feature
- **Scope:** `web`, `ui`, `ui-gallery`, `docs`
- **PR:** [#1549](https://github.com/Prism-Shadow/penguin-harness/pull/1549)

[English](2026-11-12-agent-settings-plugin-subpages.md)

Agent 设置页的插件标签页拆为四个子页面，用标签条下方的分段选择切换，同一行右端是当前子页面的操作。每个子页面都是 `?tab=` 的一个取值：`plugins`（缺省）、`skills`、`hooks` 与 `workbenches`，被它取代的旧标签页地址因此打开对应的子页面。四个子页面共用一次对该 Agent 清单的读取。

## 细节

- **插件**一行一个列出这个 Agent 的插件，形制同钩子包的行（图标、名称及紧随其后的状态、版本、操作，不写描述；「已安装」「可安装」由分组说明，行上不再重复），分**已安装**（Agent 带有其任一部件的插件）与**可安装**（Agent 一个部件都没有、且带 Skill、钩子包、MCP Server 或工作台的库内插件）两组，页头是搜索框与**打开插件市场**。任何成员都能在行上安装和更新，Project 所有者能卸载；stdio Server 的命令、更新将改写的部件和卸载将删除的部件都先确认，同插件市场。机器上的 Agent 从那台机器的插件库安装，机器版本早于卸载接口时提示先更新机器。
- 插件详情即插件市场的详情弹窗：头部是该 Agent 上的状态，不显示「N 个 Agent 在用」，README 与文件取自 Agent 所在的服务端，另有**在这个 Agent 上**一节按类别列出部件，插件库有而 Agent 没有的部件标**缺失**；每类通往各自的子页面（MCP Server 通往工具标签页）。详情有自己的地址 `?tab=plugins&plugin=<插件名>`。
- **技能**、**钩子**与**工作台**各有自己的开关、本类全部部件的一张列表，以及取代原「导入」菜单的导入按钮；技能子页面保留技能提示词。点击一行，以只读文件浏览器（可预览、可下载；Markdown 预览不显示开头的 frontmatter，同插件详情）打开该部件在 Agent State 中自己的文件夹，先打开 `SKILL.md`、钩子包的 `README.md` 或 `hooks.json`、工作台的 `README.md` 或 `package.json`；不列以 `.` 开头的条目与 `node_modules`，工作台的**打开**仍是进入应用的入口。插件安装的部件在名称后带拼图标记，写明来源插件；点击它切到插件子页面、清空搜索词，并高亮该插件所在的行，不打开详情：该行滚到视野中部、焦点落在名称上，以强调色浅底加 2px 描边显示约 2 秒后淡出。移除这样的部件时，确认文案写明它由哪个插件安装。
- 插件子页面上点击插件行的任意位置都打开详情，不再只限名称。
- 工作台行的应用中心开关改名为**展示到应用中心**（原为「应用中心」；英文仍是 Show in the App Center），悬停说明写明展示到应用中心的含义；行的**更多**菜单首项新增同一设置的可勾选项，其下为分隔线，点选即写入并关闭菜单。机器上的 Agent 两者都没有。
- 共享列表行可接收行面点击（`onBodyClick`），并可标记为一次跳转落到的行（`marked`，配合 `useMarkedRow`）；组件画廊的列表行看板演示了两者。
- 钩子包行改用共享列表行，与 Skill 行形制一致。
- 智能体页上 Skill、钩子包与工作台的计数打开对应子页面，应用中心的**在 Agent 设置中查看**打开工作台子页面。
- 这里读到的应答交给插件市场的缓存，那个页面因此无需重新询问就能显示在这里做的安装。
- 文档改写为四个子页面，并写明每个开关所在的子页面。
