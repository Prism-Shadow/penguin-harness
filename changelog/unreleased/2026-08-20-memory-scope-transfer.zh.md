# 记忆分组支持整组导出与导入

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `server`, `web`, `docs`

[English](2026-08-20-memory-scope-transfer.md)

Memory 标签页上的每个作用域分组——用户记忆，以及每个 Workspace 一组——现在可以整组搬运。导出把
一组记忆下载为一份 JSON 文档，含其中全部记忆与这一组的 `MEMORY.md`；导入把这样一份文档写回任意
agent 的任意分组，于是在一个 agent 上磨出来的约定可以交给另一个，某个 Workspace 的记忆也能带到
第二台机器上。

## 文档格式

`GET /api/projects/:p/agents/:a/memory/scopes/:key/export` 返回一个 JSON 对象——`format` /
`version` / `scopeKey` / `kind` / `workspacePath` / `exportedAt`、这一组的 `index`，以及由
`{name, content}` 组成的 `files` 数组——以附件形式下载。记忆作用域里的一切本就是 UTF-8 Markdown，
因此这份文档从头到尾都是纯文本：编辑器里能读，git 里能 diff，导入之前能审。

## 导入及其代价

`POST …/memory/scopes/:key/import` 接受 `{payload, mode?, confirm?}`：

- `skip`（缺省）只写入分组中尚未存在的名字，磁盘上的内容既不被覆盖也不被删除。
- `overwrite` 覆盖同名记忆的内容，文档中没有的记忆保持不变。
- `replace` 在此之上删除文档中没有携带的每一条记忆。

会造成覆盖或删除的导入，未携带 `confirm` 时以 409 `memory_import_confirm_required` 拒绝——判据
是这次导入实际的代价而不是模式的名字，因此对空分组执行 `replace` 无需确认。Web App 在发送前算出
同一份计划，把两种破坏性模式挡在确认框之后，并逐条列出将被覆盖或删除的记忆。

索引跟随文件走：没有 `MEMORY.md` 的分组直接采用文档的索引，`replace` 同样采用；合并式导入则保留
现有索引，并为新到达的记忆追加文档里对应的索引行——正是删除时清理索引行的镜像操作。只有索引会进入
模型上下文，因此没有索引行的记忆等于 agent 永远读不到的记忆。

## 校验与权限

条目名走的是守护记忆目录里每一次写入的同一道校验：必须是普通的 Markdown 主题文件名，不含路径、
不以点开头、不是保留的索引名，解析之后再复核是否仍在目录内。以下情形整份文档被拒、一个字节也不写入：
条目名是路径或会越出目录、内容不是字符串或含 NUL、名字重复，以及超过 500 个条目、单文件 512KB
或总计 8MB 的上限。写入先落临时文件再重命名覆盖目标，因此顶着某条记忆名字的软链接会被替换，而不是
被跟随。

导出对任何 Project 成员开放——逐个文件读取本来就是成员权限；导入仅 owner 可用，与 Agent State
快照的分工一致，并由服务端强制：成员得到 403 `owner_required`，非成员在两个端点上都得到 404。

## Web App

每个分组标题在原有的「添加」入口旁增加导出与（owner 可见的）导入入口。导入弹窗列出所选文件与其中
的记忆条数，并把同名处理方式写明，完成后以提示条汇报本次导入的结果——新增、覆盖、删除各多少条。
