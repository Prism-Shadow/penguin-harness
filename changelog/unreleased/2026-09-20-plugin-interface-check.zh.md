# 插件的接口与平台的接口，交由 TypeScript 编译器比较

- **Date:** 2026-09-20
- **Type:** feature
- **Scope:** `server`, `desktop`, `scripts`
- **PR:** [#808](https://github.com/Prism-Shadow/penguin-harness/pull/808)

[English](2026-09-20-plugin-interface-check.md)

一个插件包是否仍然适配它被加载进去的平台，原先的判断方式是到平台自己的接口表里去查它提到的接口——这等于拿一份声明和它自己比较，永远不会失败。现在双方各带各的：插件带着它的包生成时的 `ifaces.json`，平台带着本代的接口表。两份表各自渲染成一份自包含的 `.d.ts`，要问的问题写成第三个文件里的赋值语句，由 TypeScript 编译器作答，而且是双向的——平台的接口必须能赋给插件所要求的，插件所提供的必须能赋给平台所要求的。

- 平台删掉的成员、或签名已不再匹配的成员，是一个加载错误，并指出模块、别名与接口；平台新增的成员不会破坏任何东西。
- 插件的表从不被替代：它没有副本的接口记为「未比较」，绝不用平台的条目来作答。（生成器目前还不会把宿主接口复制进插件的表，所以今天大部分接口都属于这种情况——日志如实说明，而不是报告通过。）
- 渲染要么无损、要么拒绝：表里无法写成 TypeScript 的表达式按名字报告，绝不放宽。
- 编译器现在是服务端的运行时依赖，在第一次需要比较时加载，依次在模块旁、正在运行的程序旁、推送的 assets 里解析。热推送把它作为 `archives/typescript.tgz` 一并带上（只含编译器入口与默认库），因为目标机器上的程序可能早于这项依赖；桌面构建把它放在服务端 bundle 旁边，因为 bundle 自己没有 `node_modules`。三处都找不到的安装上，插件照旧加载，日志会说明没有进行比较。
- `gen-ifaces`：类型为 `unknown`（或 `any`）的可选成员保持原类型。此前用 `getNonNullableType` 去掉 `undefined` 时，`unknown` 会变成 `{}`，而 `{}` 不接受 `null`。
