# 插件：插件库可以从 zip 或地址装入一个插件，也能把它导出为 zip、删除，两个对话框同时写明导入与编写规则

- **Date:** 2026-10-01
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `docs`
- **PR:** [#943](https://github.com/Prism-Shadow/penguin-harness/pull/943)

[English](2026-10-01-plugin-directory.md)

插件市场页在构建自带的包之外多了一个插件目录：管理员可以从本地 zip 或一个地址把插件装进去，插件库像对待其他插件一样列出它，它的卡片可以再导出成 zip 或删除。两个导入对话框都写明导入接受什么，以及一个插件必须是什么样。

## 装入插件目录

路由是 `POST /api/plugins/upload`（zip 随请求提交）与 `POST /api/plugins/download`（由服务端抓取一个地址），两者都仅限管理员——这个目录属于整个安装而不是某个 Project，而且装进来的插件，其钩子脚本会以服务端自己的权限运行，因此这是「给机器装东西」那一档的能力。`GET /api/plugins/directory` 读取目录那一行，`GET /api/plugins/:plugin/archive` 供任何已登录用户把用户插件导出为 zip，`DELETE /api/plugins/:plugin` 删除一个。

压缩包分两遍读，因为压缩包不一定是插件：先在中央目录里扫出全部条目名——不解压任何内容——定位插件根，之后才只解压该根之下的文件。插件根是最浅一层含 `plugin.json` 的目录，同一层出现两个就拒绝而不是猜一个；根之外的内容一律忽略，因此一个把插件包在仓库里的 checkout 装进来的是插件，而不是仓库。GitHub 的 tree 地址（`…/tree/<ref>/<subdir>`）把搜索限制到该子目录，且按路径尾段匹配，因为压缩包自带的那层 `<repo>-<ref>/` 是托管方套上去的。上限卡的是插件而不是它所在的那个压缩包：插件根之下 200 个文件、单文件 5 MB、合计 20 MB，此外上传的 zip 不超过 14 MB，下载的归档不超过 32 MB。

插件名依次取：管理员填的名字、地址自带的名字（目录地址取末段、仓库地址取仓库名、zip 链接取文件名）、插件根的目录名；必须匹配 `^[A-Za-z0-9_-]+$`，因为它就是插件落地的那层目录。内置插件已占用的名字会被拒绝——否则加载器会继续跑内置的那一份——而同名用户插件在请求带上 `overwrite: true` 之前一律答 `409 plugin_exists`，对话框用一个确认去取这个标志，而不是让管理员再选一次文件。写入任何一个字节之前，每个条目的路径都过一遍 zip-slip 检查，清单则由插件库自己的读取器校验。

安装是一次带暂存的替换，形状与 Skill 安装相同：文件先落进一个以点开头的暂存目录（加载器的扫描会跳过它），再通过插件库自己的读取器读回——读不出来的目录在提交之前就被拒绝，而不是装完之后被静默跳过——最后用一次 rename 顶替真正的目录。暂存目录会先清空，因此中断的安装留下的残留不会被并进下一次。插件库每次都从磁盘读取、不做任何缓存，所以导入的插件在请求返回的那一刻就已经在列表里、可以安装：不重启，也不需要失效任何东西。

## 页面上的用户插件目录

`<root>/plugins` 下一个插件一个目录，布局与插件包完全一致——`plugin.json`、`icon.svg`、`skills/`、`hooks/`——因此加载器不需要第二种格式，这里来的插件与内置插件一样安装、更新、卸载。页面在标题下方标出该目录，带复制按钮与其中插件的数量；来自这里的卡片在**内置**旁边带一个**用户**标签。这样的卡片可以导出为 zip；删除会在确认之后把它的目录从磁盘移除，不可恢复。导入与删除是管理员能看见而普通成员看不见的操作，页面提示里写明了这一点。

## 规则就放在它所约束的控件旁边

两个对话框末尾是同样的两份清单，因为它们描述的是插件必须以什么形状到达，而不是某一种来源的机制，打开错对话框的管理员也应当看到它们。**插件导入规则**给出可用的来源、插件根在哪里、插件名的取值优先级、大小上限以及同名时的行为——按顺序排列，因为名字的优先级正是 GitHub 仓库地址会踩的坑。**插件编写规则**则写明一个插件对即将发布它的人意味着什么：一个插件一个目录、目录名即插件名，目录里有 `plugin.json` 和 `skills/<技能名>/SKILL.md`，插件里不写账号信息（AppID、密钥、邮箱、手机号都属于使用者——从记忆或环境变量读取，作为参数传给脚本，而不是默认成自己的），目录里不放凭据。它们写在产品里而不是某个插件仓库的 README 里，因为插件比发布它的那个仓库活得久。
