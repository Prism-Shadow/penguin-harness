# 右侧栏新增「UI 设计工作台」面板：预览、选择模式、选中元素变成的载荷，以及它去往的对话

- **Date:** 2026-09-13
- **Type:** feature
- **Scope:** `web`, `desktop`

[English](2026-09-13-ui-workbench-panel.md)

对话侧栏现在可以放一个 **UI 设计工作台** 面板，与其他面板一视同仁地登记：出现在启动器扇形菜单、侧栏的
「添加面板」菜单与「打开面板」选择器里，可以停靠在任意一侧，标签页与整体布局一起在刷新后保留。把它指向
一个正在运行的 dev server，面板会把那个页面嵌进来、说明另一端是什么、在载入失败时用 Chromium 自己的说法
讲清失败在哪一类，并让你从页面里**选元素**——悬停高亮、点击锁定（那一次点击不会落到页面上）、
「暂离」把页面还给你（要选的元素藏在得先点开的菜单里时就用它）。选中之后变成什么也**摆在你眼前**：
那份冻结的**元素载荷**——在哪儿找到的、是什么、长什么样、以及让它下一轮仍是同一个元素的 `refId`——
随选随组装，逐项、以及 JSON 原文都给你看。**「加入对话」**把这份载荷送进对话——既是 composer 里的一个 chip，
也是消息正文本身：一行人话点出这个元素，接着是 fenced JSON 载荷，最后才是你敲的那句话。

## 细节

- 工作台用来内嵌一个正在运行的 dev server，并把页面里选中的元素连同**它写在哪个文件的哪一行**一起送进
  对话，让 Agent 不必先搜索就能直接动手。它读的是用户的页面，从不自己生成页面。
- 它**只在开发模式生效**：元素的来源是靠开发构建自带的 source map（内联的，或与模块并排、由模块自己点名的
  `.map`）定位的，生产构建既没有这些 map，也没有位置信息。面板会直说这件事，而不是悄悄降级。
- 它按与其他面板相同的方式登记：`features/dock/dock-state.ts` 的 `PanelKind` + `PANEL_KINDS`、
  `features/dock/panel-meta.tsx` 的名称与图标、`features/chat/chat-page.tsx` 的 `renderPanel` 分支、
  `features/workbench/` 下的面板主体，以及 `DockPicker`（`features/dock/dock-panel.tsx`）里的一行。
  最后这处值得记一笔：选择器里的条目是**手写的行列表**，不是对 `PANEL_KINDS` 的遍历，于是漏掉它的新
  种类会「处处都登记了，唯独漏掉用户最先见到的那个界面」。侧栏端到端用例现在会从选择器里打开这个面板
  ——它当初正是因此失败的。新图标 `ELEMENT_PICKER_ICON` 是「一张页面 + 落在上面的指针」。
- 面板主体**不加 `key`**，这一点与按会话切换的面板相反：工作台自己不带服务端状态，切换对话不该丢掉预览
  指向的地址。
- `test/dock-state.test.ts` 按定时任务面板的成例为新种类补了用例——在 `PANEL_KINDS` 中列出、能开进侧栏、
  能成为该侧栏的活动标签页。

## 预览

- **地址行，按浏览器 profile 记忆**（`penguin.workbench.previewUrl`，已登记进 `lib/install-scope.ts`）。
  裸 `localhost:5173` 或裸 `5173` 都会补成 URL；`file:` 等协议被拒——会去读本地磁盘的预览不是预览。
- **直接列出探到的 dev server，而不是让你猜端口**：并行探 5173 / 5174 / 3000 / 8080，各给一个 pill，标明
  它是 Vite、普通网页，还是「有服务但不让跨源读」。没人听的不列出来。
- **载入结果只说页面能给什么**：入口模块带 source map（内联的，或它自己点名的旁挂 `.map`）的 Vite 页面显示
  「精确档可用」，两种都没有的显示「只能降级」，不让跨源读的直接说明。失败行逐类命名——端口上没服务、超时、域名解析不了、对方拒绝被嵌入、
  返回了错误页、预览进程崩了——而不是把一切都叫成连接错误。
- **只在桌面壳上开 `webviewTag: true`**（`packages/desktop/src/main.ts`）：面板是全应用唯一嵌别人站点的地方。
  这是 server 交付不了的展示能力——页面是用户的、跨源、从不经过我们的 HTTP API——且它不给两侧加 Node、
  不加 preload：面板只通过客体的 DOM 事件与 `executeJavaScript` 够到它。浏览器标签页里根本没有 guest 元素，
  所以面板说的是「需要桌面端应用」，而不是给一行根本载不入的地址栏；侧栏端到端用例断言的正是这一点。
- 有两条行为是**实测出来的**，而不是想当然的——第一次真机跑就是被它们绊倒的：与插入同一帧写入的 `src` 会被
  静默丢弃（必须写在元素进入文档之前）；失败的主帧载入**仍会**提交 Chromium 的错误页、并在 3ms 后照发
  `dom-ready`，所以失败要撑到下一次导航开始为止。后者落成有 6 条用例的纯函数 reducer（`reduceGuest`），
  没有它时「没人听的端口」会被报成「已连接」。

## 选择元素

- **拾取器注入进页面自己的世界**（`features/workbench/element-picker.ts`）：一段自包含脚本交给
  `webview.executeJavaScript`——主世界，是页面自己框架数据唯一存在的地方，也是页面 CSP 拦不住我们的地方。
  回传走 `console-message`（唯一被实测证明「不需要宿主 preload」的通道）：每条消息是一行带固定前缀的 JSON，
  解析不出来的行一律丢弃，因此**页面自己的日志永远不会被当成我们的消息**。
- **悬停只画一个高亮框**：`position: fixed` + `pointer-events: none`，每帧最多移动一次，且只在光标下的元素
  变了才上报。真机实测：同一帧内 24 次鼠标移动，高亮框只重画 **2 次**。页面布局一帧都没被动过。
- **点击即选中，并阻止这一次点击落到页面上**——在捕获阶段吞掉，链接因此不跳、表单因此不交。用一个「按钮自己
  数点击数、链接会跳转」的页面验过：两件事都没发生。
- **Esc 两段式，且归焦点所在的那一侧管**：有选中就先取消选中，没选中就退出选择模式；焦点在页面里由拾取器
  处理，在面板里由面板处理。刻意**不** `preventDefault`：拾取器的职责是接管点击，不是顺手夺走页面自己的 Esc。
- **「暂离」把页面还给你**：摘掉监听器、藏起高亮框、**保留选中**，所以回来时会重新锁定同一个元素。这就是
  「藏在必须先点开的菜单后面」的元素能被选中的原因。页面里不浮任何模式开关：控件在侧栏，页面里永远只有高亮框。
- 拾取器的状态是**三个事实**的纯函数 reducer（`reducePick`，7 条用例），而不是一个模式：用户的开关
  （`wanted`，**跨页面保留**——刷新不该把用户关掉的开关又打开）、暂离（`paused`）、以及页里到底有没有拾取器
  （`live`）。合成一个模式，正是「下次导航把开关偷偷打开」这类 bug 的写法。
- 元素的事实**跟着它被读到的那一页走**：URL 与视口是**选中那一刻**在页面里读的，不是事后从地址栏推的——
  页面内部换了路由，也不会留下一份"元素其实不在那页上"的载荷。

## 选中的元素变成什么

- **冻结的 v1 载荷**（`features/workbench/element-payload.ts`，即 PRD §6）由三样东西在面板里组装：元素的 DOM 事实、
  它被找到的那一页，以及**会话的 workspace**——也就是被预览的那个项目，它是"相对源码路径不再有歧义"的唯一前提。
  `page.projectRoot` 就是那个 workspace，不是预览地址。
- **载荷原样显示给你**：`refId`、选择器、标签、角色、名称、文本、矩形、父链、类名、项目、页面、源码位置，
  完整 JSON 点一下就在手边。这个功能的承诺就是**进不了对话的东西，用户都不可能没看过**——一份看不见的载荷不叫这个。
  （做的时候量到的：JSON 默认展开会把预览从 526px 挤到 91px，所以 JSON 默认收起、事实行限高可滚。
  载荷里的 `viewport`/`rect` 是**选中那一刻**的值，面板事后变大变小都不该改写它们。）
- **`refId` 是签发出来的，不是现抓的**——`hash(规范源码位置, 语义键)`，与需求冻结的算法一字不差：FNV-1a 作用在
  `projectRoot::file:line:column` 与一个语义键上，语义键优先 `data-testid`，其次 role + 可访问名，最后是 tag + 文本摘要。
  hash 对 FNV-1a 的公开测试向量钉死，算法不会悄悄漂移。同一个元素两次选中一致，不同元素不同。
- **现在答不出来的，就老实说答不出来。** 解析源码文件需要页面自带的内联 source map，那是下一个里程碑，所以
  `source` 写 `{confidence: "none"}`（四档里最诚实的一档），而不是编一个位置。`refId` 跟着退化：规范源码位置退到
  页面 URL——所以**只靠文本命名的元素，改文案就会换号；带 `data-testid` 的元素改文案不换号**。真机里两条都验了。
- 载荷还带一句告示：它的 `cssSelector` 描述的是页面**当下**的样子。选择器是捷径，`refId` 才是耐用的把手；
  把选择器当事实的 agent，今天改对行，明天改错行。
- DOM 事实在 DOM 所在的地方采集，且一条都不猜：页面没声明、也推不出来的角色写 `null`；可访问名按真实算法的顺序近似；
  `text` 截到 200 字符；父链到 3 层；计算样式是**一次设计改动真正会动的那几个属性**，不是浏览器手里的三百多个。
- 切换对话时面板不重挂，但它记住的项目会跟着换——切换后新选的元素，不会带着上一个项目的根路径。
- 给下一个人的一个坑：`install-scope.ts` 会扫描 web 源码里所有 `penguin.*` 字面量，没被它分类的会在测试里报错，
  而载荷的判别符（`penguin.ui-element-ref`）长得很像其中一个——它是消息里的字段，从不落存储，所以现在被明确
  登记为**有意排除**，而不是被归成某个浏览器偏好。

## 元素写在哪一行

- **载荷的 `source` 是用户项目里的一个位置**——`src/Badge.jsx:2:10`——而且是**元素自己**的、不是它所在组件的：
  拿 M1 在同一个 fixture 上量到的真值表逐条对账，两行（`span.badge` → `src/Badge.jsx:2:10`、`h2.card-title` →
  `src/App.jsx:7:7`）都落在 JSX 真正被写下的那一行，`jsxSnippet` 就是那一行的原文。面板在载荷卡里显示它，
  Agent 收到的消息里带的是同一个值。
- **位置是问出来的，不是猜的**：注入进页面的拾取器去问页面自己的框架，四条路线都是**实测**出来的，不是想当然：
  React 19 的 `_debugStack`、React 18 的组件文本、Svelte 5 的 `__svelte_meta.loc`、Vue 3 的 `type.__file`。
  整个嗅探器是**一个自包含函数**，序列化后送进页面——bundler 作用域里的东西一样都不跟着走，还有一条用例
  把序列化文本**单独 eval 一遍**来证明这一点。
- **React 19 的栈整段、按序交给宿主，由宿主挑帧。** 第一帧是 React 自己的 `jsxDEV`，而它所在的预打包依赖是从
  `/@fs/…/deps/…` 提供的——**那个 URL 里根本没有 `node_modules`**，所以没有任何基于 URL 的过滤能把它和用户代码
  分开；Vite 甚至会把 React 的生产 `jsx` 打进一个**哈希命名的共享 chunk**（`deps/chunk-4S5VGXK3.js`），
  URL 里连 `react` 两个字都没有，只有它的 sourcemap 才说得清。能分开它们的是模块文本和它里面的 map，
  而那只有宿主有：逐帧映射，**跳过 React 自己运行时的帧，第一个剩下的帧就是写下这个元素的"创建者"**——
  这也正是第一版把这个功能报成 `react-jsx-dev-runtime.development.js` 的原因。创建者**在依赖里也照样报**，
  并带上 `moduleIsThirdParty`：那个位置是准的，只是改那里没用——载荷该把 Agent 送去"传参 / 包一层"，
  而不是送去用户调用这个库的那一行。整条栈**只有** React 运行时（谁也没写下这个元素）时，载荷说
  `none` + `moduleIsThirdParty`。
- **React 18 没有可用的行号，于是在组件自己的编译文本里找元素**：用括号配对扫 `jsxDEV(...)`（嵌套元素在父元素那次调用
  **里面**，所以搜索必须继续往调用内走），并跳过字符串字面量（prop 字符串里的 `)` 会提前结束一次还没结束的调用）。
  同标签、同类名 token、`map()` 出来的两个兄弟：候选多于一个就报 `ambiguous` + 候选数，**绝不报 `exact`**——
  真机实测里点那个静态兄弟，载荷落在的是 `map()` 那个兄弟身上，这正是"不许报 exact"的理由本身。
  元素**只有自己 fiber 上的** `_debugStack` 才算它的位置：祖先 fiber 上的那一段写的是祖先自己被谁创建，
  选中的元素刚好由不捕获栈的运行时创建时，拿它顶替就会把**用户渲染库的那一行**报成 `exact`。
- **sourcemap 就地读，两种形态都读，档位如实说**：模块文本用一次普通的 CORS 请求向页面自己的 dev server 取回，
  **每次选元素都现读**（见「送出去之前，再问一次页面」）；map 可以是内联的 `data:` URL，也可以是模块**在末尾点名**的旁挂 `.map`——Vite 7 在同一个页面里
  两种都用（小 chunk 内联、大依赖如 `deps/react-markdown.js` 旁挂），只读内联的那种写法会把依赖库内部的元素
  从"能定位"降成"不知道"。解码由**零依赖的 VLQ 解码器**做，且**只对问的那一行作答**——那一行没有映射就是 `none`，
  因为"退到邻近的映射"正是把"精确"变成"看着像"的那一步。`sources` 条目按**它所在的那个模块**解析
  （Vite 在 `/src/Badge.jsx` 的 map 里写的是 `Badge.jsx`，当成路径读就丢了 `src/`），再相对会话 workspace 取值。
  生产构建根本没有 map，面板把原因说出来，而不是编一个行号（见下一节）。
- **`refId` 现在由源码位置签发**，这本来就是计划：上一版的退化口径（页面 URL）已删除，所以**只靠文本命名的元素
  不再因改文案而换号**，组件跨一次编辑也保号。要提前知道的后果：**本次改动之前**加入对话的元素 chip 会换号一次，
  这次发送前重解析会把它显式暴露出来（见「送出去之前，再问一次页面」），而不是悄悄掩过去。
- **四条路线现在都是真机量过的，不只是单测。** 真桌面壳在 M1 用的四个最小项目里逐条点元素——React 19 / React 18 /
  Svelte 5 / Vue 3——**17 个元素**的载荷全部与「现读这些项目源码算出的真值表」逐字一致：6/6、4/4、3/3 是 `exact`，
  Vue 3 的四个一律 `file-only`、一个行号都没编。量这一遍还定下一条口径：**载荷的列从 1 数起**，而 Svelte 5 自己报的列
  从 0 数起，所以宿主把它挪到载荷的基准上，而不是原样透传（`src/Badge.svelte` 曾报成 `5:0`，真值是 `5:1`）。

## 定位不到的时候，说清楚为什么

- **面板的「源码位置」那一行现在说的是档位本身**，四种都明说：`精确 src/App.jsx:7:7`｜
  `只到文件 src/App.vue（这个框架只说得出文件，不编行号）`｜
  `有歧义 src/Rows.jsx:5:9（同一处写法有 2 个候选，可能是兄弟节点）`｜`无源码位置：…`。
  机器可读的 `confidence` 一个字段都没少——它仍在载荷 JSON 里，也就仍在发给 Agent 的消息里；
  人读的是这一行，Agent 读的还是那个字段。
- **四种"没有源码位置"是四件不同的事，面板分开说**：这个页面读不到 sourcemap（多半是生产构建）／这个元素由框架
  或依赖的运行时创建、不在你的项目里／这个页面的框架没有提供元素位置（未支持的框架或构建）／拿到了线索但这个位置
  没能映射回源码。判据的顺序是定的：**页面级的事实先说**——同一页上任何元素都定不了位，那就是页面的事，不是这次
  点中的元素的事——再轮到元素自己的。说原因而不是说"没有"，是因为这四种各自指向不同的下一步。
- **降级不阻断。** 在一个**真的生产构建**（`vite build` 出来的页面，用 `vite preview` 按生产的方式伺服）上跑完整条：
  状态行点名「读不到 sourcemap」，载荷是 `confidence: "none"` 且**一个文件都没编**，那一行把原因说清楚；
  同时选择、加入对话、发送全部照常，DOM 那半张载荷（选择器、类名、`24px` 的计算字号、文本）原样齐全——
  Agent 就是靠它去源码里搜的。真机断言里还有一条"这条消息真的发出去了"，而不只是"按钮没灰"。
- **还没问出答案时说的是"正在定位"，不是"没有"。** 解析是异步的，从选中到答案回来之间面板还不知道源码在哪，
  这段时间说"没有源码位置"就是在声称一件没人量过的事。
- **"正在定位"这一瞬，卡片绝不会说成上一个元素的位置。** 解析结果是**按选择本身（页面 URL + 选择器）加键**存着的，
  换一个元素时，属于上一个元素的那个答案就不再被采用——那几帧读作"正在定位"，而不是"新元素配旧文件行"。
  这一条是量出来的：真机上交替点两个元素，把**每一次卡片 DOM 变更**和**每一个动画帧**都记下来（改前 9/19 条、
  8/18 条张冠李戴，改后 0/19、0/9），而不只是比对收敛后的值（`实测脚本/m54-卡片归属/`）。
- **「它支不支持我的项目」在面板里就能问到**：还没载入任何页面时，面板里有一块**「支持范围（L1）」**，
  默认收起，展开是五行 —— 精确到行列的框架（React 19 / React 18 / Svelte 5，配 Vite 实测）、只到文件的框架（Vue 3）、
  降级档（webpack / Next.js 这类还没实测的构建、以及任何生产构建）、选不到的结构（shadow DOM 内部、iframe 里面）、
  第三方库节点（位置照给但在依赖自己的文件里）。**这些行写的是量过的结果**，不是框架自己的宣称：真机测过两种
  语言下都同形，且没实测过的框架只出现在"降级"那一行（`test/workbench-copy.test.ts` 把这条钉住）。载入页面之后
  这块让位给状态行 —— 那时说的是**这个页面自己**的档位，比静态清单准；预览区高度也没被它吃掉（`实测脚本/m55-支持范围/`，8/8）。
- **档位行本身的口吻也改准了**：从「精确档可用」改成「页面带 sourcemap：能否精确到行，选中后看载荷那一行」。
  页面有 map 不等于这个元素能到行——Vue 3 就是活例子：它的页面带 map、精确档的前提成立，而框架只说得出文件，
  载荷如实报 `file-only`，面板那一行写「只到文件」。把这两句话都摆出来，比只让其中一个说话诚实。

## 够不着的地方，说清楚是哪一种

有些地方首批**不去**（PRD §2.3）：shadow DOM 内部、iframe 里的文档、第三方组件库内部节点、当前看不见的元素。
划出去不是问题，**不吭声才是问题**——用户点了一个东西，面板要么给对，要么说清楚为什么给不了另一种，绝不能把
邻居当答案递过去。现在这四种各有一条自己的话，而且是在**撞上它的那一刻**说：

- **点进 shadow DOM 里，面板会告诉你给你的是外层宿主。** 页面自己的 DOM 树在 shadow 宿主那里就停住了
  （实测：指针落在 shadow 内部时，`document.elementFromPoint` 返回的就是宿主），所以选中给的是宿主
  `shadow-widget`，连带它的真实源码位置——宿主确实是一个真元素、也确实在 `src/App.jsx` 里。面板那一行说
  「这个元素在 Shadow DOM 内部：L1 不穿透 shadow root，给你的是外层宿主 shadow-widget——要改样式就改宿主，
  或者在组件里传参。」**唯一给不了答案的是只开了一半的 shadow root**（closed），它在外面看起来和普通宿主一模一样，
  这一点写进产品说明，不当成能做的事。
- **iframe 里的东西根本点不到，所以面板提前说。** 拾取器装不进 frame 的文档，所以那里面的元素不是"选中之后提示
  不支持"，是**点不到**。于是**一开始拾取**面板就说「这个页面里有 N 个 iframe：L1 不进入 frame 内部，那里面的元素
  选不到。」（每次导航重新数，停止拾取就收回）；而点到 iframe 元素本身时——**边框**是父文档画的，只有它点得到——
  面板说「这是 iframe 元素本身，它里面是另一个文档：L1 不进入 frame 内部——请让那个页面单独打开，再对它开一个预览。」
- **看不见的元素按它自己的事实说。** `opacity: 0` 的元素**照样能被点到**，所以"它其实看不见"这件事只能由面板说：
  「你选中的元素现在是 opacity:0——占着位置但完全透明。」四种情形各一句（`display:none`、`visibility:hidden`、
  `opacity:0`、尺寸 `0×0`），并且把怎么做也说清楚：「先『暂离』把页面操作到它可见（展开下拉、打开模态），
  再『恢复选择』重新点它；L1 不会替你展开。」「暂离」那一行本身也改准了，点名下拉、模态、悬停浮层都可以点开。
- **库内部节点：位置照给，再补一句"这是谁的"。** 元素由依赖库自己造出来、位置落在它的文件里时（例如 react-markdown
  造的标题），行里仍然写「精确 `<依赖自己的文件>:381:18`」，后面追加「库内部（依赖自己的文件，改它不算数：
  给组件传参或包一层）」——「在哪」和「是谁的」是两个答案，两个都要给。
- **同一句话也告诉 Agent。** 载荷的 schema 是冻结的（§6 v1），这一轮**没有**为它加字段：面版上那段话给**人**看，
  而消息正文的行首多了一句从句给 **Agent** 看——「选中的 UI 元素：shadow-widget（页面 …）——这是 Shadow DOM 的
  宿主元素，你点的那部分在它的 shadow root 里（L1 不穿透）」。两处用的是同一个判据，所以不会互相打架。

## 把选中的元素放进对话

- **「加入对话」把元素变成 composer 本就认识的「引用」**——一种新的 `ComposerReference`（`kind: "element"`），
  结构与选中的文件/目录同形，所以 chip、发送路径，以及它们下游的一切**只有一条代码路径，不是两条**。
- **chip 用「人话」命名，而不是用一个它还没有的路径**。文件有路径，所以 chip 取最后一段；选中的元素**还没有**
  workspace 路径（那是下一个里程碑的活），于是引用改带一个 `label`——元素自己的描述（`span.badge "hello"`），
  chip 有 `label` 就优先用它。chip 的 tooltip 追加元素的 `refId`，那是唯一能说明**是哪一个**元素的东西。
- **同一元素放两次是「更新它的 chip」，不是多出一个。** 去重按 `refId`，且是**就地替换**而非忽略第二次：
  你要是改了元素又重新选了一次，chip 带的是**新载荷**，不是你一分钟前放进去的那份。
  （`stageReference` 是有用例的纯函数，绝不改动入参；没有 `refId` 的引用——文件或目录——仍按原来的追加行为。）
- **载荷从不进输入框**：它在发送时才被拼到消息上，composer 里只有你敲的字——**实测**两个元素 staged 时草稿依然为空，
  所以你可以先删掉一条引用再发，而不必在自己那句话里找 JSON。
- **消息正文 = 一行人话点出元素 + fenced JSON 载荷 + 你那句话。** 真机实测：两个元素共 **3769 字符**（约 1.9 KB/个），
  你敲的句子在最后，两段 JSON 都能解析、`refId` 与面板一致。引用拼在**你敲的字之前**（它们才是消息的主体），
  选了技能时 `[use_skills]` 包装留在**最外**，所以一条消息可以同时带两者。
- **chip 只显示摘要，不做载荷的折叠预览**；完整载荷在面板的载荷卡上读。它带的是**加入对话那一刻**的快照，
  但那份快照不是最终答案——发送之前会再问页面一次（见下一节）。

## 送出去之前，再问一次页面

- **消息带的，是页面此刻的说法。** chip 里那份载荷是选中那一刻的快照，而用户的 dev server 每保存一次就热更一次；
  发送前 composer 会拿 chip 的 `cssSelector`（带上它自己的 `data-testid`，如果有）回到页面重读一次，重新组装一份
  载荷再拼进消息。真机实测两条：给 `<h2>` 上方插一个空行之后发送，消息里的位置是**移动后的新行号**
  （`src/App.jsx:8:7`），而 chip 快照里明明白白是旧的 `7:7`；给同一个元素加一条内联颜色之后发送，消息里的
  `color` 是新值（`rgb(11, 22, 33)`），快照里是 `rgb(0, 0, 0)`。
- **同一个元素的判据是"同一条路径上还是同一个东西"**：路径命中的节点标签相同、且它自己的 `data-testid`（有的话）
  相同，就是同一个；**刻意不比对语义键** —— 语义键里含可访问名，改文案就会变，而"被改了文案的那个元素"显然还是
  同一个元素。代价已知：结构大改之后，同标签的另一个节点可能顶替它；带 `data-testid` 的元素不受影响。
- **页面里已经没有它了，这条就扣住不发。** 元素消失（`missing`）、那个位置上换成了别的元素（`replaced`）、
  或者预览已经切到另一个 origin（`page-changed`）——三种都**不发出那份已被页面否定的载荷**：toast 说清是哪个元素、
  为什么，面板上同一句话再出现一次，composer 里那条 chip 就地标红并写「已消失」，**你敲的那句话原样留在输入框里**
  （扣住是不替你发，不是替你清空）。真机三个分支各断了一条「消息一条不涨」，并且切回原页面之后再发一次就能发出去。
- **拿不到答案的，明说是"没核对过"**：没有预览页面、页面里没有拾取器、或跨源够不着——这种 chip 保留它自己的快照
  发出去，面板不宣称核对过。**唯一不做的事，是声称一次没有量过的"新鲜"。**
- **元素移动之后 `refId` 会换号**，这是签发算法的口径本身（位置进了哈希），预期之内；chip 就地换成新的那一个，
  面板与消息在这一点上永远一致。
- **预览切走再切回来，同一条 chip 是活的**：切到另一个 origin 会把它标成已消失，切回原页面之后再发一次就发得出去，
  重新解析出的是回来之后的位置——作废是一次核对的结果，不是一次性的封杀。
- **面板卡片读的是"现在"的模块文本。** 这一条是真机上跑出来的一个上一里程碑的遗留 bug：模块文本原先按 URL 缓存，
  而 dev server 在**同一个 URL 上**就服务新文本，于是保存之后重新选元素，卡片还停在保存前那一行——用户眼前的证据是假的，
  而消息里是对的。现在每次选元素都现读，卡片与消息说的是同一件事（同一个断言从"卡片仍是旧行号"变成"卡片跟着新行号"）。

## 一个源码位置背后的四件事

"源码位置"听起来是一个事实，其实是好几件。面板现在在**还没指向任何页面**的时候就把"能给什么"列出来，
并且在框架支持矩阵下面列出**每个位置都带着的四条边界**：

- **位置指的是这段 JSX 写在哪儿，不是某条 CSS 规则在哪儿。** 载荷给的是元素在你源码里的文件、行、列；
  而你要的改动如果是样式，CSS 规则可能完全在另一个地方。
- **改样式时可能落在样式表里，那不算位置给错了。** 盲测里四次复跑四次都是这样：让改一个颜色，agent 改的是
  样式表里的规则，不是 JSX——页面按你要的变了。递给你的那一行是元素自己的 JSX，改在哪儿是 agent 的判断。
- **「有歧义」的那一个，可能指到包着你的那层元素上。** 源码里有些写法让多个兄弟节点共用一处位置，
  于是活下来的位置是外面那层（实测：真实项目上 33 个这样的选中里 24 个如此）。那一行会这么说，
  而不是假装自己是精确的。
- **回传走的是页面自己的 console，页面可以伪造一条。** 拾取结果用最便宜、不需要 preload 的方式回来：
  console 上一行带我们前缀的消息。页面自己也能写出那一行——所以载荷**先摆给你看**，你不点「加入对话」
  它哪儿都不去。要彻底堵住就得动应用的安全边界，首批**故意不做**；文案就照实这么说，
  不把这条通道说成是鉴权过的。

这四条与框架矩阵在同一块折页里，而且都有单测钉着——后来的改动没法悄悄把它们说软。

## 不碰用户的项目

- **用户的项目只读，从不写。** 在一个**真的 git 仓库**上实测：整条流程——开面板、载入预览、选中元素、加入对话、发送——
  之后 `git status --porcelain` **仍为空且逐字相同**，7 个文件的 sha256 一个都没变：没有新增、没有删除、没有改写。
  验收用的 Vite dev server 也把缓存指到临时目录，理由相同：一个帮你读页面的工具，没资格往里面丢文件。
- **工作台自己的状态落在我们这边**：它记住的预览地址在**宿主 profile 的 local storage**（`penguin.workbench.previewUrl`），
  与其他面板的状态同一个地方；用户项目里没有对应文件。
- **没有任何东西发出去。** 整轮里用 Electron 自己的请求监控（挂到所有 session）看到的 **93 条**请求只去了**六个 loopback host**，别处一个没有：
  我们自己的 app server、工作台自己的端口探测（5173/5174/3000/8080）、以及用户的 dev server。判据是**loopback 白名单**而不是
  "没有请求"——端口探测是我们自己的正当流量；并且配了一条"清单非空且含 dev server"的断言，**让"什么都没看到"的监控不能靠沉默过关**。
- **页面够不到宿主**：客体自己的主世界里 `require`、`process`、`window.ipcRenderer`、`window.electron`、`module` 全是 `undefined`，
  页面加载的资源也全部来自 loopback。拾取器回话只用一个通道：页面自己的 console——这正是它便宜、不需要 preload 的原因。
- **注入脚本本身没有任何"对外"的手段**：交给客体的那段文本会被检查是否含网络原语（`fetch`、`XMLHttpRequest`、`WebSocket`、
  `EventSource`、`sendBeacon`、动态 `import`，以及任何 `http(s)`/`ws(s)`/协议相对 URL）与宿主或存储能力（`require`、`process`、
  `ipcRenderer`、`postMessage`、`localStorage`、`sessionStorage`、`document.cookie`、`eval`）——以**单测**的形式钉在序列化文本上，
  而那段文本正是客体要 eval 的东西，所以**往 installer 里加一个原语躲不过它**。用例同时断言这段源码是真东西、不是空字符串
  （空字符串能通过所有"不含"检查）。
- **页面在我们的通道上说话，推不动面板**：console 是共享通道，所以解析只接受**我们的前缀 + 我们认得的 kind**——
  一行普通页面日志、一行"前缀 + 坏 JSON"、一行"前缀 + 未知 kind"，面板都**原地不动**。但有一点要提前知道：
  **这条通道没有鉴权，页面可以伪造拾取器消息**。其影响面是：它能改面板**显示**什么，而在用户明确点「加入对话」之前
  **什么都进不了对话**——载荷先给用户看，才可能被发出去。
