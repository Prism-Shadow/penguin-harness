# Ctrl+F 搜当前区域，Ctrl+Shift+F 搜整个窗口

- **Date:** 2026-10-06
- **Type:** feature
- **Scope:** `web`, `ui`, `docs`
- **Issue:** [#991](https://github.com/Prism-Shadow/penguin-harness/issues/991)

[English](2026-10-06-chat-find.md)

应用内查找栏：`Ctrl+F` 搜索焦点所在的区域，`Ctrl+Shift+F` 一次搜索屏幕上所有区域并列出命中，
`Escape` 关闭。全程不向服务端发请求——每个命中都在已经渲染出来的 DOM 里找。

## 细节

- **区域靠主动声明。** 在滚动容器上写上 `data-find-region="<kind>"` 就是一个可搜索区域，除此之外
  没有别的要求：主对话、子会话面板里的对话、侧栏的会话列表、文件面板都带了这个属性。Ctrl+F 把焦点
  元素解析到最近的这类祖先；焦点不在任何区域里时（输入框、工具栏）回退到对话，而不是文档顺序里的
  第一个区域。
- **高亮走 CSS Custom Highlight API**（`::highlight(penguin-find)` / `::highlight(penguin-find-current)`），
  因此它从不包裹或拆分被标记的文本节点，其下的重渲染也不可能继承一棵被切开的树。
- **打字不会滚动页面。** 计数每次按键都更新，但在一段边流边读的对话里，跟随每个字符滚动的页面是跟
  读者较劲的页面。回车、上/下按钮、点击结果行是三种移动方式，且第一次按回车只是把你已经选中的那条
  展示出来，第二次才走到下一条。
- **`Aa` 区分大小写**，计数显示 `3/12`（无命中时显示「无结果」）并通过 `aria-live` 播报，
  `Enter` / `Shift+Enter` / `Shift+F3` 分别向后、向前步进。
- **搜索会展开被折叠的内容。** 轮次分组只在展开时挂载自己的行（`features/chat/work-group.tsx`），
  所以查询生效期间会挂载所有可折叠主体（`lib/find-expand.ts`），折叠分组里的命中是命中而不是看不见
  的文字。分组自身的展开状态不受影响，因此关闭查找栏后页面原样恢复。
- **聚合列表**每个命中一行——区域标签，加上命中前后各 40 个字符，超出用省略号截断——最多画 50 行，
  其余只计数不渲染。底部一行范围按钮把搜索放宽到所有区域，也能收回 Ctrl+F 一开始的那个区域。
- **从未加载过的内容是这个功能唯一修不了的东西，而它会说出来。** 知道自己还有更早历史的区域带
  `data-find-more` 属性，它会变成「更早的内容尚未加载 · 加载并继续搜索」那行：点击后触发该区域自己的
  滚动入口会触发的那次回填，窗口落位后搜索**向上**从读者原先所在的位置继续，而不是跳到对话开头。
- **重建索引由 DOM 变更驱动并做了防抖**，因为对话会在搜索脚下流式变化，索引过期是常态而不是错误：
  文档变更安静下来 300ms 后重新遍历，在一段永不停止的流里也至少每 1.5s 遍历一次。查找栏自己的面板被
  排除在这个观察器之外；已经离开文档的命中有一次重建索引的机会来落位，之后才会放弃它。
- **对话框里的 Ctrl+F 交给浏览器。** 对话框里的表单是 Ctrl+F 唯一该表示浏览器自带查找的地方，在那里
  抢走它并不受欢迎；只要存在 `[role="dialog"][aria-modal="true"]`，查找栏自己的窗口级处理就不介入。
  查找栏本身是一个 Escape 层（`components/ui/modal.tsx`），所以 Escape 先关掉它而不是它下面的东西
  ——而盖在它上面的对话框会先拿到那次 Escape。
- **配套改动**：`@prismshadow/penguin-ui` 中的 `FileTree` 与 `SidebarFrame` 新增可选的 `findRegion`
  属性，让文件面板与会话列表可以声明区域而其他使用方不必跟着声明；`packages/docs/content/chat.en.md`
  / `chat.zh.md` 记录了两个快捷键。
