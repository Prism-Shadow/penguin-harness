# 已退出的进程可移除、复制只用图标反馈、轨迹文件行改为单行

- **Date:** 2026-08-18
- **Type:** fix
- **Scope:** `web`, `server`, `docs`
- **PR:** [#327](https://github.com/Prism-Shadow/penguin-harness/pull/327)
- **Issue:** [#312](https://github.com/Prism-Shadow/penguin-harness/issues/312)

[English](2026-08-18-session-details-and-copy-ux.md)

对话会话详情卡及其周边复制控件的三处修复：已退出的后台进程可以从进程列表移除，复制按钮只以图标确认，轨迹文件行改为单行显示文件名。

## 已退出的进程可移除

详情卡的会话进程列表会保留命令已经退出的条目。这些行新增了「移除」按钮，点击即把条目从列表删掉；运行中的行保留原有的「停止」按钮（照旧是先杀停再移除），并有意不提供移除。

- 新增 `DELETE /api/sessions/:sessionId/processes/:processId`：204 表示已退出的条目已移除，进程仍在运行时返回 409 `process_running`（应改用停止），id 未知或运行时已不在时返回 404 `process_not_found`。移除复用了作用在已死条目上的 kill 路径，与 `input_command` 在进程退出后的回收一致。
- 移除立即生效且不可撤销：条目会连同该进程已捕获的输出一起离开运行时注册表，此后对该 `process_id` 调用 `input_command` 会报告 `process_id` 未知。没有加确认步骤——按钮的 tooltip 与 Web App 文档会说明这一行会带走什么。
- 文档中的 session 端点表补上了全部三条 `/processes` 路由；此前 GET 与 kill 的 POST 都没有写进文档。

## 复制按钮只用对勾图标确认

复制成功后，每个复制按钮都会把复制图标短暂换成对勾，并把 tooltip 翻成「已复制」。那个一闪而过的「已复制」**文字标签**在各处都去掉了——它此前出现在 Session id 行和 Agent State 路径行的对勾旁边。记忆标签页与技能导入对话框的「复制 Prompt」按钮从 toast 反馈改到同一套约定上：只翻转图标，可见的文字标签保持不动；它们原先用的 toast 文案也一并删除。

- 图标切换是无声的，因此每个复制控件旁边还会渲染一个视觉隐藏的 polite live region，把这次确认播报给屏幕阅读器。可访问名称仍是复制这个动作本身。
- 连续点击时每次都能拿到完整的闪现窗口：待执行的复位定时器会被重启，而不是沿用上一次点击留下的那个。在这个窗口内被卸载的控件——轨迹文件那一行点下去会把详情卡本身关掉——也不会再遗留定时器。

## 轨迹文件行只显示单行文件名

详情卡的轨迹文件行不再把完整绝对路径折成好几行，而是只用一行显示文件名。完整路径移到了 tooltip，以及文件名旁边新增的复制完整路径按钮上；点击文件名仍然跳转到聚焦本会话的轨迹观测页。
