# 组织员工的 Agent 不可删除，已删除的 Agent 不再打开别的对话

- **Date:** 2026-10-10
- **Type:** fix
- **Scope:** `server`, `web`, `ui`, `docs`
- **PR:** [#1027](https://github.com/Prism-Shadow/penguin-harness/pull/1027)

[English](2026-10-10-company-employee-agents.md)

删除组织员工所用的 Agent 后，员工仍留在组织图上，它的工位指向一个已不存在的会话；在公司模式点这个工位，打开的却是最近的一条开发模式对话。现在任职中的 Agent 不能删除；对于 Agent 已经不在的员工，界面会标出来并且不能打开；链接指向不存在的会话时，页面原地说明。开发模式把员工和其他 Agent 分开列出，组织图也可以设置员工的思考等级。

## 细节

- **服务端**：只要本 Project 有组织雇用该 Agent，`DELETE /api/projects/:p/agents/:a` 就答 `409 agent_employed`，消息写明每个组织和头衔。已暂停的组织同样算在内。`org_chart.yaml` 无法解析的组织只保护它的 CEO（`<org_id>_ceo`）。
- **服务端**：`GET /api/projects/:p/agents` 为每个 Agent 附上 `employments`（组织 id 与名称、头衔、状态），不是员工的 Agent 没有这一项。
- **服务端**：组织图里引用的 Agent 已不存在的条目带 `agentMissing`。会话已不存在的工位不再出现在组织图的 `desk` 和组织会话列表里，直到对账为它开出新的工位。组织的文件不会被改写。
- **Web**：**智能体**页把员工列在**公司模式员工**一节，卡片写明所在组织和头衔，删除按钮置灰，悬停说明原因。新建对话与 `/agent` 的选择器把员工排在最后，用同一个标签分组。侧边栏的 Agent 分组不再列出没有开发对话的员工。
- **Web**：在公司模式下，Agent 已删除的员工在组织图和**工位**分组里标为**Agent 已删除**，工位不能打开，菜单只保留不依赖 Agent 的项；用**离任**即可移出。被删除的若是 CEO 的 Agent，组织图会提示重新创建同 id 的 Agent。
- **Web**：服务端对会话链接答 404 时，页面显示**会话不存在或已被删除**，并提供**新建对话**（公司模式下为**回到组织概览**），不再改为打开最近的对话。删除当前正在看的会话后，仍然跳到最近的对话。
- **Web**：组织图的员工菜单新增**设思考等级**，写入员工 Agent 配置的 `model.thinking_level`。当前工位会话单独固定了等级时，对话框会说明。在工位对话里选的思考等级仍然只固定那一个会话。
- **UI**：`PickerList` 新增可选的 `groupLabel`，在一组行的第一行之上标出这组的名称。
- **文档**：公司模式页说明了员工就是 Agent、删除保护、**Agent 已删除**的标记和思考等级；智能体页补充说明员工不能删除。

已经存在「Agent 已删除」条目的组织不需要任何操作：在有人让这名员工离任之前，条目一直显示**Agent 已删除**。
