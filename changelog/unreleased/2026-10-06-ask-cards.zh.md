# 助手回复可以提问，并画出一张可回答的卡片

- **Date:** 2026-10-06
- **Type:** feature
- **Scope:** `web`
- **Issue:** [#991](https://github.com/Prism-Shadow/penguin-harness/issues/991)

[English](2026-10-06-ask-cards.md)

助手回复中要求用户做选择的问题，现在会就地渲染成一张可回答的卡片：一卡一问，单选或多选，恒有一行
自由填写，右下角是「跳过 / 提交」。一轮问多个问题时全部画出，并额外提供一次「全部提交」。答案以一条
普通用户消息发出——没有新的消息类型，没有待答请求协议，也没有让智能体卡在里面的某一轮。

## 细节

- **形状是一个围栏块** ` ```ask `，其正文按行书写：`title:`（必填，问题本身）、`select: single|multi`、
  编号选项行、以及用选项编号指名推荐项的 `recommend:`。无法识别的 info string 会退化成普通代码块，
  因此早于本功能的客户端会显示原文而不是丢掉它；正文解析失败时（没有 title、选项少于两个、选项编号
  重复）也把围栏留在消息里，而不是画一张坏卡片。未知的键被忽略，后续版本可以加键而不破坏当前版本。
- **末尾那行「其他」不是作者写的。** 每张卡片都会拿到一行，所以「要记得写它」这条指示既不可能被忘记，
  也不可能被写两遍。
- **卡片从不预选它推荐的选项。** `recommend:` 只是在那一行加一个浅蓝色 `推荐` 小标，仅此而已：预选会
  把一次误双击「提交」变成用户从未给出的答案。多选卡片完全忽略 `recommend:`——「全都要」不是推荐。
- **提交会拦下空答案**并就地提示（「请先选择一项，或点「跳过」」），因为「跳过」才是刻意放弃的方式。
  跳过把该问题记为已作答但跳过（`跳过，未作答`），而不是悄悄采纳推荐项，这样模型才分得清"用户放过了"
  和"用户从没看见"。两者都走输入框用的那条发送路径；发送失败时草稿保持可编辑，由发送方自己的错误提示
  说明原因。
- **一条消息可以带多张卡片。** 每张各自提交；只要还有未作答的卡片，这条消息同时提供一个「全部提交」
  按钮和 `n/m 题待回答` 计数，且只在剩余卡片全部有答案后才可用。
- **卡片在该轮结束之后才能回答**：流式输出期间这个块还在被写，因此消息按普通 Markdown 渲染，卡片在
  该轮落定后出现。随之而来的代价说清楚：智能体无法在同一轮内等待回答——它结束这一轮，把回答当作下一轮
  读进来。卡片提交后会显示已提交的内容并提供「重新回答」，因为提交无法撤回。
- **子会话的转录同样展示卡片**，但行是惰性的：子智能体面板里没有任何东西能代表那段对话发消息。
- `test/ask-block.test.ts` 覆盖解析器、切分器和拼接出的答案；卡片本身带
  `data-ask-card="pending|sent|readonly"` 属性，那正是通知链路读取的钩子。
