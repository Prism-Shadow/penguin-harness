# 官网新增下一版公司模式的规格草案 /company

- **Date:** 2026-11-13
- **Type:** feature
- **Scope:** `landing`

[English](2026-11-13-company-spec-page.md)

penguin.ooo/company 是下一版公司模式的规格草案，沿用 /amsp 的页面结构，用一个页面说明这个模式是什么：人只和一个主理 Agent 说话，工作记成工单，每张工单由它自己的工作会话完成，工单只在等人接受、回答或验收时找人。已发布的公司模式没有变化，页面链接到它的文档。页面不在顶栏和页脚里，通过地址访问。

## 细节

- **播放器。** 首屏分三段重放同一个收件箱的一天：一次提出两张工单的巡检、一次停在一个问题上的要求，以及一次交付。每一段都从上一段留下的收件箱开始。左栏逐条列出事件（时间、谁做的、做了什么）；让工单开始等人的事件带琥珀色底。右栏是这个人的收件箱，等他的排在最前，下面是这一段那张工单的文件：路径（所在目录就是状态）和这一段写入的字段。
- **各节内容。** 三个角色（人、主理 Agent、工作会话），各自做什么、不做什么，以及退到工单背后的东西（员工、频道、手册、组织图）。一张工单的一生画成同一条时间轴上的条形图：等人的几段、Agent 进行的几段、工作会话，以及人的三次操作。工单文件逐个字段：一个示例，然后是 frontmatter、正文各节和按人保存的处置，每个字段写明类型、谁写、已发布的格式里有没有。服务端强制的规则，逐条编号，各带被拒绝的写入得到的回答，以及现在是否已经强制。四步的初始化，以及它所依据的文档链接。
- **规格给工单新增的内容。** 三个 frontmatter 字段（`source`、`ask`、`deliverables`）、一个 `## Decisions` 节，以及三个按人保存、不写进文件的处置值（`unread`、`snoozed_until`、`archived`）。五种状态不变。「等人」从它们读出：`proposed`、`review`，或 `in_progress` 且 `blocked_by` 是一个人。
- **每类内容只在一处。** 状态、等待规则、收件箱排序、字段和规则在 `src/lib/company-spec.ts`；脚本化的一天和画成图的工单一生在 `src/lib/company-demo.ts`，由 `test/company-demo.test.ts` 按规格的规则检查。
- **共用的重放外壳。** AMSP 播放器的标签页、计时、暂停控件和减少动态效果时的行为移入 `src/components/replay-frame.tsx`，两个播放器共用。AMSP 播放器的播放方式不变，标签页文字不再换行。
- **站点。** 页面单独打包、按需加载。标签页标题和描述随读者语言切换；静态外壳带有页面自己的标题和描述，分享卡片用站点的。`/company/` 已加入站点地图。
