# 官网新增下一版公司模式的规格草案 /company，附一个可以操作的原型

- **Date:** 2026-11-13
- **Type:** feature
- **Scope:** `landing`, `ui-gallery`

[English](2026-11-13-company-spec-page.md)

penguin.ooo/company 是下一版公司模式的规格草案。页面的主体是这个模式的原型，用 Web App 自己的外壳和控件搭在示例数据上，实时嵌在页面里：人把新的事告诉主理 Agent，它记成工单，每张工单由它自己的工作会话完成；工单是记录，会话是 Agent 干活时的对话。工单只在等人接受、回答或验收时找人，人也可以打开某个会话直接和它说话。原型下面列出相对已发布版本的改动、公司怎么越做越好、服务端强制的规则，以及工单文件的逐个字段。已发布的公司模式没有变化，页面链接到它的文档。页面不在顶栏和页脚里，通过地址访问。

## 细节

- **原型。** 画廊的第四个文档 `company.html`（`packages/ui-gallery/src/company`），和组件库看板一样挂在应用自己的 Provider 下。窗口分左右两栏。左栏是收件箱，也是全部导航：顶上一行「对主理说」（任何地方按 ⌘K 或 Ctrl+K 都能到），下面按状态分组，每组可以折叠，彼此同级（等你、进行中、稍后、已处理、归档），最后是日程；每张工单一行，写标题和它在问什么、交了什么或最近做了什么；等你、进行中和日程默认展开，其余默认收起。右栏显示左栏选中的内容，打开时停在第一张等你的工单上。左栏的布局和 Agent 页面的侧栏一致：上面固定的一块是「对主理说」和团队、手册、看板，下面是带自己标题的收件箱，位置和 Agent 页面的「工作区」相同。日历和财务不再是独立页面，Token 用量和花费显示在团队页（含全公司本月合计）和工单上。工单的记录和它的工作会话是同一个视图里的几个标签页；已发布的弹窗只显示阻塞原因，这里等人的工单在记录顶部接收答案：接受或驳回提议，为它唯一的问题选一个选项，验收交付或附一句话打回。团队页取代组织图：每名员工一行，写明名字、职位、汇报对象、职责、本月用掉的 Token 和花费，以及它正在做的工作会话；主理提议、还没被接受的角色列为待加入。工单、会话和看板上的署名都带职位。手册按用途分成目录、决定、教训、技能和文档：回答问题记一条决定，打回交付记一条教训，被接受的文档交付归档进来，被接受的技能工单把技能装给对应员工；每份文件链接它来自的工单，工单的记录里也列出它记进手册的文件。公司按两层循环进化：每张工单把回答记成决定、打回记成教训，被打回或被纠正的员工把要点记进自己的技能 `notes`，不需人批，团队页显示每人的一次通过、打回次数、每张完成工单的花费和自己学到的东西；每周主理按自己的定时日程复盘一次（每家公司一开始就有，默认每周一 09:00，和巡检列在一起），回看上次复盘以来关闭的工单，复盘写进手册，对比上一次的数字和上次接受的改动之后的变化，改动作为提议工单交给人；接受的技能把它所来自的教训移出手册索引。和主理的对话把读者说的话记成工单。在工作会话里，读者可以直接和干活的 Agent 说话；会话等人时，输入框上方显示和工单上相同的回答或验收区块。还没有任何东西的公司只问一句话，主理以提议工单作答。没有 Agent 在运行：页面下方的一栏在读者点击时让每个工作会话前进一步。
- **一张工单，几名员工。** 工单只有一个负责方，由它开发，还可以指定一名验证人（工单文件新增 `verifier` 字段）。有验证人的工单，负责方把每次交付交给一个由验证人工作的验证会话；验证发现的问题写到工单上，并送回开发会话，开发者也把它记进自己的技能；只有验证通过的交付才等你验收，你打回后会在新的验证会话里再验证一次。`sessions` 的每一项写明谁在里面工作、是开发还是验证，工单视图每个会话一个标签页，也这样命名（「沈知远 · 开发」「林清越 · 验证」）。团队页也列出员工在别人的工单上做验证的会话。新增一条规则：有验证人的工单，交付要验证通过才到你这里（`409 not_verified`）。
- **原型里的规则。** 它的状态（`model.ts`）遵守规格的规则：只有工单在等某个操作时，这个操作才生效；只有让工单开始等人的那一步才把它标为未读，同时把它从「稍后」里带回来；工作会话停在它的问题上，直到有人回答；答案先写进工单，再作为人的消息送进提问的同一个会话，不另开会话；打回的意见同样送进交付的那个会话；人在会话里说的话也写进工单；日程提出的工单在被接受之前不开会话，除非这个日程已被改为直接开工；等人的工单不能稍后或归档。`test/company-model.test.ts` 按这些规则检查它。
- **页面。** 开头说明这一页是什么，然后以站点的语言和明暗模式嵌入原型；窗口栏选择原型从哪个状态打开（用了一周的公司，或还没说第一句话的公司），并链接到单独打开的原型。随后四节：相对已发布版本的改动，每行写明事项、现在和规格；公司怎么越做越好：两层循环、复盘看的四条曲线（一次通过与打回、提问、重复的错误、每张工单的花费），以及手册怎样做减法；服务端强制的规则，逐条编号，各带被拒绝的写入得到的回答，以及现在是否已经强制；工单文件逐个字段，包括规格新增的三个 frontmatter 字段（`source`、`ask`、`deliverables`）、`## Decisions` 节和三个按人保存的处置值（`unread`、`snoozed_until`、`archived`）。服务端规则新增两条：员工自己的技能不被插件升级覆盖、执行改动前先打快照。「等人」从已发布的五种状态读出：`proposed`、`review`，或 `in_progress` 且 `blocked_by` 是一个人。
- **每类内容只在一处。** 状态、等待规则、收件箱视图、字段和规则在画廊的 `src/company/spec.ts`，原型按它行事，页面把它列成表。
- **共用的窗口。** 官网的实时应用窗口拆成两层：`LiveFrame` 嵌入任意一个画廊文档（按需加载、按栏宽缩放、作为页面的客人），`LiveAppFrame` 经由它继续嵌入应用界面。首页的窗口没有变化。
- **站点。** 页面单独打包、按需加载。标签页标题和描述随读者语言切换；静态外壳带有页面自己的标题和描述，分享卡片用站点的。`/company/` 已加入站点地图。
