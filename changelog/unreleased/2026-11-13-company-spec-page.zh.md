# 官网新增下一版公司模式的规格草案 /company，附一个能体验开局和日常的原型

- **Date:** 2026-11-13
- **Type:** feature
- **Scope:** `landing`, `ui-gallery`

[English](2026-11-13-company-spec-page.md)

penguin.ooo/company 是下一版公司模式的规格草案，按公司模式调研定下的轻量自治组织来写：你只跟一个主理 Agent 对齐目标，执行者和独立验证者按工单状态机推进，验证不通过自动打回，只有卡点、熔断和最终拍板进收件箱；验收按领域在各自的工作台里做，拍板和打回都写成本地文件，组织从中学习。页面的主体是这个模式的原型，用 Web App 自己的外壳和控件搭在示例数据上，实时嵌在页面里，开局和日常两段都能上手操作。已发布的公司模式没有变化，页面链接到它的文档。页面不在顶栏和页脚里，通过地址访问。

## 细节

- **开局。** 原型从还没开张的公司打开。主理先列出它在你环境里找到的机器、模型和外部 CLI，再问你要做什么：挑一张起步卡（一人公司、软件维护、科研实验、垂直业务），或直接写一句目标，也可以导入组织模板包。随后它用一张可点选的 A2UI 表单问三件事：交付哪几类活、单张工单预算、验证者打回轮次上限，并问外部事件来了要不要直接开单。答完它给出一份组织清单，确认前每项都能改：交付的活、编制（默认 1 主理、1~3 执行、1 验证，执行者的模型可换，各自的机器和权限写明）、状态机、两个上限、对外动作的审批分级、触发方式、各类活对应的工作台和第一批工单，以及两条提醒。确认后进入收件箱，第一批工单已经派出。左栏在开局时列出四步进度。
- **日常。** 也可以直接打开一家跑了一周的一人公司「浮冰工作室」，停在最要紧的那张工单上。收件箱按待拍板、进行中、已收尾分组，未发的草稿所在的行会高亮。每张工单顶部是状态条（执行、验证、待拍板、完成，各写明接手方）、预算和打回进度；下面按等你的原因给出操作：卡点是一张 A2UI 决策卡，回答写回工单，可选写进组织手册；熔断写明是预算还是打回轮次到顶，可以加预算或再给一轮、自己拍板或停掉；待验收按对外动作的分级处理（一键批准、复核后批准，或打开预填草稿自己发），也可以附意见打回；主理的提议可以采纳或驳回。工单分记录、工作台和运行记录三个标签：工作台按领域给出代码对比和检查结果、实验曲线和指标表、带版本和按段批注的长文档、合同台账和发票对账、预填的回帖草稿；运行记录是每次运行的模型、Token、缓存命中和花费，执行日志默认折叠。底栏「让时间过去」让每张工单走一步：交付转给验证者，验证不通过自动打回，到顶的工单熔断，GitHub Issue 和外部消息到了就开单。打回会记成一条教训并给对应成员的 Skill 加一版。
- **其他页面。** 「主理」是唯一提新需求的入口：说一句话，主理回一张草拟工单（执行者、验证者、工作台、上限、对外动作），确认才开单。团队页列出每名成员的角色、机器、模型（可换）、权限、一次通过率、返工和单张花费，可以导入导出组织模板包，并说明外部 CLI 是扩展方向。规则页是状态机、预算和打回上限、对外动作分级和触发开关，以及三条不做的事。手册与技能页列出拍板记下的决定、打回记下的教训、每名成员的 Skill 版本（可回滚）和组织文件。复盘与评测页按成员列出一次通过率、返工和单张花费，「现在复盘」会让主理提一张优化工单，下面是 Shared RSI Community 的组织模板评测表。原型右侧的「体验清单」列出开局 4 项和日常 11 项操作，做过的会打勾，也能从任一段重新开始。
- **原型里的规则。** 状态（`model.ts`）遵守规格的门禁：只有当前状态的接手方能推进工单；未经验证的交付不进收件箱；打回到上限或花费到预算时服务端熔断；对外动作在你批准前不执行；回答先写进工单再交回会话；改 Skill 或模型前先存快照。`test/company-model.test.ts` 按这些规则检查它。
- **页面。** 开头说明这一页是什么，然后以站点的语言和明暗模式嵌入原型；窗口栏选择从开局还是日常打开，下面并排列出两段各可以试什么，各带一个从这里开始的按钮。随后六节：架构图（主交付流水线、状态机里的自动打回、双层自进化）和初版的四个问题与这一版的回答；从 T3 Code、Lody、Raft、Multica、Grok Bot 各借了什么、怎么落地、在原型的哪里；边界（自治交付组织和现实公司镜像分开做，四件不做的事，外部 CLI 作为扩展方向）；现有产品没解好的两个问题（通用工单和专业验收、组织怎么越跑越稳），附五种工作台和复盘看的三项指标；服务端硬门禁十三条，各带被拒绝时的回答，以及初版是否已有；工单文件逐个字段，以及「等你」从字段推导的四条规则。
- **每类内容只在一处。** 状态、接手方、转移、等待规则、收件箱分组、对外动作与分级、工作台、触发、字段和门禁在画廊的 `src/company/spec.ts`，原型按它行事，页面把它列成表。
- **共用的窗口。** 官网的实时应用窗口拆成两层：`LiveFrame` 嵌入任意一个画廊文档（按需加载、按栏宽缩放、作为页面的客人），`LiveAppFrame` 经由它继续嵌入应用界面。首页的窗口没有变化。
- **站点。** 页面单独打包、按需加载。标签页标题和描述随读者语言切换；静态外壳带有页面自己的标题和描述，分享卡片用站点的。`/company/` 已加入站点地图。
