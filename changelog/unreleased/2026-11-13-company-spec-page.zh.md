# 官网新增下一版公司模式的规格草案 /company，附一个可以操作的原型

- **Date:** 2026-11-13
- **Type:** feature
- **Scope:** `landing`, `ui-gallery`

[English](2026-11-13-company-spec-page.md)

penguin.ooo/company 是下一版公司模式的规格草案。页面的主体是这个模式的原型，用 Web App 自己的外壳和控件搭在示例数据上，实时嵌在页面里：人只和一个主理 Agent 说话，工作记成工单，每张工单由它自己的工作会话完成，工单只在等人接受、回答或验收时找人。原型下面列出相对已发布版本的改动、服务端强制的规则，以及工单文件的逐个字段。已发布的公司模式没有变化，页面链接到它的文档。页面不在顶栏和页脚里，通过地址访问。

## 细节

- **原型。** 画廊的第四个文档 `company.html`（`packages/ui-gallery/src/company`），和组件库看板一样挂在应用自己的 Provider 下。侧栏固定收件箱、主理和看板，把规格没有改动的四个页面收进折叠区，下面只列正在运行的工作会话。收件箱取代概览：一行写明进行中的数量和已用成本，一个按读者自己的视图筛选的控件（等你、进行中、稍后、已处理、归档），下面是日程，每条带一个让它提出的工单直接开工的开关。工单在已发布弹窗的框架里打开；已发布的弹窗只显示阻塞原因，这里等人的工单就地接收答案：接受或驳回提议，为它唯一的问题选一个选项，验收交付或附一句话打回。和主理的对话把读者说的话记成工单。还没有任何东西的公司只问一句话，主理以提议工单作答。没有 Agent 在运行：页面下方的一栏在读者点击时让每个工作会话前进一步。
- **原型里的规则。** 它的状态（`model.ts`）遵守规格的规则：只有工单在等某个操作时，这个操作才生效；只有让工单开始等人的那一步才把它标为未读，同时把它从「稍后」里带回来；工作会话停在它的问题上，直到有人回答；日程提出的工单在被接受之前不开会话，除非这个日程已被改为直接开工；等人的工单不能稍后或归档。`test/company-model.test.ts` 按这些规则检查它。
- **页面。** 开头说明这一页是什么，然后以站点的语言和明暗模式嵌入原型；窗口栏选择原型从哪个状态打开（用了一周的公司，或还没说第一句话的公司），并链接到单独打开的原型。随后三节：相对已发布版本的改动，每行写明事项、现在和规格；服务端强制的规则，逐条编号，各带被拒绝的写入得到的回答，以及现在是否已经强制；工单文件逐个字段，包括规格新增的三个 frontmatter 字段（`source`、`ask`、`deliverables`）、`## Decisions` 节和三个按人保存的处置值（`unread`、`snoozed_until`、`archived`）。「等人」从已发布的五种状态读出：`proposed`、`review`，或 `in_progress` 且 `blocked_by` 是一个人。
- **每类内容只在一处。** 状态、等待规则、收件箱视图、字段和规则在画廊的 `src/company/spec.ts`，原型按它行事，页面把它列成表。
- **共用的窗口。** 官网的实时应用窗口拆成两层：`LiveFrame` 嵌入任意一个画廊文档（按需加载、按栏宽缩放、作为页面的客人），`LiveAppFrame` 经由它继续嵌入应用界面。首页的窗口没有变化。
- **站点。** 页面单独打包、按需加载。标签页标题和描述随读者语言切换；静态外壳带有页面自己的标题和描述，分享卡片用站点的。`/company/` 已加入站点地图。
