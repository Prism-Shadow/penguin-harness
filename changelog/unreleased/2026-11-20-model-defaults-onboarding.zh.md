# 新建 Project 不再预设默认模型，首次打开时引导用户选定

- **Date:** 2026-11-20
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `cli`, `docs`
- **PR:** [#1674](https://github.com/Prism-Shadow/penguin-harness/pull/1674)
- **Breaking:** yes — 新建 Project 没有默认模型，在其中不指定模型就创建 Session、定时任务或组织会被拒绝，直到设置了默认模型

[English](2026-11-20-model-defaults-onboarding.md)

新建 Project 与「恢复默认」不再把 DeepSeek V4.1 Flash 设为默认模型：默认模型由所有者选定，Web App 在首次打开该 Project 时询问。默认模型集中到一个「默认模型」弹窗；在模型配置里一键「设为默认模型」，工具模型即成为它能承担的全部多模态项的默认模型。已有 Project 保留原来的默认模型。

## 「默认模型」弹窗

- 模型库页头的「默认模型」（取代原先通往「项目设置 › 多模态模型」的入口）打开一个弹窗，分三组：**对话**（默认对话模型）；**多模态**（文本生成、图像生成、图片理解——即 Project 的视觉模型——、视频生成、语音识别、语音合成）；以及字色较淡的**工具**（网页搜索、读取网页，以及其他插件声明的绑定）。
- 每行一个选择器，只列出能承担该项的已配置模型，选中即保存。没有候选的一行写「连接一个提供这类模型的供应商」并附「前往模型库」。成员看到同样的各行，只读。
- 文本生成未绑定时，该行写「跟随默认对话模型（<模型>）」；选定模型即绑定，选择器底部的「跟随默认对话模型」解除绑定。
- 弹窗即 `@prismshadow/penguin-ui` 的 `DefaultModelsDialog`，组件画廊新增「模型」板，与引导（`ModelSetupGuide`）同列。
- 「项目设置 › 多模态模型」与弹窗的多模态、工具两组列出同样的各行（次序、名称、候选、空态与「跟随默认对话模型」一致），二者共用同一组件 `DefaultModelSections` 与同一处填行代码；语音输入的润色设置仍在各行之下。

## 设为默认模型

- 模型配置不再逐项列出多模态能力、各带一个「设为默认」。紧挨「测试连通性」只有一个「设为默认模型」，按钮、确认与浮层都不再写「多模态」。能对话的模型点它即设为默认对话模型，与此前相同。不能对话的工具模型点它，先确认（正文列出各项），再成为它能承担、当前默认又不是它的全部多模态项的默认模型，并以浮层列出已设置的各项；它已承担全部可承担项后，按钮变为「移除默认模型」：不确认，直接解除它承担的各项，浮层列出已移除的各项。工具模型一项也不能承担时不显示；弹窗有未保存的修改时停用。逐项指定（包括让能对话的模型承担文本生成或图片理解）在「默认模型」弹窗里进行。
- `PUT /models` 新接受 `visionModel: null`，即清除视觉模型（不带仍为保留）。
- 模型只要是本 Project 某一项的默认（默认对话模型，或承担了多模态绑定），卡片与配置弹窗的标签行就只有一枚「默认」标签，悬停写明用于哪些（如「默认用于：对话、语音识别」）；不再有单独的「默认多模态」标签，也不再用芯片图标。只是视觉代理的模型仍只有「视觉代理」标签。网页搜索与读取网页属于工具，只在「默认模型」弹窗里设置。

## 首次引导

- 所有者打开没有默认对话模型的 Project 时：已有对话模型带 key（模型自己的、分组的，或服务端环境变量里的——与模型选择器同一判定）则直接打开「默认模型」弹窗；否则先出现引导，请其连接 TokenDance 或 Penguin Go（各自打开模型库并走该分组的连接流程），或者填写 key；key 一到（本窗口的改动，或回到窗口时），引导即换成弹窗。
- 引导与弹窗只在对话页上自动出现，每个 Project 在一个浏览器里只自动出现一次，关闭后记在该浏览器。成员不会看到。
- 之后，没有模型的新对话在首页显示一张注意色调的提醒卡「还没有默认模型」，所有者另有主按钮「设置默认模型」（成员看到「还没有默认模型，请找所有者设置」）；卡片显示时占据 Logo 旁版本号那一行、版本号隐去，不与 Logo 重叠，也不另留空白；为本次对话选定模型或设置默认模型后卡片消失，版本号照常显示。发送要等选定模型。Project 没有默认模型时，新对话不再自动用列表里的第一个对话模型。
- 在没有默认模型的 Project 里连接 TokenDance 或 Penguin Go，改为打开「默认模型」弹窗，不再询问是否更换默认模型。「未配置 API key」引导只在默认模型存在而没有 key 时出现。

## 没有默认模型时

- 在没有默认模型的 Project 里不指定模型就创建 Session，得到 400 `no_default_model`，消息写明两条出路（指定模型，或在「默认模型」里、经 `penguin config model default` 设置默认模型）。
- 在这样的 Project 里，新建或更新不指定模型的定时任务、新建不指定模型的组织，同样被拒绝。定时任务表单此时要求选择模型，选定前「创建」停用。
- `penguin run` 与 `penguin chat` 遇到这一拒绝时输出「这个 Project 没有默认模型：请用 --provider 与 --model-id 指定模型，或用 `penguin config model default …` 设置默认模型。」，`penguin chat` 开场的模型一栏写明没有默认模型，并提示 `/switch-model <分组> <模型 id>`。
- `/agent` 交接的浮层等 Web App 各处的提示改为「该 Project 还没有默认模型，请先在模型库的「默认模型」中设置」。
- 文档「模型」页写入了弹窗、引导与新建 Project 没有默认模型的情况。

## 兼容性

已有的 `.project_config.toml` 保留其 `default_model`；变化的只是新建 Project 与「恢复默认」写入的内容。先创建 Project、再不指定模型就创建 Session、定时任务或组织的脚本，需要指定模型，或先经 `PUT /api/projects/:projectId/models/default` 或 `penguin config model default --provider <分组> --model-id <模型 id>` 设置默认模型。
