# Windows 沙盒保留真实的用户目录，完全访问也能断网

- **Date:** 2026-09-16
- **Type:** fix
- **Scope:** core, server, plugins
- **PR:** [#767](https://github.com/Prism-Shadow/penguin-harness/pull/767)

[English](2026-09-16-windows-home-and-full-access.md)

Windows 账户沙盒有两处不合理，现已修复。

- **被封禁命令的用户目录被改写**到了 `C:\ProgramData\penguin\sandbox-home`，于是 `~/.gitconfig`、`~/.ssh`、工具缓存以及本平台自身的配置全都不可见，「写你的 home」这类测试写进了一个假目录还报告成功。现在用户目录就是真实的那个。安装脚本一次性为沙盒账户授予用户目录的**读取**权（完全访问的账户授予**修改**权），与 Linux、macOS 沙盒同一形态——Agent 在沙盒中可以读你的 home，只有写入受限。唯一仍被重定向的是临时目录，指向一个共享的可写目录，且仅在「临时目录可写」开启时。
- **完全访问与断网无法同时成立。** `danger-full-access` 在读取网络设置之前就短路为「不封禁」，于是「完全访问」悄悄丢掉了「断网」——权限按钮可能显示了一个并未生效的断网。完全访问且网络放行（且无屏蔽路径）时仍是真正的不封禁；完全访问且**断网或屏蔽路径**时，现在会走到一个后端去执行这一维度，同时不限制文件系统。这是对沙盒契约的小幅放宽：provider 现在可能收到 `danger-full-access`，此时它必须放开文件、但仍要断网或隐藏路径。bwrap 把根目录以读写方式绑定并仍 `--unshare-net`；seatbelt 不拒绝任何写入但仍 `(deny network*)`；Windows 后端以一个被防火墙挡住、且 home 可写的账户运行命令。
- **Windows 后端现在有四个账户**——网络轴（放行 / 阻断）与文件系统轴（home 只读 / 可写）的交叉——因此每个账户的可达范围在安装时一次性授予，没有命令需要再去重排你用户目录的权限（目录较大时那会花上几分钟）。

## 兼容性

这改变了 Windows 安装脚本留下的东西（四个账户、一处用户目录授权、一个共享临时目录）以及状态文件的形态，因此早前版本留下的状态会被读作「未安装」。请重新运行一次安装——沙盒卡片提供按钮，或在管理员 PowerShell 中执行 `setup\penguin-sandbox-setup.ps1`。在重新运行之前，Windows 沙盒拒绝加载，封禁模式会 fail-closed 而不是不封禁地运行；新脚本的 `-Remove` 也会一并清除旧的账户、组与规则。首次重新运行比以往慢，因为要为账户授予用户目录访问权。等到不再有 Windows 主机持有双账户状态文件时，本条即可移除。
