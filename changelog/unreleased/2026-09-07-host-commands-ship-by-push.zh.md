# 宿主命令移到热更新接缝之下

- **Date:** 2026-09-07
- **Type:** improvement
- **Scope:** `server`

[English](2026-09-07-host-commands-ship-by-push.md)

`/api/command` 原先挂在平台 HTTP 接缝**之上**，这让它成了 runtime 代码：它的形状只能靠重建并重新分发每一个安装来改变。而这正是 runtime 层不该承担的——runtime 只装机制，「宿主命令是什么、叫什么、谁能运行」是策略。

现在它由平台提供，因此和其他业务 API 一样靠推送发布。留在 runtime 的是消息端口本身：宿主发来的最后一帧以 `runtime:shell-frames` 发布出来，原样不解析，由平台解释。这一帧必须由 runtime 发布而不能由平台自己保存，因为宿主每次接线只宣告一次——平台把它存在自己内存里，下一次推送就会丢失，而且不会再被告知。

两条兼容路径都放在可推送的那一半：比该状态袋更旧的 runtime 改从它自己的 service 读；同时 runtime 在接缝**之下**保留了一份路由，这样回滚到仍然拒绝该前缀的旧平台时，这个接口依然有人应答。
