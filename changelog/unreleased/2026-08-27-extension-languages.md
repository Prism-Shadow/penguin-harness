# Languages from extensions, and an index beyond the builtin one

- **Date:** 2026-08-27
- **Type:** feature
- **Scope:** `core`, `server`, `web`, `docs`
- **PR:** [#526](https://github.com/Prism-Shadow/penguin-harness/pull/526)

[中文版](2026-08-27-extension-languages.zh.md)

An extension can contribute a syntax-highlighting grammar now, and the Extensions page lists more than what the server package ships with. The first language extension, `@prismshadow/penguin-extension-languages`, contributes **Typst, Swift, Kotlin, C# and Dart**.

## Details

- **`iface.languages.register({id, displayName, aliases, extensions, grammar})`**, delivered on `initialize` like the sandbox floor beside it. `LanguageContribution` and `LanguageRegistry` are part of the closed extension contract in `@prismshadow/penguin-core/extension`, for the same reason the sandbox vocabulary is: a language extension is written against those names and nothing else, while the service that stores and serves the grammars stays in the harness. Registration lands in a service built with each App — so a language whose extension a hot push removed stops being served rather than lingering until the process restarts.
- **`GET /api/languages`** lists what was registered, without the grammars, and **`GET /api/languages/:id/grammar`** serves one, cached for an hour: a grammar is tens to hundreds of kilobytes, only the languages a conversation shows are worth fetching, and a grammar cannot change without a new App — which is a new page load. The App carries the fence aliases and file extensions **before** the grammar loads, because Shiki registers a grammar's own aliases only once it is loaded and the fence info string is exactly what decides whether to load it. Grammars arrive after the first paint, so a code block already on screen re-highlights when they land rather than staying plain for the life of the page.
- **A contributed language cannot shadow a bundled one**, by id or by alias: the bundled grammar is the chunk built and tested against this Shiki version, and replacing `typescript` with whatever an extension shipped would be silent. A grammar is **data, not code** — a document Shiki's JavaScript regex engine interprets — so nothing on the path from an extension to the browser evaluates anything it ships. That engine is not oniguruma: a grammar leaning on an oniguruma-only construct fails to compile and its blocks render unhighlighted. The five grammars are re-exported from `@shikijs/langs`, the same package the App's own come from, so each is the exact document the bundled path would have loaded.
- **`GET /api/extensions` merges the published index** — the one the `penguin-extensions` repository publishes — beside the entries embedded in the server package. That document is a **release asset on a fixed tag**, `releases/download/nightly/index.json`, rather than a GitHub API query: the tag is never re-pointed, a six-hourly workflow in the index repository replaces the asset on it, so "latest nightly" is a name the publisher resolves and reading it costs none of the unauthenticated API budget a deployment shares with everyone behind its address. Fetched at most **once every 30 minutes**, with concurrent readers sharing one request and the last good document served when a refresh fails.
- **A source that fails shortens the listing rather than emptying it.** The response carries a `failures` array naming each source that could not be read, and the page renders a notice above the list — a silently shorter list reads as "that extension does not exist". This is deliberately unlike the rule *within* one document, where a single malformed row still fails the whole artifact. On a `name@version` collision the earlier source wins, and the builtin registry is listed first: what a deployment ships is the truth about it. **`PENGUIN_EXTENSION_INDEX`** unset reads the published index, `off` disables the lookup entirely with no outbound request (the shape `PENGUIN_UPDATE_CHECK=off` already gives the version check), and any other value replaces the URL for a fork or a private index.
