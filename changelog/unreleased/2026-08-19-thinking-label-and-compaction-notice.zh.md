# 思考等级标签按界面分化，压缩行改为按模式命名

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `web`, `server`
- **PR:** [#340](https://github.com/Prism-Shadow/penguin-harness/pull/340)

[English](2026-08-19-thinking-label-and-compaction-notice.md)

界面上的两处显示修正。中文的思考等级标签不再处处带上线路值，只在挑选档位的地方带；压缩步骤则改为如实说明它做了什么——清空上下文的那一步不再被报成压缩——两种模式因此都不必再写结果文案。Trace 页的轮次徽标沿用同一套命名，为此把模式一路带过了分析 DTO。

## 思考等级标签

- `S.chat.thinkingLevelNames` 改为纯粹的档位名：中文读作 低 / 中 / 高 / 极高 / 最高，历史遗留的 `none` 另有 无；英文仍是它一贯的名字，即线路值本身。凡是展示「已选定档位」的界面都读它——草稿态与活动会话两个输入框选择器的按钮与悬浮提示、对话中途的切换确认框及其 toast，以及 Project 对话缺省值的控件与其只读视图。
- `S.chat.thinkingLevelMenuName` 负责组合下拉行的变体，在名字后附上这次挑选将要发送的线路值（`极高 (xhigh)`）。只有输入框自己的下拉菜单调用它：Project 对话缺省值用的是原生 `<select>`，它会把选中项自身的文字画到收起后的控件上，给行加注解等于把线路值又送回了按钮。
- 英文没有分化。它的档位名本就是线路值，所以 `thinkingLevelMenuName` 只接名字并原样返回，不去复制一份表。
- 新增一道防漂移测试，用 core 的 `DEFAULT_CHAT_THINKING_LEVELS` 去核对两份真实词典——此前 Web 的测试只跑一个手写替身：每个档位在两种语言下都有名字，中文名一律不含拉丁字母与圆括号，而带注解的变体必须含有线路值。

## 压缩行

- 该行的标题改为标明自身模式。`summarize` 一步仍叫 压缩 / "Compaction"；`discard` 一步改叫 清空 / "Clear"——它丢的是旧上下文，并没有压缩什么，把这一步称作压缩正是让人困惑的地方。
- 模式落到标题上之后，settled 状态两种模式都不再写结果文案：只呈现状态图标、标题与耗时，`summarize` 另有那个点开就是既得摘要的折叠箭头。`已丢弃旧上下文` / "old context discarded" 两条文案，连同在它们之间做选择的 `compactionDone`，一并从两份词典中删除。
- 运行中的那一行也不再把模式作为原始的 `summarize` / `discard` 重复到 detail 槽位；那是未翻译的线路值，如今标题已经承担了它。
- 失败或中断的压缩仍会说明原因，两种模式皆然：原因正是标题带不了的那部分。

## Trace 页

- 轮次卡片上的压缩徽标同样标明模式，且直接复用对话行的标题、不再另起一份 Trace 专用文案，两处便无从走样：被丢弃的那一轮读作 清空 / "Clear"。Trace 专用的 `compactionRound` 一条随之删除，不留第二份同义文案。
- `TraceTaskStats` 新增 `compactionMode`，**并列**在既有的 `compaction` 标志旁边，而非取而代之。标志仍是判定「这是不是压缩轮」的唯一依据，只读布尔值的旧客户端不受影响；模式缺失时按 `summarize` 理解，也就是徽标一贯显示的那个。
- 被丢弃的那一轮现在才真正被标记为压缩轮。它不发起任何模型请求——core 把 `compaction_begin` 与 `compaction_end` 背靠背地发出——而此前该标志只在压缩请求处设置，于是这样一轮渲染出来是一张既无徽标也无统计的空卡片。改为依据它自己的 `compaction_begin` 标记，`summarize` 的情形落在同一轮上。
