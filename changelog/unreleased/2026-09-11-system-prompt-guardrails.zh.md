# 默认 System Prompt 的护栏与交互规则

- **Date:** 2026-09-11
- **Type:** fix
- **Scope:** `core`
- **PR:** [#697](https://github.com/Prism-Shadow/penguin-harness/pull/697)

[English](2026-09-11-system-prompt-guardrails.md)

默认 System Prompt 只说工具调用失败要调整后重试、遇到「无法解决」的错误要停下上报，却从未说明「无法解决」长什么样，于是一个顽固错误换来的是无休止地尝试变体。它没有提到工具调用的并行、交互式命令、臆造的名字和项目自带的验证命令，于是 Agent 每轮只读一个文件、在 `y/n` 提示上干等到轮询超时、引入项目里并不存在的包、汇报一次从未跑过的构建。它对怎么跟用户说话也几乎没有交代，于是回复以「好的！」开头、满口工具名、把命令贴出来让用户自己跑、结尾不说成果在哪。十七处小改动——每处一个从句或一条要点，其中数处替换原有句子，取自公开的 Claude Code、Qoder 与 CodeBuddy 提示词——补上了这些缺口。

## 细节

- `# Stop rules`：「无法解决」有了可观测的触发条件——同一错误经三次不同修法仍在——上报时说明试过什么；请求只有在查过文件与环境之后仍含糊才算含糊，追问只问一个具体问题并列出看到的选项；最终答复自足——做了什么、在哪些文件、怎么运行或验证、还有什么没做。
- `# Tool use`：「优先用工具」一条改为「以证据而非记忆工作」，并要求自己执行命令、自己编辑文件，而不是贴给用户去操作；另增三条——不臆造路径、参数、包、API 或 URL（库以 manifest 或 lockfile 出现为准）；相互独立的工具调用在同一轮一并发出，引擎会并发执行；命令一律非交互式运行，等待输入的命令视为卡住而非慢。
- `# Personality`：「不要反复解释工具」一句改为四条——以结果开头（不用填充语起头、不叙述即将发起的工具调用、不在结尾复述做了什么，除非被要求）；用自然语言而非工具名描述动作，不复述用户已能看到的输出；未被要求不用 emoji，代码块一律标语言；拒绝时一句话说明并给出最接近的替代方案。
- `# Success criteria`：验证指的是项目自带的测试、lint、类型检查与构建命令，从 README 或 manifest 里找到，而不是臆测。
- `# Constraints`：遵循周围代码的惯例；问题先作答，被要求时才改文件；git 历史属于用户——被要求才 commit、push 或 reset。
- `# Suggested workflows`：`PLAN.md` 的每一步先验证再进入下一步，只在看到它生效后才标记完成；Web 应用用框架 CLI 脚手架，展示前实际起服务请求一次。
- 这是一次 kernel 变更（generation `2026-09-11`，prompt tab）：Prompt tab 仍是内置默认值的存量 Agent 会在 kernel 更新时拿到这些规则，用户改过的则保持原样。
