# 点击上下文圆环，看清上下文被什么占满

- **Date:** 2026-08-24
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#442](https://github.com/Prism-Shadow/penguin-harness/pull/442)

[English](2026-08-24-context-composition-panel.md)

对话输入区的上下文圆环变成了按钮。点击后弹出面板，把当前模型上下文拆成六项——系统提示词、工具定义、
用户消息、模型消息、工具请求、工具结果——以堆叠条与图例呈现各自的 token 用量与占比，其下是流量占用
最多的五个工具。原先跟在圆环旁的 `已用 / 上限` 数字移入面板表头，输入区只留圆环，悬停圆环即可读到
这两个数字。

## 细节

- `GET /api/sessions/:sessionId/context` 返回六个分项、它们的合计与工具排行。它读取该 Session
  **最新的一个 Trace 分片**，一个分片即一个完整的模型上下文：Trace 写入器在压缩时轮转，新文件以
  `session_meta` 与 `tool_list_ready` 开头，而 Session 恢复会继续追加到中断时的那个分片。
- 各项大小取自 core 已经用于估算请求输入的字符启发式（`approximateMessagesTokens`），因此图片按固
  定额度计入而不是按 base64 长度，也不引入本地 tokenizer。
- 面板只使用这些数字的**占比**。每一项按其占估算总量的比例，折算到圆环自身报告的占用量——最近一次
  `token_usage` 的 `request.total`——因此各项之和恰好等于面板表头的数字，且每个折算值都带 `~` 标记。
  两列均按最大余额法分配，占比合计恰为 100，token 列合计恰为实测占用。
- 事件消息一律跳过（它们都不会发给模型）；`compaction_begin` 与 `compaction_end` 之间的消息同样跳
  过：压缩请求的提示与它产出的摘要虽记录在该分片里，却从不属于这里所描述的上下文。
- 工具排行统计每个工具的调用**与**结果两部分 token，标题里直接写明。工具的**定义**计入「工具定义」
  一项；调用不在同一分片里的结果仍计入「工具结果」，但没有可归属的工具——因此排行之和可能小于两个工具
  分项之和。
- 悬停条形分段或对应的图例行会把两者关联起来：该行高亮，其余分段淡出。条形本身没有标注，占比只有 1%
  的细条正是靠这个才能认出来。
- 以状态为 completed 的 `compaction_end` 结尾的分片报告 `contextClosed`，判据与 Trace 重放判定
  「无需重放」的一致。此时面板显示 `—` 并说明占用待下次请求回报，与圆环在该状态下的表现一致，而不是去
  描述刚刚被压缩掉的那个上下文。
- 面板经 `usePortalPanel` 传送并定位，点击外部、Esc、滚动或改变窗口大小即关闭。它只出现在
  Session 级端点能够服务的地方：草稿输入区没有 Session，子智能体输入区的子 Session 未登记在 sessions
  表中，两处都不提供。

## 配色

- 六个分项在 `lib/category-colors.ts` 中拥有独立的分类色序列，与 `SERIES_COLORS` 分开——后者的长度
  同时是成本中心的折叠上限。
- 图例行与条形分段同序绘制，读者只需分辨相邻项；该顺序在浅色与深色下都通过相邻项校验（最差相邻
  ΔE：模拟红色盲／绿色盲 21.1，未模拟 22.1，OKLab ×100）。六种色相无法同时对**任意**两项通过这些
  校验，因此每一行图例都在名称旁给出自己的数值。
