# 程序目录迁到平台的数据目录

- **日期：** 2026-08-15
- **类型：** change
- **范围：** `tooling`、`cli`、`desktop`

[English](2026-08-15-install-layout.md)

安装时程序树放到 XDG 数据目录（`~/.local/share/penguin`，Windows 上是 `%LOCALAPPDATA%\penguin`），
不再放在 `~/.penguin`。**你的数据不会移动**：数据根仍然是 `~/.penguin/data`，也就是 `PENGUIN_HOME`
的默认值。

## 一次性迁移

重新跑安装脚本——或者跑 `penguin update`，它内部会调用安装脚本——会把已有的安装搬过去：先在新位置安装
并做冒烟测试，通过之后才从 `~/.penguin` 里删掉旧的程序目录（`bin`、`lib`、`web`、`node`，Windows 上
还有 `git`）。`data/` 从不触碰，`~/.penguin` 本身只在里面什么都不剩时才删除。旧副本清不掉只是警告，
不算安装失败。

设置了 `PENGUIN_INSTALL_DIR`（或 `-InstallDir`）就完全不迁移：明确指定的位置是一个选择，不是一种需要
迁移的布局。同样的道理，`penguin update` 不再把旧的默认路径回传给安装脚本——那样会把所有已有安装永久
钉死在旧布局上。

## 为什么

程序和状态原本混在同一个目录里：升级要替换其中四个子目录，还要绕开第五个。把它们分开，各自放到平台
期望的位置，让"删掉程序"和"删掉我的数据"变成两件事；也给自动安装那条路径（往一台还没有服务的机器上装
一个）一个可写的位置，而不必和那台机器上可能已经存在的数据根纠缠在一起。
