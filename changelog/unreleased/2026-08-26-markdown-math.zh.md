# 所有 Markdown 界面渲染 LaTeX 公式

- **Date:** 2026-08-26
- **Type:** feature
- **Scope:** `web`
- **PR:** [#503](https://github.com/Prism-Shadow/penguin-harness/pull/503)

[English](2026-08-26-markdown-math.md)

Markdown 正文改用 KaTeX 渲染数学公式。渲染管线是共用的，因此对话消息、Trace 事件、Benchmark 用例与
Workspace 文件预览同时具备该能力。

## 细节

- 启用三种分隔符：`\[…\]` 与 `$$…$$` 渲染为独立成块的公式，`\(…\)` 渲染为行内公式。`$$…$$` 无论
  写在哪里都是成块公式，不限于单独占据整行的写法。模型最常输出的 TeX 方括号形式以 micromark 语法
  扩展的方式加入解析器，这使其不会侵入行内代码与围栏代码块，也使流式输出中尚未闭合的 `\[` 先按普通
  文本显示、待结束符到达后再变为公式。
- 保持关闭单个 `$` 的行内公式。`$PATH`、`$HOME` 以及 `$5 和 $10` 这类价格保持原样；`$$…$$` 不受影响。
- KaTeX 无法解析的公式显示为其自身源码，解析错误保留在悬停提示中，不会波及所在的整条消息。尺寸类命令
  被限制在 5em 以内，模型输出的 `\rule{9999em}{9999em}` 只会得到一个小方块，而不是一整页那么大。
- `\text{}` 中的中文使用应用自身的字体栈渲染。KaTeX 的字体不含 CJK 字形，且未为其标记的中文片段定义
  样式，本次改动补齐了该样式。
- 成块公式在自身区块内横向滚动，与表格、代码块的既有处理一致；过长的行内公式也在自身范围内滚动，而不
  会撑宽整列消息。
- 消息仍在流式输出时，其中的公式先显示为 TeX 源码，待消息结束后再排版。逐个增量渲染意味着每秒约八次
  重新解析 KaTeX 的产物、并为每条公式重建数百个元素，而这正是消息记录的 memo 与延后语法高亮已经在
  规避的开销。
- `\[` 与 `\]` 同时也是 CommonMark 中方括号的转义写法，本次改动把这一冲突判给公式：
  `See \[1\] and \[2\] for details.` 会被读成两条居中公式，而不是两个脚注标记。被空行截断的 `\[…\]`
  不匹配，`\[a\\]`（TeX 换行紧贴结束符）在第二个反斜杠处闭合。
- 分隔符之间出现反引号时放弃识别该公式，因此在行内代码里展示结束符的句子，代码片段与句子都完好。
- KaTeX 的样式表与 woff2 字体作为本地资源打包，离线也能渲染公式。KaTeX 同时提供的 woff 与 truetype
  回退在构建时丢弃；Web 产物体积增加约 550KB，其中约 250KB 是仅在出现公式时才会请求的字体。
- remark 与 rehype 插件列表移至 `packages/web/src/lib/markdown-plugins.ts`，所有 `ReactMarkdown`
  调用点改为读取该列表，不再各自拼装。
