# Discord 成为第五个消息渠道

- **Date:** 2026-09-07
- **Type:** feature
- **Scope:** `server`, `web`, `docs`

[English](2026-09-07-messaging-discord.md)

Session 多了第五个可绑定的渠道：Discord 机器人，接在前四个渠道早已使用的同一套连接器接口后面。绑定它只需从开发者后台粘贴一条 Bot Token，Token 的第一段就是机器人的身份，因此账号身份像 Telegram 那样直接从凭据中得出。入站消息走平台的 Gateway WebSocket，绑定它不需要任何公网回调地址；文字、图片与文件双向都能传输。

## 细节

- 传输层落在 `discord-api.ts`：REST 调用（以 `GET /users/@me` 作凭据探测、抑制提及的频道消息发送、multipart 上传、带上限的附件下载）与 Gateway 会话——identify、带 ACK 看门狗的心跳、按 READY 交回的地址 resume、遇到两个终结会话的关闭码后重新 identify、Token 被拒或 intent 被拒时不再重试。它接在可注入的工厂后面，测试用假实现替换而不开网络。不引入 SDK：Gateway 的 op 码编号与 QQ 连接器已经在说的是同一套。
- **机器人只读取私聊与 @ 它的消息，不申请任何特权 intent。** 没有消息内容 intent 的机器人，Discord 会把服务器频道消息的内容清空，私聊与 @ 它的消息除外——因此连接器只订阅两个非特权的消息 intent，只读这两类消息，并像 Telegram 连接器那样去掉句首用于称呼的提及。机器人不需要在后台调任何设置就能工作；在服务器频道里不带 @ 的消息不会送达，绑定编辑器把这条规则立在屏幕上而不是收进折叠。
- 这个平台上子区本身就是一个频道，因此仅凭频道 id 就能把回复送回提问的地方；回复引用把频道 id 与消息 id 打包在一起。机器人的消息（包括本机器人自己的）与系统消息一律丢弃。
- **连接器接口新增可选的 `textChunkChars`。** Discord 把一条消息限制在 2000 字符，低于桥分段用的共享上限，于是上限更紧的渠道自己声明它，而不是把所有渠道的上限一起压低。Discord 连接器按 1900 分段，给渲染器加入的转义留出余量；渲染后仍超出上限的回复改以纯文本按上限分段发出——损失排版，不损失消息。
- `discord-markdown.ts` 把回复渲染成 Discord 客户端能读的子集。与微信一样是做减法而不是翻译：三级以内的标题、粗体、斜体、删除线、列表、引用、链接与代码原样渲染；更深的标题改为一行粗体，表格改为代码块，分割线改为一行短横，任务框改为字形。
- 入站附件按输入框的两种附件形态到达——图片作为 `image_url` 部分，其余作为 Session scratchpad 里的文件——语音消息的录音除外，它仍得到「暂不支持」提示。出站方向图片与文件是同一种上传：Discord 会把图片附件内联显示。
- `/discord` 路由子树带着其他渠道同样的动词集到来，PUT 与凭据测试按 Telegram 的形态手写：一条 Token，保存时解出其机器人 id（否则 400 `discord_token_invalid`），探测报出机器人的用户名。绑定编辑器新增该渠道、带开发者后台链接的 Token 字段、屏幕上的 @ 规则说明与两条常见问题；服务端 API 文档新增其各行。
