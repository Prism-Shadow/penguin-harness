# zip 导入的目录条目同样受归档上限约束

- **Date:** 2026-11-03
- **Type:** fix
- **Scope:** `server`, `docs`
- **PR:** [#1450](https://github.com/Prism-Shadow/penguin-harness/pull/1450)

[English](2026-11-03-zip-directory-entry-caps.md)

名称以 `/` 结尾的 zip 条目不再能绕过归档上限。Skill、插件与 Benchmark 的导入原先只对文件条目计数并检查大小，而 fflate 照样会解压目录条目里的任何字节：Skills 归档路由曾接受一个 262 KB、其中目录条目解压后达 256 MB 的 zip，按 14 MB 的上传上限，一次请求就能让服务端分配约 14 GB 内存。

## 细节

- 每个条目（包括目录）都计入归档的条目上限（Skill 与钩子包 200 个，Benchmark 1,000 个，插件 2,000 个），其声明大小计入单文件与总量上限。两者都在解压任何内容之前从中央目录读取，上面那个请求因此以 400 拒绝，并点名该条目。
- 未超上限的目录条目不会被解压，也不出现在导入读取的内容中。钩子包导入原本就跳过目录条目、不解压它们，现在同样对其计数并检查大小。
- 超出条目数的拒绝信息改称条目上限（目录计入），不再称文件上限；Skills、评估中心与服务端 API 文档也改按条目给出数量上限。
