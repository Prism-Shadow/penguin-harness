# 机器页在一次故障里说的两句不实的话

- **Date:** 2026-09-07
- **Type:** fix
- **Scope:** `server`, `web`

[English](2026-09-07-machine-linked-but-stopped.md)

只要本服务器持有到某台机器的 ssh 会话，机器卡片就显示**已连接**——哪怕最近一次探测发现那边根本没有服务端在跑，而这一点就写在同一张卡片展开后的详情里。

这两件事是被刻意分开的：连接是**本侧**的一个进程，它比对端的服务端活得久，所以它只说明「隧道有地方可去」，从不说明「有人在应答」。把其中一个当作另一个，正是当年造成重连死循环的原因。卡片犯的是同一个错误的反方向——而且更糟，因为它是无声的：由于这一行看起来「就绪」，**启用**按钮被收了起来，于是唯一能把对端服务端重新拉起来的动作，被隐藏它故障的同一个 bug 一起隐藏了。

现在：连接在、服务端已停止 → 显示「已连接，未在提供服务」，attention 色，并提供启用；连接在、机器连不上 → 显示连不上，并带上 ssh 自己的原话。

这是在真实机群上发现的：一台机器的服务端绑不上端口，而页面坚称一切正常，实际上什么都做不了。

## ……以及与上一行自相矛盾的插件同步

一次连接会先后打印这两句：

```
Models synced: default_project.
Plugins of default_project not synced — that machine has no such Project
```

两句不可能同时为真，错的是第二句。比「Project 插件清单」更旧的机器，对一条它从未听说过的路由回 404，而同步把所有 404 都读成「没有这个 Project」。现在它会追问一个所有版本都答得上来的问题——它列出这个 Project 了吗——并说清是哪一种：需要更新的旧版本，还是真的没有这个 Project。
