# 服务端为所连机器保留一份 Trace 行副本，远程对话的历史从这份副本流式发出

- **Date:** 2026-10-29
- **Type:** feature
- **Scope:** `server`
- **PR:** [#1392](https://github.com/Prism-Shadow/penguin-harness/pull/1392)

[English](2026-10-29-history-stream-hub.md)

连接机器的服务端把每台机器发来的 Trace 行保留在 `<数据根>/machines/traces/` 下，远程对话的历史从这份副本以带进度的流发出。再次打开同一对话时，只向机器要副本里还没有的行；旧版本的机器也仍能加载历史。

## 细节

- `GET /api/sessions/:id/history` 以整条记录为行流式发送一个窗口，大块内容折叠，查询参数与 `/messages` 相同（`tailLimit`、`before` 加 `limit`、不带参数为完整记录），另加 `budget` 与 `fill=1`。每个事件的 id 为 `<windowId>:<offset>`，两分钟内带着这个 id 重新发起的流从原窗口的断点继续，且仅限同一 Session、同一用户、同一查询。任何失败都以 `error` 事件结束流；用户被登出时，HTTP 流随之结束。本机的 Session 直接从自己的 Trace 应答。
- 机器上的 Session 由服务端经 API socket 调用该机器的 `history-lines` 路由，把完整的行写入一份按字节一致的副本，再从副本拼出窗口。每个对话一个同步任务，同一时刻只开一条机器流：窗口与正文优先，后台补全为它让路；没有读者再等补全时，补全即结束。只有机器在 15 秒内什么都没有发来——socket 上没有，同一 ssh 会话上随之代理的其他请求上也没有——流才被切断，慢链路上排在一个大应答之后的流不再被误报为机器没有回应；API socket 本身也只在同样静默 40 秒后才断开，仍听得见链路时服务端向机器发 ping；有进展的流被切断后立即从副本处重开；没有进展的流以及不在线的机器，从 1 秒起倍增到 30 秒重试，等待状态以 `progress.waiting` 告知。最后一个读者离开时立即取消机器流；服务端代际被替换时，其流不报错地结束，读者重新发起。各代际共用同一目录的同一份副本。
- 每个文件的 `have` 列出副本持有的全部区段和一行尚未收全的内容，整个对话的 `have` 不超出机器的上限，本对话自己的文件优先。副本写不进去时读取照常进行：窗口直接由这条流带来的行拼出。
- 每次打开都校验副本：机器上被改写或替换的文件从头重来，按 inode 判定，创建时间只在双方都知道时比较，设备号从不比较。窗口或补全中机器不再列出的文件被删除；取回一个值从不删除任何文件。副本读不回的窗口只重取它自己的区段。超出机器所报文件大小的行从不保存。机器删除的对话随即删除副本，依据机器的 `session_not_found` 或其 `session_deleted` 事件。副本目录以 id 的哈希命名。副本上限 1 GiB，每个文件按其已持有的最高偏移计入，超出时先淘汰最久未读的对话。机器连同数据卸载时删除它的副本；机器不再出现在本服务端的列表中时，于下次启动时删除；ssh 配置读不出时，启动时什么也不删。
- `GET /api/sessions/:id/trace-body?ref=` 完整发送一个折叠的值，来自副本，或在取回所在行之后，进度只有一个总量。按引用的图片也从副本应答，Trace 面板的事件同样如此——当前文件亦然，到副本从文件开头起持有的记录为止；其分析由服务端从副本计算，按该对话所在 Project 的价格。Project 范围的 Trace 路径若不是该 Session 的 Project，则查无此文件。其余请求照旧转发给机器。
- 只由副本应答的读取（图片、Trace 面板的事件与分析、已持有的值）先向机器确认该对话仍然存在，每 30 秒至多一次：在机器上被删除而本服务端未曾得知的对话答 `404` 并删除副本；机器离线时副本照常应答。机器不让本服务端查看某个对话（`403` `session_forbidden`）时，读取以该错误结束，副本保留。删除已删对话的副本时，保留分叉仍在引用的子会话副本；本服务端没有其配置的 Project，其分析交给机器计算。机器流一分钟内只有节拍时，读者会得知机器响应缓慢（`waiting.reason` 为 `slow`），而不是毫无提示；socket 自身的通道沉默超过两个周期时，无论链路其余部分多忙都会断开。
- 对本服务端不持有的 Session 发出的 Session 级请求，若可能持有它的机器未及时应答，则答 `503` `machine_no_answer`，并在 `details` 中指明那台机器；只有每台被询问的机器都答复没有时，才答 `404` `session_not_found`。
- 没有 `history-lines` 的机器、或本服务端拿不到其 API socket 的机器，其窗口在同一条流里经 HTTP 读取它的 `/messages`，边到达边计字节，不做缓存；窗口的 Task 数（`units`）由服务端自行计数。拒绝本服务端会话的机器以 `machine_refused` 结束流，正在升级的机器被等待，已不在本服务端列表中的机器以 `machine_not_found` 结束流。
