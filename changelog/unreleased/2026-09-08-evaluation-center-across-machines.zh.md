# 评估中心会读遍本服务器持有的每台机器

- **Date:** 2026-09-08
- **Type:** fix
- **Scope:** `web`
- **PR:** [#450](https://github.com/Prism-Shadow/penguin-harness/pull/450)

[English](2026-09-08-evaluation-center-across-machines.md)

Benchmark 属于 Project，而 Project 在它借给的每台机器上都是同一个。它的 `benchmarks/` 目录却不是：Benchmark 在哪台机器上创建或评测，就写在哪台机器上，于是同一个 Benchmark 的题目与记分板被摊在它跑过的所有磁盘上。而评估中心只读它自己所在的那块磁盘：在机器上建的 Benchmark 根本不会出现在列表里；两边都评测过的 Benchmark，则会显示一段缺了在别处跑过那几轮的历史——一张有洞的曲线，而且屏幕上没有任何东西说明这一点。

现在卡片列表与 Benchmark 自己的页面会同时问本机与本机持有连接的每台机器，并按 benchmark id 归并：一个 Benchmark 一张卡片，其下是一段完整历史。机器作为**归属信息**而非分组维度出现——当某个 Benchmark 存在于不止一处时，评测行会点名记录它的那块记分板所在的机器（`[SSH: prod-1]`）；只存在于某台机器上的 Benchmark 以那台机器命名；它评测过的 Agent 取所有记分板的并集。

顺序只有一种定法。记分板的追加顺序**就是**评测序列，页面信任它胜过信任时间戳——但两块磁盘上的两份记分板之间根本不存在共同的追加顺序，因此合并出来的历史按时间排序，而只来自单台机器的 Benchmark 则原样保留其文件里的顺序。

Benchmark 的题目取持有它的机器的并集，题目文件从其列表来源的那台机器读取。答不上来的机器会被排除在归并之外：本机持有的内容照常渲染，只有当没有任何来源作答时才报错。创建与删除仍只作用于本机：只有本机持有的 Benchmark 才提供删除，删除的也是本机这一份。
