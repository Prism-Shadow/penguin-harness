# 服务端模块的 iframe 系统应用在应用中心的窗口中打开

- **Date:** 2026-11-20
- **Type:** feature
- **Scope:** `web`, `docs`

[English](2026-11-20-plugin-app-window.md)

服务端模块经 `WebModule.pages` 贡献、以 iframe 渲染、带 `app` 与标题的页面是系统应用，在应用中心的窗口中打开，与 Agent 的应用是同一个窗口：最小化后继续运行，全屏以无窗口外框的整页绘制，关闭即结束（设计：[PRFC-0036](https://github.com/Prism-Shadow/penguin-harness-design/pull/503)）。Web App 自带的系统应用（模型库、插件市场、机器管理、成本中心、评估中心）仍以整页打开。本次改动不针对任何一个具体应用。

## 细节

- **窗口**：图块打开 `/apps?app=system_agent/<页面键>`。运行中的应用带运行中短横，图块的名称与悬停提示写明「运行中」。标题栏与 Agent 的应用相同。
- **应用内的位置**：窗口地址带 `at`，即应用内的路径与查询串。iframe 从文档片段（`src#<at>`）得知初始位置。页面发 `{ type: "penguin:location", at }` 时，宿主替换 `at` 而不新增历史记录；地址在宿主一侧改变时（后退、前进、链接或粘贴地址），宿主向页面发同样的消息，而不重载页面。不带 `at` 的地址（例如图块）让运行中的窗口回到页面当前所在的位置，并把该位置写进地址。
- **导航**：页面发 `{ type: "penguin:navigate", to }` 时，宿主前往 `to`；`to` 须是本应用同源、不在 `/api/` 下的路径。窗口随之最小化并继续运行，后退即恢复。来自其他 iframe 或其他源的消息，以及最小化窗口中的页面发出的导航请求，一律忽略。
- **旧地址**：页面的 `path` 及其下的每个地址都进入窗口，余下的路径与查询串即 `at`，并替换历史记录中的当前项：`/reports/r1?tab=a` 打开 `/apps?app=system_agent/reports&at=%2Fr1%3Ftab%3Da`。
- **全屏**：全屏是页面 `/app/<projectId>/system_agent/<页面键>?at=…`，与 Agent 工作台的整页一样在应用外壳之外。它从窗口所在的位置开始，并随时更新 `at`；退出球与命令面板的「退出全页模式（回到应用窗口）」回到该位置的窗口。
- **iframe 的上下文**：每个贡献的 iframe 页面（窗口中、全屏或整页）的根元素都带 `lang`（`zh-CN` 或 `en`）与 `data-project-id`，与主题一起随之更新。iframe 不再写死白色或黑色底色，主题的页面底色因此透出。
- **开始页**：开始页在自带的三个计数之后，画出服务端模块经 `GET /api/contributions` 的 `startMetrics` 贡献的计数。点击打开它所指的系统应用：在窗口中打开的进入窗口，否则进入其页面。不发送这一列表的服务端没有这些计数。
- **文档**：「插件」页新增「应用窗口中的页面」一节，说明地址、`at`、两种消息与 iframe 的上下文。
