# Session 绑定消息软件机器人（飞书、Telegram）

- **Date:** 2026-08-25
- **Type:** feature
- **Scope:** `server`, `web`, `docs`
- **PR:** [#464](https://github.com/Prism-Shadow/penguin-harness/pull/464)

[English](2026-08-25-feishu-session-bridge.md)

新增消息渠道绑定，飞书（Lark）与 Telegram 为首批两个渠道：Session 绑定到自建飞书应用或 Telegram 机器人后，发给机器人的消息以普通用户输入进入该 Session，AI 完成的回复再转发回对应会话。

## 细节

- 两处管理入口共用同一个渠道感知的绑定编辑器：会话行菜单的「消息软件绑定…」对话框，与对话页右侧面板栏新增的「消息软件」停靠面板（排在轨迹面板之后，管理当前会话的绑定）。未绑定时由渠道选择器（飞书 / Telegram）决定表单，绑定后锁定（换渠道须先解绑）；字段随渠道切换——飞书为 App ID / App Secret / API 域名，Telegram 只有一条 Bot Token——上方是按渠道的链接行（「前往教程」与「前往开发者后台」）。编辑器包含凭据测试（Telegram 成功反馈会报出机器人的 @username）、「发送测试消息」探测（需连接中且机器人收到过消息）与带确认的解绑；已保存的密钥只以全站统一掩码作为占位符展示（输入即替换、留空即保留），已绑定的行显示一枚按渠道的小标识。
- 保存与启用拆分为两件事：「保存」只保存凭据、从不建立或断开连接（唯一例外——已启用绑定在保存新凭据时用新凭据重启连接器，存储配置与在线连接永不背离）；独立的「启用连接」开关用已存凭据即时建立或断开连接（表单有未保存修改时置灰并提示先保存凭据）。新绑定默认停用；服务端启动只连接已启用的绑定。
- 侧栏会话行的悬停按钮改形：归档保留为直接按钮，删除按钮换成实心三圆点「更多」按钮——点击即在按钮处打开该行的完整右键菜单（菜单新增了仅靠右键难以发现的配置类操作），删除移入菜单（仍为危险样式）。
- 服务端以带渠道判别列的 `messaging_bindings` 表存储绑定（一个 Session 一个绑定，同一渠道下一个机器人账号一个绑定——409 `feishu_app_in_use` / `telegram_bot_in_use`；`enabled` 为存储的连接意图），并经渠道连接器接缝运行消息桥——每个启用绑定一条入站事件连接：飞书走 SDK 的 WebSocket 长连接，Telegram 走基于 offset 的 `getUpdates` 长轮询（建立连接时先清空停用期间的积压；轮询瞬时失败按指数退避、每次故障只上报一次、恢复后自动回连）——两者都无需公网地址。入站文本以 `queueIfBusy` 按普通输入框口径发起 Task（无标记块、无特殊 sender，模型不知道消息来自消息软件）；其他消息类型收到双语「仅支持文本」回复；每个完成的任务把助手文本镜像回最近的会话（群聊回复到原消息），按渠道文本上限分段（不超过 Telegram 的 4096 字符硬上限）；有工具调用等待审批时发送一行指向 Web 界面的提醒。
- `/api/sessions/:sessionId/messaging` 下新增接口：渠道无关的 GET（读出无论哪个渠道的绑定，以 `channel` 判别）加上每个渠道相同的动词集——`/feishu` 与 `/telegram` 各有 get / put / state / delete / test / test-message。Telegram 的机器人身份取 Token 冒号前的数字 id，换发 Token 不丢绑定。密钥在所有响应中掩码、留空重存时保持原值，读取与测试对任意 Project 成员开放、写入仅限所有者。删除 Session 连带删除其绑定。
