# 同步预置不再覆盖你的 base URL、API key 与输出上限

- **Date:** 2026-09-21
- **Type:** fix
- **Scope:** `web`

[English](2026-09-21-sync-presets-keeps-deployment-fields.md)

**同步预置**此前会把已配置的预置模型上所有「目录字段」一律复位，base URL 也在其中。于是指向代理、自建网关或公司出口的模型，在下一次同步时丢掉了那个端点：内置目录不为一方厂商模型记录 base URL，该字段因此被清空，模型随即不可用。现在同步只更新目录知道的那部分模型事实，本机怎么访问这个模型则原样保留。

## 细节

- 已配置的模型上一律不覆盖：base URL、API key、最大输出 Token 与快速模式。输出上限与快速模式原本就在覆盖范围之外，现在 base URL 与它们同列，而 API key 从来就不在这次写入里。
- 仍按目录刷新：上下文窗口、定价、协议、视觉支持与促销折扣。内置模型在目录钉住协议之前存下的行，修复方式依旧是重跑一次同步。
- base URL **为空**且目录带有一个时，会被补齐。网关模型，以及 `custom` 分组里的预置行（如 Atria），没有端点就什么也访问不到，这类行上的空值是损坏而不是选择——与显示名为空时的补齐同一处理，代价也相同：有意清空的值会在下次同步时回来。
- 「模型库」角标遵循同一条规则：你自己的 base URL 不再算作「有差异」，红点不会再指向一个并不打算改它的按钮。
- 按钮提示与确认弹窗的文案改为分别点名这两类字段。

早先的同步已经清掉的 base URL 无法找回——旧值已不在 `.project_config.toml` 里。请在模型上重新填写，此后它会保留下来。
