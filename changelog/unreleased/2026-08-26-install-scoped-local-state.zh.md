# 删除数据根后，浏览器侧属于它的 UI 状态也会一并清除

- **Date:** 2026-08-26
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#508](https://github.com/Prism-Shadow/penguin-harness/pull/508)

[English](2026-08-26-install-scoped-local-state.md)

删掉数据文件重启后，应用回来时仍然选中着原来的 Workspace。其中一部分状态本就不在数据根里：Web App
把新会话草稿、侧边栏登记的 Workspace、置顶的 Session、已读标记以及上次的 Project/Agent 存在
`localStorage`——在桌面端它位于 Electron 的 userData 目录，删除 `PENGUIN_HOME` 一个字节也碰不到。
而每个键里的用户与 Project 都是编译期常量（`admin`、`default_project`），于是清空重启后重新置备出
同样的 id，键再次对上，旧状态就回来了。

这次给数据根加上了一个身份标识，并让浏览器侧的状态按它划定作用域。

## 细节

- 在数据根首次被使用时，向 `<root>/install-id` 铸造了一个不透明 id，由新增的公开路由
  `GET /api/install` 提供。它被定为**身份**而非凭据——不授权任何操作，不含主机名、用户名或时间戳，
  使用普通文件权限，而不是 `api-token` 那一套处理。之所以公开，是因为 Web App 必须在还不知道是否
  有人登录时就发问，而刚被清空的数据根根本没有任何人处于登录状态。
- Web App 在 React 挂载之前，把该 id 与自己记录的值做了比较。不同则清除引用服务端实体的那些键；
  相同——也就是每一次普通重启——什么都不清。
- 采用「存一个 id + 一次清扫」，而不是把 id 嵌进每个键名：键名保持原样，磁盘上已有的键无需迁移，
  早先数据根遗留的孤儿键也在同一趟里被回收，而不是永久堆积。
- 保留了浏览器偏好：主题、语言、强调色、字号、显示币种、终端外观、侧边栏折叠、面板宽度、分组与排序
  方式、导航分组折叠，以及运行中发送模式。它们都不指向服务端的任何东西，清空数据根也不等于要求
  重置某人的主题。
- 会被清除的：会话草稿与停放的草稿、侧边栏 Workspace 登记表、置顶 Session、会话与分组的手动顺序、
  已读标记、折叠与置顶的侧边栏分组、上次的 Project 与 Agent、折叠的 Memory 作用域、模型页分组的
  展开状态与顺序、Dock 按会话记录的标签布局，以及独立终端页所附着的 shell。
- 真正发生清扫的那次启动改为重新加载页面，而不是继续渲染。整张静态 import 图的模块求值都发生在
  入口文件执行第一条语句之前，因此在模块作用域读过 `localStorage` 的模块——Dock 按会话记录的标签
  布局就是这样——手里已经握着清扫随后删掉的那份解析结果，它第一次切换作用域就会把整张清空前的表
  原样写回；而那时 id 已经对上，从此再也不会被清扫。重新加载让每个模块对着清扫后的存储重新求值，
  第二趟对账结果为「未变化」，正常渲染。
- 跨过这次清空仍然开着的标签页也会重新加载。清扫每次页面加载只跑一趟，因此另一个仍对着旧数据根的
  标签页把那份状态留在内存里，下一次置顶、拖动排序或草稿输入就会把它写回去；现在记录 id 的跨标签
  `storage` 事件会让其余每个标签页先清扫再重新加载。
- 该路由挂在了 platform 上，而不是 runtime 外壳里。一次热更新把 platform、CLI 与 web 产物作为一个
  版本一起送达，且从不包含 runtime，因此这个端点现在与调用它的产物同行——挂在 runtime 里的话，恰恰
  是那些通过热更新拿到新 Web App 的安装会缺少它，本次修复在那里会一直静默失效，直到下一次安装新的
  runtime。
- `penguin.chatRouteApplied.*` 未被触及：它存在 `sessionStorage` 中，作用域限于一个标签页的历史，
  不可能活得比数据根更久。
- 这张分类表从「靠自觉」改为「可强制」：新增的测试会读取 Web App 源码，收集其中每一个 `penguin.*`
  键字面量，只要有表里没覆盖到的就失败——遗漏一个 install 作用域的键，就会悄无声息地把这个 bug
  放回来。
- Workspace 在清空后存活的另一条路径被有意保留：若删掉了 `web.db` 但没有删掉 `default_project`
  目录，`ProjectService.provisionInitialProject` 会沿用已有目录及其 `.project_config.toml`，
  其中包括 `[default_chat].workspace`。该沿用行为是有意为之，本次未做改动。

## 兼容性

磁盘上已有的数据没有做任何迁移，升级时也没有销毁任何东西。相应的决定，以及在本版本**之前**清空过
数据根的用户唯一需要手动做的一件事，都记在[向后兼容](2026-08-27-backward-compatibility.zh.md)里。
