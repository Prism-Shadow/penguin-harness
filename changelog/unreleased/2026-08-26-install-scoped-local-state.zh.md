# 删除数据根后，浏览器侧属于它的 UI 状态也会一并清除

- **Date:** 2026-08-26
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#508](https://github.com/Prism-Shadow/penguin-harness/pull/508)

[English](2026-08-26-install-scoped-local-state.md)

删掉数据文件重启后，应用回来时仍然选中着原来的 Workspace。其中一部分状态本就不在数据根里：Web App
把新会话草稿、侧边栏登记的 Workspace、置顶的 Session、已读标记以及上次的 Project/Agent 存在
`localStorage`——在桌面端它位于 Electron 的 userData 目录，删除 `PENGUIN_HOME` 一个字节也碰不到。
而每个键里的用户与 Project 都是编译期常量（`admin`、`default_project`），于是清空重启后重新置备出
同样的 id，键再次对上，旧状态就回来了。

现在数据根带有一个身份标识，浏览器侧的状态按它划定作用域。

## 细节

- 服务端在数据根首次被使用时，向 `<root>/install-id` 铸造一个不透明 id，并由新增的公开路由
  `GET /api/install` 提供。它是**身份**而非凭据：不授权任何操作，不含主机名、用户名或时间戳，
  使用普通文件权限。之所以公开，是因为 Web App 必须在还不知道是否有人登录时就发问——而刚被清空的
  数据根根本没有任何人处于登录状态。
- Web App 在 React 挂载之前把该 id 与自己记录的值比较。不同则清除引用服务端实体的那些键；相同——
  也就是每一次普通重启——什么都不清。
- 采用「存一个 id + 一次清扫」，而不是把 id 嵌进每个键名：键名保持不变，磁盘上已有的键无需迁移，
  早先数据根遗留的孤儿键也在同一趟里被回收，而不是永久堆积。
- 保留的浏览器偏好：主题、语言、强调色、字号、显示币种、终端外观、侧边栏折叠、面板宽度、分组与排序
  方式、导航分组折叠，以及运行中发送模式。它们都不指向服务端的任何东西，清空数据根也不等于要求
  重置某人的主题。
- 会被清除的：会话草稿与停放的草稿、侧边栏 Workspace 登记表、置顶 Session、会话与分组的手动顺序、
  已读标记、折叠与置顶的侧边栏分组、上次的 Project 与 Agent、折叠的 Memory 作用域、模型页分组的
  展开状态与顺序、Dock 按会话记录的标签布局，以及独立终端页所附着的 shell。
- `penguin.chatRouteApplied.*` 不在此列：它存在 `sessionStorage` 中，作用域限于一个标签页的历史，
  不可能活得比数据根更久。

## 关于升级

一个已经存有这些键、但从未记录过 install id 的浏览器，与一个数据根被清空过的浏览器无法区分。因此它
会**沿用**当前 id 而不做任何清除——升级时毁掉合法状态，会是比正在修的这个更糟的 bug。

后果直说：**本次发布时已经陈旧的状态，不会因为装上这个版本而被清理。** 在此版本之前清空过数据根的
用户仍会看到旧的 Workspace，今天唯一的清理办法是手动操作——在浏览器中清除该应用来源（origin）的
站点数据，而这同时也会重置上面列出的那些偏好。只有从本版本起发生的清空才会被自动处理。

## 本次未修的部分

Workspace 还能通过另一条独立路径在清空后存活：若删掉了 `web.db` 但没有删掉 `default_project`
目录，`ProjectService.provisionInitialProject` 会沿用已有目录及其 `.project_config.toml`，其中包括
`[default_chat].workspace`。该沿用行为是有意为之，保持不变。
