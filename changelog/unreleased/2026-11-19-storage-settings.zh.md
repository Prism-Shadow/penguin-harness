# 设置 › 存储空间：显示数据根的占用，清理可以再生的文件

- **Date:** 2026-11-19
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `ui-gallery`, `docs`
- **PR:** [#1641](https://github.com/Prism-Shadow/penguin-harness/pull/1641)

[English](2026-11-19-storage-settings.md)

设置在「已归档对话」之后新增**存储空间**子页：按八个分类显示数据根的占用，并按 Project 与 Agent 分项；经审阅后清理可以安全删除的草稿区、临时工作区与缓存；按大小与时间列出会话，以删除其轨迹。成员看到并清理自己可进入的 Project，管理员另可看到并清理整个数据根。

## 细节

- **测量**：服务端在后台逐个单元测量——每个 Project 的文件夹一个单元，服务端自己的顶层条目一个单元——与后台删除 Agent 共用同一种限流（同时至多两个文件系统调用），不跟随链接。结果带测量时刻、只存在内存中；页面写明测量时刻，测量进行中时轮询，另有「刷新」；进行中的测量被复用，从不重开。
- **分类**：每个字节恰好计入一类——轨迹；Agent State（`agent_state/`、`agent_state.git/`、`snapshots/`）；临时工作区；草稿区；缓存（Agent 的 `shared_env/` 与数据根的 `.cache/`）；日志；插件；其他。管理员另见其不能进入的 Project 的合计（不列名称）与数据根的各个顶层条目。缓存文件夹在服务端登记为一张表（`packages/server/src/storage/layout.ts`），之后新增的缓存文件夹（如 Workbench 的缓存）登记进表，即计入缓存并可清理。
- **清理先审阅、再删除**：审阅只列出此刻可以安全删除的条目——孤立的草稿区（索引与 Trace 都没有该 Session，且一天内没有改动；缺省勾选）、闲置对话的草稿区（会话属于某个列表、未在使用、最近活动早于所选天数，缺省 7 天；缺省不勾选，删除后这些对话里附带的图片不再显示）、孤立的临时工作区（没有任何 Project 的会话以它、其中的文件夹或该 Agent 的目录与 `workspaces/` 为 Workspace，且一天内没有改动；缺省勾选——仍被会话使用的临时工作区从不列出）、Agent 的工具环境（`shared_env/<名称>/`，该 Agent 的会话都未在使用时列出；缺省不勾选），以及数据根 `.cache/` 的条目（只对管理员）。
- **删除**：每个条目重新判定，并在同一个同步步骤里以一次 rename 移开——Agent 级的移入 `agents/.deleting/`（服务端下次启动时本就会接着删完），服务端缓存移入该缓存自己的 `.deleting/`——之后才开始的 Task 不会写进正在删除的文件夹。「在使用」指：有 Task 或压缩在进行、有排队的输入、有仍在运行的后台进程或子会话，或正在被删除；由会话运行时新增的 `sessionInUse` 与 `agentInUse` 回答。
- **轨迹**：用户的 Project 中的会话按大小（Trace 文件加上测量到的草稿区）或最近活动列出，可按 Agent、归档与否与时间筛选，至多 500 条；运行中的会话标出、不能勾选。「清理旧对话」打开同一个列表，预设为 30 天前的已归档会话。删除走已归档对话页现有的批量删除，会话的子会话、草稿区与草稿一并删除。「已归档对话」打开该子页。
- **接口**：新增 `GET /api/me/storage`、`POST /api/me/storage/refresh`、`GET|POST /api/me/storage/cleanup`、`GET /api/me/storage/sessions` 与 `POST /api/me/storage/reveal`（在桌面应用自己的窗口中显示数据根或 Project 的文件夹）。
- **共享 UI**：共享 UI 包新增带图例的堆叠用量条与「先审阅、再删除」列表，各有组件画廊展板；画廊为每个新接口提供模拟数据。
- **文档**：设置与 Server API 两页写明了这个子页与它的接口。
