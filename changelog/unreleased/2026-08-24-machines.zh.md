# 在「机器」页面把服务端装到另一台机器上

- **Date:** 2026-08-24
- **Type:** feature
- **Scope:** `server`, `web`, `desktop`, `docs`

[English](2026-08-24-machines.md)

侧栏「模型库」下方新增的**机器**页面，列出服务端自身 `~/.ssh/config` 中声明的主机，并把当前这套 PenguinHarness 安装到你选中的那一台上。它取代了桌面应用菜单里的 **Install Server on Remote Host**——那个入口只能靠重新分发应用才能更新，而且只存在于 Electron 壳里。

## 列表

目标只来自 `~/.ssh/config`，别无他处。列表就是配置文件的文本本身——只有别名，不跑 `ssh -G`，不起进程，不联网——所以哪怕配置里声明了几百台主机，代价也只是一次文件读取。`Host *` 这类模式条目会被跳过（它们是在配置别的主机，而不是命名某一台），`Include` 通配则按 OpenSSH 自己的方式展开。该文件永远只读不写。别名到用户、主机名与端口的解析只在真正安装时才发生，而且交给 `ssh -G` 去做，因此 `Match`、`Include` 与通配继承的行为与 ssh 所述完全一致。

无论个人服务端还是多用户服务端都仅限管理员：安装会以**服务端账户**的密钥派生 ssh，并在另一台机器上写入程序目录。对其他人，侧栏里根本不会渲染这一行。

## 如何选择

主机以选择器（下拉菜单）呈现，而非平铺列表——ssh 配置动辄声明几百条。面板先显示前几条，上方是搜索框，并用一行计数说明当前视图省略了多少台：静默截断会被读成「我的配置里没有那台主机」。查询采用**子序列**匹配而非子串匹配，因为别名带有标点，而你记得的往往是字母、不是分隔符：`gpu1` 能找到 `gpu-01`。排序上，连续命中优于词首命中，词首命中优于零散命中，同分则保持配置文件自身的顺序；每一行还会高亮查询真正命中的字符——在子序列匹配下，一行不作标记就会显得像是错误结果。

## 安装的是什么

是本服务端正在运行的东西，靠探测得到而非靠配置指定。按顺序探测三种形态：hmr 存储中热推过的版本（由推送的 CLI bundle、web 产物与技能库组装而成，版本号打为 `0.0.0-hmr.<cli>.<web>`）、tarball 安装自身的程序目录、以及桌面应用暂存的 payload。因此「两端一致」是构造性成立的——对端收到的就是这一端正在运行的字节；每一次新的热推也都会给远端带来一个可升级到的新版本。只有从未被热推过的源码检出没有镜像，页面会预先说明，而不是让每次安装都倒在同一步。

发送任何东西之前先询问对端是什么。Node 22 及以上会直接复用对端自己的 `node -v`——常见情况因此不需要下载、不需要传输约 30 MB、也不会在已有 Node 的机器上再装一份；低于 Node 24 时会把 `--experimental-sqlite` 打进启动器，因为服务端用到的 `node:sqlite` 在那些版本里位于该开关之后。否则从 nodejs.org 拉取该平台与架构的官方构建，对照该发布自带的 `SHASUMS256.txt` 校验，并作为 `lib/runtime` 安装；未经校验的下载绝不会离开本机，运行时按形态缓存，因此同类的第二台主机同样没有下载开销。

判定规则是：未安装 → 安装；版本不同 → 替换；版本相同 → 无需操作。远端最终得到的与一次普通安装一致——程序目录（`~/.local/share/penguin`、`%LOCALAPPDATA%\penguin`）内含运行时，POSIX 上另有 `~/.local/bin/penguin` 符号链接。不需要 sudo，不写 systemd unit，不改 profile，数据目录也始终不被触碰。

## 过程可见

最坏情况下安装以分钟计，因此它是一个任务：页面启动它之后转入轮询，展示的进度行凡是有对端原话的地方就用对端自己的话——关于一把被拒绝的密钥或一个不可用的 Node，ssh 的诊断与远端安装器的输出比任何改写都说得更清楚。同一时刻只有一个安装在跑，期间按钮拒绝再次启动。任务面板跟随**任务**并标明它所属的主机，而不是跟随当前选择——安装进行中再选另一台，不应把正在跑的那次安装从画面上挤掉。任务存在服务端内存里，热推与重启都不保留，重跑即是恢复手段：每一步都是幂等的，而对端的安装器会先暂存、冒烟测试再切换，切换开始后一旦失败便恢复原有安装。

## 认证

连接一律带 `BatchMode=yes`：这里没有任何终端，一个决定索要密码的 ssh 只会挂在那里无处输入。目标主机必须已经能用密钥或 agent 认证；不能时，页面原样展示 OpenSSH 自己的诊断信息。

## 细节

- 新增 API（仅管理员）：`GET /api/machines` 与 `POST /api/machines/:machineId/install`（见 [服务端 API 参考](../../packages/docs/content/server-api.zh.md)）。
- 该能力从 `packages/desktop/src/remote/` 迁到了 `packages/server/src/machines/`，这正是它得以在浏览器中可达、对 tarball 安装同样可用、并且能通过热推下发的原因。桌面应用仍然会把安装镜像暂存进自己的资源目录——打包后的应用正是三种镜像形态之一。
- 在对端运行的安装器现在以文本形式内嵌在服务端 bundle 里，不再从文件读取：热推的 bundle 位于 hmr 存储中，那里解析不到任何同级文件。
