# 机器上的 Agent 归那台机器所有

- **Date:** 2026-10-15
- **Type:** feature
- **Scope:** `web`, `ui`, `docs`
- **PR:** [#1152](https://github.com/Prism-Shadow/penguin-harness/pull/1152)

[English](2026-10-15-machine-agents.md)

智能体页、创建弹窗与插件市场此前把 Agent 当作每个 Project 一份：智能体页按 Agent id 把每台已连接机器的列表并进本服务端的列表，于是机器自己的 `default_agent`（以及 id 在本服务端也存在的任何 Agent）从不显示，只有机器上才有的 Agent 则显示为一张不可操作、让人「到那台机器上管理」的卡片。现在每台机器的 Agent 都作为那台机器自己的 Agent 列出、打开、修改、对话、删除和安装插件。

## 细节

- 智能体页把每台已安装机器的 Agent 与本服务端的 Agent 并列在同一列表里，按列表本身的顺序（先创建的在前），如同侧栏把机器上的工作区与本机的并列；机器上的卡片在 Agent 名称之后写 `[SSH: <别名>]`，与机器上的工作区分组同一写法；两台服务端上同 id 的 Agent 是两张卡片。机器卡片的名称、「设置」与统计项打开它在那台机器上的设置页，「新建对话」在那台机器的临时工作区开草稿，「删除」先确认（文案点明机器）再在那台机器上删除；成本中心仍只统计本服务端。机器正在重连、服务已停止或读取失败时，它上次答复的 Agent 仍留在列表中、整卡淡显，标签之后一枚拔出插头的图标，悬停写明原因，各按钮不可用、悬停提示同一原因。
- Agent 设置页接受 `?machine=<机器 ID>`：各标签页都经那台机器读写，在对话中导入技能或钩子包、用 AI 添加记忆、密钥或定时任务都在那台机器上开对话，定时任务弹窗的模型、工作区与 Session 取自那台机器，API 标签页写那台机器上的地址；问不到那台机器时只显示原因。
- 机器上的 Session 通往其 Agent 设置的链接（记忆面板的管理链接、输入框的 Agent 设置）现在打开那台机器上的该 Agent。这些链接此前已带 `?machine=`，设置页显示的却是本服务端同 id 的 Agent。
- 有已连接的机器时，创建弹窗首行为「位置」（本机或某台已连接的机器）。选了机器时，可选的插件来自那台机器的插件库，技能目录在那台机器上浏览，Agent 建在那台机器上，建好后进入它在那台机器上的设置页。
- 插件市场的「管理安装」按智能体页的顺序把已连接机器上的 Agent 与本服务端的并列，名称后写 `[SSH: <别名>]`；这些行上的安装、卸载、更新与「设置」都经那台机器进行、用那台机器的插件库，卡片上的「N 个 Agent 在用」与状态把它们计入。导航角标与页头的批量更新仍只计本服务端的 Agent。
- 在这些页面上创建或删除机器上的 Agent 后，会话列表也会重新读取那台机器的 Agent，侧栏不再列出已删除 Agent 的会话。
- 插件市场页头与系统设置插件页上的机器切换改为共用的 `Select`、取 `sm` 档，与旁边的搜索框、分组下拉和按钮同高（此前是固定高度的按钮，比旁边的控件高出约 5px）；`Button` 新增与 `base` 档控件同高的 `base` 档，组件画廊并排展示每一档的下拉、输入框与按钮。
- 与 Agent 相关的 API 封装末尾多一个机器 ID 参数（共用的辅助在 `lib/agent-location.ts`、`lib/machine-agent-lists.ts`），`deleteAgent` 的路径改为经过编码。
- 智能体文档与插件安装文档写明了机器上的 Agent 与创建位置。
