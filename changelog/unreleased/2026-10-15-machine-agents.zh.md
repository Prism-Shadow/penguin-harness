# 机器上的 Agent 归那台机器所有

- **Date:** 2026-10-15
- **Type:** feature
- **Scope:** `web`, `docs`

[English](2026-10-15-machine-agents.md)

智能体页、创建弹窗与插件市场此前把 Agent 当作每个 Project 一份：智能体页按 Agent id 把每台已连接机器的列表并进本服务端的列表，于是机器自己的 `default_agent`（以及 id 在本服务端也存在的任何 Agent）从不显示，只有机器上才有的 Agent 则显示为一张不可操作、让人「到那台机器上管理」的卡片。现在每台机器的 Agent 都作为那台机器自己的 Agent 列出、打开、修改、对话、删除和安装插件。

## 细节

- 智能体页先列本服务端的 Agent，其后每台已安装的机器一个横线分节（**gpu-box 上的 Agent**），卡片在 Agent 名称之后写 `[SSH: <别名>]`，与机器上的工作区分组同一写法；两台服务端上同 id 的 Agent 是两张卡片。机器卡片的名称、「设置」与统计项打开它在那台机器上的设置页，「新建对话」在那台机器的临时工作区开草稿，「删除」先确认（文案点明机器）再在那台机器上删除；成本中心仍只统计本服务端。机器正在重连、服务已停止或读取失败时，分节标题下写明原因，下面是它上次答复的 Agent，按钮全部不可用。
- Agent 设置页接受 `?machine=<机器 ID>`：各标签页都经那台机器读写，在对话中导入技能或钩子包、用 AI 添加记忆、密钥或定时任务都在那台机器上开对话，定时任务弹窗的模型、工作区与 Session 取自那台机器，API 标签页写那台机器上的地址；问不到那台机器时只显示原因。
- 有已连接的机器时，创建弹窗首行为「位置」（本机或某台已连接的机器）。选了机器时，可选的插件来自那台机器的插件库，技能目录在那台机器上浏览，Agent 建在那台机器上，建好后进入它在那台机器上的设置页。
- 插件市场的「管理安装」在本服务端的 Agent 之后列出已连接机器上的 Agent，名称后写 `[SSH: <别名>]`；这些行上的安装、卸载、更新与「设置」都经那台机器进行、用那台机器的插件库，卡片上的「N 个 Agent 在用」与状态把它们计入。导航角标与页头的批量更新仍只计本服务端的 Agent。
- 在这些页面上创建或删除机器上的 Agent 后，会话列表也会重新读取那台机器的 Agent，侧栏不再列出已删除 Agent 的会话。
- 与 Agent 相关的 API 封装末尾多一个机器 ID 参数（共用的辅助在 `lib/agent-machine.ts`、`lib/machine-agents.ts`），`deleteAgent` 的路径改为经过编码。
- 智能体文档与插件安装文档写明了机器上的 Agent 与创建位置。
