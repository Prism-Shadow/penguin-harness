# 被限流的会话改到 Project 降级链的下一个模型上跑完

- **Date:** 2026-10-13
- **Type:** feature
- **Scope:** `core`, `server`

[English](2026-10-13-429-failover.md)

模型回答 **429** 时，该轮会把整条同模型重连阶梯——默认五次重连、约 60 秒退避——耗在一份已经用完的配额上，最后还是结束该轮。现在它会改到 Project 降级链的下一个模型上，在同一段对话里把该轮跑完。

## 链

`.project_config.toml` 里的 `[[model_fallback_chain]]` 是一份有序的成对引用列表，优先级从高到低：

```toml
[[model_fallback_chain]]
provider = "anthropic"
model_id = "claude-sonnet-4-6"
```

它经模型 API 读写（`GET` / `PUT /api/projects/:p/models` 的 `fallbackChain`）；指向的模型若在同一次请求里没有被保留，该条目会被丢弃而不是留成悬空引用。**未配置（或为空）= 不降级**：被限流的一轮仍像过去一样在自己的模型上重试——每个 Project 在明确开启之前都是这样。

## 这次移动

- 429 的结果是 `retryable` + `error_code: rate_limited`，这正是把它与传输中断区分开的依据（见上一条）。
- 当一次 run 以该结果结束，且链上存在「既不是当前模型、也未曾被切过去过」的条目时，宿主会把这次移动**与该轮的重发**一起排队，并排在用户已排队的输入之前。
- 移动发生在下一个 Task 边界，驱动方式与 `POST /switch-model` 完全相同——因此它就是普通的会话内切换（关闭上下文、压缩、在新模型上重开），切换的事件照常进入频道与 Trace，`model_switch` 记录使它在重启后依然成立。没有任何手工的历史迁移。
- **有界**：每个模型每个会话最多试一次，因此整条链都被限流时会停下而不是来回打转，该轮随后按原来的方式结束。
