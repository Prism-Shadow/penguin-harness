# 终端归开启它的对话所有；侧栏里的终端是一个带标签页的面板

- **Date:** 2026-10-18
- **Type:** fix
- **Scope:** `server`, `web`, `ui`, `docs`
- **PR:** [#1207](https://github.com/Prism-Shadow/penguin-harness/pull/1207)

[English](2026-10-18-terminal-scope.md)

在一个对话里开的终端，可以从另一个对话里打开：在远程机器上运行的对话里新建的终端，交给独立窗口之后，会出现在本地对话侧栏的菜单里，并且能在那里打开。侧栏此前凭浏览器里存着的布局推测终端归属，任何一份已存布局都没占着的活动终端都会提供给每一个对话。现在终端归开启它的对话所有，归属记在服务端，只有那个对话列出、打开它。侧栏里的终端是每个对话一个「命令行终端」面板，像浏览器面板装着它的网页那样，以自己的标签页装着本对话的终端；侧栏的「在新窗口打开」已取消。

## 细节

- 服务端记录每个终端是为哪个对话打开的：`POST /api/terminals` 接受 `sessionId`，每个终端的信息都带上它（打开时没有给出则为 `null`），`PATCH /api/terminals/:id` 把终端改记到另一个对话名下，Web App 在对话 id 自愈更换时用它。
- 终端与其他面板一样是一个侧栏面板「命令行终端」，列在侧栏的「+」菜单、空侧栏的选单（带 `` Ctrl+` `` 按键）和悬浮球里，缺省落在下侧栏。此前每个终端各占一个侧栏标签，「+」菜单里的「新建终端」一行每点一次就新开一个。
- 面板的标签条列出本对话在其所在机器上活着的终端，各标编号和标题，在另一台设备或另一个浏览器里为本对话开的也在其中。条末的 +（「新建终端」）再开一个并切到它，标签上的 × 确认后结束那个终端。其他对话、其他机器、其他 Project 的终端，以及经 API、CLI 或独立 `/terminal` 页面打开的终端，一律不会列出。这条标签条就是浏览器面板的那一条，现作为 UI 包的 `PanelTabs` 由两个面板共用。
- 对话没有活着的终端时打开面板，会新开一个。最后一个终端结束时，无论是点 × 关闭还是自行退出（`exit`），面板随之关闭；面板是侧栏最后一个标签时侧栏一并收起。第一个终端没能启动时，弹出错误提示后面板也关闭。`` Ctrl+` `` 隐藏、调到前面或打开这个面板，`` Ctrl+Shift+` `` 在面板里再开一个终端。当前显示的终端按对话记住，刷新后也一样。
- 新对话在发出第一条消息之前没有终端：草稿页不提供这个面板，`` Ctrl+` `` 与 `` Ctrl+Shift+` `` 在草稿页不生效。草稿页的侧栏布局按 Project 区分，不再由所有 Project 的新建对话页共用一份。
- 旧版本存下的侧栏布局里每个终端各有一个标签（`terminal:<id>`）。读入时，每个侧栏的第一个这样的标签在原位变成终端面板的标签，原来显示的终端继续显示，其余丢弃；草稿页布局里的这些标签直接丢弃。旧版本让其穿越到别的对话里的标签因此会消失一次，因为面板只列出本对话自己的终端。读取旧格式的代码在 `packages/web/src/features/dock/legacy-terminal-tabs.ts`，下次 `penguin.dock.layout` 改变格式时连同它的唯一调用一并删除。
- 本窗口正在新开或改记终端时读到的列表不会被采用，而是重新读取。
- 旧版本机器不报告终端的归属，因此在该机器更新之前，它的终端不会列在任何面板里；仍可经 `/terminal?id=` 打开。
- 侧栏头部的「在新窗口打开」按钮及其往返（终端交给 `/terminal` 窗口，窗口关闭后再收回侧栏）已移除；要放大终端，用侧栏的全屏。独立 `/terminal` 页面仍可按地址打开。
- 向运行旧版本的机器推送本版本时，那台机器上开着的终端会被关闭而不是接管，因为旧版本的终端无法记录归属。
