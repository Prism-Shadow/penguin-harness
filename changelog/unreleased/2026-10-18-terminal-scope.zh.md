# 终端归开启它的对话所有，始终是该对话侧栏里的一个标签页

- **Date:** 2026-10-18
- **Type:** fix
- **Scope:** `server`, `web`, `docs`
- **PR:** [#PRNUM](https://github.com/Prism-Shadow/penguin-harness/pull/PRNUM)

[English](2026-10-18-terminal-scope.md)

在一个对话里开的终端，可以从另一个对话里打开：在远程机器上运行的对话里新建的终端，交给独立窗口之后，会出现在本地对话侧栏的菜单里，并且能在那里打开。侧栏此前凭浏览器里存着的布局推测终端归属，任何一份已存布局都没占着的活动终端都会提供给每一个对话。现在终端归开启它的对话所有，归属记在服务端，只在该对话的侧栏里列出、打开。侧栏的「在新窗口打开」已取消：终端始终是对话侧栏里的一个标签页。

## 细节

- 服务端记录每个终端是为哪个对话打开的：`POST /api/terminals` 接受 `sessionId`，每个终端的信息都带上它（打开时没有给出则为 `null`），`PATCH /api/terminals/:id` 把终端改记到另一个对话名下，Web App 在对话 id 自愈更换时用它。
- 一个对话的侧栏只列出、只打开它自己的终端，且只在对话所在的机器上。「+」菜单里的终端一行由「新建终端」改为「命令行终端」，图标换成终端图标，其下列出本对话在别处（另一台设备或另一个浏览器）开着、这里还没有标签的终端。空侧栏的选单、悬浮球和 `` Ctrl+` `` 先带回这样的终端，没有才新建。其他对话、其他机器、其他 Project 的终端，以及经 API、CLI 或独立 `/terminal` 页面打开的终端，一律不会出现。
- 新对话在发出第一条消息之前没有终端：草稿页不提供终端入口，`` Ctrl+` `` 与 `` Ctrl+Shift+` `` 在草稿页不生效。草稿页的侧栏布局按 Project 区分，不再由所有 Project 的新建对话页共用一份。
- 刷新终端列表时，不归本对话所有的终端标签会从每一份已存的侧栏布局中移除，与此前已结束终端的标签一样。旧版本让其穿越到别的对话里的标签，会在更新后第一次刷新时消失一次。本窗口正在新建或改记终端时读到的列表不会被采用，而是重新读取。
- 旧版本机器不报告终端的归属：这些终端已有的标签保持原位，在该机器更新之前不会出现在任何菜单里。
- 侧栏头部的「在新窗口打开」按钮及其往返（终端交给 `/terminal` 窗口，窗口关闭后再收回侧栏）已移除；要放大终端，用侧栏的全屏。独立 `/terminal` 页面仍可按地址打开。
- 向运行旧版本的机器推送本版本时，那台机器上开着的终端会被关闭而不是接管，因为旧版本的终端无法记录归属。
