# 热更新通道有了自己的体积上限

- **Date:** 2026-08-23
- **Type:** fix
- **Scope:** `server`
- **PR:** [#426](https://github.com/Prism-Shadow/penguin-harness/pull/426)

[English](2026-08-23-hot-update-has-its-own-size-bound.md)

`POST /api/hmr/upgrade` 解压 gzip 请求体时没有任何界限：几百 KB 的传输量就能决定这个进程分配多少
GB，而请求要等到 `JSON.parse` 撞上已经解压出来的内容才会失败。现在升级通道有了自己的 256MB
上限，对压缩后的请求体和它解压后的大小同时生效。

## 细节

- 这个数字是传输真正走不通的地方，而不是偏好：解压后的载荷会变成一个字符串交给 `JSON.parse`，而 V8
  的字符串上限在 512MB 附近。真实推送是个位数 MB。
- 给解压后的大小定界，才让给请求体定界有意义——通道因此声明自己的数字，而不是沿用 `/api/*` 那条针对
  JSON 请求体的上限：后者对一条 gzip 流会膨胀成多大没有任何发言权。
- 上限在通道自己的鉴权之前生效，于是超大的请求体会在流上被截断，而不是一边校验凭据一边被缓冲下来。
