# 路由组的 auth 标记不再随挂载位置而变

- **Date:** 2026-09-18
- **Type:** fix
- **Scope:** `server`
- **PR:** [#793](https://github.com/Prism-Shadow/penguin-harness/pull/793)

[English](2026-09-18-route-group-auth-per-group.md)

平台的 HTTP 面原先只在第一个受保护路由组之前、于 `/api/*` 上挂一次登录门。现在登录门挂在每个受保护路由组
自己的前缀上，路由组的 `auth` 标记不再取决于它的 `order`。

## 细节

- 以 `auth: "none"` 贡献、位于 `/api` 下的路由组，即使排在受保护路由组之后也保持公开。此前，未登录的请求
  会得到 401。
- 受保护的路由组在自己的前缀上设门（含前缀本身），无论该前缀是否位于 `/api` 之下。路径经过多个受保护前缀的
  请求只鉴权一次。
- 没有任何路由组服务的路径由平台拒绝，返回 404。此前，`/api` 下的这类路径对未登录的请求返回 401。
- `GET /api/contributions` 的响应中，每条贡献的 `id` 与 `from` 恒为服务端自己的归属信息。此前，贡献数据中
  的同名字段会将其覆盖。
