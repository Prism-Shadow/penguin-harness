# 机器重连合成一行，5 次后停止，并可随时放弃重试

- **Date:** 2026-10-26
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `ui-gallery`, `docs`
- **PR:** [#1344](https://github.com/Prism-Shadow/penguin-harness/pull/1344)

[English](2026-10-26-unified-retry-row.md)

本服务端保持连接的机器，现在连续失败 5 次（原为 8 次）后停止自动重连，用户也可以随时放弃重试。机器管理页和那台机器上的对话里，重连进行到哪里只占一行：等待时为「23 秒后尝试第 4/5 次重连」，尝试时为「正在尝试第 4/5 次重连」，「立即重试」和「放弃重试」是同一行里的链接样式文字。上一次失败的原因收在句末的带圈问号里。

## 服务端

- 重连连续失败 5 次即停止这一轮（`reconnect.maxAttempts` 为 5）。每次尝试前的等待从 5 秒起翻倍，不再另设上限。
- `POST /api/projects/:projectId/machines/:machineId/stop-reconnecting` 立即停止正在等待或正在尝试的一轮（`reconnect.gaveUp: "cancelled"`，`nextAt: null`），此后直到「重试」「启动服务」或本服务端重启都不再尝试。已在进行的那次尝试不会被打断：连上了，机器即为已连接；失败了，之后不再安排。已连接的机器、已停止的一轮不受影响。答复机器列表，或 `404` `unknown_machine`。
- 放弃重试时某次尝试仍在进行，随后再按「重试」，会把这次尝试算作新一轮的第 1 次，不再并行发起第二次。保存的密码被拒的机器，重新保存密码后会立即试一次，无论此前是否放弃过重试。

## 机器管理页与对话

- 卡片中段、详情弹窗的「重新连接」分节，以及机器连不上的对话里，重试行依次为：「23 秒后尝试第 4/5 次重连」，带「立即重试」与「放弃重试」；「正在尝试第 4/5 次重连」，带「放弃重试」；「5 次重连均失败」「已放弃重试」，以及重试也不会好转的 ssh 失败「重连失败，需先解决 ssh 问题」，均带「重试」；「登录被拒，已停止重连」不带任何操作。倒计时在句中逐秒刷新。
- 在卡片和对话里，上次失败的原因（ssh 拒绝或密码被拒时为解决办法）收在句末的带圈问号里。详情弹窗的重试行不带问号：分节在它下面先写已持续多久，再写出完整的上次失败。
- 卡片中段较窄时，两个操作一起换到句子下面。

## UI 包与组件画廊

- `RetryStatus` 改为一行：标记、句子、`reason` 对应的问号，以及链接样式的操作。新增第五个阶段 `cancelled`（淡色的暂停）。`gaveUp` 改用危险色的叉。`countdown` 返回剩余秒数下的整句，`label` 是时刻到达后显示的句子，`size`（`xs` / `sm`）取代 `layout`。
- `RetryActions` 新增 `look`：默认的 `button` 让对话里模型请求的重试提示行保持原样，`link` 用于重试行。
- 组件画廊的「重试」主题展示两种尺寸下的五个阶段，模拟 API 也响应新路由。
