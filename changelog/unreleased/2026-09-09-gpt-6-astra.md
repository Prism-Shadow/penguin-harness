# GPT-6 Astra in the built-in catalog, direct and on OpenRouter

- **Date:** 2026-09-09
- **Type:** feature
- **Scope:** `model-catalog`, `core`, `docs`, `skills`

[中文版](2026-09-09-gpt-6-astra.zh.md)

The built-in model catalog gained OpenAI's GPT-6 Astra twice over: `gpt-6-astra` at the head of the direct OpenAI group and `openai/gpt-6-astra` at the head of the OpenRouter `openai/*` rows. Both carry a 1,050,000-token context window and accept images.

## Details

- **`gpt-6-astra` (provider `openai`)** — display name GPT-6 Astra, 1,050,000-token context window, `vision = true`, and neither `client_type` nor `base_url`: like every direct OpenAI row it is auto-routed by its id, and a blank credential falls back to `OPENAI_API_KEY` / `OPENAI_BASE_URL`. Prices per MTok are $1 / $12.5 / $50 (cache read / cache write / output), read on 2026-09-09 from https://developers.openai.com/api/docs/models/gpt-6-astra, whose list is $10 input, $1 cached input, $12.5 cache write and $50 output. The `cache_write` bucket carries the published cache-write price; the $10 rate applies only to input that is never written to cache, a split the three buckets do not express. Every rate doubles above 272K input tokens (output 1.5x) — the row records the base tier, as the catalog does for every tiered vendor.
- **`openai/gpt-6-astra` (provider `openrouter`)** — the same window, vision flag and $1 / $12.5 / $50 prices, with `client_type = "openai-responses"` and the preset OpenRouter base URL, matching its `openai/*` siblings. Read on 2026-09-09 from the models API and the per-model endpoints API: the default endpoint is OpenAI's own and reports `discount: 0`, so the list price is what OpenRouter bills. The endpoints API also publishes overrides above 272,000 prompt tokens, which the row does not record.
- **Routing and fast mode mirror AgentHub.** `resolveModelEnv` and `fastModeProtocol` gained the `gpt-6` substring beside `gpt-5.4` / `gpt-5.5` / `gpt-5.6`, so a `gpt-6*` id resolves the `OPENAI_*` pair and is offered the fast-mode toggle on the OpenAI protocol (`service_tier: "priority"`). That mirrors the routing AgentHub's GPT client takes on in its next release; until PenguinHarness moves to that release the id sits in the catalog without being routable at runtime, because `@prismshadow/agenthub` stays pinned at `^0.4.8` here and the bump is a separate change.
- Both rows sit where the catalog's ordering rule puts them — dictionary order by model id within a provider, newer series first — so `gpt-6-astra` precedes `gpt-5.6` and `openai/gpt-6-astra` precedes `openai/gpt-5.6-luna`. Tests pin both positions, both prices, the gateway row's context window and protocol pin, and the two routing answers.
- The bilingual `models` page names `gpt-6-astra` in its sample of the preset catalog. The `unified-llm-api` skill gained a GPT-6 row in its model-id table, `gpt-6` in its routing-order list, and `gpt-6` as the GPT client type that maps fast mode; the `agent-development` plugin's version moved to `2026-09-09.1` so installed copies are offered the update.

## Compatibility

Existing Projects do not pick the two rows up on their own: presets are copied into `.project_config.toml` when the Project is created, and nothing rewrites them afterwards. Use **sync presets** on the models page to bring them into a Project that already exists — it appends catalog entries the Project is missing and updates catalog-owned fields on the ones it has, deleting nothing and touching neither the stored default model nor any credential.
