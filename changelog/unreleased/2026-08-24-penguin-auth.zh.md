# `penguin auth` —— 在终端里登录服务

- **日期：** 2026-08-24
- **类型：** feature
- **范围：** `cli`、`server`、`docs`

[English](2026-08-24-penguin-auth.md)

以前没有办法在终端里登录 PenguinHarness 服务。CLI 做的一切都是直接操作数据根——`config`、`run`、
`chat` 都是开文件，从不开 socket——所以它从来不需要充当客户端，"登录"除了浏览器登录页之外没有答案。

```bash
penguin auth login                      # 用密码登录该数据根上运行的服务
penguin auth login --server https://penguin.example --user-id alice
penguin auth status
penguin auth logout
penguin auth token                      # 不需要密码：直接从数据根签发
```

## 两种登录方式

`login` 需要密码，向正在运行的服务发起请求，和浏览器登录页做的事完全一样。目标默认是该数据根上正在
运行的服务（从锁文件读端口），所以登录自己的服务不必写 URL。交互运行时会先问账号，并在密码提示里写明
是哪个账号的，避免把一个账号的密码输到另一个账号上；如果用非交互方式给了密码，两个问题都不会问——那是
脚本，脚本没法回答。

`token` 完全不需要密码。它直接从数据根签发会话，其授权依据就是你能读这个数据根——而它本来就装着这个
令牌所能触及的全部凭据。适用于没有密码可给的场合：管理员密码被人改过的机器，或不该持有密码的脚本。

## 会话现在是签名声明

鉴权在每个请求上都要跑，是服务里最热的一条路径。会话过去是一行数据库记录——每个请求一次读，每次签发和
续期一次写。现在它是签名令牌（`v1.<claims>.<hmac>`，密钥只在进程内存里）：签发和验证
都是纯 CPU，数据库只记录例外——过期前的登出会写进一张很小的吊销表，启动后常驻内存，过期的吊销行在启动
和每次登录时清扫。CLI 签发时向运行中的服务兑换本次启动的 owner token；服务停着时退回插入一行会话记录——那是唯一不需要密钥的形态。

行模型保证过的性质换了实现方式后依然成立：只要密钥还活着，登出就是真吊销——而密钥能穿越热推（热推只换 App 不换进程）；管理员重置密码仍会杀掉
该用户的全部在外会话（按用户的 not-before 标记，因为已无行可删）；切换之前签发的会话继续按行验证直到
过期；长会话照样滑动续期，只是从改行变成下发替换 cookie。声明里记 `v: "cli"`，且不因此获得任何权限——
凡不是 `desktop` 的都按普通密码会话处理，签出来的令牌永远够不到桌面端专属路由。

真正放弃的性质只有一条：签发本身不留审计痕迹——只有吊销留痕。（签名密钥本身不落盘，见 owner-token 一条。）

## 其它

- 会话写入 `<root>/cli-session.json`，权限 0600，并在覆盖写时重新设置：`mode` 写入选项只在创建时生效，
  否则重新登录会悄悄把令牌降级为所有人可读。
- `logout` 会先告诉服务端，让会话在那边真正失效，而不只是本地忘记；连不上服务时本地文件照样删除。
- 优先用 `PENGUIN_PASSWORD` 或交互输入，而不是 `--password`：命令行参数可以被 `ps` 看到。
