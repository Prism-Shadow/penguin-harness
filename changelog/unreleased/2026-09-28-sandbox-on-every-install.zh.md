# 每一种安装都有沙盒

- **Date:** 2026-09-28
- **Type:** feat
- **Scope:** `release`, `server`, `web`

[English](2026-09-28-sandbox-on-every-install.md)

每个平台、每种安装方式看到的是同一个沙盒：输入框的权限菜单、设置对话框插件页上的「沙盒」卡片，以及随时可以启用的本平台后端。平台之间的区别只在由哪个后端实施、以及它自己的选项（画在「沙盒」卡片里面）。封禁仍默认关闭，不替运维启用任何东西。

- **安装的 CLI 带上内置插件。** 各平台（Linux、macOS、Windows）的安装包都在 `lib/plugins/` 下附带内置插件前缀——其中包括四个沙盒后端——与桌面端此前的做法相同。在插件页启用本平台的后端不再经过网络；此前安装的 CLI 要从 npm registry 取包，连不上 registry 的主机就没有沙盒可启用。
- **输入框说明哪些档位没有后端能实施。** 未安装任何沙盒后端时，「只读」「仅工作区可写」「无网络」「本地网络」仍列出，但置灰并标注「未安装」，提示里写明如何添加后端——此前它们可以被选中，随后每条命令都会被拒绝。后端已启用、但加载失败或检查没通过时（例如专用发行版尚未初始化的 WSL 后端），这几个档位改标「不可用」，提示里写出该后端的名字与原因。只能封禁文件、不能管网络的后端（DSH 适配器）只置灰它实施不了的网络档位。
- API 中 Session 的 `sandbox` 对象在 `localNetworkSupported` 旁新增三个仅用于响应的字段：`confinementSupported`（「只读」与「仅工作区可写」可以实施）、`noNetworkSupported`（「无网络」可以实施）与 `unavailableBackends`（已启用但未在用的后端及原因；适用于其他平台的后端不列）。
