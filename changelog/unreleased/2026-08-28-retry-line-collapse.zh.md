# 一轮重试在对话里只占一行，而不是每次一行

- **Date:** 2026-08-28
- **Type:** fix
- **Scope:** `web`
- **PR:** [#528](https://github.com/Prism-Shadow/penguin-harness/pull/528)

[English](2026-08-28-retry-line-collapse.md)

每一次可重试的请求结束都会新增一行，于是一个重试了四次的请求在对话里留下四行：

```
[重试]连接超时或网络中断，已发起第 1 次重试
[重试]连接超时或网络中断，已发起第 2 次重试
[重试]网络或服务暂时不可用，已发起第 3 次重试
[重试]连接超时或网络中断，已发起第 4 次重试
```

现在后一次重试会覆盖前一次，这一轮只显示一行，并一直数到「已发起第 4 次重试」。次数本来就写在这一行里，因此「一共重试了几次」并没有从对话中丢失。

## 细节

- 合并只发生在对话页的视图模型（`lib/omni/stream-model.ts`）里。**Trace 不受影响**：每一次尝试仍作为独立事件被记录，而 Trace 面板是基于原始事件而非该模型构建的，因此完整的重试过程在那里依然可读。引擎的重试行为没有任何改动。
- 失败的尝试若没有产出任何内容，该轮重试会合并为一行；若某次尝试在中断前已经流出思考或正文，这些内容会插在两次之间，该轮便不合并，仍与以往一样每次一行。
- 新的一次故障另起一行，不会覆盖上一轮：同一次事件内的尝试序号递增，下一次事件则从第 1 次重新开始。
- **已放弃的那一轮会保留自己的行。** 它承载着最终失败及其详情，是最值得留在屏幕上的一行；之后的事件另起一行。
- 被覆盖的 item 的 id 会被保留，因此渲染出来的那一行是就地更新，而不是重新挂载、重放入场动画——后者看起来像是又出了一次新故障。该行中属于单次尝试的状态会随之重置，因此「立即重试」与「放弃」在这一轮的每次倒计时上都可用。
- 早于「尝试序号」字段的 Trace 全程读作第 1 次，因此永远不会发生合并，回放效果与以往完全一致。

## 这次合并的代价

被覆盖的那次尝试的**原因**也随之离开对话：一轮中各次失败原因不同时（先超时、后网络错误），只会显示当前所处的那个原因。次数得以保留，逐次的原因仍在 Trace 中。
