# 每个会话保留自己的权限，输入区一眼看出权限等级

- **Date:** 2026-09-16
- **Type:** feat
- **Scope:** core, server, web

[English](2026-09-16-session-permissions.md)

沙盒策略现在归属于会话。会话在创建时取服务端的沙盒设置并一直保留，因此修改这些设置不再影响已经在运行的 Agent。输入区的审批控件改为权限按钮，一眼即可看出权限等级。

- **权限按钮**只有一个盾牌图标，按等级着色。红色为完全访问：文件系统完全开放、网络放行、所有调用自动批准。琥珀色为部分权限：存在写权限，但仍有某项在约束。绿色为只读：命令无法写入。灰色为关闭：所有工具调用都被拒绝。卡片足够宽时盾牌旁显示等级名，tooltip 列出三项取值。
- **菜单分三节。** 文件系统可选只读、仅工作区可写、完全访问。网络可选放行或断开。「更多…」在同一面板内展开四种审批模式。草稿页使用同一按钮，初值取服务端沙盒设置；子智能体面板修改的是根会话的取值。
- **设置变为缺省值。** 设置页的沙盒卡片已如此说明。修改某个会话的策略，从该会话的下一条命令起生效。子智能体沿用根会话的策略；分叉、切换模型与交接给其他 Agent 时都会带上原策略。
- **管理员的沙盒对其他人仍是上限。** 非管理员可以收紧会话策略，但不能选择比服务端设置更宽的文件系统模式或网络；API 返回 `403 sandbox_forbidden`。
- **API。** `SessionInfo.sandbox` 返回 `{ mode, network }`。创建会话与 `PATCH /api/sessions/:id` 接受 `sandbox`。`GET /api/projects/:p/chat-defaults` 同时返回新会话的初始策略。插件侧，`CreateAgentOptions.confineSpawn` 与 `controlEnv` 一样按会话坐标求值，沙盒服务新增 `confinerFor`。
- **已知缺口：** 文件系统与网络只约束命令执行，文件写入工具仍与此前一样只由审批模式把关。

存量会话的处理见[向后兼容](2026-09-16-backward-compatibility.zh.md)。
