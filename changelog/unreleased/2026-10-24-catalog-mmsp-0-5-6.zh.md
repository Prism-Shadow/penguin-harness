# MMSP 0.5.6：Moonshot 与 OpenRouter 新增 Kimi K3.1 Pro

- **Date:** 2026-10-24
- **Type:** feature
- **Scope:** `model-catalog`, `core`, `skills`, `docs`
- **PR:** [#1315](https://github.com/Prism-Shadow/penguin-harness/pull/1315)

[English](2026-10-24-catalog-mmsp-0-5-6.md)

PenguinHarness 升级到 MMSP 0.5.6，内置模型目录同步了 MMSP 0.5.6 注册表为 PenguinHarness 已有分组新增的 Kimi K3.1 Pro 条目。新建 Project 会把它们作为预置写入；已有 Project 通过「添加新模型」获得。

## 变更内容

- **MMSP：** core、服务端与 CLI 的 `@prismshadow/mmsp` 依赖由 `^0.5.5` 升至 `^0.5.6`。
- **Moonshot：** 新增 `kimi-k3.1-pro`，输入 CNY 13 / 输出 68 / 缓存命中 1.3；新增 `kimi-k3.1-pro-highspeed`（Kimi K3.1 Pro Highspeed），CNY 26 / 136 / 1.3。两者都是 1,048,576 Token，支持图片输入，按 id 路由到 Moonshot 官方客户端（`moonshot-official`）。
- **OpenRouter：** 新增 `moonshotai/kimi-k3.1-pro`，$2 / $10 / $0.20，1,048,576 Token，支持图片输入。
- **思考等级 `none`：** 在 MMSP 0.5.6 中，Moonshot 官方客户端对 Kimi K3、K3.1 Pro 与 K3.1 Pro Highspeed 发送 `reasoning_effort: "none"`，即关闭推理；MMSP 0.5.5 发送的是 `"low"`。Anthropic 官方客户端在 Claude Sonnet 4.6、Opus 4.8、Sonnet 5 与 Opus 5 上据此关闭思考，在 Claude Fable 5 上按最低强度运行。会话标题生成、`read_file` 的代理视觉读取以及服务端的一次性补全（如 id 建议）都请求 `none`，因此在这些模型上不再推理。
- **`unified-llm-api` Skill**（`agent-development`，版本 2026.10.24.1）：模型表列出 K3.1 Pro 的 id；配置说明写明 `NONE` 在 Kimi K3 系列上关闭推理，且 `moonshot-official` 在该系列上接受 `prompt_caching` 的 `ENHANCE`。
- **文档：** `models` 页的预置列表列出 K3.1 Pro 的条目。
