# Command confinement, with backends as extensions

- **Date:** 2026-08-22
- **Type:** feature
- **Scope:** `core`, `server`, `extensions`, `docs`
- **PR:** [#354](https://github.com/Prism-Shadow/penguin-harness/pull/354)
- **Breaking:** yes — the extension contract is closed; `context.terminals` now needs a cast

[中文版](2026-08-22-sandbox.zh.md)

Shell commands an agent runs can now be confined. The harness gained its own sandbox interface — argv rewriting, honest enforcement reporting, fail-closed — naming three dimensions: `fs-write`, `network` and `mask-paths`. No backend is part of the harness: each is an extension package a deployment installs and names in `extensions.json`, which is why this builds on the [extension mechanism](2026-08-22-extension-mechanism.md). A default deployment names none and confines nothing.

## Details

- **The seam is in core.** `confineSpawn` is threaded along the existing `proxyEnv` line and applied in `ManagedSession` immediately before spawn: it receives the exact argv, `cwd` and `workspaceDir`, and returns the argv to spawn instead. Mechanism only — it never interprets the argv.
- **Routing cannot silently drop a dimension.** A backend declares which dimensions it implements (declaring none means filesystem-only) and the service routes each policy to one that covers what it requires. A requirement nothing covers fails closed, naming what each mounted backend does cover. `confine` must return enforcing argv or throw; a throw aborts the spawn and surfaces as the command's spawn error, so a command never runs unconfined because a backend failed.
- **Four backends ship as packages:** `extension-sandbox-dsh` (the portable DSH adaptor, file effects on all three platforms), plus `extension-sandbox-bwrap` (Linux), `-seatbelt` (macOS) and `-mxc` (Windows, through Microsoft MXC's `processcontainer`) — the three native ones implementing all three dimensions. With no backend inside the platform bundle, the bundle no longer inlines any native-adjacent module, and `deploy.mjs`'s runtime-resolved-natives shim is gone. Confinement settings ride the parked platform context, so a hot push cannot silently un-confine a deployment.
- **The extension contract is closed, and owns the sandbox vocabulary.** `PenguinContext` and `PenguinInterface` name every member instead of being reopened by `declare module`: an extension checking against the contract used to compile against members only one embedder supplies. `SandboxPolicy`, `SandboxProvider`, `ConfinedArgv` and the mode/dimension unions live in `@prismshadow/penguin-core/extension` now, since a backend is written against those names and nothing else — while the helpers that read them stay in the server package, which keeps both extension subpaths emitting types and nothing else. A backend therefore names core alone: all four dropped `@prismshadow/penguin-server` from their dependencies and can no longer resolve it, and the server's extension subpath narrowed to the one member it owns, `HarnessContext`.

## Compatibility

`terminals` is a harness class and cannot be in the contract. It is named on `HarnessContext`, which extends it, so the emitted value still satisfies the contract and the seam is unchanged — but an extension reading `context.terminals` now writes `ctx as HarnessContext`, stating where it is used that it depends on this embedder. Nothing about the wire or on-disk formats changes.
