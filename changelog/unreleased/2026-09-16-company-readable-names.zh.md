# 公司模式在原先显示 id 和路径的地方显示名称和文件夹

- **Date:** 2026-09-16
- **Type:** feature
- **Scope:** `web`
- **PR:** [#753](https://github.com/Prism-Shadow/penguin-harness/pull/753)

[English](2026-09-16-company-readable-names.md)

公司模式有三处不再让人读机器写法：在频道输入框里 `@` 选中的 Agent 写入名称而不是 id，工单里的数据路径渲染为文件夹胶囊，
组织状态以文字胶囊的形式放在组织名称旁边。

## 频道输入框里的提及

- 从 `@` 菜单选中后，输入框写入的是显示名称（`@Ada Lovelace`），并按已发送消息里提及标签的样子着色；此前写入的是 id。
  发出的消息仍然携带 id（`@ceo`、`@user:alice`、`@all`），因此服务端、投递与 `mention_not_member` 均未改变。
- 选中的提及成为一个整体：在其后按退格或在其前按 Delete 一次删去整个名称，触及它的按词删除、剪切或输入覆盖选区同样整段删去；
  光标跨过名称移动，落在名称内部的点击或选区端点移到其边缘。上述退格或 Delete 之后按 Ctrl+Z 可整段恢复该提及；
  输入法组字触及名称时，在组字结束时整段删去。
- 复制、剪切或拖动含有已选提及的文字时，提及随之带走：粘贴或拖放进频道输入框后逐个恢复为提及，其他应用拿到的则是纯文本名称。
  只有名称仍是该频道为其 id 显示的名称时才恢复为提及，因此来自别处的 `@名称` 文字仍是纯文本。
- 与前后文字紧贴的提及（`x@Ada`、`@Ada.md`）发送时以空格隔开其 token，照常投递；紧跟其后手动输入的 `@id`
  （`@张三@ceo`）同样投递。同名员工不会混淆，手动输入或粘贴的 `@id` 照旧可用。
- 菜单也能匹配以任意文字输入的名称（`@张`）；在 `@` 之后用输入法组字时按 Enter 不再选中候选。

## 工单里的路径

- 工单弹窗中的目标、验收标准、进展、结果与阻塞原因把数据路径画成胶囊：文件夹或文件图标加最后一段名称，悬停显示完整路径，
  点击按原样复制路径，图标随之变成对勾。存储的文本未改变。
- 路径指 `<app_data_dir>/…`，或经过该 Project 的 `organizations/`、`agents/` 目录的绝对路径，分隔符可以是 `/`、`\`
  或二者混用，因此 Windows 服务端写出的路径（`C:\Users\…\.penguin\data\…`）同样计入。正文里的路径只由 ASCII
  文件名字符组成，遇到空格、中日韩文字或标点即结束，句末的句点不计入路径。延续到非 ASCII 段的路径（`…/workspace/调研报告.md`）、
  从非 ASCII 段延续而来的路径（`C:\Users\张三\…`）与本服务自己的路由（`/api/projects/…/organizations/…`）保持为文本。
  只含一条路径的行内代码按原样变为胶囊；代码块、行内代码里的命令与链接文字保持原样。以分隔符结尾、或最后一段没有扩展名的读作文件夹；
  最后一段带扩展名的读作文件。
- Markdown 字段里以反斜杠书写的路径按源文本原样复制，尽管 Markdown 会把标点前的反斜杠读作转义并从文本里去掉。

## 组织状态

- 组织切换器的触发按钮把状态显示为名称右侧的文字胶囊——运行中 / 已暂停 / 配置无效（英文为 Running / Paused /
  Invalid configuration）——取代名称前的圆点。空间不够时先截断名称，状态也并入了触发按钮的无障碍名称。
- 未暂停组织的英文标签在所有出现处由 "Active" 改为 "Running"。
