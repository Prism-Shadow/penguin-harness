# 插件安装显示字节进度、停在停滞，未经同意不下载

- **Date:** 2026-11-26
- **Type:** fix
- **Scope:** `server`

[English](2026-11-26-plugin-install-progress-and-consent.md)

装一个插件过去由时钟封顶、看不见自己的进度，还会在没人要求的地方悄悄开始下载。几十兆的发行资产在慢链路上跑不完安装的固定窗口，下到一半被杀掉；安装流说不出下载到了哪里，因为下载由 npm 做、字节它自己拿着；而创建 Agent 会默认装上插件库的默认插件——这是一次下载——除非调用方恰好知道要显式拒绝。

## Details

- 发行通道的资产（发布在 github release 通道上的插件版本）现在由服务器自己下载，流式写盘并逐字节计数：安装流本来就有的字节进度（带 received 和 total 的 `download` 事件）第一次报出真实数字。下载的文件先对上索引条目钉住的 sha512 才交给 npm，npm 随后安装 `<prefix>/archives/` 里的本地 tarball，和上传 zip 的做法一样。
- 下载没有任何时限——慢链路是慢，不是死。只有不动了才被切断：超过 30 秒没有字节，这个地址被切断、试下一个（镜像），和以前的遍历顺序相同。被拒的地址什么也不留下；下到一半的文件到不了 archives。
- 同样的「按移动计」规则替换了无 npm 下载的固定窗口——桌面应用的 server 身边没有 npm，过去在 120 秒的绝对窗口里取 registry tarball 和发行资产。registry 文档（小的索引查询）保留绝对窗口：那里死地址应该花掉一个窗口，而不是挂死。
- registry 安装时 npm 运行的绝对窗口封的是 npm 在干活，不是下载，现在放宽到 10 分钟：npm 用自己的单请求超时和重试取 tarball；这个窗口抓的是卡死的 npm，不是慢链路。
- Agent 的创建不再下载插件库的默认插件，除非调用方明确要求（`defaultPlugins: true`）。Web 对话框本来就发送它展示过的完整清单，那边没有变化；CLI 用 `--default-plugins` 选择加入，过去是 `--no-default-plugins` 选择退出。公司的 Agent 仍然拿到组织雇佣它时指名的插件——那是显式指定，不是默认。
- 组织的周期巡检不再自作主张更新员工的插件。它逐个对比员工装着的公司插件与插件库的版本，记录有更新的那些（Plugins 页会显示）；装不装由人来定。
