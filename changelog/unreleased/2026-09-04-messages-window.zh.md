# 对话记录按有界的消息窗口串加载

- **Date:** 2026-09-04
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#619](https://github.com/Prism-Shadow/penguin-harness/pull/619)

[English](2026-09-04-messages-window.md)

对话页不再把从实时尾部到读者滚动所及的全部历史都留在内存里。历史按窗口取回，窗口以 message 数计大小、以 Task 为切分单位——服务端 `GET /messages` 新增 `messages=<n>`，取至少含 n 条 message 的最短完整 Task 串，因此工具调用与其输出、compaction 区间、steering 组永不分家——已加载的始终是一段连续的窗口串。打开对话取一窗、后台再补一窗；滚动接近顶部即取更早的一窗，正在读的那条消息原地不动。超出预算后从远端整窗驱逐：向上翻阅先与实时尾窗脱钩，向下回来用新的 `after=<游标>` 形式补回——永不越过尾窗起点——补到那里便重新挂回。渲染的就是已加载的这一段，手机上的 DOM 与内存同时有界；尾窗不在屏幕上时，「回到最新消息」按钮直接把它带回。

resync 改按尾窗起点游标重取而非按大小，会话在此期间长大也不再退回全量读取。
