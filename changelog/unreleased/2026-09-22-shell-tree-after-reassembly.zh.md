# 插件变更后，运行时不再停留在已释放的 App 上

- **Date:** 2026-09-22
- **Type:** fix
- **Scope:** `server`
- **PR:** [#0000](https://github.com/Prism-Shadow/penguin-harness/pull/0000)

[English](2026-09-22-shell-tree-after-reassembly.md)

运行时自己要用 App 的模块树：WebSocket 握手的鉴权、热更新的门禁、启动时读的设置、进程级错误的记录。这棵树原先是一份快照，只在推送落地时重新指向。安装或移除插件会在同一个平台实例内部重组 App——没有推送，快照便停留在刚被释放的那个 App 上。下一次 WebSocket 握手向已释放的树索取鉴权服务（`no api 'Auth' on module 'IdentityModule'`），拒绝处理器再向它索取错误记录器，在处理器内部再次抛出，进程随即退出。

- `ServerBoot` 改为持有平台实例，每次使用时从实例上读取 `tree`；replace 钩子改为重新指向实例。重组一完成即被跟上，推送照旧。
- 进程级处理器在守护内记录错误：树答不上来时只多一行控制台输出，绝不变成第二次失败。
- `TestApp` 暴露 `boot`；新增测试经路由安装插件，断言运行时的树是重组后 App 的，而第一代的树已释放。

这是热更新接缝之下的运行时代码：安装实例要靠重装运行时获得，推送送不到。在那之前，插件变更后推送一次即可重新指向树。
