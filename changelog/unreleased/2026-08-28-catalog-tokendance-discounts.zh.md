# TokenDance 排在模型页首位，促销条目显示实际价格

- **Date:** 2026-08-28
- **Type:** feature
- **Scope:** `model-catalog`, `core`, `server`, `web`, `cli`, `docs`
- **PR:** [#531](https://github.com/Prism-Shadow/penguin-harness/pull/531)

[English](2026-08-28-catalog-tokendance-discounts.md)

腾讯 Hy4 preview 经两个卖家一并收录进目录；六个 TokenDance 条目声明了折扣，模型页据此展示、
成本中心据此计价；TokenDance 成为官方推荐分组并默认排在首位；模型卡片按三行重建，并会说出每个模型
花掉了多少 Token；中文界面重命名了三个价格档位。

## 模型目录

- OpenRouter 分组新增 `tencent/hy4-preview`：1,048,576 Token 上下文，纯文本，每百万 Token
  $0.834 输入 / $2.501 输出 / $0.042 缓存命中。
- TokenDance 分组新增 `hy4-preview`：同一个上游模型经第二个卖家提供，按该网关自己的 CNY
  6 / 18 / 0.3（输入 / 输出 / 缓存命中）计价，上下文 1,024,000 Token。每条记录各自卖家的
  收费，因此这一对与两条 `qwen3.8-flash` 一样必须保持分开。
- 目录条目新增 `discount` 字段：卖家在牌价基础上正在执行的折扣率。无论促销是否进行，
  `pricing` 始终是牌价，由新增的 `effectivePricing()` 应用折扣。六个 TokenDance 条目声明了
  折扣——`deepseek-v4-flash-0731`、`deepseek-v4-pro-0813` 与 `glm-5.3-flash` 五折，
  `kimi-k3` 八折，`glm-5.3` 与 `qwen3.8-max` 九折。
- 修正 TokenDance 分组中 `deepseek-v4-flash-0731` 与 `deepseek-v4-pro-0813` 的牌价——此前把
  促销价当作了牌价：两者各翻一倍，改为 CNY 0.1 / 3 / 9 与 CNY 0.3 / 9 / 27
  （缓存命中 / 输入 / 输出），使五折后正好等于 TokenDance 的实际收费。
- `presetModelEntries()` 现在向 Project 写入折后价而非牌价，促销条目因此按实际计费价核算成本。
- **DeepSeek 直连条目改为跟随其峰谷计价。** 此前它们记录空闲档，并把高峰用量按同一价格计算，令高峰
  成本少算一半。现在记录**高峰价**——两条 V4 Flash 为 CNY 0.1 / 3 / 9，V4 Pro 为 CNY 0.3 / 9 / 27
  ——并声明 `offPeakDiscount`：在北京时间周一至周五 9:00–12:00、14:00–18:00 之外，各档价格减半。
  模型页在空闲时段标记 `-50%` 并显示减半后的数字；高峰时段显示存盘价、不带任何标记；成本中心按当下
  生效的那一档计价。
- 目录条目在 `discount` 之外新增 `offPeakDiscount`，两者的区别在于折扣**在哪一步生效**。固定促销是
  一个持续到结束的价格，因此「同步预置」会把它写进 Project。而按时段的折扣一天变两次，因此**什么都不
  预先写死**：落盘的是高峰价，减免在读取价格时应用。`.project_config.toml` 里一个「一小时后含义就变了」
  的数字是无法阅读的，而且会让重新同步按时钟改写价格。`effectivePricing` 与 `offPeakAt` 都接收判定
  时刻，因此答案取决于厂商的时钟，而不是宿主机的时区。

## 模型页

- TokenDance 被标记为官方推荐分组：默认排在分组顺序首位，在自己的折叠栏上佩戴一枚绿色的「官方推荐」
  胶囊，并且是首次访问时默认展开的分组。该胶囊直接写成绿色，而不是取用 `Badge` 的 `brand` 语义色
  ——后者刻意是灰的（状态词汇之外的中性强调），而「推荐」既不是状态、也不中性。英文标签只用一个
  词：这是唯一带五个操作的分组，其所在行是整页最拥挤的一行，而旁边的厂商名才是读者最先需要的。
- **模型卡片改为固定三行。** 第一行是名称（字号小一号），右端是该模型的累计花费；第二行是全部常驻
  标记独占一行——默认、视觉、视觉代理、快速、免费、折扣，顺序固定，好让视线学会去哪里找；第三行是
  价格行。这些标记此前挤在标题那一行，每一枚都是模型**名字**让出来的宽度。标记行即使为空也会渲染，
  高度就是标记自身的高度：多数模型一枚标记也没有，而两列网格中同一行的卡片会被撑到最高者，因此一个
  会塌陷的行表现出来是参差的留白，而不是一张更矮的卡片。
- **上游 id 从卡片上撤下。** 它是需要时才去查的细节，而不是用来扫读的信息，而且在配置对话框里只有
  一次点击之遥；它此前占用的宽度现在归还给名称与花费数字。
- **每张卡片会说出该模型消耗了多少 Token**——形如 `17.7B toks`，灰色，字号比价格行再小一档，落在
  标题行的右端。这是一个不限时间、不限 Agent 的累计值，因此它来自专用的 `GET /usage/model-totals`
  而非成本中心那份带筛选的聚合，并且是独立的一次请求而不是塞进模型列表：统计取不到时代价是这个数字
  消失，而不是整页失败。从未跑过的模型显示空白而不是 0——0 读起来像是一次测量结果，而不是「没有」。
  为此 `humanizeTokens` 增加了十亿档，Web 端与共用同一套约定的 CLI 一并调整；单位沿用页面上已有的
  缩写方式——`tok/s`、`/M tok`。
- **页面上的标记是一枚枚无填充的小圆角胶囊**：只有一道细描边，完全不铺底色，色相只留在文字上。六枚
  标记配六块彩色底会把这一行变成花花绿绿的碎纸；在一个以扫读名称为本职的页面上，这些标记本就该是第二
  眼才看到的东西。三种墨色把它们归类而不是逐个点名：模型**是什么**、**能做什么**、**多少钱**。它们写
  在模型页而不是 `lib/tone.ts`：它们是身份而不是判断——「默认」「视觉」「免费」说的是模型**是什么**，
  彼此之间没有高下；而且每一枚的身份都由文字承担，墨色只负责让视线一眼分堆。分组标题上的「官方推荐」
  胶囊同理，也不再铺底色。
- **模型配置对话框的头部改为三行**：名称、上游 id，然后是标记。此前标记与名称挤在同一行，长名称会折行
  钻到它们下面，把头部撑得参差不齐。这些标记与卡片上的是同一种胶囊，使列表与对话框对「标记长什么样」
  保持一致。
- 折扣中的模型卡片只显示**实际计费价**。这一行在没有促销时会是多少钱，并不回答浏览这份列表的人
  正在问的任何问题，而为它花掉价格行的宽度，会把真正该显示的数字挤出去；折扣率改为标记行里的一枚
  标签。价格已被改成与目录不同的条目两者都不显示。
- **窄屏下的分组标题不会再压到自己的按钮上。** 厂商名是这一行里唯一占用剩余空间、也是唯一会截断的元素；
  给它设最小宽度正是重叠的成因——它旁边那些标记从不收缩，一旦它们的宽度加上这个下限超过按钮，整组内容
  就溢出盒子、钻到操作按钮底下。现在下限去掉了，改为在窄行时让模型数量与推荐标记先行退场——这正是那些
  操作按钮的文字标签早就遵循的规则。已在 1500px 至 400px 的九个宽度上验证无溢出。

- **按时段的价格会在整点重新读取。** 目录能表达的窗口边界都对齐整点，因此页面把定时器瞄准下一个整点
  而不是轮询：否则 08:59 打开的页面到 09:05 还在承诺半价。

## 卡片改造中发现的三个问题

- **模型的显示名称又可以清空了。** 必填的只有 provider 与 model id，输入框也写着「留空则使用 model
  ID」——但对内建目录收录的模型来说，磁盘上没有 `display_name` 的含义是「继承目录里的名字」，因此清空
  等于什么都没写，刚删掉的名字下次加载又回来了。现在用空字符串记录这次删除，读取时把它与「字段缺失」
  区分开。目录里没有的模型仍然什么都不写——那里「缺失」本身已经表示「没有名字」。
- **保存确认会说出它在问哪个模型。** 名称清空后它读作 `确定保存对「」的配置修改？`：回退到 id 的判断
  只认 `undefined`，而清空输入框留下的是 `""`。对话框标题栏也有同样的缺口——标题印成空白，下面又把
  id 重复了一遍。
- **重新保存不再改动模型的价格。** 表单会把存储的美元价四舍五入到四位小数以便输入，而提交时又把这个
  舍入后的值当作新价格写回——于是打开一个促销条目、什么都不动直接确认，它就偏离了卖家实际计费的数字，
  标示这一点的折扣标记也随之消失。现在仍然保持着加载值的价格档位会被原样写回；只有真正编辑过该输入框，
  键入的值才具有权威性。

## 磁盘上的配置

清空显示名称会往 `.project_config.toml` 写入 `display_name = ""`，这是此前没有任何代码会写的值。不需要
迁移，存量 Project 也不需要做任何事：没有该字段的配置行为与从前完全一致。旧版本读到新配置时会把空字符串
当作缺失、重新显示目录里的名字——被清空的名字会重新出现，除此之外没有别的变化。

## 中文价格标签

中文界面中三个价格档位显示为 `缓存命中` / `缓存未命中` / `输出`——包括模型页的价格字段、
成本中心的 Token 档位与图例，以及 CLI `penguin config model add` 的价格选项。英文标签不变，
字段名、类型名与协议键名同样不变。

## 存量 Project

预置模型在 Project 创建时复制进 `.project_config.toml`，此后不会被改写，因此上述价格改动
不会自行到达存量 Project，只能通过模型页的**同步预置**获得：同步会把六个促销中的
TokenDance 条目下调到实际计费价；修正后的 DeepSeek 牌价同样只有在同步后才会到达存量
Project。默认分组顺序与首次访问展开的分组都只是默认值：拖动过分组标题、或展开/折叠过分组的
Project 保持自己的排列不变。
