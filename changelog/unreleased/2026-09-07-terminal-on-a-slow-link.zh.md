# 终端在移动网络下不再假死

- **Date:** 2026-09-07
- **Type:** feature
- **Scope:** `server`, `web`
- **PR:** [#639](https://github.com/Prism-Shadow/penguin-harness/pull/639)

[English](2026-09-07-terminal-on-a-slow-link.md)

在手机网络上打开的终端，过去是悄无声息地死掉的。那种链路上的 socket 不会礼貌地关闭——基站切换、运营商 NAT 回收空闲连接、浏览器冻结后台标签页——页面手里剩下的是一条再也不会传输任何字节的连接，界面上写着「stream closed」。而服务端的 pty 自始至终好好的，唯一的回去方式是刷新页面。

现在两端互相探测：任意一端都可以发 Ping，对端原样回 Pong，于是一条不再传输字节的 socket 会在有界的沉默窗口内被发现，而不是永远发现不了。服务端关闭不再应答的观察者；客户端在对方不再应答时按有界退避重新接入，重连后由服务端的快照重绘整屏——与首次接入拿到的是同一份重绘。网络恢复或标签页回到前台会立即结束等待：连接马上重试，而看起来还开着的 socket 会先被探测再被信任；被浏览器挂起过的标签页不会被误判成死链路。唯一值得停下来的失败是终端真的不在了，重连前会先确认这一点。这一整套状态在界面上叫 `reconnecting`，与首次接入的 `connecting` 区分开。

重连的每一步都自带期限，同一时刻至多一次尝试在途。网络或标签页在一次接入还没结果时回来，加入的就是这次在途的尝试，而不是再起一次：首次接入的宿主策略只跑一遍（跑两遍可能意味着两个终端），任何时刻只有一条 socket，被放弃的尝试迟来的结果什么也不会打开——拨下一条之前，旧的 socket 已经关掉。永远到不了 open 状态的拨号（15 秒）与永远不回话的存在探测（10 秒），读作与被拒相同的暂态失败，交回退避阶梯；面板消失时，连还在途的探测也一并停掉。被沉默判决的资格属于挣得它的那条 socket：探测的应答不跨重连继承，重连落到一台从不应答的旧服务端上，不会被上一条的应答误杀。

三个按局域网调出来的常量不再是常量：

- **输出合并窗口**跟随往返时延。200ms 的链路上，固定 5ms 几乎合并不了任何东西，却每秒产生几百个小帧；现在取实测往返的四分之一，限制在 5–50ms，快链路上行为不变。
- **背压高水位**原本是固定的 1MB，在局域网上是几毫秒的滞后，在慢上行链路上却是好几秒——正是「输出迟迟不来、然后猛地跳过去」的来源。现在它由该观察者 socket 实际投递的速率推出，界定的是**时间**（0.75 秒）而不是字节数。
- **容器尺寸变化**过去每次像素变动都会传到 pty。手机上地址栏收起、软键盘弹出会不断触发，而每一次尺寸落地都意味着一次 SIGWINCH 与运行中程序的整屏重绘。现在它们先静置 120ms，并且只有真正改变了行列数的变化才会发出去。

流本身也在链路上压缩了（permessage-deflate，限定窗口）；小帧不压由发送方逐条决定。ws 只对协商放弃压缩上下文的一侧应用配置级的 `threshold`，而这条流保留自己的上下文——共享上下文正是重复输出压得最好的原因——512 字节的分界因此落在发送调用上、逐帧判定。在这台服务器最可压缩的流量上，这点 CPU 是值得的。
