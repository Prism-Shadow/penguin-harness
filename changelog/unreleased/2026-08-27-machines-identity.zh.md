# 经 ssh 把这个构建装到另一台机器上，并持有一条通往它的连接

- **Date:** 2026-08-27
- **Type:** feature
- **Scope:** `server`, `web`
- **PR:** [#448](https://github.com/Prism-Shadow/penguin-harness/pull/448)

[English](2026-08-27-machines-identity.md)

一台机器就是本 server 自己 `~/.ssh/config` 里的一个主机。Machines 页把它们列出来、把这个构建装到某一台上、并持有一条通往它的连接——此后那台机器的 API 就在本源的 `/server/<machineId>/api/…` 上应答。对机器的一切询问都经由 ssh,任何地方都不新增监听。

## 身份

机器上的 server 首次启动时为自己铸造一个 id——16 个 base64url 字符，跨改名、改别名与重装保持不变。凡是被存下来的东西都指向它，因为别名只是某个配置文件里的一行，人随时可以改写。地址(`ssh:<别名>`)是本 server 触达它的方式，别名是给人读的;同一主机的两个别名共享一个 id。

## 安装，以及让新构建真正服役

安装是在对侧下载 release,而不是从这边传过去;安装脚本本身走 stdin——一次握手而非三次。装成了什么则**从机器读回来**,否则一次跑得干干净净却什么也没改的安装，会被记成"成功装上了机器并不拥有的版本"。

已经装着正确 release、只是推送状态不同的机器，属于热更新而非安装：它走那台机器自己的更新通道，由通道去问机器、并带回它的回答，包括拒绝。交接携带 platform、CLI、web 三个包**以及原生资产**——platform 只从它的资产目录解析 `node-pty`,所以缺了资产的交接会让那台机器上的终端一个也起不来。exec 位随文件一起过去，`spawn-helper` 除按模式外还按名字标记，因为 Windows 根本没有 exec 位可读。

## 每台机器一张嘴

本 server 对机器说的每一句话，都经由那台机器的 `MachineConnection` 离开(`machines/transport/`):小命令走一条持有的 `ssh -T sh` 共享 shell,长步骤与 stdin 载荷各走自己的 ssh,大件流式传输，以及那条把它的 server 变成本地回环源的 `ssh -N -L`。门后的模块是私有的，并有测试钉住——门外无人开 ssh。保证的是**权威**而非 socket 数：底下存在哪些 socket 是这个目录自己的事，将来可以收紧而调用方无感。

## 点名自己测量了哪一层的事实

关于一台机器，可以为真的东西有三样，所以列表会说清它报的是哪一样：

- `forward`——本 server 持有一条通往它的 `ssh -N -L`。这是关于**本侧**一个 ssh 子进程的事实，而它能活过对侧的 server。
- `status`——那边的 server 在最近一次探测时是否在跑，带探测自己的时刻。探测要花一次 ssh 往返，所以列表只报最近一次答案，自己从不探测。
- `api`——本 server 的代理最近一次把请求送过去时，机器的 API 应答了没有。由那些流量打戳，而非另起探测：没有定时器、没有循环，没人问津的机器就干脆不被测量。

把其中一个当成另一个来读，正是"活着的 forward 通往死掉的 server"却显示为健康机器的成因;所以 connect 即使已持有 forward,也要问那边实际在跑什么，没有就启动它。

## 权限边界

自始至终仅限管理员：页面、代理，以及它们背后的每一条路由。全程一个身份——调用者是本 server 的管理员，而本 server 的管理员就是那台机器的管理员，凭一条本 server 通过当初安装程序所用的 ssh 通道铸造的会话。浏览器的 Cookie 从不过去，机器的 Cookie 也从不回来。
