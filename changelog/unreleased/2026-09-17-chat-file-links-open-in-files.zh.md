# 回复中指向 Workspace 文件的链接改在文件面板中打开，桌面端不再因此多开窗口

- **Date:** 2026-09-17
- **Type:** fix
- **Scope:** `web`, `desktop`
- **PR:** [#780](https://github.com/Prism-Shadow/penguin-harness/pull/780)

[English](2026-09-17-chat-file-links-open-in-files.md)

助手回复里指向 Agent 所写文件的链接——如 `[pelican-bike.html](pelican-bike.html)`——点击后会在浏览器
新标签页打开一个并不存在的 Web App 路由，在桌面端则每点一次就多开一个完整的 PenguinHarness 窗口。现在对话中
的链接在渲染前先分类，桌面壳也只为确实需要应用内窗口的地址开窗。

## Web App

- 在对话内——消息流与智能体面板中的子会话对话，含思考过程与压缩摘要——相对链接，或位于该 Session
  Workspace 之内的绝对路径，会像文件卡片的行一样在文件面板中打开该文件：href 先做百分号解码、去掉开头的
  `./`、忽略查询串与片段，越出 Workspace 的 `..` 一律拒绝。文件不存在时照样在该路径上打开面板，由面板
  自己提示文件不存在。
- 在对话内，`#锚点` 链接（脚注引用与回跳）改为在页面内滚动到目标，不再打开新标签页；指向 App 打不开
  之物的链接——Workspace 之外的路径、`file:` URL——点击后不再打开任何东西。
- 外部 `http(s)` 与 `mailto` 链接仍在新标签页打开，对话之外的所有链接（记忆、公司手册、工单）也照旧在
  新标签页打开。

## 桌面端

- 新窗口请求——无论来自主窗口还是它打开的任何窗口——遵循同一条规则：Workspace HTML 预览的「新标签页
  打开」路由、预览主机上的页面与拆出的终端获得应用内窗口；指向其他任何地方的 `http(s)` 与 `mailto` 链接
  交给系统浏览器；应用的其余地址一律拒绝并记日志，而不是再开一份 App。
- 从预览窗口打开的窗口同样受这套规则约束；此前它们不受任何约束。
- 协议不是 `http`、`https` 或 `mailto` 的链接与导航，不再交给操作系统处理。
