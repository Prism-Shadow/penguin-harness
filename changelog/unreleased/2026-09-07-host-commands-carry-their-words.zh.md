# 宿主命令自带文案

- **Date:** 2026-09-07
- **Type:** improvement
- **Scope:** `desktop`, `server`, `web`

[English](2026-09-07-host-commands-carry-their-words.md)

命令面板会向宿主询问「你能做什么」。此前的回答只是一串 id，页面再拿每个 id 去查自己内置的表——于是它能显示的永远只有自己早已带着的那几条。宿主提供别的东西没有任何意义；而页面没听说过的 id 会在构建动作列表时抛错，整个 App 变成空白页。

现在宿主把文案随命令一起发过来：`GET /api/command` 返回 `offers`，每条是一个 id 加两种语言的标签，页面照单渲染。服务端与页面都不再拿 id 去比对自己的清单，两边唯一要问的是「宿主是否提供了它」。

这件事之所以重要，是因为三个程序各走各的发布节奏——桌面 shell 经安装包抵达用户，服务端与页面经热推送抵达——所以「shell 比它所服务的页面新」是常态，不是边角情况。

页面**认识**的命令仍用页面自己的文案：它们翻译得更准、带搜索关键词，而且改动只需一次推送而不是一个安装包。宿主的文案是兜底，不是命令。

两侧的旧版本都照常工作。只发裸 id 的旧 shell 会被读成「没有文案的 offer」，而这类 shell 能提供的命令页面本来就有文案；比 `offers` 更旧的页面读的是收窄后的 `commands` 字段，其中只有它查得到的 id。
