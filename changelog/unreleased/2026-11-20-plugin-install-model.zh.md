# 一个安装操作先把插件装上服务端、再装到 Agent，安装从不卡住

- **Date:** 2026-11-20
- **Type:** feature
- **Scope:** `server`, `web`, `ui`, `ui-gallery`, `docs`, `plugins`, `scripts`
- **PR:** [#1672](https://github.com/Prism-Shadow/penguin-harness/pull/1672)

[English](2026-11-20-plugin-install-model.md)

插件卡片只有一个安装操作，打开两步的安装流程：插件还不在服务端时先安装到服务端，再安装到 Agent。顶部的进度条写明所在的一步（1/2，然后 2/2），服务端这一步逐一写出安装进行到哪里。成员的流程停在服务端这一步，改为向管理员请求。「管理安装」改称「安装到 Agent」。从服务端卸载移到插件详情里，会先从这台服务端的所有 Agent 卸载，确认写明受影响的 Agent 数与名称。失败时在出错的那一步写明原因，并给出下一步。

## 细节

- **安装流程**：卡片的安装操作沿用市场的文字（「安装」「N 个 Agent 已装」「更新」），点开即是安装流程。第 1 步安装到服务端：管理员按下即开始，这一步已写明它做什么，不再另弹确认，装好后流程自动进入下一步；随构建自带的服务端模块在这一步启用。插件已在服务端时直接打开第 2 步，列出各 Agent，首行是「新建空白 Agent」。只带服务端模块的插件只有一步。关掉流程不中止安装，其间卡片的安装操作写明当前这一步。
- **详情里的服务端操作**（管理员）：「从服务端卸载」、随构建自带的服务端模块「停用服务端模块」，以及包的更新。随构建自带的插件不能从服务端卸载，标签的悬停说明写明这一点。
- **从服务端卸载**：`DELETE /api/admin/plugins?package=…`（管理员）先对这台服务端每个 Project 的每个 Agent 卸载该插件（含本地改动与 Workbench 的数据），再把它移出各 Project 的本机表，最后卸载包。`GET /api/admin/plugins/holders?package=…` 列出受影响的 Agent，确认里最多列出五个，其余合计。有 Project 的共享表列出它时拒绝（`409 plugin_shared`），随构建自带的拒绝（`409 plugin_shipped`）。机器选择器选中一台机器时经代理在那台机器上执行。
- **成员与不在服务端的插件**：第 1 步的「请管理员安装」记一条请求（`POST /api/projects/:projectId/plugins/modules` 带 `package` 与当前 Agent），管理员的请求列表在包装上服务端之前不允许「启用」。
- **安装事件流**：发出 `stage` 事件（询问 registry 时的 `checking`、每个尝试的来源，以及重新装配前的 `loading`），也发出此前从未发出的渠道下载进度 `download`；每 20 秒一次的 `ping` 使事件流 40 秒的空闲断开不再切断仍在进行的安装。答复至多等待重新装配 60 秒，启动更久的模块报告为仍在启动（`loading`）。
- **失败说清原因**：按名称安装之前，先由 npm 向 registry 询问该包（`npm view`，用安装同一 registry 与代理），请求以 10 秒为限、不重试，12 秒未结束即终止。registry 上没有的包随即答复 `400 plugin_not_published`（「…尚未发布到 <registry>」），registry 无答复或代理连不上它为 `400 plugin_source_unreachable`，都在数秒内给出、不再运行安装；构建带有离线包时改从离线包安装。本机没有 npm 时由服务端自己询问：读取该包在 registry 上的文档，每个地址 10 秒为限，拒绝时同样写明 registry 主机。registry 答复之后，安装以 `--fetch-timeout=60000 --fetch-retries=1` 运行；安装时查询索引每个地址只试一次、10 秒为限。安装流程服务端这一步的失败说明附「插件源设置」与「从文件导入」。
- **随构建携带的离线包**：仓库中列在内置索引、却不随构建自带的插件由构建打包放在 builtin 前缀旁的 `offline/`，记下 sha512；registry 没有该包、不可达或本机没有 npm 时，市场在校验后从这份离线包安装，本机没有 npm 时不经 npm 直接放入前缀；工作区检出时改为现场打包仓库自己的插件。离线包不预装、不加载。市场条目带 `offline`，卡片因此在安装前就知道这类插件带什么。
- **UI 包**：`ImpactList` 在危险操作的确认里列出它会波及什么，组件画廊的 data 画板展示它。
