# 新增仓库 Skill：文字由网关模型撰写

- **Date:** 2026-10-19
- **Type:** process
- **Scope:** `skills`
- **PR:** [#1216](https://github.com/Prism-Shadow/penguin-harness/pull/1216)

[English](2026-10-19-writing-skill.md)

在 `.agents/skills/` 下新增开发用 Skill `penguin-harness-writing`，记录 penguin.ooo 上的文字怎样产出，博客文章、文档页和 landing 文案都适用。读者能看到的每一个字都由 TokenDance 网关上的模型撰写，每一步单独调用一次 API。Agent 负责调研、整理事实、编写提示词、拼装模型写好的各节、按模型给出的文字画图、检查和发布。密钥从 `TOKENDANCE_API_KEY` 或 `TOKENDANCE_KEY_FILE` 读取，不进入仓库。

## 细节

- 文章按人写文章的方式产出，由 `scripts/prose.mjs` 完成：
  - `outline` 先列提纲，其中的 `# Plan` 表给每一节定下篇幅、可用的事实和配图。
  - `plan` 对照 Profile 的篇幅预算、图表清单和事实文件检查这张表，通过后冻结。
  - `section` 按冻结的提纲一次写一节，依次往下写，并能看到已经写好的各节。
  - `assemble` 把各节逐字节拼成全文，`route` 按审阅意见引用的原文把意见分到对应的节。
  - `translate`、`polish`、`fix`、`review` 都按节进行；`review` 只给出供 `fix` 使用的问题清单，不改写原文。
- 篇幅预算是硬性约束。提纲受 Profile 上限约束。单节篇幅超过计划篇幅的 1.1 倍或 Profile 的上限时，`check` 报错。受篇幅约束的提示词都写明上限和 `check` 的计数规则。单节的提示词按计划篇幅提要求，全文剩余篇幅更少时按剩余篇幅，从不按 1.1 倍的余量。每完成一节，`check` 都会报告全文合计与上限的对比。单节仅存在篇幅过长问题时，交由 `trim` 删减，不重写。
- `fix` 和 `trim` 的输出先经检查再保存。这类输出若出现以下任一情况：引入审阅意见未提及的事实、改动审阅意见未指向的图块、改动事实标记，或删减后仍超出上限，整份输出将被搁置。`fix`、`polish`、`translate` 和 `trim` 的输出若改动了版本说明，同样会被搁置。被搁置的输出不写入下一个版本。
- 文章采用论文式引用，每句最多一处关键引用。事实文件中的每条事实都标注来源。`strip` 把写作时的事实标记转换为带编号的 GFM 脚注，文末附带链接的参考资料列表，编号按首次引用的顺序排列。每句话引用其对应事实里第一个尚未引用过的来源：我们自己的网页和仓库全文只引用一次，其他来源每节引用一次。可选的 `## NOCITE` 一节里列出的事实不产生引用。TL;DR 是正文的概括，不带脚注。脚注放在结束该分句的标点之前（`text[^1].`、`文字[^1]。`）。每 100 个英文词超过 3.5 处引用、或每 100 个汉字超过 1.5 处引用时，`check` 给出警告；一句话里有两处引用也会警告。另一种语言引用来源的顺序相同时，沿用同一套编号。`pair` 检查两种语言引用的来源是否一致。`**Sources**` 页脚不再使用。正文中的 URL 写成 `<https://…>` 格式的自动链接，因为网站会把紧跟在裸 URL 后面的脚注当成链接的一部分。
- `reference/profile-<name>.md` 存放随文字类型而变的部分：结构、读者、篇幅，以及 `check` 据以检查的规则。目前提供观点文章、文档页和 landing 文案三种，各自配有输出约定。
- 文风规则要求模型把读者设想为有阅读障碍或注意力缺陷（ADHD）、读起来吃力的人。写作需做到要点先说，句子短，用常见的词，不插题外话，不预先辩解。规则还点名禁止「是的，但是……」式的让步转折，`review` 会检查这两点。英文句子超过 35 个词、中文句子超过 60 个字时，`check` 给出警告。中文里 Harness 和 Agent Harness 保持英文。`check` 把「夹具」当作错误，把小写的 harness 当作警告。
- 面向相同读者，文章开头提供列出关键结论的 TL;DR。新增的 `emphasize` 步骤将每节的一个关键句标为粗体，不改动其他任何字符。文章中的粗体仅可用于这一关键句，界面标签写在引号内，其他粗体 `check` 一律报错。`emphasize` 的输出如果改动了正文、某节没有标出或标出两处、或是将收尾的 `**` 放在句末标点之后，都会被拒绝，中文里这样收尾的粗体无法显示。`check` 会标出 CommonMark 无法识别为粗体的 `**`。
- 图里的每一个字都来自模型写的 figure 块。绘制的图以内联 SVG 嵌入正文，`check` 会把其中的文字逐条与 figure 块比对。
- 脚本的本地步骤不联网检查文字，覆盖结构、篇幅、配图、事实标记及其来源、脚注和各语言的禁用词表。`selftest` 用内置样例跑一遍这些步骤。
- 开发 Skill 的阅读表和 `reference/authoring.md` 都加了指向新 Skill 的入口。
