# 模型库的 Provider 分组可以拖动排序

- **Date:** 2026-08-25
- **Type:** feature
- **Scope:** `web`
- **PR:** [#467](https://github.com/Prism-Shadow/penguin-harness/pull/467)

[English](2026-08-25-model-group-order.md)

模型库的 Provider 分组可以拖动成自定义顺序，与对话侧边栏的分组一致。顺序按 Project 保存、刷新后仍在，
对话页的模型拾取器也会跟随。

## 细节

- 拖动本身就是意图：没有排序开关，也没有置顶。未存过顺序的 Project 渲染的仍是内置目录原本的顺序。
- 没有存过位置的分组排在页面**顶部**，彼此之间保持目录顺序，因此首次使用的 Provider 不会出现在长页面的
  最底下。
- 一次拖放提交的是**模型库可能展示的全部分组**，包括当前没有模型、因而未渲染的内置分组。某个 Provider
  新增第一个模型时会出现在它的目录位置，而不是作为新成员出现在顶部。
- custom 分组保留自己的规则——没有搜索词时始终显示，以承载「新增模型」入口——位置由顺序决定。
- 分组顺序与分组展开状态是两个独立数组、两个独立存储键（`penguin.modelsGroupOrder.<projectId>` 与
  `penguin.modelsExpandedGroups.<projectId>` 并列），因此拖动分组不会顺带展开或折叠它。
- 分组头即拖动手柄，落点指示线画在整个分组上，因此「下方」表示排在该分组及其模型卡片之后。指示线不占布局
  宽度，分组头在各种宽度下仍保留最多五个动作。
- 搜索期间不允许拖动：搜索把页面过滤成匹配项，对该子集做出的排列并不是模型库的排列。
- 该手势需要能拖动的指针，因此只在存在这种指针的设备上提供——HTML5 拖放在触屏上不触发。已存的顺序在触屏
  设备上照常生效：没有需要降级的模式，手机渲染的就是其主人在桌面端排好的顺序。
- 对话页的模型拾取器本就沿用模型库页的顺序，现在读取同一个存储数组，两者保持一致。
- 拖动载荷使用自己的私有 MIME 类型，与侧边栏的分组拖动区分开：侧边栏与模型库页同屏渲染，共用一个类型会让
  从对话列表拖出的分组在这里画出落点指示线。
- 匹配不到分组的存量键会被忽略，且不做清理；分组以相同的键回来时会回到原位。存储值损坏时降级为目录顺序。
