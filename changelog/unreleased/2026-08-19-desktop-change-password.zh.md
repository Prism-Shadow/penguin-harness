# Web App：桌面窗口不再提供「修改密码」

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `web`, `docs`
- **Issue:** [#346](https://github.com/Prism-Shadow/penguin-harness/issues/346)

[English](2026-08-19-desktop-change-password.md)

侧边栏的用户菜单对每一个会话都提供**修改密码**，桌面应用自己的窗口也在其中——而那恰恰是唯一一个从未见过密码的会话。桌面外壳通过兑换一次性令牌登录，而不是走登录表单；由桌面端创建的数据根目录，其种子密码是完全随机且刻意从不打印的。于是这一项等于是在要求它的持有者去替换一个自己根本说不出来的秘密。现在它在那里被隐藏了，加入了更新行、用户管理入口与退出登录的行列——那几项桌面模式早已去掉。

## 这一项以什么为判据

是否显示由一个小的纯函数（`offersChangePassword`）决定，依据的是 `GET /api/me` 本就返回的那一对字段——`desktopMode`（服务端由桌面外壳拉起）与 `sessionVia`（本会话来自外壳的令牌，而非登录表单）。两者必须同时成立，这与服务端自己对 `PUT /api/me/password` 的判据一致，并且在两个方向上都有意义：

- 只看 `desktopMode`——也就是该菜单里其余几项所用的写法——会连带把这项从「浏览器经环回地址连到同一个桌面模式服务端」的会话上一并拿掉。那个会话是在登录表单里真真切切输过密码的，服务端至今仍允许它修改密码，这样一来它就被困住了。
- 只看 `sessionVia`，则会把这项从「桌面会话的 cookie 被拿到同一个共享数据根目录上的普通 `penguin server` 去重放」的情形中拿掉，而在那里旧密码和别处一样是必填的。

没有引入任何新机制：`desktopMode` 本就是 Web 应用做桌面模式分支的唯一来源，而修改密码对话框本就以 `sessionVia` 为判据。

## 路由本身未被改动

服务端没有删除也没有新增任何拦截。`PUT /api/me/password` 在桌面模式下依旧可达且完全可用，包括它为桌面会话准备的免旧密码路径——被隐藏的是一个仍然有效的控件，而不是一个已经坏掉的控件，因此将来的调用方或自动化脚本不受影响。若一个由桌面端创建的数据根目录之后需要一个人类真正能用的密码，可以离线通过 `penguin server reset-admin-password` 获得，桌面端快速上手文档现在也指向了它。

## 回归防护

一个单元测试在 `desktopMode` × `sessionVia` 的全部四种状态上按值钉住了这条规则——仅在桌面外壳自己的窗口中缺席，在浏览器与多用户场景中均存在——并断言菜单确实使用了该判据，而不是无条件渲染这一项；因为前端测试套件运行在 node 环境下，无法真正渲染菜单本身。
