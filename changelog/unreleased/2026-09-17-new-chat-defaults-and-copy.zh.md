# 新建对话遵循 Project 的默认 Agent，三处文案如实描述行为

- **Date:** 2026-09-17
- **Type:** fix
- **Scope:** `web`, `cli`
- **PR:** [#773](https://github.com/Prism-Shadow/penguin-harness/pull/773)

[English](2026-09-17-new-chat-defaults-and-copy.md)

侧栏的「新建对话」此前总以 `default_agent` 打开草稿，覆盖了 **Project 设置 → 新对话默认值**中选定的
Agent。现在新建对话从 Project 的新对话默认值开始。同时修正了三处描述已不存在行为的文案：登录页的忘记密码
提示、目标模式下「+」菜单对图片的说明，以及草稿页 slash 菜单中的 `/compact`。

## 新建对话

- 每个「新建对话」入口——侧栏常驻按钮、侧栏标题栏的新建按钮与分组头「+」、收起栏、对话页的空状态、
  Agent 卡片上的「新建对话」以及插件的快速开始——在路由状态中只指明与自身相关的字段：Agent 分组的「+」
  或 Agent 卡片指明其 Agent，Workspace 分组的「+」指明其路径。常驻的「新建对话」与收起栏不再指明
  `default_agent`，Workspace 分组的「+」也不再指明当前 Agent。
- 入口与草稿缓存都未指明 Agent 的草稿，依次取 `[default_chat].agent_id`（仍指向本 Project 的 Agent 时）、
  `default_agent`、第一个 Agent（`newChatAgentId`）。Agent 选择器会等 Project 默认值加载完成，不再先显示
  最近使用的 Agent；在草稿打开时保存新的默认值，也按同一顺序重选。
- 这些入口在跳转前还会清理新建对话槽位中、此前一份未输入正文的草稿留下的内容，只保留模型的延续选择与
  已选技能（`prepareNewChatDraft`）。因此放弃的分组「+」草稿不会在下一次「新建对话」时顶替默认值，删光了
  提示词的评估中心草稿也不会让下一个普通对话作为评估运行归入**评估任务**。已输入的正文照旧停放为草稿对话。

## 文案

- 登录页页脚第二行此前称 `penguin server reset-admin-password` 会重置为新的初始密码；现在改为：执行后
  服务再次启动时会打印新的首次登录链接，打开它即可设置新密码。CLI 中该命令自己的 `--help` 说明也有同样的误述，已一并改正。
- 目标模式下，「+」菜单的**上传图片**一项此前称图片在任何模型上都以文件路径发送；现在与非目标模式显示
  相同的说明，因为目标的图片随其第一条消息作为普通图片输入发送，只有不支持视觉的模型才以路径接收。
- 草稿页的 slash 菜单不再列出在该页不起作用的 `/compact`；草稿提供 `/goal` 与已安装的技能。
