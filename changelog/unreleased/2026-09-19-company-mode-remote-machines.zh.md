# 公司模式：组织的公共工作区可以在远程机器上

- **Date:** 2026-09-19
- **Type:** feature
- **Scope:** `server`, `web`
- **PR:** [#796](https://github.com/Prism-Shadow/penguin-harness/pull/796)

[English](2026-09-19-company-mode-remote-machines.md)

组织属于 Project。它的公共工作区现在可以是 Project 已连接的某台机器上的目录，组织随之在那台机器上**运行**——员工的 Agent、工位与工单会话都在那里，日程也由那台机器的服务端驱动——而本服务端保留它的文件镜像，把它与 Project 的其他组织列在一起，并留有一份不依赖那台机器的副本。

## 创建

- 创建弹窗的公共工作区选择器可以选 Project 已连接的机器，与新对话的选择器一致。选中机器上的目录，组织就在那台机器上运行；没有单独的「运行位置」字段。Model 列表随所选机器而定，因为工位使用的是那台机器的 Model 配置。
- `POST /api/projects/:projectId/organizations` 在 `workspace` 之外接受 `workspaceMachine`（已连接机器自己的 id）。请求被转交给那台机器自己的服务端，由它完成创建——CEO 的 Agent、工位与第一轮工作都是它的会话与状态——所以它拒绝的理由（id 已占用、目录不存在、没有该 Model、那里未开启公司模式）原样返回。机器未连接时为 `409 machine_not_connected`。公司模式是每个服务端各自的开关，机器上默认关闭，而那台机器的设置页在这里打不开：创建者是本服务端的管理员时，创建会替他在那台机器上打开开关并重试；其他人则收到那台机器的 `company_mode_off`。
- `org_config.toml` 新增 `workspace_machine`，即组织运行所在机器的 id；缺省表示持有该文件的服务端。存量组织没有这个字段，不受影响。

## 运行与镜像

- 只有组织运行所在的服务端才驱动它。调度器遇到在别处运行的组织时，做的是复制而不是对账：对镜像做对账会发现工位的会话不在本服务端而另开新工位，并让日程再触发一次。
- 镜像是单向的，按内容哈希整文件复制：`GET …/organizations/:orgId/mirror` 列出组织的文件（不含 `workspace/` 与以点开头的条目，单个文件不超过 8 MB），`GET …/mirror/file?path=` 返回其中一个。那台机器上已不存在的文件会从镜像中删除。机器连不上时镜像保持原样。
- 在本服务端写入一个镜像组织会以 `409 org_runs_elsewhere` 拒绝：它会被下一次复制覆盖。

## Web App

- 组织列表只有一份，来自本服务端。在机器上运行的组织带 `machineId`；它自己的请求（`…/organizations/:orgId/…`）以及应答中出现的会话，经现有的 `/server/<machineId>` 路由发往那台机器，名称显示为 `名称 [SSH: alias]`。列表行里的实时信息（谁在运行、花费多少）取自那台机器；问不到时由镜像单独作答。

## 尚未支持

- 一个组织仍只在**一台**机器上运行：员工还不能分布在多台机器上，那需要组织文件的双向同步。
- 远程组织的通知由运行它的那台机器发出、发给那台机器上的用户；只有两边存在相同的用户 id 时，它们才会经那台机器的事件流到达本窗口。
