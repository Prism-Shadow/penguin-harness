# 公司模式：组织可以建在另一台机器上

- **Date:** 2026-09-19
- **Type:** feature
- **Scope:** `web`

[English](2026-09-19-company-mode-remote-machines.md)

组织就是文件与工位——组织图、手册、工单与频道由「公共工作区所在的那台机器」的服务器写入，员工的会话也在那里运行。此前公司模式的每个请求都发往窗口所在的服务器，因此组织只能在本机创建和使用：创建对话框不提供机器选项，也选不了机器上的工作区。现在组织可以建在 Project 已连接的任意一台机器上，之后在同一个窗口里像本机组织一样使用。

## 创建

创建对话框新增 **运行位置**——「本机」，或 Project 已连接的某台机器（显示为 `SSH: <alias>`）；Project 没有可用机器时不出现这一项。表单其余部分随之而变：工作区浏览器列出那台机器的目录，模型选择器列出那台机器的模型（模型配置按服务器各自保存），生成的 id 由那台机器的服务器给出。切换机器会清空模型与工作区，因为它们属于上一台机器。误关对话框时保留的草稿会连同路径一起记住机器。目标机器未开启公司模式时会明确提示；Project 在另一台机器上已有同 id 的组织时，在请求那台机器之前就拒绝。

## 使用

组织列表是本机组织与各已连接机器组织的合并；机器未开启公司模式视为「那里没有」，连不上的机器只会把列表标为不完整，而不会被当成组织已删除。切换器把远程组织显示为 `名称 [SSH: alias]`，与机器上的 Workspace 同一种写法。两台机器持有相同 id 时，列出的是本机的那个。

所有针对某个组织的请求——`/api/projects/<p>/organizations/<orgId>/…` 下的四十来个——都按会话已经在用的同一条路径规则，发往该组织上次被列出时所在的机器，因此各页面都不需要点名机器。组织的应答里出现的会话（工位、工单的工作会话、新组织创建后打开的 CEO 工位）同样记在这台机器名下，打开它们才会到达正确的服务器。招募时列出的是组织所在机器的 Agent（Agent 按服务器各自存在），设置对话框也在那台机器上浏览目录、列出模型。公司事件此前已经随每台已连接机器的事件流到达。
