# 直连 GPT-5.6 条目显示它实际抵达的 Sol 变体

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `model-catalog`, `core`

[English](2026-08-19-gpt-5.6-sol-display-name.md)

内置模型目录中直连 OpenAI 的 `gpt-5.6` 条目不再显示为 **GPT-5.6**，而是 **GPT-5.6 Sol**，让展示名点明这个 id 实际抵达的变体。model id 未作改动。

## 细节

- 裸 `gpt-5.6` id 在上游路由到 `gpt-5.6-sol` 并按该档定价，而 `gpt-5.6-luna`、`gpt-5.6-terra` 以及 OpenRouter 的 `openai/gpt-5.6-sol` 条目本就都显示各自的代号——只有这一条的名字没有说明用户拿到的是哪个变体。
- 改动仅限展示名。该条目发出的仍是 `gpt-5.6`，其价格、上下文窗口、视觉标记与客户端路由一如既往，请求与成本估算都没有移动。
- 目录中那条「同一模型在直连分组与其网关条目之间只保持一个展示名」的测试扩展到了三个 GPT-5.6 条目；此前 sol 这一对的两个名字对不上，它们一直被排除在外。

## 兼容性

预设复制进 Project 的 `.project_config.toml` 时并不带 `display_name`，而该字段的取值是「存储值优先、缺失则回退到目录」，因此既有 Project 立刻就能看到新展示名，无需同步预设。手工改过名字的模型则保留自己的名字，因为存储值仍然优先。由于 id 从未改变，已存储的模型与设为 `gpt-5.6` 的默认模型在两种情况下都照常可用。
