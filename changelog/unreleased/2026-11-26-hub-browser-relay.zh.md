# 远程机器上的对话使用人自己的浏览器

- **Date:** 2026-11-26
- **Type:** feature
- **Scope:** `browser-automation`, `server`, `web`

[English](2026-11-26-hub-browser-relay.md)

运行在远程机器上的对话现在有浏览器了：就是这个人在本服务端用的那个——桌面端的内置浏览器，选了 Chrome 时则是其配对的 Chrome。浏览器面板与本机对话相同，列出此对话的页面，可新建、直接操作与关闭；机器上的 Agent 驱动的也是这些页面，面板同样显示「Agent 正在操作」。

## 工作方式

- 本服务端为其管理员的 Project 所用的每台机器，在机器连着时经已持有的 ssh 连接保持一条通道，把人自己的浏览器经它转给机器；管理员在内置浏览器与 Chrome 之间切换时通道重开，机器上的 Agent 随之换用。
- 这些页面归机器上的那个对话（连同其机器），落在该对话所属 Project 的分区；这类页面弹出的标签页归同一对话。
- 机器上对话的浏览器面板在本服务端为它开页（`POST /api/builtin-browser/tabs` 带 `machineId`），先由那台机器确认这个对话。
- 机器上的 Agent 只能操作自己的页面、只能在使用这台机器的 Project 里开页；读写人的 Cookie 或存储的原始 CDP、指向非网页地址的跳转以及 Cookie 与数据命令一律在本服务端拒绝，网络类事件不转给机器。
- 本服务端的浏览器不可用时，机器上的 Agent 得到与人相同的原因（如 `extension_not_paired`）；本服务端没有连上时，机器上的 `penguin browser status` 请用户在添加这台机器的那台电脑上打开 PenguinHarness 并保持机器连接。
- 版本过旧、没有这条通道的机器在重新连接之前不再询问，那里的对话照旧没有浏览器。
- 先前「机器上的对话用不了浏览器」的过渡提示去掉。
