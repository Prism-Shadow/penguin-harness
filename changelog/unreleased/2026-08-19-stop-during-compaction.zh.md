# 输入区重新可以打断压缩

- **Date:** 2026-08-19
- **Type:** fix
- **Scope:** `web`
- **PR:** [#347](https://github.com/Prism-Shadow/penguin-harness/pull/347)

[English](2026-08-19-stop-during-compaction.md)

压缩进行期间，聊天输入区那颗唯一的操作按钮会显示为「停止」，压缩因此重新可以从 Web App 打断。

## 详情

按钮此前用 `running && midRunAction(...) === "stop"` 判断自己是否该是「停止」，但压缩中的 Session 状态是 `compacting` 而不是 `running`，于是落进了「发送」分支——而 `canSend` 在整个压缩期间都把它禁用，结果就是本该出现唯一可用操作的位置上摆着一颗死按钮。

- 该判断移入 `composer-send.ts` 中与 `midRunAction` 并列的 `isStopAction`：这个模块本就是为了终结同一类错误而拆出来的——凡是发不出任何东西的状态，都必须留下「停止」，而不是一颗禁用的「发送」。压缩中无条件属于这种状态：插话与排队两条通道在压缩期间都不开放，因此无论输入区里有什么，按钮都是「停止」。
- 原本正常的状态一切照旧：空闲的 Session 从不显示「停止」，运行中的 Session 也仍然只在草稿无处可发时显示它。

服务端与核心自始至终都不在问题范围内：abort 路由接受任何非空闲状态下的打断，核心也会依信号中止压缩请求，让成对事件以 `aborted` 收束并保留原上下文——与用户退出程序导致压缩中断时抵达的，是同一个定义明确的终态。两侧现在都有测试钉住。
