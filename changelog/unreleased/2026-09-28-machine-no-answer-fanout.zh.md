# 不答的机器只被问一次，不再每次重载都把每个 Agent 问一遍

- **Date:** 2026-09-28
- **Type:** fix
- **Scope:** `web`
- **PR:** [#863](https://github.com/Prism-Shadow/penguin-harness/pull/863)

[English](2026-09-28-machine-no-answer-fanout.md)

到某台机器的中继断开时，会话列表每次重载仍会就该机器上的每个 Agent 各问一遍。每条查询先等满套接字 20 s 的应答超时，再改用 fetch 向同一台机器重问。22 个 Agent 加上几次重载，这些 fetch 就把浏览器耗尽了（`net::ERR_INSUFFICIENT_RESOURCES`），连头像都加载不出。现在这样的机器不占浏览器连接，同一时刻对它最多只有一个问题在等回答。

## 细节

- 对机器（`/server/<id>/…`）的读若没有应答、而页面的套接字一直有帧往来，就不再改走 HTTP 重问：两种传输进的是 hub 上同一条路由、同一条到那台机器的转发，HTTP 那份也答不了。这时以 `machine_no_answer` 失败。对本服务端的读，以及套接字自己静下来时的读，仍照旧回退到 HTTP。
- 一次重载里一个问题都没答的机器进入休息：列表显示它的缓存行，2 s 后用一个问题探询它。每次探询落空，休息时间翻倍，最多 30 s。它一答，就恢复整轮查询；控制台会写明哪台机器在休息、休息多久。
