# Agents export to a zip and import from one

- **Date:** 2026-11-04
- **Type:** feature
- **Scope:** `server`, `trace-index`, `docs`
- **PR:** [#594](https://github.com/Prism-Shadow/penguin-harness/pull/594)
- **Breaking:** yes — `GET …/agents/:agentId/export`, `POST …/agents/:agentId/import` and the `dataBase64` field of `POST …/agents` were removed

[中文版](2026-11-04-agent-zip-export-import.zh.md)

An Agent now leaves the server as one zip holding the parts the caller picks, and comes back from one as a new Agent or as the replacement of an existing Agent's State. The old `.tar.gz` snapshot export and its import routes were replaced.

## The zip

- One top-level directory named after the Agent, holding `agent_state/` laid out as on disk, `manifest.json` (`format: "penguin-agent-zip/1"`, the last entry), and, when Sessions are selected, `traces/<date>/<sessionId>_NNN.jsonl` with `traces/sessions.json`.
- The config always travels: `system_config.yaml`, `AGENTS.md` and `tools/`. Skills, hooks, memory, workbenches (with or without their `state.json`) and schedules are each selectable; schedules are off by default.
- Literal MCP credentials are blanked and named in `manifest.redacted` by place: credential-named `env` and `headers` values, `oauth` secrets, a URL's password and credential-named query parameters, and credential-named `args` (`--name=value` and the argument after `--name`, as `args:--name`, and the same places in a URL-shaped argument). A name is a credential's when one of its words is one or ends with one (`GITHUB_TOKEN`, `apiKey`, `PGPASSWORD`, `NGROK_AUTHTOKEN`), not when a word only starts with or contains one (`max-tokens`, `keyword`, `keyboard`). A value written as `${KEY}` vault references travels unchanged, as does the rest of the config; a credential reached through a YAML alias is blanked at its anchor too. The vault never travels, only its key names (`manifest.vaultKeys`), and the Agent's secret vault values — under a credential's name or token-shaped, never digits only — are replaced by `[vault:<KEY>]` inside the JSON strings of the Trace files and in the Sessions' titles, counted as `traces:vault-values:<n>` (lines that do not parse as `traces:unscrubbed-lines:<n>`). A workbench's `.build/`, `.harness/`, `.plugin.json` and `node_modules/`, any `.git` path, a vault under any letter case, staging leftovers, expired schedules and links (a part directory that is one included) never travel.
- Sessions are selected as none, the last N most recently active (1–500), or a date range over the Trace date directories. Each travels whole, with its subagent children under the same Agent and the facts the sessions table holds for it. A Session with a file over 256 MiB is left out and reported.

## Routes

- `GET /api/projects/:p/agents/:a/archive?<parts>` streams the zip (`<agentId>-<yyyymmdd>.zip`); `GET …/archive/preview?<parts>` reports what it would hold, its entry count and its notes. Any member may call both. An export past what an import accepts (50,000 entries, 1 GiB uncompressed, a file over 256 MiB) is refused 413, and the preview says why first.
- `POST /api/projects/:p/agents/import?agentId=&overwrite=1` takes the zip, or an old `.tar.gz` package, as a raw `application/octet-stream` body and answers 201 with the Agent's card, what was imported, the Sessions skipped, what to fill and notes (`{code, subject?, message}`). A taken id is 409 `agent_exists` with `details.agentId`; `overwrite=1` is the Project owner's.
- Caps: 100 MiB uploaded, 50,000 entries, 256 MiB per entry and 1 GiB inflated (413 `archive_too_large`): the central directory's declared sizes are held to them before anything is inflated, and no entry inflates past its declared size. Names, links, case-folded duplicates (Trace files included), Skills' `SKILL.md`, hook packages' `hooks.json` and workbench ids are checked before an Agent is touched. A part the manifest marks `false` is not imported, nor are Sessions when it selects none.
- A new id creates the Agent from the template and swaps the archive's State in. A hand-written zip without `system_config.yaml` carries a `definition` (MCP servers, model settings, built-in tool names), applied with the config route's validation to a copy of the Agent's own config, never to the live file.
- An overwrite writes an import backup first, keeps the Agent's identity, Sessions, vault, API keys and employments, keeps its own copy of every part the zip leaves out, of its expired schedules, of its workbenches' data when the zip has none, of its `tools/` for a hand-written zip and of anything else in its State, fills a blanked credential from its own config only for the same server (name and command, or URL origin) and the same place by name, and invalidates the Agent's cached runtimes. An Agent whose own config does not parse can still be overwritten, with nothing filled from it and a note; its export is 422 `invalid_config`.
- Imports of one Agent run one at a time, from recovery to the last Session. The swap is a series of renames in a marked folder under the Agent (`.import-<hex>/`, `.penguin-swap.json` with its phase). A failure before it completes puts everything back; what cannot be put back stays in the marked folder, nothing is deleted, the answer is 500 `import_rollback_failed` naming the folder and the backup, and the next import of that Agent or the next server start moves it back (as it does after a stop mid-swap); a committed swap's leftovers are removed, never installed. Until the swap, a failure leaves the Agent as it was and removes a half-built new one; after it, the import always answers 201 with its report.
- Imported Sessions keep their title, dates, archived or kept mark, approval mode, thinking level and client; each moves in whole or not at all. A row whose fields do not hold up, a first file whose head is not its `session_meta` within 256 KiB, or a Session that cannot be moved in is skipped as `invalid` with a `detail`; a Session id the install already knows, or a file a case-folding disk already holds at its place, is skipped as `exists`, and no existing Trace file is ever replaced.

## Compatibility

- API clients of the removed routes move to `GET …/archive` and `POST …/agents/import?agentId=<id>&overwrite=1`; `POST …/agents` with `dataBase64` moves to `POST …/agents/import`. The version-conflict confirmation is gone: `overwrite=1` is the confirmation. The `penguin` CLI never called the removed routes, and the Web App changes with this release.
- Old `.tar.gz` packages still import; see [backward compatibility](2026-11-04-backward-compatibility.md).
