# 系统设置页

- **Date:** 2026-08-20
- **Type:** feature
- **Scope:** `web`, `docs`

[English](2026-08-20-system-settings-page.md)

把散落在侧边栏用户菜单里的三处设置——代理选项、上传限制与「显示 CLI 会话」开关——合并为一个位于 `/settings/:section` 的系统设置页，左侧子导航按组切换。用户菜单在原位只保留一条「系统设置」入口，此前由它打开的两个对话框组件已删除。

## 子页面

- **个人 → 通用**——按用户存储的「显示 CLI 会话」开关，与在菜单里时一样改动即刻生效并持久化。
- **服务器 → 代理选项**——仅管理员。两个开关与共用地址保持单次 PUT 保存、`invalid_proxy_url` 内联报错与「无改动可保存」提示；保存后改为以响应作为新的基线，因此地址会落到服务端存储的归一化形式，而不是当初键入的形式。
- **服务器 → 上传限制**——仅管理员。保存路径不变，`invalid_attachment_limit` 仍内联报错，保存后同样重新拉取 `/api/me`，让输入框的上限跟上刚调高的值。

## 细节

- 服务器组只对管理员渲染；非管理员直接输入 `/settings/proxy` 会被送回自己的第一个子页面——与输入一个不存在的路径得到的答案完全一致，因此地址栏无从探知有哪些分区存在。只剩一个分组的访问者看不到任何分组标题。
- 该路由注册在既有的 `RequireAuth` 守卫之下；`/settings` 不带路径段时解析为该访问者可打开的第一个子页面。
- 服务端未作改动：搬走的是界面，其背后仅管理员可用的 `GET|PUT /api/admin/settings` 接口原样保留。
- Web App 参考文档新增**系统设置（/settings）**一章，吸收了原先的上传限制一章，并首次记录代理选项子页面。
