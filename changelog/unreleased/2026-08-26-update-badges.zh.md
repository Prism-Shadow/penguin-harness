# 更新提醒红点从最外层菜单一路指向更新入口

- **Date:** 2026-08-26
- **Type:** feature
- **Scope:** `web`
- **PR:** [#472](https://github.com/Prism-Shadow/penguin-harness/pull/472)

[English](2026-08-26-update-badges.md)

有东西可更新时，外层界面会出现手机式的红点，且每个红点都沿一条不断裂的路径指向真正执行更新的控件。两条路径各自触发红点：**软件**更新——浏览器安装看新版本发布，桌面端外壳自己的窗口看已下载的客户端构建——以及当前 Project 中任一 Agent 的**内核**更新。移动端的菜单按钮对两者都显示同一个红点。

## 两条路径

- **软件**——`<md` 顶栏的菜单按钮、收起态侧栏的头像、固定侧栏的头像，终点是用户菜单里的更新入口及其更新对话框。
- **Agent 内核**——同一个菜单按钮、固定侧栏的「智能体」入口、收起态侧栏的智能体图标、Agents 列表中每个内核落后的卡片，然后是该 Agent 的设置页：概览标签页、内核小节，以及紧邻其旁、处于可用状态的「更新内核」按钮。更新本就会刷新配置，红点随之消失。

会话列表的对话分组刻意不加红点：那份列表面向对话而非 Agent 配置，在那里加红点会指向一条无事可做的路径。

## 细节

- `components/ui/update-dot.tsx` 是这个红点颜色唯一被写下的地方，本功能的每个红点都经由它渲染——包括侧栏头像原先自绘的那个主题色标记。通知红点不是状态语义色，因此颜色不放进 `lib/tone.ts`（其五种语义色各自是对事物状态的判断）；组件头部说明了这一点，并记录了红点会落在的四种表面上实测的对比度。红点本身 `aria-hidden`，由其锚点在 `title` 与可访问名称中说明什么可更新。
- 更新检查改为在 App 布局挂载时按浏览器会话执行一次，因此刚打开页面就能看到红点；此前要打开侧栏用户菜单才会触发。模块级缓存保证仍只有一次请求，检查依旧 fail-soft，`PENGUIN_UPDATE_CHECK=off` 时既无红点也无提示。
- 只有当前运行模式确实提供可操作的控件时才出现红点。桌面模式隐藏服务端发布入口、改由外壳更新，因此那里的头像标记的是已下载待安装的客户端构建而非服务端发布；仍在下载中的客户端构建不标记，因为在它落地前用户无事可做。
- 判定逻辑是 `lib/update-badges.ts` 中的纯函数，并附单元测试：发布判定（含关闭检查与查询失败两条路径，以及「可用但未命名版本」的情形）、覆盖外壳全部状态的客户端构建判定、「是否存在内核落后的 Agent」，以及合并措辞。
- `Tabs` 新增可选的单标签页红点，会把说明折入该标签页的 tooltip 与可访问名称，并置于按钮内边距之内，使标签栏的纵向裁剪不会切掉它。
- 新增一条双语文案，用于同时覆盖两条路径的锚点——它不能声称自己是其中某一条。
