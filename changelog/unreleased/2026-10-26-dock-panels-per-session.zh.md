# 停靠面板只属于各自的 Session

- **Date:** 2026-10-26
- **Type:** fix
- **Scope:** `web`
- **PR:** [#1335](https://github.com/Prism-Shadow/penguin-harness/pull/1335)

[English](2026-10-26-dock-panels-per-session.md)

每个停靠面板现在只属于屏幕上的那个 Session。此前在一个 Session 里打开内置浏览器，切到下一个对话时它也会打开，
切到新建对话（`/chat/new`）也一样；另有几条自动路径会拿上一个对话的数据去操作刚切过去的对话。

## 细节

- 浏览器：从停靠栏显示着浏览器的 Session 切走时，离开的面板还会挂载一次渲染，「面板显示时始终保留一个标签页」的规则
  因此为目标对话新开了页面，这个页面又把浏览器面板带进了它的停靠栏。该规则现在只看屏幕上那个对话自己的停靠布局。
- 子智能体面板：它在任务首次派生子智能体时的自动打开，在切换后的一次渲染里读的还是上一个 Session 的消息流，
  因此从一个正在运行、已派生子智能体的 Session 切走时，子智能体面板可能在目标 Session 里打开。消息流现在会写明
  它的数据属于哪个 Session，自动打开要等到新 Session 自己的数据到来。
- 首次发送与自愈的 id：草稿的首次发送或 Session id 的自愈若在用户已切到别的对话之后才完成，交给新 Session 的是
  屏幕上的那份布局，草稿自己的布局反而留给了下一次新建对话。现在只移交草稿（或旧 id）自己的布局，屏幕上的停靠栏不受影响。
- 草稿的首次发送和 Session id 的自愈完成时，若用户已切到别的对话（包括又新建了一个草稿），不再把用户带到新 Session；
  只有仍停留在该草稿或旧 id 上的用户才会被带过去。新 Session 照常出现在侧栏，停靠布局也照常随它移交，
  除非屏幕上同一 Project 的另一张草稿页正用着这份布局。
- 交给面板的请求（点开文件链接、记忆条目、子会话 chip）在切换后的一次渲染里才清除，下一个对话的面板因此可能执行
  上一个对话的请求：记忆面板落到它的条目上，子智能体面板聚焦到它的子会话。现在路由一变就丢弃。
- 需要确认的标签关闭（文件面板有未保存的编辑）若在切换对话之后才得到答复，不再关闭另一个对话里的同类面板；
  命令行终端面板在最后一个终端结束后关闭自己时也按同样的方式核对对话。
- 停靠布局的存储（`penguin.dock.layout`）格式未变，已有的布局照常读取。
