# 服务进程早于 API 套接字的机器，提示需要重启

- **Date:** 2026-10-26
- **Type:** fix
- **Scope:** `server`, `web`, `ui`, `docs`
- **PR:** [#1338](https://github.com/Prism-Shadow/penguin-harness/pull/1338)

[English](2026-10-26-machine-restart-needed.md)

远程机器若没有运行本服务端的版本，它上面的对话能加载历史，却不会实时更新，回复要刷新页面才出现。早于 0.2.17 的服务端应答 HTTP，却不应答 API 套接字的握手，而流从不经 HTTP 转发。现在这类机器在机器管理页和对话的输入框上方都会显示需要重启，直到一次握手完成。

## 细节

- 拨机器的 API 套接字握手超时后，本服务端会经同一端口再问一次 HTTP。机器的服务端有应答时，它的套接字状态记为 `unanswered` 而不是 `failed`，因此被拒的每条流都以 `502 machine_socket_unavailable` 作答，错误信息用日常的话写成，前面不带机器 id：这台机器的版本不一致，请在机器管理页点「重启服务」，还不行就重新安装。本服务端不会自动重启它。
- 这一状态只存内存，再次拨号期间保持不变，一次握手完成后（即机器运行本服务端的版本之后）清除。进入和离开这一状态都会推送 `machines_changed`，打开着的页面无需刷新就能看到。
- 机器管理页把这台机器显示为「需要重启」，即使记录的版本与本服务端相同；悬停胶囊显示「这台机器的版本和当前不一致，对话不会自动刷新。请点「重启服务」；还不行就重新安装。」详情弹窗里「重启服务」成为主按钮（有「更新」时仍以「更新」为主），API 套接字一行显示「连接不上」。
- 这类机器上的对话会在输入框上方显示一条提示：「<机器> 的版本和当前不一致，这里的对话不会自动刷新。请到「机器管理」重启这台机器。」附「去机器管理」按钮。流在后台照常重试，机器运行本服务端的版本后自行打开。

## 机器必须运行本服务端的版本

远程机器必须与本服务端运行同一版本。本服务端在机器的服务端运行时交给它的更新，只替换平台，不动服务进程；本服务端启动时又会把自己的构建交给每台构建不同的机器，所以一台机器可能显示为已是当前版本，实际运行的却不是本服务端的版本。请在机器管理页重启它；仍连不上时，更新或重新安装它，使它运行本服务端的版本。0.2.17 发布说明中「在机器管理页更新每台机器」的建议，覆盖不到已经显示为当前版本的机器。
