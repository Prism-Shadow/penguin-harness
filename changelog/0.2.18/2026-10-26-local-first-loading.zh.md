# 本机页面不再等待机器或公网

- **Date:** 2026-10-26
- **Type:** fix
- **Scope:** `web`, `server`, `desktop`, `ui-gallery`, `docs`
- **PR:** [#1345](https://github.com/Prism-Shadow/penguin-harness/pull/1345)

[English](2026-10-26-local-first-loading.md)

一台已连接的机器不再应答时（ssh 连接背后的网络断了，或它的服务端卡住），本服务端的 Session 列表、`/chat` 打开最近一次对话、评估中心和终端列表都要等到它的每次请求超时才显示，已归档对话的分组在服务端也要等它。插件库页每次读取都让本服务端自带的内置模块等着尚未应答的发布索引。服务端启动时要等两个调度器的首轮扫描，而这一轮可能补发错过的定时任务、访问网络；桌面端还在启动过程中就经网络选择更新源。现在每个页面先只凭本服务端显示本机的内容，之后才去问机器和公网，各部分各自加载。

## 细节

- **Session 列表**：先问本服务端，它一应答，本机的会话就上屏；之后才问各台机器。还在等答复的机器保留它已显示的会话（或缓存里的会话）和它的缓存，等它自己的答复到了再重建列表。`/chat` 打开最近一次对话时不等任何机器。
- **应用外壳的远程读取**等本服务端的 Session 列表上屏之后才开始（没有列表可等时也照常开始）：侧栏背后各台机器的 Agent 列表与事件流、机器上的定时任务标记、版本更新检查，以及固定显示的余额（`lib/local-first.ts`）。
- **评估中心**：列表、Benchmark 详情页及其题目都先显示本服务端的；每台机器在本服务端应答之后才问，应答一到就并入。机器连上或掉线不再让列表退回骨架屏；一个 Benchmark 不在已到的答复里，只有在没有机器还在等答复时才判为不存在。
- **终端列表**：本服务端一应答，它的终端就上屏；之后才问机器的终端列表，超过 API 套接字自身的应答等待即放弃，不再拖住之后每一次共用同一个在途请求的刷新。
- **已归档对话**：`GET /api/me/archived-sessions/groups` 新增参数 `servers=here`（只返回本服务端的分组，不问任何机器）与 `servers=machines`（只返回机器上的分组）。「设置 › 已归档对话」先问本服务端的分组，连同各组的会话一起显示，再问机器上的分组并合入；在此之前，刷新时屏幕上的机器分组保留不动。不带该参数时路由照旧两边一起返回。
- **插件注册表**：`GET /api/plugins/registry` 以及读取同一份列表的 readme 与 archive 路由，不再等待尚无缓存的发布索引：随构建发布的条目立即列出，并注明该来源仍在加载，页面照旧再次读取。
- **启动时的调度器**：服务端公布端口、开始提供页面之前，不再等待定时任务调度器与公司模式调度器的首轮扫描。首轮扫描照常在平台起来时运行，错过的时间点照常处理，失败会记入异常记录；周期扫描在首轮之前就已排好。
- **桌面端更新检查**：桌面端要等主窗口显示之后才选择更新源（OSS 镜像或 GitHub）并开始自动检查，启动过程中一概不做。应用直接启动到托盘、启动十分钟后仍未显示窗口时，到那时照常开始；两者谁先到就由谁开始，只开始一次。菜单里的「Check for Updates…」随时可用。
- 组件画廊的模拟接口对已归档对话的机器一侧返回空；服务端 API 文档说明了 `servers`；设计规格与前端 skill 写入了这条规则。
