## 两个逐面板的宽度偏好被并入一个共享键

Workspace 文件面板与 Agent 面板各自持久化自己被拖出的宽度——localStorage 中的 `penguin.filesPanelWidth` 与 `penguin.subagentsPanelWidth`。它们现在共用 `penguin.panelWidth` 这一个宽度，因此已存的取值必须被承接过来，否则每一个曾经拖过面板的用户在升级后首次加载时都会悄无声息地弹回默认宽度。

**被容忍的旧形态：** 两个旧键中的任意一个。升级后的首次读取会同时查看两者，把其中**更宽的**那个采纳进新键，然后删除两个旧键。取更宽者，是因为这两个面板此前是各自独立调整尺寸的：取碰巧先被读到的那个键，可能会把用户两次选择中较窄的那个交给合并后的面板，而这在原本较宽的那个面板上读起来就是一次倒退。

**生效范围：** 仅浏览器 localStorage——不涉及服务端数据、配置文件或 Trace。两个键都没有（或存储不可用）的用户会得到按比例的默认值，与此前一致。

**用户需要做的：** 无。这次迁移是静默且单向的，不需要重新拖动任何东西。

**移除：** 相关代码是 `packages/web/src/features/chat/use-panel-width.ts` 中的 `LEGACY_WIDTH_KEYS` 与 `storedWidth()`。它是自清理的——读取旧键的同时就删除它们——因此对任何在本次发布之后打开过一次 Web App 的人来说，它已是死代码。**它应当在下下个发布中删除**（即承载本批次的那个版本之后再隔一个版本），由准备那次发布的人执行；代码处的注释也是这么写的。仓库里没有别的东西读这些键，因此移除它是一次纯粹的删除，没有任何可见影响。留得更久只是多一个死分支——没有任何正确性上的理由需要保留它。

## 面板可见性与草稿页的示例布局不构成兼容面

这两者在本批次中都改变了行为，而且都不读取持久化状态：面板的开合是逐会话保存在内存中的（本就从未存储过），而示例文件夹的展开状态是会在挂载时重置的组件状态。升级的用户会立刻看到新行为，没有任何东西需要迁移。

`nav.railAgents` 与 `benchmark.maxScore` 已从两份词条中删除，另有若干 `nav.*` 的措辞发生变化。界面文案是编译进产物包的，既不持久化也不被已存数据引用，因此不存在需要容忍的旧形态。在此记录只是为了说明已做过检查。
