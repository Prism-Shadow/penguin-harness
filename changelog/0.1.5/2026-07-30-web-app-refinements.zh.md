# Web App：每个导航条目一个名字、一行更新入口、一个面板宽度，以及定高的示例架

- **Date:** 2026-07-30
- **Type:** feature
- **Scope:** `web`, `server`
- **PR:** [#119](https://github.com/Prism-Shadow/penguin-harness/pull/119), [#130](https://github.com/Prism-Shadow/penguin-harness/pull/130)

[English](2026-07-30-web-app-refinements.md)

对每次访问都会碰到的那些界面做的一轮梳理。导航条目各自定于一个名字，用户菜单里三行更新入口收拢为一行，两个停靠面板不再表现得像两个不同的面板，Project 显示名变为可编辑，草稿页的示例变成一个定高、可持续扩充的架子。

## 导航条目各有唯一名字

侧边栏、收起态导航栏与页面标题此前各自漂移——导航栏写「智能体」而固定导航写「智能体仓库」，英文里 Costs 与 Trajectory 混用。现在每个条目在每种语言下恰好一个名字，并在所有地方使用：

| | |
| --- | --- |
| 新建对话 / New chat | 智能体 / Agents |
| 技能库 / Skills | 模型库 / Models |
| 成本中心 / Cost Center | 轨迹观测 / Trajectories |
| 评估中心 / Evaluation Center | |

仅用于导航栏的 `nav.railAgents` 字符串已删除，因为两份词条现在对该条目的措辞与固定导航一致。

## 侧边栏的「新建对话」不再与滚动的列表相撞

滚动侧边栏时，导航条目会一路贴到固定的「新建对话」按钮上，两处文字挨在一起。按钮下方的那段间距是滚动容器**内部**的内边距，因此它属于可滚动内容并随之滚走。它现在属于固定区块，从而在任何滚动位置都保持——与两个相邻导航行之间同样的文字到文字的节奏。

## 三行更新入口变成一行

最糟的情况下，用户菜单会把发布说明链接、管理员的「立即更新」行与「检查更新」行三者叠在一起。现在只有一行，具备两种状态：在尚未得知有更新版本之前，它显示「检查更新」并执行手动检查；一旦得知，它就以一个前置的强调色圆点标出该版本，并打开更新对话框。版本号旁的上标角标已移除——标签本身就点明了新版本。

该对话框吸收了原先各行承载的内容：它现在展示发布说明链接，并且只向管理员提供自更新。非管理员看到的是同样的版本与链接，只读，而不是一个端点本来就会拒绝的操作。

## 两个停靠面板表现为一个面板

Workspace 文件面板与 Agent 面板是互斥的——打开一个就关闭另一个——因此在观感上它们本就是一个会切换内容的右侧面板。它们现在也照此行事：

- **一个宽度。** 拖动任一面板会立即改变另一个的尺寸，并作为单一的布局偏好持久化。存放在此前任一逐面板键下的宽度会被采纳一次，取两者中更宽的那个，因此合并后的面板绝不会比原先任一面板都窄。
- **更宽的默认值**，约为窗口的 40% 而不是约三分之一（上限未变，仍是窗口的一半、720px 封顶）。现在一个面板既要放文件树，也要放子 Agent 的对话记录，而对话记录是要求更高的那一位租客——三分之一的窗口会把它渲染成一列窄窄的、不断折行的工具输出。
- **一条可见性规则。** 打开的面板能在切换对话时存活；**新建对话**是唯一会把两者都关闭的时点，因此从草稿创建的 Session 开场时两个面板都是关的。这项改动退役了 Agent 面板此前按 Task 作用域的自动关闭，而那正是两者之间唯一一处刻意的分歧。该面板保留「在当前 Task 首次实时派生子 Agent 时自动打开」的行为；Task 边界现在只是重新武装这次尝试，而不再关闭任何东西。

## Agent 面板会说出子 Agent 被派去做什么

调用图此前只写出每个子节点的 Agent，却从不写出它的任务，因此打开一份子对话记录时，看不到它自身目的的任何交代。图中每个节点现在是两行：Agent 名称连同其已用时间与状态，其下是派生它的那次 `run_subagent` 调用中由模型撰写的 `description`。这句话是自由格式的，而节点框是固定尺寸，因此它被截断为一行，完整文本放在该节点的 tooltip 中。节点高度保持统一——没有描述的节点（根节点、独立的子节点、被省略的那种）会丢掉第二行并把第一行居中，而不是收缩高度，因为收缩会连带牵动行的排布与连线几何。

## Project 显示名可编辑

Project 设置对话框此前把显示名作为静态文本展示，改名意味着重建 Project。所有者现在可以编辑它（`PATCH /api/projects/:projectId`，把 `name` 写入 `project_config.toml` 并保留文件中的其他一切）。id 保持不可变——它命名着目录、Workspace 路径与每一处已存引用——现在以弱化的说明文字置于该字段下方。成员看到的名称为只读。

## 草稿页的示例变成定高的架子

三张示例卡片占据了页面上固定的一块，且没有地方再加第四张。它们现在是两个书签式的文件夹，**搭建网页应用 / Build web apps** 与 **搭建和优化智能体 / Build and optimize agents**，任何时刻恰好有一个处于展开状态：选中一个文件夹会关闭上一个，而展开的那个无法被收起。因此这一块的高度是恒定的——两行文件夹加上一个文件夹的内容行——所以切换文件夹时它下方的东西不会位移，而一个六行的展示区内部也永远不需要滚动条。

每个示例现在是单行标题，它那句描述移入行的 tooltip，图标移到文件夹行上——那才是你真正会扫视以挑选类别的地方。

目录中新增两项：

- **由多个 Agent 搭建的迷你游戏中心**——十个游戏，两两机制不重样，各自是一个单文件的 `games/<slug>/index.html`，由子 Agent 并行搭建，统一挂在一个索引页之后。
- **Claude Code 文档 RAG Agent** 示例现在点明了查询与语料的语言匹配问题。文档是英文而问题常是中文，而对 BM25 这类词法检索器，中文查询必须先桥接到英文——否则一个词都匹配不上，检索会静默退化为空而不是失败。它的自测现在覆盖一个中文问题与一个英文问题。

## 评估中心

Case 行与陈述预览此前都打印「Max 100」。这个量程不该由界面来断言——一个 Benchmark 的总分由它自己的评分 Rubric 定义——因此该标签连同其字符串一并移除。「查看任务」也不再以强调链接色渲染：行本身就是按钮，因此其中一个强调色的标签读起来像是第二个可单独点击的目标。它现在与 Workspace 下载链接一样采用安静的灰色，悬停反馈交由行来承担。
