# Web App 与 CLI：时长与字节的缩写会进位到下一个单位

- **Date:** 2026-07-28
- **Type:** fix
- **Scope:** `web`, `cli`
- **PR:** [#112](https://github.com/Prism-Shadow/penguin-harness/pull/112)

[English](2026-07-28-duration-and-byte-formatting.md)

两个显示助手是依据原始输入来选定单位、或把取值拆成分与秒的，打印出来的却是四舍五入之后的值，于是时长会读作 `1m60s`、文件大小会读作 `1024KB`。现在两者都先四舍五入，再决定打印什么。

## 时长不再打印出 60 秒的余数

`humanizeDuration` 对分钟取下整，却对秒余数四舍五入——同一次拆分上施加了两个相反的取整方向。因此落在 `[59.5, 60)` 的余数会进位成 60，而分钟并未随之进位：119.7s 渲染成 `1m60s` 而不是 `2m0s`，3599.7s 渲染成 `59m60s`。紧凑模式在低一级单位上有同样的错配：它依据未取整的值选择了「不足一分钟」分支，然后把 `Math.round(59.6)` 打印成 `60s` 而不是 `1m0s`。现在每一种整秒形式都先对总量取整、再拆分这个整数，因此分钟与余数总是来自同一个数字；紧凑模式之外、不足一分钟的取值保留其十分位，不受影响。修复落在两份副本上——`packages/web/src/lib/format.ts` 与 CLI 的 `packages/cli/src/render.ts`，二者的缩写是刻意保持一致的——因此 Web App 与 `[stats]` 行不会各自漂移。凡是展示已结算时长的地方都可见：基准测试评估、Case 与 Run 计时、Trace 轮次时长、工具调用卡片、任务统计页脚，以及 Agent 拓扑视图。

## 字节数不再打印出超范围的单位

`formatBytes` 是拿原始字节数与各数量级阈值比较来选单位的，但取值是经共享的一位小数取整渲染的。一个略低于边界的数值在单位已经定死之后被取整越过了边界，于是 1048570 字节打印成 `1024KB` 而不是 `1MB`，MB/GB 边界也是同样的表现。单位现在依据取整后的值来选择。在 Trace 文件大小与工作区文件浏览器中可见。
