# 成本中心：错误表可以往回翻页、读起来更短，并且不再记录普通的命令退出

- **Date:** 2026-07-29
- **Type:** feature
- **Scope:** `server`, `web`, `core`
- **PR:** [#103](https://github.com/Prism-Shadow/penguin-harness/pull/103)

[English](2026-07-29-cost-center-errors.md)

对错误面板的三处改动——它已经变得难以胜任自己存在的目的：找到那个真正要紧的错误。

## 表格可以往回翻页

它只显示最新的 20 行且没有任何继续往下的方式，因此一小时前的错误根本够不着。

一个新端点会以最新在前的顺序返回历史中的任意窗口，并附带过滤后的行数，好让翻页器知道终点在哪。第 0 页不产生额外开销——它就是仪表盘响应本就携带的那一批——因此只有往回翻才会发出请求。

该端点只接受仪表盘的**日期与 Agent 过滤条件**。模型过滤刻意不予接受：它本就从未作用于错误（HTTP 与进程错误没有模型维度），因此在这里遵从它，会暗示一种上方汇总并未做出的收窄。对未归属错误仅管理员可见这一点原样沿用——一个普通成员往回翻页，绝不能开始看到另一个租户的登录失败。

翻页器位于滚动框之外，因此无需滚到行列表底部就能够到，且只在页数多于一页时出现。加载失败的页会显示其错误信息并保留已经在屏幕上的行，而不是把表格清空。

## 更短的来源标签

一行的来源现在读作 `[env] tool_failed:exec_command`，而不是 `environment · tool_failed:exec_command`。只有 `environment` 需要缩短——其余每种来源（`http`、`llm`、`session`、`usage`、`title`、`subagent`、`process`、`schedule`）本就一眼可读——因此这里是一处缩写，而不是一套方案。「最常见错误码」这个统计量使用同样的形态，因此两者彼此一致。

## 命令工具的非零退出码不再算作错误

Core 此前把每一个非零退出码都映射为失败，而每一个失败都会被记录。但非零退出是 shell 命令返回信息的方式，而不是故障：`grep` 在无匹配时退出 1，`test -f` 在文件不存在时如此，`diff` 在文件有差异时如此。记录它们会把错误表变成 Agent 日常工作的流水账，把真正的错误埋掉，并且消耗掉那些本为保护真错误而存在的行数上限与去重窗口。Agent 本就看得到退出码并会自行调整；其中没有任何东西需要人来处理。

两个命令工具都被覆盖，而不只是显眼的那一个：轮询后台命令的那个工具也会走到同一处退出码映射，因此只排除前台路径会导致同一个命令的非零退出「记不记录取决于它碰巧是怎么结束的」。

被丢弃的判据是工具追加的那条注记（`[exit code: N]`），而不是工具的名字——同样的 `failed` 状态还覆盖着 Agent 无论如何调整都绕不过去的故障：被信号杀死的命令（被 OOM 杀掉的构建、段错误的测试二进制）、spawn 失败（工作目录不存在、EMFILE、无法解析的 shell）、工具超时，或缺失的命令会话管理器。这些仍然记录，而它们恰恰就是这张表所服务的「需要人来处理」的情形。

排除发生在错误被捕获之处，而不是被查询之处，因此这些噪音从不进入表格、行数上限或去重键。带翻页的路由的租户隔离现在也有测试覆盖：外部人员得到 404，穿越式 id 得到 404，而一个成员在偏移量之间翻页时，即便同一页中交错着外部记录，也永远到不了另一个租户的行。
