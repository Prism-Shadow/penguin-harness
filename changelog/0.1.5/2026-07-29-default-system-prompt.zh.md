# Core：更紧凑的默认系统提示词、一条回复语言规则，以及共享工具目录

- **Date:** 2026-07-29
- **Type:** refactor
- **Scope:** `core`, `docs`
- **PR:** [#120](https://github.com/Prism-Shadow/penguin-harness/pull/120)

[English](2026-07-29-default-system-prompt.md)

内置的 Agent 模板会被模型在每一轮重新读取，而它恰恰在重复最多的那些小节里变得啰嗦。它减掉约十分之一的词数（1087 → 969）且没有任何规则随之消失，同时把两条提示词从未言明的行为写了进去。

## 精简改变了什么

「个性」一节把回复语言钉在用户自己的语言上——工具 schema 本就对每一条调用描述提出了这个要求，因此二者在实践中一致，只是只有其中一方把它说了出来。它的作用范围限于散文：代码、标识符与提交信息保留各自的惯例。进程/端口约束从两句收缩为一句，保证不变：不要杀死不是你启动的东西（包括 PenguinHarness 自己的服务），除非被要求；不要占用服务端口；想要的端口被占用时另选一个空闲端口。

API 认证处理不再被拆在两个小节里。「约束」一节带着「至多重试一次」，而「停止规则」一节又带着第四条规则说明之后该做什么；现在它只说一次，作为既有的「你无法解决的错误」规则的特例——至多重试一次，然后停止调用工具，并请用户在对话之外去 Agent 的 vault 或模型设置中更新 key。那些让旧措辞变长的事实完好保留：密钥绝不粘贴进对话；新 key 只在下一次对话中生效，因此继续重试不可能成功。

「系统标记」一节词数减半，同时保留全部四个标记及其说明。「文件系统」一节从八条要点减为七条、从 262 词减为 243 词：两处合并——工作区相对路径的约定并入 `CWD` 那条，其他 Agent 的状态并入对你自己状态的描述——换来一条新增的共享工具要点。「建议工作流」本就推荐并行派发独立子任务；现在它明说这就是穿过一个大任务的快路。它那条 Playwright/curl 的说法并入「工具使用」要点，后者保留了原先两行分别承载的两半：装了 Playwright 就优先用它，否则用 `curl`。

## 工具只安装一次

「文件系统」一节新增一条约定，而 Skills 一节去掉了那句解释「不存在某物」的「没有 skill 工具」的填充文字。它落在「文件系统」而非 Skills，是因为它管辖任何要安装工具的任务，而不只是一次 Skill 运行；它也是按模型真正面临的选择来写的：项目本身有环境时就装进项目自己的环境；否则把那些可复用的东西——Python 虚拟环境、模型与包缓存——放在 `<app_data_dir>/agents/<agent_id>/shared_env/<name>/` 之下，并跨 Session 复用。

Node 被单独点名，且在**项目本身之内**优先使用 pnpm——这两半都重要。它的共享存储使重复安装不会在磁盘上产生副本，而位置则决定了安装是否可解析：`node_modules` 是从项目目录向上解析的，因此放在 Agent 目录之下的包，对运行在 `CWD` 中的代码是不可见的。

`shared_env/` 是一条提示词层面的约定，而不是代码会创建的路径：`paths.ts` 未做改动，Agent State 快照仍然只打包 `agent_state/`，因此一个虚拟环境绝不可能撑爆一次导出。Sessions & Traces 文档中的数据布局树列出了该目录并写明了这个注意事项，`01-PRINCIPLES.md` 中的逐 Agent 布局也做了记录。

## App Data Dir 那条要点不再自相矛盾

同一小节的 App Data Dir 要点既说该目录「不是任务的目录」，又说产物绝不可留在那里。而一个临时 Workspace 是 `<app_data_dir>/agents/<agent_id>/workspaces/tmp-<8hex>`——正在那棵树之内，并且对任何被指派了它的任务而言就是 `CWD`——因此这条规则恰恰在最需要它的地方破了。它现在只承载输入规则（App Data Dir 的内容不是用户提供的，绝不是任务输入），并明说 `CWD` 可以位于那棵树之内：那一个文件夹属于任务，其余的不属于。产物该放哪里，其下方的草稿区要点本就正面陈述过，而那条无论 `CWD` 指向何处都成立。

## 已有的 Agent

不迁移任何东西，也不重写任何东西。Agent 始终逐字地以其磁盘上的 `agent_state/system_config.yaml` 运行，因此这项改动只影响**新创建的** Agent。已有 Agent 通过设置页的 *恢复默认配置* 操作来采纳它，而该操作会覆盖整份配置——自定义系统提示词、工具列表、模型与压缩设置、MCP Server——只保留 `name`、`description` 与 `version`。
