# web-design 与 penguin-sdk Skill：编辑风主题、输出契约、思考与图片

- **Date:** 2026-07-30
- **Type:** feature
- **Scope:** `skills`, `web`
- **PR:** [#133](https://github.com/Prism-Shadow/penguin-harness/pull/133)

[English](2026-07-30-skills-web-design-and-penguin-sdk.md)

两个内置 Skill 经过三轮迭代重做（web-design v3 → v6，penguin-sdk v14 → v17），目标是让更短的用户提示词得到更好的结果。

## web-design

- 第二套完整的视觉语言，即可选启用的**纸质编辑风**主题：暖色的纸/墨/细线 Token，一个暖强调色加一个状态绿，系统衬线体的展示级标题配无衬线正文（中日韩衬线回退，仍不使用 CDN 字体），以大写等宽的微标签作为层级工具，更紧的圆角配柔和暖阴影，以及标志性形状（非对称圆角的品牌标记、与之呼应的用户气泡圆角、轨道徽章装饰）。仅浅色；GitHub 风格的默认主题保留，二者绝不混用。
- 与主题无关的聊天/RAG 升级：可选的知识侧栏（带索引状态行）、更完整的空状态构图（眉题 → 单强调词标题 → 副标题 → 药丸标签或编号示例卡片）、答案流式输出期间的检索状态行、作为另一种引用呈现方式的来源折叠面板，以及输入区改进（快捷键提示、免责声明、渐变淡出）。
- 一份**交付即完整**的契约：那一行请求就是全部规格——该 Skill 从不询问页面该长什么样，而是按请求形态路由到相应配方，并且每次交付都包含 `lang`/viewport/title、持久化的深色模式、经过设计的加载/空/错误状态、可用的键盘路径、alt 文本，以及零外部请求。
- 针对现代模型新增的两类消息的聊天配方：可折叠的推理区块（在第一个答案增量到来时自动折叠，绝不重新样式化成答案正文），以及输入区图片附件（回形针/粘贴/拖放、缩略图队列、消息内预览）。

## penguin-sdk

- 一节**思考与图片消息**，已对照 core 的 OmniMessage 协议核实：把 `partial_thinking` 流式送入它自己的折叠通道并忽略 `fidelity`（那是 core 的重放记账）；用 `imageUrlMessage` 与 `userText` 并列构建图片输入，并让配置中的 `vision` 标记优雅降级（折叠为 `[attached image: <path>]` 并经项目的 `vision_model` 回读）；另附一份速查表，覆盖其余与应用相关的载荷（`request_end` 的错误信号、`token_usage`、压缩事件、工具活动）。
- 流式循环的指引涵盖 `opts.thinkingLevel`（`none…xhigh`，对 `model.thinking_level` 的逐轮覆盖），并把 Session 生命周期点名为应用的记忆模型——有状态聊天用一个长生命周期 Session，无状态问答则每个请求一个。
- RAG 配方中新增一段**输出格式与语言**：在人设与逐请求提示词中固定格式（纯文本、裸 `[n]` 引用——或在结构确有必要时用一份经过消毒的 HTML 白名单），而不是塞进一个 Markdown 渲染器；并用一份在入库时构建、于 `search()` 中展开的小型双语关键词映射，来桥接跨语言的词法检索。
- 原本重叠的「构建之前」与「先检查模型」两节合并为一节关于 key 与数据根目录的内容，每条规则只陈述一次。

## Web 草稿页示例

知识既已移入 Skill，草稿页的示例提示词在两种语言下都变短了：RAG 示例去掉了它那段关于 BM25 跨语言的讲解与空状态指令（保留双语自测步骤），而游戏中心 / 音乐播放器示例去掉了主题持久化与响应式细节——那些现在由 web-design Skill 来保证。
