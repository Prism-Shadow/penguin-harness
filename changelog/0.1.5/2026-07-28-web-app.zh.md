- **Scope:** `web`
- **PR:** [#105](https://github.com/Prism-Shadow/penguin-harness/pull/105), [#106](https://github.com/Prism-Shadow/penguin-harness/pull/106), [#113](https://github.com/Prism-Shadow/penguin-harness/pull/113), [#114](https://github.com/Prism-Shadow/penguin-harness/pull/114), [#116](https://github.com/Prism-Shadow/penguin-harness/pull/116)

[English](2026-07-28-web-app.md)

四处渲染与输入处理修复：浏览器不再把账号凭证填进模型配置；一个关闭的停靠面板不再在打开的那个旁边画出一条多余的 1px 分隔线；一条携带 Provider 签名但不含文本的消息不再画出一个空的回复气泡；Benchmark 成本改用设置中所选的显示货币。

## 浏览器自动填充不再把账号凭证塞进模型配置

打开模型对话框可能把浏览器保存的登录信息直接递进配置里：账号密码落进 API key 输入框，用户名落进它上方的那个字段。有两个成因，都是浏览器在做它自以为有帮助的事：

- 该对话框的字段不属于任何 `<form>` 元素——整个应用只有一个真正的表单，在登录页——因此浏览器把页面上无归属的字段归入一个合成表单，并自行挑一个「用户名」输入框。
- API key 输入框本已声明 `autocomplete="off"`，而 **Chrome 与 Safari 在密码字段上会忽略它**。它们照样把保存的登录信息递上来。

现在每一个共享表单控件都默认退出自动填充，除非其调用方声明了一个真实的凭证角色。普通字段发出 `autocomplete="off"`，而退出自动填充的*密钥*字段发出 `autocomplete="new-password"`——这是密码管理器唯一会读作「这不是账号密码」的取值——并同时带上各管理器扩展的退出属性（1Password、LastPass、Bitwarden、Dashlane），因为它们读的是自家属性而不是 `autocomplete`。应用的这些表单本就没有一个想要自动填充：它们装的是 API key、模型 id、URL、目录与价格。

登录页与密码对话框未受影响——它们声明了 `username` / `current-password` / `new-password`，而已声明的角色会作为调用方的决定被放行，因此保存与填充真实密码照常可用。

该策略落在共享的 `Input` / `Textarea` 中而不是各个调用点，因此它也覆盖了那些从未被报告过的页面（Agent、Skill、定时任务、vault）；少数绕开这些组件的裸输入框——模型与 Skill 菜单的搜索框、目标预算、Workspace 路径编辑器——则各自显式带上同样的退出设置。

## 关闭的停靠面板不再画出多余的分隔线

打开 Workspace 文件面板时，会看到对话与文件之间像是楔进了第二个空面板：一条细线、一段空隙，然后才是真正的分隔线。

两个停靠面板（Workspace 文件、Agent）在关闭时仍保持挂载——宽度过渡需要这个节点——收缩为一个零宽的裁切窗口。在 border-box 尺寸模式下，它们的左边框仍然会在那里画出 1px，于是关闭的 Agent 面板在打开的那个旁边留下一条搁浅的线，而打开面板的拖拽槽成了两者之间的空隙。当两个面板都关闭时，这两条残留的线就叠在窗口右缘。

分隔线现在只属于打开状态，因此关闭的面板完全不占宽度，而对话与当前打开的那个面板之间恰好只有一条分隔线。

## 思考片段之后不再出现空回复气泡

模型思考结束后，有时会紧接着出现一个空的 `assistant:` 气泡——没有文本，只是一个占了一行的空白块。

那并不是一个游离的空字符串。当 Provider 把一个不透明的 `fidelity` 载荷附加到一个原本为空的片段上时，Core 会**刻意**发出一条正文为空的完整文本或思考消息——Gemini 在文本片段上的 `thoughtSignature`、GPT-5 的 `fidelity.phase` 分段标记、GPT-5 思考侧的加密推理。这条消息必须存在，否则签名会从历史中丢失，下一个请求就会不带它发出。它只是没有任何可显示的内容，而且落在思考→文本的交界处，这正是那道空隙出现在思考之后、且只在部分 Provider 与部分轮次出现的原因。

空正文现在在两条可能产生它的路径上都不再生成任何条目。当这条消息独自到达时——历史重建，或中途加入一个流——它被跳过而不是追加。而当确实流式输出过一个纯空白片段时（Core 在第一个*真值*增量上就打开文本片段，而 `"\n\n"` 是真值），进行中的片段会被丢弃而不是就地结算，因此实时视图与刷新后的页面渲染出同样的结果，而不是空气泡在刷新后才消失。纯空白在各处都算作空，与回复复制路径本就当作「无内容」的判断一致。

## Benchmark 成本跟随所选的显示货币

Benchmark 成本此前在显示货币切到 CNY 之后仍停留在 USD。该页面调用共享的金额格式化函数时没有传入所选货币，于是它的 USD 默认值继续生效，而模型库、成本中心、聊天与 Trace 视图都跟随了该设置。

成本趋势的坐标轴与提示气泡、评估总量、Case 总量以及各次运行的成本，现在全部接收所选的显示货币。分数与时长的格式化未变。

## 工具卡片行只陈述一次结果

折叠的工具卡片把同一件事说了两遍：左侧的状态图标本就区分了完成、失败与中止，而时长右侧的药丸又把那个词拼写了一遍。两个药丸——调用的与输出的——都已移除，只留下图标，以其 title 与可访问名称作为唯一来源。

## 页面不再能把文档撑出第二条滚动条

当一个很长的会话列表下方还有第二个 Agent 时，Traces 页与 Agent 设置页会把**文档**撑大：出现第二条滚动条，拖动它会把整个应用外壳往上拉，顶部留出空白。两处的导入控件都把文件输入框保持为视觉隐藏但可 Tab 聚焦，这意味着 `position: absolute`，而两个滚动容器都不是包含块——因此没有任何东西裁切这些盒子，它们位于折叠线以下的位置就变成了文档级溢出。只有一个 Agent 时它完全被掩盖：那个控件位于树的顶部。

该规则现在落在一处而不是每个滚动容器里——每个可滚动容器都是它自己的包含块，在样式表中声明一次——而视觉隐藏的文件输入框成为一个共享控件，无论被放在哪里都自带包含块。一次端到端扫描守护这条不变式：在有两个 Agent、且列表长到足以把第二个推到折叠线以下时，任何页面都不得把文档撑大。
