# Web App：聊天导航——输入历史、层叠粘性标题、缩略图刻度轨

- **Date:** 2026-08-03
- **Type:** feature
- **Scope:** `web`
- **PR:** [#164](https://github.com/Prism-Shadow/penguin-harness/pull/164)

[English](2026-08-03-web-chat-navigation.md)

长对话此前很难穿行：想召回一条此前的请求就得重打一遍，想折叠一段很长的思考/工具运行就得一路滚回它的标题处，而要抵达某次具体的问答就得滚过中间的一切。聊天页新增的三个导航辅助解决了这一点（[#164](https://github.com/Prism-Shadow/penguin-harness/pull/164)）。

## ↑ 输入历史

- 在输入区（实质上）为空时，↑ 以最新在前的顺序召回本会话此前的输入，与 shell 一致；↓ 反向前进，并在越过最新一条之后恢复开始导航时暂存的草稿。
- 编辑一条被召回的内容会立即结束导航；在一条多行内容内部，方向键先逐行移动光标（只有在首行按 ↑ / 末行按 ↓ 才跨越历史，与 zsh 一致），而输入法候选词的导航不受影响。
- 只有用户真正打出来的文本才算数：交接 / 模型切换的来源区块、定时触发的提示词，以及第 1 轮之后的目标重发都排除在外；转向消息包含在内；连续的重复项会被折叠。草稿聊天没有历史，保留方向键的原生行为。

## 「推理与工具」粘性标题，按层级层叠

- 分组标题在其分组主体处于视野内时吸附在消息列表顶部，而当前滚动到的思考/工具行则紧贴其下方钉住——各行在其小节边界处互相推出，因此内容正上方的那条栏总是正在阅读的那一节，绝不会是被跳过的层级。一段很长的运行可以从它内部的任何位置折叠，可以按小节，也可以整体折叠。
- 从被吸附的标题处折叠会把视图滚回那个分组/行（展开，以及在视野内折叠，则不移动视图）。该卡片使用 `overflow: clip` 而非 `overflow: hidden` 做裁切——hidden 的祖先是一个滚动容器，而这恰恰是 `position: sticky` 失效的原因；分组的偏移量以相同的 rem 单位抵消掉流容器自身的顶部内边距（行的偏移量再在其上加一个标题高度），而被吸附的栏其背景是不透明的，因此滚动内容不会透出来。

## 对话缩略图（刻度轨）

- 这个快速跳转索引不占用对话的任何宽度：一条刻度轨覆盖在居中列所空出的左侧空白上——每次问答一个刻度（轮次增多时刻度间距压缩），当前阅读位置的刻度更长更深，由滚动侦测跟踪（流的底部算作最新一轮）。
- 悬停或聚焦某个刻度会弹出一张浮动预览卡——加粗的用户问题，下方是截断的纯文本回复预览（Markdown 已扁平化；最新一轮在其回复尚未开始时显示一个脉动的「回答中」提示）——点击则直接跳到该轮，并在落点消息上短暂闪烁。这张卡片是纯粹的 tooltip：不接收点击，且只在悬停时挂载，因此静止状态下消息文本绝不会在 DOM 中重复一份。
- 当刻度轨完全无法显示时——没有悬停指针的手机，或者左侧空白被停靠面板吃掉的任何窗口——该索引移到右上角工具栏的一个图标按钮上，点开是一个问答下拉列表（问题 + 截断的回复、当前阅读位置高亮、点击跳转），使导航在任何布局下都可达。当前条目的判定只计入属于大纲条目的锚点：仅有横幅的消息、被合并的图片片段，以及第 1 轮之后的目标轮次，都解析到覆盖它们的那个条目，而不是清除高亮。
- 工具栏的 Agent 面板按钮在 sm 以下与它旁边的 Workspace 按钮一样去掉文字标签（只保留图标与 title/aria）——那些文字在手机上吃掉了会话标题的空间。
- 刻度轨只在实测左侧空白确实有余量时才渲染（实时测量——打开停靠侧栏会隐藏它，关闭则恢复），且仅限支持悬停的指针；覆盖层本身不接收指针事件，因此滚轮在左侧空白的任何位置都照常滚动消息流。协议横幅不生成条目，目标轮次并入第 1 轮的条目，定时轮次会被列出；跳转锚点只打在主对话上，且查询限定在其滚动容器范围内，因此嵌套的子 Agent 渲染不会与之冲突。

## e2e

新增的 `outline.spec.mjs` 在 1440×860 下端到端覆盖刻度轨（悬停卡片、跳转、面板吃掉空白时的自动隐藏）、层叠粘性标题与历史召回；测试套件保持 Playwright 的默认视口——刻度轨在静止状态下不重复任何文本，因此既有用例无需改动。
