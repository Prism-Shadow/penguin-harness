PenguinHarness 0.2.20 发布了。这篇文章介绍 0.2.17 那篇之后的全部更新，涵盖 0.2.18、0.2.19 和 0.2.20。**PenguinHarness 现在是一套 Harness OS：应用中心是 Project 的桌面，其中的应用由 Agent 构建、优化和发布**。现在可以语音输入消息、收听朗读的回复，从插件市场安装应用和 Agent 能力，在四套主题之间切换或导入主题包。设置和草稿随账号同步。0.2.20 让桌面应用里的工作台恢复正常加载。

## 应用中心是 Project 的桌面

**「应用中心」现在是 Project 的桌面：每个应用一个图块**。排在最前的是改为系统应用的「模型库」「插件市场」「机器管理」「成本中心」，以及「自进化工作台」。系统应用从侧栏移到了网格里，侧栏的固定块只剩「新建对话」「智能体」「应用中心」三项。「机器管理」仍只对管理员显示。Project 中各 Agent 的每个工作台都有一个图块，管理员还能看到 Project 已连接机器上的应用。

![应用中心：系统应用「模型库」「插件市场」「机器管理」「成本中心」，「自进化工作台」「命令行终端」与各 Agent 的工作台](/blog-assets/penguinharness-0-2-20-app-center-zh.png)

图块可以拖动排序，也可以拖进分组。分组从图标处就地展开，只剩一个应用的分组会自动解散。点击图块即打开应用。应用可以最小化并在后台继续运行，也可以全屏打开或关闭，几个应用可以同时运行。侧栏的「应用」分组列出当前窗口里打开的应用，每行带「更多操作」「全屏打开」和「关闭」。「命令行终端」和「浏览器」也有自己的图块，列出有活动终端或打开了网页的 Session。

**对话和应用可以并排打开**。在对话右侧栏选「打开应用中心」即列出应用，点开的应用就在对话旁边。两个窗格可以互换，任一个都能占满整个宽度。

![一段 glm-5.3-flash 的对话，右侧栏里并排打开了 AI PPT](/blog-assets/penguinharness-0-2-20-app-side-zh.png)

## 在新对话页构建、优化和发布应用

**新对话页的输入框下方有三个固定的快捷指令：「构建新应用」「优化已有应用」和「发布应用」**。它们只把提示词填进输入框，不代为发送。「构建新应用」请 Agent 构建一个新的工作台应用并上线到应用中心，同时附上 `penguin-plugin` 和 `web-design` 两个 Skill。「优化已有应用」请 Agent 改进你选中的应用。「发布应用」请 Agent 提交 Pull Request，把应用加入 PenguinHarness Apps 仓库并在插件索引中登记。

![「构建新应用」把提示词填进了输入框，并附上 penguin-plugin 与 web-design 两个 Skill](/blog-assets/penguinharness-0-2-20-build-app-zh.png)

应用由文件构成。工作台页面可以是一个引入 React 和 `@prismshadow/penguin-ui` 的 `.tsx` 文件，后者随每个版本发布到 npm。服务端在加载时对页面做类型检查并编译，类型错误报告为 `ui/<file>:<line>:<col>`。工作台的历史版本是 Agent State 旁边一个裸仓库（`agent_state.git/`）里的 git 提交，由内置的 Git 引擎写入，不需要系统装有 git；「历史版本」和「恢复」读取的就是这些提交。工作台可以打包成 zip 导入导出。工作台有自己的数据、缓存和状态目录，可以开一个只对话的 Session（`approvalMode: "deny-all"`），用 Project 的语音模型朗读，还可以为游戏请求指针锁定。

还有一批新应用可以直接用。AI PPT 来自内置的 `use-bento-slides` 插件，把 Bento 的幻灯片编辑器放在 Agent 的对话旁边，你和 Agent 编辑同一份文稿。新 Project 的默认 Agent 已预装它。图像工作室来自多模态工具插件，用 Project 的图像模型生成图片。阅读工作台和五个日常工作台（冰箱管家、会议行动簿、跑团桌、派对猜词、每日一签）可以从插件市场安装。

## 语音输入消息，收听回复

**选定语音识别模型后，发送按钮旁的麦克风会把语音转写进草稿；选定语音合成模型后，回复上的扬声器会朗读最终回复**。两者都在「多模态模型」里选择，从模型库或项目设置打开：第一行是 Project 的视觉模型，其下每行对应已启用插件声明的一项用途。`@penguinharness/multimodal-tools` 插件基于这些模型提供八项工具：文本生成、图片理解、网页搜索、读取网页、图像、视频与语音生成，以及语音识别。Agent 通过 `penguin tools …` 命令调用它们。

录音时，麦克风变为「完成录音」，工具栏显示取消按钮、录音时长和音量条，发送按钮和其他控件位置不变。录音为 16 kHz PCM WAV。完成后转写插在光标处；取消或按 Esc 丢弃这次录音。「润色语音输入」用 Project 的文本生成模型整理转写，润色失败时插入原始转写。只有静音的录音不会发给模型：界面提示未识别到语音，并保留草稿和附件。Project 所有者也可以选用支持音频输入的 Gemini 模型做语音识别。

![用 TokenDance 的 DeepSeek ASR 语音输入：取消按钮、录音时长、音量条与「完成录音」](/blog-assets/penguinharness-0-2-20-dictation-zh.png)

「朗读回复」从最终回复的第一段读到最后一段，跳过此前的进度说明和工具调用。音频随 Session 保存：用同一语音模型再次朗读同一条回复时直接播放，不再发起请求，Project 的成员都能复用。TokenDance 分组新增工具模型 DeepSeek TTS（`tokendance/deepseek-tts`）。工作台无需创建 Session，也能用 Project 的语音模型朗读文字。

![glm-5.3-flash 回答了语音输入的问题，DeepSeek TTS 正在朗读，按钮显示「停止朗读」](/blog-assets/penguinharness-0-2-20-read-aloud-zh.png)

## 插件市场：安装应用和 Agent 能力

**「插件」页面现在是一个市场：封面卡片或紧凑列表、搜索、筛选、分组，每个插件都有可分享的地址**。安装时只有一条进度条，按这次安装的阶段分段（查找、下载并安装、启动、选择 Agent），并可选「在后台继续」。管理员可以在市场或「Agent 设置」里更新插件，两处都先列出已装版本和目标版本。对管理员，市场还会列出 Project 每台机器上的插件。

![插件市场的封面卡片，按类别分组](/blog-assets/penguinharness-0-2-20-market-zh.png)

「Agent 设置」新增「插件」标签页，分为「插件」「技能」「钩子」「工作台」四个子页面。整个插件可以一步从 Agent 上卸载。插件索引来源及其 CDN 镜像在「设置 › 插件」里配置。`penguin plugin link <directory>` 把本地插件包目录链接到服务端，不再上传副本。没有依赖的插件在没有 npm 的机器上也能安装和卸载，桌面应用也是如此。

**0.2.20 让市场恢复列出已发布的插件索引，并写明来源失败的原因**。索引为十九行条目加上了不带 `url` 的 `npm` 渠道，而服务端读到第一行这样的条目就拒绝了整份文档。现在只有安装时下载用的 `github` 渠道必须带 `url`。市场提示下的「详情」逐个列出读取失败的来源地址和服务端给出的原因，后接「[报告问题]」。

![插件市场的提示展开后：一个文档被拒的来源和一个主机无法解析的来源，各附服务端给出的原因](/blog-assets/penguinharness-0-2-20-market-sources-zh.png)

## 主题包，以及第四套主题

**每套主题现在都是一个主题包，卡通是继白领、极客、朴素之后的第四套内置主题**。管理员以 zip 文件（不超过 16 MB）导入主题包，本服务器上的每个账号都能选用。任何主题包，包括内置的，都能导出为同样的 zip。导入时会校验主题包。卡通是第一个以白领为基准的主题包：沿用白领的布局、间距和动效，重画纸张、字体和笔触。

![卡通主题下的「设置 › 外观」：四个内置主题包各带导出按钮，下方是导入主题包](/blog-assets/penguinharness-0-2-20-themes-zh.png)

「设置 › 外观 › 思考显示方式」提供「标准」「展开」「紧凑」三种呈现对话推理与工具步骤的方式。每套主题有自己的翻页动效和等待动画。没有头像的 Agent 画成一只小企鹅，随主题换风格；也可以给 Agent 设置自己的头像。

## 设置随账号同步，工作台实时跟随 Agent

**从 0.2.18 起，设置页上的偏好和 Web App 里尚未发送的草稿保存在服务端的账号里**。在另一个浏览器或桌面应用登录同一账号，看到的是同样的主题、语言、背景图片和草稿。升级后，浏览器第一次登录时会把自己原有的偏好和草稿交给账号一次，前提是账号里还没有。面板宽度、停靠栏布局、折叠和置顶仍留在浏览器里。

**工作台可以在 Agent 工作时实时跟随它开启的 Session**，读取的是与对话相同的 AMSP 记录。页面引入 `../sdk/workbench.js`（每个工作台旁都会提供），使用 `followSession()` 和 `abortSession()`；处理程序调用 `WorkbenchHost.subscribe(sessionId, listener)`。工作台页面通过 `/workbench-ui.css` 套用应用的整套主题。内置的 PenguinHarness 客服工作台就用到了这些：问题处理期间，对话框随写随显回答，说明 Agent 正在做什么，并提供「停止」。

![客服工作台用 glm-5.3-flash 查阅一个问题：随写随显的进度，以及「停止」](/blog-assets/penguinharness-0-2-20-support-live-zh.png)

## 修复加载失败的工作台

**0.2.20 起，凡是显示工作台文件加载失败的地方，Web App 都在「重新加载」旁提供「用 AI 修复」与「[报告问题]」**。它们出现在应用中心窗口、应用中心的「查看错误」对话框，以及「Agent 设置」中该工作台那一行的「更多」菜单里。

![类型检查失败的工作台在应用中心窗口里：错误、「重新加载」「用 AI 修复」与「报告问题」](/blog-assets/penguinharness-0-2-20-workbench-fix-zh.png)

「用 AI 修复」会先请你确认，再由默认 Agent 在临时 Workspace 里开一个新对话。修复请求预填在输入框里，不代为发送。请求写明工作台、所属 Agent 与所在机器、目录，以及原样的加载错误，并说明加载的过程。Agent 在改动之前会先说明打算。错误出自平台本身时（例如缺少 Node 或 TypeScript 的声明），Agent 会直接说明、不做改动，并建议报告问题。「[报告问题]」打开共用的问题报告，附上工作台和打码后的加载错误。

## 没有摘要时，也能看到交接内容

**0.2.20 起，压缩未能生成完整摘要时，对话会展示新上下文改以什么开头**：就地的交接说明，或会话内切换模型时的 Trace 交接说明。它放在所接续的压缩行里。该行定格为「压缩完毕」，由状态图标说明没有摘要的原因。

![glm-5.3-flash 真实回答一轮后，从一个已不在配置中的模型切换出去：「压缩完毕」一行展开到「交接说明」，下方是「模型已切换」分隔线](/blog-assets/penguinharness-0-2-20-handover-zh.png)

这一行默认折叠。其中的「交接说明」一节依次给出原因、交接说明点名的 Trace 文件以及交接说明原文。从一个已无法访问的模型切换出去时，不会向它发出任何请求，这一行会写明「原模型不可用，没有请求摘要」。

## 0.2.17 以来还有

- **自进化**：新 Project 会在默认 Agent 上安装自进化工作台。产品自带默认 RSI 工具包；OPRO、APE、ACE、AWM、SkillAdam、SkillOpt、OpenSkill、TRACE 和新增的 RRSI 从插件市场安装。Benchmark 的「使用」对话框新增「被测智能体使用的模型」一栏。新 Project 收到按六个领域拆分的 GDPEVO 训练与测试 Benchmark。
- **新插件**：Computer Use 让 Agent 通过 `penguin computer` 查看并操作 macOS、Windows 和 Linux 上的桌面应用。默认只有管理员，以及管理员驱动的对话里的 Agent 可以使用。预装的「存储空间」在「设置 › 存储空间」和 `penguin storage` 里显示数据根的占用，经审阅后清理草稿区、临时 Workspace 和缓存。计划模式是输入框 + 菜单里的一个开关，也可以用 `/plan`，让 Agent 先和你商定做法再动手。Trace Lookup 教 Agent 读取自己的 Trace 文件。插件可以为 `penguin` 增加命令。
- **对话**：运行中发送新增第三种方式「打断」，与「插话」「排队」并列。压缩可以把细节存进交接文件，并总会开启下一段上下文。子 Agent 以 Session ID 寻址。智能体面板在可平移缩放的画布上绘制拓扑。任务运行时输入 `/`，可以把 Agent 的某个 Skill 加进插话。应用显示的每个失败都提供「[报告问题]」。
- **Agent**：合并 Pull Request、发布软件包或强制推送之前，Agent 会等人确认。所有出厂命令策略规则改为请求确认，不再直接拒绝。Agent 可以打包成其目录的 zip，用于导出和导入。记忆可以保存 Agent 复用的脚本。Agent 会记录作者，「智能体」页面按作者分组。0.2.20 的默认系统提示词新增六处优化，涉及交付物校验、低成本定位失败，以及长命令与常驻服务的运行（内核版本 `2026-11-26`）。
- **模型**：新 Project 不再带默认模型，首次使用时由「默认模型设置」对话框请你选择。新增预设包括 Gemini 4 Neon 和 Gemini Nano Banana 2.1；腾讯 Hy4；TokenDance 上的 Hy4 Flash、Qwen4 Max 和 GLM-5.4；Penguin Go 里的 Gemini 4 Hydrogen 与七个工具模型；Runcrate 网关分组；以及 JellyToken 服务商。导入模型分组时，可以挑选要导入的模型。
- **远程机器与终端**：从 0.2.18 起，页面先显示本服务端已有的内容，不再等待机器或互联网。机器重连与模型请求重试共用一行，带「立即重试」和「放弃重试」。自动重连在连续失败五次后停止。远程对话的历史从最新一条开始流式加载，机器断开期间仍能阅读最近的消息。机器对话框新增「重新安装」。0.2.20 起，机器的服务端仍在启动时，连接机器不再在「同步配置」一步失败。终端能应对移动网络。管理员可以为每个用户设置终端与内置浏览器页面的上限。
- **桌面应用**：可以从命令面板打开第二个窗口，标题栏成为应用的一部分。新增右键编辑菜单。内置浏览器支持 Google 登录，Cmd/Ctrl+B 切换侧栏。Windows 安装程序可以把服务端数据和桌面配置放到另一个盘。0.2.20 让桌面应用里的工作台恢复正常加载，0.2.19 中它们都以 `TS2688` 失败。
- **修复**：删除大型 Agent 时，目录立即移开，文件在后台删除。从模型库连接 TokenDance 后，重定向回浏览器所在的地址。成本中心对异常结束的计费请求只计一次。插件安装失败时显示 npm 自己的错误，而不是 npm 先打印的警告。提示气泡里的长路径在面板内折行。

## 升级须知

从 0.2.17 升级时：

- **0.2.16 及更早版本的 Windows 桌面应用**：请从 [penguin.ooo/download](https://penguin.ooo/download) 手动安装一次这个版本。0.2.16 及更早版本的更新程序会拒绝新证书签名的安装包。
- **数据根**：无需操作。服务端首次启动时会把各 Project 一次性移到 `<root>/projects/<project_id>/`，并在原位置留下链接。名为 `projects` 的 Project 会让服务端无法启动：请先启动旧版本，把其中的 Agent 移到别的 Project，删除它，再重新启动。在 Windows 上，所有 Project 目录要么全部移动，要么都不动。如果启动时提示有程序占用了某个目录，请先关掉那个程序。
- **远程机器**：机器必须与服务器版本一致，请在「机器管理」页面逐台更新。仍是旧目录结构、拒绝热更新的机器，需要先重启它的服务端（这会结束其上的终端和命令），再更新。
- **已有 Agent**：在「智能体」页面运行「更新内核」，获得等人确认的规则、记忆的脚本说明和优化后的默认系统提示词。接受那里提供的插件更新，例如 `use-bento-slides`、`agent-development`、`goal` 和 `penguin-support`，并在「Agent 设置」的「插件」标签页安装计划模式。
- **名为 `system_agent` 的 Agent**：请把它导出，以另一个 id 导入，再删除原来的那个。在此之前，该 Project 没有系统 Agent。
- **新 Project 与脚本**：新 Project 没有默认模型。先创建 Project、再创建 Session、定时任务或组织的脚本，必须指定模型，或先运行 `penguin config model default --provider <group> --model-id <id>`。
- **HTTP API 与 SDK 调用方**：Agent 的 `export` 与 `import` 路由由 `GET …/agents/:agentId/archive` 和 `POST …/agents/import` 取代。删除组织改为应答 `200` 并附报告，记忆导出改为 zip。`@prismshadow/penguin-core/a2ui` 移到了 `@prismshadow/a2ui`。忽略 `context.reason` 的审批回调在全部放行时会放过命中出厂规则的命令。完整列表见 [0.2.19 更新日志](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.19)。
- **插件作者**：插件包必须先构建，带上 `ifaces.json`（`penguin-gen-ifaces`）。不再读取 `package.json` 里的 `penguin` 块。
- **打开中的对话里的交接说明**：没有切换模型、压缩退回到交接说明时，「交接说明」一节要在重新加载后才出现；切换模型的交接说明即时出现。
