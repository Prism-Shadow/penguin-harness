PenguinHarness 0.2.13 重建了评估中心，一个 Benchmark 现在可以评估多个 Agent；文件面板也成了真正能用的文件管理器。关掉窗口之后，桌面应用会留在系统托盘里继续运行；运行中的工具调用可以转入后台；三个曾让 Task 中途终止的网关问题也修好了。我们还以内测形式推出了公司模式：由管理员开启之后，你就可以在 Project 里建立一个由 Agent 组成的组织。

## 重建的评估中心

Benchmark 不再放在被测 Agent 的目录里。它从 `agents/<agent>/benchmarks/<id>/` 移到了 Project 自己的 `benchmarks/<id>/`，所以一个 Benchmark 可以评估多个 Agent，每条评估记录也会写明被测的是哪个 Agent。

- 每条评估记录的标签是 `<agent_id> · <model_id> · <thinking_level>`，图表按标签各画一条序列。只有可比的分数才会落在同一条线上，所以同一个 Agent 在同一运行时上的历次版本，现在能连成一条完整的趋势线。
- 打开一个 Benchmark，会进入它自己的页面 `/benchmark/:benchmarkId`。点击评估表格里的一行，会打开评估详情对话框；点击一道题目，会打开题目对话框。
- 两个对话框的末尾都有**问 AI** 按钮，把屏幕上的信息交给一个预填好的对话。从评估详情发起时，交过去的是 Benchmark id、序列标签、版本、供应商、模型、思考等级、各题分数，以及每次运行的 Session id；从题目发起时，交过去的是这道题的任务材料和评分标准的路径，以及最近一次评估中各次运行在这道题上的得分。
- Benchmark 有了 `status` 字段。`benchmark-design` Skill 校准期间，处于 `draft` 状态的 Benchmark 会以遮罩显示；被测 Agent 的基线分在 0–100 分制下低于 85 时，Skill 就会发布它。
- 评估产生的会话会归进单独的**评估任务**文件夹，不再挤进被测 Agent 的活跃列表。

## 文件面板成了文件管理器

Workspace 浏览器改名为**文件浏览**，现在不只能浏览 Workspace，还能用它来管理 Workspace。

- 目录树的任意一行和预览区都有右键菜单，右键点击、按 Shift+F10 或长按都能打开。菜单里有复制路径、添加到对话、上传、下载、重命名、移动和删除。
- 重命名和删除沿用编辑器保存时的同一项检查：如果对话框开着的时候 Agent 改写了这个文件，这次操作就会遭到拒绝。
- 语法高亮移到了后台 Worker 里，体积上限也随之取消。高亮 TypeScript 每千字节大约要花四毫秒，这正是过去源码视图超过 64KB、编辑器超过 32KB 就不再处理的原因。现在这两道上限都没有了。
- 文本预览现在最多可以读取 1MB。打开一个 400KB 的文件时，高亮的整个过程中页面都能稳定保持每秒 60 帧。
- 搜索框现在在服务端搜索整个 Workspace，而不是只过滤目录树碰巧已经加载的那些行。
- 自动换行现在默认开启。

![文件浏览面板，目录树上的一行打开着右键菜单](/blog-assets/penguinharness-0-2-13-files-panel-zh.png)

## 关掉窗口，桌面应用继续运行

桌面应用现在在 Windows、macOS 和 Linux 上都有系统托盘图标。默认情况下，关闭主窗口只会把应用收进托盘，内嵌的服务端和它的后台任务照常运行。

- 左键点击托盘图标可以把窗口叫回来。右键点击会看到**打开 PenguinHarness**、**新建会话**、**模型**、**关闭窗口后继续在托盘中运行**复选框，以及**退出**。
- **系统设置** › **外观**里的**托盘图标**开关可以关掉托盘图标，不需要重启。
- 文件浏览面板的预览头部新增了**在文件夹中显示**。它只在桌面应用自己的窗口里出现，并由服务端把关：登录同一个服务端的浏览器拿不到它，哪怕浏览器就运行在那台机器上。macOS 和 Windows 上会选中这个文件，Linux 上则会打开所在的文件夹。

## 把运行中的工具调用转入后台

`exec_command` 或 `run_subagent` 执行期间，它在对话里的那一行会出现**转入后台执行**按钮。点击后，这次调用会带着 `process_id` 或 `subagent_id` 返回，不会终止任何东西，这一轮也继续往下走，不必等命令跑完。

- 转入后台的子 Agent，在启动它的那一轮结束之后，仍然会继续运行、继续流式输出。
- **转入后台执行**要等调用运行满十秒才会出现，几秒就能返回的命令不会再让它闪一下又消失。

![运行中的 exec_command 行上出现的转入后台执行](/blog-assets/penguinharness-0-2-13-send-to-background-zh.png)

## 三个曾让 Task 中途终止的网关问题

这三个问题都会让供应商返回 4xx 错误，引擎把它当作致命错误处理，Task 就停在了原地。三个问题都已在 AgentHub 里修复。

- AgentHub 0.4.12 把 `read_file` 读到的图片，或者 MCP 工具返回的图片，从 `tool` 消息挪到这一轮之后的那条 user 消息上。这是 Chat Completions 文档里唯一给出的放置方式；以前，按 schema 校验请求的网关会把整个请求打回。
- AgentHub 0.4.14 修复了 DeepSeek 上的两个错误：一个是在严格的 Responses 中继后面，第一次工具调用之后的那条请求报 `400 invalid_json`；另一个是长工具链跑到一半时报 `400 The reasoning_content in the thinking mode must be passed back to the API`。
- AgentHub 0.4.15 修复的是一轮里并行调用两个工具、而网关先打开所有调用再逐个关闭的情况。以前到了下一个请求，这一整轮都会丢失，并报 `No function call found for function_call_output`。

## Shell 命令可以受约束运行

Harness 新增了一个沙箱接口，从三个维度约束 shell 命令：`fs-write`、`network` 和 `mask-paths`。后端负责改写命令的 argv，并如实报告自己实际强制执行了哪些约束。路由宁可拒绝也不放行：如果没有任何后端能覆盖某项要求，命令就不会启动，而不是不受约束地运行。

Harness 本身不带任何后端。四个后端以插件包形式提供，包名是 `@prismshadow/penguin-plugin-<backend>`，由部署方自行安装，并写进 `plugins.json`：

| 后端 | 平台 |
| --- | --- |
| `sandbox-dsh` | 跨平台 |
| `sandbox-bwrap` | Linux |
| `sandbox-seatbelt` | macOS |
| `sandbox-mxc` | Windows |

默认部署一个后端都不写，也就什么都不约束。

## 模型目录

- OpenRouter 的全部 43 条预置现在都使用 Responses API，此前只有十条 `openai/*` 是这样。协议由 OpenRouter 分组本身固定，所以你手动加进这个分组的模型也会使用 Responses。
- `Atria-Dawn-Preview` 加入 Custom 分组：Anthropic Messages 协议，256K 上下文窗口，仅支持文本。
- 免费的 `dots-3-note-preview` 加入 TokenDance 分组：512K 上下文窗口，支持图片。
- 协议识别不再照字面读取你填入的 URL。多一个 `/v1`、少一个 `/v1`，或者从供应商文档里整段复制来的端点路径，现在都能正确识别，**模型库**页面还会把修正后的 URL 写回输入框。

## 一个 Project 里可以有一家 Agent 公司

公司模式是内测功能，默认关闭，需要管理员在**系统设置** › **服务器** › **公司模式**里打开。开关一拨，立即生效。模式切换处和总开关下方都标着**内测版**：这项功能还很新，你可能会遇到问题。

打开公司模式后，你可以在 Project 里创建组织，一个 Project 里可以有多个组织。创建组织只需要一句话，也就是组织的使命；刚创建时，组织里只有 CEO。管理者的预算涵盖其所有下属，所以 CEO 默认每月 100 USD 的预算，从一开始就封住了整个组织的开销。

一个组织包括：

- 一位 CEO，位于汇报树的根部；每位员工各有一条常驻的工位会话
- 一份日历
- 一块工单板
- 若干频道
- 每位员工的月度预算：用到 80% 时告警，用到 100% 时暂停这位员工及其所有下属的日历

这些全都以文件形式存放在 `<project>/organizations/<org_id>/` 下。SQLite 只保存缓存，每一轮都从这些文件重建。

**概览**、**组织图**、**日历**、**工单**、**财务**和**手册**六个页面，挂在 Project 切换器上方的**开发 | 公司**开关后面。命令行一侧，`penguin org` 覆盖了全部 API，每条命令都支持 `--json`。

## 工单板、日历，以及谁来拍板

- 工单板分五列：`proposed`、`in_progress`、`review`、`done` 和 `rejected`。
- 按照设计，CEO 负责提议，由你拍板，但这只是写给 Agent 的指引，服务端并不强制执行。CEO 的 Skill 和组织手册要求它：在招聘（岗位、预算、模型）、设定或提高预算、驳回别人提的工单、不经审核就关闭 P0 或 P1 工单，以及做任何超出组织范围的事情之前，先在全员频道里发一条提案，等你答复。
- 服务端调度器每 30 秒对每个组织对账一次，每次 API 写入之后也会马上再对一次。它把到期的日程投递给工位，送达频道里的提及，并重新计算预算。组织暂停期间到期的日程，恢复之后不会补发。
- 工单变更从不启动运行。变更先排队，等到这位员工下一次日历巡检时才送达，列在 `## Since your last sweep` 标题下。
- 在频道里，只有 `@` 提及才能把消息送到某个人那里。
- 工位会话和工单会话都是普通对话，消息列表、工具卡片和输入框都和开发模式一样。公司模式没有自己的聊天页。
- 工位会话和工单会话无人值守运行，从不停下来请人审批工具调用。组织的审批模式默认是**全部放行**，也没有「总是询问」这个选项。

## 这一版还有

- **默认系统提示词加了护栏。** 一共改了十四处，针对旧提示词放任的四种失败模式。「无法解决」现在有了可观测的触发条件：换了三种不同的修法之后，同一个错误依然存在。相互独立的工具调用会一次发出，命令以非交互方式运行，一个库要在清单文件里出现才算可用。新增的 `# Output` 一节去掉了空洞的开场白、复述工具名和结尾总结。
- **同一个文件上的两处并发编辑，不会再悄悄丢掉一处。** `edit_file` 和 `write_file` 在读取、修改、写回的整个过程中都持有按文件加的锁。锁以文件的真实路径为键，所以软链接和它指向的文件共用同一把锁。
- **每个账号都有了个人资料。** 头像（128×128，会重新编码，超过 128 KiB 拒收）和 1–32 个字符的昵称，取代了侧栏、导航栏和管理员列表里的原始用户 id。
- **代理选项可以测试连通性**，目标共六个：OpenAI、Anthropic、Gemini、DeepSeek，以及 GLM 的两个域名。测试由服务端发起，不带任何凭据，每个目标限时五秒，哪个目标有了结果，就填进对应的那一行。任何 HTTP 应答都算连通，401 和 403 也算，因为即使凭据遭到拒绝，也说明域名解析、TCP 连接和 TLS 握手都已成功，主机也作出了应答。
- **长 Trace 现在能打开了。** 以前只取前 1000 条事件，靠后的轮次（包括压缩那一轮）显示的都是空的消息列表。现在查看器会分页读完整个文件，边读边渲染。
- **工具卡片可以显示短名。** `read_file` 显示为「读取」，`exec_command` 显示为「执行命令」，`run_subagent` 显示为「子智能体」。**外观**里有一个开关控制这项功能，默认开启，悬停提示里仍是真实名字。
- **压缩请求使用会话锁定的思考等级**，和其他请求一样。以前它用的是上下文的基础等级，在 DeepSeek 上可能导致请求直接遭到拒绝。
- **侧栏文件夹每次展开十条对话**，点击**收起**可以折叠回去。
- **上下文面板更好读了。** 拖动压缩阈值的虚线时，数值始终看得清；模型本身有、但压缩不允许会话用到的那部分空间，会以斜纹标出；点击长条上的一段或图例里的一行，可以把高亮固定住。
- **任务完成通知这次真的能用了。** 以前没有任何代码调用过 `Notification.requestPermission()`，而 Electron 不问任何人就报告 `granted`，所以在 macOS 上，从没申请过授权的应用包发出的通知会直接丢失。现在**系统设置** › **通用**里新增了一个开关，默认关闭，打开的那一刻才去申请权限。浏览器现在也能显示这类通知了。
- **用过或已过期的一次性登录链接**，现在会跳到 `/login`，并弹出对话框说明原因，而不是显示一页原始 JSON。
- **退出登录前会先确认**，并说明后果：当前的登录会话结束，运行中的对话在服务端继续。
- **行为准则升级到 Contributor Covenant 3.0**，中英文同步。执行阶梯的每一级现在都写明了期望的补救措施，而不只是后果。举报渠道不变。

## 升级须知

- **把 `extensions.json` 改名为 `plugins.json`，其中的 `"extensions"` 键改为 `"plugins"`。** 旧文件名不再读取，也不做迁移。按旧名称配置插件的部署会照常运行，但一个插件都不会加载，这些插件提供的能力就这样悄无声息地没了。
- **按新契约改写插件。** import 路径改为 `@prismshadow/penguin-core/plugin`，不再是 `/extension`；`activate(ctx)` 换成了 `Plugin { modules }`。按旧契约编写的已安装插件会加载失败，报「the default export is not a Plugin」。`@prismshadow/penguin-server` 不再导出 `AppDeps`、`buildAppDeps` 和 `createApp`。这次改名不影响线上传输格式、数据库，也不影响磁盘上的任何文档。
- **到模型库页面点一次同步预置。** 已存的模型条目会保留写入时的协议、显示名和视觉标记。OpenRouter 改用 Responses、`deepseek-v4-flash` 更正为仅支持文本，以及两条新预置，都只能通过同步进入已有的 Project。同步还会把你特意清空的显示名重新填上。
- **想用公司模式，就自己打开**：位置在**系统设置** › **服务器** › **公司模式**。它默认关闭，开关一拨就生效。
- **两个默认值变了。** 任务完成通知默认关闭，需要你自己打开；对于从没动过**自动换行**开关的人，文件编辑器的自动换行默认开启。
- **把还留在 `agents/<agent>/benchmarks/` 下的 Benchmark 手动移到 Project 的 `benchmarks/`。** 这个版本不读取旧位置，也不会迁移或删除那里的内容。
- **迁移 5、6、7、8** 都是只做新增的迁移，在打开数据库时自动执行。个人资料页带来迁移 5，公司模式带来迁移 6、7、8。

## 安装

桌面应用的安装包在 [penguin.ooo/download](https://penguin.ooo/download)。

Linux 和 macOS 上，用下面的命令安装 CLI 和服务端：

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows 上用 PowerShell：

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

用 Docker 运行服务端：

```sh
docker run -d --name penguin -p 127.0.0.1:7364:7364 -v penguin-data:/data hiyouga/penguinharness:latest
```

每一项改动的完整细节见 [`changelog/0.2.13/`](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.13)。
