PenguinHarness 0.2.21 发布了，这是基于 0.2.20 的紧急修复版本。**glibc 低于 2.42 的 Linux 系统上，终端恢复可用：在 0.2.19 和 0.2.20 中，服务端、Linux 桌面应用和远程机器上的终端都打不开**。服务端启动时收到 socket 不再退出；连不上的机器上的对话不再无限重试，改为显示缓存副本；从「快捷方式」打开的「记忆」能正常加载；浏览器面板会自动打开第一个标签页；通过「远程控制」连接的 QQ 机器人可以双向收发图片、文件和语音消息。0.2.17 以来的全部新功能，请看 [0.2.20 的文章](/blog/penguinharness-0-2-20)。

## Linux 上的终端恢复可用

**在 0.2.19 和 0.2.20 中，glibc 低于 2.42 的 Linux 系统上，所有终端都以 `terminal_spawn_failed` 失败**。受影响的包括 Debian 12 和 13、Ubuntu 25.04 及更早版本、RHEL 8 和 9，问题报告见 [#1900](https://github.com/Prism-Shadow/penguin-harness/issues/1900)。node-pty 的 Linux 绑定在安装时编译，而发布带的是 `ubuntu-latest` 运行器编译出的那一份。这个运行器已换成 Ubuntu 26.04，其 glibc 给 `cfsetispeed` 和 `cfsetospeed` 加了新的符号版本，于是绑定需要 GLIBC_2.42。Linux 桌面应用带的也是这个绑定，而桌面应用推送给机器的安装镜像则完全没有 Linux 绑定。

现在 x64 和 arm64 两个 Linux 绑定都在 `manylinux_2_28` 容器中构建，只需 glibc 2.28，与随附的 Node 要求相同。Linux 安装包、npm 包的随带存储、桌面应用自身的 node-pty，以及它推送给机器的安装镜像，都带上了这两个绑定。glibc 为 2.28 到 2.33 的系统（例如 RHEL 8 和 Debian 11）也能用终端了：0.2.18 及以前，绑定需要 2.34，机器检查也不再提示终端需要这个版本。

发布流程现在直接检查发出去的东西。`scripts/check-native-glibc.mjs` 读取安装包、npm 包的随带存储和桌面应用中每个 Linux `*.node` 的符号版本；只要有一个需要高于 2.28 的 glibc，或缺少应有的绑定，发布、桌面端构建和 CI 的 npm packaging 都会失败。

## 连不上的机器上的对话显示缓存副本

**打开一台连不上的远程机器上的对话时，不再无限重试**。每次等待都会写明原因和第几次（上限 5 次），例如「连不上 Office 上的服务，2 秒后重试（第 2/5 次）」。连续 5 次重试（1、2、4、8、16 秒后）都没有进展后，页面显示本服务端缓存的对话副本，以及一行写明原因的状态，句末带「[重试]」，按下只再试一次。

![连不上的机器 Office 上的对话，重试已停止：状态行「Office 上的服务没有响应。正在显示上次同步的对话记录。」与「重试」，下方是一段真实 glm-5.3-flash 对话的缓存副本](/blog-assets/penguinharness-0-2-21-offline-machine-zh.png)

在这台机器的任何一条流再有进展之前，对它的后续读取只尝试一次、不再重试，反复打开对话不会重新开始一轮。机器列表已把机器读作离线时，缓存副本和状态行会立即显示。机器的 API socket 重新连上后，页面会自动重新读取实时历史，不需要轮询。

## 从「快捷方式」打开的「记忆」能正常加载

**从 0.2.19 起，从对话的「快捷方式」打开的「记忆」会一直停在加载状态；现在它一打开就读取 Agent 的记忆**。这个问题在本服务端和远程机器上的对话里都存在。现在「记忆」从对话所在的机器读取；读取失败时显示失败原因和「[报告问题]」，不再一直等待。

![一条真实 glm-5.3-flash 回复依据 Agent 的记忆作答，旁边是从「快捷方式」打开的「记忆」，列出三条用户记忆](/blog-assets/penguinharness-0-2-21-memory-zh.png)

从「快捷方式」打开的文件、记忆和智能体跳转，在对应工具关闭时也会重置，再次打开不会重放上一次的跳转。

## 浏览器面板自动打开第一个标签页

**打开没有标签页的浏览器面板时，会自动新建一个标签页，就像终端面板自动创建第一个 shell 一样**。每次面板显示时只创建一次；已有标签页或内置浏览器不可用时不创建。关掉最后一个标签页后，面板保留「新建标签页」按钮，不会再自动打开。

![浏览器面板及其自动打开的第一个标签页：标签栏里带蓝色地球图标的「新标签页」、地址栏和列出常用网站的起始页](/blog-assets/penguinharness-0-2-21-browser-tab-zh.png)

新标签页的地球图标改用主题的链接色，不再是过淡的次要文字色，四套主题和深色模式下都清晰可辨。

## QQ 机器人双向收发图片、文件与语音

**通过「远程控制」连接到 QQ 机器人的对话，不再只能收发文字**。Agent 在回复里写出的图片和文件会发到 QQ。你发来的图片、文件和语音消息也会送达 Agent。语音消息以 QQ 自带的转写文本送达；被引用消息的文本作为引用块放在回复之前。

文件经 QQ 的富媒体上传后以被动回复发出，服务端不需要公网地址。每个文件占用 QQ 为你这条消息允许的一条回复，且仅在没有文字等着最后一条回复时才可使用。没有剩余回复或被 QQ 拒绝的文件，会在聊天里留一行说明；QQ 无法识别的图片格式会改作文件重发。

## 本版其他更新

- **服务端**：服务端正在启动或替换运行中的模块时到达的 socket，可能导致进程退出，例如仍开着上一个服务端的浏览器标签页，在新数据根尚在启动时重连。现在启动完成之前，服务端对所有请求都以带 `retry-after` 的 503 应答，WebSocket 握手则立即以 1013（Try Again Later）关闭。格式错误的 WebSocket 请求可能让运行中的服务端停止，现在会以 400 拒绝。终端流或 API socket 的握手失败会记入日志并被拒绝，这些情况都不再导致进程退出。
- **远程机器**：在桌面应用里，运行于远程机器上的对话打开浏览器时，会说明此对话运行在另一台机器上、那台机器没有桌面应用、机器上的对话用不了浏览器，不再让已经在用桌面应用的人去打开桌面应用。在机器上，`penguin browser status` 会说明会话的浏览器在添加这台机器的那台电脑的 PenguinHarness 里。
- **界面**：停靠栏的「+」菜单不再列出「隐藏悬浮球」。该项仍保留在悬浮球自身的菜单里，已隐藏的悬浮球可在「设置 › 外观」的「快捷方式悬浮球」开关中重新显示。
- **界面**：打开应用时，侧栏的「应用中心」不再与该应用自己的行同时高亮。
- **界面**：换行或带标题的提示条，状态圆点停在第一行，四套主题都是如此。

## 升级须知

- **Linux 桌面应用**：在「应用信息」对话框中更新应用；`.deb` 安装通过包管理器更新。
- **Linux 服务端或 CLI 安装**：运行 `penguin update`，或重新运行安装脚本。
- **远程 Linux 机器**：先把添加它们的桌面应用或服务端更新到 0.2.21，再在「机器管理」页面逐台「更新」，或「全部更新」。机器运行 0.2.21 后，其上的终端即可打开。
- **npm 安装与 Docker 镜像**：node-pty 在安装处编译，不受影响。

安装包可从 [penguin.ooo/download](https://penguin.ooo/download) 下载。完整细节见 [0.2.21 的更新日志](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.21)。
