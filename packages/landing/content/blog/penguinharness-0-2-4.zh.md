PenguinHarness 0.2.4 发布。这一版由三件事撑起来：一个能读图的 DeepSeek 模型，一个可以自己编排而不必将就的工作区，以及一个终于像一整页、而不是四个互不相干小部件的成本中心。

## 一个会看图的 DeepSeek 模型

AgentHub 0.4.6 把 `deepseek-v4-flash-vision-exp` 带进了模型库。它在 V4 Flash 的文本能力之上增加图像输入，保留 1M 上下文窗口，价格与 V4 Flash 相同。

![DeepSeek 模型分组，视觉模型上带有「视觉」标记](/blog-assets/penguinharness-0-2-4-deepseek-vision-model-zh.png)

它是该分组里唯一具备视觉能力的模型，这会改变一次会话处理图片的方式。纯文本模型要把图片交给 `vision_model` 代理，由 `describe_image` 转述成一段文字再递给 agent；而运行视觉模型的会话直接读图——中间既没有代理，也没有那段转述。

该模型同时上架 OpenRouter，按该网关的公开价格计费。两条记录都采用 DeepSeek 的**非高峰**档，与既有记录同一口径：北京时间 9:00–12:00 与 14:00–18:00 的计费正好翻倍，而成本中心只按一个费率计算，因此高峰时段的用量会被低估一半。

同一版本还把第一方 DeepSeek 客户端从 Chat Completions 切到 OpenAI Responses API，base URL 的协议提示也随之改变。

![模型弹窗的 base URL 字段，协议提示显示 /responses](/blog-assets/penguinharness-0-2-4-model-protocol-hint-zh.png)

如果你把 `deepseek-v4*` 条目指向的不是 DeepSeek 官方端点，这是一处破坏性变更——见下方[升级须知](#升级须知)。

模型库的其他变化：`claude-opus-5` 进入 Anthropic 直连分组；新增分组弹窗可以直接导入某个端点的完整模型列表，不必一个个手敲 id；由环境变量提供 key 的模型终于被算作「已配置」——不再被「显示未配置 key 的模型」过滤器藏起来，凭据引导也不再反复提醒。

## 工作区变成可以自己编排的

对话页原先是抽屉式侧边面板加一套独立的终端窗格系统，两者各有各的规则。现在两者都没了。所有侧边元素——子智能体面板、工作区文件面板、记忆、新增的轨迹面板，以及任意多个终端——都成了两个 Dock（一个在右侧、一个在底部）里的可关闭标签页。

![对话页：右侧 Dock 显示智能体、记忆与工作区标签，底部 Dock 里是一个终端](/blog-assets/penguinharness-0-2-4-dock-tabs-zh.png)

任何一项都可以放进任一 Dock。把标签拖过去，按这项任务真正需要的方式分配注意力，这套编排会跟着对话保留下来。

终端是真正的服务端 shell，和其他所有内容共用同一条标签栏。

![底部 Dock 中的实时终端，显示 git log 输出](/blog-assets/penguinharness-0-2-4-dock-terminal-zh.png)

## 耗时命令不再堵住对话

耗时数分钟的命令不再占住这一轮。它转入后台，agent 继续往下走，命令结束时由 Harness 注入一份完成回报——模型不必轮询就能知道结果。配套提供了终止工具；开了端口的进程还会直接给出访问链接。

![后台进程行：命令、pid、localhost 链接与停止按钮](/blog-assets/penguinharness-0-2-4-background-process-zh.png)

与之配套的是 Project 级的**沙箱命令策略**：用正则规则在 shell 命令执行前拦下它，两个 shell 入口都会检查，且无论审批模式本来允许什么都一律拒绝。它是防误操作的护栏，不是安全边界——运行时拼装出来的命令仍可能绕过某条模式。

## 成本中心读起来是一整页

原先的用量页是四个小部件，在四个不同的时间窗里回答四个不同的问题。现在只有一条时间轴，页面上每张图都画在它上面。

![成本中心：时间范围预设，以及带缓存命中率曲线的 Token 图](/blog-assets/penguinharness-0-2-4-usage-range-zh.png)

你选一个范围——最近一小时、最近 24 小时这样的滚动窗口，最近 7 / 30 / 90 天这样的自然日预设，或者一对自定义日期——精度完全由范围决定：按分钟、按小时、按天、按周或按月。不存在第二个需要与第一个保持同步的控件。

占比饼图与按模型的进度条被两张并排的图取代，一张按 Agent 拆分，一张按模型拆分。每个时间桶的请求数是一根对着左轴的堆叠柱；每个实体的成功率是一条对着右侧百分比轴的虚线，颜色与它的柱段相同。

![按 Agent 与按模型的「请求数与成功率」两张图并排，各自带图例](/blog-assets/penguinharness-0-2-4-usage-agent-model-zh.png)

两种拆分同时在屏幕上——没有需要来回切换的维度开关，也没有一上来就给你一个说明不了任何问题的汇总总量。用量前四的实体各占一种通过色觉校验的色相，其余折叠成一条中性序列，标签里写明折叠了多少个。悬停某个柱段、某条成功率曲线或某个图例项，都会把该实体单独提出来、其余淡化。

Token 图保留三段式堆叠柱，并新增缓存命中率作为一条画在自己百分比轴上的虚线——想知道某一天的花费为什么是那个数，通常看它最快。

## 这一版还有

- **记忆**：文件摘要下方新增变更列表与并列的记忆侧栏；记忆分组可以整组导出导入；提示词也明确了**何时**值得记——同一诉求被再次提出、能超出本次任务的纠正、反复讲到的习惯——拿不准时就直接问。
- **设置**：合并为一个系统设置弹窗；解释性文字收进带圈问号，不再每次进来都占着屏幕；必填字段统一了标记方式。
- **新对话页**：新增音乐节奏游戏、对话式投资 Copilot，以及一整个定时任务示例分类。点击示例现在是填入输入框而不是直接发送，你可以先读、先改再发出；也可以把自己常用的提示词存成快捷指令，按用户存在服务端，换台机器依然还在。
- **MCP Server** 支持按服务器单独设置权限。
- **桌面端**：安装包改由 bundle 构建而非组装依赖树；GUI 启动会导入登录 shell 的环境变量；终端所需的原生模块重新随包发布；客户端更新入口移到账号菜单。

## 升级须知

这一版有五处需要你做一次判断，而不是升级完就没事了。

**DeepSeek 切到 Responses 协议。** id 含 `deepseek-v4` 且未设置 `client_type` 的条目，会仅凭 id 被路由到 DeepSeek 客户端，而该客户端现在请求 `{base_url}/responses`。指向 `https://api.deepseek.com` 的条目不受影响——DeepSeek 两种协议都提供。指向只提供 Chat Completions 的端点（自建服务、中转、第三方 DeepSeek 兼容网关）的条目升级后会开始失败：在 `.project_config.toml` 里或通过模型页的协议选择器，把它设为 `client_type = "openai-chat"` 即可。

**模型库的新条目不会自动出现。** 预置模型是在创建 Project 时复制进 `.project_config.toml` 的，此后不再被改写。在模型页点**同步预置**即可补入新模型：它只做追加与更新 catalog 所属字段，绝不会动你保存的默认模型。

**`GET /usage` 的返回结构变了。** `trend`、`byAgent`、`success` 已移除，改为 `series`、`byAgentSeries` 与 `byModelSeries`。原先 `success` 携带的按状态失败明细没有替代项。

**已保存的终端 Dock 布局不会迁移。** Dock 会有一次以关闭状态启动；正在运行的 shell 仍可从任一 Dock 的「+」菜单找回。

**`agent-creation` 技能更名为 `agent-initialization`。** 新名字说的是它实际做的事——初始化一个 Agent 的设置，而不是「创建 Agent」。已安装的旧副本仍可使用，但不再对应技能库里的任何 Skill，因此不会再收到更新。请安装 `agent-initialization`，在该 Agent 的技能标签页删除 `agent-creation`，并把手工点名旧名字的地方一并改掉：旧名字不会报错，只会静默地什么都匹配不到。

每一项改动的完整细节见 [`changelog/0.2.4/`](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.4)。
