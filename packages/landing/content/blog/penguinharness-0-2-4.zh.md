PenguinHarness 0.2.4 发布了。这一版加入了一个能读图的 DeepSeek 模型，把对话页的侧边面板和终端变成右侧栏和下侧栏里的标签页，由你自行摆放；耗时的命令转入后台运行，成本中心也围绕同一个时间范围重建。升级时有五处改动需要你做判断，列在文末的「升级须知」里。

## DeepSeek 新增视觉模型

AgentHub 0.4.6 把 `deepseek-v4-flash-vision-exp` 带进了模型目录。它在 V4 Flash 文本能力的基础上增加了图片输入，保留 1M 上下文窗口，价格与 V4 Flash 相同。

![DeepSeek 模型分组，视觉模型上带有「视觉」标记](/blog-assets/penguinharness-0-2-4-deepseek-vision-model-zh.png)

它是 DeepSeek 分组里唯一支持视觉的模型，这会改变会话处理图片的方式。纯文本模型要把图片交给 `vision_model` 代理，由代理用 `describe_image` 逐张描述，再把一段文字交给 Agent。使用视觉模型的会话则直接读图，中间既没有代理，也没有转述这一步。

这个模型同时上架了 OpenRouter，按该网关公布的价格计费。两条记录都采用 DeepSeek 的非高峰档价格，与已有记录的口径一致。北京时间 9:00–12:00 和 14:00–18:00 的用量价格正好翻倍，而成本中心只按一个费率计算，所以高峰时段的用量会少算一半。

同一版本还把第一方 DeepSeek 客户端从 Chat Completions 切换到了 OpenAI Responses API，模型弹窗里 base URL 的协议提示也随之改变。

![模型弹窗的 base URL 输入框，协议提示显示 /responses](/blog-assets/penguinharness-0-2-4-model-protocol-hint-zh.png)

如果你的 `deepseek-v4*` 条目指向的不是 DeepSeek 官方端点，这就是一处破坏性变更，处理方法见文末的「升级须知」。

模型目录的其他变化：

- `claude-opus-5` 加入 Anthropic 直连分组。
- 新增分组的弹窗可以一次导入某个端点的完整模型列表，不必再逐个输入 id。
- 密钥来自环境变量的模型，现在也算作已配置。它不会再被**显示未配置 key 的模型**这个过滤器藏起来，凭据引导也不再提示它。

## 侧边面板和终端都变成了标签页

对话页原来的抽屉式侧边面板，以及那套独立的终端窗格，都已经移除。现在每个侧边元素都是一个可以关闭的标签页，放在右侧栏或下侧栏里。子 Agent 面板、Workspace 文件面板、记忆、新增的 Trace 面板，以及任意多个终端，都是这样的标签页。

![对话页：右侧栏里有智能体面板、记忆和工作区标签页，下侧栏里是一个终端](/blog-assets/penguinharness-0-2-4-dock-tabs-zh.png)

标签页放在右侧栏还是下侧栏都可以。按任务的需要把标签页拖过去，这套布局会跟着会话保存下来。

终端是真正在服务端运行的 shell，和其他标签页共用同一条标签栏。

![下侧栏里的实时终端，显示 git log 输出](/blog-assets/penguinharness-0-2-4-dock-terminal-zh.png)

## 耗时命令不再卡住对话

要跑好几分钟的命令，不会再占住当前这一轮。它转入后台运行，Agent 继续往下做。命令结束时，Harness 会注入一份完成报告，模型不用轮询就能知道结果。Agent 可以用终止工具停掉后台命令；开了端口的进程还会附上一个直达链接。

![后台进程行：命令、pid、localhost 链接和停止按钮](/blog-assets/penguinharness-0-2-4-background-process-zh.png)

## Shell 命令策略

每个 Project 现在都有一套沙箱命令策略：用正则规则在 shell 命令执行前把它拦下。两个 shell 入口都会检查这些规则，而且不管审批模式原本是否放行，命中规则的命令一律拒绝。新建的和已有的 Project 都自带一小套默认规则，会拒绝 `rm -rf` 这类破坏性命令，全部放行模式下也不例外。你可以在 **Project 设置** › **安全策略**里编辑或停用某条规则，也可以关掉整套策略。

这套策略是防止误操作的护栏，不是安全边界。运行时才拼出来的命令，仍然可能绕过规则。

## 成本中心围绕同一个时间范围重建

用量页原先是四个小部件，在四个不同的时间窗里回答四个不同的问题。现在页面上的每张图都画在同一条时间轴上。

![成本中心：时间范围预设，以及带缓存命中率曲线的 Token 图](/blog-assets/penguinharness-0-2-4-usage-range-zh.png)

先选一个时间范围：最近 1 小时或 24 小时、最近 7 天、30 天或 90 天（按自然日计），或者一对自定义日期。精度完全由范围决定，分为按分钟、按小时、按天、按周和按月。不存在第二个需要和它保持同步的控件。

占比饼图和按模型的进度条，换成了两张并排的图：一张按 Agent 拆分，一张按模型拆分。每张图里，每个时间桶的请求数画成一根堆叠柱，对应左侧坐标轴；每个实体的成功率画成一条同色虚线，对应右侧的百分比轴。

![按 Agent 与按模型拆分的请求数和成功率，两张图并排，各带图例](/blog-assets/penguinharness-0-2-4-usage-agent-model-zh.png)

两种拆分同时显示在屏幕上，不需要来回切换维度，两张图也都不会一打开就给你一个说明不了问题的汇总数。用量前四的实体会单独列出名字，各用一种经过色盲友好校验的颜色；其余实体合并成一条中性色的序列，标签上写明合并了几个。鼠标悬停在某个柱段、某条成功率曲线或某个图例项上，这个实体就会突出显示，其余的变淡。

Token 图保留三段式柱状图，并新增一条缓存命中率虚线，画在它自己的百分比轴上。想弄清某一天为什么花了那么多钱，通常看这条线最快。

## 这一版还有

- **记忆**的变更现在列在文件摘要下方，记忆也有了自己的侧边面板，和其他面板并列。记忆分组可以整组导出、导入。记忆提示词现在写明了哪些信息值得记下来：重复提出的请求、在 Task 结束后仍然成立的纠正、不止一次提到的习惯。拿不准时，Agent 会直接问你。
- **设置**合并成了一个**系统设置**弹窗。说明文字收进了带圈的「?」里，不再每次打开都占着屏幕；必填字段也统一了标记方式。
- **新对话页**新增了节奏游戏示例、对话式投资 Copilot，以及一个定时任务示例分类。现在点击示例只会把内容填进输入框，不会直接发送，你可以先看、先改。你还可以把自己常用的提示词存成快捷指令。快捷指令按用户保存在服务端，换一台机器也还在。
- **MCP Server** 支持按服务器单独设置权限。
- **桌面应用**的安装包改为基于 bundle 构建，不再组装依赖树。从图形界面启动时会导入登录 shell 的环境变量，终端所需的原生模块重新随安装包提供，客户端也可以从账号菜单里更新。

## 升级须知

这一版有五处改动需要你做判断，不是升级完就没事了。

- **DeepSeek 改用 Responses 协议。** id 中含有 `deepseek-v4`、且没有设置 `client_type` 的条目，会按 id 路由到 DeepSeek 客户端，而这个客户端现在请求的是 `{base_url}/responses`。指向 `https://api.deepseek.com` 的条目不受影响，因为 DeepSeek 两种协议都支持。如果条目指向只支持 Chat Completions 的端点，比如自建服务、中转服务或第三方 DeepSeek 兼容网关，升级后就会开始报错。给它设置 `client_type = "openai-chat"` 即可，可以写在 `.project_config.toml` 里，也可以用模型页的协议选择器。
- **模型目录的新条目不会自动出现。** 预置模型只在创建 Project 时复制进 `.project_config.toml`，之后不会再被改写。要用上新模型，请在模型页点击**同步预置**。它会补入缺少的条目，更新由模型目录管理的字段，并且不会改动你保存的默认模型。
- **`GET /usage` 的返回结构变了。** `trend`、`byAgent` 和 `success` 已移除，改为 `series`、`byAgentSeries` 和 `byModelSeries`。原先 `success` 里按状态拆分的失败统计，没有替代项。
- **已保存的终端侧栏布局不会保留。** 升级后侧栏会先以关闭状态启动一次。正在运行的 shell 仍然可以从任一侧栏的「+」菜单里找回。
- **`agent-creation` Skill 更名为 `agent-initialization`。** 新名字说的是它实际做的事：初始化一个 Agent 的设置，而不是创建 Agent。已经安装的旧副本仍然可以用，但它不再对应技能库里的任何 Skill，所以不会再收到更新。请安装 `agent-initialization`，在该 Agent 的**技能**标签页里删除 `agent-creation`，并手动修改所有写死了旧名字的地方：旧名字不会报错，只会什么都匹配不到。

每一项改动的完整细节见 [`changelog/0.2.4/`](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.4)。
