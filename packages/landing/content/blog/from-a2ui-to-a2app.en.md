> Written for PenguinHarness 0.2.16. Later releases may differ in some details.

Google's open A2UI project changed human-AI interaction by moving structured interactions out of plain text and into chat replies.[^1] PenguinHarness ships A2UI blocks modelled on that approach, rendered inline from a trusted component catalog.[^2][^3][^4]

![PenguinHarness chat reply showing a rollout flowchart with Show source, a three-step preparation block with a caution and note, and an unanswered canary traffic choice with options 5% Recommended, 25%, Skip the canary, and Other…](/blog-assets/penguinharness-0-2-14-a2ui-blocks-en.png)
_PenguinHarness's A2UI blocks, modelled on A2UI, render pre-approved catalog components inline in a reply; diagrams use a standard Mermaid fence._

A2APP is our name for this pattern, not a standard. It moves interaction to dedicated software. In PenguinHarness, we implemented A2APP as the agent workbench. It is a job-specific app beside chat that calls its agent turn by turn, edited by the same agent when asked.[^5]

## What A2UI solved, and what it left
Google's stated goal for A2UI was UI safe like data, but expressive like code: agents only name pre-approved catalog components and send no executable code.[^1]

PenguinHarness's A2UI blocks follow that model, but do not implement Google's protocol.[^3][^4] The client renders catalog components from agent-supplied fields; the agent never sends HTML, scripts or styles.[^2][^6]

Selections fill the composer; nothing sends until the user presses Send.[^7][^8] Only the latest main conversation reply accepts input; older blocks are read-only.[^7] Weather and metrics are static model snapshots — the client fetches no data.[^2][^9] Blocks handle inline choices and steps, but stop at reply edges.

Vibe coding sits opposite, producing standalone apps. Karpathy coined the term in early 2025 for unreviewed code, fine for throwaway weekend projects.[^10][^11] He later found local demos easy, but deployed real apps a slog.[^12] A2UI blocks, vibe-coded apps, and A2APP workbenches split along four dimensions.

## The workbench as A2APP

In PenguinHarness, a workbench is a small app tied to one agent. It lives in that agent's folder, opens as a tab beside Chat, and works before any chat message is sent.[^5][^13] The Contract desk for a legal agent is a typical example: an upload area and file status table built for that single contract review job.[^5]

![The Contract desk workbench open in a tab next to Chat, showing an upload prompt and file status table for contract reviews.](/blog-assets/workflow-page-en.png)
_A workbench appears as a dedicated tab beside its agent's chat, with a custom interface built for one specific job._

Workbench server code runs in the main server process with no sandbox.[^14] Sessions it starts run in allow-all mode, so no step waits for a person's approval.[^14][^15] The server calls the agent over a narrow, fixed host API.[^16]

The agent never sees the page or the person's clicks.[^14][^16] It receives only the text the server sends, turn by turn.[^14][^16] The server polls for a snapshot of the agent's final result to update the page state.[^13][^16]

Two loops run side by side: the task loop the page starts through the server, and the edit loop asked for in the Chat tab.

## Using and changing the app in one place

You work directly in the custom workbench interface, while the agent handles the tasks the app sends it and changes the app when asked. If the Contract desk is missing a Risk column, ask for it in the adjacent Chat tab.[^5] The same agent edits the workbench's plain HTML, CSS and JavaScript files.[^5][^13][^17] The server type-checks backend TypeScript, hot-reloads the open tab on success, and keeps the last working version if edits fail.[^5][^18] There is no build step and nothing to install.[^13][^17] Every successfully loaded revision is saved to History, up to 20 entries.[^5][^19]

![The workbench History panel open, listing two saved revisions above the updated Contract desk which now includes a Risk column.](/blog-assets/workflow-history-en.png)
_Edits requested in Chat update the workbench files, with recent loaded revisions kept in the History panel; Restore rolls back code, not saved data._

In vibe coding, the AI's part ends once the code is written. In a workbench, the same agent stays to run the app's work and adjust the interface when asked.

## A concrete starting point

MCP Apps, Claude artifacts, Opal mini-apps, and Patchwork all explore agent-connected interfaces.[^20][^21][^22] Our choice is to tie each app directly to the single agent that can modify it, via a narrow host API for turn-by-turn work calls.[^16]

In PenguinHarness 0.2.16, the start page lists three one-sentence starters under **Build an AI app from one sentence**.[^23][^24] Each creates a dedicated agent with its own workbench: a RAG docs expert, an investment analyst, and a legal agent.[^23][^24] A new Project's default agent ships with the three required builder Skills preinstalled.[^13][^25] No separate deploy step or external hosting is required to open or edit the resulting A2APP.

To try it, create a new Project, select the legal agent starter, open the agent, start a new chat, and select its workbench tab.[^23][^24]
