> Written for PenguinHarness 0.2.16. Later releases may differ in some details.

A2UI moved small, structured interactions out of plain text and into chat replies. Agents send fields for pre-approved blocks, and the client draws them inline: flow diagrams, numbered steps, and choice prompts, instead of only text.

![PenguinHarness chat reply showing a rollout flowchart with Show source, a three-step preparation block with a caution and note, and an unanswered canary traffic choice with options 5% Recommended, 25%, Skip the canary, and Other…](/blog-assets/penguinharness-0-2-14-a2ui-blocks-en.png)
_PenguinHarness's A2UI blocks, modelled on A2UI, draw structured choices, steps and diagrams inline in one reply from pre-approved catalog components._

A2APP, our name for this pattern, moves that shift to dedicated software. **In PenguinHarness, A2APP is the agent workbench: a job-specific app beside an agent's chat that calls the agent turn by turn,** and that the same agent edits when asked in Chat.

**TL;DR**
- A2UI blocks put trusted, structured widgets directly in chat replies.
- PenguinHarness workbenches pair one agent with a tab the same agent edits, calling it turn by turn.
- In vibe coding the AI stops after writing code; workbenches keep that agent working for the app.

## What A2UI solved, and what it left
The path to workbenches began with Google's A2UI project, announced late 2025, proposing declarative client-drawn UI from a trusted catalog, as safe as structured data[^1]. PenguinHarness's A2UI blocks follow that model but do not implement Google's protocol; agents send only component fields, never code, scripts or styles.

Block selections fill the composer; nothing sends until the user presses "Send"[^2]. Only the latest main-conversation reply accepts input; older blocks render read-only. Weather and metrics are static model-supplied snapshots; the client fetches nothing. **These blocks handle choices, steps and diagrams in one reply, stopping at the reply edge**.

Vibe coding crosses that edge, producing standalone apps separate from chat. Karpathy coined the term in early 2025 for coding where you accept all AI changes without reading code, fine for throwaway weekend projects[^3]. He later noted the style works for local demos but becomes a slog for deployed real apps.

## The workbench as A2APP
**A PenguinHarness workbench is a small app for one agent, stored in its folder, that opens as a tab beside "Chat"** instead of a separate deploy. The Contract desk for a legal agent is a typical example: an upload area and file table for reviews, built for that job[^4].

![The Contract desk workbench open in a tab next to Chat, showing an upload prompt and file status table for contract reviews.](/blog-assets/workflow-page-en.png)
_A workbench appears as a dedicated tab beside its agent's chat, with a custom interface built for one specific job._

These are current limits: Workbench server code runs inside the server process with the server's permissions, no sandbox around it or its same-origin page[^5]. Sessions a workbench starts run in `allow-all` mode, so no step pauses for user approval.

The workbench server calls its agent over a narrow, fixed host API[^6]. The agent never sees the page or user clicks; it receives only text the server sends, turn by turn. The server polls for a snapshot of the agent's final result to update page state.

## Using and changing the app in one place
The same agent that runs the app's tasks edits its files when asked. If the Contract desk is missing a risk column, the person asks for the change in the "Chat" tab beside the workbench. The agent edits the workbench's plain HTML, CSS and JavaScript files directly. The server type-checks the TypeScript backend, and the open tab reloads automatically when changes pass, with no build step or extra install required[^7].

Every workbench version that loads successfully is saved, up to 20 recent revisions, listed in the "History" panel. A user can select "Restore" on an older version if an edit misses the mark, which rolls back code without touching saved work data[^8].

![The workbench History panel open, listing two saved revisions above the updated Contract desk which now includes a Risk column.](/blog-assets/workflow-history-en.png)
_Edits requested in Chat update the workbench files, with recent loaded revisions kept in the History panel; Restore rolls back code, not saved data._

In vibe coding the AI's part ends once the code is written; **with a workbench the same agent keeps working for the app and changes it when asked**.

## A concrete starting point
Other teams have explored pieces of this pattern before us, where an agent works for its app. MCP Apps render sandboxed interactive UI from tools, Claude artifacts run small apps that call back to Claude, Opal lets users build AI mini-apps in natural language, and Patchwork generates malleable tools from chat[^9]. Our implementation ties the app directly to the single agent that can modify it, using a narrow host API for turn-by-turn work calls.

In PenguinHarness 0.2.16, the start page lists three one-sentence starters under "Build an AI app from one sentence": a RAG docs expert, an investment analyst, and a legal agent. **Each starter creates a dedicated agent with its own workbench, and a new Project's default agent already has the builder Skills it needs**[^10].

To try it, create a new Project, select the legal agent starter, open the agent, start a new chat, and select its workbench tab.
