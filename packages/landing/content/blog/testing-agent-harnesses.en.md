> Written for PenguinHarness 0.2.16. Later releases may differ in some details.

A prompt-cache regression throws no error, leaves output unchanged, passes standard CI, and only moves the bill.[^1][^2]

All token counts, ratios and costs come from an offline Anthropic cache-rule simulator over recorded fixtures, not live providers.[^3][^4]

Cited run times come from a 2026-10-19 suite run on our test machine.[^5]

This post covers the CI check design, using PenguinHarness's prompt-cache suites as the worked example.

**TL;DR**
- On 2026-10-19, 33 prompt-cache tests ran in 1.54 s with no network or keys.[^5]
- Reverting the compaction thinking-level fix fails two tests; estimated compaction cost rises 1.13× to 10.2× depending on interim work.[^5][^6]
- A 49-character system prompt edit shifts hit ratio from 88.61% to 88.62% while the invariant holds.[^5]

## The silent regression no test caught

Providers serve a cached prefix only when consecutive requests match byte for byte from the front.[^1][^7][^8]
Everything from the earliest divergence onward is re-read at full price on that request; requests that still extend their predecessor keep hitting.[^1]

These regressions leave no functional signal.[^1][^2]
No error is thrown, UI output stays the same, and standard CI checks pass as soon as expected numbers are edited.[^1][^2]
Uncaught, they ship.[^1]

A small request assembly change can pass every default check while raising per-request cost.[^1]

## The invariant we hold to
Our check rests on one invariant.

Every follow-up request in a context must read back the full prefix of that context's prior request.[^9]

The simulator scores cache hits against a fixed ordered block list.[^3]
Any early divergence invalidates all later blocks up to the harness's single automatic breakpoint.[^3][^7]

These blocks run from model ID through conversation messages to the cache breakpoint, in the order below.

## The test pipeline end to end
We run unmodified Session, ContextEngine and GenerativeModel code.[^10]

Only the provider stream is replaced, so recordings hold exact wire bytes.[^11]

Scripted replies return zero cache-read tokens; the simulator models hits offline.[^11]

Two readers interpret recordings: one finds the earliest request divergence, the other applies Anthropic's documented rules to report expected cache reads.[^3][^12]

## Fake only the edge, not the system
The obvious cache test calls the live provider API.

Without cache diagnostics, live runs show only `cache_read_input_tokens` dropping to zero, no root cause.[^2] CI test jobs get no secrets, so live calls cannot run there.[^13]

We use the approved scripted MMSP client, running real harness code, replacing only the network stream.[^11][^14] Recordings hold exact wire bytes, not in-memory objects.[^11]

These suites run on Linux, macOS and Windows when CI selects core.[^13][^15][^16] The dev skill routes request-assembly changes there.[^1] On 2026-10-19 they ran 1.54 s on our test machine, no network needed.[^5] Tradeoff: the simulator cannot confirm live provider behavior.[^4]

## Bytes alone are not enough
A raw byte-equality check cannot judge cache behavior.

A request past the default 5-minute cache TTL can match its predecessor byte for byte.
The simulator still estimates a full miss: 0 tokens read, 2,041 estimated written.[^3][^5][^7]

A thinking-level change leaves tools and system prompt bytes identical.
With the harness's single automatic breakpoint, the simulator reads 0 tokens back and writes an estimated 1,719.
Extra tool and system breakpoints, a measured what-if, would recover the 1,656-token prefix.[^3][^5][^7]

The offline simulator applies documented provider rules to separate these cases, reporting standard usage fields.[^3]

The two checks differ on that thinking-level change.

## Assert an invariant, not a number
Pinning exact per-request token counts is the obvious design, and brittle.
A harmless 49-character system prompt edit shifts 10 of 20 per-request counts, leaves the prefix intact, and barely moves the simulated hit ratio.[^5]

We assert only the full prefix read-back invariant, with a bounded allow-list for by-design misses such as thinking-level moves, reopened contexts, and model switches.[^4][^9][^17]
Exemptions fail if hits resume, so stale entries cannot weaken the suite.[^9]
Failure reports name the request, diverged tier, and token shortfall, so the agent that broke the check can read the cause without help.[^1][^3][^12]
That leaves one clear rule for handling failures.

## Never re-baseline to green
When checks fail, re-baselining to green is easy. We never do.[^1]

Before #700 merged 2026-09-14, compaction used the context's opening thinking level for cache protection; user level moves left a mismatched prefix, so #700 switched it to the Session's current level. The suites arrived the next day, citing #700 as their reason.[^6][^18][^19]

A deliberate #700 revert fails two core tests: the invariants suite thinking-level move case, and the engine test #700 inverted. All other tests pass, lifecycle included.[^5][^6]

Under the #700 revert, compaction costs an estimated 1.13× shipped one task post-move, 10.2× after five tool tasks, at claude-sonnet-4-6 prices.[^5]
