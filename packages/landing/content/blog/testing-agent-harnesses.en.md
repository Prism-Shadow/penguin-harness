> Written for PenguinHarness 0.2.16. Later releases may differ in some details.

**Agent harnesses can break without throwing errors or changing visible output, raising user costs while standard tests pass**. The CI system that catches these breaks scripts only external edges, runs unmodified harness code between them, checks an invariant with a named allow-list instead of pinned numbers, and runs on every relevant change across OSes without API keys[^1]. This post uses PenguinHarness's prompt-cache suites as a worked example of this CI design, not a guide to prompt cache calculation.

**TL;DR**
- Silent prompt-cache regressions pass functional tests.
- 33 keyless cache tests run in 1.54 s; CI runs them across three OSes.
- A 49-character prompt edit breaks pinned checks but leaves the cache invariant intact.
- Reverting PR #700 raises 5-task compaction cost 10.2×, caught by two test failures.

## Silent harness regressions pass every standard test
**These prompt-cache breaks are the canonical silent harness regression**, triggered by small code changes that leave output identical, throw no errors, and produce no signal standard CI inspects[^2]. Every token count, ratio and cost here is an estimate from the suites' simulator over recorded fixture requests, priced at the catalog's `claude-sonnet-4-6` row. These suites run on our test machine (Node v24.20.0, vitest 3.2.7) with no network or API keys.

Our core design replaces only the outermost provider stream with a script, runs unmodified `Session`, `ContextEngine`, `GenerativeModel` code, and checks exact bytes sent to the provider against documented cache rules[^3]. Faking deeper in the stack would be easier, but it tests our assumptions about request shape, not the bytes the provider receives.

## Script only the edge, not the system under test
The obvious way to inspect those wire bytes is to run live provider calls in CI. That design fails for routine use. Live checks need API keys and network access, so they skip fork PRs where secrets are unavailable. They give no precise root cause for misses[^4].

**Our scripted edge replaces nothing inside the harness, only the provider byte stream**. It produces byte-identical requests across runs, requires no secrets, and completes 33 tests in 1.54 s[^5].

We accept one trade-off: the simulator models documented provider rules, not confirming live provider behaviour.

Because the check needs no key and runs fast, CI runs it on every core-touching change across Linux, macOS and Windows[^6]. Browser end-to-end tests follow the same edge-fake rule with their mock LLM endpoint. A release, shared file change, or missing comparison base runs full validation. One separate installer job holds a DeepSeek key for a live end-to-end step skipping fork PRs.

A check failing on harmless changes is useless.

## Assert an invariant, not a pinned number
The obvious check for those bytes is pinning token counts or hit ratios to known good values. That design fails exactly on harmless, intended changes. A trivial 49-character system prompt edit changes 10 of 20 per-request counts, breaking pinned checks despite nearly unchanged cache behaviour, with a simulated hit ratio shift from 88.61% to 88.62%[^7].

**Our invariant asserts only one rule: every request reads back the full prefix of the previous request**[^8]. Intentional, by-design misses sit on a short allow-list: thinking-level moves, reopened contexts, model switches. The list auto-fails if an entry no longer applies, closing the gap where stale exemptions could let regressions pass. Even a precise invariant fails if teams edit tests to hide failures.

## Fail loud, never re-baseline to green
That test-editing pattern, re-baselining, breaks cost checks: CI goes green when expected numbers are edited, with no other problem signal. PR #700 fixed a bug where compaction kept the opening thinking level after a user moved it, diverging its request prefix. PR #722 added the suites the next day to guard that fix[^9].

Deliberately reverting #700 fails exactly two core tests while all others pass. It raises estimated compaction cost 1.13× after one task and 10.2× after five tool-using tasks.

**Our rule is simple: never edit an expected value or add an allow-list entry to green a test**. That choice means deliberately spending user money, so it requires human sign-off. The revert fails loudly, placing its divergence tier and estimated cost directly in front of that person.

## This design works for any silent harness property
Silent, cost-impacting regressions like the compaction drift #700 fixed are not unique to prompt caching. **The same CI design applies to any harness property with no functional signal**. You do not need live provider access to check bytes your harness sends. Run suites locally with `pnpm --filter @prismshadow/penguin-core exec vitest run prompt-cache` from repo root, and read prefix-stability rule docs at <https://penguin.ooo/docs/agent-loop>[^10].
