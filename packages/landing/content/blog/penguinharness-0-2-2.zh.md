PenguinHarness 0.2.2 发布了。之前的版本为 Agent 配齐了干活的工具：文件工具、子 Agent、Skill 和定时任务。这个版本给它们加上了记忆：Agent 在一个会话里学到的东西，下一个会话还能接着用。这一版还加入了 MCP Server 支持、可编辑也可关闭的提示词区块，以及给 Agent 配置本身的版本标记。

## 记忆

每个 Agent 把长期笔记存在 `agent_state/memory/` 下，分两种作用域。用户作用域的内容，每个会话都会读取；Workspace 作用域绑定 Agent 工作的目录，关于某个项目的笔记不会混进另一个项目。临时 Workspace 没有自己的作用域，因为之后不会有会话回来读它。

只有 `MEMORY.md` 索引会进入上下文，每个作用域最多 200 行、25,000 字符，超出上限时会附上明确的截断说明。主题文件留在磁盘上，模型需要时再用普通的文件工具打开。

写入也是同样的方式。模型通过编辑文件来保存、合并自己的笔记，Harness 则把这些写入限制在记忆目录里。为此没有新增任何工具。

Agent 设置里多了一个**记忆**标签页，按作用域分组列出所有记忆。你可以查看某条记忆、删除它（对应的索引行会一并移除），也可以通过一段预填好的对话，让 Agent 自己来改。标签页底部还可以编辑两段记忆提示词。

记忆功能推出之前创建的 Agent 不受影响：模板里没有 `{{MEMORY}}` 占位符，就不会注入任何内容。标签页会指出这一点，并提供一键插入。

## MCP Server

Agent 现在可以使用 MCP（Model Context Protocol）服务器提供的工具。这项支持基于官方 TypeScript SDK v2，覆盖三种传输方式：stdio、Streamable HTTP 和旧式 SSE。

服务器的工具以 `mcp__<server>__<tool>` 的名字出现，沿用现有的执行和审批规则。服务器用 `readOnlyHint` 标记的工具获得只读权限。密钥保险柜里的值永远不会传给 MCP 服务器进程。

Agent 设置的**工具**标签页里，**MCP Server** 分区过去只以只读 JSON 展示配置，现在可以用表单管理服务器：添加、编辑、删除，还能当场测试连接。连不上的服务器会直接跳过并给出警告，不会卡住会话创建。服务器连接期间，对话里会以步骤行显示进度，你的第一条消息不会再无声无息地卡住。

这是本版唯一的破坏性变更：工具集记录从 `session_meta.tools` 移到了新的 `tool_list_ready` 事件。变更之前写下的 Trace 不再显示其中内嵌的工具记录。

## 可编辑、可关闭的提示词区块

记忆注入提示词的方式，现在也用到了另外三个会往系统提示词里加内容的子系统上：密钥保险柜、技能和定时任务。这三部分在系统提示词模板里只保留 `{{VAULT}}`、`{{SKILLS}}` 和 `{{SCHEDULES}}` 三个占位符。每个占位符展开为一段随 Agent 保存的提示词，可以在对应标签页的底部编辑，标签页顶部则有一个启用开关。

开关只决定模型能看到什么。关掉某个区块，它就从系统提示词里消失，但功能照常运转：密钥保险柜的值仍以环境变量的形式传给 shell 子进程，已安装的 Skill 仍可显式调用，定时任务也照样准时触发。

### 在对话里安排定时任务

定时任务的默认提示词是新写的。它教模型用文件工具管理 `agent_state/schedule/` 下的 TOML 文件。提示词写明了字段规则、最短五分钟的周期、服务端大约三十秒内就会载入改动，还附上了现有任务的列表。现在你可以在对话里说一句「每天早上九点跑一遍测试套件」，模型会自己把文件写好。

### 已有 Agent

已有 Agent 在创建时就把旧模板的各个区块固化了进去，这些模板照旧可用。原版措辞没有改动过的，标签页提供一键迁移到占位符写法；手动改过的区块保持不动。

## Agent 配置的内核版本

Agent 的 `system_config.yaml` 在创建时就固定下来，绝不会在背后悄悄升级。这让行为可以预期，但在此之前，新的默认值也只有新 Agent 才用得上。

0.2.2 给每份配置打上内核版本：一个日期，记录这份配置出自哪一代内置默认值。创建或还原配置时写入这个标记，日常编辑不会动它。CI 里有一个守卫测试，只要默认值变了而日期没有更新，测试就会失败，所以这个标记不会落后。

Agent 概览页上，**更新内核**现在就在**还原为默认配置**旁边。它会逐个字段合并：

- 仍与某一代已记录的默认值一致的字段，更新为新的默认值。
- 自定义过的字段保留，并以可读的名称列出。
- 来源不明的值稳妥起见也保留。

想彻底重置时，**还原为默认配置**仍然可用。

## 核心运行时

`max_turns` 的默认值现在是 -1，即不限轮次。请求上限和压缩阈值改为根据模型的上下文窗口推算，小窗口的 vLLM 类部署不再需要手工调参。

LLM 重试阶梯现在从 2 秒起步，除凭证验证失败外，所有失败都会重试。

Trace 的追加写入现在串行执行，每条记录一次 `write(2)`；恢复会话时，会修复崩溃时写坏的文件末尾。大记录不会再在 512 KiB 的分块边界处断成两截。部分用户偶尔遇到的 Trace 损坏，根源就在这里。

## 桌面应用与 Web App

桌面应用在各个平台都换上了企鹅品牌图标，Task 结束时会发出系统通知，有了明确的单用户模式，还自带可以在 PATH 中直接调用的 `penguin` CLI。

管理员多了一个**代理选项**对话框：应用和 Agent 环境各有自己的开关，共用同一个代理地址；地址留空时跟随系统代理，回环流量始终不走代理。

Web App 积累了一个月的修复，值得一提的有：

- 对话头部的统计收进一张详情卡片，会话 id 点击即可复制，卡片里还列出后台进程，每个进程的**停止**按钮都能正常使用。
- 输入框里有没发出去的文字时新建对话，这段文字会以草稿的形式留在侧栏。
- 初始密码横幅可以永久关闭。
- 点击已锁定的模型标签，现在只提示**输入 /model 切换模型**。
- Agent 详情页的标签顺序定为**概览**、**系统提示词**、**运行参数**、**工具**、**技能**、**记忆**、**密钥保险柜**和**定时任务**，Agent 列表里的统计图标也按同样的顺序排列。
- Agent 概览页改为用分隔线分节的排版，Agent State 路径可以直接复制。
- 共用的开关组件点击后不再残留灰色光晕。
- 离开正在运行的对话时，整个应用不会再闪烁。

## 其余改进

- 模型目录新增 Thinking Machines Lab 的 Inkling（上架 OpenRouter 和 Fireworks AI），以及 Fireworks AI 上的 DeepSeek V4 Flash 0731。GLM-5.1 的网关条目已移除，Z.AI 直连条目保留。OpenRouter 的价格按它的 models API 重新刷新。
- 技能库新增 `humanizer`：一个需要手动安装的 Skill，用来去除各种语言文字里的机器写作痕迹。
- 依赖覆盖把 `@hono/node-server` 强制升到 2.0.5 或更高，以修复一则路径穿越安全通告：问题出在 Windows 上的 `serve-static`，有漏洞的版本经由 MCP SDK 间接引入。`nanoid` 也强制升到 3.3.17 或更高。现在 `pnpm audit` 没有任何需要报告的问题。
- 发布工作流会拒绝版本号与仓库不一致的 tag。

完整清单见 [changelog/0.2.2](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.2)。

## 安装或升级

桌面应用：到 [penguin.ooo/download](https://penguin.ooo/download) 下载对应平台的安装包。从这个版本起，macOS 安装包已签名并完成公证，Gatekeeper 会直接放行。这一版的 Windows 安装包仍未签名：在 SmartScreen 里选「更多信息 → 仍要运行」。

CLI / 服务端：

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows 上请在 PowerShell 中运行 `irm https://penguin.ooo/install.ps1 | iex`。Node >= 24 的环境也可以用 `npm install -g @prismshadow/penguin-cli` 安装。在 Linux 和 macOS 上升级已有安装，运行 `penguin update` 即可。
