有些工作必须在另一台电脑上完成，通常是存放数据的那台。PenguinHarness 0.2.15 可以把自己安装到服务器能通过 ssh 访问的机器上，保持连接，并在机器上运行会话。窗口始终在你自己的服务器上，只有与这台机器相关的调用才会经过这条连接。

本教程添加一台名为 `devbox` 的 Linux 机器，然后让 Agent 在其中一个文件夹里跑一次检查。

## 前提条件

- PenguinHarness 0.2.15，以管理员身份登录。**机器管理**页面及其所有内容仅管理员可用。
- 一台 Linux 或 macOS 机器，服务器的操作系统账号能通过 ssh 登录这台机器：可以用密钥（在服务器的终端里执行 `ssh <host>`，不提示输入任何内容就能连上），也可以用保存在 PenguinHarness 里的密码。目前还不能连接 Windows 机器。基于 musl 的 Linux 系统（如 Alpine）不受支持。
- 只要求 ssh 可达。机器会从 GitHub 或 OSS 镜像下载安装包。两边都连不上，或者机器上没有 `curl` 时，服务器会通过 ssh 连接把安装包传过去。
- **模型库**页面上要有一个模型，并且密钥已保存在 Project 里。服务器从环境变量读取的密钥不会复制到机器上。

## 第 1 步：添加机器

1. 在侧边栏选择**机器管理**，然后选择**添加机器**。
2. 选择**手动填写**，填入**名称**、**主机地址**和**用户名**。这个名称会成为这台机器的 ssh 别名。把**私钥文件**留空，就会使用 ssh 的默认密钥。
3. 让**添加后立即安装并连接**保持勾选，然后选择**添加**。

![添加机器对话框，名称、主机地址和用户名已填好](/blog-assets/machines-add-dialog-zh.png)

对话框会在服务器的 `~/.ssh/config` 里追加一个 `Host` 块，所以在服务器的终端里 `ssh devbox` 也能连上：

```text
# Added by PenguinHarness on 2026-10-12T17:04:24.886Z
Host devbox
  HostName 172.17.0.6
  User penguin
  Port 22
  StrictHostKeyChecking accept-new
```

已经在这个文件里的主机，会出现在**从 ssh 配置选择**标签页里。

## 第 2 步：等待安装完成

机器的卡片上有一条进度条，每个步骤占一段，下方一行文字标明当前步骤。机器对话框里列出的步骤依次是**检查机器**、**安装程序**、**传送构建**、**重启服务**、**建立连接**和**同步配置**。如果服务器是从源码仓库运行的，步骤会从**构建安装镜像**开始。

![安装过程中的 devbox 卡片，正处于「安装程序」这一步](/blog-assets/machines-installing-zh.png)

程序装到机器的 `~/.penguin`，数据在 `~/.penguin/data`。服务监听在机器回环地址的 7364 端口上，你的服务器通过 ssh 连接访问这个服务。最后一步会把 Project 的配置下发给机器：模型、默认模型、命令策略、新对话默认设置和插件列表。

## 第 3 步：确认连接

安装完成后，卡片上的圆点会变蓝。点击卡片打开对话框，里面显示地址、数据目录，以及远程服务是否在运行。

![机器管理页面，本服务器和 devbox 都已连接](/blog-assets/machines-page-zh.png)

![devbox 对话框：已连接，显示地址、数据目录和远程服务端口](/blog-assets/machines-detail-zh.png)

在对话框的工具栏里可以**停止服务**、**重启服务**、**同步配置**、**配置 SSH**或**卸载**。这个页面不用一直开着：服务器会保持与机器的连接，会话断开或重启之后会自动重连。

## 第 4 步：在机器上打开 Workspace

1. 选择**新建对话**，再点消息框下方的文件夹按钮。还没选文件夹时，按钮上显示**临时工作区**。
2. 在**机器**下选择 `devbox`。此时选择器浏览的就是这台机器的文件夹。
3. 找到要工作的文件夹，选中后点击**选择**。

![Workspace 选择器正在浏览 devbox，已选中 etl 文件夹](/blog-assets/machines-workspace-zh.png)

卡片上的**使用**按钮是个快捷方式：打开一个新对话，Workspace 设为这台机器上的临时 Workspace。

## 第 5 步：在机器上运行 Agent

发一条消息。运行 Agent 的是机器自己的服务，所以每条命令都在机器上执行。消息、Trace 以及你打开的终端也都存放在那边。侧边栏会把这个会话归到对应的文件夹和机器下面，显示为 `etl [SSH: devbox]`。

![devbox 上 etl 中的会话：命令打印出了 devbox 和检查结果，Agent 报告有一个文件存在问题](/blog-assets/penguinharness-0-2-14-machines-zh.png)

## 限制

- Agent 从属于各自的服务器。在一台机器的 Workspace 里，Agent 选择器列出的是那台机器上已有的 Agent。
- 机器上的会话，行菜单里目前还没有**归档**。
- 卡片上的**删除**会把机器从 Project 中移除。程序、数据和 `Host` 块都保留。对话框里的**卸载**则会移除程序。
