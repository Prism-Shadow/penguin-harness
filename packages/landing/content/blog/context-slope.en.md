> Written for PenguinHarness 0.2.16. Later releases may differ in some details.

Context slope is our term for how much an agent's model context grows with each request, the quantity a harness directly controls. Our bet is that **harnesses should cut that per-turn growth first, using the index first, fetch on demand pattern across every surface**, rather than treating growth as a problem for lossy compaction to solve[^1].

**TL;DR**
- Split context into a fixed intercept and per-turn slope; compaction is a lossy backstop, not a design.
- The index first, fetch on demand rule cuts slope across Skills, tool output, and CLI surfaces.
- MCP sets need fixed, deferred tool definitions to keep intercept small and caches warm.

## Intercept and slope
**Each request's context has two parts: a fixed intercept per turn (system prompt, tools, Skill roster), and per-step context slope** from tool output, fetched instructions, and replies. LangWatch's 287,748-call trace measured per-step growth of about 3,200 tokens below 50k, settling at about 1,470 above 200k; every context doubling cost about six times more[^2]. Anthropic documents context rot: recall falls as tokens grow; a 2025 arXiv study found 13.9–85% drops across five LLMs, even with perfect retrieval in advertised windows.

This slope sets how fast sessions hit compaction, a lossy backstop. It can drop subtle context, costs a request, and in our prompt-cache simulator the next context starts with a cold cache. We ran a synthetic 0.2.16 test with a scripted model, using character-based estimates and no provider calls. Both runs shared a 2,963-token intercept, differing only in the 16,000-character output cap[^3].

## Progressive Skill loading as the template
**A flatter slope keeps compaction at bay, and one principle produces every lever to get there: index first, fetch on demand**. Anthropic's Agent Skills use progressive disclosure: only names and descriptions load upfront, full SKILL.md loads when relevant, bundled files load only when needed[^4]. We measured each content tier across the 35 built-in Skills in 0.2.16 to quantify the gap between index and full content.

PenguinHarness follows this shape: one roster line per Skill in the system prompt, with the model reading full SKILL.md via `read_file` or shell, no dedicated Skill tool. This does not eliminate cost: fetched Skill bodies stay until compaction, moving spend from the universal intercept to the turns that use the Skill. We have two unaddressed intercept bloat points in 0.2.16: `AGENTS.md` loads whole with no cap, and all configured MCP schemas ride every request.

## Tool output belongs on disk first
Those Skill savings come from keeping only a small pointer to full content in active context, a rule that applies just as cleanly to raw tool output. PenguinHarness 0.2.16 caps default inline tool output at 16,000 characters, keeping a head and tail window with a truncation marker, and writes full output to a scratchpad recovery file with the path printed inline.

Critics argue truncation risks losing critical mid-task data, but the model can access saved output with the existing `read_file` and a targeted `rg` or `tail`, no dedicated retrieval mechanism required. Manus frames the filesystem as restorable extended context, so full text stays reachable for targeted reads without riding every subsequent turn[^5]. **With the cap on, an over-cap turn adds about 4,163 estimated tokens regardless of raw output size, so output length no longer drives slope**.

## CLI and MCP follow the same rule
**That index first, fetch on demand principle extends to CLIs and MCP, where defaults bloat intercept and slope**. Willison notes LLMs use `--help`, so CLIs need little upfront schema[^6]. The browser plugin adds no schema; the model drives it via `exec_command`, with bounded output and `--save`. `penguin run --json` prints one final object with the run's assistant text, so delegated tool traffic stays out of the caller's context.

Zechner found well-designed MCP is token-efficient, but many servers bloat; Willison writes GitHub's official server uses tens of thousands of tokens[^7]. Anthropic's Tool Search defers loading to cut from about 77K to about 8.7K without breaking cache, while Cloudflare's Code Mode uses two tools in about 1,000 tokens versus 1.17 million for API schemas. Manus warns mid-context tool changes invalidate cache.
