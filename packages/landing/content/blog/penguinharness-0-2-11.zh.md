PenguinHarness 0.2.11 发布了，这一版的大部分改动都在对话里面。你可以在双栏的文件面板里编辑 Workspace 文件，上下文环改为按压缩触发点计量，定时任务搬进了右侧栏，对话边缘还多了一个打开各个面板的悬浮球。钩子成为 Agent 循环的一部分，目标模式和持续学习以可安装插件的形式提供。有了官方 Docker 镜像，部署服务端只需一条 `docker run`；新建的 Project 默认使用 DeepSeek V4.1 Flash。

## 可以直接编辑的双栏文件面板

文件面板现在左边是目录树，右边是选中的文件，中间的分隔条可以拖动。目录树在你展开某个目录时才加载其中的内容。

- 文本文件新增**编辑**操作：打开等宽字体的编辑器，带**自动换行**开关，按 Ctrl+S 保存。
- 保存时会用 `ETag` / `ifVersion` 做版本校验。如果你打开文件之后 Agent 改过它，服务端会返回 `409`，不写入任何内容。面板随后提供**仍然覆盖**，你的草稿也会保留。
- 把操作系统里的文件拖到面板上，就会上传到鼠标指针所在的目录。
- 有未保存的修改时，切换文件或移除面板前会先确认。收起右侧栏不会丢失草稿。

![文件面板：左侧目录树，右侧是在纯文本编辑器里打开的文件](/blog-assets/penguinharness-0-2-10-files-panel-zh.png)

## 上下文环按压缩阈值计量

输入框旁的上下文环现在以压缩阈值为满格，不再以模型的上下文窗口为满格。阈值是 128k 时，用掉 64k 显示为 50%。

上下文面板里的长条仍以模型窗口为刻度，并用一条虚线标出压缩阈值。拖动这条虚线就能修改阈值：确认框弹出时已经填好新值，你还可以再改。每到一个压缩检查点，都会重新读取压缩设置，所以修改对正在运行的对话同样生效。

面板还新增了第二个 Top 5 视图，列出当前上下文里文件工具读写最多的文件。

![上下文面板：以模型窗口为刻度的长条、可拖动的压缩阈值虚线，以及 Top 5 文件视图](/blog-assets/penguinharness-0-2-10-context-panel-zh.png)

## 对话边缘的悬浮球

没有打开任何面板时，对话区域右缘内侧会浮着一个半透明的圆形按钮，下方写着**快捷方式**。点击它，各个面板和一个终端的入口会围着它展开成半圆。这些入口只显示图标，鼠标指向哪一个，下方的文字就显示哪一个的名称。选中一个入口，就会打开对应的面板，悬浮球随之隐藏。

悬浮球可以沿着边缘拖动，并记住你放下的位置。有待审批的请求时，它会显示提示小圆点。半圆上的最后一个入口会永久收起悬浮球，想找回来，可以在**外观**设置里重新打开。

![对话右缘的悬浮球，展开成一圈半圆形的面板入口](/blog-assets/penguinharness-0-2-10-shortcuts-launcher-zh.png)

## 定时任务进入对话

右侧栏新增了**定时任务**面板，列出绑定到当前会话的定时任务。面板带搜索、状态过滤和启用开关，每个任务的执行时间都用通俗的话写出来。

- 面板顶部有**用 AI 创建**和**手动创建**两个按钮。前者把请求填进当前对话的输入框，但不会发送；后者打开的表单已经选好当前会话。
- 在侧栏里，还有定时任务没触发的会话会显示一个闹钟。
- 保存定时任务时，提示不再说「在新对话中生效」，而是如实说明调度器会怎么执行。

![右侧栏里的定时任务面板，带「用 AI 创建」和「手动创建」两个按钮，以及侧栏中带闹钟标记的会话行](/blog-assets/penguinharness-0-2-10-schedule-panel-zh.png)

## 钩子成为循环的一部分，目标模式变成插件

会话现在有三个钩子触发点：`stop`、`pre_tool_use` 和 `user_prompt`。钩子就是一个普通的 Node 脚本，安装在 `agent_state/hooks/` 下，以子进程方式运行。stop 钩子可以返回 `continue`、`stop`、一个 `subagent` 请求，也可以什么都不返回。

- 目标模式现在就是 `goal` 插件的 stop 钩子。
- `continual-learning` 插件会把长任务中的发现交给一个后台子 Agent，由它更新相关的 `SKILL.md` 文件。
- 技能库改名为**插件库**。插件以 npm 包的形式发布，版本号是日期，每个插件都有带文件浏览器的详情弹窗。
- Agent 设置新增**钩子**标签页，每个 Agent 有一个 `hooks.enabled` 开关。关闭后，这个 Agent 不加载任何钩子，已安装的钩子包仍然留在磁盘上。每个钩子包的那一行用小标签列出它的触发点，标签页还支持 zip 导出、导入，以及通过对话导入。

![Agent 设置的钩子标签页：启用开关卡片、带触发点标签的钩子包，以及导入对话框入口](/blog-assets/penguinharness-0-2-10-hooks-tab-zh.png)

## 「用 AI 创建」做成通用套件

Web App 里凡是用表单创建的对象，都会多一条创建途径：把它描述给 Agent。这一版发布的是支撑这条途径的套件，包括一对按钮、一个带示例和完整提示词折叠预览的提示词面板，以及一个把提示词交给 Project 默认 Agent 的对话框。

- 两个按钮彼此独立。**用 AI 创建**是强调样式，图标是魔杖；**手动创建**是普通样式，图标是一只手。
- 对话框唯一的出口是**在新对话中编辑**，任何内容都不会自动发送。提示词作为草稿进入输入框，发不发由你决定。
- 除了定时任务面板，技能标签页里通过对话导入技能、记忆标签页里新增和编辑记忆，也已经接入了这个套件。其他创建表单会在后续版本陆续接入。

![页面顶部的用 AI 创建和手动创建按钮，上面打开着用 AI 创建对话框](/blog-assets/penguinharness-0-2-10-create-with-ai-zh.png)

## 把服务端放到另一台机器上

Docker Hub 上现在有官方容器镜像 `hiyouga/penguinharness`，从源码构建，支持 `linux/amd64` 和 `linux/arm64`。镜像在 `0.0.0.0:7364` 上运行 `penguin server`，数据放在 `/data` 卷里。`latest` 标签跟随 `main` 分支，`X.Y.Z` 标签由各个发布版本构建。文档里的 `docker run` 命令把端口发布在宿主机的回环地址上，所以新部署的实例只有运行 Docker 的那台机器能访问。

用来通过 ssh 在其他机器上安装 PenguinHarness 的**机器**页面，也有几处变化：

- 机器记录从 JSON 文件迁入了 `web.db`，并归属于某个 Project。每台机器会自己生成一个 16 字符的 id。
- PenguinHarness 通过 ssh 运行 `penguin server status`，获取机器的 id，并确认上面的服务端有没有在运行。
- 每台机器只保持一条常驻的 `ssh -T -D` 会话，发往这台机器的所有流量都走这条会话。已连接机器的 API 在同源路径 `/server/<machineId>/api/…` 下应答。

## 模型目录

- **DeepSeek V4.1 Flash** 以不带版本号的 id `deepseek-flash` 上架，并成为新建 Project 的默认模型。它有 1,000,000 Token 的上下文窗口，支持图片输入，按 Flash 系列定价，非高峰时段价格减半。它的直连条目固定了客户端和 base URL。
- **Gemini 3.8 Flash** 加入直连分组和 OpenRouter，上下文窗口 1,048,576 Token，支持图片输入。Gemini 3.x Flash 的条目现在保存官方标价，并单独声明上线折扣，不再把折扣直接算进价格；两条计费价格有误的条目也已更正。
- **GPT-6 Astra** 加入直连分组和 OpenRouter，上下文窗口 1,050,000 Token，支持图片输入，每百万 Token 的价格为 $1 / $12.5 / $50（缓存读取 / 缓存写入 / 输出）。
- 三个 **Doubao Seed** 模型加入 TokenDance 分组，按五折计费。
- 新增 **vLLM** 分组，收录八个自建部署的模型。这些条目价格为零，不带 base URL，协议由分组统一固定。

已有的 Project 需要在模型页点击**同步预置**，才能拿到这些条目。

## 这一版还有

- `exec_command` 除了 `cmd`，也接受 `command`。工具拒绝一次调用时，现在会说明错在哪里、有哪些参数，以及正确的调用形式。`read_image` 和 `describe_image` 并入了 `read_file`。
- 耗时较长的轮次会显示时间花在了哪里，例如 `Elapsed 10.3s (API 5s, tools 5.3s)`。两部分都不计入等待审批的时间。
- 有开发服务器或后台子 Agent 正在运行的会话，会在侧栏里带上标记，对话顶部也会显示对应的胶囊标签。
- 压缩行会显示状态和耗时，思考内容和摘要分别流式写进各自可以展开的行里。
- `model.timeoutMs` 现在是上游两次事件之间的空闲时限，默认值提高到 300000，所以请求只会因为长时间没有响应而超时，不会因为生成时间长而超时。收到内容之后，重试阶梯会从头开始。
- 更新全部在一个对话框里完成：检查更新、查看发布说明、下载时显示进度条，最后点击**重启并更新**。
- 打开对话时只加载最近 50 轮，向上滚动时再加载更早的内容。
- 按 Workspace 分组时，侧栏会列出所有 Workspace，不再只列出已加载会话所属的那些。
- 终端更像终端了：屏幕重绘之后，链接仍能正确打开；通过 OSC 52 复制的内容也能进入系统剪贴板。
- 插件版本号现在写作 `2026.09.10.1` 这样的形式。用旧写法（短横线分隔）安装的副本仍算作同一个版本，不会误报有更新。

## 关于 0.2.10

0.2.11 是用 electron-builder 26.16.1 重新构建的 0.2.10，签名的 macOS 安装包又能正常构建了。0.2.10 已经打了 tag，npm 包和 Docker 镜像也已发布，但签名的 macOS 构建失败，所以 0.2.10 始终没有安装包，也没有 Release 页面。各项改动的记录仍在 [`changelog/0.2.10/`](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.10)。

## 升级须知

- **需要重启一次。** 这一版包含第一个只能在重启时执行的数据库迁移 `drop-goal-state`。热推送到运行中的实例时，系统会在改动数据库之前就拒绝；正常安装则会重启并执行迁移。回退到 0.2.9 仍然可行。
- **给 0.2.10 之前创建的 Agent 安装 `goal` 插件。** 不装的话，目标模式会返回 `409 goal_plugin_not_installed`。每个 Agent 点一下就能装好。
- **把内核更新到 `2026-09-10`**，Agent 才会用 `read_file` 读图。在此之前，调用旧图片工具会得到「未知工具」的回复，读图也仍按已保存的 30 秒超时执行。
- **把创建 Agent 的脚本里的 `skills` / `--skills` 改成 `plugins` / `--plugins`。**
- **API 变化。** `POST /api/version/update` 现在返回任务状态，不再阻塞到更新结束。机器相关的路由移到了 Project 下面，所以 0.2.9 里的机器列表升级后会是空的；从这台机器所属的 Project 重新安装一次即可恢复。

## 安装

桌面应用的安装包在 [penguin.ooo/download](https://penguin.ooo/download)。

Linux 和 macOS 上，用下面的命令安装 CLI 和服务端：

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows 上用 PowerShell：

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

用 Docker 运行服务端：

```sh
docker run -d --name penguin -p 127.0.0.1:7364:7364 -v penguin-data:/data hiyouga/penguinharness:latest
```
