> 本文基于 PenguinHarness 0.2.16 撰写，之后的版本在部分细节上可能有所不同。

Agent Harness **可能在不抛错、不改变可见输出时出故障，推高用户成本，常规测试却全部通过**。我们搭建的 CI 系统只给外部边界写脚本，中间运行未修改的 Harness 代码，用带命名豁免清单的不变量校验，无需 API 密钥，跨操作系统在每次相关变更时运行。本文用 PenguinHarness 的提示词缓存测试套件作为这套 CI 设计的实例，不讲解缓存计算规则[^1]。

**TL;DR**
- 静默的提示词缓存回归可通过所有功能测试。
- 33 个无密钥缓存测试总耗时 1.54 s，CI 在三个操作系统上运行。
- 49 字符的提示词修改会打崩钉值检查，却不违反缓存不变量。
- 回滚 PR #700 会让 5 轮任务的压缩成本升至 10.2 倍，两个测试失败即可捕获。

## 静默的 Harness 回归能通过所有常规测试
**提示词缓存回归就是典型的静默 Harness 回归**，由微小代码改动触发，输出完全一致、不抛错误，常规 CI 检查抓不到任何信号[^2]。本文所有 Token 计数、比值和成本均为模拟器对录制请求的估算，定价取目录中 `claude-sonnet-4-6` 条目。所有测试在我们的测试机 (Node v24.20.0, vitest 3.2.7) 上运行，无需网络和 API 密钥。

## 只给边界写脚本，不改动被测系统
要校验供应商收到的真实传输字节，最容易想到的是在 CI 直接跑线上模型调用，这个方案没法支撑日常使用。线上检查需要 API 密钥和网络，fork PR 拿不到密钥会直接跳过，也无法给出缓存未命中的精确根因[^4]。

**我们的脚本化边界仅替换供应商字节流，Harness 内部代码全量保留**，多次运行产出字节完全一致的请求，无需密钥，33 个测试总耗时 1.54 s[^5]。我们接受这一取舍，模拟器只实现公开的供应商规则，不验证线上服务实际行为。

这套检查无需密钥、运行快，CI 会在 Linux、macOS、Windows 上对所有触及核心逻辑的变更运行[^6]。浏览器 e2e 测试遵循同样的边界 mock 规则，使用独立的 mock LLM 端点。发版、共享文件改动、缺对比基线时跑全量校验。仅安装器任务持有 DeepSeek 密钥，运行一个线上 e2e 步骤，fork PR 自动跳过。对无害改动误报的检查没有实际价值。

## 校验不变量，不钉死固定数值
拿到传输字节后，最直观的检查是把预期 Token 数或缓存命中率钉在已知正确数值上，这类方案恰恰会在无害、符合预期的改动上失败。一处仅 49 字符的系统提示词修改，会改变 20 个单请求计数中的 10 个，打崩所有钉值检查，但缓存行为几乎不变，模拟器算出的命中率仅从 88.61% 变到 88.62%[^7]。

**我们的不变量只校验一条规则，每个请求都完整回读上一个请求的前缀**[^8]。符合设计预期的主动未命中仅三类，列入短豁免清单，即调整思考强度、重开上下文、切换模型。条目不再适用时自动失败，堵住过时豁免放跑回归的漏洞。就算不变量写得再精确，团队改测试让失败消失，检查照样失效。

## 直接报失败，绝不改基线凑绿灯
这种修改测试的行为叫改基线，会彻底毁掉成本检查，只要改掉预期数值，CI 立刻变绿，不会留下任何问题信号。PR #700 修复了一个压缩逻辑 bug，用户调整思考强度后，压缩步骤仍保留初始思考强度参数，导致压缩请求前缀偏移。次日 PR #722 加入这套测试套件，守护该修复[^9]。

故意回滚 #700 的改动，仅两个核心测试失败，其余全部通过。回滚后，单轮任务压缩估算成本升至原版本的 1.13 倍，五轮工具调用任务后压缩估算成本升至原版本的 10.2 倍。

## 这套设计适用于所有静默 Harness 属性
#700 修复的这类推高成本的静默回归，同样会出现在提示词缓存外的 Harness 逻辑里，**这套 CI 设计可以覆盖所有无功能信号的 Harness 属性**。无需接入线上模型，就能校验 Harness 发出的字节。在仓库根目录执行 `pnpm --filter @prismshadow/penguin-core exec vitest run prompt-cache` 即可本地运行，前缀稳定性规则文档见 <https://penguin.ooo/docs/agent-loop>[^10]。
