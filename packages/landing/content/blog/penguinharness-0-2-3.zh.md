我们发布了 PenguinHarness 0.2.3。这一版集中在两件事上，一是让 Agent 正在做什么变得看得见，二是把用起来别扭的地方磨掉。

## 侧栏能看出哪个会话在跑

以前侧栏里只有一行的状态是准的，就是你当前打开的那个会话。其余每一行显示的都是上次拉取列表时的快照。你离开一个正在跑的会话，它会一直显示成在跑；而在后台开始跑的会话，那一行根本不会变。

现在会话状态走用户级的事件流推送，每一行都是实时的。运行中是一个转动的沙漏，跑完了而你还没看过是一个绿点，看过之后就什么都不显示。

![侧栏的三个会话，分别显示未读绿点、无标记和运行中的沙漏](/blog-assets/penguinharness-0-2-3-sidebar-status-zh.png)

这里有个不显眼的坑。会话是否"跑过"是服务端列表行上的一个字段，而事件只更新状态，不更新它。所以一个第一次跑任务的新会话，沙漏一停就会什么都不显示。现在这个字段跟着状态一起推送，第一次跑完也能正常落到绿点上。

## 压缩不再是一段空白

上下文压缩以前是会话里的一段空白，你只知道它发生过。现在它是一行可以展开的记录，默认折叠，和任务组里的思考一样。

![折叠状态的压缩行](/blog-assets/penguinharness-0-2-3-compaction-collapsed-zh.png)

摘要在生成的时候就流式写进去，展开就能看到 Agent 到底保留了什么。

![展开后的压缩摘要，包含任务、已确认的结论、下一步和注意事项](/blog-assets/penguinharness-0-2-3-compaction-expanded-zh.png)

压缩的时机也改了。模型产生工具调用之后触发的压缩，现在会等工具执行完，带着工具返回一起压，而不是把一次没结束的交换塞进去。压缩到一半你退出程序，那一次会被标记为失败，重新加载时直接丢掉写了半截的内容。清空上下文这种模式不再顶着"压缩"两个字，它现在就叫清空。

还修掉一个反复有人碰到的问题。客户端重启之后，明明满屏都是历史，压缩却报"当前上下文没有可压缩的内容"。原因是引擎对象是惰性构造的，会话从磁盘恢复时轮次数确实回填进了初始状态，但那个值只在引擎的构造函数里才会生效，而这时候引擎还没被造出来。顺带把服务端这类 409 拆成了三个错误码，中文界面下报错也是中文了。

## 任何一条回复都能分叉出新会话

对话跑歪了，以前要么继续将就，要么从头开一个。现在每条已完成的回复右边都有一个分叉按钮，就在复制旁边。

![回复下方的操作行，分叉按钮在复制右边](/blog-assets/penguinharness-0-2-3-session-fork-actions-zh.png)

点它会先问一句，确认之后把这条回复之前的对话原样复制成一个新会话，原来那个不动。

![分叉前的确认弹窗](/blog-assets/penguinharness-0-2-3-session-fork-confirm-zh.png)

## 排队的消息可以撤回来改

任务跑着的时候插的话、排在后面的追问，以前发出去就收不回来了。现在它们旁边有一个回弯的箭头，点一下消息回到输入框，改完再发。

撤回和引擎取用之间是互斥的，同一条消息不会既被送出去又被撤回来。如果引擎刚好在那一瞬间把它取走了，你会看到一条明确的提示，而不是消息悄悄消失或者发两遍。

## 思考等级

AgentHub 升到 0.4.4 之后多了一档 max，梯度现在是低、中、高、极高、最高。按钮上只写中文，下拉里带上英文的原始值。

![思考等级的下拉菜单](/blog-assets/penguinharness-0-2-3-thinking-level-menu-zh.png)

会话中途换等级会先弹一个框。有些模型服务商是靠在提示词最前面注入不同前缀来实现思考等级的，中途一换，整段历史的前缀缓存就失效了，下一次请求要按未缓存的价格重新计一遍。所以这个框给三个选择，先压缩再切换、直接切换、取消。

![中途切换思考等级时的确认框](/blog-assets/penguinharness-0-2-3-thinking-level-switch-guard-zh.png)

换完的等级会存在会话上，刷新页面、换个标签页都还在。

## 加自定义模型不用再猜接口

AgentHub 0.4.2 之后有三种通用协议客户端，OpenAI Responses、Anthropic Messages 和 OpenAI Chat Completions。填自定义 base URL 的时候，你现在不用自己判断对方是哪一种。检测按钮会按 Responses、Messages、Chat Completions 的顺序去探，第一个能对上的就是它，结果直接填进协议选择器里。没填 key 的时候会回退到环境变量，探不出来就弹一句提示让你查 key 和地址。

![base URL 输入框右上角的检测协议按钮，以及框内列出三种协议和各自端点路径的选择器](/blog-assets/penguinharness-0-2-3-model-add-protocol-zh.png)

视觉能力也能探。它会发一张 1x1 的图过去，正常应答就打开，模型明确拒绝图片就关掉，其他情况一律不动你的设置。这个探测会真实产生一次调用费用，所以只在你点的时候跑，保存模型的时候不会偷偷跑。

支持 fast mode 的模型多了一个开关，默认关。不支持的模型上根本不显示这个开关，免得你打开之后每一轮都报错。打开的时候会提示一句，fast mode 是溢价计费的。

## 还有一些

会话列表的悬停操作改回了归档和删除，右键菜单里是完整的那一套。附件和图片可以直接拖到聊天区域上传。CLI 加了 `/thinking` 和 `--thinking`，长工具输出默认折叠成首尾几行，`/verbose` 展开，模型和轨迹拿到的一直是完整内容。

模型目录这一版也刷了一遍。新增 Gemini 3.7、GLM-5.3、GPT-5.6 系列，以及它们在 OpenRouter 上的对应条目，其中 OpenAI 那九行走 Responses 协议。DeepSeek 的价格按官网最新的改过了，下架的 ling-3.0-flash 移除。

底层还有一个值得说的修复。经过 one-api、OpenRouter 这类网关的长时间生成，网关会往流里塞心跳事件，而这些事件以前会被当成未知输出直接让整条流失败，harness 又把它判成可重试，重试再撞上下一个心跳，表现出来就是没完没了的"正在重连"。AgentHub 0.4.3 起所有流式客户端都会跳过这些心跳。

## 从跑得动到看得懂

前面这些改动落在同一件事上。Agent 干活的时候，你应该知道它在干什么、它把什么记住了、它下一步要花多少钱。会话状态、压缩记录、切换等级前的提示，都是把原本只有日志里才有的东西搬到界面上。

## 安装与升级

桌面端到官网下载对应平台的安装包。这一版开始 Windows 构建也带签名了，macOS 从 0.2.2 起就已经签名并公证。

Linux 和 macOS 用命令行装。

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows 用 PowerShell。

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

完整的改动记录在 [changelog/0.2.3/](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.3)。
