PenguinHarness 0.2.3 发布了。这一版让 Agent 的工作过程更容易看清，也磨掉了几处用着别扭的地方。侧栏的会话状态现在是实时的，上下文压缩变成一条可以展开阅读的记录，任何一条已完成的回复都能分叉出新会话，排队中的消息也可以撤回输入框，改完再发。

## 侧栏能看出哪个会话在运行

以前，只有你当前打开的那个会话显示的是真实状态，其余各行显示的都是上次拉取列表时的结果。你离开时还在运行的会话，会一直显示为运行中；在后台启动的会话，那一行则始终不变。

现在每一行的状态都是实时的。转动的沙漏表示正在运行，绿点表示已经结束而你还没看过，什么标记都没有就是你已经看过了。

![侧栏里的三个会话，分别显示未读绿点、无标记和运行中的沙漏](/blog-assets/penguinharness-0-2-3-sidebar-status-zh.png)

第一次运行的情况也顾及到了。会话的第一个 Task 结束后，这一行和其他情况一样停在绿点上，不会变成空白。

## 压缩变成一条可以展开的记录

上下文压缩以前是对话里的一段空白，你能看出它发生过，却不知道它保留了什么。现在它是一行可以展开的记录，默认折叠，和 Task 分组里的思考内容一样。

![对话中的压缩行，默认折叠](/blog-assets/penguinharness-0-2-3-compaction-collapsed-zh.png)

摘要边生成边显示。展开这一行，就能看到 Agent 究竟决定保留哪些内容。

![展开后的压缩摘要，包含任务、已确认的结论、下一步和注意事项](/blog-assets/penguinharness-0-2-3-compaction-expanded-zh.png)

压缩的时机也变了。如果压缩在模型发出工具调用之后触发，现在会等工具执行完，带着工具结果一起压缩，不再把一次没有结束的交互塞进请求。压缩进行到一半时退出客户端，这一轮会标记为失败，写了一半的内容在下次加载时丢弃。如果这一轮是清空上下文而不是生成摘要，它不再叫压缩，而是标为「清空」。

还修复了一个反复有人反馈的问题。以前重启客户端之后，会话里明明有大量历史，压缩却报没有可压缩的内容；现在可以正常压缩。服务端拒绝压缩的三种原因也各自有了错误码，中文界面会显示中文提示，不再是英文。

## 任何一条回复都能分叉出新会话

对话跑偏了，以前只有两个选择：将就着继续，或者从头再来。现在每条已完成的回复都带一个分叉按钮，就在复制按钮旁边。

![已完成回复下方的操作行，分叉按钮在复制按钮旁边](/blog-assets/penguinharness-0-2-3-session-fork-actions-zh.png)

分叉前会先确认。确认后，到这条回复为止的对话会复制成一个新会话，原会话保持不动。

![分叉前弹出的确认框](/blog-assets/penguinharness-0-2-3-session-fork-confirm-zh.png)

## 排队中的消息可以撤回

运行中途发出的插话，以及排队等待的跟进消息，以前一发出去就收不回来。现在它们旁边都有一个回弯箭头。点一下，消息就回到输入框，改完可以重新发送。

一条消息不会既送达、又撤回。如果引擎恰好在你点击的那一刻取走了这条消息，你会看到一条明确的提示，不会出现消息悄悄消失或者重复发送。

## 思考等级

AgentHub 0.4.4 新增了 `max` 一档，梯度现在是低、中、高、极高、最高（low、medium、high、xhigh、max）。中文界面的按钮上只显示中文，下拉菜单里还会附上英文原值。

![思考等级的下拉菜单](/blog-assets/penguinharness-0-2-3-thinking-level-menu-zh.png)

在对话中途切换等级，现在会先弹出确认框。有些供应商实现思考等级的方式，是在请求的最前面放一段不同的提示词前缀。中途一换，整段历史的前缀缓存就会失效，下一次请求要把全部历史按未缓存的价格重新计费。确认框提供三个选择：「压缩后切换」「仍要切换」和「取消」。

![对话中途切换思考等级时的确认框](/blog-assets/penguinharness-0-2-3-thinking-level-switch-guard-zh.png)

选好的等级保存在会话上，刷新页面后仍然有效，在另一个标签页里也能看到。

## 添加自定义模型，不用再猜协议

从 0.4.2 起，AgentHub 就带有三个通用协议客户端：OpenAI Responses、Anthropic Messages 和 OpenAI Chat Completions。你的端点用的是哪一种，现在不用自己判断了。「检测协议」按钮会按这个顺序逐个探测，第一个按预期格式应答的就是结果，并自动填进协议选择器。没有填 key 时，会改用环境变量里的 key；一个都对不上时，会弹出一句简短的提示，请你检查 API key 和 base URL。

![base URL 输入框右上角的检测按钮，以及框内的选择器，列出三种协议和各自追加的路径](/blog-assets/penguinharness-0-2-3-model-add-protocol-zh.png)

视觉能力也能用同样的方式检测。探测会发送一张 1×1 的图片：正常应答就打开视觉设置，明确拒绝图片就关闭，其他情况一律保持你原来的设置。每次探测都是一次真实的 API 调用，所以只在你手动点击时运行，保存模型时不会运行。

支持快速模式的模型多了一个开关，默认关闭。不支持的模型不会显示这个开关，免得你打开一个每一轮都会失败的选项。打开时会明确提示：快速模式按溢价费率计费。

## 这一版还有

- 侧栏会话行的悬停操作改回了归档和删除，完整的操作都在右键菜单里。
- 附件和图片可以直接拖到聊天区域上传。单个文件附件的上限从 10MB 提高到 100MB，管理员可以在用户菜单里修改这个上限。
- 内联图片另有 20MB 的上限。内联图片的字节会进入对话和 Trace，而每翻一页历史，都要把 Trace 整个重读一遍。文件附件按路径打开，大小不会影响上下文。
- CLI 新增了 `/thinking` 和 `--thinking`。较长的工具输出现在只显示开头和结尾几行，用 `/verbose` 可以看到全部。无论是否折叠，模型和 Trace 拿到的始终是完整内容。
- 模型目录更新了一轮，新增 Gemini 3.7、GLM-5.3 和 GPT-5.6 系列，以及它们在 OpenRouter 上的对应条目。九个 `openai/*` 条目固定使用 Responses 协议。DeepSeek 的价格按当前官方价格更新，已下架的 `ling-3.0-flash` 已移除。
- 经过 one-api、OpenRouter 这类网关的长时间生成，不会再反复重连直到放弃。这类网关会往流式响应里插入心跳事件，这些事件以前会让整条流中断，Harness 随即重试，重试又撞上下一个心跳。AgentHub 0.4.3 及之后版本的所有流式客户端都会跳过这些事件。

## 安装与升级

各平台的桌面安装包都可以在官网下载。从这一版开始，Windows 安装包带有签名；macOS 安装包从 0.2.2 起就已经签名并通过公证。

Linux 和 macOS 用命令行安装：

```sh
curl -fsSL https://penguin.ooo/install.sh | sh
penguin web
```

Windows 用 PowerShell 安装：

```powershell
irm https://penguin.ooo/install.ps1 | iex
penguin web
```

完整的改动记录见 [changelog/0.2.3/](https://github.com/Prism-Shadow/penguin-harness/tree/main/changelog/0.2.3)。
