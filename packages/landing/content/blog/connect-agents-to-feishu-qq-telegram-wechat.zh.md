一个只能在浏览器标签页里使用的 Agent，你一离开工位就用不上了。PenguinHarness 可以把任意一段对话绑定到飞书、Telegram、QQ 或微信上的聊天机器人。绑定生效后，你在手机上发给机器人的消息会进入这段对话，就像在 Web App 里输入的一样；Agent 的回复也会发回同一个聊天。

在这篇教程里，你会创建一段对话，从右键菜单打开**远程控制**，再把对话绑定到微信。微信是配置最快的渠道：扫一个二维码就行，不用进开发者后台，不用等应用审核，也不用复制任何凭证。读到最后，你就能在手机上给 Agent 发一个 Task，并在聊天里看到它的回复。

教程最后一部分介绍飞书、Telegram 和 QQ 有哪些不同，以及对话绑定后要遵守的限制和安全规则。

## 准备工作

- PenguinHarness 运行在一台你离开时也不关机的电脑上：桌面应用，或者用 `penguin web` 启动的服务器。只有它在运行，机器人消息才能送达。
- 在**模型库**页面至少配置一个模型，Agent 才能回答。
- 你是 Project 的所有者。只有所有者能保存机器人的凭证、开启连接；其他成员可以查看绑定、运行测试。
- 微信渠道：手机上装有微信。
- 其他渠道：一个能创建自建应用的飞书账号、一个 Telegram 账号，或者一个已在 QQ 开放平台注册为开发者的 QQ 账号。

## 绑定是怎么回事

绑定把一段对话连到一个聊天机器人。绑定在对话的**远程控制**对话框里管理：每个渠道占一个标签页，凭证也各自保存。

## 第 1 步：创建对话

绑定要挂在已有的对话上，所以先创建一段对话。之后你发给机器人的消息，都会进入这段对话。

1. 在侧栏选择**新建对话**。
2. 选好你想在手机上使用的 Agent 和模型，再选一个放着 Agent 要处理的文件的 Workspace。
3. 发出第一条消息，例如「看一下 logs/app.log，有没有需要处理的问题？」

第一条消息发出后，对话才算真正创建。在那之前，草稿还没有可绑定的对象，**远程控制**面板会显示**发送第一条消息后可用**。

消息框的工具栏里还显示着审批模式。新对话默认是**全部放行**，工具调用不经询问直接执行。绑定机器人之前要记住这一点：任何能给机器人发消息的人，都能让 Agent 运行它的工具。本教程末尾的「限制与安全」介绍了可以怎么做。

![新建对话草稿：消息输入框，下方是 Agent 和 Workspace 选择器，工具栏里是模型](/blog-assets/remote-control-new-chat-zh.png)

## 第 2 步：打开「远程控制」

绑定在**远程控制**对话框里设置，这个对话框从对话的右键菜单打开。

1. 在侧栏里右键点击对话标题。
2. 在菜单中选择**远程控制**。

在触屏上长按、在键盘上按 **Shift+F10**，或者把鼠标悬停在对话行上、点出现的**更多**按钮，打开的都是同一个菜单。

![对话的右键菜单，「远程控制」位于「重命名对话」和「归档」之间](/blog-assets/remote-control-menu-zh.png)

你也可以让远程控制一直显示在对话旁边：点对话右上角的**右侧栏**按钮，在右侧栏里打开**远程控制**面板。面板里的设置和对话框完全相同。

## 第 3 步：绑定微信

微信机器人的凭证用手机扫码就能拿到，不用注册，也没有表单要填。

1. 在对话框顶部选择**微信**标签页。
2. 点**扫码连接**。对话框里出现二维码，并显示**等待在微信中扫码…**。
3. 用手机上的微信扫码。
4. 如果手机上显示一串数字，把它填进**配对码**，再点**确认**。
5. 在手机上确认授权。对话框会显示**已保存机器人 … 的凭据，可以启用连接了**。
6. 打开**启用连接**开关。**连接状态**变为**已连接**，侧栏中这段对话旁会出现纸飞机图标。
7. 等大约 15 秒，再在微信里找到这个机器人，给它发一条消息。

![在「远程控制」对话框里扫描微信授权码](/blog-assets/remote-control-wechat-qr-zh.png)

> **发第一条微信消息前，先等一等**。连接刚建立时，PenguinHarness 会先清空微信渠道之前排队的消息，最初几秒内到达的消息也会被一并清掉。等**连接状态**显示**已连接**大约 15 秒后，再发第一条消息。如果没有回复，就再发一次。之后的消息都是即发即达。

消息送达后，对话框会显示**最近收到消息**和时间，Agent 随即开始工作。

![已连接的微信绑定：连接已启用，并且收到了一条消息](/blog-assets/remote-control-wechat-connected-zh.png)

如果不想等真实回复，只想确认链路是否通畅，可以点**发送测试消息**。机器人收到第一条消息后，这个按钮才可用，因为在那之前，它还不知道该把消息发到哪个聊天。

## 第 4 步：在手机上和 Agent 对话

现在可以在手机上操控这段对话了。你发给机器人的每条消息，都会在对话里启动一个 Task，和在 Web App 里输入完全一样。Agent 正忙时，消息会先排队，轮到了再运行。Agent 写下的内容会发回聊天，完整的往来也都留在对话里，之后回到浏览器还能接着处理。

![Web App 中的这段对话：一条从微信发来的请求和 Agent 的回复](/blog-assets/remote-control-chat-zh.png)

有几点值得了解：

- **文字、图片和文件**在微信上都能双向传输。语音消息到达时，是微信自带的转写文字。Agent 在运行中写出文件、并在回复里提到它时，文件会跟着文字一起发到聊天里；一轮运行最多发送五个文件，图片不超过 10 MB，其他文件不超过 30 MB。渠道收不下的文件不会在聊天里说明，而是记入成本中心的异常记录。
- **审批仍在 Web App 里完成**。在默认的**全部放行**模式下，工具调用不经询问直接执行。如果把对话切换到会询问的模式，比如**放行只读**，每当有工具调用等待审批，聊天里都会收到提醒，运行也会一直等到你在浏览器里批准。
- **在 Web App 里启动的运行也会同步到聊天**，前提是机器人已经收到过第一条消息。

回复的形式由三个开关决定：

| 开关 | 作用 |
| --- | --- |
| **只发送最终回复** | 只发送一次运行的最后一条消息，而不是每条都发。 |
| **每行一条消息** | 把回复按行拆开，每行作为一条聊天消息发送。 |
| **渲染 Markdown** | 默认开启，把回复里的 Markdown 转成应用能显示的格式。 |

## 第 5 步：绑定飞书、Telegram 或 QQ

每个渠道的流程都一样：选择对应的标签页，填入凭证，点**保存**，再打开**启用连接**开关。凭证保存之前，这个开关一直不可用。对话框里每个渠道都有**如何创建机器人**一节，列出了具体步骤，并附上平台链接。

### 飞书（及 Lark）

1. 在飞书开发者后台创建一个企业自建应用。
2. 为应用开通机器人能力。
3. 订阅「接收消息」事件，事件订阅方式选择「长连接」。
4. 把应用「凭证与基础信息」页上的 **App ID** 和 **App Secret** 复制到对话框里。如果用的是 Lark，把 **API 域名**设为 `https://open.larksuite.com`；飞书保持 `https://open.feishu.cn` 不变。
5. 发布一个应用版本，并通过审核。
6. 点**保存**，打开**启用连接**开关，然后在飞书里给机器人发一条消息。

飞书在群聊里也能用：发消息时 @机器人即可，消息交给 Agent 之前会去掉这个 @。要让 Agent 能读取你发送的图片和文件，应用还需要开通读取消息资源的权限。

![「远程控制」对话框里的飞书渠道](/blog-assets/remote-control-feishu-zh.png)

### Telegram

1. 在 Telegram 里打开 @BotFather，发送 `/newbot`。
2. 按提示给机器人起名，然后把 @BotFather 返回的 **Bot Token** 复制到对话框里。
3. 点**保存**，打开**启用连接**开关。
4. 在 Telegram 里找到这个机器人，给它发一条消息。

在群聊里，Telegram 的 Group Privacy 设置默认开启：不是群管理员的机器人，只能收到专门发给它的命令。如果你的机器人开着 Group Privacy，**测试连接**会提示你。

### QQ

1. 在 QQ 开放平台注册成为开发者，并创建一个机器人。
2. 在对话框里选择**扫码连接**，用手机上的 QQ 扫码，在打开的页面里选中这个机器人并确认，对话框会替你保存凭证。如果想手动填写，就在机器人的「开发设置」页复制 **App ID** 和 **App Secret**，在「开发配置」里把事件订阅方式设为 WebSocket（不需要填回调地址），再点**保存**。
3. 在 QQ 开放平台上，把你自己的 QQ 号或一个测试群加入机器人的沙箱白名单。
4. 打开**启用连接**开关，然后在 QQ 里给机器人发一条消息。

QQ 只允许机器人回复你刚发出的消息。所以在 Web App 里启动的运行不会同步到 QQ；距离你上一条 QQ 消息几分钟后，回复就发不出去了。想继续，就再给机器人发一条消息。一条 QQ 消息最多能收到 4 条回复（群聊里是 5 条）；一次运行的回复超过这个数时，剩下的内容会合并到最后一条回复里。

QQ 还只能传输文字：机器人读不到你发送的图片和文件，Agent 也无法向 QQ 发送文件。

## 限制与安全

绑定后的对话有几条固定规则。

| 规则 | 说明 |
| --- | --- |
| 一段对话一个渠道 | 同一时间，一段对话上只能启用一个渠道的连接。 |
| 一个机器人一段对话 | 一个机器人同一时间只能在一段对话上启用。要换到另一段对话，先在原来的对话上关闭连接，再到新对话上启用。凭证会一直保留。 |
| 机器人不能先开口 | 机器人无法主动发起聊天。它要先收到你的一条消息，才知道把回复发到哪里。 |
| 微信只支持单聊 | 在群里 @ 微信机器人不会有任何反应，请直接给它发消息。 |
| 服务器必须保持运行 | PenguinHarness 停止期间发出的消息，之后不会补发。 |

> **任何能给机器人发消息的人，都能操控这段对话**。绑定没有发送者白名单，新对话又默认放行所有工具调用。不要公开机器人，也不要把它拉进你管不了的群；能从聊天应用访问的对话，只给它配你不怕暴露的 Workspace 和工具。如果机器人可能被别人找到，就把对话切换到**放行只读**，读取以外的操作都会在浏览器里等你批准。

## 常见问题

- **「启用连接」开关不可用**。先保存凭证，并关闭这段对话上已经启用的其他渠道。只有 Project 所有者能开启连接。
- **「连接状态」显示错误**。检查凭证是否正确。飞书渠道还要检查 **API 域名**，并确认事件订阅用的是长连接。
- **「发送测试消息」不可用**。先给机器人发一条消息。
- **第一条微信消息没有回复**。等**连接状态**显示**已连接**大约 15 秒后，再发一次。第 3 步的提示说明了原因。
- **机器人不理会 Telegram 群里的消息**。把机器人设为群管理员，或者用 @BotFather 关闭 Group Privacy，再把机器人重新拉进群。
- **QQ 里收不到回复了**。距离你上一条 QQ 消息已经超过几分钟。给机器人发一条新消息即可。

## 小结

你把一段对话绑定到了微信，在手机上给它发了一个 Task，并看到回复既发回了聊天，也出现在 Web App 里。飞书、Telegram 和 QQ 用的是同一个对话框，各自保存自己的凭证。对话框里每个字段和开关的详细说明，见[远程控制文档](https://penguin.ooo/docs/remote-control)。
