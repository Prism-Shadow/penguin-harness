PenguinHarness 用真实凭据在真实机器上跑智能体，所以"谁凭什么证明、能做什么"值得确切地知道。本页按你遇到它们的顺序展开：认领新服务器、管理密码、本机自动化、管理远程机器、收回访问权。底层机制——令牌格式、磁盘内容、网络暴露面——集中在文末。

一条原则贯穿所有场景：

> **能读数据根即拥有服务器。** 数据根（默认 `~/.penguin/data`）装着全部模型凭据和全部对话。放在它们旁边的秘密防不住已经能读到它们的人——所以这套模型不假装能防，而是把这份所有权变得可以安全行使：短命、可吊销、永远不要求存储或传输密码。

## 0. 你得到什么

| 能力 | 在哪里 |
| --- | --- |
| 通过启动时打印的登录链接认领新服务器——密码尚不存在，也不会展示 | 启动提示 |
| 密码登录；存储为 scrypt 哈希，尝试被节流 | Web 登录页、`penguin auth login` |
| 桌面应用静默登入自己的窗口 | 窗口打开时的一次性令牌 |
| 凭本机所有权铸造会话——全程不涉及密码 | `penguin auth token` |
| 通过 ssh 管理机器，密码不过线 | Machines 页 |
| 会话是服务端的行：可逐个吊销、跨重启存活、30 天滑动续期 | 所有场景 |
| 每个会话记录自己的建立方式 | `via`：`password`（输入的密码，或 `penguin auth token` 铸造的会话）/ `desktop` / `setup` / `token`（以 Bearer 头携带本地 API token 的请求——不存储会话） |
| 吊销一个会话，或一个用户的全部会话 | 登出 / 管理员重置密码 |
| 在服务器所在机器上找回丢失的管理员密码 | `penguin server reset-admin-password` |

## 1. 认领新服务器

**Web。** 新服务器没有可用的密码：种子值生成后即哈希、丢弃，无人见过。为了仍然让你进来，在密码被设置之前，每次启动都会打印一条登录链接：

```
+--------------------------------------------------------------------+
|   This server has no admin password yet. Open this link to claim:   |
|                                                                     |
|     http://localhost:7364/api/auth/claim?token=...                  |
|                                                                     |
|   The link works until a password is set, and changes on restart.   |
+--------------------------------------------------------------------+
```

打开、落地即已登录、设置密码。这条链接不是一次性的——邮件客户端可能先于你抓取它，第二次打开必须仍然有效——因此靠另外三重边界让它可以放心打印进控制台：

- **只在服务器未被认领时有效。** 密码一旦存在即被拒绝，控制台回滚记录不构成入口。
- 用来比对的那个值**只在内存里，每次重启重新铸造**。更早一次运行的链接会被拒绝；错过提示，重启再读新的即可。
- 错误令牌与已认领的服务器返回**完全一致**——一条过期链接连"属于哪种情况"都无法透露。

在容器里，这条提示打在容器日志（`docker logs`）中，链接里的 `localhost` 是服务端对自己的称呼——把它换成你实际访问容器所用的地址，令牌保持不变。`PENGUIN_SEED_ADMIN_PASSWORD` 可以改为直接钉死密码，但仅在空数据目录的首次启动时生效。

它授予的会话带 `via: setup`，恰好持有一项特殊豁免——免旧密码设置密码，因为旧密码并不存在——再无其他：尤其是，不含任何桌面专属路由。

**桌面。** 客户端拥有它内嵌的服务进程，它的窗口凭这一事实被放行：窗口的首次导航兑换一枚由客户端铸造的一次性令牌，落地即以 `via: desktop` 登录。令牌在兑换的瞬间死亡——泄露的 URL 无法重放。

无论来自哪里，密码登录都按用户名指数退避节流——不存在的用户名以完全相同的方式节流，时间上看不出账号是否存在。

## 2. 密码

选定的密码只以一种方式存储：scrypt 哈希（`N=16384`，每密码随机盐，参数随哈希保存，成本可日后提高）。设置密码有四条路，各由"谁在请求"决定形状：

- **你，知道当前密码**——用户设置页。先验当前密码。
- **你，处在一个从未有过密码的会话里**——`setup` 会话（§1），或桌面客户端自己的窗口。两者的账号密码都是无人见过的随机值，"旧密码"框里没有东西可填；会话的来历就是授权。
- **管理员，为另一个用户**——该账号获得新的初始密码，其持有的所有会话被吊销（§5）。
- **没人记得管理员密码**——在服务器所在机器上、停止服务后执行 `penguin server reset-admin-password`。本机文件系统访问就是授权。账号回到未认领状态、会话全部吊销，救援不产生任何需要抄写的东西——启动服务，按 §1 用链接认领。

## 3. 本机自动化

脚本和 CLI 永远不需要密码，因为本机所有权本就高于密码。会话就是数据根 `web.db` 里的一行，所以 CLI 直接写入一行：

```bash
penguin auth token          # 无密码、无提问：插入一行会话
```

能读写那个数据根就是全部授权，而且它不带来任何新权限——数据根本就装着这枚令牌所能触及的一切凭据。服务在跑或不在跑都能用，在跑时也安全——前提是该数据根上服务至少启动过一次，因为它铸造的账号就在那个根的 `web.db` 里。令牌默认活一小时（`--ttl-seconds` 可另设），作为普通密码会话行事，永远不是桌面那种。

在多用户机器上，这个界定正是要点：数据根属于运行服务的那个操作系统账号，因此只有该账号能铸造。其他人一律用密码登录——`penguin auth login --server <url>`。

## 4. 远程机器：ssh 权限即 CLI 权限

Machines 页通过 ssh 管理其他机器，一切都运行在 ssh 账户的身份之下：

- 要操作某台机器的 API，控制端**通过 ssh 在那台机器上**执行 `penguin auth token`：那台机器自己的 CLI 往那台机器自己的数据库里写一行会话。过线的只有一枚一小时的会话令牌。
- **密码永不过线。** 机器的管理员密码留在那台机器上；ssh 已经证明了密码所能证明的一切。
- 这个等式两面成立。ssh 到一台机器就能徒手读它的数据根，令牌没有授予 ssh 未曾授予的任何东西——也正因如此，**你的 ssh 私钥是它所能到达的所有机器的主凭据**，请按这个等级保护。
- 项目向机器同步模型凭据时，API key 进入各机器自己的项目配置（0600）：替你跑智能体的机器，必然持有智能体运行所用的 key。

## 5. 收回访问权

| 要吊销 | 操作 | 效果 |
| --- | --- | --- |
| 一个会话 | `penguin auth logout`，或界面登出 | 立即——行被删除，而行即会话 |
| 一个用户的会话 | 管理员重置该用户密码 | 立即——该账号的全部行被删除 |
| 管理员自己的会话 | 停止服务后执行 `penguin server reset-admin-password` | 下次启动时生效，并打印新的首次登录链接 |
| 模型 API key | 在服务商处轮换，更新项目配置 | 取决于服务商 |

这套设计围绕的正是最坏的那个场景——**整个数据根备份泄露**。应对只是一次针对其中模型 API key 的凭据轮换，仅此而已：备份里的密码是 scrypt 哈希，会话表里只有每枚令牌的 sha256、从来没有令牌本身。从备份里抄出来的任何东西都无法作为会话呈递给线上服务器。

## 底层机制

**会话。** Cookie 里装的是 32 字节随机令牌；以其 sha256 为键的 `auth_sessions` 行才是会话，行里存账号、来历（`via`）和过期时间。因为行即会话，删除它即刻吊销，而重启不会登出任何人。浏览器会话 30 天，临近过期**原地**续期——移动的是行的过期时间，Cookie 的值不变——因此常规使用中的会话永不过期，也从不产生需要追杀的第二个副本。只有自身期限达到续期窗口的会话才滑动，所以一小时的铸造令牌就在一小时到期。Cookie 为 HttpOnly、SameSite=Lax；只有请求确实是 https、或**受信任的**代理这样声明时（`PENGUIN_TRUST_PROXY=1`）才加 Secure，该头默认被忽略。

**磁盘上有的，和刻意没有的。**

| 文件 | 内容 | 存续 |
| --- | --- | --- |
| `web.db` | 密码**哈希**、会话**哈希**、应用数据 | 永久 |
| `<project>/.project_config.toml` | 模型 API key，内联，0600 | 直到被编辑 |
| `cli-session.json` | 一枚活跃会话令牌，0600 | 到登出或过期 |

从不以可用形式落盘的：会话令牌（只有其 sha256）、以及一切密码——选定的以 scrypt 哈希存在，种子在诞生时即被丢弃。模型 API key 是无法消除的剩余项：它们必须原样抵达上游服务商，无法哈希。它们被限制在项目配置里，在所有 API 响应和界面上被掩码，只在发出请求的那一刻以明文被读出。

**网络暴露面。** 服务默认绑定 127.0.0.1；对外暴露（`HOST=0.0.0.0`）是部署决定，应置于 TLS 终结之后，由代理设置 `x-forwarded-proto`。API 只在规范应用主机名下应答，这让用户生成的预览内容与应用 cookie 处于不同的浏览器源。跨站请求伪造由两层独立防线阻断：SameSite=Lax cookie，加一道 Content-Type 闸——凡 HTML 表单能够产生的内容类型的写请求，一律拒绝。
