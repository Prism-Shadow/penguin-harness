侧边栏里的**浏览器**面板承载着 Agent 在 shell 里用 `penguin browser` 驱动的浏览器：Agent 读取页面、点击和输入，并提取亚马逊订单这样的数据，登录用的是你自己的账号。它有两种后端：

- **内置浏览器**：桌面应用里的网页浏览器。你可以像使用任何浏览器一样在其中浏览，Agent 驱动的也是同一组标签页。它有自己的登录状态和历史记录，与系统浏览器互不相通，两者都可以从 Chrome、Edge、Brave、Arc、Vivaldi、Opera、Chromium 或 Firefox 导入。
- **你自己的 Chrome**：经由 PenguinHarness Browser 扩展，桌面应用和 Web App 都能用。Agent 在你 Chrome 里名为 **Penguin** 的标签组中工作，沿用你已有的登录状态，从不触碰你的其他标签页。

从哪里开始：

- 第一次使用，见[打开浏览器面板](#打开浏览器面板)。
- 想让 Agent 使用你的 Chrome，见[使用你自己的 Chrome](#使用你自己的-chrome)。
- 想让 Agent 在内置浏览器里使用你的账号，见[登录](#登录)和[从你的浏览器导入](#从你的浏览器导入)。
- 想自己写自动化，或了解 Agent 在做什么，见[在命令行中驱动](#在命令行中驱动)。
- 内置浏览器变得吃力或页面崩溃时，见[性能](#性能)。

## 开始之前

- **内置浏览器**是 macOS、Windows 和 Linux 桌面应用的一部分。用浏览器登录服务器（`penguin web`）、在 Docker 中或在远程机器上都没有它。
- **你自己的 Chrome** 在任何允许它的服务器上都能用，服务器缺省允许。它需要 Chrome 116 或更新版本，以及 PenguinHarness Browser 扩展。
- 桌面应用缺省使用内置浏览器，直到你[切换](#在内置浏览器与-chrome-之间切换)；其他服务器只提供 Chrome。Agent 从不自行选择后端；一种后端不可用时，也不会改用另一种。
- Agent 驱动的是正在驱动其对话的那个人的浏览器：发出启动本轮运行那条消息的人；如果是定时任务，则是创建它的人。在有多个账号的服务器上，每个人各自配对自己的 Chrome，Agent 从不使用别人的 Chrome。

## 打开浏览器面板

在对话工具栏右上角选择**右侧栏**或**下侧栏**，再选择**浏览器**。如果侧栏里已经有别的面板，就用它的**添加面板**菜单。见[使用侧边面板](/chat#使用侧边面板)。

整个应用只有一组浏览器标签页。每个对话的侧栏显示的都是同一组标签页，所以 Agent 在一个对话里打开的页面，切换到另一个对话后依然在。

从[浏览](#浏览)到[清除浏览数据](#清除浏览数据)这几节讲的是内置浏览器。Agent 使用你自己的 Chrome 时，面板显示的是[你 Chrome 里的标签页](#在浏览器面板中)。

Agent 在你正在查看的对话里打开页面时，侧栏会自动切换到浏览器面板，方便你旁观。

## 浏览

- 标签栏显示每个标签页的图标和标题。选择 **+** 新开标签页，选择 **×** 关闭标签页。
- 面板里始终有一个标签页。没有标签页时（第一次打开面板、应用重启后、最后一个标签页关闭后），面板会立即新开一个。如果 Agent 在面板不可见时关闭了最后一个标签页，新标签页会在你再次打开面板时出现。
- 工具栏上有**后退**、**前进**、**重新加载**（页面加载时变为**停止加载**）和地址栏。输入 URL 即可打开；只写域名（如 `amazon.com`）时以 `https://` 打开；其他内容则用 Bing 搜索。输入时会列出浏览器历史记录中的页面，可用方向键和回车选择。
- 工具栏的菜单里有**从浏览器导入…**、**清除浏览数据…**、**设置主页…**、**在系统浏览器中打开**和**开发者工具**。
- 会打开新窗口的链接和页面弹窗，都以新标签页打开。一个页面每五秒最多打开三个标签页，超出的会被忽略。
- 下载文件时会询问保存位置，与系统浏览器一样。

面板跟随应用的浅色或深色主题；页面本身保持各自的配色。

## 设置主页

主页是每个新标签页打开的页面：选择 **+** 新开的、面板在没有标签页时自动新开的，以及 Agent 不带地址新开的标签页，都会打开主页。加载期间，标签页已经显示主页的地址。没有设置主页时，新标签页为空白页，地址栏等待输入网址。

1. 在工具栏的菜单中选择**设置主页…**。
2. 输入网址。它按地址栏的规则解读：只写域名（如 `example.com`）时以 `https://` 打开，输入框下方会显示将要打开的页面。要使用屏幕上的页面，选择**使用当前页面**。
3. 选择**保存**。

设置了主页后，**重新加载**旁会出现**主页**按钮，点击即打开主页。要去掉主页，在同一个对话框中选择**清除**，再保存空的输入框。

## 打开对话中的链接

在对话里的网页链接上右键，或在链接获得焦点时按 Shift+F10 或菜单键，会打开链接的菜单：

- **在内置浏览器中打开**：在新标签页中打开链接，并让该对话的侧栏切到浏览器面板。浏览器可用时出现。Agent 使用你的 Chrome 时，这一项是**在 Agent 的 Chrome 标签页中打开**，链接会在你 Chrome 的 Penguin 标签组里打开。
- **在系统浏览器中打开**：用默认浏览器打开链接。在浏览器窗口中，这一项是**在新标签页中打开**。
- **复制链接地址**：复制这个链接。

如果同时选中了对话中的文字，分隔线下方接着是**复制**和**添加到对话**。指向 Workspace 文件的链接仍在文件面板中打开；在对话的其他位置右键，出现的仍是选中文字的菜单。

## Agent 使用浏览器时

Agent 在某个标签页里工作时，页面四周会有一圈缓慢脉动的光环，工具栏上也会出现一个图标提示。Agent 的命令通过浏览器的开发者工具作用于页面，而不是借用你的鼠标和键盘，所以你旁观时屏幕上的指针不会乱动。Agent 工作期间请不要在页面里点击：你的点击会在 Agent 不知情的情况下改变页面。

Agent 操作期间页面弹出的对话框会被自动应答，页面不必等你处理：提示框一律接受；确认框和离开页面对话框默认拒绝，除非 Agent 要求接受。你自己浏览时弹出的对话框照常显示。

屏幕上的页面按面板的尺寸排版，面板较窄时，网站可能显示它的移动版布局。你没有在看的页面（位于其他标签页，或侧栏已关闭）仍保持加载，尺寸沿用最后一次显示时的大小，从未显示过的则为 1280×800，Agent 可以继续在其中工作。

## 登录

在面板里登录网站，与在任何浏览器里一样。登录状态和网站数据保存在内置浏览器自己的配置里，重启后依然有效：在这里登录不会让系统浏览器也登录，反之亦然。

Agent 从不输入你的密码。Agent 需要的页面要求登录时，`browser-automation` Skill 会让它停下来，请你在面板里自己登录，或者从你平常使用的浏览器导入登录状态。在你自己的 Chrome 里，你已有的登录状态直接生效；缺少某个登录时，Agent 会请你在它的 Penguin 标签页里登录。

## 从你的浏览器导入

导入会把本机某个浏览器中一个个人资料的 Cookie（其中保存着你的登录状态）和历史记录复制到内置浏览器。

1. 在工具栏的菜单中选择**从浏览器导入…**。
2. 选择一个个人资料。个人资料按浏览器分组，名称与浏览器中显示的一致。
3. 选择 **Cookie 与登录状态**、**历史记录**，或两者都选。
4. 可以填写只导入哪些网站的 Cookie，用逗号分隔，例如 `amazon.com, github.com`。网站包括它的子域名。留空则导入所有网站的 Cookie。
5. 开始导入。对话框会显示找到和导入的 Cookie 与历史记录条数，以及警告信息。

| 浏览器 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| Chrome、Edge、Brave、Vivaldi、Opera、Chromium | 支持 | 支持 | 支持 |
| Arc | 支持 | — | — |
| Firefox | 支持 | 支持 | 支持 |

各平台的注意事项：

- **macOS**：基于 Chromium 的浏览器用保存在钥匙串里的密钥加密 Cookie，因此 macOS 会询问是否允许 PenguinHarness 使用以浏览器命名的钥匙串项目，例如「Chrome Safe Storage」。请选择允许；拒绝的话，加密的 Cookie 会被跳过，导入结果中会说明。
- **Windows**：Chrome 127 及以后的版本用应用绑定加密保护大部分 Cookie，只有 Chrome 自己能读取。这些 Cookie 会被跳过并给出警告，请改为在面板里登录。正在运行的浏览器也可能占用它的 Cookie 文件，关闭浏览器后再导入即可。
- **Linux**：较新的 Cookie 用保存在桌面密钥环里的密码加密，通过 `secret-tool` 读取（Debian 和 Ubuntu 上由 `libsecret-tools` 软件包提供）。没有它时，这些 Cookie 会被跳过并给出警告。
- **Firefox** 的 Cookie 不加密。容器专用的 Cookie 和按其他网站分区的 Cookie 不会导入。

导入只读取数据：每个文件都先复制到临时目录，在那里读取后删除，不会向另一个浏览器写入任何内容。导入的历史记录与内置浏览器自己的历史记录合在一起保存，最多保留最近的 5,000 个页面。只有管理员可以导入。

在 shell 里，`penguin browser import --list` 列出个人资料，`penguin browser import --from chrome --cookies --domain amazon.com` 导入一个网站的登录状态，见 [penguin browser](/cli#penguin-browser)。

## 清除浏览数据

在工具栏的菜单中选择**清除浏览数据…**，再选择要清除的内容：Cookie 与登录状态、缓存文件、网站存储或浏览历史记录。这只影响内置浏览器。

## 使用你自己的 Chrome

Agent 可以在你自己的 Chrome 里工作，而不是在内置浏览器里：带着你的登录状态、扩展和设置，在桌面应用里或在任何服务器的 Web App 里都可以。PenguinHarness Browser 扩展把你的 Chrome 连到服务器，Agent 只驱动你交给它的标签页。

### 安装扩展

扩展随每个版本以 zip 文件发布，之后会上架 Chrome Web Store。

1. 下载 [penguin-browser-extension.zip](https://github.com/Prism-Shadow/penguin-harness/releases/latest/download/penguin-browser-extension.zip) 并解压。
2. 在 Chrome 中打开 `chrome://extensions`，打开右上角的**开发者模式**。
3. 选择**加载已解压的扩展程序**，选中解压出的文件夹。
4. 在扩展菜单里把 **PenguinHarness Browser** 固定到工具栏，它的图标会显示是否已连接。

随后 Chrome 会打开扩展的配对页。Chrome 每次启动时会提醒你有处于开发者模式的扩展，扩展照常工作。更新时，把新版本解压覆盖到同一个文件夹，再选择扩展卡片上的重新加载图标。

扩展的页面缺省为英文，不随 Chrome 的语言变化。配对页顶部和弹窗底部的 **EN / 中文** 可切换语言，两个页面和工具栏图标的提示文字随即一同切换。

### 与服务器配对

配对会给你的 Chrome 一把钥匙，对应你在某一台服务器上的账号。你需要服务器地址，以及从 Web App 获得的一次性配对码。

1. 在 Web App 中打开**浏览器**面板。还没有配对 Chrome 时，面板里直接显示配对步骤；否则在面板的菜单中选择**连接你的 Chrome…**，或在**设置 › 浏览器**中选择**连接另一个 Chrome**。
2. **连接你的 Chrome** 对话框给出**服务器地址**和**配对码**，各带一个复制按钮。配对码只能用一次，10 分钟内有效；**换一个**会生成新的配对码并取代旧的。
3. 在 Chrome 中选择扩展的图标，再选择**设置**，打开配对页。粘贴服务器地址和配对码，选择**连接**。

对话框底部的**正在等待 Chrome…**会变为**已连接**，随后对话框自行关闭。服务器地址就是浏览器里 Web App 的地址，所以位于反向代理之后的服务器用它的公开地址配对。桌面应用的地址是 `http://localhost:<port>`；端口一旦改变，需要重新配对。

**设置 › 浏览器**列出你已配对的 Chrome：名称、扩展版本、最近连接时间，以及标出当前连接的状态点。**撤销**会先请你确认，然后断开这个 Chrome 并让它的钥匙失效：Agent 不能再使用它，要再次使用必须重新配对。

### 在浏览器面板中

Agent 使用你的 Chrome 时，面板显示的是它的标签页，而不是页面本身：

- 标签栏列出 Agent 在你 Chrome 里驱动的标签页。**+** 在 Chrome 里新开一个标签页，打开主页或空白页；**×** 关闭标签页。
- 工具栏上有地址栏（在当前标签页打开输入的网址）和菜单。
- 页面区显示**此标签页在你的 Chrome 中打开**；**在 Chrome 中显示**会把 Chrome 切到前台并显示该标签页。
- Agent 在某个标签页里操作时，与内置浏览器一样，有脉动的光环和工具栏上的图标提示。
- 你的 Chrome 未连接时，面板显示 **Chrome 未连接**、已配对的 Chrome 的名称，以及**重新连接帮助**。管理员关闭了 Chrome 连接时，面板显示 **Chrome 连接已关闭**。

菜单里的状态行显示「Chrome：已连接 · <名称>」「Chrome：未连接」「尚未配对 Chrome」或「Chrome 连接已关闭」，旁边是**连接你的 Chrome…**或**管理…**。

### Agent 能触及的范围

Agent 只驱动这些标签页：

- 它自己打开的标签页。它们位于名为 **Penguin** 的蓝色标签组中，每个窗口一个（Chrome 与多台服务器配对时，组名为 **Penguin · <服务器>**）。
- 你交给它的标签页：在该标签页上选择扩展的图标，再选择**添加此标签页**，它会移入 Penguin 标签组。
- 由上述标签页打开的页面，例如弹窗或在新标签页中打开的链接。

它看不到也碰不到你的其他标签页和窗口、Cookie、密码、历史记录和下载内容，触及这些内容的原始 DevTools 命令会被拒绝（`cdp_refused`）。Chrome 自己的页面（`chrome://`）、Chrome Web Store 和本地文件完全无法驱动。导入、清除浏览数据和浏览历史记录属于内置浏览器；Chrome 有它自己的。

到达服务器的，是 Agent 向被驱动的标签页索取的内容，与内置浏览器相同：简化后的 HTML 或纯文本、脚本的返回值、截图和对话框文字。页面中的脚本能读到页面本身可读的 Cookie；HttpOnly 的会话 Cookie 永远不会离开 Chrome。

### 收回标签页或让 Agent 停手

- Agent 工作时，Chrome 会显示一条提示栏，说明 PenguinHarness Browser 正在调试此浏览器。Agent 的最后一条命令过去一分钟后，提示栏消失，下一条命令到来时再出现。选择提示栏上的**取消**，会一次收回所有标签页；在你再次交出之前，Agent 不能再使用它们。
- 要收回单个标签页，把它拖出 Penguin 标签组、关闭它，或在它上面选择扩展的图标，再选择**收回此标签页**。Agent 对它的下一条命令会失败并返回 `tab_released`，Agent 会改为新开一个标签页。
- 扩展弹窗里的**暂停**会拒绝所有命令，直到你选择**继续**；标签页保持原样。
- 在**设置 › 浏览器**中**撤销**这个 Chrome，在 `chrome://extensions` 中停用扩展，或在桌面应用中切回内置浏览器。

### 多台服务器与多个 Chrome

一个扩展可以同时与多台服务器配对，例如桌面应用和一台托管的 Web App，每台服务器的标签页各占一个标签组。你也可以把不同电脑上的多个 Chrome 配对到同一个账号：同一时间只有一个保持连接，最后连上的那个接管。

### 在反向代理之后

扩展通过 `/api/builtin-browser/extension/ws` 上的 WebSocket 连接服务器。反向代理必须为这个路径转发 `Upgrade` 头，与终端流相同。配对请求来自扩展自己的来源，服务器只对这个来源作答。

## 在内置浏览器与 Chrome 之间切换

在桌面应用中，由你决定 Agent 使用哪个浏览器：

- 在**浏览器**面板的菜单中，在**浏览器**下选择**内置**或**系统 Chrome**。
- 或者在**设置 › 浏览器**中设置 **Agent 使用的浏览器**。

切换后会有提示确认，例如「Agent 现在使用你的 Chrome」。Agent 正在操作浏览器时，切换会被拒绝，并提示「Agent 正在使用浏览器，等它完成后再切换」。切换不会关闭任何东西：内置浏览器的标签页在后台保持打开，Penguin 标签页也留在 Chrome 里。应用的每个窗口都会随之切换。其他服务器上只有 Chrome，不会出现这个选项。

## 关闭 Chrome 连接

管理员可以禁止所有用户的 Chrome 连接：在**设置 › Chrome 扩展**中关闭**允许 Chrome 扩展连接**。它缺省开启。关闭前会先请你确认，随后立即断开所有已连接的扩展，所有人的 Chrome 后端都不可用（`extension_disabled`）。配对会保留：重新开启后，扩展会在一小时内自行重连。

## 在命令行中驱动

`penguin browser` 在 shell 中驱动这些标签页，Agent 也正是这样使用浏览器的，内置浏览器和你自己的 Chrome 都一样。预装的 `browser-automation` 插件教给 Agent 一个循环：打开页面、读取页面、用 JavaScript 操作，再检查页面发生了什么变化。`penguin browser status` 会说明当前使用哪个后端，Agent 无法更改它。

```bash
penguin browser open https://www.amazon.com/your-orders/orders
penguin browser scan --text
penguin browser exec <<'EOF'
return [...document.querySelectorAll('.order-card')].length;
EOF
```

- `scan` 以简化后的 HTML 输出页面，加 `--text` 时输出纯文本：隐藏、浮动和被遮挡的元素会被去掉，长列表只保留三项，并附上一条提示，给出其余条目的选择器。
- `exec` 在页面中运行 JavaScript，报告返回值、有多少元素发生变化、出现后又消失的提示，以及新打开的标签页。
- `click` 和 `type` 发送真实的鼠标和键盘输入，页面无法把它们与真人操作区分开。
- 其余由 `screenshot`、`cdp`（一条原始的 Chrome DevTools Protocol 命令）和 `history` 完成。

每条命令及其输出格式见 [CLI 参考](/cli#penguin-browser)。

## 性能

本节说的是内置浏览器；你自己的 Chrome 自行管理它的标签页。

每个标签页都是一个完整的网页，各自占用内存：繁忙的购物或新闻网站通常占用 100 到 300 MB，有的超过 1 GB。应用会留意浏览器用了多少内存，在用得太多之前提醒你。

- **出问题之前先提醒。** 当所有标签页合计使用超过 1.5 GB 内存、这台电脑的可用内存不足 10%（macOS 上不测量此项），或打开了超过 12 个标签页时，浏览器工具栏上会出现一个琥珀色的警告图标，悬停可以看到浏览器用了多少内存、分布在几个标签页里。警告出现时会弹出一次提示，占用内存最多的几个标签页会在标签栏里带一个小警告标记。请关闭不再需要的标签页。`penguin browser status` 会在 `memory:` 一行打印同样的数字，警告持续期间还会多一行 `warning:`。
- **后台标签页放慢运行。** 没有 Agent 在用的标签页不在视野中时，其定时器可能被放慢到大约每秒一次，与浏览器对待后台标签页的方式相同。Agent 正在使用的标签页全速运行：每次操作期间以及之后 30 秒内都是如此，新打开的标签页在加载时也是一样。
- **页面崩溃后，标签页仍在。** 页面的进程结束时（崩溃了，或者系统收回了它的内存），标签页会显示 **此页面已崩溃** 和 **重新加载** 按钮，而不是一片空白，应用的其余部分照常工作。Agent 再使用这个标签页时会立即得到 `tab_crashed`。如果是应用自己的窗口出错，窗口会重新加载；反复出错时，每次重试之间会等得更久，浏览器的标签页也会随之关闭。
- **用于反馈问题的日志。** 桌面应用会把各个进程的运行情况记录在 `desktop.log` 里，包括每一个意外结束的进程及其原因。文件写满 5 MB 后重新开始，并把上一个文件保留为 `desktop.log.1`。反馈崩溃问题时，请附上这两个文件：

| 系统 | 日志文件 |
| --- | --- |
| macOS | `~/Library/Application Support/PenguinHarness/logs/desktop.log` |
| Windows | `%APPDATA%\PenguinHarness\logs\desktop.log` |
| Linux | `~/.config/PenguinHarness/logs/desktop.log` |

## 工作原理

- 每个标签页都是桌面应用承载的一个 Chromium 页面，使用内置浏览器自己的持久化配置。在页面看来，这就是一个普通的 Chrome 浏览器。
- 服务器通过 Chrome DevTools Protocol 驱动页面，由桌面应用转发。读取页面、运行脚本、点击和输入都在这条链路的服务器一侧完成，因此会随服务器更新而改进。
- 读取页面与追踪变化所用的脚本改编自 [GenericAgent](https://github.com/lsdefine/genericagent)（MIT 协议），包括它的 DOM 简化以及 `web_scan` / `web_execute_js` 的设计。
- 历史记录和主页是数据根目录下的两个文件：`builtin-browser/history.json` 和 `builtin-browser/settings.json`。Cookie 和网站存储保存在桌面应用自己的配置目录里。
- 使用你自己的 Chrome 时，服务器经由扩展的 WebSocket 发出同样的命令，扩展再通过 Chrome 的调试接口转给标签页。每个已配对的 Chrome 都有自己的钥匙，它放在 WebSocket 的子协议里传递，从不出现在地址中；服务器只保存它的散列。扩展本身不申请读取页面内容的权限，也不向页面注入任何东西。
- 一切操作都经过服务器的 `/api/builtin-browser` 路由。内置浏览器、导入、历史记录和清除数据只对管理员开放；任何已登录的用户都可以配对并使用自己的 Chrome。见 [Agent 浏览器](/server-api#agent-浏览器)。

## 限制

| 项目 | 限制 |
| --- | --- |
| 可用范围 | 内置浏览器：仅桌面应用。你自己的 Chrome：任何允许它的服务器，Chrome 116 或更新版本 |
| 标签页 | 每种后端最多 20 个；超出时新建标签页会被拒绝（`too_many_tabs`） |
| 连接的 Chrome | 每个用户同一时间一个；最后连上的那个接管 |
| Chrome 中无法驱动的页面 | `chrome://` 页面、Chrome Web Store、本地文件 |
| 导入、清除数据、历史记录 | 仅内置浏览器（在你的 Chrome 中返回 `not_supported`） |
| 配对码 | 只能用一次，10 分钟内有效；输错五次即作废 |
| 负载警告 | 标签页合计超过 1.5 GB 内存、这台电脑的可用内存不足 10%，或超过 12 个标签页 |
| `scan` 正文 | 默认 35,000 个字符（`--max-chars`）；加 `--text` 时取其三分之一 |
| `exec` 显示的返回值 | 8,000 个字符；`--save` 把全部内容写入文件 |
| `exec` 脚本时限 | 默认 15 秒（`--timeout`） |
| 页面加载等待 | `open` 最多等 15 秒 |
| 历史记录 | 最近的 5,000 个页面，含导入的部分 |
| Windows 上导入 Cookie | Chrome 的应用绑定 Cookie（Chrome 127 及以后）无法导入 |
