- **想确认当前版本？** 见[查看当前版本](#查看当前版本)。

- **用的是桌面应用？** 见[更新桌面应用](#更新桌面应用)。
- **装的是 CLI？** 见[更新 CLI 安装](#更新-cli-安装)。
- **在 Docker 里运行？** 见[更新 Docker 部署](#更新-docker-部署)。

## 查看当前版本

在 Web App 里：

- 新对话页的版本行会显示正在运行的版本，形如 `vX.Y.Z · 最近更新日期 7月26日`。日期由发布流程在构建时写入，所以不联网也能显示。开发构建，以及引入日期写入之前的发布版（v0.1.2 及更早）没有日期。
- 在侧边栏的用户菜单里，紧贴**设置**下方的更新行会在右侧以浅色显示当前运行的版本。

在终端里：

- `penguin -v` 与 `penguin version` 相同，输出当前构建的单行标识；`penguin version --json` 输出完整的构建信息。见 [penguin version](/cli#penguin-version)。
- `penguin update --check` 报告已安装的版本和最新版本，不做任何改动。

## 通过 Web App 更新

更新的交互和常见的应用更新器一样，集中在一个弹窗里完成。

### 打开更新弹窗

有两个入口可以打开更新弹窗：

- 侧边栏用户菜单里紧贴**设置**下方的更新行。这一行会显示更新到了哪一步：**检查更新**、**检查中…**、**新版本 vX 可用**、**正在下载 vX 42%** 或**重启以更新到 vX**。无论显示哪种状态，点击都会打开弹窗。
- 新对话页版本行上的小上标。有新版本时显示**有新版本可用**，下载中显示**正在下载更新**，下载就绪后显示**重启以更新**。

### 执行更新

1. 打开更新弹窗。如果还不知道有没有新版本，弹窗会先检查一次。应用每次加载页面时也会向 GitHub 查询一次，而从弹窗发起的检查会绕过缓存的结果。
2. 有新版本时，弹窗会列出它，并附上**更新说明**链接。在你继续之前，不会下载任何内容。
3. 点击**下载并更新**，进度条会跟随下载进度。
4. 如果想继续做别的事，点击**放到后台**。弹窗会关闭，但不会取消任何操作：更新行继续显示下载百分比；新版本就绪后，用户按钮上会出现圆点，并弹出一条提示。
5. 点击**重启并更新**，完成更新。

> [!NOTE]
> 非管理员可以查看更新说明，但不能执行更新。

下载失败时，弹窗会显示更新命令自己的输出，并提供**重试**。无法自更新的安装方式，例如源码检出、无法识别的目录布局或 Windows，会在弹窗里说明原因。

### 服务端上的更新过程

- 下载就是在后台运行 `penguin update`，进度条读取的是安装器自己的进度。数据目录不受影响。
- 服务由 `penguin web` 或 `penguin server` 托管时，重启是真实发生的：服务会以新版本重新运行，页面自动刷新。
- 用其他方式启动的服务，弹窗会提示你手动重启。

## 更新桌面应用

在桌面应用里，同一个弹窗驱动的是应用自带的更新器。这只发生在应用自己的窗口里，服务端的版本不会在那里出现。

应用会按自己的节奏检查新版本，但从不自行下载。查到的新版本会显示为用户按钮上的圆点，并出现在更新行里。安装步骤如下：

1. 打开更新弹窗。
2. 点击**下载并更新**。显示的百分比就是更新器的真实进度。
3. 点击**重启并更新**。应用会重启，并运行已下载的新版本。

应用的原生菜单项 **Check for Updates…** 也会在原生对话框里提供同样的「先下载、再重启」两步。

> [!NOTE]
> 用密码登录同一台桌面模式服务端的浏览器，完全看不到更新入口：它既读不到那台机器的更新器状态，也无法重启应用窗口，更不能在那台服务端上运行 CLI 自更新。

有两种形态的应用无法替换自身，弹窗会说明这一点：一种是由系统包管理器管理的 Linux 安装（`.deb`），需要通过包管理器更新；另一种是开发运行。安装包的说明见[桌面应用](/quickstart-desktop)页面。

### 应用自带的 `penguin` 命令

桌面应用安装的 `penguin` 命令与应用来自同一次构建，所以更新应用时命令也会随之更新。用这个命令运行 `penguin update` 不会改动任何东西：它会说明这个命令会随应用更新一起替换，并提示你到应用菜单里检查更新。

## 更新 CLI 安装

`penguin update` 会按当初的安装方式原地升级：

```bash
penguin update --check     # report versions only
penguin update             # upgrade to the latest release, after confirming
```

| 安装方式 | `penguin update` 的做法 |
| --- | --- |
| 压缩包安装（`install.sh`） | 重新运行官方安装脚本 |
| npm/pnpm/yarn/bun 全局安装 | 执行对应包管理器的全局安装 |
| 源码检出 | 拒绝执行，请用 `git pull` 更新并重新构建 |

`--release <tag>` 可以指定某个发布版，`-y` 跳过确认。数据目录始终保持不变。

> [!NOTE]
> 在 Windows 上，`penguin update` 不会原地升级，而是告诉你应该运行什么。用 Windows 安装器装的，重新运行安装器即可升级。

重新运行安装脚本同样可以升级，文件以原子方式替换。全部选项和下载来源规则见 [penguin update](/cli#penguin-update)，安装器的说明见[安装参考](/quickstart-cli#安装参考)。

## 更新 Docker 部署

拉取新的镜像 tag，然后重建容器。数据目录在数据卷上，会原样保留：

```bash
docker compose pull && docker compose up -d
```

不支持在容器内部更新，详见[升级容器](/quickstart-docker#升级容器)。

## 关闭更新检查

设置 `PENGUIN_UPDATE_CHECK=off` 可以关闭自动的版本检查。它只关掉这一项：模型请求、已启用的远程控制连接、Key 授权和代理测试照常联网。关闭后，更新弹窗会显示**更新检查已关闭（PENGUIN_UPDATE_CHECK=off）**。见[配置参考](/configuration#环境变量)。
