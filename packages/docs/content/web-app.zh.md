PenguinHarness 自带一个开箱即用的 Web App：多用户登录、流式对话、Agent 配置、模型与用量管理都在浏览器中完成。本文按页面组织，逐一介绍各页面的功能与操作。安装与首次启动见[快速开始](/quickstart)。

## 目录结构

```text
packages/web/src
├── api/          # fetch 封装 · 每个 API 一个函数(DTO type-only 来自 @prismshadow/penguin-server/api)· SSE 封装
├── state/        # auth / project / sessions / theme / locale 五个 context
├── lib/omni/     # OmniMessage 流 → 渲染视图模型 reducer;连接先行 + 去重的流控制器
├── components/   # ui 原语(modal / drawer / select …)与应用布局
└── features/     # chat / agents / skills / models / usage / traces / benchmark / admin 各页面
```

## 启动与登录

```bash
penguin web
# 打开 http://127.0.0.1:7364
```

初始账号为 `admin`，它一开始并没有自己的密码：在设置密码之前，每次启动服务端都会以边框提示打印一条首次登录链接，打开该链接即以登录态进入浏览器并设置密码。该链接在密码存在之前一直有效，可以重复打开。系统不开放自助注册：账号由管理员在用户管理页创建；每个新用户会自动获得一个独立的初始 Project，命名为 `<userId>-default_project`。仍在使用初始密码时，页面会以横幅提示尽快修改。用户忘记密码由管理员在用户管理页重置；**管理员**自己忘记密码时，停止服务后执行 `penguin server reset-admin-password` 离线把账号恢复成未认领状态，首次登录链接随之回来。

登录状态保持 30 天（滑动续期）；管理员重置密码会使该用户的全部登录会话失效。

界面语言（中文 / English / 跟随系统）与主题（浅色 / 深色 / 跟随系统）可随时切换。

## Chat 页面（/chat）

### 新建会话

新会话从草稿开始：先选择 Agent、Workspace（服务器端目录浏览器选取）、审批模式、模型与思考等级，再发送第一条消息。Session 在首次发送时才真正创建，此后该会话的模型与 Workspace 即被锁定。草稿里切换思考等级或模型时，切换后的值即成为新的默认：思考等级立即写回所选 Agent 的 `model.thinking_level`，所选模型则作为下一个新会话的默认延续。进行中的会话里，思考等级属于该会话：输入区拾取器初始显示 Agent 配置的档位并自动跟随（未选择时发送不携带档位，配置修改持续生效）；一旦选定，该档位**存在 Session 上**——刷新页面、换一个标签页打开都保持不变，此后该会话的每次运行都用它，Agent 配置再改也不会把它带走，同时依旧不写回 Agent 配置。会话中途切换思考等级会先弹确认框，因为中途切换会降低提示词缓存命中率、增加成本——确认框提供三种选择：**压缩后切换**（推荐，等同于先执行 `/compact` 压缩上下文，压缩结束后应用新档位；压缩失败或被中断时档位照样切换，并提示压缩未成功完成）、**仍要切换**（立即生效）与取消（保持当前档位）。压缩只能在会话空闲时启动，因此任务运行期间第一项会置灰并说明原因，另外两项照常可用。会话尚无消息、重选当前显示档位、或刚完成一次成功压缩后的切换则直接生效、不弹框；模型仍在会话内锁定，改用 `/model` 命令切换模型——与 `/agent` 交接同一方式：选中模型只是在输入框暂存为一枚 chip，**发送时**才在同一 Agent 下新建一个使用所选模型、沿用当前 Workspace 的会话并跳转，其首条消息携带 `[model_switch_from]` 源块（源会话 id、Trace 文件路径、原模型），输入框中的文字随之发出（为空时发一句界面语言的自动消息）；新会话中该源块折叠为一条“已切换模型”横幅，可点击回到原会话，模型需要早前历史时按路径自行读取源 Trace 文件。

审批模式共四种：`allow-all`（全部放行）、`deny-all`（全部拒绝）、`read-only`（仅放行只读工具）、`always-ask`（每次询问），详见[工具与审批](/tools)。

草稿页在输入框下方按折叠夹陈列示例提示词，同一时刻只展开一个；点击某一行即把该提示词填入输入框，并不发送，可先阅读修改再自行发出。最后一个折叠夹「我的快捷指令」属于用户自己：点**新建快捷指令**会打开编辑框，其中已带上输入框中现有的内容，并以首行作为建议名称，保存后即归入该折叠夹——一条快捷指令由名称与提示词组成，不绑定 Skill，按用户存放在服务端，因此换浏览器、换机器都还在。每行提供编辑与删除，折叠夹标题显示「已用/上限」，存满 3 条后**新建快捷指令**行即隐藏（名称不超过 40 个字符，提示词不超过 4000 个字符）——这个上限正是为了让该折叠夹与内置折叠夹等高，不需要自己的滚动条。

### 会话列表

侧边栏的会话列表按 Workspace 或 Agent 分组，分组方式与排序方式在标题栏的**列表选项**菜单（滑块图标）里切换，每个选项前带一枚对应图标：文件夹表示按 Workspace 分组、机器人表示按智能体分组、时钟表示按最近更新排序、上下箭头表示手动拖拽排序。

会话行的操作分两层：

- **悬停**一行时，行尾的最近活跃时间让位给两个图标按钮——归档与删除；键盘同样够得到：Tab 到其中任意一个，该按钮即显形；
- **右键点击**一行，在指针处打开完整菜单：置顶、重命名、远程控制、归档、复制 Session ID、删除。触屏**长按**、键盘 **Shift+F10** 打开同一个菜单（触屏没有悬停，也没有右键）。按 Esc、点击别处或滚动列表都会关闭它；系统右键菜单只在会话行上被接管，页面其他位置照常。

会话行标题旁是它的状态标记：Session 运行中是翻转的沙漏（压缩中是向中线合拢的压缩标），有一条你还没看过的回复时是一枚绿点，会话仍有**后台任务**——超过 yield 窗口继续运行的命令、正在跑一轮的后台子智能体——时另有一枚小小的活动波形标记，悬停显示数量（「2 个后台任务」）。这枚标记与其他标记互不影响：dev server 还开着的空闲对话照样带着它，最后一项后台任务结束的那一刻它即消失，由服务端实时推送、无需刷新。

置顶只在活跃列表里出现（已归档、子智能体与定时任务的折叠夹中没有这一项），置顶的会话排在所属分组的最前面，该状态按 Project 记在浏览器本地。

### 流式渲染

- 模型文本逐 Token 渲染，思考块可折叠；
- 工具卡片可展开查看参数与输出，执行中显示实时计时；以 `run_in_background` 发起的调用在用时右侧带与会话列表同一枚活动波形标记（「在后台运行」）——调用本身立刻返回，标记说明它的工作没有；卡片以短名称呼内置工具（`read_file` 显示为「读取」），工具本来的名字留在 tooltip 里，设置页「外观」的**工具短名**开关可关掉它——其余工具（含 MCP 工具）始终显示原名；
- 上下文压缩在消息流中留下一行，标题兼作状态、与工作分组组头的「运行中」/「运行完毕」同一写法：按实际动作写作「压缩中」/「压缩完毕」，discard 则为「清空中」/「清空完毕」，并带用时；summarize 运行期间该行展开：压缩请求的思考一到就出现「思考」一节，「压缩结果」一节要等思考结束、第一段摘要文本抵达后才出现——两节默认折叠、各带自己的用时——压缩结束后该行自行收起，只留下这一行；失败的压缩保留裸的「压缩」或「清空」标题与一行原因；
- 子 Agent 在消息流中只留下一条通栏行，样式与其他折叠步骤行一致（头像、名称、短会话号、运行中转圈，子会话内有待审批时带琥珀色圆点）；点击打开右侧智能体面板——上方是该行所属 Task 派生关系的调用图（节点上显示运行时长，点节点切换），下方是所选子会话的实时对话（含子会话自己的用户消息），嵌套工具卡片与审批与主对话完全一致；面板的显示以任务为界：发送消息开启新任务时默认关闭（进入会话时同样默认关闭），仅在手动打开、或（桌面端）当前任务派生子智能体时重新显示（每个任务自动打开一次，任务内手动关闭后保持关闭到下个任务，且不抢占已打开的工作区面板）；从工具条打开面板或切换 Session 时默认展示最新 Task 的调用图，点旧轮次的行则回看那一轮的调用图；智能体面板与工作区面板不会同时显示，打开一个即关闭另一个；上下文压缩与首次 MCP 连接以统一样式的步骤行提示（与运行分组头同款外壳，含吸顶标题栏，连接中/成功/失败仅切换图标与单行详情，结果行含耗时；MCP 行主显发现的工具数并点名不可用的 Server，展开后按 Server 分组——每组一行状态、工具数与该 Server 的连接耗时，点开组内是工具列表或失败原因）；
- 每个 Task 结束后显示统计行：Token 用量、TPS、耗时、费用、复制以及位于复制按钮右侧的**分叉**操作。分叉会先弹出确认框（该操作会把对话复制为一个新对话），确认后才在该条已完成的模型回复处新建 Session，沿用 Agent、模型、Workspace、审批模式和保留范围内的历史；同一源对话从不同回复分叉时，标题使用不依赖界面语言的编号后缀，按 `原标题 (1)`、`原标题 (2)` 递增。新旧会话的 Trace 与 scratchpad 是独立快照，即使删除源对话，本地图片和附件仍可显示；
- 打开一个对话只加载最近 50 轮；滚动到顶部附近会自动向前续载 50 轮，阅读位置保持不动，载到开头显示「已是对话开头」，续载失败则点击重试。轮次编号与顶部统计由服务端随窗口附带的累计值接续，与整段加载一致。

### 头部统计与详情卡

工具行最右侧显示会话累计统计（Token、费用、用时），点击即打开详情卡——模型、Session id（旁附复制按钮）、Workspace、创建时间与逐行统计。用时一行在括号里带两个分项，形如 `用时 10.3s（API 5s，工具 5.3s）`：一项是模型请求内的时间（已扣除人工审批等待），另一项是工具的 wall time（各工具执行区间的并集，并行工具只计一次）。二者是对这段用时的两项实测，不是对它的切分——后台工具会与模型解码重叠，审批等待与 harness 开销又不属于任何一项——故其和可能大于也可能小于总用时，任一项都不由总用时减去另一项得出。其下还有一节：会话仍有后台任务时，用时右侧有一枚小胶囊显示其数量——与会话列表行上那枚标记同一个数。其下还有一节：

- **会话进程**——对话启动的后台进程（超过 yield 窗口转入后台的 `exec_command`），逐行显示命令、启动时间与 pid;运行中的行在检测到进程所服务的地址时,还会附上可点击的服务链接(取其输出打印的最后一个本机 URL,否则对其进程组做监听端口探测)。运行中的行带「停止」按钮（杀停整个进程组并把该行从列表移除）——对话会收到该进程已结束的回报，措辞是「已停止」而非失败，模型因此知道 dev server 没了，却不会把它读成需要重启的崩溃；已退出的行保留「已退出」标注，并带「移除」按钮，可把该条目从列表删除。移除立即生效且不可撤销：条目连同该进程已捕获的输出一起离开运行时注册表，之后无法再让模型读取那段输出——输出还有用时请先留着这一行。

全站的复制按钮在按钮自身给出反馈：复制成功后图标短暂切换为对勾（不再显示「已复制」文字）。

### 输入与快捷操作

- Enter 发送，Shift+Enter 换行，支持粘贴图片——嵌入对话的图片单独设有 20MB 上限，不随附件上限一起放宽：图片会进入对话与轨迹，此后每次翻阅历史、恢复会话都要重新付出它的体积，而附件只是按路径从磁盘读取；
- 「+」菜单收纳输入附加项：**上传图片**、**上传文件**与目标模式。附件不限类型（一次最多 20 个，默认单个 ≤ 100MB、合计 ≤ 120MB——两个尺寸均可由管理员在**系统设置 → 上传限制**中调整，见下文；超限的文件在读取前即被拒绝，不会先上传再报错，提示中会写出当前生效的上限），已选文件按选择顺序以可移除的小卡片显示在文本框上方；只带附件、没有正文也可发送。发送时文件写入该 Session 的 scratchpad（随 Session 一并删除），消息里每个文件追加一行 `[attached file: <path>]`，对话中渲染为一条「附加文件」提示：文件内容不进入对话，模型用普通文件工具按路径读取；
- 也可以把文件**拖拽到聊天区**上传（聊天区即对话与输入框所在区域，会话页与草稿页皆可）：文件拖到该区域上方时显示覆盖该区域的「松开以添加附件」浮层（拖离即消失，拖动文本等非文件内容不触发），松开即把整批文件附加到输入框——图片走粘贴图片的同一管线，其余文件成为附件，类型与大小校验及报错与「+」菜单一致。任务运行中同样可以拖入（附件按下述运行中发送方式送出）；目标模式下拖入的图片照常附加、文件会以提示拒绝。只有聊天区会把文件作为附件：把文件放到侧边栏、顶栏、其他停靠面板或任何没有输入框的页面上，既不显示浮层也不会添加附件，只是被直接忽略，同时不会让浏览器跳转打开该文件（文件面板是另一处拖放目标，它把文件上传到 Workspace，见下文）；
- 输入 `/` 打开快捷菜单：触发上下文压缩（`/compact`）、把会话交接给其他 Agent（`/agent`）、切换模型（`/model`）——两个切换命令都只在进行中的会话里提供，草稿没有可切换的对话，Agent 与模型本就在草稿页选定——或勾选已安装的 Skill——所选 Skill 会以 `[use_skills]` 块随消息发送；
- Task 运行期间输入框保持可用，工具条只保留一个操作按钮：输入框为空时是**停止**，一旦输入内容即变为**发送**，其行为遵循工具条「更多设置」弹出分组中的**运行中发送方式**（一个可扩展的设置面板，草稿态同样可设，选择会被记忆）：**插话**（默认）把文字以 `[user_steering]` 用户消息随下一轮送达运行中的 Agent；**排队** 把整条消息暂存在服务端，本轮结束后自动作为普通新消息发出（期间在输入框附近显示「N 条已排队」提示；队列存放在服务端，刷新页面不丢失）。每条排队提示——未送达的插话或排队中的跟进消息——行尾都带一枚**撤回**按钮（一个向回弯的箭头图标），可把消息（含附件）撤回到输入框编辑后重新发送；插话一旦送达模型即不可撤回。运行在插话送达之前结束时（工具跑着的时候按停止是最常见的情形）不用你动手：这条插话会自动回到输入框，附件一并还原，改完可以直接再发——打断不会吃掉已经打好的话；
- `/agent` 与 `/model` 都是暂存而非立即生效：选中的 Agent 或模型只在文本区上方留下一枚 chip，此时不发送任何内容，可以继续输入——按 Enter / 点发送才真正交接（为该 Agent 新开一个对话）或换用所选模型继续本对话，输入的文字随之带走；正文为空时自动填入默认消息，点 chip 上的 × 即可取消。两枚 chip 都随草稿缓存，刷新页面或切到别的会话再回来时与文字一同恢复；其中切换模型还需等待会话空闲——新会话要从本会话的 Trace 接续，而运行中的一轮或压缩仍在写入——等待期间输入框上方会给出说明；
- 工具条右侧是**上下文占用圆环**：单色圆环，标尺是压缩真正触发的那个点（Agent 的 `compaction.max_context_length`，被模型窗口留出的余地钳住），>80% 转琥珀、>95% 转红。点击展开**上下文构成面板**：`已用 / 阈值` 数字、一条以模型完整窗口为标尺的条形（已填充部分按系统提示词、工具定义、用户消息、模型消息、工具请求、工具结果六项细分，条形下方以「最大上下文 N」标出该标尺），以及工具 / 文件两份 Top 5（标题行上的一对文字按钮切换，文件视图只列出 `read_file` / `edit_file` / `write_file` 触及的文件名，完整路径悬停可见）。条形上的虚线切刀标出压缩触发点，且可以拖动——拖动它（或聚焦后用方向键，按住 Shift 步长更大），松手即弹出确认框，框内的数值仍可编辑；确认后写入该 Agent，并对当前这段对话立即生效，运行中也不例外；
- 需要人工审批时，工具调用在消息流中内联显示“允许 / 拒绝”按钮；审批模式在会话中途可随时调整；
- 引擎在重连退避等待（≥2 秒）期间，重试提示行会实时倒计时到下一次尝试，并内联提供**立即重试**（跳过剩余等待）与**放弃**（普通中断）两个按钮；
- 模型 API 拒绝该 Session 的凭据（鉴权失败）时，输入框会置灰禁用——但可恢复：Session 锁定的只是模型引用，凭据取自当前 Project 配置。提示条的主按钮跳转到模型配置页；在那里保存新的 API key 后输入框会自动解锁（已打开的标签页经 `credentials_updated` 事件即时解锁；刷新后也保持解锁，因为凭据更新时间晚于记录的鉴权失败时间）。「重试」按钮可手动清除该状态再试一次（key 仍无效时会重新变灰），一次成功的请求总会清除该状态，「新建会话」仍作为跳到全新草稿的出口。禁用态的输入框保留草稿且可选中——发送失败的长消息仍能复制出来。
- 终端位于对话两侧的停靠面板：Ctrl+` 显示或收起终端标签（没有打开的终端时会接管或新建一个 Shell），终端获得焦点时按 Ctrl+W 关闭该终端——与标签 × 相同，先确认、再结束 Shell，停靠面板与独立的 `/terminal` 页一致——按键不会到达 Shell。浏览器把 Ctrl+W 留给关闭浏览器标签页，可能先于页面响应；桌面应用会把它交给终端。

### 快捷方式悬浮球

没有面板占据屏幕时——桌面宽度下右侧停靠栏收起，窄屏下两块面板合并成的底部弹层没有打开——对话区（工具行与输入框之间的区域）右缘内侧 32px 处会浮着一枚半透明圆形按钮（球面是工作台图标）、下方带一行小字「快捷方式」，让工作台的各块面板始终一步可达——即使从未注意到工具行上的开关。点击它（或在其上按 Enter / Space）会以按钮为圆心向左展开一圈紧挨着它的圆形入口——智能体、Workspace 文件、记忆、轨迹、消息软件与终端各一枚，只有图标；指到或聚焦其中一枚时，按钮下方那行小字改显示它的名称；这行小字始终居中在按钮正下方，按钮与边缘留出的距离足以容下最长的那个名称。按钮与入口都不带 tooltip——名称已经写在屏幕上。按钮靠近对话区上下两端时，这段弧收窄为放得下的那一段。选中入口即打开对应面板——桌面宽度落在右侧停靠栏，窄屏落在底部弹层——面板一出现按钮就消失。弧末另有一枚「隐藏悬浮球」入口，选中即让按钮不再出现，并提示去哪儿恢复；设置页「外观」的**快捷方式悬浮球**开关可重新打开。Esc、点击别处或滚动都会收起这段弧。按钮可沿右缘上下拖动（短按仍是点击），拖动全程跟随指针——指针经过其他按钮也不会中断——松手回弹贴边；它不会盖住工具行或输入框，位置作为一条全局偏好记在浏览器里，所有对话共用。停靠栏收起期间若有子智能体等待审批，工具行开关上的琥珀色小点也会显示在这枚按钮上。

### 文件面板

文件面板左侧是 Workspace 的目录树，右侧是所选文件的预览。目录在首次展开时才加载内容；目录树支持方向键（上下移动、右键展开目录或进入其中、左键收起或回到上级），选中的文件高亮，工具栏的面包屑只读出当前目录的路径、不再可点——旁边就是目录树，导航交给它；路径长到工具栏放不下时，前导段折叠成一个「…」，当前目录始终可见，刷新 / 上传也不会被挤到第二行；根目录在面包屑里写作 `.`，Workspace 的绝对路径在会话详情卡片里，不在这条工具栏上。目录树上方的搜索框按条目名称过滤：命中项的上级目录一并保留并展开，名称本身命中的目录连同其内容一起显示。目录树是懒加载的，搜索只能覆盖至少展开过一次的目录——都不匹配时会明说，而不是显示成空树；按 Esc 清空搜索框。展开 / 折叠时子树以高度过渡动画展开或收起（约 200ms，折叠期间行仍可见直至收起完成；系统设为减少动态时即时）。工具栏按钮可隐藏或显示目录树（默认显示，选择记在浏览器本地），显隐时目录树以约 200ms 的宽度过渡滑出或滑入，与停靠面板展开 / 收起同款；两栏之间的分隔条可拖动调整目录树宽度（获得焦点后可用左右方向键微调，宽度同样记住）；面板宽度容不下两栏时退化为单栏——先显示目录树，选中文件后换成带「返回列表」按钮的预览。Markdown 与 HTML 以渲染视图预览并可切换源码，文本文件内联高亮显示，图片内联显示（点击放大），PDF 内嵌；其余类型提示下载。扩展名看不出类型的文件（`Makefile`、`LICENSE` 之类）在内容看起来是文本时按文本处理。

文本文件可以就地编辑：**编辑**把预览换成纯文本的等宽文本框——没有富文本编辑器——**保存**（也可按 Ctrl+S / Cmd+S）经上传所用的同一内容写接口写回文件，保存前先弹统一的确认框；取消则回到预览。旁边还有**自动换行**开关：缺省关闭，长行像代码编辑器那样横向滚动，选择会带到下一个编辑的文件。未保存的修改在可能丢失之前都会先询问——切换到别的文件、关闭该面板的标签页、离开页面。折叠或隐藏停靠面板不会丢失任何东西：面板连同预览、目录树状态与编辑草稿原样留着，重新展开即回到原处，也不会询问。切换 Session 时草稿也会保留：再次打开同一文件即回到编辑状态。超过 256KB 预览上限的文件以截断方式显示且保持只读（把不完整的文本存回去会覆盖整个文件）；超过 14MB 写入上限的保存会被拒绝并给出提示。

Agent 写的是同一个 Workspace，你编辑期间文件可能被改动。每轮 Task 结束时都会检查一次——你的文本不会被替换，但编辑器标题栏会立即标出**磁盘上已变更**；若保存会落在已变更的文件上，写入前即被拒绝：面板会询问是用你的版本**仍然覆盖**，还是继续编辑，两种选择都保留你的文本。

上传写入当前目录（工具栏的**上传**按钮，可一次多选），也可以把文件**从桌面拖到面板上**：虚线框会标出文件将落入的目录，拖到某个文件夹行上松开即上传到该文件夹（拖动经过时该行高亮），完成后自动打开第一个上传的文件。单个文件上限 14MB——超限的文件在读取前即被点名跳过——目标目录中已有同名文件时先确认再覆盖。下载按钮在预览标题栏。

### 定时任务面板

定时任务面板列出绑定到当前对话的定时任务（每次新建 Session 的任务属于 Agent，在其设置页管理），带搜索框与全部 / 生效中 / 已暂停 / 已完成筛选。每行显示状态字形、任务名与一行人话时间表（「每天 08:00 · 下次 明天 08:00」「每 30 分钟」「每周一 09:00」「一次性 · 9 月 3 日 10:00」）；owner 可用行上的开关启停任务，在行菜单里编辑或删除。**建议**区列出每日简报、每周回顾、跟进提醒、监控更新四条现成请求，点击即打开 AI 对话框并预填。绑定到对话的定时任务只在本面板创建，面板标题之下另起一行并排两枚按钮——面板宽度可以拖动，按钮若与标题同行，拖窄时会被挤裁。带魔法棒的**用 AI 创建**（所有成员可用）与别处的 AI 创建只有一点不同：它的出口是**在本对话中编辑**，把提示词预填进这段对话自己的输入框，而不是新开一个对话——因为在对话里创建的任务默认就绑定到这段对话；发不发送仍由你决定，按下发送后走的就是手输文字的同一条路。带手形的**手动创建**（仅 owner）打开与设置页相同的表单，目标锁定为本 Session。绑定了**还有下一次触发**的定时任务的对话，在侧栏会话列表的行上带一枚闹钟图标（悬停显示「有待触发的定时任务」）：只有图标、没有数量；已停用、已过结束时间、或已经触发过的一次性任务都没有下一次触发，不出现图标。保存或启停一个任务只提示发生了什么——定时任务由调度器按时触发，与对话上下文无关，改完即时生效。列表在面板到前台、窗口重获焦点、有任务触发或排队、对话每轮结束时、可见期间每 30 秒以及每次改动后刷新——会话行上的标记读的是同一份列表，同一次刷新把面板和标记一并更新，二者不会各说各话。

## 用 AI 创建

Web App 里凡是通过表单创建的对象——Agent、模型分组、Benchmark、定时任务、密钥保险柜条目、应用、Agent 导入——都可以改为向 Agent 描述。每个页面并排给出两个按钮：带魔法棒的**用 AI 创建**与带手形的**手动创建**，两条路径同时可见。提示词框自带可点击的示例，点一下即填入草稿；折叠的**完整提示词**预览展示随你的输入一起发送的固定说明，并带复制按钮。唯一的出口是**在新对话中编辑**：以 Project 的 `default_agent`（没有时取第一个 Agent）开启新对话，把提示词预填进输入框，发不发送由你决定。预填的提示词不会被浏览器留下：不作修改也不发送就离开该页面，它随即被丢弃，不会在之后的对话里再冒出来；一旦动手编辑，它就成为普通草稿，与你自己写的内容一样保留。

## Agent 管理（/agents）

列表页支持创建与删除 Agent——创建弹窗可选从导出的 Agent State 快照包直接初始化（名称与描述留空沿用包内值；此时技能选择不可用，包自带技能）；点击进入 `/agents/:agentId` 设置页，按标签页组织：

| 标签页 | 内容 |
| --- | --- |
| Overview | 基本信息、Agent State 快照的导出 / 导入，以及还原为默认配置（覆盖自定义内容，仅保留名称与描述） |
| Prompt | AGENTS.md 与 system_prompt |
| Memory | Agent 级开关，以及按作用域分组的全部记忆——用户记忆在前、每个 Workspace 一组，分组可折叠并带添加、导出与导入入口——每行提供查看 / 删除 / 对话编辑 |
| Runtime | max_turns、model.*、compaction.* 等运行参数 |
| Tools | 内置工具表格（含条目级 call_description 开关）与 MCP Server 管理：表格 + 添加/编辑表单（默认 http，字段随 transport 切换，改动即时保存，服务端按 transport 完整校验；permission 控件把该 Server 工具的审批等级固定为 `auto` / `r` / `rw`，表格列出各 Server 的生效等级）；测试连接与模型页同款——表单内独立按钮测当前条目（toast 报工具数与耗时），区块级按钮逐一测试全部 Server 并在各行显示结果徽标 |
| Hooks | 顶部一个**启用钩子**开关（仅 owner，成员只见状态）决定该 Agent 此后新建的 Session 是否运行钩子包——关闭后新建的 Session 一个钩子都不运行，已安装的包仍全部留在磁盘上。其下是已安装的钩子包（agent_state/hooks/）：每行以包名加紧随其后的钩子点胶囊（只写钩子点名，如 `stop`）开头，其下描述，行尾版本、打包导出与卸载。**导入钩子**弹窗与导入技能同款：推荐路径是让 Agent 在对话中导入——填入钩子来源（URL / GitHub 仓库 / 本地路径 / 一段描述，或其他工具的钩子配置），弹窗实时预览发送给 Agent 的 Prompt，**复制 Prompt**与**打开新对话**在来源为空时一同置灰；其下可直接上传钩子包 zip（同名已装先确认覆盖）。从插件库安装仍在插件库页完成 |
| Vault | 环境变量条目，值以掩码显示 |
| Schedule | 定时任务（TOML 定义）：创建（用 AI 创建或手动创建）、编辑、启停、删除；列表为空时展示建议 |

Memory 标签页的开关拨动即写入，不参与标签页的保存按钮，因此关闭记忆不会连带把别处未改完的内容一起存盘。关闭记忆也不会删除任何文件，标签页仍可正常查看与删除——只是记忆不再进入 Agent 上下文，也不再为新 Session 准备目录。作用域分组可折叠，折叠状态按「用户 × Project × Agent」记在浏览器本地；每组标题的折叠箭头左侧有**添加**文字入口（与模型页的分组约定一致）——和编辑一样经中转弹窗（必填的内容或来源 + 引导语实时预览）跳到新对话，由 agent 整理保存到该作用域；引导语刻意极简，写入规范由记忆提示词承载。记忆行有意不提供就地编辑，操作与技能页一致为纯图标按钮：**查看**在桌面端从右侧抽屉、窄屏从底部弹层（与对话页面板同一交互，半屏 / 全屏两档吸附）渲染正文；**删除**先确认，并同步清掉该文件在 `MEMORY.md` 中的索引行；**编辑**先打开中转弹窗（修改要求 + 引导语预览），再跳到与该 Agent 的新对话——Workspace 作用域的对话还会锁定对应 Workspace，让会话恰好读到它正在修改的那份索引。整组记忆也可以一次搬运：**导出**把它下载为一份 JSON 文档（这一组的全部记忆加它的 `MEMORY.md`），文件名带导出日期时间，多次导出互不覆盖；**导入**把这样一份文档读回来——与 Agent State 快照同样的分工，仅 owner 可用。导入时需要指定同名记忆的处理方式：保留现有的（缺省，不丢失任何内容）、改用文件里的版本、或整组替换；后两者会先弹出确认，逐条列出将被覆盖或删除的记忆。标签页下方可直接编辑两段记忆提示词（`memory.prompt` / `memory.workspace_prompt`）；当提示词模板中没有 `{{MEMORY}}` 占位符（创建于记忆功能之前的 agent）时会给出提示并提供一键插入——显式且幂等的配置写入。Agent 列表卡片的统计行也显示记忆条数，点击直达本标签页。存储模型见[配置说明](/configuration#记忆)。

定时任务按固定周期触发（最短 5 分钟），且仅在服务运行期间执行。

## 插件库（/plugins）

按分类浏览插件库——Skill 与会话钩子都在这里——把插件安装到指定 Agent（Skill 与钩子包一并装入）、更新落后于库的已装副本，或把某个 Skill 一键带入 Chat 草稿快速调用。每张卡片带一行语义化元信息（`v<版本> · N 天前更新 · N 个 Agent 在用`），点开即详情弹窗：插件完整描述与钩子包应答的钩子点，其下是它携带全部文件的浏览器——左侧文件树按 Skill 分组（各自的 SKILL.md 与参考文件）、钩子脚本单独一组，可同时展开任意多组；右侧预览所选文件，摘要与文件树始终在场。

## 模型配置（/models）

按 Provider 分组展示当前 Project 的模型表格。支持添加与编辑模型：以 `(provider, model_id)` 为唯一标识，凭据以掩码显示，可配置上下文窗口、最大输出长度（按模型的输出上限，覆盖 Agent 的 `model.max_tokens`——小上下文模型建议调低）、定价、视觉（vision）标记与快速模式（默认关闭：进入厂商的溢价快速档位、输出更快——该开关只对 AgentHub client 支持该档位的模型显示，打开时会先确认溢价计费）；开启了快速模式的模型会在列表中带角标；可设置默认模型与视觉模型（在会话模型不支持图片输入时代为读图），并对任一模型做连通性测试——测试会携带弹窗当前的快速模式开关状态，被拒时在保存前即可发现。仅 Project Owner 可编辑，概念说明见[模型与 Provider](/models)。

## 用量统计（/usage）

- 筛选条件：Agent、模型与日期范围（最近一小时 / 最近一天滑动窗口、近 7 / 30 / 90 天、或自定义起止）。图表以何种精度绘制由范围决定——最近一小时按分钟，最近一天按小时，日历档位按天，跨度很长的自定义范围按周或按月——因此没有单独的精度控件；
- 概览卡片：今日 / 近 7 天 / 累计用量；
- 图表，全部按所选范围展示的时间序列：并排的「按 Agent 拆分」与「按模型拆分」的请求与成功率图（单个时间桶的请求数按对象分段堆叠、走左轴，每个对象的成功率各自成一条虚线、走右侧 0–100% 轴并绘制在柱子上方；请求数最高的若干对象具名呈现，其余折叠为一条标注了数量的中性色序列）、Token 变化（三段堆叠柱 + 前置的缓存命中率虚线）、成本变化（折线带点 + 面积）。每张图都支持同样的悬停：悬停整列看气泡、悬停单段柱突出该段、悬停折线突出该线。所有折线都是直连线段、不做平滑，线宽统一。图表自适应卡片宽度，不出现滚动条；
- 有两种情况图画不出来。**没有比率**的桶——该对象在这个桶里一次请求都没发，或该桶没有缓存流量——折线沿坐标轴顶部横穿过去，只为让线保持连续；悬停表格在该处显示「—」而非百分比，而真正的 0%（发了请求且全部失败）仍然显示 0%。**什么都没记录**的桶一律不画：四张图都丢弃它、把其余的从左往右依次排开，因此共用同一条会跳过空闲区间的横轴，跳过处画有断轴标记。空与不空按桶判断、绝不按单个对象判断——只要有任何对象在这个区间跑过，桶就保留，当时空闲的对象在该列显示 0 与「—」；
- 服务端错误面板：汇总统计 + 异常明细表，按固定页大小分页（不滚动）。其**清空**（仅 Project owner）删除当前范围与 Agent 筛选所列的记录——确认框按档位名点出范围（如「近 7 天内」「最近一小时内」），自定义范围才写起止日期；管理员的清空同时带走只有管理员看得到的无归属记录。

## 评估中心（/benchmark）

Project 的全部 Benchmark 按被测 Agent 分组列出。每行显示最新分数与相对上一次评估的增减、评分板的分数走势小折线、题数与每题运行次数以及最近评估时间；**查看**打开详情——按模型分系列的分数曲线、带单题与逐次运行行的评估明细表、题目浏览器——宽屏在右侧窗格，窄屏取代列表。标题下折叠着一份新手指南，把闭环讲成三步：出一套 Benchmark、看分数、针对它优化 Agent。

- 右上并排两个按钮。**用 AI 创建**要求选定被测 Agent 并描述要考察的能力与场景；提示词的固定尾部把 Agent id、期望基线分与 Pilot 迭代上限交给 `benchmark-design` 技能，并要求取得基线分。**手动创建**是一张表单——标题、id、描述、每题运行次数、每道题的题干与评分细则——由服务端按技能读取的目录结构落盘（`POST …/benchmarks`，仅 owner）。
- 详情头部的**用 AI 优化**与**手动优化**是同一对按钮，共用一份提示词尾部：**手动优化**选择执行优化的 Agent（未装 `agent-optimization` 技能时有提示）、优化会话自身使用的模型、每题运行次数、最多轮数、目标分数（缺省比基线高 10 分）与可选的优化重点；**用 AI 优化**是带示例的自由文本，尾部参数相同。一行里放不下一对按钮，因此行内的**优化**只开表单。两者都以同一个出口结束——**在新对话中编辑**：提示词预填进输入框，发不发送由你决定。评测模型不在这里选——技能沿用基线记录的那一个。
- 行的溢出菜单可复制 Benchmark 的目录路径，owner 还可整目录删除（`DELETE …/benchmarks/:id`）。`?agentId=` 只展开该 Agent 的分组；`?benchmark=<agent>/<id>` 直接打开某个 Benchmark。

## 系统设置

把既不属于 Project 也不属于 Agent 的设置收进一个弹窗，入口是侧边栏用户菜单的「系统设置」：左侧一列页面导航，右侧每页是一列设置行——左边标题加一行说明，右边控件。

导航按组划分。**个人**组存放属于当前账号的偏好，改动即刻生效，没有保存按钮，关闭弹窗也不会丢失什么；**服务器**组存放服务器全局的界面：经 `GET|PUT /api/admin/settings` 写入的设置与用户管理仅管理员可见——非管理员既看不到这些条目、也不会得知它们存在，无论前端渲染成什么，接口对非管理员一律返回 403。因此非管理员只会看到「个人」组的几页，此时导航不再绘制分组标题。桌面应用中没有用户管理页（服务端是单用户模式）；桌面 shell 自己的窗口还没有「账户」页——它通过 shell 的一次性 token 登录，没有可修改的密码，而用密码登录同一服务器的浏览器会话仍保留该页。检查更新不是这里的一页，见[版本与更新](#版本与更新)。

### 通用

个人设置。**语言**（中文 / English / 跟随浏览器）与价格的**显示币种**（USD / CNY；存储始终为美元，换算只发生在显示层）。**显示 CLI 会话**（默认关）：关闭时会话列表只列出在 Web 端创建的 Session，直接由数据库返回；开启后会额外扫描轨迹目录，把 CLI 创建的会话一并列出。按用户存储。**导入 Trace**：选择目的地的 Project 与 Agent，上传从其他部署导出的 `.jsonl` 轨迹文件，它会成为该 Agent 的一个会话。两者都需要选择：接口按 Agent 划分，因为轨迹文件自身无法指认本机的 Agent；Project 则是因为本对话框不显示当前打开的是哪一个——这也意味着可以导入到当前打开之外的 Project。导出是同一条路的反方向，与它下载的文件待在一起，位于对话的 Trace 面板中。

### 外观

个人设置。应用**主题**（浅色 / 深色 / 跟随系统）、**终端主题**——终端面板保留自己的明暗配色，默认跟随应用主题，显式选定浅色或深色即与应用解耦，适合提示符与 TUI 只为一种屏幕调校过的场景——以及界面**字号**与**主题色**。

### 账户

**修改密码**操作。该页只在存在可修改密码时出现：桌面 shell 自己的窗口通过 shell 的一次性 token 登录，从未见过密码。

### 用户管理

仅管理员可见、桌面应用中不出现：列出与创建用户、重置密码、删除用户（内置 admin 不可删除）。

### 代理选项

仅管理员可见、服务器全局。两个开关——**应用程序使用代理**（server 自身出网：LLM 请求、更新检查、图片抓取）与 **Agent 环境使用代理**（Agent 命令子进程环境）——共用一个可选的**代理地址**，留空即跟随代理环境变量。地址接受 undici dispatcher 认可的任意代理 URL（`http://`、`https://`、`socks5://`，可带凭据）或裸 `host[:port]`（归一化为 `http://…` 后存储），其余一律拒绝并在输入框下方给出原因。保存前不写入任何内容，保存以单次 PUT 整体提交，因此地址被拒时其余字段也不会落库。保存后重建出网 dispatcher，对新发起的连接即时生效、无需重启；回环地址始终直连。

### 上传限制

仅管理员可见、服务器全局：两个尺寸——**单个附件上限**与**单条消息附件合计上限**，均以整数 MB 填写，默认 100MB 与 120MB。两者的取值范围为 1–200MB，且合计不得低于单个上限（否则一个本身合法的附件将无法发送）；超出范围的值——例如把「100GB」按 MB 填成 102400——会被服务端明确拒绝并在输入框下方给出原因，不会被接受。校验先于写入：一次 PUT 中只要有一个字段非法，其余字段也不会落库。

保存即刻生效，无需重启：附件校验与请求体上限都在每次请求时读取该设置。请求体上限本身不单独配置，而是由合计上限推导——附件以 base64 `data:` URL 随请求送达，体积膨胀 4/3，因此上限必须随之上浮，否则每个附件单独合法的请求会在 HTTP 层被拒。

有两个数值刻意不开放：单条消息的附件**数量**上限固定为 20（它约束的是输入框的可用性，而非服务器资源），对话内嵌**图片**上限固定为 20MB。图片不随附件上限放宽是有意为之——图片进入对话与轨迹，其体积在每次翻阅历史与恢复会话时被反复付出；而且模型侧另有更低的实际限制（供应商通常约 5MB，`read_file` 读图亦为 5MB），把它放宽到 100MB 只会把一个清晰的拒绝换成更靠后、更难懂的失败。

## 版本与更新

更新的交互和常见的应用更新器一样，集中在一个弹窗里。两个入口都打开它：侧边栏用户菜单里紧贴「系统设置」下方的那一行，以及新对话页版本行上的「有新版本可用」上标（版本行形如「vX.Y.Z · 最近更新日期 7 月 26 日」——日期由发布流程在构建时打入，直接显示、无需联网；开发构建以及打入机制之前的发布版，v0.1.2 及以前，没有日期）。那一行会说明进行到哪一步——「检查更新」「检查中…」「新版本 vX 可用」「正在下载 vX 42%」「重启以更新到 vX」——右侧以浅色显示当前运行版本，任何状态点击都打开弹窗。

弹窗按步骤走完更新：在一无所知时打开会先检查（应用每次加载也会向 GitHub 查一次，手动检查则绕过缓存结果）；查到新版本时给出更新说明链接和「下载并更新」按钮，按下之前不会下载任何东西；下载中显示进度条，「放到后台」只是关掉弹窗、不取消下载——那一行继续显示百分比，下载就绪后用户按钮上出现圆点并弹出提示；最后「重启并更新」完成整个过程。在服务器上，下载就是后台运行的 `penguin update`（数据目录不受影响），进度条读的是安装器自己的进度；当服务由 `penguin web` 或 `penguin server` 托管时，重启是真实的——服务在新版本上回来，页面自动刷新；用其他方式启动的服务则被告知需要手动重启。非管理员可以看更新说明，但不能执行更新。下载失败会显示更新命令自己的输出并提供重试；无法自更新的安装方式（源码运行、无法识别的目录布局、Windows）会说明原因。设置 `PENGUIN_UPDATE_CHECK=off` 可完全关闭新版本检查——见[配置参考](/configuration)。

**在桌面应用中**同一个弹窗驱动的是应用自带的更新器——只在 shell 自身的窗口里，服务端的版本在那里完全不出现。shell 会按自己的节奏后台检查，但绝不自行下载：查到的版本以圆点和那一行的文案出现，下载从弹窗开始，百分比来自更新器的真实进度，「重启并更新」重启进已下载的版本（shell 原生菜单里的「Check for Updates…」在原生对话框里提供同样的「先下载、再重启」两步）。用密码登录同一台桌面模式服务器的浏览器完全看不到更新入口：它既读不到那台机器的更新状态，也无法重启它的窗口，更无法在那台服务器上跑 CLI 自更新。无法自我替换的形态——由系统包管理器管理的 Linux 安装（`.deb`）以及开发运行——在弹窗里说明原因；安装包本身见[桌面应用指南](/quickstart-desktop)。
