Agent 是 Project 里配置好的助手。每个 Agent 都有自己的指令、运行参数、工具、Skill、钩子包、记忆、密钥保险柜变量和定时任务，这些内容存放在一起，构成它的 Agent State。创建 Agent、修改设置，都在**智能体**页面上完成。

- 要查看 Project 里的 Agent，见[智能体页面](#智能体页面)。
- 要添加 Agent，见[用 AI 创建 Agent](#用-ai-创建-agent)、[手动创建 Agent](#手动创建-agent) 或[导入 Agent](#导入-agent)。
- 要修改 Agent，见 [Agent 设置](#agent-设置)和各标签页对应的章节。
- 要备份、迁移或重置 Agent，见[概览标签页](#概览标签页)。
- 要删除 Agent，见[删除 Agent](#删除-agent)。

## 智能体页面

在侧边栏选择**智能体**。页面列出当前 Project 里的所有 Agent。可以用搜索框（**搜索 Agent：id / 名称 / 描述**）过滤列表。

列表默认按 Agent 由谁创建分组：**用户创建**、**智能体创建**、**公司模式创建**，依此顺序，没有 Agent 的组不显示；点击组标题可以折叠或展开该组。想看一个完整列表，在搜索框旁的下拉框里选择**不分组**，此时 Project 中各组织的员工排在最后，单独列在**公司模式员工**一节。浏览器会记住你选的分组方式和折叠了哪些组。

每个 Project 都自带内置 Agent `default_agent`。当它还是唯一的 Agent 时，它下方会出现一张卡片，提示你创建第一个自己的 Agent：「还没有自己的智能体」。

每个 Agent 卡片显示：

- Agent 的名称、id、Agent State 版本（例如 `v3`）和描述；已开启 API 的 Agent 名称后带有 API 图标（**已开启 API 访问**）；
- 一排数字：Session、工具、Skill、钩子包、记忆、密钥保险柜变量、定时任务的数量，以及最近一次修改的时间。点击任一数字即可打开对应的设置标签页；
- 这个 Agent 最近 30 天的 Session 活动；
- **新建对话**：和这个 Agent 开始对话；**设置**：打开它的设置；一个图标：在**成本中心**查看成本；**导出 Agent**：打开导出对话框（见[导出和导入 Agent](#导出和导入-agent)）；以及一个删除按钮。

部分 Agent 有新内核可用时，卡片上会显示**内核需要更新**，页面顶部的通知会提供**现在升级**和**忽略**。见[更新内核](#更新内核)。

### 机器上的 Agent

Agent 属于它所在的服务端。Project 用到机器时，每台已连接机器自己的 Agent 与本服务端的 Agent 并列在同一列表里，按列表本身的顺序（先创建的在前）排列，就像侧边栏把机器上的工作区与本机的并列。机器上的卡片在 Agent 名称之后写出机器，例如 `[SSH: gpu-box]`。机器上的 Agent 从不与本服务端的 Agent 合并，id 相同也是两个 Agent：每台机器都有自己的 `default_agent`。

这类卡片上的操作都作用于那台机器：**设置**和各个数字打开它在那台机器上的设置，改动也都保存在那台机器上；**新建对话**在那台机器的临时工作区开始对话；删除按钮从那台机器上删除这个 Agent。**成本中心**只统计本服务端的 Agent，所以卡片上的成本按钮不可用。机器正在重新连接或服务已停止时，它上次答复的 Agent 仍留在列表中、整卡淡显，机器名称之后有一个拔出插头的图标，鼠标悬停可看原因；这些卡片上的按钮都不可用。只有管理员能看到机器。

也可以从侧边栏进入某个 Agent。对话按 Agent 分组显示时，每个分组标题上有**新建对话**和 **Agent 设置**按钮；侧边栏还有**创建 Agent** 按钮，点击打开**创建 Agent** 对话框。

## 用 AI 创建 Agent

描述你想要的 Agent，一个现有的 Agent 会替你把它创建出来。

1. 在**智能体**页面选择**用 AI 创建**，打开**用 AI 创建 Agent** 对话框。
2. 描述这个 Agent 做什么、为谁服务、产出什么。想从示例开始，就在**试试这些示例**下选一个：**随记智能体**、**金融 Copilot**、**文档 RAG 智能体**、**深度研究报告智能体**或**报告写作智能体**。
3. 可选：展开**完整提示词**，查看会随描述一起发送的指令；也可以选择**复制提示词**。
4. 选择**在新对话中编辑**。会打开一个新对话，提示词已填好，此时还没有发送。
5. 检查提示词并发送。

对话框会写明由哪个 Agent 执行：「将由『*Agent*』在新对话中完成」。执行者是 Project 的 `default_agent`；没有 `default_agent` 时，用第一个 Agent。

固定指令要求执行 Agent 使用 `agent-initialization` Skill，并且：

- 使用你给定的 Agent id，或者起一个简短、能体现用途的 id；如果这个 Agent 已经存在，就停下来，不要覆盖；
- 以 `default_agent` 的配置为基础，设置名称和描述，记下它由智能体创建，把新 Agent 的角色和规则写进它的 `AGENTS.md`；
- 只从插件库复制新 Agent 需要的 Skill，其他 Agent 一概不动；
- 报告新 Agent 的 id、安装了哪些 Skill，以及怎样和它开始对话。

**报告写作智能体**示例会创建 id 为 `report-writer` 的 Agent。[评估中心](/evaluation-center)里有配套的 Benchmark 示例，创建后可以继续对这个 Agent 做评估和优化。

## 手动创建 Agent

1. 在**智能体**页面选择**手动创建**，打开**创建 Agent** 对话框。
2. 可选：有已连接的机器时，在**位置**中选择在哪里创建：**本机**或某台机器。建在机器上的 Agent 归那台机器所有：可选的插件来自那台机器的插件库，第 7 步的目录在那台机器上选择，建好后打开的是它在那台机器上的设置。改选位置会清空已选的插件和目录。
3. 可选：在**名称**中填写名称。名称留空时用 Agent id。
4. 在 **Agent id** 中输入 id，也可以点击输入框旁边的**用 AI 生成**，由 Project 的默认模型根据名称生成一个；名称为空时则根据描述生成。id 长度为 2–64 个字符，以小写字母开头，只能用小写字母、数字和下划线。生成的 id 会覆盖框里原有的内容，之后仍可以手动修改。创建后 id 不能再改。
5. 可选：填写**描述**。
6. 可选：在**插件**中从插件库选择要装到新 Agent 上的插件。Agent 创建时会一并装上这些插件的 Skill 和钩子包。
7. 可选：在**从项目目录导入技能**中选择一个目录。PenguinHarness 会读取这个目录下 `.agents/skills` 和 `.claude/skills` 文件夹里的 Skill，从中勾选要安装的。目录里的 Skill 与所选插件里的 Skill 同名时，装的是目录里的那个。
8. 选择**创建**，打开新 Agent 的设置。

任何 Project 成员都能创建 Agent。

要从导出的文件创建 Agent，选择对话框页脚的**导入 Agent**。

## 导入 Agent

**智能体**页面创建按钮旁的**导入 Agent** 打开一个对话框，提供两种方式。

### 从其他框架迁移

把在 Claude Code、Codex、DeepSeek Harness、Qoder、Qwen Code 或 WorkBuddy 里配置好的 Agent 迁移成本 Project 里的新 Agent。

1. 在**来源框架**中选择工具；其他工具选**其他**。
2. 可选：在**路径**中填写它的文件所在位置。留空则读取框中显示的该工具用户目录：`~/.claude`、`~/.codex`、`~/.dsh`、`~/.qoder`、`~/.qwen` 或 `~/.workbuddy-ai`。选**其他**时，该字段改为**路径或说明**，必须填写。
3. 可选：展开**完整提示词**查看 Prompt，或复制它。
4. 选择**打开新对话**。系统会打开与 Project 的 `default_agent`（没有时为第一个 Agent）的新对话，并预填 Prompt，此时还不会发送。
5. 检查 Prompt 后发送。

Agent 按 `skill-porting` 插件中的 `agent-porting` Skill 操作：只读取来源、不做改动，绝不复制密钥的值；按导出 zip 的布局写出新 Agent，用 `penguin agent import` 导入，并报告新 Agent 的 id、迁移了哪些内容、哪些没能迁移及原因，以及需要填写的保险柜键。如果该 Agent 还没有这个 Skill，**打开新对话**会先为它安装这个插件。

### 导入文件

1. 在**导入文件**下点击**选择文件**，选定从 Agent 导出的 `.zip`。1.0 之前，旧的 `.tar.gz` 快照包也可以导入。
2. 检查 **Agent id**。它按文件名自动填入，并去掉 `-<yyyymmdd>` 或 `-v<n>` 尾缀。
3. 选择**导入**。提示会说明 Agent 是新建还是覆盖，以及导入和略过了多少个对话；新 Agent 随即出现在列表中。

任何 Project 成员都能导入新 Agent。id 已被占用时，对话框会提示：选择**改用其他 id** 修改 id；Project owner 也可以选择**覆盖现有 Agent** 并确认。覆盖会替换该 Agent 的 Agent State 中文件所带的部分，它的对话、密钥保险柜与 API 密钥保留，替换前先写一份备份快照。

## 删除 Agent

只有 Project owner 能删除 Agent。内置的 `default_agent` 不能删除，组织的员工也不能：员工的卡片上写着它任职的组织，在公司模式离任之后才能删除（见[员工就是 Agent](/company-mode#员工就是-agent)）。

1. 在 Agent 卡片上选择删除按钮（**删除 Agent**）。
2. 确认。

> [!WARNING]
> 删除 Agent 会删除它在服务端的目录，包括全部 Trace，删除后无法恢复。

## Agent 设置

要打开某个 Agent 的设置，可以在卡片上选择**设置**，可以点击卡片上的某个数字，也可以在侧边栏对应分组上选择 **Agent 设置**。设置分为几个标签页：

| 标签页 | 配置内容 |
| --- | --- |
| **概览** | 名称、描述和作者，导出与从文件替换、内核更新、还原为默认配置 |
| **系统提示词** | `AGENTS.md` 和系统提示词模板 |
| **运行参数** | 轮次上限、输出 Token、思考等级、超时和上下文压缩 |
| **工具** | 内置工具设置和 MCP Server |
| **插件** | Agent 装了哪些插件，以及每个插件带来的 Skill、钩子包、MCP Server 和工作台；你自己的 Skill、钩子包和工作台；技能、钩子和工作台的开关 |
| **记忆** | Agent 的记忆和记忆提示词 |
| **密钥保险柜** | Agent 命令用的环境变量 |
| **定时任务** | 定时任务 |
| **API** | 是否允许程序经 Agent API 调用这个 Agent、这些对话的审批模式，以及密钥 |

每个标签页都有自己的地址：`/agents/<agentId>?tab=<tab>`，其中 `<tab>` 是 `overview`、`prompt`、`runtime`、`tools`、`plugins`、`memory`、`vault`、`schedules` 或 `api`。以前的 `skills`、`hooks` 和 `workbenches` 地址会打开**插件**。

### 保存修改

在概览、系统提示词、运行参数和工具四个标签页，以及各个提示词区块，选择**保存**并确认。确认框写着：「确定保存这些修改吗？修改将写入服务器上的配置文件。」

- 大多数修改立即对新对话生效；正在运行的对话要在下一次压缩后才生效。
- 运行参数的修改如果只涉及上下文压缩字段，则立即生效，正在运行的对话也不例外。
- **启用技能**这类开关一拨动就保存，不需要按**保存**。

这些设置对应的文件格式见 [Agent 配置](/configuration#agent-配置)。

### 权限

大多数设置，任何 Project 成员都能修改。以下操作只有 Project owner 能做：

- 删除 Agent，以及用文件覆盖或替换 Agent；
- **插件**标签页上的开关（**启用技能**、**启用钩子**、**启用工作台**和每个工作台自己的开关）、**技能提示词**，以及卸载插件；
- 编辑密钥保险柜变量、**启用密钥保险柜**开关和**保险柜提示词**；
- 创建、编辑、启用、停用和删除定时任务，编辑**启用定时任务**开关和**定时任务提示词**（成员仍可使用**用 AI 创建**）；
- 导入记忆；
- **API** 标签页上的一切：开关、审批模式、无密钥访问和密钥。

## 概览标签页

### 修改名称、描述和作者

修改**名称**、**描述**或**作者**，然后选择**保存**。**作者**说明这个 Agent 由谁创建：**用户**（用户在 Web App 中创建）、**智能体**（由智能体创建，例如通过**用 AI 创建**）或**公司模式**。它决定 Agent 在**智能体**页面归入哪一组，别的都不影响。

### 导出和导入 Agent

**Agent State** 区块显示 **Agent State 版本**和 **State 路径**（Agent State 在服务端所在的文件夹），点击复制按钮可以复制路径。

- **导出…**：打开导出对话框，卡片上的**导出 Agent** 打开的也是它。选择配置之外还带上哪些内容：**技能**、**钩子**、**记忆**、**工作台**（勾选**含其数据**时带上各工作台的状态）和**定时任务**（缺省不勾）。在**对话**下选择**不含**、**最近 N 条**（缺省 20，最多 500）或**日期范围**。选择**导出**保存 `<agentId>-<yyyymmdd>.zip`。
- **从文件替换…**（仅 Project owner）：以只有文件一节的形式打开[导入对话框](#导入-agent)。选定导出的文件，选择**替换**并确认。

Agent 以其目录的 zip 往来：`<agentId>/agent_state/…`，以及所选 Session 的 `<agentId>/traces/…`。没有清单，名称、描述与版本本就在 `system_config.yaml` 里。配置总是带上；Skill、钩子、记忆与 Workbench（可含其数据）缺省带上，可以去掉；定时任务只在选择时带上，因为导入后会按计划运行。密钥保险柜从不进包，Trace 中出现的 vault 值替换为 `[vault:<KEY>]`。直接写在配置里的字面值会原样带出，凭据请以 `${KEY}` 引用。

- 以尚无 Agent 的 id 导入时，从包新建 Agent，State、名称、描述与版本取自包内。任何成员都可以。
- 覆盖已有 Agent 只有 Project owner 能做。先把当前 Agent State 打包成一个单独的备份 `snapshots/import-backup-v<version>-<time>-<random>.tar.gz`，再以包里的内容替换：包里没有的部件（如不带记忆的导出）沿用该 Agent 现有的内容，包里没带数据的工作台也保留现有数据。Agent 的对话、密钥保险柜、API 密钥与任职保留。工作台的版本历史位于 Agent State 之外，导入不会改动它。
- 包里的 Session 落为该 Agent 的对话，标题取自首条消息。本服务器已有的 Session（同一服务器导出再导入即是如此）跳过并在结果中列出。
- `system_config.yaml` 缺 `system_prompt` 的包叠加在默认配置之上，包里没带的文件沿用默认值，因此手写的包只需写出要改的键。

此前导出的 `.tar.gz` 快照包在 1.0 之前照样可以导入。路由见 [Agent 路由](/server-api#agent-路由)。

版本和快照的工作机制见[自我进化](/self-improvement#快照与版本)。

### 更新内核

Agent 的内核版本记录它的配置基于哪一代内置默认设置。已有的 Agent 永远不会自动采用更新的默认值。PenguinHarness 发布新默认值后，**内核**区块会显示当前内核版本和最新内核版本，概览标签页上出现红点。

1. 在**内核**区块选择**更新内核**。
2. 确认。

没有自定义过的标签页会更新为当前的内置默认值。编辑过的标签页整个保持不变，并在结果中列出。名称、描述、作者、Agent State 版本和 MCP Server 不受影响。详情见[内核更新](/configuration#内核更新)。

> [!TIP]
> 要一次更新多个 Agent，可以在**智能体**页面顶部的通知里选择**现在升级**。

### 还原为默认配置

1. 在**内核**区块选择**还原为默认配置**。
2. 确认。

> [!WARNING]
> 还原为默认配置的操作无法撤销。

还原时用当前默认值覆盖 Agent 的配置：自定义系统提示词、工具列表、模型和压缩设置、MCP Server 全部替换，只保留名称、描述、作者和 Agent State 版本。插件安装的 MCP Server 也会被移除；在**插件市场**页面用**管理安装**即可装回。

## 系统提示词标签页

- **AGENTS.md** 保存 Agent 的角色、规则和工作指令。
- **system_prompt 模板**：系统提示词由这个模板生成。

在「可用占位符（点击插入）」下选择一个占位符，即可插入到模板中光标所在位置：

| 占位符 | 插入内容 |
| --- | --- |
| `{{AGENTS_MD}}` | `AGENTS.md` 的内容 |
| `{{VAULT}}` | 密钥保险柜区块：**保险柜提示词**加变量名列表；**启用密钥保险柜**关闭时为空 |
| `{{SKILLS}}` | Skill 区块：**技能提示词**加已安装 Skill 的元数据；**启用技能**关闭时为空 |
| `{{MEMORY}}` | 记忆区块：主记忆提示词，持久 Workspace 中还包括工作区附加段；记忆关闭时为空 |
| `{{SCHEDULES}}` | 定时任务区块：**定时任务提示词**加任务名列表；**启用定时任务**关闭时为空 |
| `{{PLATFORM}}` | 运行平台 |
| `{{OS_VERSION}}` | 操作系统版本 |
| `{{SHELL}}` | 执行命令所用的 shell |
| `{{DATE}}` | 当前日期 |
| `{{PROJECT_DIR}}` | PenguinHarness 应用数据根目录，存放所有 Agent 数据和 Project 数据；不是 Task 的工作目录 |
| `{{AGENT_ID}}` | Agent 的 id |
| `{{CWD}}` | Workspace 的绝对路径 |
| `{{PROVIDER}}` | 模型的供应商分组 |
| `{{MODEL_ID}}` | 上游模型 id |
| `{{SESSION_ID}}` | Session id |

密钥保险柜、Skill、记忆和定时任务区块的开关和提示词，分别在各自的标签页里。另见[系统提示词占位符](/configuration#系统提示词占位符)。

## 运行参数标签页

| 字段 | 含义 |
| --- | --- |
| `max_turns` | 一个 Task 允许的最大轮次；`-1` 表示不限 |
| `model.max_tokens` | 每次请求的输出 Token 上限 |
| `model.thinking_level` | `low`、`medium`、`high`、`xhigh` 或 `max`。新建 Agent 默认 `medium`。在部分模型上，`xhigh` 和 `max` 的实际表现与低一档相同。保存过旧档位 `none` 的 Agent 会继续保留，但选项中不再提供 |
| `model.timeoutMs` | 等待模型供应商事件的时间上限，单位毫秒；不限制整个请求的时长 |
| `max_context_length` | 触发压缩的上下文大小 |
| `max_session_turns` | 触发压缩的轮数 |
| `mode` | `summarize`（默认）：让模型总结旧上下文，然后在新的窗口里从总结继续；`discard`：直接丢弃旧上下文，不做总结 |
| `prompt` | 总结上下文时使用的提示词 |

`max_turns` 和 `model.timeoutMs` 接受大于 0 的数字或 `-1`。思考等级在各模型上的表现见[思考等级](/models#思考等级)。压缩的工作方式见[压缩](/agent-loop#上下文压缩)。

## 工具标签页

### 内置工具

表格列出全部内置工具，每个工具可以设置：

| 列 | 含义 |
| --- | --- |
| `permission` | **Read-only**（`r`）：工具只读取，「放行只读」审批模式会自动放行。**Read & write**（`rw`）：工具可能修改内容，「放行只读」审批模式会先询问你 |
| `timeoutMs` | 工具的时限，单位毫秒 |
| `maxOutputLength` | 工具最多可返回的输出量 |
| `call_description` | 模型是否为每次调用写一句话描述，调用运行时会显示给你。默认开启；只有支持描述的工具才能切换 |

字段留空即使用默认值。点击**保存**即可保存表格。审批模式见[审批](/tools#审批)。

### 添加 MCP Server

MCP Server 给 Agent 增加外部工具，工具名形如 `mcp__<name>__<tool>`。**MCP Server** 区块里的改动立即保存。

1. 在**工具**标签页选择**添加 MCP Server**。
2. 选择传输方式：
   - `http`（默认）：Streamable HTTP，当前的远程传输方式。
   - `stdio`：本地进程，由 PenguinHarness 启动，通过 stdin 和 stdout 通信。
   - `sse`：旧的 HTTP+SSE 传输方式，供尚未迁移的 Server 使用。
3. 在 **name** 中输入工具名前缀，可以用字母、数字、`_` 和 `-`，以字母或数字开头。
4. 填写连接字段：
   - `stdio`：**command**；**args**，每行一个参数；**env**，每行一个 `KEY=value`；**cwd**，默认是 Session 的 Workspace。Agent 的密钥保险柜不会整个传给 MCP Server 进程；要给 Server 机密，写成下文介绍的 `${KEY}` 引用。
   - `http` 和 `sse`：**url**；**headers**，每行一个 `Header-Name: value`，例如 `Authorization: Bearer ${LINEAR_API_KEY}`。
5. 选择 **permission**：
   - **Auto（readOnlyHint）**：工具声明了 `readOnlyHint` 注解就按只读处理，否则按 Read & write 处理。
   - **Read-only**：Server 的所有工具都按只读处理。
   - **Read & write**：Server 的所有工具都按 Read & write 处理。
6. 可选：调整 **connectTimeoutMs**（连接和发现工具，默认 10000）、**timeoutMs** 和 **maxOutputLength**，这些设置对 Server 的所有工具生效。
7. 可选：保存前选择**测试连接**验证配置，它会报告发现的工具数量和耗时。用到密钥保险柜中的值（`${KEY}`，见下文）的条目只按保存后的内容测试：条目还是新的或改动过时，测试什么都不填入，并提示先保存。
8. 选择**保存**。

> [!NOTE]
> permission 级别只在「放行只读」审批模式下起作用，其他审批模式都会忽略它。它也不限制 Server 能做什么：把 Server 标为只读，只是让这个审批模式跳过本该弹出的确认。

写成 `${KEY}` 的值（`KEY` 是 Agent [密钥保险柜标签页](#密钥保险柜标签页)上的变量名）会在 Server 连接时从密钥保险柜填入。配置里只保留引用，机密因此不会出现在 `system_config.yaml` 中。除 URL 的主机部分外，任何字段都可以使用引用，见 [Vault 引用](/tools#vault-引用)。

要修改某个 Server，在它的行上选择**编辑**。要移除，选择**删除**并确认；从下一个 Session 开始，它的工具不再可用。更多关于 MCP Server 的内容见 [MCP Server](/tools#mcp-server)。

安装带 MCP Server 的插件，也会把这些 Server 加进这个列表，见[在 Agent 上安装插件](/skills#在-agent-上安装插件)。这样的行在名称后显示拼图图标，指向它可以看到是哪个插件安装了这个 Server。**编辑**会保留条目与插件的关联，并注明重新安装插件会替换它。**删除**前会先确认，并说明可以在**插件市场**页面用**管理安装**把它装回来。

暂时连不上的 Server，行上还会显示一个图标。对话会跳过这个 Server，并在 MCP 连接那一行说明原因：

- 钥匙图标：Server 待设置，因为密钥保险柜里缺少它的条目引用的键。指向图标可以看到键名。Project owner 在**密钥保险柜**标签页添加这些键，或在插件的**管理安装**对话框中点击**设置**。
- 登录图标：Server 用 OAuth 登录，本版本尚不支持。

### 测试 MCP Server

1. 在 **MCP Server** 区块选择表头的**全部测试**。
2. 选择**开始测试**。

PenguinHarness 依次连接每个 Server 并发现它的工具，不会保存任何内容。每行显示工具数量和耗时；失败则显示**连接失败**和原因。测试前会先填入对密钥保险柜的引用；密钥保险柜缺键的 Server 直接以缺少的键名报失败，不会尝试连接。

## 插件标签页

**插件**标签页按来源插件列出 Agent 装了什么。从上到下依次是：

- **导入**：添加 Skill、钩子包或工作台（上传 zip，或在对话中让 Agent 导入）。**浏览插件库**打开**插件市场**页面，插件在那里安装。
- **启用技能**决定系统提示词是否列出已安装的 Skill，列出时使用下方的**技能提示词**。**启用钩子**决定新对话是否运行钩子包。**启用工作台**一次关闭或重新打开这个 Agent 的全部工作台。
- **已装插件**每个插件一行，写明它带来了什么（例如「3 个技能、钩子、1 个工作台」）和状态：**已安装**、**可更新**、**不完整**（少了部件）或**不在插件库**（管理员已把它从插件库删除）。**更新**把插件库里的版本重新装一遍，缺的部件也会补上。**卸载**一次删除这个插件的全部部件，确认框会先逐项列出。点开一行可以看到它的部件。
- **不属于插件**列出你自己创建或导入的 Skill、钩子包和工作台。

Skill 的名字和某个插件自带的 Skill 相同，就算作那个插件的部件。所以你自己写的同名 Skill 会列在那个插件下面，卸载插件时一起删除。插件的 MCP Server 只列名称和还缺什么（比如密钥），编辑要到**工具**标签页。

有部件没能删除时，提示会写明是哪一个，其余部件照常删除。Agent 所在的机器版本较旧时，无法整个卸载插件，先到**机器管理**页面更新那台机器。

### Skill 和钩子包

Skill 行显示名称、简短描述和版本，可以**打包导出**和**卸载**。钩子包行还会显示它在哪些钩子点运行。见[管理 Agent 的 Skill](/skills#管理-agent-的-skill)和[钩子包](/skills#钩子包)。

### 工作台

每个工作台（包括加载失败的）一行；有应用中心图标的，行首显示该图标。**打开**在新对话旁打开工作台；**更多**菜单（⋯）可以**重新加载**、在**历史版本**中**恢复**较早的版本、用**打包导出**把源码下载为 zip，或者**移除**。行上的两个开关各带文字：**启用**与**应用中心**；点击开关旁的文字同样可以拨动。

- **启用**开关关闭工作台但不删除任何东西：它不再出现在对话页和应用中心，页面也打不开，数据和历史版本都保留，**历史版本**、**恢复**、**打包导出**和**移除**照常可用。**启用工作台**关闭时，所有工作台都停用，各自的开关置灰并保持原值，重新打开即恢复。Agent 所在的机器版本较旧时不显示这些开关。
- **历史版本**最多列出 50 个版本，最新的在前。**恢复**把工作台的源码精确换成该版本并立即重新加载，数据（`state.json`）保持不变。
- **移除**删除工作台及其数据，此前的版本不再列出，即使之后再建同 id 的工作台也是如此。手工删除文件夹则不同：之后同 id 的工作台仍会列出这些版本。卸载工作台所属的插件也会这样删除它；想保留数据，请改为关掉它的开关。
- **应用中心**开关把工作台的快捷入口放进 Project 的[应用中心](/web-app#应用中心)，或从中移出。开关即拨即生效：它改写工作台自己 `package.json` 中的 `penguin.appCenter.show`，文件其余部分不变，随后的重新加载记为一个版本（已关闭的工作台不加载）。已连接机器上的 Agent 没有应用中心开关，因为应用中心只列出本服务器的 Agent。
- **打包导出**下载的 zip 只有一个以工作台 id 命名的顶层文件夹，从不包含 `state.json`、隐藏文件和 `node_modules`，可以原样导回。
- **导入** › **工作台**有两种方式。推荐的方式是在**工作台来源**中填入网页、GitHub 仓库或目录、本地路径、安装命令或一段描述，再点击**打开新对话**；也可以点击**复制 Prompt**，拿到别处使用。Agent 会读完每个文件，发现可疑之处就停下来告诉你，确认安全后把工作台装到这个 Agent 上并重新加载。另一种方式是在**上传工作台 zip**下从 zip 添加工作台：`package.json` 位于 zip 根目录，或位于唯一一个以工作台 id 命名的顶层文件夹中。zip 中若有位于工作台顶层的 `state.json`、隐藏文件、`node_modules`、链接、git 拒绝的名称或 Windows 不能使用的名称，会在写入任何文件之前被拒绝。Agent 已有同 id 的工作台时，覆盖其源码之前会先确认；数据保留，加载成功过的版本仍可从**历史**恢复，从未加载成功的本地改动会丢失。导入后工作台立即加载；加载失败时显示加载错误，而不是成功提示。

开关、**技能提示词**和卸载插件只有 Project owner 能操作，成员只能看到开关的状态。导入、更新、导出和移除部件，任何成员都能做。在对话旁打开工作台时，它的标签栏同样提供**历史**和**移除**。见 [Workbench 插件](/skills#workbench-插件)。

## 记忆标签页

记忆让 Agent 跨 Session 保留学到的东西。Agent 在工作过程中会自己保存值得记住的内容，你也可以让它记住指定内容。**用户记忆**对这个 Agent 的所有 Session 生效；Workspace 记忆按 Workspace 分别保存。

- **启用记忆**开关控制记忆的开与关，切换后立即保存。关闭后只是阻止记忆进入 Agent 的上下文、不再为新 Session 准备记忆，不会删除任何内容。
- 系统提示词模板里没有 `{{MEMORY}}` 占位符时，标签页会给出提示，选择**插入 {{MEMORY}} 占位符**即可补上。记忆功能出现之前创建的 Agent 会有这种情况。

记忆按范围分组：**用户记忆**排在最前，之后每个 Workspace 一组。点击分组标题可以折叠或展开；浏览器会为每个用户、Project 和 Agent 记住折叠状态。

### 查看、编辑和删除记忆

每条记忆一行，行上有三个按钮：

- **查看**：在侧边面板显示这条记忆的标题、日期、描述和内容；窄屏下则从底部弹出面板，可以半屏或全屏高度打开。
- **编辑**：打开**编辑记忆**对话框。在**修改要求**里描述要改什么（可选），然后选择**打开新对话**。会打开和这个 Agent 的新对话，提示词已填好；如果编辑的是 Workspace 记忆，还会使用对应的 Workspace。发送消息后，Agent 会同时更新记忆文件和 `MEMORY.md` 索引。
- **删除**：确认后删除这条记忆，并从 `MEMORY.md` 里移除对应的行。

记忆内容要通过对话交给 Agent 修改，不能就地编辑。

### 记忆附带的脚本

一条记忆可以在同名文件夹里附带脚本。这时它的一行会显示回形针和文件数；**查看**时，这些文件列在记忆内容下方的**文件**中，各带路径、大小和日期。文件一行有两个按钮：

- **查看**：在同一个侧边面板显示文件所在的路径和带行号的代码，**返回**回到那条记忆。超过 512 KB 或不是文本的文件只列出、不显示。
- **删除**：确认后删除这个文件。记忆正文中对它的说明不会随之删去，要等 Agent 更新。

删除一条记忆会连同它的文件夹一起删除，确认框会写明带走几个文件。文件没有**编辑**：要修改，在对话里请 Agent 来改。该 Agent 此后的每个 Session 都可能运行这些脚本，依赖某个脚本之前先看看它的内容。详见[脚本](/configuration#脚本)。

旁边没有同名记忆的文件夹（多半是记忆删除后留下的）不属于任何记忆。其中的文件列在分组底部的**不属于任何记忆的文件**下，按钮相同。

### 添加记忆

1. 在分组标题上选择**添加**，打开**添加记忆**对话框。
2. 在**要记住的内容或来源**里粘贴内容、文件路径或 URL。
3. 选择**打开新对话**，然后发送消息。Agent 会把内容整理成这个分组里的记忆。

### 导出和导入记忆

- 分组标题上的**导出**：把分组的文件夹下载为一个 zip：`MEMORY.md`、全部记忆及各自附带的文件，都是磁盘上原样的文件。文件名包含导出日期和时间，多次导出不会互相覆盖。
- 分组标题上的**导入**：把这样的 zip 读回分组。早先版本导出的 JSON 文件照样可以导入。只有 Project owner 能导入。

导入时，如果分组里已有同名记忆，需要选择处理方式：

| 选项 | 结果 |
| --- | --- |
| **保留现有的这条**（默认） | 只添加分组里没有的记忆。不丢失任何内容 |
| **改用文件里的版本** | 替换同名记忆，连同其附带的文件。文件里没有的记忆保持不变 |
| **整组替换** | 删除文件里没有的全部记忆及其文件，以及不属于任何记忆的文件夹 |

如果导入会覆盖或删除记忆，或者替换分组的 `MEMORY.md`，会先弹出**确认导入**对话框，列出将要发生的变化。

记忆连同文件一起迁移：采用文件版本的记忆，导入后其文件夹里恰好是文件中的那些文件。不属于任何记忆的文件夹，视为同名记忆已在分组中。

现在导出的 zip 不能导入到此前的服务端：那里只接受 JSON 文件，会拒绝它。

### 记忆提示词

在**记忆提示词**下编辑 `{{MEMORY}}` 占位符展开后的文本：

- **主提示词**（`memory.prompt`）：注入每个 Session。
- **工作区附加段**（`memory.workspace_prompt`）：只注入带持久 Workspace 的 Session。

这些提示词可以用 `{{USER_MEMORY_INDEX}}`（用户 `MEMORY.md` 索引）、`{{WORKSPACE_MEMORY_INDEX}}`（Workspace 的 `MEMORY.md` 索引）和 `{{WORKSPACE_MEMORY_DIR}}`（当前 Workspace 的记忆文件夹）。后两个只在工作区附加段里生效。每个索引最多 200 行、25,000 字符。

点击 Agent 卡片上的记忆数字即可打开这个标签页。

## 密钥保险柜标签页

密钥保险柜存放 Agent 用的环境变量，比如 API key。PenguinHarness 把它们传给 Agent 的 shell 命令；MCP Server 只拿到它的条目以 `${KEY}` 引用的那几个。模型只能看到变量名，永远看不到值。子 Agent 用各自的密钥保险柜，不继承这里的变量。修改从下一个 Task 起生效；正在运行的 Task 不受影响。

只有 Project owner 能修改密钥保险柜。成员能看到变量名，值以掩码显示。

### 添加变量

1. 在**密钥保险柜**标签页选择**手动创建**，打开**添加环境变量**对话框。
2. 在**键名**中输入变量名，例如 `OPENAI_API_KEY`。可以用字母、数字和下划线，不能以数字开头。
3. 在**值**中输入变量值。
4. 选择**添加**。变量已存在时，确认后覆盖原值。

要删除变量，在它的行上选择**删除**并确认。值无法恢复。

### 用 AI 添加变量

选择**用 AI 创建**会打开**让 AI 添加密钥**。描述需要的变量，或选一个示例：**盘点这个智能体需要的 key**、**重置一个过期 token** 或 **接入一个内部服务**。然后选择**在新对话中编辑**并发送提示词。Project 的默认 Agent 会用 `penguin config vault set` 写入变量。

> [!WARNING]
> 在这个对话框里输入的密钥值会发送给模型供应商，记录进对话的 Trace，还会在 Agent 运行的命令里再次出现。更安全的做法是让 AI 只创建变量名并说明各自用途，然后你在**密钥保险柜**标签页自己填入值。

### 保险柜提示词

- **启用密钥保险柜**控制密钥保险柜区块是否进入系统提示词。关闭时，变量仍然会传给 Agent 的命令。
- **保险柜提示词**：`{{VAULT}}` 占位符展开后的文本。其中的 `{{VAULT_KEYS}}` 占位符列出变量名，每行一个。

## 定时任务标签页

定时任务按计划给 Agent 发送提示词：发一次，或按周期反复发。这个标签页上的修改立即生效。

> [!NOTE]
> 定时任务只在 PenguinHarness 服务运行时触发。

也可以在对话里创建和管理定时任务，见[定时任务](/schedules)。

### 创建定时任务

只有 Project owner 能手动创建定时任务。

1. 在**定时任务**标签页选择**手动创建**，打开**新建定时任务**对话框。
2. 在**名称**中输入任务的文件名，不带 `.toml`。创建后不能修改。
3. 在**周期**中输入任务运行频率，例如 `30m`、`12h` 或 `7d`。一次性任务留空。最短周期为 5 分钟。
4. 设置**开始时间**，也可以设置**结束时间**。一次性任务的**开始时间**必须晚于当前时刻，**结束时间**不能早于当前时刻。
5. 在**目标**下选择提示词发到哪里：
   - **每次新建会话**：每次运行都新建一个 Session。可以再选 **Model**（不选就用 Project 默认值）和 **Workspace**（不选就用临时 Workspace）。
   - **绑定 Session**：每次运行都发给同一个已有的 Session。在 **Session** 中选择。
6. 在 **Prompt** 中输入要发送的内容。
7. 保持勾选**启用**以激活任务，然后选择**创建**。

也可以用描述的方式创建：选择**用 AI 创建**，或从列表为空时显示的**建议**中选一个：**每日简报**、**每周回顾**、**跟进提醒**或**监控更新**。然后选择**在新对话中编辑**并发送提示词。Project 的默认 Agent 会为这个 Agent 创建任务。任何成员都能使用**用 AI 创建**。

### 管理定时任务

表格显示每个任务的**名称**、**状态**、**周期**、**目标**、**下次 / 最近触发**和**排队**。状态可能是**生效**、**停用**、**已过期**、**已完成**、**已错过**或**无效**；指向**无效**可查看原因。已完成、已错过和已过期的任务会归档，随即移出表格，见[结束的任务会归档](/schedules#结束的任务会归档)。

owner 可以在每一行选择**停用**或**启用**、**编辑**、**删除**。无法解析的文件列在「解析失败的文件（已跳过调度）」下。

### 定时任务提示词

- **启用定时任务**控制定时任务区块是否进入系统提示词。关闭时，任务照常运行。
- **定时任务提示词**：`{{SCHEDULES}}` 占位符展开后的文本。它教模型用文件工具管理定时任务，其中的 `{{SCHEDULE_LIST}}` 占位符列出任务名。

## API 标签页

**API** 标签页让 PenguinHarness 之外的程序经 HTTP 与这个 Agent 对话：**开启 API 访问**、**API 会话的审批模式**、**连接**下的 **Base URL** 和 **Agent ID**、**密钥**、**允许无密钥访问**、调用**示例**，以及只对 Project 所有者显示的**试一试**：经 API 运行一次这个 Agent，按程序会收到的样子显示事件流。这个标签页没有**保存**按钮：开关和审批模式改动即生效，关闭 API 访问和删除密钥前会先确认。如何设置、如何调用，见 [Agent API](/agent-api)。

## 工作原理

Agent 的配置和数据存放在它的 Agent State 里，也就是概览标签页上 **State 路径**显示的 `agent_state/` 文件夹。里面有 `system_config.yaml`、`AGENTS.md`、密钥保险柜、工具、Skill、钩子包、工作台、定时任务和记忆。Agent 的 Trace 不在其中，而是存放在它旁边、这个 Agent 自己的文件夹里，见[数据目录](/sessions-and-traces#数据目录)。

- 记忆是 `agent_state/memory/` 下的文件，每个分组有一个 `MEMORY.md` 索引。存储方式见[记忆](/configuration#记忆)。
- 密钥保险柜变量保存在 `agent_state/.vault.toml`。文件格式见[密钥保险柜](/configuration#vault)。
- 定时任务以 TOML 文件保存在 `agent_state/schedule/` 下，也可以手动编辑。文件格式见[定时任务](/configuration#定时任务)。
- 工作台是 `agent_state/workbenches/<id>/` 下的文件夹，它们的版本是 `agent_state.git/` 中的提交，这是服务端在 `agent_state/` 旁维护的裸 git 仓库。见 [Workbench 插件](/skills#workbench-插件)。
