# JellyToken 首版验收测试用例

适用分支：`feat/add-jellytoken-provider`。依据：[功能规格](specs/jellytoken-provider/spec.md)、[技术设计与九模型价目表](design.md)。本表是可执行的验收步骤，不是测试结果。初始状态：全部待执行。

## 准备与判定基准

- 准备三个隔离项目：A 为新项目，使用没有已保存排序偏好的浏览器；B 为升级前的项目，保存一条自定义模型、地址、密钥和非 JellyToken 默认模型；C 在升级前已自建 `jellytoken` 分组并设置地址与密钥。记录 B、C 的非敏感配置以便比较。
- 自动化使用模拟网关、虚构密钥和临时数据目录；记录请求方法、目标地址、模型标识和响应事件。真实供应商联调独立执行，不作为离线测试前提。
- **九模型顺序基准**（以下称“基准序列”）：① `deepseek-v4.1-flash-1017` → ② `qwen4-max` → ③ `glm-5.3` → ④ `glm-5.3-flash` → ⑤ `qwen3.8-flash` → ⑥ `glm-5.3-flashx` → ⑦ `doubao-seed-2.1-lite` → ⑧ `doubao-seed-2-1-pro` → ⑨ `kimi-k3`。
- **两个地址分开验收**：网页登录 `https://www.jellytoken.com/auth/login`；默认推理 `POST https://aiservice.jellytoken.com/v1/chat/completions`。
- P0 为核心验收，P1 为回归或条件验收。执行时对每个编号记录通过／失败／阻塞及脱敏证据。未实现、无账号权限或未授权付费调用，均不记为通过。

## 一、模型发现与展示

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| JT-01 · P0 | 在 A 搜索 JellyToken，展开该组；清空搜索，再从「其余分组」找到它。 | 两处均能找到同一内置分组。组内恰有九张预设卡，逐项符合基准序列，而不是价格顺序或字母顺序。未把 JellyToken 设为默认或官方推荐，没有钱包连接与余额入口。 |
| JT-02 · P0 | 在 A 保存组密钥，在新对话选择器查看组内模型；再在模型库搜索 `glm`。 | 选择器中九个已配置模型的默认顺序符合基准序列；模型库过滤后，JellyToken 组内为 `glm-5.3`、`glm-5.3-flash`、`glm-5.3-flashx`，相对顺序不变，不与其他供应商同名项合并。 |
| JT-03 · P0 | 从项目模型接口读取九条预设，再检查九张模型卡和选择器项目。 | 每条实际窗口值均为十进制 `1000000`，卡片显示 `1M`。模型库和选择器均无「视觉」标签或“支持／不支持图片”说明。这里只验证配置与展示，不据此判定上游支持图片或已实测百万词元。 |
| JT-04 · P1 | 记录 SiliconFlow 等既有分组的默认顺序；给其中一组设置个人排序后刷新并查看 JellyToken。 | 其他组的默认行为和保存的排序仍有效；其他组的设置不改变 JellyToken 的默认顺序。 |

## 二、设置、权限与密钥

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| JT-05 · P0 | 以所有者打开 A 的分组设置，检查预填值；分别点击「前往密钥管理」「前往模型列表」。再打开组内新增模型表单，找到「获取模型 id」「前往密钥管理」并分别点击。 | 分组基础地址为 `https://aiservice.jellytoken.com/v1`，后缀为 `/chat/completions`，可编辑地址并手动检测协议。四个链接均打开上述网页登录地址，不附带密钥；点击「获取模型 id」不导入模型、不发推理请求。 |
| JT-06 · P0 | 在 A 输入虚构组密钥 K1 并保存。刷新、重开弹窗；密钥输入留空，只修改其他设置并保存，再用一条无覆盖的模型发起模拟请求。 | 保存本身不发推理请求；重开只见掩码，项目模型接口不回传明文；留空未清除 K1，请求仍使用组密钥。 |
| JT-07 · P0 | 将组密钥 K1 换成 K2，以两条继承分组的模型分别请求；显式清除组密钥再试。 | 两条请求均使用 K2，不再使用 K1。清除后两条无独立密钥的模型均不再具备可用密钥。 |
| JT-08 · P0 | 模型与组均无密钥，保留 JellyToken 默认地址；仅在测试服务环境中设一个假的 `OPENAI_API_KEY`，尝试对话。 | 明确提示缺少密钥；模拟网关没有收到携带环境密钥的请求。 |
| JT-09 · P0 | 分组有 K1。一条模型在同源地址设自己的 K2，另一条保留默认值；分别请求。再将第一条改为不同源测试地址并清除其独立密钥。 | 同源覆盖项使用 K2，其他项使用 K1；换到不同源且无独立密钥后，新地址绝不收到 K1。 |
| JT-10 · P1 | 所有者在 JellyToken 分组中手动添加一个模拟网关接受的额外模型标识，模型级地址、协议、密钥留空，然后调用。 | 新项归属 JellyToken，沿用组级连接和密钥；请求携带手填模型标识。原九条未被替换，也未从供应商全量导入。 |
| JT-11 · P1 | 用非所有者账号查看分组，并尝试直接提交分组连接修改。 | 不提供所有者专属的设置写入入口；服务端拒绝未授权修改，所有者再读取时连接未变。 |

## 三、推理与计费

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| JT-12 · P0 | 设置虚构组密钥，在模拟网关下对九条预设逐一发送文本请求，检查实际出站请求。 | 均为上述默认推理地址，无重复 `/v1`；鉴权为配置的 Bearer 密钥；请求体 `model` 与所选标识逐字一致，尤其不混淆两个豆包标识中的点和短横线。没有请求发往网页登录域名或同名模型的原厂地址。 |
| JT-13 · P0 | 模拟 SSE 依次返回内容「你好」「，世界」和 `[DONE]`，消费响应到结束。 | 能按顺序消费分片，最终文本为「你好，世界」，正常结束且不丢字、不重放。 |
| JT-14 · P1 | 声明一个无副作用的工具，让模拟网关返回带标识、名称和参数的工具调用，再提交工具结果获取最终回答。 | 出站请求含正确的工具定义；工具调用和返回结果能用同一调用标识关联，最终产生回答。此测试不宣称所有九个真实上游都支持工具。 |
| JT-15 · P0 | 模拟网关先返回无效密钥的 401，再用独立样例返回模型未获授权的错误。 | 两种情况均向调用方报告失败，不伪装为成功回复或自动切换供应商；用户可见的错误文本不包含明文密钥。 |
| JT-16 · P0 | 清除项目自定义价格，按设计表核对九条卡片费率；对 `glm-5.3` 构造缓存读取、普通输入和输出各 100 万词元的三个独立计费桶。 | 在无独立缓存写入费的方案下，读取／普通输入／输出分别为 ¥1／¥4／¥10，总计约 ¥15（美元约 $2.142857，允许现有换算舍入）。卡片显示「3.6折起」，费用不能因此从 ¥15 变成 ¥5.40。此处核对方案价目，不等同供应商账单。 |
| JT-21 · P0 | 逐张对照基准序列的九个模型标识和实际渲染标签；搜索 `glm` 并更换排序，再查看其他供应商的同名模型及 JellyToken 手动新增的非预设模型。 | 按基准序列逐项为：①6折起、②9.5折起、③3.6折起、④8折起、⑤至⑨均为7.5折起。每张预设卡片只显示一个对应折扣标签，保留小数和“起”字，不显示为「省 X%」。搜索或重排后仍按模型匹配，非预设和其他供应商不继承 JellyToken 标签。 |

## 四、升级与真实联调

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| JT-17 · P0 | 升级项目 B，仅打开模型库，不点击同步；读取其模型列表与设置，与升级前快照比较。 | 不自动写入九条预设，不替换已有模型、密钥、地址或默认选择。 |
| JT-18 · P0 | 在 B 执行「同步新增模型」，读取组级连接和模型表；再触发一次相同同步或检查是否仍有新增项。 | 首次仅补缺，默认选择和自定义模型不变；再次无新增 JellyToken 项，不产生重复记录，不要求「恢复默认」。 |
| JT-19 · P0 | 项目 C 同名组已保存不同源地址、虚构密钥和一条与预设同名的模型。升级并显式同步后，读取配置，分别调用原有行和新增行（模拟网络）。 | 已有行不重复，原地址与密钥不被改写；原有模型仍按原配置解析。新增行若使用另一来源，不获得该旧组密钥。 |
| JT-20 · P1 · 需授权 | 在隔离项目使用有权限的 JellyToken 测试账号核对九个实际标识；在获批额度内逐个验证可调用性，再选择一个模型流式对话，对已确认支持工具的模型做一次无副作用的工具往返。 | 按模型分别记录可用／无权限／未测；仅对实测成功的模型和能力标记通过。留存脱敏结果后清理测试凭据；不把密钥、会话内容或原始鉴权头贴入 PR。 |

## 建议执行顺序

先做 JT-01～03、05、12，能尽早发现目录数据正确但界面重排、链接混用或请求走错网关的问题。再验证密钥边界、价格和旧项目同步。JT-20 最后单独执行，禁止在常规 CI 中使用真实密钥或触发计费。自动化落点可复用服务端 `model-catalog.test.ts`、`models.test.ts` 以及前端分组、选择器、设置与排序套件；对顺序验收应读取实际渲染结果，而不是只断言数组常量。
